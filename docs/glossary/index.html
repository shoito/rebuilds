用語の索引

前提知識の資料の用語集を、題材をまたいで 1 つにまとめました。同じ用語は 1 行にまとめ、題材ごとの説明と、資料の用語集へのリンクを並べています。

このページは、共通の前提知識と各題材の資料（docs/primer/index.html、systems/*/docs/primer/index.html）の用語集から生成しています。

889 語（22 の資料：共通の前提知識と 21 題材）

2-gram
  • メルカリ文字列を 2 文字ずつずらして切った断片。辞書に頼らず部分の一致を拾える。
3 者照合
  • Stripe台帳・決済代行の精算・銀行の明細の 3 つが一致することを確かめる処理。
3 方向のマージ
  • Dropbox共通の祖先と 2 つの側を比べて、どちらで何が変わったかを決める方法。Git のマージと同じ考え方。
3D セキュア
  • StripeEMV 3-D セキュア（3DS2）。イシュアがカード会員本人かを認証する仕組み。
36 協定
  • Workday時間外・休日労働に関する労使協定。労働基準法 36 条による。事業場ごとに結んで届け出る。
A/B テスト
  • X利用者を無作為に分け、新旧のバージョンを同じ期間に見せて、指標の差で採否を決める実験。
AAL
  • Auth0Authentication Assurance Level。NIST の認証の確かさの 3 段階。AAL2 は 2 要素、AAL3 はさらに強い認証器を求める。
ABR
  • XAdaptive Bitrate。再生する側が回線の速さに合わせて、画質の段を切り替えること。
  • YouTubeAdaptive Bitrate。プレイヤーが回線とバッファに合わせて、セグメントごとに段を選び直すこと。
ACL
  • NotionAccess Control List。誰にどの水準を許すかの一覧。ここではページごとの共有の設定。
  • ServiceNowAccess Control List。テーブル・行・フィールドごとに、誰が何の操作をできるかの規則。
acr
  • Auth0Authentication Context Class Reference。達成した認証の水準を表すクレーム。
ADR
  • 共通Architecture Decision Record。設計の決定を、理由と退けた案と一緒に残す短い文書。
alternates
  • GitHubGit の仕組み。別の場所のオブジェクトの置き場も、自分のものとして読む。
amr
  • Auth0Authentication Methods References。使った認証の手段の一覧のクレーム（RFC 8176）。
App
  • GitHub本家の GitHub App に相当する連携の形。アカウントに「インストール」し、自分の bot として権限の範囲で動く。
ARC
  • GmailAuthenticated Received Chain（RFC 8617）。転送やメーリングリストが、受け取った時点の認証の結果を封印して次へ渡す仕組み。
Argon2id
  • Auth0計算とメモリーを多く使う、パスワードのハッシュの方式。総当たりを遅くする。
ASR
  • ZoomAutomatic Speech Recognition。音声を文字にする処理。
assignment_epoch
  • Uberドライバーごとの fencing token。割り当ての作成と解放で 1 増える。
AST
  • SlackAbstract Syntax Tree。本文を段落・リンク・メンションなどの節の木として持つ形。
Aurora Global Database
  • 共通別のリージョンに読み取り用の複製を持つ Aurora の構成。災害のときに昇格させる。
available
  • Shopify売れる数。引き当てで減る。
AZ
  • 共通Availability Zone。同じリージョンの中で、電源やネットワークが独立したデータセンターの群。
BalanceTransaction
  • Stripe加盟店の残高を動かす 1 件ごとの記録（txn_）。amount・fee・net・available_on を持つ。
base_rev
  • Dropbox書き込みの元にした中身のリビジョン。サーバーの今のリビジョンと違えば 409 で拒まれる。置き場所には base_node_ver を使う。
bitemporal
  • Workday有効時間と記録時間の 2 つの時間の軸でデータを持つ方式。
blob
  • Gmail受け取ったメッセージのバイトをそのまま、変えずに置いたオブジェクト。状態は持たない。
block_span
  • Airbnb泊の範囲に後ろの準備の日を足した範囲 [check_in, check_out + prep_nights)。排他の制約はこの範囲の重なりを拒む。
BroadcastChannel
  • Linear同じオリジンのタブの間でメッセージを送り合う API。
btree_gist
  • Google カレンダーPostgreSQL の拡張。= で比べる普通の列を GiST の索引に入れられるようにし、「同じ会議室で、区間が重なる」の制約を作れる。
bundle-uri
  • GitHubclone の前に、サーバーが案内する URL から bundle（履歴の固まり）を取らせる Git の仕組み。
C2C
  • メルカリConsumer to Consumer。個人どうしの売買。運営は場を提供し、品を仕入れない。
CAB
  • ServiceNowChange Advisory Board。変更のリスクを見て承認を判断する会議・グループ。
CalDAV
  • Google カレンダーRFC 4791。WebDAV の上でカレンダーを読み書きする標準。OS の標準のカレンダーが使う。
canary
  • Datadog見張りの組織として、本番に合成のデータを送り、読めることを確かめ続ける部品。
CAS
  • GitHubCompare-and-swap。「今の値が期待どおりのときだけ書き換える」操作。
case folding
  • Dropbox大文字小文字の違いを無くすための Unicode の変換。小文字にするだけでは扱えない文字（ドイツ語の ß など）も含めて畳み込む。
cbcs
  • YouTubeCENC の方式の 1 つ。AES-CBC で、ブロックの一部だけを暗号化するパターンを使う。FairPlay を含む 3 つの DRM に共通で使える。
CDE
  • StripeCardholder Data Environment。カード会員データを扱う、またはそれに接続する範囲。
CDN
  • X利用者に近い端のサーバーにコンテンツを置いて配る仕組み。この設計では CloudFront。
  • YouTubeContent Delivery Network。世界中・国中のキャッシュのサーバーから中身を配る網。
CENC
  • YouTubeCommon Encryption（ISO/IEC 23001-7）。複数の DRM で同じ暗号化したファイルを使うための標準。
CER
  • ZoomCharacter Error Rate。文字の誤り率。日本語の音声認識は語の区切りが曖昧なので文字で測る。
CGNAT
  • Auth0Carrier-Grade NAT。携帯の事業者などが、多くの利用者に同じグローバル IP を共有させる仕組み。
ChangeSet
  • Figma1 つの利用者の操作に当たる変更のまとまり。全部当たるか、全部拒否されるか（原子的）。
CI
  • ServiceNowConfiguration Item。サーバー・PC・ネットワーク機器・アプリ・サービスなど、管理の対象の構成要素。
CIAM
  • Auth0Customer Identity and Access Management。自社のサービスの利用者（顧客）のログインと認可を扱う分野。社員向けの IdP とは利用者の数と使われ方が違う。
CIT
  • StripeCustomer-Initiated Transaction。顧客がその場にいて始める取引。
Cloud Files API
  • DropboxWindows 10 1709 からの、プレースホルダーを使う同期のアプリのための API。中核のフィルターは NTFS だけで動く。
CMAF
  • YouTubeCommon Media Application Format（ISO/IEC 23000-19）。HLS と DASH で共有できる fMP4 のセグメントの形。
CMDB
  • ServiceNowConfiguration Management Database。CI とその関係の台帳。
CODEOWNERS
  • GitHubパスのパターンごとにオーナーを書くファイル。該当するファイルの変更に、オーナーのレビューを求められる。
commit-graph
  • GitHubコミットの親子と世代を持つファイル。履歴の走査を速くする。
committed
  • Shopify注文に入り、まだ発送していない数。
CONDSTORE・QRESYNC
  • GmailIMAP の拡張（RFC 7162）。MODSEQ で変わったものだけを取り、消えた UID を VANISHED で返す。
consumer
  • Zoom1 つの producer を 1 人の受け手へ流す、受け手ごとの 1 本。
count
  • Datadog直前からの増分を表す指標の型。時間で畳むと合計。
CRDT
  • FigmaConflict-free Replicated Data Type。どの順で変更が届いても同じ状態に収束するデータ構造。
  • LinearConflict-free Replicated Data Type。どの順で何回当てても同じ状態に合わさるように作ったデータ構造。
  • NotionConflict-free Replicated Data Type。どの順で操作を当てても同じ状態に収束するように作ったデータ構造。
CRF
  • YouTubeConstant Rate Factor。ビットレートではなく画質の目標で符号化する指定。数が小さいほど高画質で大きい。
CRM
  • SalesforceCustomer Relationship Management。顧客との関係（会社、人、案件、やり取り）を記録して管理する仕組み。
CRR
  • DropboxCross-Region Replication。S3 のオブジェクトを別のリージョンのバケットへ非同期に写す機能。RTC を有効にすると写す時間に目標が付く。
CSDM
  • ServiceNowCommon Service Data Model。ServiceNow が示す、サービスと CI の表し方の標準の型。
CTag
  • Google カレンダーコレクションの中身のどれかが変われば変わる印。RFC ではなく、広く使われる拡張（getctag）。
DASH
  • YouTubeMPEG-DASH（ISO/IEC 23009-1）。XML の MPD で配る国際標準の方式。
daterange
  • AirbnbPostgreSQL の日付の範囲の型。既定は [下端, 上端) の半開区間で、&&（重なる）などの演算子を持つ。
deadline-runner
  • メルカリ期限を過ぎた取引を 1 分ごとに拾い、遷移の関数を呼ぶ処理。
Dependency Descriptor
  • Zoomフレームの層とキーフレームかどうかを示す、平文の RTP のヘッダー拡張。暗号化した中身を読まずに層を選べる。
derive
  • Linearある変更から決まる別の変更（派生）を求める共有のコード。Writer が書き、クライアントが同じコードで予測する。
discovery
  • Auth0/.well-known/openid-configuration にある、エンドポイントと対応する機能の一覧。ライブラリはここから設定を読む。
DKIM
  • GmailDomainKeys Identified Mail（RFC 6376）。ドメインがヘッダーと本文に署名し、受け手が DNS の公開鍵で検証する。
  • Google カレンダー送信のドメインがメールに電子署名を付け、受け手が DNS の公開鍵で確かめる仕組み。SPF は送信元の IP をドメインの DNS の一覧で確かめる仕組み。
DM
  • SlackDirect Message。1:1 または少人数の、名前のない会話の場。
DMARC
  • GmailFrom のドメインの持ち主が、SPF・DKIM との揃いと、揃わないときの扱いを宣言する仕組み。設計は RFC 9989 に従う。
Document Server
  • Figma1 つのファイルをメモリに持ち、変更の順序を決め、検証し、ジャーナルに書いて配る Rust のサーバー。
DRM
  • YouTubeDigital Rights Management。鍵を許された端末にだけ渡し、暗号化した中身を守る仕組み（Widevine、FairPlay、PlayReady）。
drop
  • Shopifyテンプレートに渡す、読める属性を決めたオブジェクト（商品・コレクションなど）。
DSN
  • GmailDelivery Status Notification（RFC 3464）。届かなかった・遅れていることを送り手へ知らせるメール。空の MAIL FROM で送る。
DTLS-SRTP
  • ZoomDTLS（UDP 版の TLS）で鍵を交換し、SRTP（暗号化した RTP）でメディアを送る方式。WebRTC では必須。
DTSTAMP
  • Google カレンダーiTIP のメッセージを作った時刻。同じ SEQUENCE の新旧を決めるのに使う。
DTSTART
  • Google カレンダー予定の開始。UTC・TZID つき・浮動・日付のどれかの形で書く。繰り返しでは最初の回になる。
DTX
  • ZoomDiscontinuous Transmission。無音の間の送出を止める仕組み。
durability
  • LinearIndexedDB のトランザクションの完了をいつとみなすかの指定。strict はディスクへの書き込みの後、relaxed は OS に渡した後。
DVR
  • YouTubeライブの途中で巻き戻して見る機能。設計の窓は 12 時間。
E2EE
  • ZoomEnd-to-End Encryption。送り手と受け手だけが鍵を持ち、途中のサーバーは中身を読めない暗号化。
EARS
  • 共通Easy Approach to Requirements Syntax。「〈条件〉とき、システムは〈振る舞い〉しなければならない」のような決まった型で要件を書く方法。
ECAB
  • ServiceNowEmergency CAB。緊急の変更をすぐに判断する少人数の CAB。
Edge
  • Zoomこの設計で、コロケーションに自前のベアメタルの Media Node を置く構成。転送の費用を下げるため。
eDiscovery
  • Gmail訴訟や監査のために、電子のデータを探し、保全し、書き出すこと。
eKYC
  • Airbnbオンラインで完結する本人確認。書類と顔の撮影、IC の読み取りなど。
  • メルカリオンラインで完結する本人確認。書類と顔の撮影、IC の読み取りなど。
encoded-word
  • Gmailヘッダーに ASCII 以外の文字を入れる形 =?charset?B?…?=（RFC 2047）。
entitlement
  • Slackプランや個別の契約から決まる、ワークスペースが使える容量と機能の値。
epoch
  • Dropbox全体の 1 つの番号。DR の切り替えと、運用者が DB を時点へ戻したときだけ上がり、古いカーソルを取り直しにする。
  • ZoomActor の持ち主が替わるたびに増える番号。減らない。
ETA
  • UberEstimated Time of Arrival。到着までの見込みの時間。迎車の ETA と乗車の ETA がある。
ETag
  • Google カレンダーHTTP のリソースのバージョンの印。If-Match で、見たバージョンのときだけ書く条件つきの更新に使う。
EXDATE
  • Google カレンダー回の集合から引く日時の一覧。回の取り消しに使う。
facet
  • Workday一緒に変わる項目のまとまり（住所、職務、給与など）。有効日付の単位で、差分・バージョン・現在の 3 つの表を持つ。
fail closed
  • GitHub判定に要る情報が得られないとき、許可ではなく拒否の側に倒すこと。
fan-out
  • X1 件の投稿を、フォロワーごとのホームの写しへ複製して配ること。書く時に配る（プッシュ）と読む時に集める（プル）がある。
fast-forward
  • GitHub新しいコミットが旧いコミットの子孫で、ref を前に進めるだけで済む更新。
FEC
  • ZoomForward Error Correction。冗長を先に送り、損失を受け手の側で直す方式。Opus のインバンド FEC は前のフレームを低い品質で重ねる。
fencing token
  • Uber単調に増える番号を操作に付け、古い番号の操作を拒否して、古い持ち主や古い情報による書き込みを防ぐ方法。
File Provider
  • DropboxmacOS のクラウドのストレージのための OS の仕組み。同期のアプリは拡張として、OS からの呼び出しに応える。
FLS
  • SalesforceField-Level Security。項目ごとの読み・編集の権限。
frictionless
  • Stripe3DS で、イシュアがリスクを低いと見て、顧客の操作なしに認証を通すこと。逆がチャレンジ。
Fugue
  • Notionテキストの列の CRDT の 1 つ。同じ位置への同時の長い入力が交ざりにくい。
Gateway
  • FigmaWebSocket の接続を終端し、Document Server へ中継し、配信を各接続へ分けるサーバー。
  • SlackWebSocket の接続を持ち、購読に応じてイベントを配るサーバー。書き込みはしない。
gauge
  • Datadogその時刻の値を表す指標の型。時間で畳むと平均。
GC
  • Dropboxガベージコレクション。参照のなくなったブロックを、猶予の後に消す処理（block-gc）。
GCC
  • ZoomGoogle Congestion Control。到着の遅れの変化と損失から、送ってよい速さを推定する方式。
GiST
  • AirbnbPostgreSQL の汎用の索引の型。範囲の重なりなどを扱える。btree_gist の拡張で、普通の列の = も同じ索引に入れられる。
Git LFS
  • GitHub大きなファイルを別の保存先に置き、リポジトリには指し先（pointer）だけを入れる拡張。
glass-to-glass
  • Zoomカメラのレンズから相手の画面までの、映像の端から端の遅れ。
GMV
  • ShopifyGross Merchandise Value。基盤の上で売れた商品の額の合計（流通総額）。基盤の売上ではない。
GNSS
  • UberGlobal Navigation Satellite System。GPS・みちびきなど、衛星で位置を測る仕組みの総称。
GOP
  • YouTubeGroup of Pictures。キーフレームから次のキーフレームの前までのフレームの組。
grok
  • Datadog名前付きのパターンで文字列を属性に分ける書き方。Logstash で広まった。
group commit
  • Figma短い間にたまった複数の変更を、1 回の書き込みにまとめて永続化すること。
Hamming 距離
  • メルカリ同じ長さのビット列で、違うビットの数。
HCM
  • WorkdayHuman Capital Management。人事の記録・組織・報酬・勤怠などを扱う業務システムの分野。
HLS
  • XHTTP Live Streaming。動画を短い区切りと画質の段に分け、プレイリスト（.m3u8）で配る方式。
  • YouTubeHTTP Live Streaming。Apple が作った、.m3u8 の再生リストで配る方式（RFC 8216）。
HMAC
  • GitHub共有の秘密とハッシュで作る署名。送り手と改ざんのなさを確かめる。
  • Shopify共有の秘密の鍵とハッシュ関数で作る、改ざん検知用の署名。
  • Stripe共有の秘密の鍵とハッシュ関数で作る、改ざん検知用の署名。
hug / fill / fixed
  • Figmaオートレイアウトの大きさの方式。中身に合わせる・親の残りを埋める・固定。
iCal
  • AirbnbiCalendar（RFC 5545）の形のカレンダーのファイル（.ics）。掲載先の間で予約の日付を受け渡すのに使う。
iCalendar
  • Google カレンダーRFC 5545。予定を運ぶテキストの形式。BEGIN:VCALENDAR から始まり、.ics のファイルやメールの添付になる。
ICE
  • ZoomInteractive Connectivity Establishment（RFC 8445）。経路の候補を集めて並行に試し、通る組を選ぶ手順。
ICE Lite
  • Zoom公開の IP を持つ側のための簡略な ICE。自分からは確認を送らず、相手の確認に答える。
ID トークン
  • Auth0誰が・いつ・どの手段でログインしたかをアプリに伝える JWT。API の呼び出しには使わない。
ID のリンク
  • Auth0別々の接続の ID を、同じ 1 人のユーザーにまとめること。
ID（identity）
  • Auth0接続ごとの利用者の ID（user_identities の 1 行）。1 人のユーザーが複数持てる。
IdP
  • Auth0Identity Provider。利用者の ID を確かめて証明するサービス。本システムも、Google・LINE なども IdP。
IMAP
  • GmailInternet Message Access Protocol。サーバーのメールボックスを箱の単位で読み書きするプロトコル。現行は IMAP4rev2（RFC 9051）。
IME
  • FigmaInput Method Editor。かなを漢字に変換するなど、キーの入力から文字を組み立てる仕組み。変換中の文字は未確定。
  • LinearInput Method Editor。かなを漢字に変換するなど、文字の組み立てを助ける入力の仕組み。
  • Notionかな漢字変換などの入力の仕組み。変換中のキー入力は、確定まで文書の操作として扱わない。
iMIP
  • Google カレンダーRFC 6047。iTIP のメッセージをメールで運ぶ方法。text/calendar の部分に method を付ける。
inbox
  • メルカリ外から届いた Webhook を、一意の鍵で重複を除いて記録する表。
IndexedDB
  • Linearブラウザに組み込まれた、キーと値のトランザクションつきのデータベース。
inode・File ID
  • Dropboxファイルの実体を指す、ボリュームの中の番号。名前の変更・同じボリュームの中の移動では変わらない。Windows の NTFS では File ID。
Intelligent-Tiering
  • Dropboxアクセスの頻度を見て、層を自動で移す S3 の保存のクラス。128 KB 未満のオブジェクトは監視せず、高頻度の層に置く。
interleaving
