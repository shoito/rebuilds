# ADR-0002: リスクの高い変更に限り、変更単位の quality.md を作る

ADR-0001 のうち、「変更ごとのテスト文書は作らない」とした部分を改める。

## Context

ADR-0001 では、変更ごとのテスト設計を `spec.md`（シナリオ・性質）と `plan.md`（Proof）に書き、独立した文書は作らないとした。しかし、次のような変更では、Proof の表だけではテスト設計を表しきれない。

- 権限：ロール × チャンネル種別 × 操作 × 経路の組み合わせ表
- リアルタイム同期：障害注入のシナリオ一覧
- 負荷：負荷のモデルと合否の閾値

## Options

1. 変更単位のテスト文書を作らない（ADR-0001 のまま）
2. すべての変更に、変更単位の `quality.md` を作る
3. 条件に当たる変更に限り、変更単位の `quality.md` を作る

## Decision

3 を採用する。条件は、次のいずれかに当たること。

- 題材の `quality.md` のリスク上位 3 件に触れる
- 新しい種類のテスト基盤が必要になる
- 規模が「大」である

条件に当たるかどうかは、Design 段で QA が判断する。2 は、レビューの負担が増えるという ADR-0001 の懸念を再燃させる。

## Consequences

- 良くなること：リスクの高い変更で、QA がテスト設計を事前にレビューできる。
- 引き受けるコスト：作るかどうかの判断が QA に委ねられ、ばらつきが出うる。
- アーカイブ時、変更単位の `quality.md` は正本の `specs/` へは反映しない。他の変更でも使える知見だけを題材の `quality.md` へ反映する。

## Confirmation

- QA の仕様レビューのチェックリスト（各題材の quality.md の 2.1 節）に、「変更単位の quality.md が必要か」を含める。
