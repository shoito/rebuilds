# ADR-0002: トランクベース開発を採る

## Context

1 つのリポジトリに複数の題材（`systems/<name>/`）があり、人間と複数の AI エージェントが並行して変更を出す。変更の単位は `changes/YYMMDD-<slug>/` で、1 PR から数セッションで終わる大きさにする（[process.md](../process.md) の「粒度」）。

リリースは、フィーチャーフラグで「デプロイ」と「リリース」を分ける前提である。

## Options

1. **トランクベース開発**：`main` だけを長く保ち、短命なブランチから PR で入れる
2. **GitHub Flow**：1 と似ているが、ブランチの寿命やリリースの規則を定めない
3. **Git Flow**：`develop`、`release/*`、`hotfix/*` などの長命なブランチを持つ

## Decision

1 を採用する。

- **ブランチは `main` だけを長く保つ。** 作業のブランチは短命にし、目安として 2 日以内にマージする。長くかかる作業は、フラグの裏で小さな PR に分けて入れる。
- **ブランチ名は、変更フォルダと対応させる。** `<system>/<YYMMDD-slug>` の形にする（例：`slack/260926-post-and-list-messages`）。規模が「軽微」でフォルダを作らない変更は `<system>/fix-<slug>` か `repo/<slug>` にする。
- **エージェントは、変更ごとに git worktree とブランチを 1 つずつ持つ。** 同じブランチを複数のエージェントで共有しない。
- **PR は squash でマージする。** `main` の 1 コミットが 1 つの PR に対応する。コミットメッセージは Conventional Commits（`feat(slack): ...`）に従い、英語で書く。
- **`main` を保護する。**
  - 直接の push を禁止する。
  - 必須のチェックが通るまでマージさせない。
  - `CODEOWNERS` の承認を必須にする（[process.md](../process.md) の「ロールと持ち主」）。
  - merge queue を使う。キューの中で、最新の `main` と合わせた状態のまま CI をもう一度通す。採番の重複や意味の衝突（「衝突の防止」）をここで検出する。
- **リリースのためのブランチを作らない。** `main` の各コミットがデプロイの候補になる。本番で問題が起きたら、フラグで止めるか、`main` に修正を入れて前進する（forward fix）。前のイメージへの再デプロイは、最後の手段にする。
- 3 は、リリースの周期が長い製品向けで、長命なブランチの間でのマージの衝突が増える。エージェントが並行して変更を出すと、衝突の解消が主な作業になってしまう。

> 2026-09-27 の注記：配布型のクライアント（ブラウザなど、利用者の端末に版を配る製品）は、出荷した版に修正を届けるため、リリースのブランチが要る。題材の ADR で次の条件を満たすなら、上の「リリースのためのブランチを作らない」の例外として認める。この ADR は書き換えない。
>
> - ブランチは、版ごとに `main` から切る。修正は `main` に先に入れ、そこから cherry-pick する。ブランチに直接の変更を入れない。
> - 保護の規則（直接の push の禁止、必須のチェック、`CODEOWNERS` の承認）は `main` と同じにする。
> - 例：ブラウザの `release/M` のような、版ごとのブランチ。

題材ごとの CI/CD とリリースの流れは、各題材の `docs/architecture/` に書く（Slack は `delivery.md`）。

## Consequences

- 良くなること：
  - マージの衝突が小さく、早く見つかる。
  - `main` が常にデプロイできる状態を保つので、リリースの判断をフラグに寄せられる。
- 引き受けるコスト：
  - 未完成の機能が `main` に入る。フラグの管理と、フラグの両方の状態でのテストが欠かせない。
  - CI が遅いと、merge queue が詰まる。変更のあった題材とパッケージだけを検査するように、CI を分ける。

## Confirmation

- GitHub のブランチ保護（ruleset）で、直接の push の禁止、必須のチェック、`CODEOWNERS` の承認、merge queue を設定する。
- 7 日を超えて開いているブランチを、週次で一覧にする。
