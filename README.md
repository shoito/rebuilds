# rebuilds

既存のソフトウェア・システム・SaaS を **AI（コーディングエージェント）を主な作り手として再構築するなら、どう設計し、どう作るか** を書き残すリポジトリです。

実装そのものよりも、次の2つを記録することを目的にしています。

1. **設計** — その製品の本質は何か、MVP をどこで切るか、どのようなアーキテクチャ・データモデル・トレードオフになるか
2. **AI による構築プラン** — エージェントにどう分解して渡すか、何をもって正しいと検証するか、人間はどこで判断するか

## 構成

```
.
├── README.md          # このファイル（題材一覧）
├── TEMPLATE.md        # 設計ドキュメントの共通テンプレート
└── systems/
    └── <name>/
        └── README.md  # 題材ごとの設計ドキュメント
```

## 書き方

- 新しい題材は `TEMPLATE.md` を `systems/<name>/README.md` にコピーして書き始める。
- 本家の内部実装を再現することは目的としない。公開情報は参考にとどめ、**自分ならこう作る** を書く。
- 規模は「小さなチームと AI エージェントで、数週間で動く MVP に届く範囲」を基準にする。
- 判断には必ず理由と、捨てた選択肢を添える。
