## この題材に固有の規則（開発リポジトリで守る）

### 本家の実装と名前

- **パイプラインの指揮、ラダーの決め方、ABR、視聴の計測、指紋、照合のエンジン、おすすめのパイプラインを自前で作る。** 本家のプレイヤー・SDK・API のクライアントのコード、本家の内部の形式、本家から取り出したモデル・重み・指紋のデータを、核にも依存にも使わない。本家の技術ブログの考え方を読むのはよいが、設計の文書に出典を書く（[リポジトリ共通の ADR-0007](../../docs/decisions/0007-no-reuse-of-original-implementation.md)）。
- **汎用の符号化器とライブラリは、核の外の部品として ADR に理由を書いた範囲でだけ使う。** FFmpeg のライブラリ（libavformat・libavcodec）、x264、SVT-AV1、GPU の NVENC、Shaka Packager の類は「どう符号化するか」の部品である。何を・どの順で・どのラダーで符号化するかは自前のコードで決める（ADR-0001、ADR-0003）。
- **公開の標準には合わせてよい。** HLS、DASH、CMAF、CENC、WebVTT、RTMP、SRT、VAST・VMAP はプロトコルとして扱う。互換は振る舞いであって、実装の再利用ではない。
- **本家の名前を識別子に使わない。** ドメイン（`<brand>.<domain>`、配信の `<brand>video.<domain>`、取り込みの `ingest.<brand>.<domain>`）、HTTP ヘッダー（`<Brand>-Signature`、`X-<Brand>-Client`）、ストリームキーの接頭辞（`<brand>_sk_`）、ID の接頭辞、プレイヤーの名前、URL のスキームは `<Brand>`・`<brand>` で書く（[リポジトリ共通の ADR-0006](../../docs/decisions/0006-brand-neutral-identifiers.md)）。

### 預かった動画を失わない

- **アップロードの完了を返すのは、すべての部分が S3 に確定し、全体のチェックサムが合ってからにする。** マルチパートは CRC64NVME の全体のチェックサム（`FULL_OBJECT`）で作り、完了の時に S3 に照合させる（必須）。完了の前に、部分の番号・大きさ・チェックサムが記録と合うことを確かめる。部分の署名つきの URL に部分のチェックサム（`Content-MD5`・CRC64NVME）を含める形は `presigned-part-checksum-poc` で確かめるまで PoC の扱いにする。任意の SHA-256 は完了の前に読み直して確かめる。合わなければ完了にしない（ADR-0002、ADR-0011）。
- **元のファイルを消さない。** 変換の失敗、コーデックの追加、ラダーの作り直しのために、元のファイルを保持の規則の中で持つ。元のファイルの消去は、動画の削除・保持の期限・法的な削除の手続きの 3 つの経路だけにする（ADR-0002）。
- **パイプラインの段は冪等にする。** 各段の出力のキーは（`video_id`、段、入力のハッシュ、符号化の設定のバージョン）から決める。やり直しで同じキーに同じ中身を書く。途中で落ちた段は最初からやり直してよいように作る（ADR-0002）。
- **ラダーの設定は `ladder_version` で固定する。** ラダーの段、ビットレート、符号化器の設定は番号に結び付ける。変えるときは新しい番号を足し、古い番号で作ったレンディションを読めるままにする（ADR-0003）。

### 公開と措置

- **著作権の照合が終わるまで、動画を公開しない。** 公開の状態への遷移は、照合の結果（一致なし・方針の適用済み）を条件にする。照合が使えない間は「照合待ち」のまま止め、時間で公開に倒さない（ADR-0008）。
- **見える範囲は 1 つの関数で決める。** 公開の範囲（公開・限定公開・非公開・メンバー限定）、年齢の制限、地域の制限、照合の方針（ブロック）、措置を、`playable(viewer, video, region)` の 1 か所で判定する。再生の API、マニフェスト、検索、おすすめ、埋め込みは、すべてこれを通す（ADR-0009）。
- **措置と削除は記録してから効かせる。** 措置の記録を書いた後に、配信の拒否の一覧への追加と CDN の無効化を行う。配信の停止は決定から 60 秒以内（NFR-014、ADR-0005）。

### 視聴の計測

- **公開の視聴回数は、検証の規則を通した数だけにする。** 生の出来事の数を、そのまま公開の数・収益の数に使わない。仮の数と確定の数を分け、確定の数は遅れた検証で減ることがある（ADR-0007）。
- **検証の規則は 1 つのコードに置く。** 流れの中の仮の判定と、後からの確定の判定は、同じ `view-rules` のクレートを使う。経路ごとに別の規則を書かない（ADR-0007）。
- **収益の数は確定の数から作る。** 広告の収益の分配、メンバーシップの分配、収益化の条件の判定は、確定した視聴と総再生時間だけを使う（ADR-0007、monetization-and-payouts の領域）。

### おすすめと ML

- **ML の出力は順位だけ。** `playable()`、年齢の制限、子ども向けの印、照合の方針、措置を、ML の点で変えない。絞り込みは点の後にもう一度通す（ADR-0010）。
- **子ども向けの動画と、履歴を止めた利用者には、個人化しない並びを出す。** 視聴の履歴を使わない候補の源だけにする（ADR-0010。範囲は法務の L3・L5 の後に確定）。

### 運用と入力

- **利用者のデータをログに出さない。** 本システム自身のログ・トレースに、動画の題・説明・字幕の本文、コメントの本文、検索の語、IP アドレス、ストリームキーを書かない。ID と数と理由のコードだけを書く。
- **形式とラダーと規則をフラグにしない。** `ladder_version`、セグメントの形式、指紋の `fp_version`、視聴の検証の規則のバージョンはコードのバージョンとして出す。`release.*` のフラグで経路ごとに切り替えない。
- **フラグの名前**：`release.*` は kebab-case（`release.live-dvr`）、`ops.*` は snake_case（`ops.upload_enabled`）。`release.*` は 100% の後 30 日で消す。
- **テストに本物の作品を使わない。** 実在の映画・音楽・放送の録画、本家から取り出した動画を、テスト・フィクスチャー・指紋の参照に入れない。試験の動画は、生成したものと、利用の許諾を確かめた素材（オープンなライセンスの試験の映像）だけにする。

## このリポジトリでの規則

- ADR を追加・更新したら、`docs/decisions/README.md` の一覧を生成し直す。
- 領域の文書で ADR を起票するときは、[architecture/README.md](docs/architecture/README.md) の 7 節で領域に割り当てた番号の範囲の中で採番する。
- 本家の振る舞い・数値を書くときは、出典と確認日を付ける。確かめられないものは「未検証」と書く。本家と違う振る舞いを選んだら、[architecture/README.md](docs/architecture/README.md) の 1.4 節の「本家との意図した違い」に行を足す。
- 標準（HLS、DASH、CMAF、CENC）と本家の振る舞いが違うときは、両方を書き、本システムがどちらに寄せるかを明記する。
- 法令の判断は書かない。枠組みと問いだけを書き、「法務の確認待ち」にする（[intent.md](docs/intent.md) の L1〜L10）。
