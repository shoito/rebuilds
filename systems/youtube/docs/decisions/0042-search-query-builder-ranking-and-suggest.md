# ADR-0042: 検索の問い合わせは `buildVideoSearch` の 1 か所で作り、動画と字幕の索引を並べて引いて上位 200 を合わせ、`playable()` を通してから並べ直す。候補の補完は 7 日に 20 人以上が検索した語だけを、読みの前方一致で出す

## Context

- 見える範囲は `playable()` の 1 か所で決め、検索は索引の写しで絞った上で、返す前にもう一度通す（[ADR-0009](0009-single-tenant-and-playable.md)）。
- 人気の値に仮の数を使うと、水増しが検索の順位に効く（[ADR-0007](0007-two-phase-view-counting.md)）。
- 候補の補完は他人の検索の語を見せる。少ない人の語は個人を推測させる（**法務の確認待ち：L5**）。
- 日本語の入力は、変換の前のひらがなで補完を引く。

## Options

順位：

1. **関連度（候補の中の最大で正規化）× 人気（確定）× 新しさ × 題の完全一致 × 登録**
2. OpenSearch の点だけ
3. 学習した順位のモデル（S1）

補完：

- a. **7 日に 20 人以上の語だけ。正規化の文字列と読みの前方一致**
- b. 題の前方一致だけ

## Decision

1 と a を採用する。詳細は [search.md](../architecture/search.md) の 6〜8 節。

- `buildVideoSearch(viewer, query)` だけが OpenSearch を呼ぶ（lint で禁止）。語ごとに N-gram か英字のフィールドの `match_phrase` を `must`、kuromoji を `should`、絞り込みの印を `filter` にする。
- `videos` と `captions` を並べて引き、上位 200 ずつを合わせ、全部に `playable()` を通す。
- 点：`rel_n · (1 + 0.25 · log10(1 + engaged_30d)) · (1 + 0.2 · exp(−age_days / 7)) · exact · sub`。`engaged_30d` は 1 日の確定。
- 補完：`search-events` から毎日、7 日に別の視聴者 20 人以上の語を、結果が `playable()` で 1 件以上ある語だけ入れる。読み（カタカナ）にも `edge_ngram` を持ち、ひらがなの入力をカタカナに直して引く。T&S の拒否の一覧で即座に外す。
- 検索はログインしていなくても使える。

### 他の案を選ばなかった理由

- **2（OpenSearch の点だけ）**：人気と新しさを入れにくく、字幕の索引との点の尺度が揃わない。
- **3（学習した順位）**：S1 は判定のデータが足りない。評価の集まりと表示の記録が溜まってから S2 で検討する。
- **b（題だけ）**：人が実際に探す語を出せない。

## Consequences

- 良くなること：
  - 見える範囲の判定が他の経路と同じになる。
  - 補完が少ない人の語を出さない。
- 引き受けるコスト：
  - 2 つの索引を引くので、応答の予算を分ける必要がある（250 ms で打ち切る）。
  - `search-events` の保持の判断（法務の L5）を待つ。
