# ADR-0041: 検索の索引は動画・字幕の区切り・チャンネル・候補の補完の 4 つにし、字幕は 30 秒（前の 3 秒を重ねる）の区切りごとの文書にする。一致の判定は N-gram、関連度は kuromoji で付け、正規化は X の題材と同じ関数を使う

## Context

- [architecture/README.md](../architecture/README.md) の 4 節は、検索を OpenSearch（kuromoji と N-gram）にし、X の題材の形（[X の ADR-0025](../../../x/docs/decisions/0025-search-engine-and-japanese-analysis.md)）に寄せると決めた。
- この題材は題・説明・チャンネルの名前に加え、字幕を検索の対象にする（intent の MVP）。1 時間の動画の字幕は約 1.8 万字で、1 文書に入れると、どこで当たったかが分からず、強調の表示と時刻への飛びができない。
- 日本語は語の区切りがなく、形態素の解析だけでは未知語と語の途中を取りこぼす。字幕の量（1 年で約 95 億字）では、1 文字の N-gram の索引が重い。

## Options

字幕：

1. **区切り（30 秒、3 秒の重ね）ごとの文書を別の索引に置き、動画の ID で畳む**
2. 動画の文書に字幕を全部入れる
3. 字幕を索引に入れない

N-gram：

- a. **題・説明は 1〜2 文字、字幕は 2 文字だけ**
- b. 全部 1〜2 文字

## Decision

1 と a を採用する。詳細は [search.md](../architecture/search.md) の 5 節。

- 索引：`videos-v{n}`（公開の動画だけ）、`captions-v{n}`、`channels-v{n}`、`suggest-v{n}`。別名で切り替える。
- 字幕の区切り：30 秒ごと。前の区切りの最後の 3 秒の手がかりを次の頭に重ねる。手動 0.5、自動 0.3 の重み。
- フィールド：`*.gram`（一致）、kuromoji（関連度）、`*.word`（英字）、絞り込みの印（状態、公開の範囲、年齢、子ども向け、措置、地域、`search_version`）。
- 正規化は `packages/text` の `normalizeForSearch` を X の題材と共有し、`norm_version` を文書に持つ。
- 1 文字の語は字幕を引かない。

### 他の案を選ばなかった理由

- **2（動画に全部）**：当たった時刻が分からず、長い文書で関連度がゆがむ。字幕の更新で動画の文書を書き直す量が多い。
- **3（入れない）**：講座や配信の中身で見つけられない。MVP の範囲から外れる。
- **b（字幕も 1 文字）**：索引が約 2 倍になる。1 文字の語は字幕では候補が多すぎて役に立たない。

## Consequences

- 良くなること：
  - 字幕の当たった時刻を結果に出し、そこから再生できる。
  - 題・説明の部分一致を取りこぼさない。
- 引き受けるコスト：
  - 動画の状態が変わるたびに、字幕の区切りの印を全部書き直す。
  - 2 つの索引を合わせる組み立てが要る（ADR-0042）。
