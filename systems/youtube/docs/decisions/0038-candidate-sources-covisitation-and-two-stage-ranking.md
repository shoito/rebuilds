# ADR-0038: おすすめの候補の源は登録・続き・共起・人気・検索の 5 つにし、共起は 28 日の確定のエンゲージ ビューから余弦の値で作る。並べ方は軽いランク（2,000 → 300）と重いランク（S1 は手の式）の 2 段にする

## Context

- [ADR-0010](0010-recommendation-boundary.md) は、段のパイプライン、S1 の源（登録、続き、共起、人気、検索）、S1 は手で決めた式、S2 から学習済みのモデルと決めた。共起の作り方、式の形、段の件数は決めていない。
- S1 は視聴の出来事が少なく、学習済みのモデルの質が出ない。遅延の予算はホーム p99 400 ms（NFR-012）。
- 人気と特徴に仮の数を使うと、水増しがおすすめに効く（[ADR-0007](0007-two-phase-view-counting.md)）。
- 長い動画は「期待の視聴の時間」で点を付けると、長い動画ばかりが上に来る。

## Options

共起：

1. **確定のエンゲージ ビューのセッションから、余弦の値の項目どうしの共起を毎日作る**
2. 行列の分解（ALS など）の埋め込み
3. 共起を持たない（登録と人気だけ）

並べ方：

- a. **軽いランクで 300 に絞り、重いランクで点を付ける 2 段**
- b. 全候補に重いランク

## Decision

1 と a を採用する。詳細は [recommendations.md](../architecture/recommendations.md) の 5・7 節。

- 源：`subs_new`（200）、`continue`（20）、`covisit`（600）、`popular`（200）、`search_rel`（60）。次の動画は今の動画を種にし、`channel_ctx` と `category` を足す。
- 共起：28 日の確定のエンゲージ ビューを 2 時間の窓でセッションにし、組に `1 / log2(1 + n)` を足し、`c(a, b) / sqrt(c(a) · c(b))` で値を出す。別の視聴者 5 人未満の組は捨てる。動画ごとに上位 100。子ども向けの視聴と、履歴を止めた利用者の視聴は含めない。
- 軽いランク：`b_source + 0.15 · ln(1 + engaged_7d) + 2.0 · cv_max + 1.0 · subscribed`。源ごとに最低 20 件を残して 300 件。
- 重いランク（S1）：`p_play · log2(1 + E_watch_min) · (1 + rel) · q · fresh`。`p_play` は事前の値（`α = 2`、`β = 48`）で平滑化した表示からの再生の率。係数は AppConfig に置き、A/B で決める。
- 人気・特徴の視聴の数は 1 日の確定だけを使う。

### 他の案を選ばなかった理由

- **2（行列の分解）**：S1 の量では質が出にくく、学習の基盤が要る。S2 の 2 つの塔の埋め込みで扱う。
- **3（共起なし）**：「次の動画」の質が出ない。
- **b（全候補に重いランク）**：特徴の読み出しが 2,000 件になり、遅延の予算に入らない。

## Consequences

- 良くなること：
  - S1 から「次の動画」が視聴の行動に基づく。
  - 長さへの偏りを `log2` で抑え、事前の値で少ない表示の揺れを抑える。
- 引き受けるコスト：
  - 共起は 1 日遅れる。新しい動画は共起に出るまで登録と人気に頼る。
  - 手の式の係数は A/B で決め続ける。
