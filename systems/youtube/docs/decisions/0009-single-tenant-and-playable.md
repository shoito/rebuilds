# ADR-0009: テナントは 1 つ。本人だけの表は FORCE RLS、チャンネル・権利者の管理の表は持ち主の RLS にする。動画の見える範囲は `playable(viewer, video, region)` の 1 つの関数で決める

## Context

- 他の題材の多くは、ワークスペースやテナントを単位に `tenant_id` と FORCE RLS で分ける。この題材は X の題材と同じく、全利用者が 1 つの公開の空間にいる（[X の ADR-0004](../../../x/docs/decisions/0004-single-tenant-and-visibility.md)）。
- ただし、管理の権限の単位がある。
  - **チャンネル**：所有者と管理者（役割）が、動画の情報・収益・分析・コメントの管理を行う。他のチャンネルの未公開の動画、収益、分析を見てはいけない。
  - **権利者**：参照のファイル、方針、一致の一覧、収益の分け前を持つ。他の権利者の参照と方針を見てはいけない。
  - **本人**：視聴の履歴、検索の履歴、登録、通知、設定、支払いの情報。
- 動画の見える範囲は、閲覧者と動画と地域で決まる：公開の範囲（公開・限定公開・非公開・メンバー限定）、予約の公開、年齢の制限と閲覧者の年齢、地域の制限（照合の方針）、照合のブロック、措置（削除・年齢の制限・地域での非表示）、子ども向けの印、チャンネルの停止。
- 再生の API、マニフェスト、DRM のライセンス、検索、おすすめ、埋め込み、通知、再生リストのどこかで判定がずれると、措置した動画や未公開の動画が漏れる。

## Options

1. **テナントの RLS は置かない。本人・チャンネル・権利者の管理の表に持ち主の RLS を置き、公開の判定は 1 つの関数 `playable()` にする**
2. チャンネルをテナントとみなし、全テーブルに `channel_id` の RLS を置く
3. 見える範囲を RLS のポリシーで表す

## Decision

1 を採用する。

### RLS

- **本人だけの表**（視聴の履歴、検索の履歴、登録、通知、設定、支払いの手段の参照、データの書き出しの依頼）：`owner_id` と `FORCE ROW LEVEL SECURITY`。トランザクションごとに `SET LOCAL app.actor_id`。
- **チャンネルの管理の表**（未公開の動画の情報、収益の明細、分析の確定の値、コメントの保留、メンバーシップの会員の一覧）：`channel_id` と FORCE RLS。トランザクションごとに `SET LOCAL app.channel_ids`（その利用者が役割を持つチャンネルの一覧）。
- **権利者の表**（参照、方針、一致の一覧、所有の衝突、権利者の収益）：`rights_owner_id` と FORCE RLS。`SET LOCAL app.rights_owner_ids`。
- 創作者に見せる一致の情報（どの権利者の、どの区間か）は、権利者の表から写した「一致の通知」の表（チャンネルの RLS）にする。創作者が権利者の表を直接読む経路を作らない。
- RLS の外の表（公開の動画の情報、チャンネルの公開の情報、公開のコメント）は data-model の領域で一覧にし、CI で検査する。
- 運用者の参照は、RLS を外す役割ではなく、監査つきの JIT の権限で行う（security の領域）。

### `playable(viewer, video, region)`

- 入力：閲覧者（利用者か匿名、年齢の確かめの状態、メンバーシップ、チャンネルでの役割）、動画（状態、公開の範囲、予約の時刻、年齢の制限、子ども向けの印、措置、照合の方針の結果）、地域。
- 出力：`allow`、`deny`（理由のコード）、`allow_with`（年齢の確かめが要る、DRM が要る、広告なし（子ども向け）など）。
- 判定は決定表で定め、上から最初に一致した行を使う。措置と照合のブロックは、公開の範囲と役割より先に評価する（所有者でも措置した動画は管理の画面の外で再生しない）。
- 呼ぶ経路：再生の API、マニフェストの生成、DRM のライセンス、検索の結果、おすすめの絞り込み（前と後）、埋め込み、通知の送信、再生リストの表示、チャンネルのページ、コメントの表示。
- `playable()` は `packages/visibility` の 1 か所に置く。検索とおすすめは、索引の時の写し（状態、措置、年齢）で絞った上で、返す前に `playable()` をもう一度通す。
- 判定に使う動画の状態は、Aurora の正本と、outbox で更新する Valkey の写し（60 秒以内）から読む。措置の反映は 60 秒以内（NFR-014）。

### 他の案を選ばなかった理由

- **2（チャンネルをテナント）**：視聴者・コメント・登録はチャンネルをまたぐ。公開の読み出しに RLS をかけても守るものがない。
- **3（RLS で見える範囲）**：検索（OpenSearch）、おすすめ（メモリーの候補）、CDN のマニフェストに効かない。全経路で同じ判定にするには、1 つの関数のほうが確かめやすい。

## Consequences

- 良くなること：
  - 管理の権限（本人・チャンネル・権利者）の漏れを DB で防げる。
  - 見える範囲の判定を 1 か所で試験できる。
- 引き受けるコスト：
  - 全経路が `playable()` を呼ぶことを、lint と試験で守り続ける。
  - 写しの遅れ（60 秒）の間、措置の前の状態で判定されうる。配信の停止は拒否の一覧で別に止める（[ADR-0005](0005-cdn-and-origin-strategy.md)）。

## Confirmation

- 決定表の全行を表駆動テストで確かめる。
- 漏れの経路の表（[quality.md](../quality.md)）の全行で、措置・未公開・年齢・地域・メンバー限定の動画が出ないことを確かめる。
- RLS の検査：FORCE RLS の表の一覧を CI で確かめ、別のチャンネル・権利者・本人の行が読めないことを性質ベーステストで確かめる。
