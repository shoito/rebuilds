# ADR-0010: おすすめは自前の段のパイプラインにし、ML は候補の取り出しとスコアだけに使う。見える範囲・年齢・子ども向け・照合・措置の判定を上書きしない

## Context

- ホーム（ログインの有無）と「次の動画」は、視聴の時間の多くを生む。並べ方が、創作者の収益と視聴者の体験を左右する。
- 長い動画の推薦は、短い投稿と違う。1 本の視聴が数十分になり、満足の信号は「クリック」より「見終わった時間」「また見に来たか」に出る。
- X の題材は、段のパイプラインと ML の境界を決めた（[X の ADR-0006](../../../x/docs/decisions/0006-ranking-boundary.md)）。この題材も同じ境界の考え方に寄せ、動画に固有の源と信号を足す。
- 子ども向けの動画と、視聴の履歴を止めた利用者には、履歴を使わない並びが要る（法務の L3・L5）。
- S1 は視聴の出来事が少なく、学習済みのモデルの質が出ない。
- 本家の推薦のモデル・重み・特徴の定義は使わない（[リポジトリ共通の ADR-0007](../../../../docs/decisions/0007-no-reuse-of-original-implementation.md)）。

## Options

1. **自前の段のパイプライン。段の口を固定し、ML は取り出しとスコアの段の中だけに置く。S1 は規則と軽いスコア、S2 から学習済みのモデル**
2. 最初から端から端まで 1 つのモデル
3. 規則だけ
4. 外部の推薦のサービス（Amazon Personalize など）

## Decision

1 を採用する。

### 段

| 段 | 役目 | ML を使うか |
| --- | --- | --- |
| 1. 候補の取り出し | 源ごとに候補を集める。S1 の源：登録したチャンネルの新しい動画、続き（途中まで見た動画、同じ再生リスト・シリーズ）、一緒に見られた動画（同じ視聴者の集まりでの共起）、日本の人気（話題・カテゴリごと）、検索の語の近い動画。S2 で 2 つの塔の埋め込みと近傍の探索を足す | S2 から（埋め込みでの取り出し） |
| 2. 固い絞り込み（前） | `playable()` の写し（[ADR-0009](0009-single-tenant-and-playable.md)）、見終わった動画、「興味なし」、ブロックしたチャンネル、重複 | 使わない |
| 3. 特徴の付加 | 動画（長さ、経過、確定の視聴、平均の視聴の割合、言語、カテゴリ）、チャンネルとの関係（登録、視聴の回数）、閲覧者（端末、時間帯）、文脈（今見ている動画） | 使わない（決まった定義から作る） |
| 4. スコア | 期待する満足（見る確率 × 期待する視聴の時間 ＋ 満足の信号の重み）。S1：手で決めた式。S2：学習済みのモデル（多目的）を ONNX Runtime で | 使う |
| 5. 固い絞り込み（後）とガードレール | `playable()` をもう一度通す。年齢の制限・子ども向け・照合のブロック・措置・境界の動画（規約の違反の候補）を落とすか順位を下げる | 使わない |
| 6. 混ぜ合わせ | 同じチャンネルの連続の抑え、新しい創作者の枠、長さの偏りの抑え、広告の枠は持たない（広告は再生の中だけ） | 使わない |

### 境界の規則

- **ML の出力は順位だけ。** 見える範囲・年齢・子ども向け・照合・措置を ML の点で変えない。2 段目と 5 段目は点の後でも必ず通す。
- **段の口を固定する。** 候補は `(video_id, source, reason)`、点は `(video_id, score, model_version)`。
- **確定の数を使う。** 人気と特徴の視聴の数は、確定の数（[ADR-0007](0007-two-phase-view-counting.md)）か、仮の数と確定の数の小さいほうにする。仮の数の水増しでおすすめを動かさない。
- **個人化しない並び**：子ども向けの動画を見ている間、視聴の履歴を止めた利用者、ログインしていない利用者（端末の履歴を使わない設定）には、1 段目の源を「人気・続き（今見ている動画のチャンネル）・カテゴリ」だけにする。
- **時間の予算**：ホームの最初のページ p99 400 ms、次の動画 p99 300 ms（NFR-012）。段ごとに割り振り、超えたら部分の結果で返す。
- **代わりの並び**：スコアの段が落ちたら、登録の新しい動画と人気を混ぜた並びで返す。可用性に数え、どちらで返したかを記録する。
- **理由の記録**：返した動画ごとに源・理由のコード・モデルのバージョンを記録し、「この動画が表示される理由」に使う。説明の範囲は法務の L5 の後に決める。
- **視聴の履歴の消去**：利用者が履歴を消したら、特徴と候補の写しから 24 時間以内に消す（recommendations の領域）。

### 段階

| 段階 | 取り出し | スコア | 学習 |
| --- | --- | --- | --- |
| S1 | 規則の源（登録、続き、共起、人気、検索） | 手で決めた式。重みは AppConfig で、A/B で決める | なし。出来事と配信の時の特徴を記録する |
| S2 | ＋ 2 つの塔の埋め込みと近傍の探索 | 勾配ブースティング（見る確率と視聴の時間）を ONNX Runtime で | SageMaker でオフラインに学習。週ごとに作り直す（学習に使うデータの範囲は法務の L5・L8） |
| S3 | ＋ 系列のモデルでの取り出し | ニューラルネットワークの多目的のランク | 同上 |

### 変更の出し方

- 重み・特徴・モデルの変更は、オフラインの評価 → A/B（利用者の単位、7 日以上）→ 段階の拡大の順に通す。ガードレール（通報の率、「興味なし」の率、境界の動画の表示の割合、子ども向けの動画での個人化の 0 件）が決まった幅を超えて悪くなったら止める。

### 他の案を選ばなかった理由

- **2（端から端まで 1 つのモデル）**：S1 は学習のデータが足りない。安全の絞り込みをモデルの外に確実に置く境界が曖昧になる。
- **3（規則だけ）**：S2 以降で視聴の満足を伸ばす道がない。
- **4（外部のサービス）**：題材の核を設計しないことになる。`playable()` をサービスの中で強制できない。

## Consequences

- 良くなること：
  - 安全・年齢・権利の判定が、ML の変更に左右されない。
  - S1 は小さく始め、モデルを段の中で差し替えて育てられる。
- 引き受けるコスト：
  - 段の口と記録の形を保守する。
  - S1 のおすすめの質は、規則と手の重みに留まる。

## Confirmation

- 性質ベーステスト：任意の候補と点で、出力に `playable()` が `deny` の動画、子ども向けの視聴での個人化の源の候補が含まれない。
- オフラインの評価を CI で回し、ガードレールの指標を前のバージョンと比べる。
- 予算の超過と代わりの並びの割合を、runbooks の指標で見る。
