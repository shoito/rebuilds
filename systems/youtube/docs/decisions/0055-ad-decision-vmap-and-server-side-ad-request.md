# ADR-0055: 広告の判断の口 `ad-decision` が VMAP を作り、各枠の VAST は `ad-decision` が外部の広告サーバーへ代わりに要求する。MVP の要求は文脈の値だけにし、表示ごとの `imp_id` で広告サーバーの請求と本システムの有効な表示を突き合わせる

## Context

- [ADR-0024](0024-client-side-ad-insertion.md) は、再生の API が本システムの広告の判断の口の VMAP の URL を返し、プレイヤーが VMAP・VAST を読んで本編と別に再生すると決めた。広告の販売と入札は外部の広告サーバーが持つ（intent の Non-goals）。
- プレイヤーが広告サーバーに直接 VAST を要求すると、視聴者の IP アドレスと端末の情報が要求ごとに第三者に渡る（**法務の確認待ち：L5・L6**）。
- 無効なトラフィックの除外は視聴の検証と同じ規則で行う（[ADR-0007](0007-two-phase-view-counting.md)）。広告サーバーの請求と本システムの判定が食い違うことがある。

## Options

1. **`ad-decision` が VAST を代わりに要求する（サーバーの側の広告の要求）。要求は文脈だけ。`imp_id` で突き合わせる**
2. VMAP に広告サーバーの URL を書き、プレイヤーが直接要求する
3. 広告サーバーの報告の値をそのまま収益にする

## Decision

1 を採用する。詳細は [monetization-and-payouts.md](../architecture/monetization-and-payouts.md) の 4 節。

- VMAP：収益化の可否（`playable()` が `no_ads` でない、チャンネルが `active` か照合が `monetize`、創作者の設定）、枠（前・途中 8 分ごと・後）、頻度の上限（再生の前は 2 本に 1 回、枠は視聴の 8 分に 1 回）。
- VAST：プレイヤーは `ad-decision` に要求し、`ad-decision` が広告サーバーへ 300 ms で要求して包みを解いて返す。間に合わなければ枠を空にする。
- 要求の値：内容の ID のハッシュ、カテゴリ、長さ、言語、年齢の制限の印、枠、端末の種類、都道府県、`imp_id`。利用者の識別子・広告の ID・IP アドレス・視聴の履歴は送らない。
- 突き合わせ：請求ありかつ有効 → 収益、請求ありかつ無効 → `ivt_reserve`、請求なし → 0。
- 素材の取得と第三者の計測の URL は端末から出る（外部送信として扱う）。

### 他の案を選ばなかった理由

- **2（直接の要求）**：要求ごとに IP アドレスと端末の情報が第三者に渡り、要求の値を本システムで制御できない。
- **3（報告をそのまま）**：本システムが無効と判定した表示の収益が創作者に払われ、視聴の検証の規則と食い違う。

## Consequences

- 良くなること：
  - 第三者に渡る情報を本システムが決められる。
  - 収益が視聴の検証と同じ規則で守られる。
- 引き受けるコスト：
  - `ad-decision` が広告の要求の量（S1 で 1 秒数千）を受ける。
  - 文脈だけの広告は、個人に合わせた広告より単価が低い見込み。

## Confirmation

- DT-ADS-001。
- 結合テスト：VAST の要求に利用者の識別子・IP アドレスが含まれない。300 ms を超えた要求で枠が空になり、本編が始まる。
