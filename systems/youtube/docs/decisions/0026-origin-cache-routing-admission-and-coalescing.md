# ADR-0026: `origin-cache` は AZ ごとの rendezvous のハッシュの輪にし、AZ をまたがない。NVMe に入れるのは 24 時間に 2 回目の要求と、動画の最初の 3 セグメントとライブ。同じ鍵の同時の外れは 1 つの S3 の読み出しにまとめる

## Context

- [ADR-0005](0005-cdn-and-origin-strategy.md) は、自前の中間のキャッシュ `origin-cache`（NVMe、AZ ごと）を置き、セグメントの URL を S3 の範囲の読み出しに直し、同じセグメントへの同時の要求を 1 つにまとめ、急な人気の兆しで先に読み込むと決めた。
- S3 の GET の費用は小さい（[cdn-and-delivery.md](../architecture/cdn-and-delivery.md) の 7.3 節で S1 は 1 日約 17 USD）。`origin-cache` の価値は、外れの応答の速さ（S3 の最初のバイトまで 100〜200 ms）、要求の合流、S3 の接頭辞ごとの要求の速さの上限の手前で受けることにある。
- ロングテールのセグメントの多くは 1 回しか来ない。そのまま入れると、NVMe が 1 回きりのもので埋まり、中程度に人気のセグメントが追い出される。
- AZ をまたぐ転送には費用がかかり、1 つの AZ の障害が輪の全体に広がる。

## Options

振り分け：

1. **AZ ごとの輪（rendezvous のハッシュ）。AZ をまたがない**
2. 3 つの AZ を 1 つの輪にする
3. 輪を作らず、各ノードが独立にキャッシュする

入れる規則：

- a. **24 時間に 2 回目の要求で入れる。最初の 3 セグメントとライブは 1 回目から**
- b. 全部を入れる（LRU）

## Decision

1 と a を採用する。詳細は [cdn-and-delivery.md](../architecture/cdn-and-delivery.md) の 6 節。

- CloudFront のオリジンは NLB で、AZ をまたぐ振り分けを切る。AZ の中で、鍵 `video_id / gen / rendition / seq` の rendezvous のハッシュで持ち主のノードを決め、受けたノードは持ち主へ 1 回だけ渡す。
- NVMe は区画つきの LRU（見習い 20%、保護 80%）。入れる規則は、数え上げの略図で 24 時間に 2 回目の要求。動画の最初の 3 セグメントとライブの DVR は 1 回目から。
- 持ち主のノードは、同じ鍵の同時の外れを 1 つの S3 の範囲の GET にまとめる。
- 索引 `SIX1` をメモリーに 8 GB まで持つ。
- 急な人気の兆し（仮の視聴 1 時間 200 回）と、大きなチャンネルの予約の公開の 5 分前に、3 つの輪へ上位 4 段と音声の最初の 8 セグメントを読み込む。
- S1 は AZ ごとに 3 ノード（計 9）。1 つの AZ を失っても、残りでピークの外れ（30 Gbps）を受ける。

### 他の案を選ばなかった理由

- **2（1 つの輪）**：S3 の読み出しは最も少ないが、外れの転送の 2/3 が AZ をまたぎ、費用と遅れが増える。AZ の障害で輪の 1/3 の鍵が一度に動く。
- **3（独立）**：同じセグメントを全ノードが読み、キャッシュの実効の大きさがノードの数で割られる。
- **b（全部を入れる）**：1 回きりのセグメントで NVMe が埋まり、ヒットの率が下がる。

## Consequences

- 良くなること：
  - 外れの応答が NVMe の速さになり、開始の時間（NFR-003）を守りやすい。
  - 急な人気で、S3 の GET が 1 セグメントあたり最大 3 回（AZ の数）に収まる。
- 引き受けるコスト：
  - 3 つの輪が同じセグメントを別々に持つので、キャッシュの実効の大きさは 1 つの AZ の輪の大きさになる。
  - 状態を持つ部品（NVMe のノード）を運用する。

## Confirmation

- 性質ベーステスト：PROP-CDN-004（ノードの増減で動く鍵が限られる）、PROP-CDN-005（同時の外れで S3 の GET が AZ ごとに 1 件）。
- 負荷試験：急な人気の模型（10 万の同時の開始）で、S3 の GET が 1 セグメントあたり 3 回以下（[quality.md](../quality.md) の 2.2.1 節 H）。
- 本番：`origin-cache` のヒットの率と、外れの応答の p95 を SLI にする（observability の領域）。
