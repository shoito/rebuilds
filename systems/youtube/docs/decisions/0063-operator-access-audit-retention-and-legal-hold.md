# ADR-0063: 運用者は日常の権限で元のファイル・隔離のファイル・生の IP アドレス・チャットの本文を読めず、読むときは JIT と 2 人の承認と監査を要る。監査の記録は outbox から Object Lock へ書き、保持の期間は `retention_policies` の 1 つの表に持ち、法的な保全はすべての消去の経路より先に効かせる

## Context

- 本システムは、未公開の動画、メンバー限定の動画、既知の違法なメディアに一致した隔離のファイル、ログインと投稿の時の IP アドレス、チャットの本文を持つ。
- モデレーターは措置した動画・非公開の動画を見る必要がある。開示の請求と捜査機関の照会では、記録の書き出しが要る（**法務の確認待ち：L10**）。
- 元のファイルの消去は 3 つの経路だけ（[ADR-0013](0013-original-retention-and-deletion-paths.md)）で、保全のある動画はどの経路でも消さない（[upload-and-ingest.md](../architecture/upload-and-ingest.md) の 7.2 節は保全の表を security の領域に預けた）。
- 保持の期間の多くは法務の結論で変わる（L5、L10）。値が散らばると、結論の反映が漏れる。

## Options

1. **日常の権限で読めない。JIT・2 人・監査で読む。監査は Object Lock。保持の値は 1 つの表、保全は消去より先**
2. 運用者に読み出しの役割を与え、記録だけを残す
3. 保持の期間を部品ごとの設定に持つ

## Decision

1 を採用する。詳細は [security.md](../architecture/security.md) の 5・6・8・9 節。

- **役割**：`ops-readonly`（指標と ID のログ）、`ops-jit-admin`（構成の変更）、`moderation-review`（審査の画面で動画を見る。見た動画と理由を監査に残す）、`safety-review`（隔離のファイル、2 人の承認、1 回ごと）、`legal-response`（開示の書き出し、2 人の承認）、`break-glass`。どの役割も RLS を外さない。
- **監査**：創作者の重い操作、運用者の操作、自動の措置を `audit_events` に書き、同じトランザクションの outbox から log-archive の S3（Object Lock のコンプライアンスのモード、3 年。L10 で見直す）へ写す。IP は監査の本文に入れず、`login_records`・`post_records`（180 日、L10）に分ける。
- **保持**：値は `retention_policies` の 1 つの表に持ち、消去の作業はこの表だけを読む。法務の結論の反映は表の行の変更だけにする。
- **法的な保全**：`legal_holds`（対象と範囲）は、元のファイルを含むすべての消去の経路より先に効く。付与と外しは法務の承認と監査を要る。保全は消さないだけで、通常の機能に戻さない。
- **開示の請求と照会**：受け付けは法務の窓口だけ。エージェントと一般の運用者は扱わない。応じる範囲と利用者への通知は L10 の結論の後。

### 他の案を選ばなかった理由

- **2（読み出しの役割＋記録）**：記録は事後の発見で、持ち出しを防がない。隔離のファイルは 1 人で見てよいものではない。
- **3（部品ごとの設定）**：法務の結論を部品ごとに反映する漏れと、保全の確かめの漏れが起きる。

## Consequences

- 良くなること：
  - 社内の運用者からの漏れと持ち出しを、権限と 2 人の承認で防ぐ。
  - 法務の結論を表の行で反映でき、消去と保全の判定が 1 か所になる。
- 引き受けるコスト：
  - 調べものに JIT の申請の手間がかかる。
  - 審査の画面は `playable()` を通さない経路なので、漏れの経路の表に行を足して見張る。

## Confirmation

- PROP-SEC-001（保全のある対象は消されない）、DT-SEC-001（役割 × 操作）。
- Terraform の plan の検査：人のロールに `kms-media`・`kms-quarantine`・`kms-events`・`drm-content`・`kms-pii` の復号がない。
- 漏れの経路の表（[quality.md](../quality.md) の 2.2.1 節 G）の「運用者の審査の画面」の行で、役割と監査のない取得が 0。
