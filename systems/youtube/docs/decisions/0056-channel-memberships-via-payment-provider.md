# ADR-0056: チャンネルのメンバーシップは決済の事業者の定期の課金で受け、MVP は Web だけで売る。会員の状態は事業者の webhook と 1 時間ごとの突き合わせで進め、`active`・`past_due`（3 日の猶予）・`canceling` の間だけ会員の特典とメンバー限定の動画を許す

## Context

- intent の MVP は、チャンネルのメンバーシップとメンバー限定の動画（DRM）を含む。代金の流れの法令の位置づけは**法務の確認待ち：L7**。
- カードの情報を本システムが持つと、PCI DSS の範囲が広がる。
- メンバー限定の動画の許可は `playable()` と DRM のライセンスの代理が判定する（[ADR-0009](0009-single-tenant-and-playable.md)、[ADR-0021](0021-drm-key-hierarchy-and-license-proxy.md)）。
- アプリの中の購入は、アプリの店の決済の規則と手数料の対象になる。

## Options

1. **決済の事業者の定期の課金。Web だけで売る**
2. 自前で定期の課金を作り、カードの決済だけを事業者に頼む
3. Web とアプリの店の両方で売る

## Decision

1 を採用する。詳細は [monetization-and-payouts.md](../architecture/monetization-and-payouts.md) の 5 節。

- 段は 5 つまで、価格は決まった一覧（月額 90〜12,000 円の税込み）。子ども向けでは売らない。
- 状態：`pending → active ⇄ past_due → expired`、`active ⇄ canceling → expired`、`refunded`。事業者の出来事の ID で冪等にし、1 時間ごとに事業者の状態と突き合わせる。
- 会員の写し `mem:{user_id}:{channel_id}` を outbox から 60 秒以内に更新し、`playable()` が読む。ライセンスの代理がもう一度確かめる。
- 純収益 = 税込みの代金 − 消費税 − 決済の手数料。創作者へ 70%（ADR-0057）。
- アプリの中の購入は、店の規則と法務の L7 の後に決める。

### 他の案を選ばなかった理由

- **2（自前の定期の課金）**：再試行・猶予・請求書・税の計算を作り直すことになり、題材の核でない。
- **3（アプリの店も）**：店の手数料と規則、返金の経路が増え、法務の L7 の結論を待つ必要がある。

## Consequences

- 良くなること：
  - カードの情報を持たない。定期の課金の細部を事業者に任せられる。
- 引き受けるコスト：
  - アプリの利用者は Web で買う必要がある。
  - 事業者の webhook の欠けと順の入れ替えを扱う。
