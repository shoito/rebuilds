# ADR-0017: 音声は区切らずにトラックの全体を 1 回で符号化し、ラウドネスは測って再生の側で -14 LUFS へ下げるだけにする。自動の字幕は `AsrEngine` の口の後ろに置き、既定の案は GPU で自前でホストする公開の重みのモデルにする

## Context

- 映像は区切りごとに並べて符号化する（[ADR-0002](0002-upload-and-pipeline-orchestration.md)）。AAC は符号化の始めに前置きのサンプル（プライミング）を入れるので、音声を区切りごとに符号化すると、境に無音や重なりができる。
- 動画ごとに音量が大きく違う。視聴者が動画を移るたびに音量を直すのは体験が悪い。音量を上げる正規化は、ピークで歪む。
- [architecture/README.md](../architecture/README.md) の 6 節は、日本語と英語の自動の字幕（VOD だけ）を作り、エンジンは Adapter の裏で `asr-engine-poc` の後に決めるとした。`asr-worker` は GPU のプールにある（[ADR-0001](0001-platform-and-stack.md)）。
- Zoom の題材は Amazon Transcribe を Adapter の後ろに置いた（[Zoom の ADR-0026](../../../zoom/docs/decisions/0026-asr-engine-amazon-transcribe-with-adapter.md)）。Zoom は流れの中の ASR で、この題材は量の多いバッチである。
- アップロードされた音声を学習に使う範囲は法務の確認待ち（[intent.md](../intent.md) の L8）。

## Options

音声：

1. **トラックの全体を 1 回で符号化し、セグメントの境は AAC のフレームの境で切る**
2. 区切りごとに符号化し、前置きを切り詰める

ラウドネス：

- a. **測って値を渡し、再生の側で下げるだけ**
- b. 符号化の時に正規化する
- c. 何もしない

ASR の既定の案：

- x. **GPU で自前でホストする公開の重みのモデル。Transcribe を 2 つ目の実装に**
- y. Amazon Transcribe
- z. 外部の ASR の事業者

## Decision

1、a、x を採用する。詳細は [transcoding-pipeline.md](../architecture/transcoding-pipeline.md) の 7・8 節。

- `audio_encode` は AAC-LC 128 kbps と HE-AAC v1 48 kbps を、トラックの全体から 1 回ずつ作る。4 秒のセグメントは 187 か 188 フレームで、映像の境とのずれは 1 フレーム（約 21 ms）未満でたまらない。
- ITU-R BS.1770 の積分のラウドネスと真のピークを測り、`audio_loudness` に持つ。プレイヤーは -14 LUFS より大きい動画だけを下げる。元の音声は変えない。
- `AsrEngine.transcribe(audio, lang)` の口を置く。既定の案は `asr-worker`（L4）の自前でホストするモデル。費用の目安は 1 時間の音声で約 0.03 USD。Transcribe を 2 つ目の実装として同じ口に置き、`asr-engine-poc` で日本語の文字の誤りの率と費用を比べて既定を確かめる。
- 自動の字幕は推論だけに使い、モデルの学習に使わない（L8 の結論まで）。

### 他の案を選ばなかった理由

- **2（区切りごと）**：前置きの切り詰めは符号化器ごとに違い、継ぎ目の検査（音声のサンプルの数）が不安定になる。音声の符号化は軽く、並べる利点が小さい。
- **b（符号化の時に正規化）**：元の音声を変える。創作者の意図（静かな場面）を壊し、値を変えると全部を作り直す。
- **c（何もしない）**：動画を移るたびに音量が跳ねる。
- **y（Transcribe）**：量の多いバッチで、分あたりの価格（**未検証**）が GPU の自前より重いと見込む。PoC で比べる。
- **z（外部の事業者）**：利用者の音声を外へ出す契約の問題が増える（L5・L8）。

## Consequences

- 良くなること：
  - 音声の継ぎ目が出ない。
  - 音量の揃えを、元の音声を変えずに行える。
  - ASR の費用を GPU の単価で抑え、エンジンを口の後ろで替えられる。
- 引き受けるコスト：
  - 12 時間の動画の音声の符号化は 1 つの作業で、並べられない（数分で終わる）。
  - ASR のモデルの GPU の運用（イメージ、重みの更新、評価）を持つ。

## Confirmation

- 黄金の動画：音声のサンプルの数が元と一致、音声と映像のずれ 20 ms 以内（[quality.md](../quality.md) の 2.2.1 節 A）。
- ラウドネスの値を、試験の信号（既知のラウドネスの合成の音）で確かめる。
- `asr-engine-poc`：評価の音声の集まりで、日本語の文字の誤りの率と費用を比べる。
