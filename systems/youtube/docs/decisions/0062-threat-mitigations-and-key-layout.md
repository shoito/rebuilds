# ADR-0062: 信頼しない入力を復号する部品をすべて「信頼しないメディア」の実行の形で動かし、鍵はデータの種類ごと・リージョンごとの KMS の鍵にし、署名の鍵は 2 つを並べて 30 日で回す。悪用の分かったエッジのトークンは KeyValueStore の `t:` で個別に拒む

## Context

- アップロードのファイルとライブの流れは、復号器（libavformat・libavcodec、NVDEC）の脆弱性を突く入力になりうる。[ADR-0012](0012-media-probe-and-admission-checks.md) は検査（`probe`）をネットワークのない隔離した作業者にしたが、`encode-worker`・`fingerprinter`・`asr-worker`・`live-ingest`・`live-transcoder` も同じ入力を復号する。
- 預かった動画（元のファイル、メンバー限定の動画）、DRM の内容の鍵、生の IP アドレス、電話番号は、漏れたときの被害の種類が違う。
- エッジのトークンは `video_id` に結び付き、視聴者に結び付かない（[ADR-0025](0025-edge-token-signing-and-cache-keys.md)）。抜き取ったトークンで他のサイトが 6 時間まで再配信でき、措置の拒否の一覧（`b:`）は動画の単位で、トークンの単位で止められない。
- KeyValueStore は関数に 1 つ、5 MB（[CloudFront Quotas](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html)、2026-10-10 に確認）で、HMAC の鍵と措置の拒否の鍵と共有する。

## Options

実行の形：

1. **復号するすべての部品に同じ「信頼しないメディア」の形を当てる**
2. 検査だけを隔離し、検査を通ったファイルは信頼する

鍵：

- a. **データの種類ごと・リージョンごとのカスタマー管理の KMS の鍵**
- b. 1 つの KMS の鍵

トークンの悪用：

- x. **悪用の分かったトークンを KeyValueStore で個別に拒む**
- y. トークンを視聴者に結び付ける（キャッシュの鍵から外す前提を変える）
- z. 何もしない（転送の費用として受け入れる）

## Decision

1、a、x を採用する。詳細は [security.md](../architecture/security.md) の 3・4 節。

- **信頼しないメディアの実行の形**：media のサブネット（外への経路なし）、IMDSv2・ホップの上限 1、段ごとのタスクのロールと S3 の接頭辞の絞り、非 root・読み取りだけのルート・大きさの上限つきの tmpfs・seccomp の許可リスト（`execve` なし）、許す形式と符号だけで組み立てた FFmpeg（ネットワークのプロトコルと外部の参照を外す）。タスクの定義の検査を CI に入れる。
- **鍵**：`kms-media`、`kms-quarantine`（別のアカウント）、`kms-fp`、`kms-events`（生の IP は 1 時間ごとのデータの鍵）、`kms-aurora`、`kms-cache`、`drm-content`（復号は `packager` と `license-proxy` だけ）、`kms-secrets`、`kms-pii`、`kms-audit`。東京と大阪で別の鍵にし、写しは大阪の鍵で暗号化し直す。人のロールに復号の権限を与えない。
- **署名の鍵**：再生のトークン（Ed25519）、エッジのトークン（HMAC）、Webhook（HMAC）は 2 つを並べて 30 日で回す。
- **トークンの悪用**：CDN のリアルタイムのログの抜き取りで、トークンの `sig` の先頭 16 文字ごとに 1 時間 1 万の要求か 50 の ASN を超えたものを候補にし、確かめた後に `t:{sig16}` をトークンの期限まで置く。エッジの関数は `b:` の後に `t:` を引く。`t:` は同時に 2,000 件まで。

### 他の案を選ばなかった理由

- **2（検査だけ）**：検査は抜き取りの復号で、全フレームを復号する符号化・指紋・ライブの変換で初めて当たる不具合がある。
- **b（1 つの鍵）**：鍵の権限で、元のファイルと DRM の鍵と IP の読み出しを分けられない。
- **y（視聴者に結び付ける）**：トークンをキャッシュの鍵から外す前提（[ADR-0025](0025-edge-token-signing-and-cache-keys.md)）は保つが、視聴者ごとの値を入れると、マニフェストの中の相対のパスの共有（[ADR-0020](0020-manifest-generation-and-capability-classes.md)）と CDN のヒットに影響しうる。公開の動画の守る対象は転送の費用だけなので、個別の拒否で足りる。
- **z（何もしない）**：組織的な再配信で配信の費用が膨らむ。

## Consequences

- 良くなること：
  - 復号器の脆弱性の被害が、1 つのタスクの中に閉じる。
  - 鍵の権限でデータの種類ごとに読める主体を絞れる。
  - 悪用のトークンを数秒で止められる。
- 引き受けるコスト：
  - FFmpeg の組み立てを自前で保守する（許す復号器の一覧）。
  - KeyValueStore の容量を、拒否の鍵とトークンの拒否で分け合う。
  - エッジの関数の確かめが 1 回の引きぶん増える。

## Confirmation

- 構成の検査（CI）：信頼しないメディアの部品のタスクの定義に、外への経路・IMDS・root・書けるルートがない。
- 結合：隔離の作業者から外への接続・IMDS・他の動画の接頭辞への読み出しが失敗する。
- PROP-SEC-002（`b:`・`t:` のどちらかにあるトークンは通らない）。
