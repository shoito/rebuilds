# ADR-0024: 広告はクライアントの側で挿入する。プレイヤーが VMAP と VAST を読み、広告を本編と別に再生する。サーバーの側の挿入（SSAI）は MVP で作らない

## Context

- [architecture/README.md](../architecture/README.md) の 6 節は、MVP の広告を外部の広告サーバー（VAST 4・VMAP）にし、本システムは広告の枠（再生の前・途中・後）、表示の計測、無効なトラフィックの除外を持つとした。
- 挿入の方式には、プレイヤーが広告を別に再生する形（CSAI）と、サーバーが本編のマニフェストに広告のセグメントを差し込む形（SSAI）がある。
- SSAI は、マニフェストが視聴者ごとになり、CDN で共有できなくなる（[ADR-0020](0020-manifest-generation-and-capability-classes.md)）。広告の素材を本編のラダーと同じ形に変換する仕組みも要る。
- 子ども向けの動画など、広告を出さない動画がある（`playable()` の `allow_with: no_ads`、[ADR-0009](0009-single-tenant-and-playable.md)）。

## Options

1. **CSAI：プレイヤーが VMAP・VAST を読み、別の再生で広告を流す**
2. SSAI：`manifest-service` が視聴者ごとに広告を差し込む
3. 両方

## Decision

1 を採用する。詳細は [playback-and-abr.md](../architecture/playback-and-abr.md) の 8 節。

- 再生の API が VMAP の URL（本システムの広告の判断の口）を返し、プレイヤーが読む。VAST・VMAP の読み取りは自前で作る（公開の標準）。
- 途中の枠は、創作者の指定かチャプターの境を、近い 4 秒のセグメントの境に丸める。8 分未満の動画は途中の枠を置かない。
- `allow_with: no_ads` の動画は VMAP を取らない。
- 広告の表示の出来事は `event-collector` に送り、無効なトラフィックの除外は視聴の検証と同じ規則で行う（monetization-and-payouts の領域）。
- 第三者の計測の URL への送信は外部送信として扱う（**法務の確認待ち：L6**）。

### 他の案を選ばなかった理由

- **2（SSAI）**：マニフェストが視聴者ごとになり、CDN の共有と開始の速さを失う。広告の素材の変換の仕組みが要る。広告の妨げの回避の利点は MVP の目標でない。
- **3（両方）**：2 つの経路の計測と試験を持つ。MVP に見合わない。

## Consequences

- 良くなること：
  - 本編のマニフェストとセグメントを全視聴者で共有できる。
  - 広告の不具合が本編の再生を壊さない。
- 引き受けるコスト：
  - 広告と本編の切り替えで、短い黒い画面が出る。
  - 広告の妨げの機能で広告が見えないことがある。テレビの一部の機種では別の再生の切り替えが遅い（端末の試験で確かめる）。

## Confirmation

- 端末の試験：再生の前・途中・後の広告と本編の切り替えで、本編の位置と音量（ラウドネス）が保たれる。
- 表駆動テスト：`no_ads` の動画で VMAP を取らない。
- 開始の時間の集計で、広告の時間が除かれる（DT-QOE-001）。
