# ADR-0004: CMAF の fMP4 で 1 回だけ保存し、HLS と DASH のマニフェストを要求の時に作る。VOD のセグメントは 4 秒。DRM はメンバー限定の動画だけにし、CENC の `cbcs` で暗号化する

## Context

- 端末ごとに配信の形式が違う。iOS・Safari・多くのテレビは HLS、Android と Chrome などは HLS・DASH のどちらも MSE・Media3 で扱える。
- 形式ごとにセグメントを別に保存すると、保存の費用が倍になり、CDN のキャッシュも分かれて外れが増える。
- 長い動画（最長 12 時間）は、セグメントの数が多い。1 セグメント 1 オブジェクトにすると、S3 のオブジェクトと要求の数が膨らむ。
- 公開の動画は誰でも見られる。暗号化は費用（ライセンスの事業者への支払い、再生の開始の遅れ、端末の差）がかかる。有料の作品（メンバー限定）は守る必要がある。

## Options

形式：

1. **CMAF の fMP4 のセグメントを 1 つ保存し、HLS と DASH の両方のマニフェストで配る**
2. HLS の MPEG-TS と、DASH の fMP4 を別に保存する
3. HLS だけ（fMP4）

保存の形：

- a. **レンディションごとに 1 つのファイル（区切りを連ねたもの）と、セグメントの索引。CDN へはセグメントの URL で見せ、オリジンが範囲の読み出しに直す**
- b. 1 セグメント 1 オブジェクト

DRM の範囲：

- x. **メンバー限定の動画だけ**
- y. すべての動画
- z. 持たない

## Decision

1、a、x を採用する。

### セグメント

- VOD：4 秒のセグメント（2 秒の GOP を 2 つ）。全段でキーフレームの時刻を揃える（[ADR-0003](0003-codecs-and-per-title-ladder.md)）。
- ライブ：2 秒のセグメントと 0.5 秒の部分セグメント（[ADR-0006](0006-live-ingest-and-latency.md)）。
- 音声は映像と別のトラック（別のレンディション）にする。字幕は WebVTT のファイル（HLS は字幕の再生リスト、DASH は `AdaptationSet`）。シークの縮小の画像は WebVTT の索引とスプライトの画像。

### 保存の形

- レンディションごとに 1 つの fMP4 のファイル（`init` とセグメントを連ねたもの）を S3 に置き、セグメントごとのバイトの範囲と時刻を索引（`segment_index`、小さなバイナリ）に持つ。
- CDN へは `/<video>/<rendition>/<seq>.m4s` のようなセグメントの URL で見せる。`origin-cache` が索引を引いて S3 の範囲の読み出しに直す（[ADR-0005](0005-cdn-and-origin-strategy.md)）。CDN のキャッシュはセグメントの単位で効く。
- `fast_encode` の段は、全段ができたら新しいファイルで置き換える。マニフェストは索引の世代で切り替え、古いファイルは猶予（24 時間）の後に消す。

### マニフェスト

- `manifest-service` が、要求の時に、索引と動画の状態から HLS（マスターとメディアの再生リスト）と DASH（MPD）を作る。
- 端末の対応（AV1 の復号、画面の大きさ、HDR の可否）を、再生の API が出した再生のトークンから読み、段を選んだマニフェストを返す。マニフェストは短くキャッシュする（VOD 1 時間、ライブはセグメントの長さに合わせる）。
- 段の追加（全段、AV1）は、マニフェストに段を足すだけで、セグメントの URL は変えない。

### DRM

- 対象：メンバー限定の動画（と、MVP の後のレンタル・購入）。公開・限定公開の動画は暗号化しない。
- 方式：CENC の `cbcs`（AES-CBC のパターン）。1 つの暗号化したセグメントで、FairPlay（HLS）、Widevine と PlayReady（DASH・HLS）に配る。
- 鍵：動画ごとの内容の鍵を、本システムの KMS の鍵で包んで Aurora に持つ。ライセンスの発行は、外部の複数の DRM のライセンスの事業者を口（`DrmLicenseProvider`）の裏に置いて使う。ライセンスの要求は、本システムの再生の API が出した短い期限のトークン（`playable()` を通した結果）を条件にする。
- 暗号化は `packager` で行う。同じ動画の公開の範囲が変わったら（メンバー限定 → 公開）、暗号化していない形を作り直す。

### 他の案を選ばなかった理由

- **2（TS と fMP4）**：保存とキャッシュが倍になる。HLS は fMP4 を受ける。
- **3（HLS だけ）**：DASH のほうが扱いやすい端末とプレイヤー（Media3 の一部の機能、テレビの一部）がある。マニフェストは要求の時に作るので、DASH を足す費用は小さい。
- **b（1 セグメント 1 オブジェクト）**：12 時間の動画の 1 段で約 1 万のオブジェクトになり、S3 の PUT と保存の最小の単位の費用が重い。
- **y（すべて暗号化）**：ライセンスの費用と再生の開始の遅れ（ライセンスの往復）を、守る必要のない公開の動画に払う。
- **z（持たない）**：メンバー限定の動画が、URL の共有で漏れる。

## Consequences

- 良くなること：
  - セグメントを 1 回だけ保存し、HLS と DASH で同じキャッシュを使える。
  - 段の追加がマニフェストの変更だけで済む。
- 引き受けるコスト：
  - オリジンに索引の引きと範囲の読み出しの層が要る（`origin-cache`）。
  - DRM の事業者との契約と、端末ごとのライセンスの試験。DRM の再生の不具合は、メンバー限定の動画の開始の失敗に数える。

## Confirmation

- 試験のベクトル：同じセグメントを、HLS（Safari、AVPlayer）と DASH（Media3、MSE）で再生でき、フレームの数と時刻が一致する。
- 適合の検査：CMAF・HLS・DASH の仕様の検査の道具で、作ったマニフェストとセグメントを夜間に確かめる。
- 暗号化の試験：メンバー限定の動画のセグメントが、ライセンスなしで復号できないこと、トークンの期限の後にライセンスが出ないこと。
