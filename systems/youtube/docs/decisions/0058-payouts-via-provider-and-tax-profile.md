# ADR-0058: 支払いは決済の事業者の接続アカウントへの送金で月 1 回（毎月 25 日、1,000 円未満は繰り越し）にし、冪等の鍵は `payout:{party}:{yyyymm}` にする。税の情報を相手ごとに持ち、源泉徴収の率と区分は設定の表に置いて法務の確認の後に値を入れる

## Context

- intent は、支払いを Stripe に似た決済の事業者の送金の機能で月ごとに行うとした。Stripe の題材は、銀行の API での振込と 3 つの照合を設計した（[payouts-and-reconciliation.md](../../../stripe/docs/architecture/payouts-and-reconciliation.md)）。
- 創作者・権利者の本人の確かめと銀行の口座の扱いは、事業者に任せると範囲が小さくなる。
- 消費税とインボイス、国外の相手への源泉徴収は**法務の確認待ち：L7**。
- 本家の支払いの日と下限は公式の資料で確かめられなかった（**未検証**）。

## Options

1. **決済の事業者の接続アカウントへ送金し、事業者が銀行へ入金する**
2. 銀行の API で自前に振り込む（Stripe の題材の形）
3. 支払いを手作業で行う

## Decision

1 を採用する。詳細は [monetization-and-payouts.md](../architecture/monetization-and-payouts.md) の 8・9 節。

- 接続アカウント：本人の確かめと口座は事業者が持ち、本システムは事業者のアカウントの ID と状態だけを持つ。確かめと税の情報が揃うまで支払わない。
- 時機：締め（翌月の 4 営業日）の後、毎月 25 日（休業日なら前の営業日）。1,000 円未満は繰り越す。
- 状態：`scheduled → submitted → paid | failed`、`paid → returned`。失敗と組戻しは逆の仕訳で `payable` に戻し、翌月に回す。
- 冪等の鍵 `payout:{party}:{yyyymm}`。応答が欠けたら同じ鍵で問い合わせ直す。
- 照合：本システムの台帳、事業者の送金、事業者の入金の 3 つを毎日突き合わせる。
- 税：`tax_profiles`（個人・法人、居住、国、適格請求書発行事業者の登録番号、源泉徴収の区分、条約の届出）と `withholding_rules`（区分ごとの率、期間）。値は法務の確認の後に入れる。確認まで率は 0 で、国外の相手への支払いを止める。

### 他の案を選ばなかった理由

- **2（自前の振込）**：本人の確かめと口座の管理、全銀の書式、組戻しを抱える。題材の核でなく、MVP の範囲に重い。
- **3（手作業）**：S1 の相手の数で回らず、二重の支払いを防げない。

## Consequences

- 良くなること：
  - 本人の確かめと口座の情報を持たない。
  - 法務の結論に、設定の値の変更で合わせられる。
- 引き受けるコスト：
  - 事業者の手数料と、接続アカウントの作成の手間が創作者にかかる。
  - 事業者の障害で支払いが遅れる。
