# ADR-0045: 宛先の登録を署名の境界に記録し、待ち時間を境界で数える

## Context

[ADR-0008](0008-withdrawal-pipeline-and-approvals.md) は、出金の宛先を、登録から待ち時間（既定 24 時間。PM の判断待ち P4）を過ぎた許可の一覧に限り、認証の情報の変更の後 72 時間は出金を受けないと決めた。[ADR-0007](0007-signing-service-and-key-custody.md) は、境界がオンラインの部品を信じないと決めた。

許可の一覧と登録の時刻を core の DB だけに置くと、オンラインの側（`wallet-orchestrator`、`app-api`、core の DB）を破った攻撃者は、攻撃者のアドレスを「25 時間前に登録した」と書けば、待ち時間を飛ばせる。利用者のパスキーの確認も、オンラインの側が「確かめた」と言うだけになる。

## Options

1. **宛先の登録と利用者のパスキーの公開鍵を、境界が受けた時刻で境界の記録に残す。出金の依頼には、利用者のパスキーの、出金の内容への署名を添え、境界が確かめる。待ち時間と 72 時間は、境界の記録の時刻で数える**
2. 許可の一覧と時刻を core の DB にだけ置き、境界は依頼の「許可の一覧の中」の印を信じる
3. 1 の時刻の記録だけを持ち、利用者の署名は境界で確かめない

## Decision

1 を採用する。

### 境界の記録

| 記録 | 中身 | 時刻 |
| --- | --- | --- |
| 宛先の登録 | 利用者の ID、資産、アドレス、宛先の種類、登録の時の利用者のパスキーの署名 | 境界が受けた時刻 |
| 宛先の取り消し | 同上の ID | 同上。取り消しはすぐに効く |
| 利用者のパスキーの公開鍵 | 利用者の ID、資格情報の ID、公開鍵 | 境界が受けた時刻。追加の 72 時間は境界の時刻で数える |
| 認証の情報の変更 | パスワードの再設定、メール・電話の変更の事象（identity が送る） | 同上 |

- 出金の依頼には、利用者のパスキーの署名（WebAuthn の challenge を出金の内容 ― 出金の ID、資産、額、宛先 ― の正規の形のハッシュにしたもの）を添える。`policy-verifier` は、境界の記録の公開鍵で確かめ、その公開鍵が 72 時間より前に記録されたことを確かめる。
- 宛先の種類 `user_allowlisted`（[ADR-0035](0035-signing-policy-bundle-and-decision-table.md) の方針の列）は、境界の記録で、登録から待ち時間を過ぎ、取り消されていない宛先である。
- 最初のパスキーの登録（口座の開設の時）は、本人確認の後に identity が境界に送る。72 時間の数え方は、最初の登録にも当てる（口座の開設から 72 時間は暗号資産の出金を受けない）。
- 境界の記録の変更（宛先の登録、パスキーの追加）を受けたら、境界は利用者への知らせの依頼を、通知の経路とは別の経路（境界の記録を読む `custody-notifier`）からも出す。オンラインの側が知らせを握りつぶしても、利用者に届く。

### 他の案を選ばなかった理由

- **2**：オンラインの側の 1 つの侵害で、待ち時間とパスキーの確認を同時に飛ばせる。境界で方針を確かめ直す意味が薄れる（ADR-0007 の案 2 と同じ弱さ）。
- **3**：時刻は守れるが、オンラインの側が攻撃者のアドレスを利用者の名で登録し、24 時間待てば出せる。利用者の署名を要すれば、利用者の端末のパスキーも要る。

## Consequences

- 良くなること：
  - オンラインの側を破っても、利用者のパスキーなしに新しい宛先へ出せず、パスキーを足しても 72 時間待つ。その間に知らせと異常の検知が働く。
- 引き受けるコスト：
  - 境界が、利用者ごとの公開鍵と宛先の記録（S1 で 30 万口座）を持つ。境界の記録は個人のデータを含まない（ID、公開鍵、アドレス）。
  - API キー（取引の権限だけ。PM の判断待ち P2）では出金できない形がここでも固まる。P2 で「持たせる」とした場合は、この ADR を見直す。
  - `custody-notifier` の経路を持つ。

## Confirmation

- 性質：任意の操作の列（オンラインの側の記録の書き換えを含む）で、境界の時刻で待ち時間の中の宛先への署名 0。利用者の署名のない、または 72 時間の中の公開鍵の署名の出金の署名 0。
- 表駆動のテスト：DT-POL の P02・P03 の行に、境界の記録の場面（登録の直後、取り消しの後、パスキーの追加の直後）を足す。
- 外部のペンテストで、本体のアカウントの権限から境界の記録の時刻を書き換えられないことを確かめる。
