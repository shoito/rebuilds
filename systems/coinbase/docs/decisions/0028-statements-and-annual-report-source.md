# ADR-0028: 明細は仕訳の射影にし、年間の報告書の計算の方法を legal.* で持つ

## Context

利用者には、取引の明細と、年間の取引の報告書を渡す（[intent.md](../intent.md) の MVP）。

- 報告書の様式、交付、税務署への報告、取得の価額の扱いは、法務の L10 の確認待ちである。2028 年 1 月の施行と報じられた分離課税に向けて、記録の形が変わりうる（**未検証**）。
- 取得の価額の計算には、総平均法と移動平均法がある。どれを使うか、利用者が選べるかは、本システムでは決めない（法務の L10）。
- 明細と報告書が台帳と違うと、利用者の申告を誤らせる。台帳と別に計算すると、食い違いが起きる。

## Options

1. **明細は仕訳の行の射影にし、報告書は明細から作る。計算の方法は `legal.cost_basis_method` で切り替える**
2. 明細と報告書を、注文・約定の記録から別に計算する
3. 報告書は外部の税の計算の提供者に明細を渡して作る

## Decision

1 を採用する。

- 明細（`statement_lines`）は、利用者の口座に触れた仕訳の行を outbox から射影したものにする。正本は仕訳で、明細は作り直せる。
- 年間の報告書は、暦の年（JST）の明細から作る。報告書は、作った時の最後の仕訳の ID、様式のバージョン、計算の方法、要約（ハッシュ）を持つ。同じ範囲から作り直して要約が違えば、差分を財務に回す。
- 計算の方法は `legal.cost_basis_method`（`none`・`total_average`・`moving_average`）で持つ。法務の L10 の結論まで、本番の値は `none` にし、数量と円の受け払いの合計だけを出す。
- 円換算の価格は、約定と販売所の取引はその価格、入出金はその時点の参照の価格（[ADR-0006](0006-wallet-tiers-and-cold-ratio.md)）を明細に記録する。後から価格を引き直さない。
- 3 は、外部の提供者の選定と個人のデータの外部への提供（法務の L11）の結論の後に検討する。

### 他の案を選ばなかった理由

- **2**：台帳と別の計算が生まれ、手数料・端数・拘束の戻しで食い違う。
- **3**：MVP で提供者の選定と個人のデータの提供の論点が増える。

## Consequences

- 良くなること：
  - 明細と報告書が台帳と一致する。照合が要らない。
  - 法務の結論で、計算の方法をコードの書き直しなしに切り替えられる。
- 引き受けるコスト：
  - 結論までは、取得の価額を出せない。利用者は自分で計算する。
  - 明細の行が仕訳の行に比例して増える（[capacity.md](../architecture/capacity.md)）。

## Confirmation

- 性質：任意の仕訳の列で、明細の利用者ごと・資産ごとの和が台帳の残高の変化と一致する。
- 再現：同じ範囲から作り直した報告書の要約が一致する。
- 様式の正解のファイル（法務の L10 の後）は QA と財務が持つ。
