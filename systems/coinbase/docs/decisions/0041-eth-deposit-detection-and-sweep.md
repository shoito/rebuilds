# ADR-0041: ETH の入金を内部の送金まで見つけ、条件で集め直す

## Context

[ADR-0009](0009-deposits-confirmations-and-own-nodes.md) は、ETH の入金を利用者ごとのアドレスで受け、利用者用のホットのウォレットへ集め直すとし、方式を `eth-deposit-sweep-poc` で決めるまで利用者ごとの通常のアドレスを既定にした。次のことが決まっていない。

- ETH は、最上位の取引の `value` だけでなく、契約の中の呼び出し（内部の送金）でも届く。他の交換業者の一括の出金や、スマートウォレットからの送金がこの形である。最上位の取引だけを見ると、届いた入金を見落とす。
- trace にも出ない形で残高が増えることがある（契約の自己破壊による送金など）。
- 集め直しの頻度と額。頻繁だと手数料がかさみ、まれだとネットワークにつながる鍵で管理する残高が大きくなる（[ADR-0006](0006-wallet-tiers-and-cold-ratio.md)）。
- 集め直しの手数料を誰が持つか。

## Options

検出：

1. **最上位の取引と、実行のクライアントの trace の内部の送金の両方で見つけ、集め直しの前にアドレスの残高と突き合わせる**
2. 最上位の取引だけを見つけ、他は利用者の申し出で扱う
3. ブロックごとに全見張りのアドレスの残高の差を取る

集め直し：

- a. **額（0.05 ETH 以上）か時間（記帳から 24 時間、0.005 ETH 以上）の条件で、アドレスごとに 1 つずつ**
- b. 入金ごとにすぐ
- c. 1 日 1 回、全部のアドレスをまとめて

## Decision

1 と a を採用する。詳細は [deposits.md](../architecture/deposits.md) の 6.2 節と 7 節。

- 内部の送金は、失敗していない `CALL` で値を動かした呼び出しを入金にし、取引の中の呼び出しの位置を冪等キーの出力の番号に使う。2 組のノードが同じ trace の結果を返したときだけ `confirming` にする（[ADR-0009](0009-deposits-confirmations-and-own-nodes.md)）。trace の API を持つ実行のクライアントを選ぶことを、`node-ops-poc` の条件にする（[ADR-0048](0048-node-client-diversity-and-upgrades.md)）。
- 集め直しの前に、確定のブロックの時点のアドレスの残高と、記帳済みの入金 ＋ 記帳していない既知の受け取り − 集め直した額 − 払った手数料を比べる。多い分は `unattributed_receipts` に入れ、財務の 2 人の承認で記帳する。少ない分は page（鍵の侵害の疑い。[runbooks/hot-wallet-compromise.md](../runbooks/hot-wallet-compromise.md)）。
- 集め直しの取引の宛先は本システムの利用者用のホットのウォレットに固定し、署名の方針の自動の行で署名する（方針の行は custody-and-keys の領域）。送る額は「残高 − 21,000 gas × `maxFeePerGas`」。
- チェーンの手数料はアドレス自身の残高から払い、`network_fee_expense:ETH` に記帳する。利用者の残高は減らさない。
- 値（0.05 ETH、24 時間、0.005 ETH）は資産の設定でバージョンつきに持ち、`eth-deposit-sweep-poc` で手数料の実績と比べて見直す。契約から作る転送のアドレスの方式（ADR-0009 の (ii)）を選ぶときは、この ADR を置き換える。

### 他の案を選ばなかった理由

- **2**：届いたのに残高に入らない入金が出る。利用者の申し出の調べに CS と財務の時間がかかる。
- **3**：入金の取引の ID と送り手が分からず、スクリーニングとトラベルルールの結び付けができない。突き合わせの手段としてだけ使う（1 の後段）。
- **b**：小さな入金ごとに手数料がかかる。
- **c**：1 日分の入金がネットワークにつながる鍵の残高に残り、ホットの割合の計算で大きくなる。

## Consequences

- 良くなること：
  - 内部の送金の入金を見落とさない。trace に出ない受け取りも突き合わせで見つかる。
  - 集め直しの手数料と、入金のアドレスに残る額の上限を、設定で調整できる。
- 引き受けるコスト：
  - ETH のノードが trace を返す負荷を持つ（ブロックごと、2 組）。
  - 集め直しの手数料を本システムが持つ。
  - 集め直すまでの残高は、ホットの側に数える（ADR-0006）。

## Confirmation

- 性質：PROP-DEP-006（アドレスの残高の等式）。PROP-DEP-002（内部の送金も記帳は 0 か 1）。
- 結合の試験：Ethereum の開発用のチェーンで、契約からの内部の送金、自己破壊による送金、失敗した呼び出しの中の送金（入金にしない）を作る。
- 計測：集め直しの手数料の合計（月）と、集め直しの前の入金のアドレスの残高の合計（10 分ごと）。
