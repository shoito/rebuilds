# ADR-0032: 本システムの持ち分の精算は、不足の向きを 1 時間で、余りを毎日行う

## Context

利用者の財産と本システムの財産は、台帳の口座とチェーンのアドレスで分ける（[ADR-0005](0005-ledger-balances-and-trade-settlement.md)、[ADR-0006](0006-wallet-tiers-and-cold-ratio.md)）。ところが、台帳の持ち主が変わる時に、物（暗号資産、日本円）は同時には動かない。

- 約定の手数料は、利用者用のウォレットと利用者の金銭の口座の中で、本システムの持ち分になる。ADR-0005 は、手数料の暗号資産を日次に本システムのウォレットへ移すと決めた。
- 販売所の買いでは、利用者は本システムの在庫から BTC を受ける（[ADR-0010](0010-brokerage-quotes-and-inventory.md)）。台帳では利用者の BTC になるが、物は本システムのウォレットにある。利用者の財産の置き場所が足りない状態になる。
- 販売所の売りでは逆に、利用者が渡した BTC は利用者用のウォレットにあり、本システムの持ち分になる。本システムが払う日本円は本システムの口座にある。
- 一時の不足をどこまで許すかは、分別管理の規律の論点である（法務の L2・L3。確認待ち）。

## Options

1. **仕訳の行に精算の束の ID を持たせ、精算の待ちを集計する。利用者の財産の不足の向きは 1 時間ごと（閾値で即時）、余りの向きは毎日、差し引いて移す**
2. 販売所の受け入れのたびに、チェーンの上で移す
3. 販売所の在庫を、利用者用のウォレットの中に台帳の口座だけで分けて持つ

## Decision

1 を採用する。

- 本システムの口座と利用者の口座の間の仕訳の行のうち、物が反対の置き場所にあるものを、`settlement_batch_id` が空の行として集計する。
- 利用者の財産の不足の向き（販売所の買いの BTC・ETH、販売所の売りの日本円）は、1 時間ごとに精算する。累計が閾値（既定は円換算 1,000 万円。本システムの値）を超えたら、その時点で精算する。
- 本システムの持ち分の余りの向き（手数料、販売所の売りで受けた暗号資産、販売所の買いで受けた日本円）は、毎日精算する。チェーンの手数料（`network_fee_expense`）は余りから引く。
- 両方向を差し引いて、資産ごとに 1 回の移し替え（暗号資産は `house_wallet` と利用者用のホットのウォレットの間。日本円は本システムの口座と利用者の金銭の口座の間）にする。宛先は互いの許可の一覧のアドレス・口座に固定する（[ADR-0007](0007-signing-service-and-key-custody.md)）。
- 精算の仕訳（`internal_transfer`）を書いたら、対象の行に束の ID を付ける。
- 不足の額と時間を、分別管理の日次の報告に出す。閾値と頻度は、法務の L2・L3 の結論で見直す。

### 他の案を選ばなかった理由

- **2**：販売所の受け入れのたびにチェーンの手数料がかかり、承認の待ちの間も不足は残る。
- **3**：利用者の財産と本システムの財産が同じアドレスに混ざる。AGENTS.md の「混ぜない」に反する。

## Consequences

- 良くなること：
  - 利用者の財産の置き場所の不足が、1 時間と閾値で上限を持つ。
  - 移し替えの数が、販売所の取引の数でなく時間で決まる。
- 引き受けるコスト：
  - 本システムのウォレットのホットに、1 時間分の販売所の受け渡しの在庫を置く必要がある（ネットワークにつながる額の割合の計算には本システムの財産として入らないが、侵害の損失には入る）。
  - 法務の結論で、不足を許さない（受け入れの前に物を移す）となれば、この ADR を置き換える。

## Confirmation

- 性質（PROP-REC-002）：任意の約定・販売所・精算の列で、利用者の財産の全体の等式が成り立ち、精算の後に持ち分の項が 0 に戻る。
- SLI：利用者の財産の不足の額と、最も古い精算の待ちの年齢。閾値か 1 時間を超えたら呼び出す。
- 方針の決定表：精算の移し替えの宛先が許可の一覧の組だけであること。
