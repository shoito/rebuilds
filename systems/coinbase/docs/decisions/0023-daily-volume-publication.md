# ADR-0023: 日々の売買高を約定の記録から作り、台帳と照合してから公表する

## Context

2026 年 7 月に成立した改正法で、日々の売買高などを公表することが入る（[intent.md](../intent.md) の出典。大和総研の解説）。何を、どの単位で、いつまでに、どこに公表するかは、法務の確認待ちである（L1）。

- 公表した値が誤っていると、利用者と当局への誤った情報になる。公表した後に黙って書き換えられない。
- 売買高は 2 か所から作れる。エンジンの出力の記録（約定の正本）と、台帳の約定の仕訳（お金の正本）。2 つは一致するはずである（[ADR-0005](0005-ledger-balances-and-trade-settlement.md)）。
- 販売所の取引を売買高に含めるかは、法令の解釈による（L1）。

## Options

1. **出力の記録から作り、台帳の仕訳から作った値と照合し、一致したときだけ公表する。定義は `legal.daily_volume_definition` に置く**
2. 台帳の仕訳だけから作って公表する
3. 出力の記録だけから作って、すぐに公表する

## Decision

1 を採用する（法務の確認待ち L1）。

- 日本時間の 1 日ごと（[ADR-0022](0022-candles-from-sequencer-time.md) と同じ境界）、板ごとに、約定の数、基準の資産の数量、日本円の代金の合計を、出力の記録の `Trade` から作る。
- 同じ値を ledger の `trade` の仕訳から作り、一致を確かめる。販売所を含める定義のときは、`brokerage` の仕訳から販売所の分を別の行として作る。
- 翌日の 0 時 30 分に計算し、照合が一致したら公開の頁と REST に出す。一致しなければ公表を止め、財務とコンプライアンスに知らせる（runbook の候補 `daily-volume-mismatch.md`）。
- 公表した値は書き換えない。訂正は新しいバージョンとして、理由と一緒に出す。
- `legal.daily_volume_definition`（含める取引、単位、公表の時刻）は、L1 の結論まで本番で有効にしない。それまでは計算と照合だけを毎日回す。

### 他の案を選ばなかった理由

- **2**：台帳の記帳の欠けと遅れ（NFR-005 の欠けの見張りの外のもの）を、公表の前に見つけられない。
- **3**：記帳の欠けや出力の欠けを持ったまま公表しうる。

## Consequences

- 良くなること：
  - 公表の値が、約定の正本とお金の正本の両方で裏付けられる。
  - 公表の前に、記帳の欠けを毎日もう一度見つけられる。
  - 定義の違い（販売所を含めるか）を、コードを書き直さずに切り替えられる。
- 引き受けるコスト：
  - 照合が合わない日は公表が遅れる。
  - L1 の結論で、単位や時刻が変わると、公表の頁と API の形を足すことになる。

## Confirmation

- 性質（PROP-MD-5）：任意の約定の列で、出力の記録からの値と台帳からの値が一致する。記帳の欠けを入れた列では公表が止まる。
- 設定の検査：`legal.daily_volume_definition` が無効の間、公表の経路が動かない（[quality.md](../quality.md) の 1 節のリスク 12）。
