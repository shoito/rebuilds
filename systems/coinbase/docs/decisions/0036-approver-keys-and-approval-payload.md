# ADR-0036: 承認者の鍵を専用の機器に置き、承認は取引の中身に署名する

## Context

[ADR-0007](0007-signing-service-and-key-custody.md) は、境界の `approval-verifier` が承認者の署名（端末のパスキーかハードウェアの鍵）を確かめ、承認者の公開鍵の一覧は方針と同じ手順でだけ変わると決めた。ここでは次を決める。

- 承認者の鍵をどこに置くか。
- 承認者が何に署名するか。
- 承認の期限と、承認者の一覧の変更の手順。

承認者の端末と承認の画面は、狙われやすい。画面に出た宛先と、署名される取引の宛先が違えば、承認は意味をなさない。

## Options

1. **承認者ごとに会社が配る FIDO2 のハードウェアの鍵を使い、承認の内容（出金の ID、資産、額、宛先、束の ID、期限）の正規の形のハッシュに署名する。境界は、それが取引の中身と一致するかを自分で確かめる**
2. 承認者の普段の端末のパスキー（同期するもの）で、出金の ID だけに署名する
3. 承認の画面の操作（ボタン）を、運用の画面のセッションの記録で承認とみなす

## Decision

1 を採用する。

### 承認の内容

| 項目 | 内容 |
| --- | --- |
| `request_id` | 出金の ID か移し替えの ID |
| `asset`・`amount` | 資産の最小の単位の整数 |
| `destination` | 宛先のアドレス（正規の形） |
| `policy_bundle_id` | 方針の束の ID（[ADR-0035](0035-signing-policy-bundle-and-decision-table.md)） |
| `role` | 承認者の役割（運用、コンプライアンス、財務、セキュリティ） |
| `expires_at` | 承認の期限。署名の時刻から 30 分 |

- 承認の画面は、上の項目を `ops-api` から受けて表示し、FIDO2 の鍵で、項目の正規の形のハッシュを challenge にした署名を作る。
- `approval-verifier` は、署名を承認者の公開鍵で確かめ、項目を、自分で解読した取引の中身（[ADR-0007](0007-signing-service-and-key-custody.md)）と照らす。1 つでも違えば、その承認を数えない。
- 期限を過ぎた承認は数えない。期限までに署名に届かなければ、承認を集め直す。
- 1 つの依頼に同じ承認者を 2 度数えない。依頼の作成者は承認者になれない。同じ承認者が同じ依頼に違う役割で 2 度数えられない。

### 鍵と一覧

- 承認者の鍵は、会社が配るハードウェアの鍵（同期しない。端末から鍵を取り出せない）だけにする。承認者ごとに 2 本（主と予備）を登録する。
- 承認の画面は、会社が管理する専用の端末でだけ開ける（端末の証明。security の領域）。
- 承認者の一覧（公開鍵、役割、有効の期間）の変更は、方針の束と同じく、セキュリティと財務の 2 人の署名で出し、追加は 24 時間の後に有効にする。外す変更（離職、鍵の紛失、侵害の疑い）はすぐに有効にする（[runbooks/hot-wallet-compromise.md](../runbooks/hot-wallet-compromise.md)）。
- 承認者の数は、役割ごとに 3 人以上（休みと交代のため）。

### 他の案を選ばなかった理由

- **2**：同期するパスキーは、承認者の個人のアカウントの乗っ取りで別の端末に移る。出金の ID だけの署名では、画面の宛先が書き換えられても気づけない。
- **3**：運用の画面のセッションが盗まれれば承認になる。境界がその承認を確かめられない。

## Consequences

- 良くなること：
  - 承認の画面や `ops-api` が書き換えられても、承認者が見た内容と違う取引には署名されない。
  - 承認者の鍵が端末の外に出ず、乗っ取りで承認者を増やせない（追加は 24 時間の待ち）。
- 引き受けるコスト：
  - ハードウェアの鍵の配布と管理、専用の端末。
  - 承認の期限（30 分）を過ぎた出金は承認を集め直す手間がある。

## Confirmation

- 性質（[quality.md](../quality.md) の 2.2.1 節 E）：承認の内容と取引の中身が 1 項目でも違う依頼の署名 0。期限の切れた承認、同じ人の 2 度目、作成者の承認を数えた署名 0。
- 表駆動のテスト：承認の内容の各項目の食い違いの行。
- 毎月、承認者の一覧と鍵の使用の記録を見直す（[runbooks/README.md](../runbooks/README.md) の 5 節）。
