# ADR-0026: 販売所の画面に買いと売りの価格とスプレッドを並べて示す

## Context

販売所の値段の差（スプレッド）が分かりにくく、取引所の板との違いも分かりにくい（[intent.md](../intent.md) の Problem）。価格の示し方、説明の義務、広告の規制は法務の確認待ちである（L8・L12）。

- スプレッドは提示の価格の中に含まれ、手数料として別に出ない（販売所は手数料を取らない。[ADR-0027](0027-fee-schedules-and-rounding.md)）。
- 本システムは取引所も持つ。同じ資産を取引所で買えば、利用者の払う額が変わることがある。
- 法務の結論で、出す項目と文言が変わる。

## Options

1. **買いの価格と売りの価格を並べ、その差を円と割合で出す。取引所の直近の価格と入口を同じ画面に出す。項目と文言は `legal.brokerage_display` の設定にする**
2. 押した向きの価格だけを出す
3. 1 に加えて、取引所で同じ数量を買ったときの見込みの額を出す

## Decision

1 を推奨し、法務の L8・L12 の確認を待つ。

- 画面に出すもの：買いの価格、売りの価格、その差（円と割合）、取引所の直近の約定の価格、取引所の画面への入口、提示の期限の残りの秒。
- 価格の上下を色だけで伝えない（[quality.md](../quality.md) の 2.2 節のアクセシビリティ）。
- 出す項目と文言は `legal.brokerage_display` のバージョンつきの設定にする。法務の結論まで、本番の値を有効にしない（販売所の Story の承認は L8 で止まる。intent の表）。
- API の提示の応答にも、`mid`・`spread_bps`・向きの価格を含める。

### 他の案を選ばなかった理由

- **2**：差が利用者から見えず、intent の Problem を解かない。
- **3**：見込みの額は板の状態で変わり、示した額で取引できない。誤解を招く表示になりうる（法務の L8）。

## Consequences

- 良くなること：
  - 利用者が、提示の中の差と、取引所との違いを同じ画面で見られる。
  - 法務の結論で、コードを書き直さずに項目と文言を替えられる。
- 引き受けるコスト：
  - 差が見えるので、スプレッドの広い時間帯に利用者が離れうる。
  - 画面の項目が増える。

## Confirmation

- E2E：販売所の画面で、買いと売りの価格と差、取引所の価格と入口、期限の残りが出る（Playwright、Maestro）。
- アクセシビリティ：axe と VoiceOver・TalkBack で、価格と差が読み上げられる。
- 設定の検査：`legal.brokerage_display` が無効の間、本番の販売所の画面が出ない。
