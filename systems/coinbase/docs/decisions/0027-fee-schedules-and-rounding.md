# ADR-0027: 手数料はバージョンつきの表と ppm の整数で持ち、切り捨てる

## Context

手数料は、約定・暗号資産の出金・日本円の出金で取る。誤りはエラーにならずに、金額の違いとして残る（[quality.md](../quality.md) の 1 節のリスク 6）。

- 約定の仕訳は、買い手は受け取る暗号資産から、売り手は受け取る日本円から手数料を引く（[ADR-0005](0005-ledger-balances-and-trade-settlement.md)）。端数の規則は決めていない。
- 拘束は手数料の上限を切り上げで含める（[ADR-0004](0004-order-entry-holds-and-idempotency.md)）。実際の手数料が上限を超えると、拘束が足りなくなる。

> 2026-11-15 の注記（統合）：ADR-0004 の注記で、拘束に手数料の上限を含めないことにした。手数料は受け取る資産から引くので、拘束の不足は起きない。PROP-LED-003 は「任意の約定で、0 ≤ 手数料 ≤ 受け取る額（買い手は受け取る暗号資産、売り手は受け取る日本円）。`done` の注文の拘束の残りは 0」と読む。下の「実際の手数料 ≤ 拘束の上限」も同じに読み替える。
- 手数料の率は、注文の受け付けの時に `order-gateway` が決め、エンジンの出力に載る（[ADR-0003](0003-matching-rules-and-self-trade-prevention.md)）。表を変えた時に、受け付け済みの注文の扱いを決める必要がある。
- 本家は、メイカーとテイカーの率を 30 日の取引高で段に分ける（[Get fees](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/fees/get-fee)、2026-11-15 に確認）。端数の規則は**未検証**。
- 銀行の振込の手数料（本システムが銀行に払う額）を記帳する口座がない。

## Options

率の表し方：

1. **100 万分率（ppm）の整数**
2. 小数（`numeric(10,8)`）の率

端数：

- a. **実際の手数料は切り捨て、拘束の上限は切り上げ**
- b. どちらも切り上げ
- c. 銀行の丸め（偶数への丸め）

## Decision

1 と a を採用する。

- 表は `fee_schedules` にバージョンつきで持つ。種類は `trade`（板ごとのメイカーとテイカー）、`crypto_withdrawal`（資産ごとの固定の額）、`fiat_withdrawal`（固定の額）。表の変更は財務と PM の承認を要し、`effective_from` の後に受け付けた注文・出金から効く。
- 注文と出金は、受け付けの時の表のバージョンと率を持つ。`ledger-poster` は表を引き直さず、エンジンの出力の率で計算する。
- 実際の手数料 ＝ `floor(受け取る額 × 率 ÷ 1,000,000)`。拘束の上限 ＝ `ceil(…)`。最低の手数料を持たない。負の率（メイカーへの払い戻し）は MVP で持たない。
- 既定の率（本システムの値）：テイカー 1,000 ppm（0.10%。[architecture/README.md](../architecture/README.md) の 2.1 節）、メイカー 500 ppm（0.05%）。段は MVP で 1 つにし、30 日の取引高の段は PM の判断待ち P1 の結論の後に足す。メイカーの率は PM が確かめる。
- 販売所は手数料を取らない。収益はスプレッドである（[ADR-0010](0010-brokerage-quotes-and-inventory.md)）。
- 口座の種類に `bank_fee_expense:JPY` を足し、日本円の出金で銀行に払った振込の手数料を記帳する。利用者から受ける `fiat_withdrawal` の手数料との差を本システムが持つ。

### 他の案を選ばなかった理由

- **2**：TypeScript と Rust と DB で小数の扱いが分かれ、浮動小数点の混入の余地が残る（[AGENTS.md](../../AGENTS.md) の「数量と価格は整数で持つ」）。
- **b**：約定ごとに利用者が 1 単位未満を余分に払う。説明が難しい。
- **c**：上限が実際の手数料を下回る場合が出て、拘束の不足が起きる。

## Consequences

- 良くなること：
  - 実際の手数料 ≤ 拘束の上限が常に成り立つ。拘束の不足が起きない。
  - 表を変えても、受け付け済みの注文の手数料が変わらない。
- 引き受けるコスト：
  - 切り捨ての端数を本システムが負う（約定 1 件で 1 単位未満）。
  - 0.0001% より細かい率は表せない。

## Confirmation

- 性質（PROP-LED-003）：任意の約定で、実際の手数料 ≤ 拘束の上限、手数料 ≥ 0。
- 表駆動のテスト（DT-LED-002）：率・受け取る額・期待する手数料の表。期待する値は QA の正解のファイル。
- lint：`packages/ledger` で浮動小数点の型と `Math.round` を禁止する。
