# ADR-0046: 2 台が一致する高さを合意の頭とし、外部と ID を比べる

## Context

[ADR-0009](0009-deposits-confirmations-and-own-nodes.md) は、自前のノード 2 台（組）が同じ結果を返したときだけ入金を記帳し、外部の提供者は遅れと分かれの見張りにだけ使うとした。「同じ結果」の定義が決まっていない。

- 2 台の頭は、ブロックの伝わり方で数秒から数十秒ずれる。ほぼ同時に 2 つのブロックが掘られると、同じ高さで違うブロックを返す。
- 承認の数を、どちらの頭から数えるかで、記帳の時点が変わる。
- 2 台が同じ網から P2P につながると、2 台がそろって別の鎖に置かれる（孤立させる攻撃）ことがありうる。ADR-0009 の外部の見張りは、頭の遅れだけを見る。
- 比べの規則を、入金・出金・移し替え・照合が別々に書くと、判定がずれる。

## Options

1. **2 台が同じブロックの ID を返す最も高い高さ（合意の頭）と、両方の確定の低いほうでチェーンの姿を決める。承認の数は合意の頭から数える。外部とは頭の差に加えて、合意の頭の近くのブロックの ID を比べ、違えば記帳を止める。規則は 1 つの純粋な関数に置く**
2. 2 台の頭の低いほうから承認の数を数え、ブロックの ID は入金のブロックの高さでだけ比べる
3. 3 台を比べに入れ、多数決で決める

## Decision

1 を採用する。詳細は [chain-nodes-and-confirmations.md](../architecture/chain-nodes-and-confirmations.md) の 4 節。

- 合意の頭：高さ h ≤ min（頭 A、頭 B）で、A と B が h に同じブロックの ID を返す最も高い h。BTC の承認の数は、取引のブロックの高さ d で両方の ID が同じとき、合意の頭 − d ＋ 1。
- ETH の確定：両方の組の確定のブロックの高さの低いほうで、その高さのブロックの ID が両方で同じとき。
- 規則は `packages/chain-view` の純粋な関数にし、`deposit-watcher`・`wallet-orchestrator`・`rebalancer`・照合が同じバージョンを使う。
- 合意の頭が 2 台の頭の低いほうより 2 ブロック（BTC）・32 スロット（ETH）以上低いまま 5 分続いたら、2 台の分かれとして記帳を止める。
- 外部の見張り：1 分ごとに、頭の差（ADR-0009 の止める閾値は変えない）と、合意の頭 − 2（BTC）・確定の高さ（ETH）のブロックの ID を比べる。ID が違えば記帳を止め、page する。外部が応答しないときは記帳を続け、チケットにする。
- 比べに入れるのは各資産 2 台（組）だけ。待機のノードは、Ops の判断で見習いの期間を経て入れ替える。

### 他の案を選ばなかった理由

- **2**：低いほうの頭が、もう一方と違う鎖の上にあっても承認の数が増える。入金のブロックの高さだけの比べでは、その上に積まれたブロックが同じ鎖かを確かめていない。
- **3**：多数決は、1 台の誤りを結果から消すので、クライアントの不具合や孤立を見つけにくい。ノードの台数と費用も増える。

## Consequences

- 良くなること：
  - 承認の数が、2 台が同じと認めた鎖の上でだけ増える。
  - 2 台がそろって別の鎖にいる場面を、外部の ID の比べで止められる。外部の誤りで記帳が進むことはない。
- 引き受けるコスト：
  - 2 台の伝わりの遅れの分、記帳が数十秒遅れる。
  - 外部の見張りの誤り（提供者の分かれ）でも記帳が止まる。止める側に倒す（[ADR-0011](0011-external-providers-boundary.md)）。

## Confirmation

- 性質ベーステスト（`chain-sim`）：PROP-CHN-001（合意の頭はどちらの頭も超えず、ID は 2 台で同じ）、PROP-CHN-002（片方だけのブロックの取引の承認の数は 0）、PROP-CHN-003（外部の値で承認の数・確定が変わらない）。
- 結合の試験：regtest で 2 台を別の鎖に分け、記帳が止まること。外部の模型で ID を変え、記帳が止まること。
- SLI：合意の頭の遅れ、記帳の停止の時間。
