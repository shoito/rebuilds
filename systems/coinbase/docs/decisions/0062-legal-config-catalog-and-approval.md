# ADR-0062: legal.* の値をカタログで持ち、承認の記録なしに本番で効かせない

## Context

- この題材は、法的に未決の値（コールドの割合、信託の額の計算、本人確認の方式、保持の日数、トラベルルールの対象、出金の上限など）を `legal.*` の設定で持ち、法務の結論まで本番の値を有効にしない（AGENTS.md、[ADR-0005](0005-ledger-balances-and-trade-settlement.md)、[ADR-0006](0006-wallet-tiers-and-cold-ratio.md)）。
- 鍵は領域ごとに増える。鍵ごとに、未設定のときに何が起きるか、施行の日・方式の終わりの日といった有効の期間、誰の承認で入ったかが要る。
- 品質のリスクの 12 位は「無効のはずの `legal.*` の値が動く」（[quality.md](../quality.md) の 1 節）。
- 変更の適用は Ops が平日の昼に、法務・財務の承認の記録を添えて行う（[runbooks/README.md](../runbooks/README.md) の 3 節）。

## Options

1. **鍵ごとに L 番号・持ち主・開発の既定・本番の値・未設定の時の振る舞い・有効の期間・承認の記録・GA に要るかを持つカタログを `config/legal/` に置き、読むのは `legalValue(key, at)` だけにする**
2. AppConfig のフラグとして鍵と値だけを持ち、承認は PR の記録に任せる
3. 法務の結論が出たら、値をコードの定数にする

## Decision

1 を採用する。

- カタログの列と 2026-11-15 の一覧は [regulatory-compliance-japan.md](../architecture/regulatory-compliance-japan.md) の 4.1・4.2 節。
- `prod_value` を入れる PR は `approval_ref`（法務・財務の結論の文書の ID）を必須にし、CODEOWNERS（法務、お金の鍵は財務も）の承認でだけマージできる。CI はカタログの検証（型、期間の重なり、`approval_ref` の有無）を通す。
- 読み方：`legalValue(key, at)`。`at` は判定の基準の時刻で、有効の期間から値を選ぶ。本番で空なら `when_unset` を返す。`when_unset` は止める側か緩めない側にする（保持の日数は「消さない」）。
- 判定の記録に、使ったカタログのバージョンを残す。値の変更で過去の判定は変えない。
- lint：カタログにない `legal.` の参照を拒み、値を使う関数の近くの法令の値の数の定数を拒む。
- 適用は 4.4 節の手順（法務の結論 → PR → 承認 → Ops の適用、前後の照合）。適用の記録を `legal_config_changes` に残す。
- GA の判定（E16 の `ga-decision`）は、`ga_required` の鍵の本番の値が揃っていなければ通さない。

### 他の案を選ばなかった理由

- **2**：未設定のときの振る舞いと有効の期間が鍵ごとにばらばらになり、施行の日に合わせた切り替えを前もって入れられない。承認の記録と値の対応を機械で確かめられない。
- **3**：法令の改正と施行のたびにコードを直し、デプロイの時刻が施行の時刻と合わない。結論の前の値がコードに入る誤りを止められない。

## Consequences

- 良くなること：
  - 本番で効いている法令の値ごとに、根拠の文書と承認者が分かる。
  - 施行の日や方式の終わりの日を、前もって入れておける。
  - GA に要る法務の結論の欠けが、検査で見える。
- 引き受けるコスト：
  - カタログの保守と、鍵ごとの `when_unset` の設計が要る。
  - 領域ごとに足した鍵を、工程 3 でカタログに合わせる作業が要る。

## Confirmation

- DT-REG-001（鍵ごとの `when_unset` と、有効の期間の前・中・後の `legalValue`）の表駆動のテスト。
- PROP-REG-001（`approval_ref` のない `prod_value` が読まれる件数 0）、PROP-REG-003（`ga_required` の鍵が空なら GA の検査が落ちる）。
- 本番：日次に、AppConfig の本番の値と `config/legal/` のカタログを比べ、食い違いをチケットにする。
