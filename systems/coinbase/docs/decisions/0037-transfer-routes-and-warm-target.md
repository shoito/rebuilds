# ADR-0037: 移し替えの経路を固定し、ウォームの目標を 2% に置く

## Context

[ADR-0006](0006-wallet-tiers-and-cold-ratio.md) は、`rebalancer` が 10 分ごとに段ごとの残高と目標を比べ、ホットやウォームが目標を超えたらコールドへ、ホットが目標の 50% を下回ったらウォームから補充すると決めた。ホットの目標は利用者の暗号資産の 1%、ホットとウォームの合計は `legal.hot_ratio_max` まで。次が決まっていない。

- ウォームの目標の額。
- どの段からどの段へ移してよいか（経路）と、宛先のアドレスの持ち方。
- 小さな移し替えを繰り返さないための幅。

移し替えの経路は、侵害された部品が「移し替え」の形で資産を外へ出す道にもなる。

## Options

1. **経路を 6 本に固定し、宛先は本システムのウォレットの許可の一覧のアドレスだけにする。ウォームの目標は利用者の暗号資産の 2%、移し替えの最小の額を目標の 10% にする**
2. 段の間を自由に移せるようにし、宛先の確かめだけを置く
3. ウォームの目標を、`legal.hot_ratio_max` からホットの目標を引いた残り（翻訳の資料の値なら 4%）にする

## Decision

1 を採用する。

### 経路

| 経路 | 依頼する者 | 承認（[ADR-0035](0035-signing-policy-bundle-and-decision-table.md) の方針の行） |
| --- | --- | --- |
| ホット → コールド | `rebalancer`（目標を超えた分） | 自動 |
| ウォーム → コールド | `rebalancer`（目標を超えた分） | 自動 |
| ウォーム → ホット | `rebalancer`（ホットが目標の 50% を下回ったとき） | 2 人（運用 1 人と財務 1 人） |
| コールド → ウォーム | 運用者が儀式の予定に入れる | 儀式（[ADR-0034](0034-cold-key-quorum-and-locations.md)）と 2 人 |
| 入金のアドレス → ホット（ETH の集め直し） | `rebalancer`（[ADR-0009](0009-deposits-confirmations-and-own-nodes.md)） | 自動。宛先はその資産の利用者用のホットだけ |
| 利用者用のウォレット → 本システムのウォレット（手数料） | 日次の手数料の移し（[ADR-0005](0005-ledger-balances-and-trade-settlement.md)） | 2 人（財務 2 人） |

- ウォーム → コールドを自動にするのは、ADR-0006 の「目標を超えたらコールドへの移し替えの依頼を自動で作る」に合わせたものである。題材の AGENTS.md は「ウォームとコールドからの移し替え」に 2 人以上の承認を求めており、宛先がコールドに固定された移し替えもそこに含むかが食い違う。どちらに合わせるかは Dev（テックリード）の確認を待つ。

> 2026-11-15 の注記（統合）：次のように分けて、食い違いでないことにした（Dev の承認待ち）。コールド**へ入る**移し替え（ホット → コールド、ウォーム → コールド。目標を超えた分）は、ネットワークにつながる額を減らすので自動にする。ウォームとコールド**から出る**移し替え（ウォーム → ホット、コールド → ウォーム）は、作成者と別の 2 人以上の承認を要する。題材の [AGENTS.md](../../AGENTS.md) の「一人でお金を動かせない」も、この分け方で書き直した。
- これ以外の段の間の経路（ホット → ウォーム、コールド → ホット、本システムのウォレット → 利用者用のウォレット）は方針で拒む。本システムのウォレットから利用者用のウォレットへの補填は、hot-wallet-compromise の後の財務の判断で、別の手順（儀式と 3 人の承認）にする。
- 宛先は、本システムのウォレットの許可の一覧（段、資産、アドレス）にあるものだけ。一覧の変更は方針の束と同じく 2 人の署名で出し、追加は 24 時間の後に有効にする。コールドのアドレスは儀式で作った鍵から導き、儀式の記録と照らしてから一覧に入れる。

### 目標と幅（S1 の既定。ウォレットの方針の設定の値）

| 値 | 既定 |
| --- | --- |
| ホットの目標 `hot_target_ratio` | 利用者の暗号資産の 1%（ADR-0006） |
| ウォームの目標 `warm_target_ratio` | 利用者の暗号資産の 2% |
| ホットの補充の閾値 | ホットの目標の 50%（ADR-0006）。補充はホットの目標の 100% まで |
| 移し替えの最小の額 | その段の目標の 10%。これより小さい超えは次の周期にまとめる |
| ホットとウォームの合計の警告 | `legal.hot_ratio_max` の 80% で警告、超えたら ADR-0006 の止め方 |

- ホットとウォームの合計の目標は 3% で、翻訳の資料の 5% との間に 2 ポイントの余裕を置く。入金の急増、価格の急変（コールドより早く動くわけではないが、ETH のアドレスの集め直しの前の残高が増える）で 5% に近づく時間を短くする。
- 値は `legal.hot_ratio_max` の結論（法務の L2）で見直す。

### 他の案を選ばなかった理由

- **2**：`rebalancer` か `wallet-orchestrator` が破られたとき、「移し替え」の依頼で外のアドレスへ出せる。
- **3**：上限に余裕がなく、入金の急増ですぐに超える。超えたら出金の署名が止まる（ADR-0006）。

## Consequences

- 良くなること：
  - 自動の移し替えの行き先は、本システムのコールドとホットだけになり、移し替えの形での流出の経路がない。
  - ウォームで 1,000 万円を超える出金の多くを、儀式を待たずに払える。
- 引き受けるコスト：
  - ウォームの目標を超えた分はコールドへ戻すので、大きな出金の集中のときはコールドの臨時の儀式が要る。
  - 本システムのウォレットの許可の一覧の運用（追加の 24 時間）。

## Confirmation

- 性質（[quality.md](../quality.md) の 2.2.1 節 G）：任意の入出金と価格の列で、移し替えの宛先は許可の一覧のアドレスだけ。表にない経路の署名 0。`rebalancer` の依頼の後に割合が `legal.hot_ratio_max` 以下に戻る。
- 表駆動のテスト：経路の表の全行と、表にない経路の拒否。
- SLI：段ごとの残高と目標の比（10 分ごと）、移し替えの回数と手数料。
