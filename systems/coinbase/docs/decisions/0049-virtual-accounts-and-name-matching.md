# ADR-0049: 日本円の入金は利用者ごとの口座番号で受け、名義を正規化して照らす

## Context

利用者は銀行の振込で日本円を入れる（[architecture/README.md](../architecture/README.md) の 1.3 節 E）。

- 1 つの口座に全員が振り込むと、振込の依頼人の名義と金額だけで利用者を決めることになり、同姓同名と入力の誤りで取り違える。
- 本人と違う名義の振込（第三者からの振込）は、マネー・ローンダリングの経路になりうる。受けてよいかは法務の L4 の確認待ちである。
- 振込の依頼人の名義は全銀の使用文字（半角カナなど）で届き、本人確認の氏名のカナとは表記が揺れる（全角・半角、小書きの仮名、空白）。
- 銀行の着金の通知は取りこぼしと重複がありうる。銀行の能力（口座番号の払い出しの API、通知、照会）は**未検証**で、提携銀行を選ぶときに確かめる。

## Options

1. **利用者ごとに振込先の口座番号を払い出し、口座番号で利用者を決め、名義を正規化して完全一致で照らす。一致しなければ記帳せず、人が確かめるか組戻す**
2. 1 つの口座で受け、依頼人の名義の前に利用者の番号を入れてもらう
3. 利用者ごとの口座番号で受け、名義は照らさない

## Decision

1 を採用する。

- 本人確認を終えた利用者に、1 つの振込先の口座番号を払い出す。番号は `kyc-vault` に置く。退会の後も再利用しない。
- 着金は通知と入出金の明細の照会の両方で受け、銀行の取引の番号を冪等キーにして 1 回だけ扱う。
- 名義の正規化：全銀の使用文字に寄せ、半角カナにし、小書きの仮名を大きくし、空白を除く。依頼人の名義と、本人確認の氏名のカナを同じ正規化にして完全一致で比べる。似ているもの（1 文字違いなど）を自動で一致と見なさない。
- 遷移の表：

| 状態 | 条件 | 次 |
| --- | --- | --- |
| `notified` | 口座番号で利用者が決まり、名義が一致 | `credited` |
| `notified` | 名義が一致しない | `review` |
| `notified` | 口座番号が使えない（退会、払い出していない） | `returning` |
| `review` | 本人の別の表記（旧姓など）と確かめた。作成者と別の人の承認 | `credited` |
| `review` | 本人と確かめられない、翌営業日を過ぎた | `returning` |
| `returning` | 組戻しが完了した | `returned` |

- `review` と `returning` の間、着金した額は `suspense:bank` に置く。利用者の残高に入れない。
- 第三者からの振込を受けるか、どの表記の違いを本人と認めるかは法務の L4 の結論で決める。結論までは、表記の違いだけを `review` で認め、別の人の名義は組戻しにする。

### 他の案を選ばなかった理由

- **2**：利用者の番号の入れ忘れ・誤りが多く、人の確かめが増える。番号を入れても、名義の照合は別に要る。
- **3**：第三者からの振込を確かめずに記帳する。法務の L4 の結論の前に、止める側に倒せない（[ADR-0011](0011-external-providers-boundary.md) の既定と反する）。

## Consequences

- 良くなること：
  - 利用者の取り違えがなく、名義の違う振込が残高に入らない。
  - 通知の取りこぼしと重複が、記帳の誤りにならない。
- 引き受けるコスト：
  - 口座番号の払い出しと名義の照合ができる提携銀行に限られる（選定の条件）。
  - 表記の揺れの `review` に CS の時間がかかる。組戻しの手数料がかかりうる（**未検証**）。

## Confirmation

- 性質（PROP-FIAT-001）：`bank-sim` の任意の通知の重複・遅れ・取りこぼしで、着金ごとの記帳は 0 か 1。名義が一致しない着金の記帳 0（承認つきの `review` を除く）。
- 表駆動のテスト（DT-FIAT-001）：名義の正規化の決定表。期待する値は QA の正解のファイル。
- 照合：`suspense:bank` の年齢が翌営業日を超えたらチケット。
