# ADR-0011: 外部の提供者をアダプターの後ろに置き、障害の間は止める側に倒す

## Context

交換業者は、自分で作るべきでない機能を、外部の提供者に頼る。

| 機能 | 自分で作らない理由 |
| --- | --- |
| eKYC（書類の読み取り、IC チップ、公的個人認証、顔の照合） | 書類の真贋と顔の照合のモデル、公的個人認証の接続は、専門の提供者の領域。方式は法令で決まる（法務の L4） |
| 銀行（入金の口座番号、着金の通知、出金） | 銀行の免許が要る |
| 信託（利用者の日本円） | 信託銀行の業務である（法務の L3） |
| チェーン分析（アドレスの危険の点） | チェーン全体の取引の分析と、悪用のアドレスの情報の収集は、専門の提供者の領域 |
| トラベルルールの通知 | 相手の交換業者と通知をやり取りするプロトコルは、業界で共有するもの（法務の L5） |
| 参照の価格（複数の取引所の価格の指数） | 他の取引所の価格を集める |
| HSM・MPC | [ADR-0007](0007-signing-service-and-key-custody.md) で扱う |

一方で、何を通し、何を止めるかの判断は、本システムの責任で、規則とテストで確かめたい。提供者の障害の間に、確かめずに通すと、法令の違反と損失になる。

## Options

1. **提供者ごとにアダプターの契約を自前で決め、提供者の結果（点、一致、通知の状態）は入力にし、判定と状態は自前の規則で持つ。障害の間は止める側に倒す**
2. 提供者の製品の判定（通す・止める）をそのまま使う
3. 障害の間は通し、後で確かめる

## Decision

1 を採用する。

### アダプター

- 提供者ごとに `packages/providers/<kind>` に契約（要求、応答、誤りの種類、冪等の鍵、時間切れ）を書き、提供者の実装はその後ろに置く。契約を満たす模型（`kyc-sim`、`bank-sim`、`screening-sim`、`travel-rule-sim`、`price-sim`）を作り、試験と開発は模型で回す。
- 提供者の応答は、元の形を `provider_responses`（core。個人のデータは `kyc-vault` の参照だけ）に残し、正規化した結果を規則に渡す。
- 提供者を 2 つ持てる契約にする。MVP は eKYC・チェーン分析・トラベルルールの各 1 つ、銀行は入金と出金で 1 つ（予備に全銀の形式のファイル。[Stripe の ADR-0018](../../../stripe/docs/decisions/0018-payout-execution-via-banking-partner.md) の形）、参照の価格は 2 つ（片方の障害で販売所を止めないため）。

### 判定（自前）

- 本人確認：提供者の結果（書類の種類、IC の読み取りの成否、顔の照合の点）を、確認の水準の決定表（kyc-and-accounts の領域）に当てて、口座の状態を決める。
- スクリーニング：チェーン分析の点と分類、制裁の一覧との一致を、規則（`packages/compliance-rules`、バージョンつきの規則の表）に当てて、通す・止める（`compliance_review`）・拒むを決める。閾値と規則は、コンプライアンスの担当が承認する（法務の L6）。
- トラベルルール：相手の交換業者が分かるか、通知を送れたか、受け取った情報が揃っているかで、出金と入金の状態を決める（法務の L5）。

### 障害の間の既定

| 提供者 | 障害の間 |
| --- | --- |
| eKYC | 新しい口座の確認を待たせる。既存の口座は止めない |
| 銀行 | 入金の記帳と出金の依頼を待たせる。着金の通知は後から照会で取る |
| チェーン分析 | 暗号資産の入金の記帳と出金の署名を止める（NFR-015）。取引所の板は止めない |
| トラベルルール | 対象の出金の署名を止める。対象外（法務の L5 の結論で決まる）の出金は止めない |
| 参照の価格 | 2 つとも使えなければ販売所の提示を止める。取引所の価格の帯は板の価格で決める |

- 止めた間の待ちは SLI にし、利用者には待ちの理由（「確認中」）だけを出す。

### 他の案を選ばなかった理由

- **2**：判定の基準が提供者の製品の中にあり、決定表とテストで確かめられない。提供者を替えると判定が変わる。
- **3**：制裁の対象への送金や、確認のない口座の取引を、一度でも通すと取り戻せない。

## Consequences

- 良くなること：
  - 判定の規則を、本システムのテストと承認の手順で確かめられる。
  - 提供者を替えても、契約と判定は変わらない。
  - 模型で、エージェントが提供者なしで端から端まで試せる。
- 引き受けるコスト：
  - 提供者ごとのアダプターと模型を持つ。
  - 提供者の障害で、入出金が止まる時間が出る。

## Confirmation

- 契約の試験：提供者の実装ごとに、契約の試験（模型と同じ試験の組）を通す。
- 表駆動のテスト：スクリーニングと本人確認の決定表の全行。
- 障害の注入：提供者ごとの時間切れ・誤りの応答で、上の表の既定どおりに止まること（性質：チェーン分析の障害の間の出金の署名 0）。
