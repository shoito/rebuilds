# ADR-0013: 銘柄の設定をバージョンつきにし、sequencer の入力でだけ変える

## Context

価格の刻み、数量の刻み、最小の数量、価格の帯の幅は、約定の規則の一部である（[ADR-0003](0003-matching-rules-and-self-trade-prevention.md)）。変えると、どの注文が通るかが変わる。

- 設定の変更が、板のどの入力の前に効いたかが決まらないと、再生で同じ結果にならない（[ADR-0002](0002-sequencer-and-event-journal.md)）。
- 板に注文がある間に価格の刻みを変えると、刻みに合わない注文が板に残る。
- `order-gateway` も同じ設定で注文を検査する（[ADR-0004](0004-order-entry-holds-and-idempotency.md)）。エンジンと `order-gateway` の設定がずれる時間がある。
- 1 注文の最大の数量は ADR-0003 で決めていない。桁の誤りの注文（数量の誤り）の被害を、価格の帯だけでは止められない。

## Options

1. **設定をバージョンつきの全体の値にし、`SetConfig` の入力として sequencer を通す。刻みの変更は `halted` の間だけ受ける**
2. エンジンが起動の時に設定のファイルを読み、変更はエンジンの入れ替えで行う
3. 設定を AppConfig のフラグで持ち、エンジンが定期的に読む

## Decision

1 を採用する。

- 設定は `instrument_configs`（core）に、板とバージョンごとの全体の値で持つ。部分の更新をしない。変更は Dev と Ops の 2 人の承認の後に、`ops-api` が `SetConfig` を sequencer に送る（[runbooks/README.md](../runbooks/README.md) の 2 節）。
- エンジンは `SetConfig` を、次の条件を満たすときだけ受け、`ConfigApplied` を出す。満たさないときは `ConfigRejected` を出し、今の設定を変えない。
  - バージョンが今のものより大きい。
  - 価格の刻みと数量の刻みの変更は、板が `halted` で、板の全部の注文が新しい刻みに合う。
  - そのほかの項目（最小・最大の数量、帯の幅、急変の判定、取り消しだけの時間）は、どの状態でも受ける。板にある注文には効かず、その後の注文から効く。
- 1 注文の最大の数量を足す。既定は BTC/JPY 100 BTC、ETH/JPY 1,000 ETH（本システムの値）。
- エンジンの設定が正本で、`order-gateway` は `ConfigApplied` を出力の記録から読んで写しを替える。ずれの間に `order-gateway` が通した注文は、エンジンが新しい設定で拒み、拘束を戻す（[matching-engine.md](../architecture/matching-engine.md) の 4.4 節）。
- スナップショットは今の設定のバージョンと値を持つ（[ADR-0014](0014-output-hash-chain-and-snapshots.md)）。

### 他の案を選ばなかった理由

- **2**：設定の変更のたびにエンジンの入れ替えの手順（板の停止）が要る。帯の幅の見直し（急変の後）が遅れる。どの入力から効いたかが記録に残らない。
- **3**：読んだ時点がエンジンごとに違い、本番と写しで違う設定が効く。決定性を壊す。

## Consequences

- 良くなること：
  - 設定がどの `seq` から効いたかが記録に残り、再生で同じになる。
  - 刻みの変更で、刻みに合わない注文が板に残らない。
  - 数量の桁の誤りの注文を、最大の数量で止められる。
- 引き受けるコスト：
  - 刻みの変更には板の停止が要る（予定した停止の時間に行う）。
  - `order-gateway` の写しのずれの間、エンジンでの拒否が増える。

## Confirmation

- 決定表（DT-ME-4）：状態・項目・板の注文の刻みとの合い方ごとに、受けるか拒むか。
- 性質：任意の `SetConfig` を混ぜた列で、板の注文はどの時点でも今の設定の刻みに合う。`engine-ref` と結果が一致する。
- レビュー：`instrument_configs` の変更は 2 人の承認の記録を持つ。
