# ADR-0022: ローソク足を sequencer の時刻で作り、日の足を日本時間で切る

## Context

ローソク足は、画面と API の利用者が価格の推移を見る主な手段で、税の計算や苦情の調べで「その時刻の価格」の根拠にもなる。

- 足の境界を壁の時計（`md-publisher` の受け取りの時刻）で決めると、部品の遅れや作り直しで、同じ約定が別の足に入る。
- 日の足を UTC で切るか日本時間で切るかで、日本の利用者の「1 日」の値が変わる。日々の売買高の公表（[ADR-0023](0023-daily-volume-publication.md)）とも揃えたい。
- 本家の粒度と日の境界は公式の資料で確かめられなかった（**未検証**）。

## Options

足の時刻：

1. **約定を出した入力の `ts`（sequencer の時刻）で決め、`ts` が足の終わり以上の入力（`Tick` を含む）で確定する**
2. `md-publisher` の受け取りの時刻で決める

日の境界：

- a. **日本時間（UTC+9）の 0 時**
- b. UTC の 0 時

## Decision

1 と a を採用する。

- 粒度は 1 分、5 分、15 分、1 時間、6 時間、1 日。6 時間と 1 日の足は日本時間の 0 時を起点にする（日本に夏時間はないので、境界は固定）。
- 足の時刻は `Trade` を出した入力の `ts` で決める。エンジンの `InputDigest` は `ts` を持ち、`Tick`（[ADR-0012](0012-engine-io-encoding-and-ticks.md)）で静かな板でも 1 秒以内に足が確定する。
- 値は整数で持つ（始値・高値・安値・終値・出来高・代金・約定の数）。約定のない足は作らない。
- 確定した足は core の `candles` に書き、夜間に S3 の出力の記録から作り直して一致を確かめる。
- 取引所の約定だけで作る。販売所の取引は入れない（価格の決め方が違うため）。

### 他の案を選ばなかった理由

- **2**：`md-publisher` の停止と作り直しで、境界の近くの約定が別の足に入る。作り直しの比べができない。
- **b**：日本の利用者の 1 日（0 時〜24 時）と 9 時間ずれる。公表の日（法務の L1）とも合わない見込み。

## Consequences

- 良くなること：
  - 同じ記録から何度作っても同じ足になり、夜間の比べで誤りを見つけられる。
  - 日の足と日々の売買高の日が揃う。
- 引き受けるコスト：
  - UTC の日の足を求める API の利用者には、1 時間の足から作ってもらう。
  - 本家の境界と違う可能性がある（**未検証**）。

## Confirmation

- 性質（PROP-MD-4）：同じ出力の記録から作った足は、何度作っても同じ。
- 試験のベクトル：日本時間の 23:59:59 と 0:00:00 の約定、静かな板での確定（`Tick` だけ）。
- 夜間：前日の足の作り直しと、書いた値の一致。
