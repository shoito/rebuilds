# ADR-0044: 詰まった取引は時間と回数を決めて置き換え、作り直しを確かめで縛る

## Context

[ADR-0008](0008-withdrawal-pipeline-and-approvals.md) は、結果の分からない放送では作り直さず、詰まった取引は同じ入力（BTC）・同じ nonce（ETH）で手数料だけを上げた置き換えだけを許し、別の取引は前の取引が確定しえないとチェーンで確かめた後だけと決めた。次が決まっていない。

- いつ「詰まった」とみなすか、何度まで、いくらまで上げるか。
- 「確定しえない」をどう確かめるか。取引が待ちの取引の置き場（mempool）から消えた（dropped）だけで、確定しえないとみなしてよいか。

## Options

1. **ブロックの数で詰まりを決め、置き換えは 5 回まで、手数料は方針の上限まで。待ちの置き場から消えたことは作り直しの理由にしない。作り直しは、入力か nonce が、この出金の取引でない確定した取引で使われたときだけ**
2. 時間（30 分）で詰まりを決め、回数を決めない
3. 待ちの置き場から消えたら、作り直してよい

## Decision

1 を採用する。

| 規則 | BTC | ETH |
| --- | --- | --- |
| 詰まりの判定 | 放送から 6 ブロック、ブロックに入らず、手数料の率が今の 3 ブロックの見積もりより低い | 放送から 25 ブロック（約 5 分）、ブロックに入らない |
| 置き換えの手数料 | 今の 3 ブロックの見積もりの 1.2 倍（前の取引の手数料の額と率の両方を上回る） | 前の取引の最大の手数料と優先の手数料をそれぞれ 20% 以上上げる（クライアントが求める最小の引き上げは `node-ops-poc` で確かめる。**未検証**） |
| 回数 | 5 回まで。超えたら自動の置き換えを止め、運用の判断（`stuck-withdrawals.md`） | 同じ |
| 手数料の上限 | 方針の P06（表の手数料の 10 倍まで自動）、超えたら P07（運用 1 人の承認）（[custody-and-keys.md](../architecture/custody-and-keys.md) の 6.2 節） | 同じ |
| 結果の分からない放送 | 同じ署名済みの取引を 2 台以上のノードに流し直し、取引の ID で照会する | 同じ |
| 待ちの置き場から消えた | 同じ署名済みの取引（か最後の置き換え）を流し直す。作り直さない | 同じ |
| 作り直してよい条件 | この出金のどの取引（元と置き換え）の入力も、この出金のものでない取引に使われ、その取引が 6 承認に届いた | この出金の nonce が、この出金のものでない取引で使われ、その取引が確定した |

- 作り直しは `broadcast` → `signing` の遷移（[ADR-0042](0042-withdrawal-transition-table.md)）で、新しい取引の署名には、前の取引の確かめの記録（使った取引の ID、承認の数）を依頼に添える。`nonce-and-utxo-guard` は自分でノードに照会して同じ条件を確かめる（[ADR-0007](0007-signing-service-and-key-custody.md)）。
- 本システムの出金の入力が他の取引に使われるのは、本システムの鍵での別の署名しかない。作り直しの条件に当たったら、その事実を侵害の兆しとしてセキュリティに知らせる（[security.md](../architecture/security.md)）。
- ETH のレーン（[ADR-0043](0043-one-transaction-per-withdrawal-and-fee-table.md)）で前の nonce が詰まると後の取引も止まる。詰まりの判定はレーンの最も古い取引から当てる。

### 他の案を選ばなかった理由

- **2**：回数の上限がないと、手数料の急騰で置き換えを繰り返し、払う手数料が上限まで膨らむ。ブロックの数のほうが、チェーンの進みに沿う。
- **3**：待ちの置き場から消えた取引も、誰かが流し直せば確定しうる。作り直すと両方が確定し、二重に払う。

## Consequences

- 良くなること：
  - 作り直しの条件が、チェーンの上の確定した事実だけになり、二重の出金の経路がない。
  - 置き換えの回数と手数料に上限があり、手数料の急騰でも費用が膨らまない。
- 引き受けるコスト：
  - 置き場から消えた取引は、流し直しで確定するまで待つ。手数料が上がりきった時期は、利用者の待ちが長くなる。
  - 5 回を超えた取引は人の判断になる。

## Confirmation

- 性質（`chain-sim`）：任意の放送の結果（成功、時間切れ、詰まり、置き場からの消え、置き換え、巻き戻り）で、1 つの出金から確定する取引は 0 か 1。作り直しの条件を満たさない作り直しの署名 0。宛先・額の違う置き換えの署名 0。
- 結合の試験：bitcoind の regtest と Ethereum の開発用のチェーンで、低い手数料の取引を詰まらせ、置き換えと置き場からの消えを作る。
