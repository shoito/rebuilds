# ADR-0008: 出金をステートマシンにし、許可した宛先と額による承認だけで署名する

## Context

暗号資産の出金は、取り消せない外部への送金である。

- 乗っ取られた口座から、すぐに攻撃者のアドレスへ出される。利用者の端末のマルウェアが、貼り付けたアドレスを書き換える。
- 出金は、スクリーニング（制裁、チェーン分析）とトラベルルールの通知を通らなければ送れない（法務の L5・L6）。
- 放送した取引が詰まる（手数料が低い）。ノードの応答が切れて、放送できたか分からない。ここで新しい取引を作ると、両方が確定して二重に払う。
- 大きな出金は、ホットの残高を超え、ウォームやコールドの署名を待つ（[ADR-0006](0006-wallet-tiers-and-cold-ratio.md)）。

## Options

1. **出金を明示のステートマシンにし、拘束 → スクリーニング → 方針 → 承認 → 署名 → 放送 → 確定の順に、1 つの遷移の関数で進める。宛先は許可の一覧だけ**
2. 宛先を自由に入れられるようにし、新しい宛先だけ追加の確認をする
3. 出金をジョブの連なりにし、各ジョブが自分の判断で進める

## Decision

1 を採用する。

### 状態

| 状態 | 意味 | 次 |
| --- | --- | --- |
| `requested` | 利用者がパスキーで確かめて依頼した | `held` |
| `held` | 拘束（額 ＋ 出金の手数料）を書いた | `screening` |
| `screening` | 制裁・チェーン分析・トラベルルールの判定中 | `policy`、`compliance_review` |
| `compliance_review` | 担当が判断する | `policy`、`rejected` |
| `policy` | 方針の判定（[ADR-0007](0007-signing-service-and-key-custody.md)） | `approving`、`signing`、`waiting_funds` |
| `waiting_funds` | 段の残高が足りず、補充を待つ | `signing` |
| `approving` | 承認を集めている | `signing`、`rejected` |
| `signing` | 署名の境界に依頼した | `broadcast` |
| `broadcast` | 2 台以上のノードに流した | `confirming`、`replacing` |
| `replacing` | 同じ入力・nonce で手数料を上げた取引を作る | `broadcast` |
| `confirming` | チェーンに入り、承認の数を待つ | `completed` |
| `completed` | 閾値に届き、記帳した | — |
| `rejected` | 送らずに終えた。拘束を戻す | — |

- 遷移は `transitionWithdrawal()` の 1 つの関数だけが書く。遷移ごとに `withdrawal_events` に行を足す。遷移の決定表（DT-WD の候補）は withdrawals の領域で確定する。
- `signing` 以降は `rejected` に進めない。送った可能性のある出金を、送らなかったことにしない。

### 宛先の許可の一覧

- 出金の宛先は、利用者が登録した許可の一覧の中にだけ置ける。登録と変更は、パスキーの確認、メールとプッシュの知らせ、待ち時間（既定 24 時間。PM の判断待ち P4）を要する。待ち時間の間は、知らせから取り消せる。
- 登録の時に、宛先の種類（交換業者のアドレス、自分で管理するウォレット）と、トラベルルールの情報（相手の交換業者、受取人）を受ける（法務の L5）。
- パスワードの再設定、端末の追加、メール・電話の変更の後 72 時間は、出金を受け付けない（値は kyc-and-accounts の領域で確定する）。

### 額による承認の段（S1 の既定。本システムの値）

| 1 件の円換算の額 | 承認 | 署名の段 |
| --- | --- | --- |
| 100 万円まで | 自動（方針の中） | ホット |
| 100 万円を超え 1,000 万円まで | 運用者 1 人 | ホット（足りなければウォーム） |
| 1,000 万円を超える | 運用者 1 人 ＋ コンプライアンスか財務の 1 人 | ウォーム（足りなければコールドの儀式） |

- 口座の 24 時間の累計、ホットの 24 時間の累計（[ADR-0007](0007-signing-service-and-key-custody.md)）が上限を超えたら、1 つ上の段の承認に回す。
- 値は withdrawals と custody-and-keys の領域で、財務・Ops・コンプライアンスと確定する。

### 取引の作り直しの規則

- 結果が分からない放送（時間切れ、ノードの誤り）では、取引を作り直さない。同じ署名済みの取引を流し直し、取引の ID でノードに照会する。
- 詰まった取引は、`replacing` で次の形だけを許す。BTC は同じ入力を使い、手数料だけを上げた取引（Replace-by-Fee）。ETH は同じ nonce で、手数料だけを上げた取引。宛先と額を変えない。
- 同じ出金に、別の入力・別の nonce の取引を作ってよいのは、前の取引の入力が別の確定した取引で使われた（BTC）、または同じ nonce の別の取引が確定した（ETH）とチェーンで確かめた後だけ。署名の境界の `nonce-and-utxo-guard` も同じ規則を確かめる。

### 手数料

- 利用者から受ける出金の手数料は、資産ごとの表（バージョンつき）で持つ。チェーンの手数料の見積もりは自前のノード（BTC は手数料の見積もりの RPC と待ちの取引の分布、ETH は基本の手数料と優先の手数料）から作る。
- 実際に払ったチェーンの手数料は `network_fee_expense` に記帳し、受けた手数料との差を本システムが持つ（[ADR-0005](0005-ledger-balances-and-trade-settlement.md)）。

### 他の案を選ばなかった理由

- **2**：乗っ取りの直後の出金と、宛先の書き換えを止められない。
- **3**：どの段で止まっているか、どの段まで進んだら取り消せないかが、ジョブの間に散る。送った可能性のある出金を取り消す誤りが入りやすい。

## Consequences

- 良くなること：
  - 乗っ取りの後の即時の出金と、宛先の書き換えを、許可の一覧と待ち時間で止められる。
  - 二重の出金を、作り直しの規則と署名の境界の守りの 2 段で止められる。
  - 出金の状態と待ちの理由が、利用者と運用に見える。
- 引き受けるコスト：
  - 新しい宛先への出金は、最短でも待ち時間の後になる。
  - 承認の段の分、運用の人の時間が要る。

## Confirmation

- 性質ベーステスト（`chain-sim`）：任意の放送の結果（成功、時間切れ、詰まり、取引の置き換え、巻き戻り）と、利用者・運用の操作の列で、1 つの出金から確定する取引は 0 か 1。許可の一覧の外の宛先の取引 0。`signing` の後に `rejected` になる遷移 0。
- 遷移の決定表の全行を表駆動のテストで確かめる。
- 照合：出金の状態と、チェーンの上の確定した取引と、台帳の記帳を日次で照らす。
