# ADR-0058: 取引の監視は宣言の規則で警告を出し、届出は 2 人で承認する

## Context

交換業者は、取引を監視し、疑わしい取引を届け出る義務を負う。届出の基準と手順、記録の保存の期間は法務の確認待ち（L4）である。次のことを決める。

- 監視の規則をどこに、どの形で書くか。規則は、コンプライアンスが読み、変え、効果を確かめられなければならない。
- 規則を、事象ごとに評価するか、日次でまとめて評価するか。入金から即時の出金（TM-01）は、日次では出金の後に見つかる。
- 警告から届出までの流れと、誰が決めるか。届出は 1 人の判断と誤りに依存させたくない。
- 調べの存在を利用者に知らせないこと。CS の画面からも、理由が漏れてはならない。
- Mercari の題材は、宣言の規則のエンジン（[ADR-0051](../../../mercari/docs/decisions/0051-rules-engine-declarative-tables.md)）と、審査の待ち行列（[ADR-0052](../../../mercari/docs/decisions/0052-review-cases-queues-and-appeals.md)）を設計した。

## Options

1. **Mercari の題材の宣言の規則と待ち行列を引き継ぎ、規則を事象ごと（outbox）と日次で評価し、警告を口座ごとの案件にまとめる。届出は担当の起案と責任者の承認の 2 人。利用者と CS に調べの存在を出さない**
2. 取引の監視の提供者の製品の規則と案件の画面を使う
3. 日次のバッチの SQL だけで警告を作る

## Decision

1 を採用する。詳細は [aml-and-travel-rule.md](../architecture/aml-and-travel-rule.md) の 8 節。

- 規則は `packages/compliance-rules` に宣言の形で置き、[ADR-0055](0055-screening-rule-table-and-human-reject.md) と同じく、影の評価とコンプライアンスの 2 人の承認で有効にする。最初の束（TM-01〜TM-08）の値は aml-and-travel-rule.md の 8.1 節の案で、法務の L4 の確認の後に有効にする。
- 事象ごとの規則は、台帳と入出金の outbox の事象（入金の記帳、出金の依頼、日本円の入出金、約定）を読み、p95 1 分で警告を出す。期間の集計の規則は日次で評価する。
- 警告は、同じ口座の 30 日の中のものを 1 つの案件にまとめる。案件の状態は `open` → `investigating` → `closed_no_action`、または `str_draft` → `str_approved` → `filed` → `closed_filed`。
- 届出の起案（担当）と承認（コンプライアンスの責任者）は別の人。届け出る手段・期限・項目は法務の確認待ち（L4）。
- 調べの間の口座の制限（出金だけ、全部）は、担当が案件ごとに選び、2 人の承認で効かせる。
- 利用者と CS には「コンプライアンスの確認中」の印だけを出し、理由・規則・案件の有無を出さない。案件の画面はコンプライアンスの役割だけが期限つきの権限で開く（[Auth0 の ADR-0056](../../../auth0/docs/decisions/0056-operator-access.md)）。

### 他の案を選ばなかった理由

- **2**：規則と判断の基準が提供者の製品の中にあり、本システムの表とテストで確かめられない（[ADR-0011](0011-external-providers-boundary.md) と同じ理由）。口座・台帳の事象を外へ送る量も大きい。
- **3**：入金から即時の出金のような規則が、出金の後にしか見つからない。規則の変更の効果を、影の評価で数える仕組みがない。

## Consequences

- 良くなること：
  - 規則の変更の影響を本番の前に数えられる。題材をまたいで同じ規則のエンジンを使える。
  - 届出が 1 人の判断に依存しない。判断の記録が案件に残る。
- 引き受けるコスト：
  - 案件の量（S1 で月 300 件の見込み）に合わせたコンプライアンスの体制が要る。
  - 事象ごとの評価の Worker と、日次の集計を持つ。

## Confirmation

- 表駆動のテスト：TM の規則ごとの、当たる・当たらないの境目の入力（額、日数、回数）。
- 性質：案件の状態の遷移で、起案した人と同じ人の承認 0。`filed` の前の `str_approved` の欠け 0。
- レビュー：利用者向けの画面・通知・API の応答に、案件・規則の ID と理由のコードが出ないことを、E2E の検査で確かめる。
