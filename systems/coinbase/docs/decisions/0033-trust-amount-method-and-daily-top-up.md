# ADR-0033: 信託すべき額は方式の型で持ち、毎営業日に不足だけを自動で依頼する

## Context

利用者の日本円は信託の口座で管理する（[ADR-0005](0005-ledger-balances-and-trade-settlement.md)、[AGENTS.md](../../AGENTS.md)）。ADR-0005 は、信託すべき額の計算を `legal.trust_amount_method` の設定にし、法務の L3 の結論まで本番の値を有効にしないと決めた。この ADR は、その設定が取る値と、依頼の規則を決める。

- 信託すべき額の計算（入金の途中・出金の途中の数え方）と頻度、信託までの間の扱いは、法務の L3 の確認待ちである。改正法の後の「顧客の金銭の分別管理・信託」の規律も確かめていない（L1）。
- 出金を銀行に依頼して結果の前の日本円（`fiat_in_transit`）は、利用者の残高からは引いたが、まだ銀行の口座にある。
- 名義の違いで記帳していない着金は、誰かの日本円だが、利用者の残高にない（[fiat-and-banking.md](../architecture/fiat-and-banking.md)）。
- 信託の追加と解約は、信託銀行への依頼で、時刻の締めがある（**未検証**）。

## Options

計算：

1. **方式を `user_balance`・`with_in_transit`・`with_unapplied` の型で持ち、`legal.trust_amount_method` で選ぶ。試験の既定は最も大きい `with_unapplied`**
2. 1 つの式をコードに書く

依頼：

- a. **毎営業日、前日の締めのスナップショットで計算し、不足だけを自動で依頼する。減らすのは財務の 2 人の承認**
- b. 過不足の両方を自動で依頼する

## Decision

1 と a を採用する。

- 方式は 3 つ。`user_balance` は利用者の日本円の残高の和、`with_in_transit` はそれに `fiat_in_transit` を足したもの、`with_unapplied` はさらに記帳していない着金を足したもの。3 つは単調に増える。
- 試験と検証の環境の既定は `with_unapplied`（最も大きい額）にする。本番の値は法務の L3 の結論の後に、法務と財務の承認で入れる。どの方式も、法務の結論で別の式が要れば型を足す。
- 毎営業日、前日の締め（JST 0:00）のスナップショットで計算し、`trust_calculations` に残す。信託の額が足りなければ、その営業日の中に追加の依頼を出す（依頼の流れは fiat-and-banking の領域）。依頼の額は不足の額を 1 万円の単位に切り上げる（本システムの値）。
- 信託の額が多くても自動では減らさない。解約は財務の 2 人の承認で依頼する。
- 本システムの持ち分の日本円は、信託すべき額に入れない（[ADR-0032](0032-house-share-settlement.md) の精算の後の額で数える）。
- 当日の中の入金の急増で、締めの前に不足が大きくなる場合の追加の計算（日中の計算）を持つかは、法務の L3 の結論の頻度で決める。

### 他の案を選ばなかった理由

- **2**：法務の結論で式を変えると、コードの変更とデプロイが要る（ADR-0005 の決定）。
- **b**：信託を減らす依頼は、誤りのときに利用者の金銭の保全を弱める。減らす向きは人が確かめる。

## Consequences

- 良くなること：
  - 法務の結論を、設定の変更で入れられる。
  - 不足の向きの誤りが、利用者の金銭を減らす向きに出ない。
- 引き受けるコスト：
  - 結論までは、本番で信託の自動の依頼を有効にできない（E3 の `trust-instructions` を承認しない）。
  - 最も大きい方式では、本システムの手元の資金が信託に多く回る。

## Confirmation

- 性質（PROP-REC-004）：任意の残高と途中の額で、3 つの方式の額は単調に増える。不足の依頼の額 ≥ 不足の額。自動の依頼で信託の額が減らない。
- 照合：REC-TRUST と信託すべき額の不足を、毎営業日に財務が確かめる（runbooks の R5）。
- `legal.trust_amount_method` の変更は、法務・財務の承認の記録を添えて適用する（[runbooks/README.md](../runbooks/README.md) の 3 節）。
