# ADR-0003: 価格・時間の優先と自己約定の防止を engine-core にだけ書く

## Context

取引所の約定の規則は、利用者が最も強く信じる約束である。規則の誤りは、エラーにならずに、誰かが損をする約定として残る。

- 本家の Coinbase Exchange は、受け付けた順に価格・時間の優先で約定し、約定の価格は板にあった注文の価格である。同じ利用者の注文は約定せず、テイカーの指定で 4 つの防ぎ方を選べる（既定は `dc`）（[Exchange Matching Engine](https://docs.cdp.coinbase.com/exchange/concepts/matching-engine)、2026-11-15 に確認）。
- 規則が複数の場所（エンジン、販売所、テストの道具）にあると、場所ごとにずれる。
- エンジンは決定的でなければならない（[ADR-0002](0002-sequencer-and-event-journal.md)）。
- 誤った価格の注文（桁の誤り）で、板の価格が一瞬で飛ぶことを防ぎたい。

## Options

自己約定の防止の既定：

1. **新しいほう（テイカー）の残りを取り消す（`cancel_newest`）**
2. 古いほう（板の注文）を取り消す（`cancel_oldest`）
3. 小さいほうを取り消し、大きいほうを減らす（`decrement`。本家の既定）
4. 両方を取り消す（`cancel_both`）

誤った価格への備え：

- a. **価格の帯（参照の価格からの幅）の外の注文を拒み、成行は帯の端で止める**
- b. 帯を持たず、相場の急変の検出で板を止める

## Decision

1 と a を採用する。規則は `engine-core` にだけ書く。

### 数と単位

- 価格は「基準の資産 1 単位あたりの日本円の整数」（BTC/JPY なら 1 BTC あたりの円）。数量は基準の資産の最小の単位の整数（satoshi、wei）。
- 銘柄の設定（バージョンつき。sequencer を通る入力で変える）：価格の刻み、数量の刻み、最小の数量、最大の数量、価格の帯の幅。S1 の既定は BTC/JPY が刻み 1 円・数量の刻み 0.0001 BTC・最小 0.0001 BTC、ETH/JPY が刻み 1 円・数量の刻み 0.001 ETH・最小 0.001 ETH（本システムの値）。
- 約定の代金は `floor(価格 × 数量 ÷ 基準の資産の 1 単位)` の円。買い手が払う額と売り手が受ける額は同じ整数で、端数は生まれない側に切る。手数料の端数は ledger-and-balances の領域で決める。

### 注文の種類（MVP）

| 種類 | 期限・条件 | 振る舞い |
| --- | --- | --- |
| 指値 | `gtc`（取り消すまで） | 突き合わせて残りを板に置く |
| 指値 | `ioc`（即時に約定できる分だけ） | 突き合わせて残りを取り消す |
| 指値 | `post_only`（メイカーだけ） | 板の反対側と交差するなら、約定させずに拒む |
| 成行 | 金額の指定（買い）か数量の指定（買い・売り） | 価格の帯の端まで突き合わせ、残りを取り消す |

- 逆指値、期限つき（`gtd`）、全部か取り消し（`fok`）、隠れた注文は MVP に入れない。

### 突き合わせ

- 板は、価格ごとの段を順序の付いた木（`BTreeMap`）で持ち、段の中は `seq` の順の待ち行列で持つ。
- 新しい注文（テイカー）は、反対側の最も良い価格から、同じ価格なら古い順に突き合わせる。約定の価格は板にあった注文の価格である（本家と同じ）。
- 約定ごとに `trade_seq`（板ごとの連番）を付け、メイカーとテイカーの別、注文に付いてきた手数料の率（`order-gateway` が受け付けの時に決めた値）を出力に入れる。

### 自己約定の防止

- 同じ「自己約定の組」（個人は口座、法人は同じ法人の口座の全部）の注文どうしが突き合わさるときに働く。
- テイカーの指定が優先する（本家と同じ）。指定がなければ `cancel_newest`。
  - `cancel_newest`：テイカーの残りを取り消す。それまでに他の利用者と約定した分はそのまま。
  - `cancel_oldest`：板の注文を取り消し、テイカーは次の注文と突き合わせを続ける。
  - `decrement`：小さいほうを取り消し、大きいほうを同じ数量だけ減らす。
  - `cancel_both`：両方を取り消す。
- 本システムの在庫の口座（販売所）の注文も、他の口座と同じ規則に従う（[ADR-0010](0010-brokerage-quotes-and-inventory.md)）。

### 価格の帯

- 参照の価格は、その板の直近の約定の価格と、最良の気配の中値のうち、直近 1 分に更新されたもの。どちらもなければ、運用の操作で入れた値。
- 指値は、参照の価格の上下 10%（既定。銘柄の設定）の外なら拒む。成行は、参照の価格の上下 5% の端で止まり、残りを取り消す。
- 参照の価格が 1 分で 15% 以上動いたら、エンジンは板を `cancel_only` にし、運用に知らせる（値は market-surveillance と matching-engine の領域で見直す）。

### 板の状態

| 状態 | 受ける入力 |
| --- | --- |
| `trading` | すべて |
| `cancel_only` | 取り消しと運用の操作だけ |
| `halted` | 運用の操作だけ（取り消しも受けない） |

- 再開は `halted` → `cancel_only`（既定 5 分）→ `trading` の順にする。板寄せでの再開は MVP の後（intent）。

### 他の案を選ばなかった理由

- **3（本家の既定）**：大きいほうの数量が利用者の知らないうちに減り、板にある注文の意図（数量）が変わる。選べるようにはする。
- **2・4**：板にある注文の時間の優先を、新しい注文が壊す。選べるようにはする。
- **b**：桁の誤りの注文が、止まる前に板を通り抜けて、多くの利用者の注文を不利な価格で約定させる。

## Consequences

- 良くなること：
  - 約定の規則が 1 つの crate にあり、参照の実装と比べるテストの対象がはっきりする。
  - 自己約定の既定が、板にある注文を変えない。
  - 桁の誤りの注文の被害を、帯の中に閉じる。
- 引き受けるコスト：
  - 帯の幅と参照の価格の決め方を、相場の急変のたびに見直す運用が要る。
  - 本家と自己約定の既定が違う（[architecture/README.md](../architecture/README.md) の 1.4 節）。

## Confirmation

- 参照の実装 `engine-ref`（素直な配列の板）と、任意の入力の列で、約定・取り消し・板の状態が一致する（性質ベーステスト。PR で 2,000、夜間で 20 万の列）。
- 性質：同じ自己約定の組の約定 0。約定の価格は板にあった注文の価格。同じ価格の段の約定は `seq` の順。`post_only` の注文はテイカーにならない。帯の外の約定 0。
- 板の状態の決定表（DT-ME の候補）を spec に置き、表駆動のテストで全行を確かめる。
