# ADR-0031: 台帳とチェーンは同じ高さで比べ、途中の項目を一覧で説明する

## Context

台帳とチェーンの照合（ホットとウォームは 1 時間ごと、コールドは毎日。NFR-006）は、流出を最も早く見つける手段である（[runbooks/ledger-reconciliation-mismatch.md](../runbooks/ledger-reconciliation-mismatch.md) の R1）。

- チェーンは動き続け、台帳は承認の数を待って遅れて書く（[ADR-0009](0009-deposits-confirmations-and-own-nodes.md)）。出金も、放送からチェーンに入り `completed` の記帳までの間がある（[ADR-0008](0008-withdrawal-pipeline-and-approvals.md)）。
- 段の間の移し替え（[ADR-0006](0006-wallet-tiers-and-cold-ratio.md)）の途中は、移し元と移し先で記帳の時刻がずれる。
- 時点の揃わない値を比べると、差が常に出て、本当の減りが埋もれる。差を「許す幅」で吸収すると、小さな流出を見逃す。
- 一般の 3 者の照合と仮勘定の形は Stripe の [ADR-0017](../../../stripe/docs/decisions/0017-three-way-reconciliation-with-suspense.md) にある。チェーンの高さと途中の項目は、その形にない。

## Options

1. **自前のノード 2 台が同じブロックの ID を返す高さ h を選び、h の時点のチェーンの残高と、同じ読み取りの時点の台帳と途中の項目を比べる。差の幅を持たない**
2. 台帳の残高とチェーンの最新の残高を比べ、一定の幅（例：手数料の数回分）の差を許す
3. 1 件ずつの突き合わせ（入出金ごとに取引の ID で照らす）だけにし、残高の比べをしない

## Decision

1 を採用する。

- 照合の時点は、2 台のノードが同じブロックの ID を返す高さ h にする。ノードの残高は h の時点で引く。外部の提供者の値は使わない（ADR-0009）。
- 台帳の側は、h を決めた後に 1 つの読み取りのトランザクション（REPEATABLE READ）で、`wallet:*` の口座の残高と、途中の項目（記帳を待つ入金、記帳を止めた入金、`completed` の前の出金、段の間の移し替え、集め直し、巻き戻り）の状態を同時に読む。途中の項目は含まれたブロックの高さを持ち、h より後のものは数えない。
- 期待する残高 ＝ 台帳 ＋ 途中の項目の和。差 ＝ チェーン − 期待する残高。差の幅を持たない（1 satoshi・1 wei の差も差にする）。
- 差が出たら h を 1 ブロック前後にずらして取り直し、2 回続けて同じ差なら説明のつかない差にする。減りは呼び出し、増えは翌営業日に説明がつかなければ `suspense:chain` に置く。
- 1 件ずつの突き合わせ（3）は、残高の比べの差の原因を探すときに使う。

### 他の案を選ばなかった理由

- **2**：幅の中の流出を見逃す。幅をいくつにするかの根拠もない。
- **3**：本システムの知らない取引（鍵の侵害による送金、誤送金）を見つけられない。

## Consequences

- 良くなること：
  - 1 単位の減りでも見つかる。流出の発見が照合の間隔（1 時間）に収まる。
  - 差が出たとき、途中の項目の一覧から原因の候補が分かる。
- 引き受けるコスト：
  - 途中の項目の状態に、含まれたブロックの高さを持たせる必要がある（出金、入金、移し替えのそれぞれの領域）。
  - ノードが食い違う間は照合を見送る（最後の成功の時刻で知らせる）。

## Confirmation

- 性質（PROP-REC-001）：`chain-sim` の任意の入出金・移し替え・巻き戻り・置き換えの列と任意の h で、チェーン ＝ 台帳 ＋ 途中の項目の和。
- 変異の試験（PROP-REC-003）：わざと入れた 1 単位の記録にない減りを、必ず見つける。
- regtest：bitcoind の regtest で、移し替えの途中と巻き戻りを作って照合を回す。
