# ADR-0064: 報告は基準の時刻から作り直せる書き出しにし、提出は人が行う

## Context

- 交換業者は、当局と自主規制団体に報告を出す。分別管理の状況（法務の L2・L3）、協会への月次の取引の状況と不公正取引の措置（L7・L9）、事業報告書や改正法の後の自己資本規制比率（L1）、税の書類（L10）、障害と流出の発生（L13）が候補である。様式、頻度、期限、提出の手段は、この題材では確かめていない（**未検証**）。
- 協会の不公正取引の規則は、措置の発生の報告と月次の報告を求める（[規則](https://jvcea.or.jp/cms/wp-content/themes/jvcea/images/pdf/B10_jvcea202005.pdf) の第 22 条。2020-04-24 一部改正のときのもの）。業界の団体は、協会が会員の注文と取引のデータから売買審査をする方針を示した（[2025-11-26 の WG の資料](https://www.fsa.go.jp/singi/singi_kinyu/angoshisanseido_wg/gijishidai/20251126/02.pdf)）。
- 報告の数は台帳と照合の結果から来る。提出の後に誤りが分かったとき、何を基準にどう作ったかを説明し、作り直せなければならない。
- 税の書類には利用者の個人の項目が要る（`kyc-vault` の `reportSubject`。[ADR-0054](0054-kyc-vault-purpose-api-and-retention.md)）。

## Options

1. **報告ごとにバージョンの付いた定義（材料の関数、様式、型）を持ち、基準の時刻（`as_of`）の時点の値から書き出す。同じ定義と `as_of` から同じ中身のハッシュが出る。作成者と別の 2 人が確かめ、提出は人が行う**
2. 担当者が台帳と画面から表計算で作り、提出する
3. 書き出しから当局・協会の受付へ自動で送る

## Decision

1 を採用する。

- 定義（`report_definitions`）：ID、バージョン、型（`legal.regime`。[ADR-0063](0063-regulatory-regime-switch.md)）、宛先、根拠の L 番号、頻度、材料の関数（読み取りだけ）、様式、持ち主。定義の変更は `config/reports/` の PR で、コンプライアンスと財務の CODEOWNERS。
- 実行（`report_runs`）：定義のバージョン、`as_of`、中身のハッシュ、確かめた 2 人、提出した者、受付の番号。
- 材料は `as_of` 以前の仕訳と、`as_of` の時点の履歴の行から読む。今の値から作らない。
- 照合の差（[runbooks/ledger-reconciliation-mismatch.md](../runbooks/ledger-reconciliation-mismatch.md)）が開いている間は、お金の報告の提出を止める。
- 出力は書き出し専用の S3 の場所に、報告ごとの鍵で暗号化して置き、読む役割をコンプライアンスと財務に限る。
- 提出は人が行い、本システムは外へ自動で送らない。定義の候補の一覧は [regulatory-compliance-japan.md](../architecture/regulatory-compliance-japan.md) の 6.1 節で、どれも法務の確認待ち。

### 他の案を選ばなかった理由

- **2**：作り方が人に残り、同じ数を作り直せない。照合の差を見落としたまま出しうる。
- **3**：提出の手段と様式が確かめられていない。誤った報告を確かめずに外へ出す経路になる。手段が API で決まったら、確かめの記録を条件に別の ADR で検討する。

## Consequences

- 良くなること：
  - 提出した数を、後から同じ定義と時刻で作り直して説明できる。
  - 報告の作り方の変更が、定義のバージョンとして残る。
- 引き受けるコスト：
  - core の状態の履歴（時点の値を読める形）を、報告に使う表で持つ必要がある（data-model の工程で各領域と合わせる）。
  - 2 人の確かめと手の提出の時間が要る。

## Confirmation

- PROP-REG-002（同じ定義のバージョンと `as_of` から、`as_of` より後の書き込みを混ぜても同じハッシュ）。
- 月次の再現の試し：提出の後に作り直し、ハッシュの一致を確かめる。
- レビュー：新しい報告の定義の PR は、根拠の L 番号と材料の関数を書いている。
