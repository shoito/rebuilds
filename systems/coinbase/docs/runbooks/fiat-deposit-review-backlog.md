# Runbook: 日本円の着金の名義の確かめの滞留

- Owner: CS、コンプライアンス、財務
- 対応するアラート: 名義が一致しない着金（`review`）が翌営業日を超えた（チケット）、`review` の件数の急増（チケット）、`returning` の組戻しが終わらない（チケット、財務）
- 最終確認日: 2026-11-15

前提の設計は [ADR-0049](../decisions/0049-virtual-accounts-and-name-matching.md) と [fiat-and-banking.md](../architecture/fiat-and-banking.md) の 5 節。第三者からの振込を受けるか、どの表記の違いを本人と認めるかは法務の確認待ち（L4）で、結論までは、表記の違い（旧姓など）だけを `review` で認め、別の人の名義は組戻しにする。**似ている名義を自動で一致と見なさない。**

## 症状

- 着金の依頼人の名義と、本人確認の氏名のカナ（正規化の後）が一致せず、`review` に入った着金が翌営業日を過ぎても決まらない。
- `review` の件数が急に増えた（正規化の規則の誤り、銀行の名義の形式の変更の兆候）。

## 影響

- その着金は利用者の残高に入らず、`suspense:bank` に置かれる。利用者には入金が反映されていない。
- 記帳していない着金は、信託すべき額の `with_unapplied` に入る（[ADR-0033](../decisions/0033-trust-amount-method-and-daily-top-up.md)）。
- 仮勘定の期限（翌営業日。NFR-006）を外れる。

## 確認

1. 滞留の件数、最も古い着金の経過、額の和。対象は着金の ID と口座の ID と額で見る。名義は金庫の画面でだけ見る（[security.md](../architecture/security.md)）。
2. 急増なら：同じ銀行・同じ時刻帯に偏っていないか。正規化（全銀の使用文字、半角カナ、小書きの仮名、空白）の直近の変更。
3. 1 件ごとに：本人の別の表記（旧姓、法人の略称）の届け、本人確認の記録。

## 対処

1. **本人の別の表記と確かめた**：作成者と別の人の承認で `credited` にする（`fiat_deposit` の仕訳。冪等キーは銀行の取引の番号）。
2. **本人と確かめられない、翌営業日を過ぎた**：`returning` にし、組戻しを依頼する（財務）。利用者に、組戻しと理由を知らせる（文言は法務の確認の後）。
3. **正規化の誤りによる急増**：規則を直すまで、新しい `review` を自動で `returning` に進めない（期限の判定を止める）。直した後に、滞留した分を新しい規則で照合し直す（一致したものも 2 人目の確かめを通す）。
4. **組戻しが終わらない**：銀行に照会する。組戻しの手数料の扱いと API の可否は提携銀行で確かめる（**未検証**）。

## エスカレーション

- 第三者の名義の振込が多い、マネー・ローンダリングの疑い：コンプライアンス（[aml-and-travel-rule.md](../architecture/aml-and-travel-rule.md)）。
- 認めてよい表記の違いの判断に迷う：法務（L4）。結論まで組戻しの側に倒す。

## 事後

- 滞留の原因（人の手の不足、規則、銀行）を記録し、`review` の期限の実績を CS の体制の見直しに使う。
