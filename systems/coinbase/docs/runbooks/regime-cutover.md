# Runbook: 法令の型の切り替え（施行の時刻）

- Owner: コンプライアンス、Ops、法務
- 対応するアラート: 定期作業（改正法の施行の時刻への切り替え。1 回の作業）。切り替えの後の用語・報告・部品の試験の失敗
- 最終確認日: 2026-11-15

前提の設計は [ADR-0063](../decisions/0063-regulatory-regime-switch.md)（`legal.regime` を有効の期間つきの値で持ち、施行の時刻に `psa_exchange` から `fiea_trading` へ切り替える）。型ごとに切り替えるものは [regulatory-compliance-japan.md](../architecture/regulatory-compliance-japan.md) の 5.2 節、手順の骨は 5.3 節。**施行の日、経過の措置、型を増やすかは法務の確認待ち（L1）。**

```mermaid
flowchart LR
    legal["法務が施行の日と<br/>経過の措置を確かめる"]
    stg["検証の環境で<br/>fiea_trading を動かす"]
    prod["本番に<br/>effective_from つきで入れる"]
    edge["施行の前後で<br/>照合と報告の試し"]
    watch["最初の報告まで<br/>毎日の差の確かめ"]
    legal --> stg --> prod --> edge --> watch
```

## 症状

改正法の施行の日が決まり、切り替えの準備に入る。

## 影響

- 切り替えで変わるのは、用語（業の名前、登録の番号の表示、契約の前の書面の文言）、報告の定義、改正法で入る規律の部品（自己資本規制比率の報告、責任準備金の仕訳、日々の売買高の公表、インサイダー取引の規制）である。
- 板と入出金は止めない。切り替えの誤りがあっても、用語と報告を前の型に戻すかを法務と決める。

## 確認

1. 法務の結論の文書：施行の時刻（日本時間）、経過の措置、型の値。
2. 検証の環境で `legal.regime = fiea_trading` にした全部の試験（DT-REG-002：部品が有効か、用語の鍵の全部が両方の型に文言を持つ。E2E：画面の用語、報告の定義の一覧）の結果。
3. 部品の準備（台帳の口座、計算、試験）が `psa_exchange` の間に済んでいるか。
4. 施行の時刻が、凍結の時間帯（月末と月初、年末年始）や予定した板の停止と重ならないか。

## 対処

1. **前もって入れる**：本番に、施行の時刻を `effective_from` にした `fiea_trading` の値を入れる（[legal-config-change.md](legal-config-change.md) の手順。法務の承認つき）。前の値には `effective_to` が付く。
2. **施行の前日**：照合と報告の書き出しの試しを回し、結果を記録する。お知らせと書面の差し替えの準備（文言は法務の確認の後）。
3. **施行の時刻**：`legalValue('legal.regime', at)` が新しい型を返すことを、画面の用語と部品の有効の印で確かめる。切り替えの前後の判定の記録に、使った型のバージョンが残ることを確かめる。
4. **施行の後**：照合と報告の書き出しの試しをもう一度回す。
5. **最初の報告の期日まで**：型ごとの報告の差を毎日確かめる（[regulatory-report-submission.md](regulatory-report-submission.md)）。

### 誤りがあったとき

- 用語・報告の誤り：法務と、前の型に戻すか、文言だけを直すかを決める。戻すときも `legal-config-change.md` の手順で、次のバージョンとして入れる。
- 部品の誤り（準備金の仕訳など）：その部品を持つ領域の Dev と財務。お金の誤りは [ledger-reconciliation-mismatch.md](ledger-reconciliation-mismatch.md)。

## エスカレーション

- 施行の時刻の後に、型に合わない表示や報告が出た：コンプライアンスの責任者と法務。
- 経過の措置の中身が直前に変わった：PM と法務。切り替えの時刻を変えるかを決める。

## 事後

- 切り替えの記録（値のバージョン、時刻、試験の結果）を残す。自主規制の規則の対応の表（`compliance/rule-map.yaml`）の差分を作り、足りない行を Intent に起票する。
