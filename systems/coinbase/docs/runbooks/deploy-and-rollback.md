# Runbook: デプロイとロールバック

- Owner: Ops
- 対応するアラート: デプロイ中の自動ロールバック、デプロイの後の SLO の悪化、エンジンの入れ替えの後の要約の食い違い
- 最終確認日: 2026-11-15

方針は [README.md](README.md) の 3 節。仕組みの詳細は [delivery.md](../architecture/delivery.md)（4.5 節のデプロイの経路、4.6 節のエンジンの入れ替え、4.9 節の設定の束）。予定したエンジンの入れ替えは [engine-swap.md](engine-swap.md)、署名の方針の切り替えは [signing-policy-rollout.md](signing-policy-rollout.md)。

## 症状

- 段階のデプロイ（見張りの口座 → 5% → 25% → 100%）の中で、自動のロールバックが働いた。
- デプロイの後に、受け付けの 5xx・p99、拘束の照合の不一致、記帳の重複・遅れ、方針の判定の食い違い、入金の記帳の停止が悪化した。
- エンジンの入れ替えの後に、写しのエンジンとの要約が食い違った。
- アプリの新しいバージョンのクラッシュのない率が 99.5% を下回った。

## 影響

- Fargate のサービスの段階のデプロイでは、新しい組の割合の利用者に影響する。正しさの指標（照合、記帳、残高）は組で分けられないので、全体に影響しうる。
- エンジンの入れ替えの誤りは、板の全部の利用者に影響する。

## 確認

1. デプロイの記録で、対象のサービス、イメージのダイジェスト、段、ロールバックの理由を見る。
2. 新旧の組の指標を比べる。
3. 同じ時間帯のマイグレーション、フラグ、署名の方針、銘柄の設定、`legal.*` の変更の有無。
4. 正しさの指標が 1 件でも出ていれば、[incident-response.md](incident-response.md) の SEV1 の候補として扱う。

## 対処

1. **フラグで戻せるものはフラグで戻す**（`release.*` を 0% に）。約定の規則・仕訳の型・署名の方針はフラグにしていないので、コードと設定のバージョンを戻す。
2. **Fargate のサービス**：新しい組の重みを 0 にし、前のイメージのタスクで受ける。自動のロールバックが働かなかったときは、デプロイの関門の「戻す」の操作で同じことを行う（Ops の承認）。
3. **マイグレーション**：戻さない。広げる段だけなので、前のイメージが今の DB で動く。縮める段の後は前へ戻さない。
4. **台帳（`ledger`・`ledger-poster`・`reconcilers`）**：単独の日に出しているので、そのサービスだけを前のイメージに戻す。記帳の誤りは打ち消しの仕訳で直す（財務の承認。[ledger-reconciliation-mismatch.md](ledger-reconciliation-mismatch.md)）。
5. **エンジン**：板を止める（[market-halt.md](market-halt.md)）。前のビルドの ID で `engine_build_change` を sequencer に送ってから前のビルドに戻し（[ADR-0074](../decisions/0074-engine-swap-in-planned-halt-window.md)。日次の再生がこの `seq` でビルドを切り替える）、最後のスナップショットと記録から再生して、要約が入れ替えの前の本番と一致することを確かめてから、取り消しだけ → 取引中の順で再開する。入れ替えの後に出た約定は、再生の結果と比べ、違いがあれば IC と Dev のテックリードが扱いを決める。
6. **署名の方針・署名の境界**：ホットの自動の署名を止め、手続き中の依頼が片付くのを待ってから、前の方針のバージョンの束（2 人の承認の署名つき。[ADR-0075](../decisions/0075-signed-config-bundles-for-policies-and-rules.md)）に戻す。前のバージョンへ戻すのも新しい束として出す（緩める向きなら 24 時間の待ちがかかる。[ADR-0035](../decisions/0035-signing-policy-bundle-and-decision-table.md)）。境界の部品は前のイメージに戻し（テックリードとセキュリティの 2 人の承認）、`custody-nonprod` と本番の試験の出金を通してから 2 人の承認で開ける。
7. **設定の束**（規則の表、資産と銘柄の設定）：前のバージョンの束を出し直す。銘柄の設定は sequencer を通した変更の入力で、板の停止の時間の中で入れる。
8. **アプリ**：App Store の段階のリリース・Google Play の段階の公開を止める。修正は臨時のバージョンで出す。
9. **ホットフィックス**：`main` に入れて通常の段で出す。各段の 30 分は Ops の判断で 10 分に縮めてよい。凍結の中は作成者と別の Ops の承認。

## エスカレーション

- 戻しても正しさの指標が戻らない：IC を立て、Dev のテックリードと財務を呼ぶ（SEV1）。
- 守る物（拘束の条件つきの更新、仕訳の釣り合いのトリガー、RLS のポリシー、署名の境界の方針の確かめ）に触れた変更の後の異常：テックリードとセキュリティ（ledger は財務も）。

## 事後

- 自動のロールバックの理由と、CI で捕まえられなかった理由を `changes/` の `intent.md` に起票する。エンジンの食い違いは、縮めた入力の列を再生の固定の列に足す。
- 戻したイメージ・フラグ・方針のバージョンの記録を確かめ、次のデプロイの前に修正を出す。
