# Runbook: 日々の売買高の照合の不一致

- Owner: Ops、財務、コンプライアンス
- 対応するアラート: 公表の前の照合で、出力の記録から作った値と台帳の約定の仕訳から作った値が一致しない（チケット。翌日の 0 時 30 分の計算）
- 最終確認日: 2026-11-15

前提の設計は [ADR-0023](../decisions/0023-daily-volume-publication.md) と [market-data.md](../architecture/market-data.md) の 4.6 節。何を、どの単位で公表するかは法務の確認待ち（L1）で、`legal.daily_volume_definition` の本番の値は結論まで有効にしない。それまでは計算と照合だけを毎日回す。**一致しない値を公表しない。公表した値を書き換えない。**

## 症状

- 日本時間の前日分の、板ごとの約定の数・基準の資産の数量・日本円の代金の合計が、出力の記録の `Trade` と台帳の `trade` の仕訳とで一致しない。
- 販売所を含める定義のときは、`brokerage` の仕訳から作った販売所の行が、販売所の受け入れの記録と一致しない。

## 影響

- その日の公表を止める（公表が有効なとき）。公表の遅れの扱いは法務の L1 の結論による。
- 不一致は、約定の記帳の欠け・重複か、出力の記録の欠けの兆候で、利用者の残高の誤りにつながりうる。

## 確認

1. 板、日付、どの値が、どちらの側で多いか。差の約定の `trade_seq` を突き合わせて特定する。
2. 出力にあって台帳にない約定：記帳の欠け。`ledger-poster` の遅れ・停止の記録。
3. 台帳にあって出力にない約定：記帳の重複か、DR の打ち消しの対象（[disaster-recovery.md](disaster-recovery.md)）か。
4. 日の境界：約定を出した入力の `ts`（sequencer の時刻）で切っているか。台帳の記帳の時刻で切っていないか（[ADR-0022](../decisions/0022-candles-from-sequencer-time.md) と同じ境界）。
5. 見張りの口座（`canary`）の取引を除いているか。

## 対処

1. 公表を保留する（公表が有効なとき）。財務とコンプライアンスに知らせる。
2. **記帳の欠け・重複**：[ledger-reconciliation-mismatch.md](ledger-reconciliation-mismatch.md) の R3 に従って台帳を直す。手で約定の仕訳を書かない。
3. **計算の誤り**（境界、除外の条件）：計算の部品を直し、同じ日を作り直す。
4. 両方の値が一致してから公表する。既に公表した値に誤りが分かったときは、書き換えずに、新しいバージョンとして理由と一緒に訂正を出す（コンプライアンスの承認）。

## エスカレーション

- 当日の中に一致しない：コンプライアンス、法務（公表の遅れの扱い。L1）。
- 記帳の重複が見つかった：SEV1 の候補（[ledger-reconciliation-mismatch.md](ledger-reconciliation-mismatch.md)）。

## 事後

- 原因と訂正の有無を `daily_volume_publications` の記録に残す。縮めた例を照合の回帰に足す。
