# Runbook: 障害の一般の手順

- Owner: Ops（当番）
- 対応するアラート: 個別の手順のないすべての page と、個別の手順から呼ばれたとき
- 最終確認日: 2026-11-15

SLO とアラートの一覧は [README.md](README.md) の 1・4 節。個別の手順があれば、そちらを先に使う。

## 症状

- page が鳴った。または利用者・運用者・提供者・銀行・他の交換業者から、注文できない・約定がおかしい・出金が届かない・入金が反映されない・身に覚えのない出金がある、などの報告が来た。

## 影響

障害の重さ（SEV）を最初の 15 分で決める。迷ったら重いほうにする。

| SEV | 例 | 呼ぶ人 |
| --- | --- | --- |
| SEV1 | 方針の外の署名、ホットの残高の説明のつかない減り、二重の出金、写しのエンジンとの要約の食い違い、使える残高の負、約定の記帳の重複、記帳の後の巻き戻り、個人のデータの漏れの疑い、取引所の全体の停止 | IC（インシデントの指揮）、Dev のテックリード、セキュリティ（署名・漏れ）、財務（資産・台帳）、コンプライアンス（報告の要否）、PM |
| SEV2 | 受け付けの SLO のバーンレート、記帳の遅れ、ネットワークにつながる額の超え、入金の記帳の停止、提供者・銀行の障害、出金の詰まりの急増 | IC、Dev の当番、財務（資産のとき） |
| SEV3 | 配信の遅れ、販売所の提示の停止、1 つの機能の劣化 | Ops の当番 |

## 確認

1. どの SLI が外れているか（[README.md](README.md) の 1 節）。正しさの SLI は、不一致の数と「最後の成功からの時間」の両方を見る。照合や比べが止まっている 0 を正常と読まない。
2. 直近のデプロイ、フラグの変更、署名の方針のバージョン、銘柄の設定、`legal.*` の変更、Terraform の適用。
3. 外部の状況（ノードの頭と外部の見張り、チェーンの混み、提供者、銀行、AWS の Health Dashboard）。
4. 影響の範囲を、ID と数と理由のコードだけで数える。氏名・住所・口座の番号・API キーを調べの記録に書かない。

## 対処

1. **資産と公正さを先に守る。** 正しさの SLI が外れたら、まず止める（止めるのは当番が一人でできる）：
   - 署名・出金の異常：`ops.hot_auto_signing_enabled.<asset>` と `ops.withdrawals_enabled.<asset>` を切る（[hot-wallet-compromise.md](hot-wallet-compromise.md)）。
   - エンジンの食い違い・番号の抜け：板を止める（[market-halt.md](market-halt.md)）。
   - 残高・台帳の誤り：その資産の出金を止め、[ledger-reconciliation-mismatch.md](ledger-reconciliation-mismatch.md) に従う。
   - 入金の異常：`ops.deposit_crediting_enabled.<asset>` を切る（[chain-reorg.md](chain-reorg.md)）。
2. 直近のデプロイが疑わしければ戻す（[deploy-and-rollback.md](deploy-and-rollback.md)）。フラグで戻せるなら先にフラグ。
3. 外部の障害なら、その経路だけを止める（提供者の障害は [ADR-0011](../decisions/0011-external-providers-boundary.md) の既定で止まる。止まっていることを確かめる）。
4. 残高・板・署名の記録を手で書き換えない。直しは決まった入力（sequencer を通す）、決まった仕訳の型、打ち消しの仕訳だけ。
5. 利用者への知らせは、お知らせと状況のページで出す（文言の型は法務の確認の後）。

## エスカレーション

- SEV1 は 15 分以内に IC を立て、30 分ごとに状況を共有する。
- 資産の障害は財務とセキュリティを必ず呼ぶ。当局への報告の要否と時期は、コンプライアンスと法務が判断する（法務の L1・L13）。漏れの疑いは法務（漏えい等の報告の要否は法務の L11）。
- 大阪への切り替えの判断は IC と Ops の責任者（[disaster-recovery.md](disaster-recovery.md)）。
- 止めたものを開けるのは、作成者と別の 2 人の承認（IC と Ops の責任者）。

## 事後

- SEV1・SEV2 は 5 営業日以内に振り返りを書く。調査の結果は ID と数と理由のコードだけで、`changes/` の新しい `intent.md` として起票する（Maintain 段。[quality.md](../quality.md) の 4.3 節）。
- 止めたフラグを戻したこと、照合と比べが 0 に戻ったことを確かめる。
- この手順と個別の手順で足りなかったことを反映する。
