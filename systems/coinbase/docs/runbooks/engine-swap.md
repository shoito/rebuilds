# Runbook: エンジンの入れ替え

- Owner: Ops、Dev のテックリード（種類 B・C は QA も）
- 対応するアラート: 計画作業（予定した板の停止の時間）。停止の時間の中で `cancel_only` に入れない（page）、入れ替えの後の要約の不一致（page）
- 最終確認日: 2026-11-15

前提の設計は [ADR-0074](../decisions/0074-engine-swap-in-planned-halt-window.md)（写しで先に確かめ、`engine_build_change` の入力で入れ替える）、[delivery.md](../architecture/delivery.md) の 4.6 節（状態と戻し方）と 4.11 節（例）。時間帯と凍結は [README.md](README.md) の 3.1 節。**入れ替えは sequencer を通した入力で行い、どの `seq` から新しいビルドが処理したかを記録に残す。**

## 症状

- `engine-core` か `engine-host` の新しいビルドを本番に入れる予定がある（週 1 回まで、1 回の停止 10 分）。
- または、入れ替えの途中で次へ進めない（`verifying` で要約が一致しない、06:10 の時点で `cancel_only` に入っていない）。

## 影響

- 予定した停止の時間（既定は平日の早朝 10 分）、その板の注文と取り消しを受けない。予定した停止は NFR-010 の可用性に数えない。
- 停止の時間を超えると、予定の外の停止になり、可用性の SLO を消費する。

## 確認

1. 変更の種類（A：出力が変わらない、B：規則を意図して変える、C：記録の形を変える）。PR の説明と CODEOWNERS の確かめ。
2. A：写しの `engine-host` を新しいビルドにしてから 24 時間、入力ごとの要約の食い違いが 0（`shadow_testing` → `scheduled`）。
3. B・C：staging で前日の本番の形の生成の列を新旧で再生した差が、意図した違いの一覧と一致することを QA が承認した（`staging_diff` → `scheduled`）。C は、再生の道具が新旧の両方の記録の形を読めるビルドが先に出ている。
4. 2 営業日前までにお知らせを出した。凍結（README の 3.1 節）の外である。
5. `engine_builds` に新しいビルドの ID（バイナリのハッシュ）、記録の形のバージョン、SBOM がある。

## 対処

1. **停止**（`halted_for_swap`）：運用の画面から `halt` の入力を sequencer に送る。エンジンが停止の入力でスナップショットを書いたことを確かめる。
2. **入れ替えの入力**：`engine_build_change`（新しいビルドの ID、記録の形のバージョン）を sequencer に送る。エンジンは状態を変えない。この入力の `seq` を `engine_swaps` に記録する。
3. **起動と確かめ**（`verifying`）：本番の `engine-host` を新しいビルドで起こし、停止のスナップショットを読み、要約が停止の時点と一致することを確かめる。
4. **一致しない**（`rolled_back`）：前のビルドの ID で `engine_build_change` を送り、前のビルドで同じ確かめをする。一致したら次の 5 へ進む。
5. **取り消しだけ**（`cancel_only`）：既定 5 分。その後、2 人の承認で取引中にする。
6. **写し**：A は既に新しいビルドで比べを続ける。B・C は入れ替えと同時に写しを新しいビルドにする。
7. **停止の時間の中で終わらない**：板を止めたままにし、IC を立てる。取引中にしない。前のビルドで再開してから原因を調べる。
8. **翌日**：日次の再生が `engine_build_change` の `seq` でビルドを切り替え、食い違い 0 であることを確かめる。

## エスカレーション

- `verifying` で前のビルドでも一致しない：SEV1 の候補。[market-halt.md](market-halt.md) の 2（どちらが正しいかを決める）に移り、Dev のテックリードを呼ぶ。
- 停止の時間を超える：IC、PM（利用者への知らせ）。

## 事後

- `engine_swaps` に、停止と取引中の時刻、停止の時間を記録する。
- 戻したときは、縮めた入力の列を再生の固定の列に足す（QA の承認）。調査結果を `changes/` の新しい `intent.md` として起票する。
