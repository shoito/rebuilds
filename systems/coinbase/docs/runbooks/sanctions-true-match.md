# Runbook: 制裁の一致の確定

- Owner: コンプライアンス、Ops（当番）、法務
- 対応するアラート: 制裁の照合の「一致」（利用者、トラベルルールの相手、制裁の対象のアドレス）をコンプライアンスが確かめた（page）
- 最終確認日: 2026-11-15

前提の設計は [ADR-0056](../decisions/0056-sanctions-name-matching-inside-vault.md)（金庫の中の名前の照合）、[ADR-0055](../decisions/0055-screening-rule-table-and-human-reject.md)（規則の表。拒むのは人だけ）、[ADR-0052](../decisions/0052-account-lifecycle-levels-and-restrictions.md)（制限の行）。照合の流れは [aml-and-travel-rule.md](../architecture/aml-and-travel-rule.md) の 6 節。

**当局への報告、凍結した資産の扱い、対象にする一覧は法務の確認待ち（L6）。** この手順は、止めることと記録を残すことだけを決める。結論が出たら、報告の手順を足す。

## 症状

- `sanctions_matches` の行が `candidate` から `confirmed` になった（照合の点と、生年月日・国籍での絞りの後に、コンプライアンスの担当が確かめた）。
- 制裁の対象のアドレスとの直の取引（入金の送り元、出金の宛先）を規則の表が `priority_review` にし、担当が確かめた。

## 影響

- その口座は `frozen` になり、取引・入出金がすべて止まる。未約定の注文は取り消される。
- 利用者と CS には理由を出さない（「確認中」の一般の文言。調べの間の利用者への説明は法務の確認待ち）。

## 確認

1. 一致の種類（利用者の名前、トラベルルールの相手、アドレス）、一覧のバージョン、点。照合の記録は ID と点と一覧のバージョンだけで、氏名は金庫の外に出さない。
2. その口座の残高、手続き中の注文・出金・入金。出金が `signing` を過ぎていないか。
3. 同じ人（`person_key`）や結び付いた口座（`account_links`）があるか。

## 対処

1. **止める**：コンプライアンスの担当が口座に `frozen`（`sanctions_match`）を立て、2 人目のコンプライアンスの担当が承認する。`identity` が未約定の注文の取り消しを依頼し、写しを消す。
2. **手続き中の出金**：`signing` の前の出金は `compliance_review` から `rejected` にせずに止めたまま残す（拒む判断と資産の扱いは L6 の後）。`signing` を過ぎた取引は止められないので、取引の ID と額を記録する。
3. **入金**：その口座への入金は、検出と追跡を続け、記帳しない（DT-KYC-001 の `frozen` の行）。日本円の着金は記帳してから拘束の口座に移す。
4. **アドレスの一致**：宛先の登録を `suspended` にする。入金の送り元の一致なら、その入金の記帳を止め、`compliance_review` に入れる。
5. **案件**：`compliance_cases` に案件を開き、判断の記録（理由のコード、判断した人、規則と一覧のバージョン）を残す。
6. **法務に知らせる**：案件の番号、一致の種類、止めた資産の額を、その日のうちに法務に渡す。

## エスカレーション

- `signing` を過ぎた出金があった、結び付いた口座で同じ時期に大きな出金があった：コンプライアンスの責任者、法務、IC。
- 一致の誤り（同姓同名など）が確かめられた：2 人の承認で `confirmed` を `dismissed` に変え、`frozen` の行を外す（[account-restriction-release.md](account-restriction-release.md)）。外した理由を記録する。

## 事後

- 一致から凍結までの時間、止めた資産、取り消した注文を記録する。
- 照合の閾値（「一致」と「候補」）は、影の評価と 2 人の承認で見直す（[aml-and-travel-rule.md](../architecture/aml-and-travel-rule.md) の 5.3 節）。
