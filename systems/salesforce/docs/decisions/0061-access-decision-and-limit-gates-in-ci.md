# ADR-0061: 決定表・性質・上限・漏えいの経路を CI の関門にし、上限の登録簿は設計の記録の governor-limits.md と機械的に比べる

詳細は [delivery.md](../architecture/delivery.md) の 2 節と 3 節。

## Context

systems/salesforce の AGENTS.md は、開発リポジトリで次を守るとした。

- アクセス制御の規則は決定表（`DT-*`）で書き、表駆動テストは `spec.md` から表を直接読む。
- 共有の変更には性質ベーステスト（参照の評価器との一致、新旧の世代が混ざらない）を付ける。
- 上限を足す・変える変更には上限の試験を付け、値を緩めて通さない。

[ADR-0041](0041-limits-registry-and-counting-rules.md) は、上限の正本を開発リポジトリの登録簿と governor-limits.md の一覧にし、CI で一致を検査するとした。[ADR-0051](0051-leak-path-register-and-threat-model.md) は、漏えいの経路の登録簿の全ての行にテストの ID を求めた。

設計の記録（rebuilds）と開発リポジトリは別のリポジトリである（[リポジトリ共通の ADR-0005](../../../../docs/decisions/0005-design-record-repository.md)）。一致の検査を、どちらのリポジトリの CI で、どの向きに行うかを決める必要がある。

## Options

上限の一致：

1. **開発リポジトリの CI が、rebuilds の `main` の governor-limits.md を読み、登録簿から作った表と比べる。食い違ったら失敗。値を変える時は、rebuilds の PR を先にマージする**
2. 開発リポジトリに文書の写しを持ち、写しと比べる
3. 登録簿から rebuilds の文書を自動で書き換える

関門の重さ：

- a. **PR ごとに速い組（決定表の全行、性質ベーステスト 1,000 通り、上限の試験の全て、漏えいの経路のテスト）。夜間に重い組（性質ベーステスト 10 万通り、負荷の小さな回帰）**
- b. 全てを PR ごとに回す

## Decision

1 と a を採用する。

- 上限の一致の検査は、rebuilds のリポジトリを読むだけの権限で取り出し、governor-limits.md の 4.1 節と 6 節の表を読み、`id`・値・`scope` を登録簿と比べる。rebuilds の側で値を変えた PR がマージされ、開発リポジトリがまだ古い時も失敗する（どちらの遅れも見つける）。
- 失敗の文言に、直す向き（設計を先に直す）を書く。緊急の値の変更（本番の障害）は、開発リポジトリで先に変え、24 時間以内に rebuilds を直す例外を許し、例外の一覧に期限を付けて持つ。
- 決定表の検査：`specs/` と進行中の `changes/` の全ての `DT-*` の表を読み、行ごとにテストが 1 つ生まれることと、テスト名に `DT-XXX-NNN #行` があることを確かめる。表の行が増えてテストが増えない時に失敗する。
- 性質の検査：`PROP-SHR-*`・`PROP-RPT-*`・`PROP-SRCH-*` など、アクセスの判定の性質は PR で 1,000 通り、夜間に 10 万通り。夜間の失敗は、翌朝のマージを止める（merge queue の必須の検査にする）。
- 上限の試験の網羅：登録簿の全ての `id` に、`LIM-*` の試験の ID があり、テストのコードから参照されていること。試験の期待値を緩める差分（上限の値の増加と試験の期待値の変更が同じ PR にある）は、`security:sensitive` と同じ 2 人の承認にする。
- 漏えいの経路：`LEAK-*` の全ての行のテストの ID が参照されていること。
- 2 は、写しを直し忘れても通る。3 は、開発の都合で設計の記録が変わり、設計の記録が正本でなくなる。
- b は、10 万通りの性質ベーステストで PR が 1 時間を超える。

## Consequences

- 良くなること：
  - 上限の値が、設計の記録と実装で食い違ったまま出ない。
  - アクセスの判定の規則が、表・性質・経路の 3 つで CI に縛られる。
- 引き受けるコスト：
  - 開発リポジトリの CI が、rebuilds のリポジトリの表の形に依存する。表の形を変える時は、検査の道具も直す。
  - 夜間の失敗で、翌朝のマージが止まる。

## Confirmation

- CI の自己テスト：わざと値をずらした表・行を足した決定表・参照のない `LEAK-*` を与え、それぞれ失敗する。
- 月に 1 回、例外の一覧が空か、期限の中かを確かめる。
