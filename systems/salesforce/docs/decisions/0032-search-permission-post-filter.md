# ADR-0032: 検索の結果は候補とし、オブジェクトの権限と FLS は前に絞り、レコードの共有はデータ層の問い合わせで後に確かめる。件数の合計を返さない

詳細は [search.md](../architecture/search.md) の 6 節。

## Context

intent は、利用者が見られないレコードが検索に現れないこと、FLS で見えない項目の値がどの経路でも返らないことを求める。[ADR-0004](0004-record-access-model.md) と [sharing-and-record-access.md](../architecture/sharing-and-record-access.md) の 6.4 節は、全文検索でも「索引から得た ID を、データ層の問い合わせで絞り直してから返す」とした。

検索の索引は OpenSearch の写しで（[ADR-0031](0031-search-index-and-japanese-analysis.md)）、共有の設定（OWD、ロール、共有ルール、手動の共有、チーム、暗黙の共有）は常に変わる。

本家（[SOQL and SOSL Reference](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_soql_sosl.pdf)、Winter '27 版、2026-09-28 に確認）は、まず最大 2,000 件の一致を探し、「すべてのデータの参照」のない利用者には権限で絞って見られるものだけを見せる。この段の上限で、一致したレコードが結果から落ちることがある。システムの文脈は `IN ALL FIELDS` の照合で FLS を無視する（利用者の文脈の細部は未検証）。

## Options

1. **前に絞る（組織・オブジェクトの権限・FLS）＋ 後で確かめる（共有）。候補を 1,000 件ずつ最大 3,000 件まで取り直す**
2. 共有の情報（見られるグループ）を索引の文書に写し、OpenSearch の中で全てを絞る
3. 全てを後で確かめる（FLS も後で）

## Decision

1 を採用する。

- OpenSearch の問い合わせには、組織・読めるオブジェクト・読める検索の項目（`texts.f`）の絞りを付ける。権限の形から作るので、組織の全てのレコードに同じで、前に絞っても漏れない。
- 候補の ID は、オブジェクトごとにデータ層の問い合わせ（`id IN (...)` と要求の `where`）にし、通常のコンパイラ（ADR-0003 の段 3・4）が共有の条件・FLS・ごみ箱の除外を付ける。判定は画面・REST と同じ 1 か所で、参照の評価器（[ADR-0017](0017-reference-access-evaluator.md)）と同じ意味になる。本番の標本の照合を検索の結果にも当てる。
- 返す値と強調は、後の確かめで DB から読んだ値で作る。読める項目だけ。
- 候補は 1 回 1,000 件、合わせて 3 回・3,000 件まで。予算は `search.request`（OpenSearch の時間 2 秒）。
- 件数の合計を返さない。`more_may_exist` だけを返す。落ちた件数を応答に出さない。
- 2 は、共有の変更のたびに索引の文書を書き直すことになり（共有の再計算と同じ量）、書き直しの遅れの間に見えないはずのレコードが出る。
- 3 は、読めない項目の値で一致させることになり、一致するかどうかから値を推し量れる。

## Consequences

- 良くなること：
  - 検索の判定が、問い合わせと同じ 1 か所の判定になる。
  - 共有の変更が索引に影響しない。
  - 読めない項目で一致させない。
- 引き受けるコスト：
  - 見られるレコードが少ない利用者で、見られる一致が候補の外にあると出ない（本家と同じ性質）。E5 で率を測る。
  - 後の確かめの問い合わせの分だけ遅くなる。
  - 応答の時間から見えない一致の多さを推し量れうる。MVP では対策しない。

## Confirmation

- 決定表：`DT-SRCH-001`（一致の場所 × 項目の読み × レコードの見え方 → 結果）を表駆動テストにする。
- 性質ベーステスト：`PROP-SRCH-001`（結果が参照の評価器で読めるレコードだけ）、`PROP-SRCH-002`（組織の分離。索引の `org_id` を誤らせても、後の確かめで落ちる）。
- 否定側のテスト：件数の合計がない。強調に読めない項目の断片がない。読めない項目にだけある語で出ない。
- 本番：検索の結果の標本の照合で、`access_oracle_mismatch_total{direction="over"}` が 0。
