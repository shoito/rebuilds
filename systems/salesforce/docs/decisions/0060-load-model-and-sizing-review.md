# ADR-0060: 負荷と大きさは capacity.md の式で持ち、E3・E4・E12 の計測で係数を置き換える。S1 の主のクラスタは writer 1 台に reader 2 台で始め、項目の変更の履歴は S1 から別のクラスタに置く

詳細は [capacity.md](../architecture/capacity.md)。

## Context

- architecture の README は、S1 を 5 億件・5 万人・対話のピーク 2,000 件/秒・Aurora の writer 1 台と reader 2 台とした。
- 各領域が量を見積もった：records とピボット（[data-storage.md](../architecture/data-storage.md) の 8 節）、変更のイベント（3 日で約 130GB）、項目の変更の履歴（18 か月で約 350 億行・約 3.5TB。capacity の領域で見直すよう依頼）。
- 共有の再計算の時間の目標（NFR-005）と、ピボットの書き込みの増幅（ADR-0002 の持ち越し）は、計測で確かめる必要がある。
- 数字の多くは本システムの想定で、E12 の負荷試験の前は仮の値である。

## Options

1. **式（件数 × 係数）で見積もり、係数を計測で置き換える。見直しの時期を Epic に結ぶ**
2. 固定の数を置き、E12 でまとめて見直す

## Decision

1 を採用する。

- 見積もりは capacity.md に式と係数で書き、係数の出どころ（想定・PoC・本番）を列に持つ。係数を計測で置き換えたら、日付を付けて直す。
- 見直しの時期：E3（保存の書き込みの増幅、問い合わせの p95）、E4（共有の条件の結合、閉包の読み、ルールのバージョンの作成の速さ）、E11（履歴の行の増え方）、E12（全体）。GA の後は四半期ごと。
- S1 の主のクラスタは、writer `db.r8g.8xlarge`、reader `db.r8g.4xlarge` × 2（レポートと一括の問い合わせ）で始める。E12 で writer の CPU の p95 が 50% を超えるなら、S2 の前にクラスタを分ける（[ADR-0055](0055-shard-placement-and-stage-criteria.md)）。
- 項目の変更の履歴（`field_history`）は、S1 で主のクラスタの保存の量の半分以上になりうる。S1 は主のクラスタの月ごとの分割のまま持ち、S2 の前に、書き込みの多い組織の履歴を別のクラスタ（`history`）へ分けるかを決める。分けると、手順 9 が同じトランザクションで書けなくなるので、その時は別の ADR で outbox からの書き込みとの損得を比べる。
  > 2026-09-28 の注記：統合の工程で、この判断を S2 の前から S1 に前倒しした（既定案）。18 か月で約 3.5TB の履歴は、主のクラスタの履歴以外の全て（約 2.2TB）より大きく、保存の量・VACUUM・バックアップ・組織の移動の時間を圧迫する。**S1 から `history` のクラスタ（`events` と同じ形の別の Aurora）に置き**、手順 9 は同じトランザクションの outbox から Relay が写す形にした。別の ADR を起こさず、[ADR-0047](0047-field-history-tracking-and-retention.md) の注記で書き方を改めた。OpenSearch の台数も、3 台ではなく 6 台で見積もり直した（[capacity.md](../architecture/capacity.md) の 7 節）。
- 2 は、E12 まで誤った前提で設計が進み、負荷試験で大きく外れた時の手戻りが大きい。

## Consequences

- 良くなること：
  - どの数字が想定で、どれが計測かが分かる。
  - 計測のたびに、次の段階の時期を前もって知れる。
- 引き受けるコスト：
  - capacity.md を計測のたびに直す運用が要る。
  - 履歴の置き場所の判断を、S2 の前に持ち越す。（2026-09-28 の注記：S1 から別のクラスタに置くと決めたので、持ち越しは無くなった。代わりに `history` のクラスタの費用と運用が S1 から加わる。）

## Confirmation

- 負荷試験（E12）：capacity.md の 2 節の負荷のモデルで、NFR-001〜005 を満たす。係数を表に戻す。
- 計測：`records` とピボットの行の数、表の大きさ、1 件の保存で書く行の数の分布を毎日出し、capacity.md の係数と 30% 以上ずれたら見直す。
