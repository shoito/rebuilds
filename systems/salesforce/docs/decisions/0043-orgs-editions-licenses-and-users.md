# ADR-0043: 組織は種類と状態を持って 30 日の猶予の後に消し、エディションは割り当てと機能だけを変え、ライセンスを権限の上限にし、利用者は消さずに無効にする

詳細は [orgs-users-and-auth.md](../architecture/orgs-users-and-auth.md) の 3〜5 節。

## Context

intent は、組織の作成、エディションとライセンス、利用者を E2 の範囲にする。[ADR-0005](0005-tenancy-and-governor-limits.md) は、トランザクションの上限をエディションで変えず、組織ごとの割り当てだけをエディションとライセンスの数で変えるとした。

- 利用者は、レコードの所有者・作成者・更新者・承認者・履歴の変更者として、多くの行から指される。
- 法務の L1 は、本人からの請求での個人データの扱いを問う。L7 は、解約時のデータの返却と削除を問う。
- 本家の価格の段（Starter Suite、Pro Suite、Core、Advanced、Max など）と機能の差は、要約でしか確かめていない（intent。未検証）。本家は、ライセンスの種類ごとに API の割り当てが違う（[Developer Limits and Allocations Quick Reference](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_app_limits_cheatsheet.pdf)、2026-09-28 に確認）。

## Options

エディション：

1. **トランザクションの上限は同じにし、割り当て・機能の組・カスタムオブジェクトの数・Sandbox の数だけを変える**
2. エディションでトランザクションの上限も変える

利用者の削除：

- a. **消さずに無効にし、本人の請求では個人の項目を匿名に置き換える**
- b. 消して、参照を「削除した利用者」の 1 つの行へ付け替える

## Decision

1 と a を採用する。

- 組織は `kind`（`production`・`sandbox`・`trial`・`developer`）と `status`（`provisioning`・`active`・`read_only`・`suspended`・`deleting`）を持つ。作成は 1 つのトランザクションで、標準の種と最初の管理者を入れる。
- 削除は、申し込みから 30 日の猶予（管理者だけがログインして書き出せる）の後、7 日以内に全ての行・ファイル・索引・イベントを消す。値は法務の L7 の結論で変えうる。
- エディションは `starter`・`pro`・`enterprise`・`unlimited`・`developer`。本家の段との対応と機能・価格は E2 の着手前に PM が決める。下げで使えなくなる設定は消さずに無効にする。
- ライセンスは `full`・`platform`・`integration`。権限セットは割り当てられるライセンスを持ち、ライセンスの外の権限を持つ権限セットを割り当てられない。`integration` は画面のログインを持たない。
- 利用者は `invited`・`active`・`frozen`・`deactivated`。無効化でセッションとトークンを失効し、キュー・グループから外す。匿名化は氏名・カナ・メール・電話を置き換え、ID は残す。`username` は全ての組織で一意。
- 2 は、公平のための上限がエディションで変わり、大きなエディションの組織が共有の DB を多く使える。ADR-0005 に反する。
- b は、数百万の行の参照の付け替えになり、共有の判定（所有者）も変わる。

## Consequences

- 良くなること：
  - 公平の上限が全ての組織で同じで、エディションは商用の差だけになる。
  - ライセンスで、権限の上限を機械的に守れる。
  - 利用者の無効化・匿名化が、参照の書き換えなしで済む。
- 引き受けるコスト：
  - エディションの機能の組を、メタデータの保存と API の入口の両方で確かめる。
  - 匿名化した利用者の ID は残るので、ID から行動の履歴を追えることは残る（法務の L1 で確認する）。
  - `username` の一意で、利用者は組織ごとに違う名前を持つことがある。

## Confirmation

- 結合テスト：組織の作成から最初のログインまで 2 分以内。削除の猶予の間の書き出しと、猶予の後の全ての表からの消去。
- 結合テスト：ライセンスの外の権限セットの割り当てを断る。ライセンスの数を超える有効化を断る。
- 性質ベーステスト：無効化の直後に、その利用者のセッション・トークンで要求が通らない。
- 上限の試験：エディションごとのカスタムオブジェクト・Sandbox の数。
