# ADR-0013: 権限は権限セットで与えて和で合わせ、プロファイルは既定値と基本の権限セットの入れ物にする。読めない項目は存在しない項目と同じに扱う

詳細は [sharing-and-record-access.md](../architecture/sharing-and-record-access.md) の 3 節。

## Context

利用者がオブジェクトと項目に何をできるかは、オブジェクトの権限（参照・作成・編集・削除、「すべて参照」「すべて変更」）と FLS で決まる。本家はこれをプロファイルと権限セットで与える（[Record-Level Access: Under the Hood](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_record_access_under_the_hood.pdf)、2026-09-28 に確認）。

- 本家は、Spring '26 からプロファイルの権限を廃止する計画を出したが、取りやめた。今後もプロファイルの権限は使えるが、既定値（アプリ、レコードタイプ、レイアウト、ログインの時間と IP、パスワードとセッションの方針）はプロファイルに、権限は権限セットに置くことを勧める（[Permissions in Profiles Retirement Cancelled](https://help.salesforce.com/s/articleView?id=003834041&type=1)、2026-09-28 に確認）。
- 権限を狭める権限セット（muting）もある。権限セットのグループの中で、指定した権限を外す（[Metadata API Developer Guide](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf)、Winter '27 版の MutingPermissionSet、2026-09-28 に確認）。
- 読めない項目で絞る・並べる問い合わせを許すと、値を二分探索で推し量れる。

## Options

1. **権限は全て権限セットで与え、和で合わせる。プロファイルは既定値（レイアウト、レコードタイプ、ログインの制限）と 1 つの基本の権限セットの入れ物にする**
2. 本家と同じく、プロファイルにも権限を持たせ、権限セットで足す
3. 1 に、権限を狭める権限セットを加える

## Decision

1 を採用する。

- オブジェクトの権限（`read`・`create`・`edit`・`delete`・`view_all`・`modify_all`）、項目の権限（`read`・`edit`）、システムの権限を権限セットに持つ。権限の依存（`edit` → `read` など）は保存の時に検査する。
- 利用者の権限は、割り当てた権限セット（グループを展開したもの）とプロファイルの基本の権限セットの和にする。
- 割り当ての集合のハッシュを「権限の形」とし、`(org_id, metadata_version, 権限の形)` で権限の表をコンパイルしてキャッシュする。割り当ての変更はデータの変更で、メタデータのバージョンを上げない。
- 読めない項目は、`SELECT` では既定でエラー（画面用は落として返せる）、`WHERE`・`ORDER BY`・`GROUP BY`・記述では存在しない項目と同じ応答にする。
- 2 は、同じ権限を 2 か所で持つことになり、判定と管理の画面が複雑になる。3 は、和だけの単純な判定を崩す。要望が出てから扱う。

## Consequences

- 良くなること：
  - 権限の出どころが権限セットだけになり、判定が「和」の 1 つの規則で済む。
  - 読めない項目の存在と値を、問い合わせの応答から推し量れない。
- 引き受けるコスト：
  - 本家のプロファイルに慣れた管理者は、権限の置き場所の違いを学ぶ必要がある。移行の道具で、プロファイルの権限を基本の権限セットへ写す。
  - 権限を狭める道具がないので、「ほぼ全てだが 1 つだけ除く」を別の権限セットの組み合わせで作る必要がある。

## Confirmation

- 決定表：`DT-SHR-003`（項目の種類 × 権限セットの和 → 読み・編集）を表駆動テストにする。
- 性質ベーステスト：任意の権限セットの割り当てで、コンパイルした権限の表が、権限セットの和を直接求めたものと一致する。
- 否定側のテスト：読めない項目を `WHERE`・`ORDER BY`・`GROUP BY` に使った問い合わせの応答が、存在しない項目の応答と区別できない。
