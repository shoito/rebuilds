# ADR-0053: 運用者は組織の管理者の許可と期限つきの権限でだけ組織のデータに触れ、全ての操作を組織の監査に残す。データの種類ごとに保持と消去の期限を 1 つの表で持つ

詳細は [security.md](../architecture/security.md) の 6 節と 7 節。

## Context

- サポートと障害の調査で、運用者が組織の設定やレコードを見る必要がある。法務の L1 は、サポートでの参照を委託として扱うかを問う（[intent.md](../intent.md)）。
- [ADR-0046](0046-setup-audit-trail-and-login-history.md) は、運用の操作を `actor_kind = support` として組織の監査に残し、組織の管理者が見られるとした。誰が、どの条件で入れるかは決めていなかった。
- データの保持の期限は、各領域に散っている（ごみ箱 15 日、履歴 18 か月、監査 180 日と 1 年、イベント 3 日、一括の結果 7 日、組織の削除 30＋7 日）。バックアップと、ログの中の個人データの期限は決めていなかった。
- rebuilds の他の題材（Auth0 の ADR-0056）は、AI エージェントに本番の経路を持たせず、運用者は JIT で入る形を決めた（[auth0 の ADR-0056](../../../auth0/docs/decisions/0056-operator-access.md)）。

本家は、利用者が自分のアカウントへのログインのアクセスを、管理者かサポートに期限つき（最大 1 年）で与える機能を持つ。与えたアクセスでの Setup の変更は、設定の変更の履歴に残る（[Grant Login Access](https://help.salesforce.com/s/articleView?id=xcloud.granting_login_access.htm&type=5)、2026-09-28 に確認）。

## Options

運用者のアクセス：

1. **組織の管理者の許可（期限つき）＋運用者の JIT の権限＋2 人目の承認。操作は全て組織の監査と本システムの監査の両方に残す**
2. 運用者の JIT の権限だけ（組織の許可なし）
3. 運用者は組織のデータに一切触れない

データのライフサイクル：

- a. **データの種類ごとの保持と消去の期限を security.md の表を正本にし、各消去のジョブの遅れを計測する**
- b. 各領域の文書に任せる

## Decision

1 と a を採用する。

- 運用者の入口は 3 段。
  - **メタデータとログ**（組織の設定、エラー、トレース。レコードの値を含まない）：JIT の `support-read` のロール（4 時間）。組織の許可は要らない。
  - **レコードの値**：組織の管理者（`manage_users`）の許可（1〜7 日の期限、範囲はオブジェクトの単位）＋JIT の `support-data` のロール（2 時間）＋別の運用者の承認。画面は本システムのサポートの道具からだけ。読むだけ。
  - **break-glass**（組織が応答できない SEV1、法的な要求）：2 人の承認とセキュリティの担当の承認。事後 24 時間以内に組織の管理者へ知らせる（法的に知らせられない時を除く。法務の判断）。
- 運用者の道具も、データ層を通る（組織の解決、RLS、上限）。直接の SQL の経路は break-glass だけにし、セッションを記録する。
- AI エージェント（コーディング・運用）は本番に経路を持たない。本番の調査は、人が道具で取り出した、個人データを含まない材料だけを渡す。
- データの保持の表（security.md の 7 節）を正本にし、各領域の期限はその写しとする。バックアップは 35 日（Aurora の自動バックアップの保持は 1〜35 日。[Overview of backing up and restoring an Aurora DB cluster](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Managing.Backups.html)、2026-09-28 に確認）、アプリのログは 30 日で、ログに個人データを入れない（[ADR-0058](0058-slis-and-per-org-resource-metrics.md)）。
- 各消去のジョブは `*_overdue` の計測を持ち、期限を過ぎた件数を 0 に保つ。
- 期限の値は法務の L5・L7 の結論で変えうる。値は設定にする。
- 2 は、組織が知らないうちにレコードを見られる。3 は、障害の調査とデータの復旧ができない。
- b は、バックアップ・ログ・写し（検索の索引、イベント）の期限が抜ける。

## Consequences

- 良くなること：
  - 組織の管理者が、運用者のアクセスを許し、監査で見られる。
  - 消去の期限が 1 つの表で見え、写しの消し漏れを計測で見つけられる。
- 引き受けるコスト：
  - 組織の許可を待つ分、サポートが遅い。緊急は break-glass で、事後の知らせを守る。
  - バックアップの 35 日の間、削除したデータが残る。組織への説明（DPA）に書く（法務の L7）。

## Confirmation

- 結合テスト：組織の許可のない `support-data` のロールで、レコードの値が読めない。期限を過ぎた許可で読めない。
- 網羅のテスト：サポートの道具の全ての操作が、組織の監査に `actor_kind = support` で残る。
- IaC の検査：AI エージェントの実行環境のロールに、本番のアカウントへの `AssumeRole` がない。
- 本番：全ての `*_overdue` の計測が 0。
