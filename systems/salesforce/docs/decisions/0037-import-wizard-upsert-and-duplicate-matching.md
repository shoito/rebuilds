# ADR-0037: インポートのウィザードは一括のジョブの上の画面にし、upsert と照合での既存の更新は同じ鍵の行を同じ部分に集めて順に処理し、見えない一致は無いものとして扱う

詳細は [bulk-and-import.md](../architecture/bulk-and-import.md) の 4 節と 5 節。

## Context

intent は、CSV の取り込みのウィザード、重複の照合、外部 ID での upsert を MVP に含め、K8（新しい組織で取引先 1 万件を取り込み、リストビューで見るまで中央値 30 分）を置く。日本の組織の CSV は、表計算のソフトが書く Shift_JIS（CP932）が多い。

[ADR-0022](0022-duplicate-rules-and-japanese-matching.md) は、重複の照合を正規化した照合の鍵で行い、見えないレコードとの一致を既定で知らせない（`enforce`）とした。[ADR-0020](0020-rest-api-shape-and-versioning.md) は、外部 ID を必ず一意にした。

取り込みでは、同じファイルに同じ会社・同じ人の行が何度も出ることがある。並行の部分で同じ鍵の行を同時に作ると、一意の違反か重複のレコードになる。

本家のインポートのウィザードは 1 回 5 万件まで（ヘルプの要約。未検証）。本家のウィザードが照合でどう既存を選ぶか、見えないレコードをどう扱うかは確かめられなかった（未検証）。

## Options

ウィザードの処理：

1. **一括の取り込みのジョブ（[ADR-0036](0036-bulk-jobs-chunking-and-partial-success.md)）の上の画面にする。下見は同じ保存の手順を巻き戻すトランザクションで通す**
2. ウィザード専用の同期の取り込み（画面の要求の中で保存する）

同じ鍵の行：

- a. **分割の時に鍵で振り分けて同じ部分に集め、同じ塊に同じ鍵を入れずに順に処理する（最後の行の値が残る）**
- b. 同じ鍵の 2 行目以降を失敗にする
- c. 並行に処理し、一意の違反をやり直しで直す

見えない一致：

- x. **無いものとして扱う（作成になりうる）**
- y. 止めて「表示できない一致があります」と返す

## Decision

1、a、x を採用する。

- ウィザードは、文字コード（BOM、UTF-8 の正しさ、CP932）と区切りを判定し、列と項目を自動で合わせ（対応の型を保存できる）、最初の 200 行を巻き戻すトランザクションで保存の手順に通して下見を見せ、`source = wizard` の一括のジョブを作る。1 回 5 万行・50MB。`import_records` のシステムの権限が要る。
- 和暦（令和・平成）の日付、桁区切りと全角の数、選択リストのラベルを受ける。
- upsert は外部 ID、照合での既存の更新は照合の鍵で、分割の時に行を振り分け、同じ鍵の行を同じ部分に集める。同じ塊に同じ鍵を 2 行入れず、後の塊に回す。
- 照合での既存の更新は `DT-IMP-001`（見られる一致の数 × ファイルの中の前の行 × 操作 → 結果）で決める。見られる一致が 2 件以上なら `MULTIPLE_MATCHES` で、見られる一致の ID だけを返す。
- 見えない既存のレコードとの一致は無いものとして扱う（ADR-0022 の `enforce` と同じ）。
- 取り込みでも自動化は通常どおり動く。止める選択は持たず、フローの条件で保存の出どころ（`$Origin`）を見られるようにする。
- 2 は、画面の要求の時間とトランザクションの上限で数千行が限度になり、一括の API と別の保存の経路を持つことになる。
- b は、名刺の取り込みのように同じ人が何度も出るファイルで、利用者が手で重複を直す手間が大きい。c は、競合のやり直しが増え、結果が処理の順で変わる。
- y は、止めたことで見えないレコードの存在が漏れる。

## Consequences

- 良くなること：
  - ウィザードと一括の API の保存の経路が 1 つで、上限・再試行・結果が同じになる。
  - 日本の CSV を、文字コードを選ばずに取り込める。
  - 同じ鍵の行が決まった順に処理され、結果が処理の分け方に依らない。
- 引き受けるコスト：
  - 見えない既存のレコードがあると、重複のレコードを作りうる。重複の記録で後から見つける。
  - 鍵での振り分けで、同じ鍵が多いファイルは部分の大きさが偏る。
  - 下見の 200 行でも保存の手順を全て通すので、フローの重い組織では下見が遅い。

## Confirmation

- 決定表：`DT-IMP-001` を表駆動テストにする。
- 性質ベーステスト：同じ外部 ID の行を含む任意の CSV で、upsert の後のレコードの数が外部 ID の数と等しく、値が最後の行の値になる。
- 性質ベーステスト：UTF-8 と CP932 で書いた同じ内容の CSV が同じ値で読める。
- 否定側のテスト：見えないレコードの ID・件数が、結果・下見・エラーに出ない。
- 計測（E9・E12）：1 万件のウィザードの取り込みからリストビューまでの中央値（K8）。
