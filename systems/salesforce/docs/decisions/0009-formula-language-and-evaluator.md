# ADR-0009: 数式は表計算に寄せた独自の言語にし、決定性で 4 つに分け、値は参照先を全て読める人にだけ返す

詳細は [metadata-and-runtime.md](../architecture/metadata-and-runtime.md) の 7 節。

## Context

数式の項目、入力規則、フローの条件、リストビューとレポートの条件は、同じ式の言語で書く。本家の数式との互換は目標にしない（[ADR-0001](0001-platform-and-stack.md)）。[ADR-0003](0003-metadata-driven-runtime.md) は、TypeScript の参照の評価器を 1 つ持ち、SQL にできる式でもテストで SQL と評価器の結果を比べるとした。

決めていなかったこと：

- 文法、型、空の扱い、10 進の計算の丸め。
- どの式を SQL にし、どの式に索引を張れるか。
- 数式が、見る人の読めない項目を参照する時の扱い。intent は「数式やレポートの集計を通して値が漏れない」とする。

本家（2026-09-28 に確認）：

- 数式は 3,900 文字まで。コンパイル後 15,000 バイトまで。参照した数式の大きさが加わる（[Tips for Reducing Formula Size](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_formula_size_tipsheet.pdf)）。
- 決定的な数式には索引を張れる。他のオブジェクトを参照する数式、時刻で変わる数式には張れない（[Best Practices for Deployments with Large Data Volumes](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_large_data_volumes_bp.pdf)）。
- 参照先の項目の FLS と数式の値の関係は、確かめられなかった（未検証）。

## Options

言語について：

1. **表計算に寄せた独自の言語。値を作る式として 2 値の論理（空は偽）を使う**
2. 問い合わせの言語の式（SQL に寄せた 3 値の論理）を数式にも使う
3. JavaScript の式の部分集合

FLS について：

- a. **数式の項目と、展開した後に参照する全ての項目を読める時にだけ値を返す**
- b. 数式の項目の FLS だけで決める

## Decision

1 と a を採用する。

- 演算子は `+ - * / ^ & = <> < <= > >= && || !`、関数は `IF`・`CASE`・`ISBLANK`・`TEXT`・`DATE` など表計算で一般的なものにする。親への参照は `account.owner.name` の形で 5 段まで。
- 数は 10 進（38 桁）で計算し、`ROUND` は 0 から遠い方へ丸める。暗黙の型の変換はしない。数の空は、数式ごとの設定で 0 として扱うか空のまま伝える。`&&`・`||`・`IF` の条件では、空を偽とする。
- 式を、A 同じレコードで決まる（SQL にし、索引にできる）、B 親をたどる（SQL にするが索引にできない）、C 時刻・利用者で変わる（値をバインド変数にして SQL にする）、D 評価器だけ、に分ける。分類はコンパイルの時に決める。
- 参照の評価器を意味の正本にし、SQL の生成は評価器と同じ結果を返す形に固定する。
- 数式の値は、見る人が数式の項目と、展開した後に参照する全ての項目を読める時にだけ返す。入力規則とフローの中の数式は、システムの文脈で評価し、エラーの文言に値を差し込ませない。
- 上限は、式 5,000 文字、展開した後の AST 2,000 節、親への参照 5 段、1 つのオブジェクトの数式がたどる関係 15、数式の参照の深さ 10 で始める。
- 2 は、表計算に慣れた管理者に 3 値の論理を求めることになり、「空なら偽」の書き方が冗長になる。3 は、評価器を砂場に入れる必要があり、SQL にできる部分集合を定めにくい。
- b は、読めない項目の値が数式を通して漏れる（例：`salary * 1` の数式）。

## Consequences

- 良くなること：
  - 数式を通した FLS の漏れがない。
  - どの式を SQL にし、どの式に索引を張れるかが、コンパイルの時に機械的に決まる。
  - 数式・入力規則・問い合わせの条件で、評価器を 1 つ共有できる。
- 引き受けるコスト：
  - 数式の言語（2 値）と、問い合わせの言語（3 値）で空の扱いが違う。数式を問い合わせの条件に使う時は、数式の値を先に作ってから 3 値で比べる。文書に書く。
  - 本家より厳しい FLS で、本家から移る組織では、見えていた数式の値が見えなくなる。
  - 10 進の計算と丸めを、評価器と SQL で揃え続ける。

## Confirmation

- 性質ベーステスト：任意の数式と任意のレコードで、SQL の結果と評価器の結果が一致する。
- 決定表：数式の FLS（数式の項目の読み × 参照先の読み → 返すか）。
- 上限の試験：式の文字数、AST の節の数、親への参照の段、関係の数、参照の深さで、ちょうどで通り、1 つ超えたら拒否する。
- 結合テスト：読めない項目を参照する数式の項目が、API・リストビュー・レポートのどこにも出ない。
