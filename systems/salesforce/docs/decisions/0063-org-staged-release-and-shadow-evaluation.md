# ADR-0063: リリースは組織を単位に段階で広げ、アクセスの判定・問い合わせのコンパイルを変える時は、新旧を本番の標本で並べて比べる影の実行を経る

詳細は [delivery.md](../architecture/delivery.md) の 5 節と 6 節。

## Context

- デプロイとリリースは分ける（他の題材と同じ。未完成の振る舞いは release フラグの裏に置く）。フラグは AWS AppConfig（[ADR-0001](0001-platform-and-stack.md)）。
- この題材の変更は、組織ごとのメタデータの違いで影響が変わる。同じコンパイラの変更が、ある組織では正しく、別の組織の特定の設定（深いロール階層、多くのルール、暗黙の共有）でだけ誤る。
- アクセスの判定の誤りは、5xx にならず、見えてはならないものが見える形で現れる。本番の標本の照合（[ADR-0017](0017-reference-access-evaluator.md)）は、事後に見つける仕組みで、誤りを出す前に止めるものではない。
- rebuilds の他の題材（Auth0 の ADR-0066）は、テナントの単位のカナリアを決めた（[auth0 の ADR-0066](../../../auth0/docs/decisions/0066-tenant-canary-release.md)）。

## Options

1. **組織を単位に、段（社内の組織 → Sandbox・試用 → 本番の 1% → 10% → 50% → 全て）で広げる。判定・コンパイルの変更は、影の実行で新旧の結果を比べる段を先に置く**
2. 全ての組織に同時にリリースし、フラグで戻す
3. タスクの割合（リクエストの割合）で広げる

## Decision

1 を採用する。

- フラグは組織の ID で評価する。段は、`internal`（社内の組織と合成監視の組織）、`nonprod`（Sandbox・試用・Developer）、`prod_1`、`prod_10`、`prod_50`、`all`。1 つの段は最低 24 時間（判定の変更は 72 時間）置く。
- 次の段へ進む条件：その段の組織の SLI の悪化がない、エラーの率が変わらない、`access_oracle_mismatch_total{direction="over"}` が 0、影の実行の食い違いが 0。自動で進めず、Ops が確かめて進める。条件を外れたら、ガードがフラグを自動で前の段に戻す。
- **影の実行**：アクセスの判定・問い合わせのコンパイラ・共有の条件の生成・検索とレポートのコンパイルを変える時は、`shadow` の段を `internal` の前に置く。本番の要求の標本（組織ごとに 1 分 10 件、全体で 1 秒 100 件まで）で、旧いコンパイラの結果（返すレコードの ID の集合と、FLS で落とす項目の集合）を返し、同じ要求を新しいコンパイラでも reader で実行して比べる。食い違いは、参照の評価器でどちらが正しいかを判定して記録する。
- 影の実行の結果は、ID の集合のハッシュだけを残し、レコードの値を残さない。影の実行は、要求の上限・割り当てに数えず、組織の DB の時間には数える。
- マイグレーションは expand → 移行 → contract の 3 回に分け、contract は 1 つ前のリリースで参照をやめてから行う（他の題材と同じ）。メタデータのコンパイル済みの部品の形を変える時は、部品の鍵に形のバージョンを含め、新旧が同時に L2 にあってよい形にする。
- 2 は、組織の設定に依る誤りが、全ての組織で同時に出る。3 は、同じ組織の中で新旧の判定が要求ごとに混ざり、「古い構成か新しい構成のどちらか一方」の性質（[ADR-0016](0016-recalculation-rule-versions-and-skew.md)）に似た保証を利用者に説明できない。

## Consequences

- 良くなること：
  - 組織の設定に依る誤りを、多くの組織に出す前に見つけられる。
  - 判定の変更の誤りを、利用者に見せる前に影の実行で見つけられる。
  - 1 つの組織の中では、判定が新旧のどちらか一方にそろう。
- 引き受けるコスト：
  - 判定の変更のリリースに、少なくとも 1 週間かかる。
  - 影の実行の分、reader の負荷が増える。
  - フラグの評価が組織の ID に依るので、組織の移動・Sandbox の作成でフラグの段を写す規則が要る（Sandbox は元の本番の段を継ぐ）。

## Confirmation

- 結合テスト：フラグの段ごとに、対象の組織だけが新しい振る舞いになる。ガードで前の段に戻る。
- 結合テスト：影の実行で、わざと 1 行多く返す新しいコンパイラを与えると、食い違いが記録され、次の段へ進めない。
- 本番：影の実行の食い違いの数と、段の滞在の時間をリリースごとに記録する。
