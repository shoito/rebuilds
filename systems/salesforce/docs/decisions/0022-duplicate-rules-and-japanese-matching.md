# ADR-0022: 重複の照合は同じトランザクションで書く正規化した照合の鍵で候補を引き、評価器で判定する。日本語は表で正規化し、見えないレコードとの重複は既定で知らせない

詳細は [sales-objects.md](../architecture/sales-objects.md) の 6 節。

## Context

[ADR-0008](0008-dml-order-of-execution.md) は、保存の手順 5 を「重複の規則（sales-objects の領域）」とした。日本の営業の組織では、同じ会社・同じ人が、表記の揺れで別のレコードとして何度も登録される。

- 全角・半角、ひらがな・カタカナ、長音（`ー`・`－`・`-`）、拗音の大小（`キャ`・`キヤ`）、異体字（`髙`・`高`）、法人格（`株式会社`・`(株)`・`㈱`）の揺れ。
- 漢字の名前から読みを正しく決めるのは難しい。
- 重複の判定は、保存する人が見られないレコードとの一致を扱う。止めると、そのレコードの存在が漏れる。

本家（2026-09-28 に確認）：

- 重複の規則は、作成・更新ごとに許可（警告・記録）か止めるかを選び、照合の規則を持つ。共有を守る設定では、見えないレコードとの重複は何も知らせず保存を通す（[Metadata API Developer Guide](https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf)、Winter '27 版の DuplicateRule）。
- 照合の方法は、完全一致と、名・姓・会社名・電話・市区町村・番地・郵便番号・役職のあいまいな照合（同 MatchingRule）。あいまいな照合は Jaro-Winkler、Metaphone 3、異表記の辞書、編集距離などを使い、会社名の法人格を無視する（ヘルプの要約。本文は未検証）。
- 有効な重複の規則は 1 オブジェクト 5、照合の規則は 5、1 つの重複の規則に照合の規則 3（ヘルプの要約。未検証）。
- 日本語の扱いは確かめられなかった（未検証）。

## Options

1. **正規化した照合の鍵（ブロッキングの鍵）を、ピボットの表と同じく同じトランザクションで書き、鍵の等価で候補を引いて、評価器で点数を付ける**
2. 全文検索の索引（OpenSearch）で候補を引く
3. PostgreSQL の trigram の類似で、保存のたびにその場で候補を引く

日本語の読み：

- a. **読みの推定をせず、カナの項目があればカナで、なければ正規化した漢字の等価で照合する**
- b. 形態素の解析で漢字から読みを推定する

## Decision

1 と a を採用する。

- 照合の方法は `exact`、`person_name`、`company_name`、`phone`、`email`、`postal_code`、`address`。方法ごとに正規化・ブロッキングの鍵・判定を決める。
- 正規化は 1 つの関数にし、NFKC → 小文字 → ひらがなをカタカナに → 長音の統一 → 記号と空白の除去 → 異体字の表 →（会社名）法人格の除去 →（カナ）小さなカナを大きく、の順にする。冪等にする。
- 鍵は純粋な関数 `deriveMatchKeys` で決め、`record_match_keys` に保存の手順 6 で差分を書く。整合の検査の対象にする（[ADR-0012](0012-derived-copies-consistency-and-projections.md)）。照合の規則を有効にする時は、範囲ごとに鍵を作ってから使う。
- 候補は照合の規則ごとに 200 件まで。超えたら照合せず保存を通して数える。
- 共有の既定は `enforce`：見えない一致は無いものとして扱う。`bypass` は管理者の明示の選択で、止める時も見えない一致の件数・ID・名前を返さない。
- 2 は、索引が非同期で、直前に作ったレコードとの重複を見逃す。同じ要求の中の 2 件の重複も見つけられない。3 は、共有の表で全組織に類似の索引を張ることになり、日本語の短い名前では trigram の効きが悪い。
- b は、辞書の保守と、誤った読みの説明が重い。カナの入力を促す方が確実である。

## Consequences

- 良くなること：
  - 書いた直後のレコードとの重複と、同じ要求の中の重複を見つけられる。
  - 日本語の主な表記の揺れを吸収できる。
  - 既定で、見えないレコードの存在を漏らさない。
- 引き受けるコスト：
  - 照合の規則の項目の数だけ、保存で鍵の行を書く（書き込みの増幅）。
  - カナが空の日本語の名前は、揺れを吸収できない。
  - 拗音の大小を同じにするので、違う名前が一致することがある。`person_name`・`company_name` だけに使う。
  - `bypass` は、止めたことで存在が 1 ビット漏れる。

## Confirmation

- 決定表：`DT-DUP-001`（重複の規則の動作）と、共有と重複の表を表駆動テストにする。
- 性質ベーステスト：正規化の冪等と揺れの吸収。鍵の表と `deriveMatchKeys` の一致。候補の上限の内側で、ブロッキングの判定が総当たりの判定と一致する。
- 否定側のテスト：`enforce` で見えない一致が応答・重複の記録に出ない。`bypass` の応答に見えない一致の件数が出ない。
- 上限の試験：規則・照合の規則・項目・候補の上限。
