# AGENTS.md — Salesforce

Salesforce（Sales Cloud とメタデータで動くプラットフォーム）の再構築の設計。リポジトリ共通のルールはルートの [AGENTS.md](../../AGENTS.md) にある。このリポジトリには設計だけを置き、実装は Salesforce の開発リポジトリで行う（[リポジトリ共通の ADR-0005](../../docs/decisions/0005-design-record-repository.md)）。

## 最初に読むもの

- [docs/intent.md](docs/intent.md) — 何を、なぜ作るか
- [docs/architecture/](docs/architecture/README.md) — 全体像、規模の段階、非機能要件、領域の一覧
- [docs/decisions/](docs/decisions/README.md) — ADR。特に 0002（カスタムオブジェクトの保存）、0003（メタデータの実行基盤）、0004（レコードのアクセス）、0005（テナントとガバナ制限）

## この題材に固有の規則（開発リポジトリで守る）

- **データへのアクセスは、実行基盤のデータ層だけを通す。** レコードの読み書きは、問い合わせと DML の AST を実行基盤でコンパイルして行う。アプリのコードで `records` とピボットの索引の表に直接 SQL を書かない。直接の SQL は、権限・共有・上限の計測をすり抜けるため（ADR-0003、ADR-0005）。
- **アクセス制御の規則は決定表で書き、表駆動テストで確かめる。** オブジェクトの権限、項目レベルのセキュリティ（FLS）、組織の共有設定（OWD）、ロール階層、共有ルール、手動の共有の組み合わせで結果が決まる規則は、`spec.md` の `DT-*` にする。テストは表を `spec.md` から直接読み込む。決定表のない変更で、アクセスの判定を変えない（ADR-0004）。
- **共有の変更には、性質ベーステストを付ける。** 事前計算した共有の行（share の表とグループの閉包）で判定した結果が、設定から毎回計算し直す参照の評価器の結果と一致することを、任意の設定・レコード・操作の列で確かめる（`PROP-*`）。再計算の途中で、古い世代と新しい世代が混ざって見えないことも性質にする（ADR-0004）。
- **上限を足す・変える変更には、上限の試験を付ける。** 1 トランザクションの上限（問い合わせの数、取得の行数、DML の数と行数、CPU 時間、フローの要素の数など）は、上限ちょうどで通り、1 つ超えたらトランザクション全体が巻き戻ることを試験する。上限の値を緩めて試験を通さない。上限を超えた例外を、フローや利用者のロジックで捕まえられるようにしない（ADR-0005）。
- **メタデータの変更は、版を上げる 1 つのトランザクションで行う。** オブジェクト・項目・レイアウト・フロー・権限の変更は、組織のメタデータの版を 1 つ上げる。版を上げずにメタデータの行を書き換えない。コンパイル済みのメタデータは版をキーにして不変に扱い、上書きでキャッシュを無効にしない（ADR-0003）。
- **組織のテーブルには `org_id` と RLS を付ける。** `org_id` を主キーとインデックスの先頭に置く。組織の解決の前に、DB を読まない（ADR-0005）。
- **本家の実装・言語との互換を目標にしない。** Apex・SOQL・本家のメタデータの XML の形式・Visualforce をそのまま受け付ける層を作らない。問い合わせの言語、数式の言語、メタデータの形式は、この題材で定めた独自のものにする（ADR-0001、[リポジトリ共通の ADR-0007](../../docs/decisions/0007-no-reuse-of-original-implementation.md)）。
- **セキュリティに関わる変更は、追加のレビューを受ける。** アクセス制御、共有の再計算、テナントの分離、Sandbox へのデータの複製、監査のログ、暗号、秘密の保存に触れる PR には `security:sensitive` のラベルを付ける。Dev のテックリードに加え、セキュリティの担当の承認を必須にする。エージェントは承認しない。
- **本家の名前を識別子に使わない。** ドメイン、ヘッダー、ID の接頭辞、イベントのチャンネルの名前、メタデータの型の名前は `<Brand>`・`<brand>` で書く（[リポジトリ共通の ADR-0006](../../docs/decisions/0006-brand-neutral-identifiers.md)）。
- **テストに本物の個人データを使わない。** 実在の会社名・人名・メールアドレス・電話番号を、テスト・フィクスチャー・シード・Sandbox のテンプレートに書かない。生成したデータを使う。

## このリポジトリでの規則

- ADR を追加・更新したら、`docs/decisions/README.md` の一覧を生成し直す。
- 領域の文書で ADR を起票するときは、[architecture/README.md](docs/architecture/README.md) の 7 節で領域に割り当てた番号の範囲の中で採番する。
- 本家の振る舞い・数値を書くときは、出典と確認日を付ける。確かめられないものは「未検証」と書く。
