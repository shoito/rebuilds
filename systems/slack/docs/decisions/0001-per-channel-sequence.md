# ADR-0001: メッセージの順序付けにチャンネル内連番 `seq` を使う

## Context

チャンネル内のメッセージは、全メンバーが同じ順序で見る必要がある。あわせて、切断・再接続時の欠損検知、既読位置、差分取得のそれぞれにも「位置」の表現が要る。

## Options

1. `created_at`（タイムスタンプ）
2. Snowflake 型のグローバル ID
3. チャンネル内の連番 `seq`

## Decision

3 を採用する。`channels.last_seq` をメッセージ INSERT と同じトランザクションでインクリメントして採番する。

- 欠損検知が「受け取った `seq` が直前 + 1 か」という整数比較になる。
- 既読位置・未読数・差分取得の API をすべて `seq` で表せる。
- 1 と 2 は、同時刻の衝突や時計のずれがあり、「間が抜けている」ことを判定できない。

## Consequences

- 良くなること：クライアントの同期ロジックが単純になる。
- 引き受けるコスト：チャンネル行のロックが採番のたびに発生する。書き込みが集中するチャンネルでは待ちが出うる（負荷試験で計測する）。

## Confirmation

- 性質ベーステスト（PROP-MSG-001）で、並行投稿時にも `seq` が欠番・重複なく単調増加することを検証する。
