# ADR-0025: 利用状況の分析に Google Analytics 4 を使う

## Context

プロダクトの判断（PM）のために、利用状況を知る必要がある。見たいのは、どの機能が使われているか、登録から最初のメッセージまでのファネル、継続率などである。

一方、このシステムは、組織の会話という機密性の高いデータを扱う。そのため、次の 3 つを前提に使い方を決める。

- 障害の監視や性能の計測は、この ADR の対象外とする。これらは [ADR-0021](0021-observability-stack.md)（AMP・X-Ray・CloudWatch）と、自前の RUM（[observability.md](../architecture/observability.md)）で行う。GA は集計に時間がかかり、運用の監視には向かない。
- 第三者のスクリプトを読み込むと、CSP を広げることになり、XSS の攻撃面が増える（[security.md](../architecture/security.md)）。
- 第三者へ利用者の情報を送るため、法令への対応が要る。日本では電気通信事業法の外部送信規律、EU・英国では同意の取得が必要になる。

## Options

1. **Google Analytics 4**（gtag.js をクライアントで読み込む）
2. **自前の分析基盤**：イベントを API に送り、S3 と Athena で集計する
3. **自前でホストする分析ツール**（PostHog など）

## Decision

1 を採用する。ただし、送る内容と読み込む条件を強く絞る。

- PM が使い慣れた道具で、すぐに分析を始められる。
- 2 と 3 は、データが社外に出ない点で勝る。ただし、分析の画面と集計の基盤を自分で持つことになる。
- 企業顧客の要件で GA が使えなくなったときは、2 へ移る。イベントの定義（下記）を共通にしておき、送り先だけを差し替えられるようにする。

### 送ってよいもの

イベントは、`packages/analytics` に型付きで定義した許可リストだけにする。定義にないイベントや引数は、型検査で失敗させる。

| 送ってよい | 送らない |
| --- | --- |
| イベント名（`message_sent`、`channel_joined`、`search_performed` など） | メッセージの本文、ファイル名、検索語 |
| 列挙型の引数（チャンネルの種別、送信の手段、結果の件数の区分） | チャンネル名、ワークスペース名、表示名、メールアドレス |
| 画面の種類（`/workspaces/:ws/channels/:ch` のように ID を伏せた経路） | ID を含む URL、参照元の URL のクエリ |
| 仮名の ID（下記） | `account_id`・`member_id`・`workspace_id` そのもの |

- `user_id` には、`account_id` の HMAC（鍵はサーバーだけが持つ）を使う。ワークスペースは、`workspace_id` の HMAC をユーザー属性にする。GA の側からは、元の ID を復元できない。
- `page_location` と `page_referrer` は、送る前に、ID を伏せた経路へ書き換える。
- Google シグナル、広告のパーソナライズ、Google 広告との連携は無効にする。データの保持期間は 14 か月にする。

### 読み込む条件

- **アプリでは、Google Tag Manager を使わない。** gtag.js を直接読み込む。タグマネージャーを使うと、コードのレビューを経ずに任意のスクリプトを本番に足せてしまうため。マーケティング用のサイトでは使ってよい。
- **ワークスペースの管理者が、計測を無効にできる。** 無効のワークスペースを表示している間は、gtag.js を読み込まない。企業向けのプランでは、既定で無効にする。
- **同意を取ってから計測する。** Consent Mode v2 を使い、EU・英国の利用者には、同意するまで `analytics_storage` を `denied` にする。日本の利用者には、外部送信規律に沿って、送信先・送る情報・目的をプライバシーポリシーで公表し、設定画面で止められるようにする。
- CSP には、GA の送信先のドメインだけを `script-src`・`connect-src`・`img-src` に加える（[security.md](../architecture/security.md) と [client.md](../architecture/client.md) の CSP を更新する）。

## Consequences

- 良くなること：
  - PM が、機能の利用とファネルを自分で分析できる。
  - イベントの定義が型付きなので、送ってはいけないものが紛れ込みにくい。
- 引き受けるコスト：
  - 第三者のスクリプトを読み込むため、CSP が広がる。Google の配信の侵害は、アプリの XSS と同じ影響を持ちうる。
  - 同意しない利用者や、計測を無効にしたワークスペースの分は、GA に現れない。数値は全体の推計として読む。
  - 企業顧客のセキュリティ審査で、GA の利用を問われうる。既定で無効にすることと、送る内容の一覧で答える。

## Confirmation

- CI で、`packages/analytics` の外から gtag を直接呼んでいたら失敗させる。
- E2E で、送信されるリクエストを横取りして検査する。本文・名前・ID が含まれていないこと、計測を無効にしたワークスペースでは gtag.js が読み込まれないことを確かめる。
- 四半期ごとに、GA に届いているイベントと引数を、許可リストと照合する（QA）。
