# ADR-0015: ファイルは署名付き PUT で直接上げ、GuardDuty でスキャンし、CloudFront の短命な署名付き URL で配る

## Context

MVP にファイル添付（画像プレビューまで）を含める（intent.md）。ファイルには次の危険がある。

- マルウェアを配る経路になる。
- HTML や SVG を開かせて、アプリのオリジンでスクリプトを動かされる。
- 権限のない人やほかのワークスペースに、URL 経由で漏れる（quality.md のリスク 1 位）。

加えて、大きなファイルを API サーバーに通すと、状態を持たない API の資源を占有する。

## Options

アップロード：

1. API サーバーが受け取り、S3 に書く
2. 署名付きの PUT の URL で、クライアントが S3 に直接書く

スキャン：

1. GuardDuty Malware Protection for S3（マネージド）
2. ClamAV などを自前の Worker で動かす
3. 外部のスキャンサービスに送る

隔離：

1. 取り込み用と配信用のバケットを分け、問題がなければコピーする
2. 1 つのバケットで、スキャン結果のタグによるアクセス制御（TBAC）で止める

配信：

1. API がファイルを中継する
2. S3 の署名付き GET の URL
3. CloudFront の署名付き URL（専用ドメイン）

## Decision

アップロードは 2、スキャンは 1、隔離は 2、配信は 3 を採用する。

- **署名付き PUT で直接上げる。** 署名に大きさと種類を含め、完了時に `HeadObject` で大きさを確かめる。API は大きなバイト列を扱わない。
- **GuardDuty Malware Protection for S3 でスキャンする。** 保護対象のバケットへの書き込みで自動的に始まり、結果は EventBridge とオブジェクトのタグ（`GuardDutyMalwareScanStatus`）で得られる。シグネチャの更新やスキャン環境の隔離を、自分たちで持たずに済む。2 は定義ファイルの更新とスキャナーの運用が加わる。3 は顧客のファイルを第三者に渡す。
- **1 つのバケットと TBAC で隔離する。** `NO_THREATS_FOUND` のタグがないオブジェクトは、GuardDuty 以外の誰も読めない。加えて、DB の状態が `ready` でなければ API は URL を出さない。二重に止める。1 はコピーの手間と、コピーでの再スキャンの料金がかかるわりに、守りは TBAC と変わらない。
- **スキャン結果が `NO_THREATS_FOUND` 以外なら配らない。** `UNSUPPORTED`（暗号化されたアーカイブなど）も、安全側に倒す。
- **原本は常にダウンロードとして配る。** 画面に出すのは、サーバーが再エンコードしたサムネイル（WebP）だけ。サムネイルは別のバケットに置き、スキャンの対象にしない。
- **CloudFront の署名付き URL で、アプリとは別のドメインから配る。** 有効期限は原本 5 分、サムネイル 15 分。応答のヘッダー（`attachment`、`nosniff`）は経路ごとに CloudFront で固定する。1 は API の帯域と接続を占有する。2 はキャッシュが効かず、応答のヘッダーを一律に固定しにくい。
- **1 つのファイルは 1 つのメッセージにだけ付く。** ファイルを読めるかを、メッセージのチャンネルを読めるか（ADR-0005）に帰着させる。

詳細は [files.md](../architecture/files.md)。

## Consequences

- 良くなること：
  - スキャン前・感染したファイルが、配られない。S3 と DB の二重の止めになる。
  - 利用者が上げた内容が、アプリのオリジンでも、inline でも動かない。
  - API がファイルのバイト列を扱わない。
- 引き受けるコスト：
  - スキャンが終わるまで（通常は数秒〜数分。未検証）、ファイルを開けない。画面に「スキャン中」を出す必要がある。
  - GuardDuty のスキャンとタグ付けに、データ量とオブジェクト数に応じた料金がかかる。保護できるバケットは 1 アカウント・1 リージョンあたり 25 なので、セル構成（S3）でもバケットの数を抑える。
  - 暗号化されたアーカイブなど、スキャンできないファイルは共有できない。要望が強ければ、ワークスペースの設定で許す案を別途検討する。
  - 署名付き URL は取り消せない。権限を失った人が、有効期限の間だけ使える。
  - 同じファイルを複数のメッセージで共有できない。共有したいときは、上げ直しになる。

## Confirmation

- ステージングで EICAR のテストファイルを上げ、`blocked` になること、CloudFront 経由で取得できないことを確かめる。
- IaC の検査：`uploads` バケットに TBAC のポリシー（読み出しの拒否と、タグの書き換えの禁止）があり、パブリックアクセスが遮断されている。
- 経路ごとの漏洩テスト（quality.md）：別のワークスペース、参加していないチャンネル、削除済みのメッセージのファイルに、URL が発行されない。
- 原本の応答が、申告した種類によらず `attachment` と `nosniff` を持つ。
