# ADR-0028: AI エージェント向けに、リモートの MCP サーバーを提供する

## Context

利用者が、自分の AI エージェント（MCP クライアント）から、ワークスペースの会話を読み、検索し、必要なら投稿したいという要求がある。

一方、intent.md では、汎用の公開 API とボットのプラットフォームを、互換性の維持の負担を理由に対象外にしている。

関係する技術の状況は次のとおり。

- MCP の 2026-07-28 版で、Streamable HTTP からセッションがなくなり、ステートレスになった。
- クライアントの登録は、Client ID Metadata Document（CIMD）が推奨になり、Dynamic Client Registration（DCR）は非推奨になった。
- 認可サーバーには、OAuth 2.1 と Protected Resource Metadata（RFC 9728）が求められる。

## Options

1. **リモートの MCP サーバーを、専用のサービスとして提供する**（メンバーの委任、OAuth 2.1）
2. **汎用の公開 API を作り、MCP サーバーは第三者に任せる**
3. **提供しない**

## Decision

1 を採用する。

> 2026-09-26 の注記：汎用の公開 API は、MVP の後（E12）に提供することにした（[ADR-0030](0030-versioned-public-api.md)）。下の「汎用の公開 API を作らないという方針は保つ」は、これで改められた。MCP は AI エージェント向けの小さな面として残し、公開 API と同じサービス関数の上に作る。この ADR は書き換えない。

- **権限の上限はメンバーと同じ。** エージェントは、同意したメンバーの権限の範囲でだけ動く。テナントのコンテキストと権限の判定（ADR-0005、0009）を、api と同じドメインの層で通す。
- **小さな面に絞る。** ツールは、読み取り・検索・投稿・リアクションに限る。管理の操作、一斉メンション、ファイルの本体は出さない。汎用の公開 API を作らないという方針は保つ。
- **認可は Better Auth で行う**（[ADR-0012](0012-self-hosted-auth-with-better-auth.md)）。`@better-auth/mcp`（OAuth 2.1 の提供者、RFC 9728、トークンの `aud` の束縛）と `@better-auth/cimd` を使う。同意は（アカウント、クライアント、ワークスペース）の組で記録する。DCR は有効にしない。
- **mcp は独立したステートレスのサービス**（ECS Fargate、Hono＋MCP の公式 TypeScript SDK v2）にし、Web と別のオリジンで公開する。受け取ったトークンを、他のサービスへ横流ししない。
- 2 は、汎用の API の互換性を長く保つ負担が大きく、intent の方針に反する。第三者のサーバーが、利用者のトークンを預かる形にもなる。
- 3 は、利用者が非公式の方法（ブラウザの自動操作など）で会話を持ち出すことを促し、かえって統制が効かなくなる。

設計の詳細は [mcp.md](../architecture/mcp.md) にある。

## Consequences

- 良くなること：
  - 利用者が、公式で監査できる経路で、AI エージェントから会話を使える。
  - ワークスペースの管理者が、MCP の利用、許可するクライアント、書き込みの可否を統制できる。
- 引き受けるコスト：
  - ツールの入出力が、外部との契約になる。互換性を壊す変更は、新しいツール名で出し、古いツールを告知してから外す。
  - プロンプトインジェクションで、エージェントが意図しない書き込みをしうる。書き込みの既定を無効にし、レート制限と監査で抑える。
  - MCP の仕様の改訂が速い。仕様の版ごとの互換を、Better Auth と SDK の更新に合わせて保つ必要がある。

## Confirmation

- 結合テスト：
  - トークンの `aud` が mcp でないもの、別のワークスペースのもの、取り消し済みのものを拒否する。
  - スコープにないツールを拒否する。
- 性質ベーステスト：任意のメンバーとツールの呼び出しで、MCP が返すデータは、同じメンバーが API で読めるデータの部分集合である。
- CI で、MCP の仕様の適合を検査する。対象は、Protected Resource Metadata、401 の応答、古い版への 405。
- ツールの説明文と入出力のスキーマを、`packages/contract` の Zod で定義し、スナップショットで差分を検知する（ADR-0008 と同じ考え方）。
