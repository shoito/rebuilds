# Intent: Slack を AI エージェント主体で再構築する

- Author: shoito
- Status: accepted
- Date: 2026-09-26

## Problem

チームのチャットツールは、組織の意思決定と知識の大部分が流れる基盤になっている。一方で、その中身（配信の順序保証、既読管理、権限と検索の整合）は外から見えにくい。小さなチームと AI エージェントで、本質的な部分をどこまで作り直せるかも、まだ実証されていない。

## Proposed outcome

ワークスペース単位で閉じた「チャンネル型メッセージング」を、順序が保証されたイベントストリームとして作り直す。小さなチームと AI エージェントで、数週間のうちに、次の 3 つの価値を満たす MVP を動かす。

1. **速い会話**：送ったメッセージが、相手の画面に 1 秒以内に、正しい順序で出る。
2. **取りこぼさない**：未読・メンション・スレッドにより、どこで何が起きたかを後から確実に追える。
3. **積み上がる知識**：過去のやり取りが検索でき、チームの記録として残る。

絵文字や連携機能の多さは価値を増幅するものであって、本質ではない。MVP では上の 3 つだけを確実に作る。

### MVP に含める

- ワークスペース、メンバー、招待（メールリンク）
- パブリック / プライベートチャンネル、DM（1:1 と少人数グループ）
- メッセージの投稿・編集・削除、スレッド返信、リアクション、@メンション
- 既読位置と未読数、メンション数のバッジ
- ファイル添付（画像プレビューまで）
- 全文検索（日本語対応）
- Web クライアント

### 守るべき振る舞い

個々の要件は各変更の `spec.md` で定義する。ここには、それらすべてが満たすべき前提を書く。

- メッセージはチャンネル内で、**全メンバーが同じ順序** で見る。
- クライアントが切断・再接続しても、欠けたメッセージを自動で補完する。
- 同じメッセージの二重送信（再送・ボタン連打）で、重複投稿しない。
- 編集・削除・リアクションも、接続中の全クライアントにリアルタイムで反映する。
- 権限のないチャンネルの内容は、検索・通知・API のどこからも見えない。

## Affected users and systems

- ワークスペースのメンバー（一般メンバー、管理者、ゲスト）
- Web クライアント（PWA）
- 通知の送り先（メール、Web Push）

## Constraints

- 多数のワークスペースを 1 つのシステムで提供するマルチテナント SaaS とする。ワークスペースをまたいだデータの漏洩は、どんな機能よりも優先して防ぐ。
- 規模は 1 ワークスペース最大 5,000 人、全体で同時接続 5 万を想定する（段階的に 100 万接続まで拡張する。詳細は [architecture/](architecture/README.md) の「規模の段階」と「非機能要件」）。
- 本家の内部実装の再現は目的にしない。公開情報は参考にとどめる。
- 実装の大部分を AI エージェントが担う前提で、技術を選ぶ。

## Non-goals

| 機能 | 理由 |
| --- | --- |
| 音声・ビデオ通話（Huddle） | WebRTC / SFU は別の製品と言えるほど大きい |
| Slack Connect（組織間チャンネル） | テナント境界をまたぐ権限モデルが必要になり、MVP の単純さを壊す |
| アプリ / Bot プラットフォーム、汎用の公開 API | 外部公開 API の互換性を維持する負担が大きい。内部イベントが安定してから公開する。ただし、AI エージェント向けのリモート MCP サーバーは、面を小さく絞って提供する（[ADR-0028](decisions/0028-remote-mcp-server.md)） |
| Enterprise Grid（複数ワークスペースの束ね） | 需要が大企業に限られる。データモデル上の拡張余地だけ残す |
| モバイルネイティブアプリ | Web（PWA）で代替する。API とイベント仕様を先に固める |

## Open questions

- 未読数をどこまで正確にするか。現時点では近似で許容している（[read-state-and-notifications.md](architecture/read-state-and-notifications.md)）。
- データの保持期間と、法的保全（リーガルホールド）をいつ扱うか。
- ワークスペースの削除・エクスポートと、データの保管地域（データレジデンシー）をいつ扱うか。
