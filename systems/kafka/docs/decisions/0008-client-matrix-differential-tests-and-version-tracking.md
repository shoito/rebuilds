# ADR-0008: 行列は具体の版で持ち、差分テストは生の要求を正規化して比べ、本家は x.y.1 以降を取り込む

詳細は [protocol-and-compatibility.md](../architecture/protocol-and-compatibility.md) の 6〜8 節。

## Context

[ADR-0005](0005-compatibility-policy.md) は、クライアントの行列、本家との差分テスト、3 か月以内の版の取り込みを決めた。具体の版、差分テストの作り方、取り込む版の選び方は、この領域に任された。

事実（2026-09-27 に各リポジトリで確認）：

- Java：4.3.1 が最新。4.4.0 は RC1（2026-09-22 のタグ）。
- librdkafka v2.15.1（2026-09-09）、franz-go v1.22.0、Sarama v1.61.0（2026-09-22）。
- KafkaJS の最後のリリースは 2.2.4（2023-02-27）で、最後の push は 2024-08-02。confluent-kafka-javascript（librdkafka の上の Node.js のクライアント）は v1.10.1（2026-09-10）。
- 本家の 4.3.0 は 2026-05-22、4.3.1 は 2026-06-25 に出た（[4.3.0 の発表](https://kafka.apache.org/blog/2026/05/22/apache-kafka-4.3.0-release-announcement/)）。
- ApiVersions の要求はクライアントの名前と版を運ぶ（KIP-511。[Protocol Guide](https://kafka.apache.org/43/design/protocol/)）。

## Options

差分テスト：

1. **生の要求の列（版を指定）を、本家と自社の両方に送り、応答を正規化して比べる**
2. **クライアントのライブラリで操作を流し、結果（読めたレコード）だけを比べる**
3. **本番の通信を記録して、本家に再生する**

取り込む版：

- A. **x.y.0 が出たらすぐ取り込む**
- B. **x.y.1 以降を、x.y.0 から 3 か月以内に取り込む**

## Decision

1 と B を採用する。

- 差分テストの送り手は、本家の Java の要求の型で、API と版を指定して組み立てる。生成器で列を作り、シードを記録する。
- 比べる前に、非決定的な値（throttle の時間、ID、ホスト、タイムスタンプなど）を消す。違いは「許された違い」の表（[ADR-0006](0006-api-exposure-table-and-denial.md) の拒否・絞る・フラグ、[ADR-0007](0007-topic-config-allowlist.md) の固定の設定）と照合し、表にない違いを失敗にする。正規化の規則の追加はレビューを受ける。
- 2 は、クライアントの再試行と版の選択に違いが隠れる。行列（別のテスト）で補う。
- 3 は、利用者のデータを記録することになる（[AGENTS.md](../../AGENTS.md)）。
- 行列の Node.js は、confluent-kafka-javascript を「対応」、KafkaJS を「凍結」（日次で流すが、壊れても直さない）にする。ADR-0005 の「止まっていれば、代わりを選ぶ」に従う。
- 本家は x.y.1 以降を入れる。x.y.0 から 3 か月を過ぎても x.y.1 がなければ、Dev のテックリードが判断する。RC の段階から差分テストと行列と耐久性のテストを回す。
- フィーチャーの版（`metadata.version` など）は、全ての物理クラスタでバイナリが揃ってから 7 日後に上げる。
- A は、x.y.0 の不具合を最初に踏む。耐久性を最優先にする題材に合わない。

## Consequences

- 良くなること：
  - 違いが機械的に見つかり、許された違いが表として残る。
  - 本家の初期の不具合を避けつつ、ADR-0005 の 3 か月を守れる。
- 引き受けるコスト：
  - 生の要求の送り手は、本家の内部の型に依存する。本家の版ごとに直す。
  - KafkaJS の利用者に、移行を案内する必要がある。データ面のエージェントの Admin API のクライアント（[ADR-0001](0001-upstream-brokers-and-stack.md) の候補の KafkaJS）も見直す（control-plane-and-provisioning の領域）。

## Confirmation

- CI：差分テスト（PR ごとに代表、日次に全体）と行列の結果。「許された違い」の表の行数の増減を毎回出力する。
- 監視：本家の最新のマイナー版からの遅れ（日数）。3 か月を超えたらアラート。
