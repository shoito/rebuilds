# ADR-0005: 互換の範囲は、動かしている本家のブローカーの API から管理の API を除いたものにし、行列と差分テストで確かめる

## Context

intent.md の最初の価値は「既存のクライアントがそのまま動く」ことである。決めることは 4 つある。

- どの API と、どの版を受け付けるか
- マルチテナントで許せない API（クラスタ全体の管理）をどう扱うか
- 互換をどう確かめるか
- 古い版をいつ、どう止めるか

事実（いずれも 2026-09-27 に確認）：

- 本家の Apache Kafka は、4.0 で、2.1 より古いクライアントのプロトコルの版を取り除いた（KIP-896。[4.0.0 の発表](https://kafka.apache.org/blog/2025/03/18/apache-kafka-4.0.0-release-announcement/)、[KIP-896](https://cwiki.apache.org/confluence/display/KAFKA/KIP-896%3A+Remove+old+client+protocol+API+versions+in+Kafka+4.0)）。4.0 の最小のクライアントは 2.1 である。
- 本家の最新は 4.3（2026-05-22。4.3.1 は 2026-06-25）。4.3 は、従来のリバランスのプロトコルでコンシューマーを起動すると、新しいプロトコル（KIP-848）を勧める記録を出す（[4.3.0 の発表](https://kafka.apache.org/blog/2026/05/22/apache-kafka-4.3.0-release-announcement/)）。
- 共有のグループ（KIP-932）は 4.2 で本番向けになった（[4.2.0 の発表](https://kafka.apache.org/blog/2026/02/17/apache-kafka-4.2.0-release-announcement/)）。
- クライアントの版は ApiVersions の要求で、ブローカーが受け付ける API の版の範囲を知り、両者が対応する最大の版を使う。

[ADR-0001](0001-upstream-brokers-and-stack.md) で、本家のブローカーを使うと決めた。

## Options

1. **本家の ApiVersions をそのまま広告し、管理の API だけを拒否する。互換は、クライアントの行列と、本家のブローカーとの差分テストで確かめる**
2. **使ってよい API と版の許可リストを自前で持ち、それ以外を広告しない**
3. **互換の範囲を文書で宣言するだけで、テストは主要なクライアントの結合テストに限る**

## Decision

1 を採用する。

### 受け付ける API

- 動かしている本家の版が広告する API と版を、そのまま広告する。版の範囲は、本家の版を上げると広がる。
- 次の API は、テナントには拒否する。ApiVersions では広告したまま、本家と同じエラーコード（`CLUSTER_AUTHORIZATION_FAILED`、`TOPIC_AUTHORIZATION_FAILED`、`POLICY_VIOLATION` など、その API に定義されたもの）を返す。接続は切らない。広告から外すと、一部のクライアントや管理の道具が起動時に失敗する恐れがあるため。
  - ブローカー・コントローラーの間の API と、クラスタの構成を変える API（パーティションの再配置、ログのディレクトリの変更、リーダーの選出の強制、クォーラムの変更、フィーチャーの更新、ブローカーの登録の解除など）
  - クライアントのクォータの変更（AlterClientQuotas）。クォータは層と CU で決まる
  - SCRAM の資格情報の変更。API キーは制御面で発行する
  - 許可リストにないトピックの設定の変更（CreateTopicPolicy・AlterConfigPolicy で拒否する）
- 拒否する API の正確な一覧と、許可するトピックの設定の一覧は、protocol-and-compatibility の領域の文書に表で持ち、開発リポジトリの spec の正本にする。
- 共有のグループ（KIP-932）は、クォータとテストを足すまで、フィーチャーフラグで無効にしておく。無効の間は、本家で無効のときと同じ応答を返す。

### 対応するクライアント

| クライアント | 言語・用途 | 行列に入れる版 |
| --- | --- | --- |
| Apache Kafka の Java のクライアント（Kafka Streams を含む） | Java・JVM の言語 | 最新、1 つ前のマイナー版、3.x の最後、2.1（最小の版） |
| librdkafka（とその上の Python・Go・.NET のクライアント） | C と、それを包む各言語 | 最新、1 年前の版 |
| franz-go | Go | 最新 |
| Sarama（IBM） | Go | 最新 |
| KafkaJS | Node.js | 最新（保守の状況は未検証。止まっていれば、代わりの Node.js のクライアントを選ぶ） |

- 「対応する」とは、行列のテストが通り、問題を受け付けて直すことを指す。行列の外のクライアントも、プロトコルに沿っていれば動くが、保証はしない。

### 互換の確かめ方

| テスト | 中身 | 頻度 |
| --- | --- | --- |
| クライアントの行列 | 各クライアントの代表の操作（produce・fetch、冪等、トランザクション、グループの 2 つのプロトコル、オフセットの操作、管理の操作、エラーの扱い）を、自社のクラスタに対して流す。各クライアントの持つ結合テスト（librdkafka、franz-go などは、実際のブローカーに対して流すテストを持つ）を、実行できる範囲で流す | PR ごと（代表の操作）、日次（全体） |
| 本家との差分テスト | 同じ要求の列を、本家のブローカー（パッチなし）と自社のブローカー（パッチ＋差し込み口）に送り、応答（エラーコード、オフセット、見える資源）を比べる。違いは、上の「拒否する API」と、名前空間による違いだけであること | PR ごと |
| 耐久性（Jepsen の形） | Jepsen の Kafka のワークロード（queue、トランザクション）で、ブローカーの停止、ネットワークの分断、AZ の喪失、時計のずれ、ディスクの遅延を注入し、`acks=all` の書き込みの喪失、中止したトランザクションの読み取り、オフセットの矛盾を検出する（[jepsen.tests.kafka](https://jepsen-io.github.io/jepsen/jepsen.tests.kafka.html)） | 日次と、耐久性に関わる PR ごと |
| Kafka Streams | exactly-once（`exactly_once_v2`）の代表のトポロジーを、障害注入の下で動かし、出力の重複・欠落がないことを確かめる | 日次 |

- Jepsen が本家の Kafka のトランザクションで報告した問題（[Jepsen: Bufstream 0.1.0](https://jepsen.io/analyses/bufstream-0.1.0)）のうち、本家で直っていないものは、差分テストでも「本家と同じ」になる。これは互換としては正しいが、利用者向けの文書に既知の制約として書く。

### 版の追従と廃止

- 本家の新しいマイナー版は、出てから 3 か月以内に取り込む。新しい API の版は、名前空間の表（[ADR-0004](0004-logical-clusters-on-shared-physical-clusters.md)）と行列を更新してから広告する。
- 本家が古い版を取り除くとき（KIP-896 のような場合）は、本家の版の更新を遅らせてでも、6 か月前に告知する。告知の間は、該当する版で接続しているクライアントの数を、テナントごとにメトリクスとコンソールで見せる。
- 自社の都合で、本家が受け付けている版を止めることはしない。

## Consequences

- 良くなること：
  - 互換の範囲の定義が単純で、本家の文書とクライアントの挙動をそのまま参照できる。
  - 差分テストで「本家と同じか」を機械的に確かめられる。
- 引き受けるコスト：
  - 本家の版に、互換の範囲が引きずられる。本家の既知の問題も引き継ぐ。
  - 行列と Jepsen の形のテストは、実行の時間と費用が大きい。PR ごとと日次に分ける。
  - 管理の API を「広告して拒否する」ので、管理の道具によっては、拒否のエラーを表示する。文書に一覧を書く。

## Confirmation

- CI：上の表のテストを、決めた頻度で回し、失敗したらマージしない（日次の失敗は、次の PR をマージする前に直すか、Issue にして Dev のテックリードの判断を受ける）。
- CI：ApiVersions の広告する API の一覧を、本家のパッチなしのブローカーと比べ、違いがないことを確かめる。
- テスト名に、対応する要件の ID（`REQ-...`・`PROP-...`）を含める（ルートの AGENTS.md）。
