# ADR-0015: 検索の権限は、読めるリポジトリの条件をクエリの前段に入れ、権限の属性の変更は除外の表で即時に効かせる

[ADR-0002](0002-repository-permission-model.md) の「検索では、索引の段階で公開の種類とリポジトリの ID を持たせ、クエリの前段で絞る」を、コード検索（Zoekt）と Issue・Pull Request・リポジトリの検索（OpenSearch）について具体化する。

## Context

非公開のリポジトリの中身が、検索から権限のない人に見えてはならない（intent.md、NFR-010）。検索の結果だけでなく、件数・ページング・ハイライト・応答時間からも、存在が漏れうる。

本家の Blackbird は、全シャードに問い合わせてから、集めた結果を権限で絞る（[The technology behind GitHub's new code search](https://github.blog/engineering/architecture-optimization/the-technology-behind-githubs-new-code-search/)）。ADR-0002 は、後から除く方式を採らないと決めている。

前段で絞るには、索引の文書に権限の属性（公開の種類、持ち主、enterprise）の写しを持たせる必要がある。写しは、非同期の索引の更新で遅れる。公開 → 非公開、非公開のリポジトリの別の Organization への移動、Issue の非公開のリポジトリへの移動の直後に、古い写しで当たると漏洩になる。

## Options

1. **読めるリポジトリの条件（公開 ∪ enterprise ∪ 持ち主 ∪ リポジトリの ID）をクエリに入れ、権限の属性の変更は、同じトランザクションで書く除外の表で、索引の更新まで検索から外す**
2. 文書に権限の属性を持たせず、読めるリポジトリの ID をすべて列挙してクエリに入れる
3. 本家と同じく、結果を後から権限で絞る
4. 権限の属性の変更を、索引の更新が終わるまで同期で待つ

## Decision

1 を採用する。詳細は [search.md](../architecture/search.md) の 4 節にある。

- **条件は、判定関数の `accessPredicate(actor)`（[identity-and-permissions.md](../architecture/identity-and-permissions.md)）から作る。** 公開のリポジトリ、所属する enterprise の internal のリポジトリ、基本の権限で読める持ち主の非公開のリポジトリ、個別に読めるリポジトリの ID の集合の和で表す。`can` と同じ集合を表すことを、性質ベーステストで確かめる。
- 条件はリクエストごとに DB から作り、キャッシュしない。権限を外すと、次の検索からすぐに効く。
- **権限の属性を変えるトランザクションの中で、`search_exclusions` に行を書く。** 全ての検索は、未処理の行のリポジトリ・Issue を `must_not`（Zoekt も同等の否定の条件）に入れる。両方の索引の更新が済んだら行を片付ける。
- クエリは組み立て関数 1 つだけで作り、条件と除外を必ず含める。検索のクライアントを他の場所から使うことを lint で禁止する。
- 結果は、API で判定関数を通して読み直す。権限が理由で落ちた件数を計測し、0 件でなければバグとして扱う（多層防御）。
- 2 を採らない理由：公開のリポジトリは数百万になり、ID で列挙できない。大きな Organization のメンバーも数万の ID になる。
- 3 を採らない理由：ADR-0002 に反する。件数・ページングから存在が漏れ、非公開の多い人のページが空になる。
- 4 を採らない理由：公開の種類の変更の API が、検索のクラスタの遅れと障害に巻き込まれる。除外の表なら、DB のトランザクションだけで漏洩の窓を閉じられる。

## Consequences

- 良くなること：
  - 公開の種類の変更・移動の直後の漏洩の窓がなくなる（変更と除外が同じトランザクション）。
  - 権限の変更（メンバーの除外）が、索引の作り直しなしに、すぐ効く。
- 悪くなること、引き受けるコスト：
  - 除外の対象のリポジトリは、変更後に読める人にも、索引の更新が済むまで検索に出ない。
  - 検索のたびに、条件と除外の表を DB から読む。検索のたびに DB への問い合わせが増える。
  - 個別に読めるリポジトリが 65,536 を超える人は、OpenSearch の `terms` の上限に当たるので、範囲の指定を求める。
  - 索引の更新が止まると、除外の表の行が残り続け、そのリポジトリが検索に出ない状態が続く（アラートで検知する）。

## Confirmation

- 性質ベーステスト：`accessPredicate` と `can` の一致。任意の検索の構造について、組み立てた要求が権限の条件と除外を含む。
- 漏洩テスト：公開 → 非公開の直後、別の Organization への移動の直後、コラボレーターから外した直後、Issue を非公開のリポジトリへ移した直後に、コード検索・Issue の検索・リポジトリの検索の結果・件数・ハイライトに出ない。索引の更新を止めた状態でも出ない。
- 運用：`search_hydration_permission_drop` が 0 でなければアラート。`search_exclusions` に 15 分を超えて残る行があればアラート。
