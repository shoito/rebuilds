# ADR-0030: 削除したリポジトリは 90 日の間は復元でき、その後に消去する。アカウントの削除は復元せず、バックアップの期限を削除の最終的な期限にする

## Context

GitHub の削除には、Slack にない難しさがある。

- **リポジトリは 3 つの複製とバックアップにある**（[ADR-0003](0003-replicated-git-storage.md)）。
- **fork のネットワークはオブジェクトを共有する。** 親を消しても、fork から到達できるオブジェクトは消せない（[git-storage.md](../architecture/git-storage.md)）。
- **誤った削除が多い。** リポジトリの削除は、名前を 1 つ打ち込めば実行でき、取り返しがつかないと被害が大きい。
- **他人の場所に残る書き込み。** 利用者は、他人のリポジトリに Issue・コメント・レビューを書く。

本家の振る舞いは次のとおり（2026-09-26 に確認）。

- 削除したリポジトリは 90 日の間は復元できる。ただし、活動中の fork のネットワークに属していたリポジトリは、ネットワークの他のリポジトリがすべて削除・切り離されるまで復元できない。チームの権限は復元されない（[Restoring a deleted repository](https://docs.github.com/en/repositories/creating-and-managing-repositories/restoring-a-deleted-repository)）。
- 個人のアカウントの削除は復元できない。持つリポジトリ・非公開のリポジトリの fork・Issue・PR などは消える。他人のリポジトリへの Issue・PR・コメントは残り、ghost の利用者に付け替わる。名前は 90 日後に誰でも使える。人気のある公開のリポジトリ（Marketplace の Action を含む、または前の週に 100 回を超える clone か Actions の利用があった）の `OWNER/REPOSITORY` の組は永久に使えなくなる（[Deleting your personal account](https://docs.github.com/en/account-and-profile/how-tos/account-management/deleting-your-personal-account)、[Personal account reference](https://docs.github.com/en/account-and-profile/reference/personal-account-reference)）。
- Organization の削除も復元できない。名前は 90 日使えない（[Deleting an organization account](https://docs.github.com/en/organizations/managing-organization-settings/deleting-an-organization-account)）。
- プライバシーステートメントは、削除後の保持の日数を示していない。

## Options

1. **削除の操作で、その場で 3 つの複製とメタデータを消す**
2. **本家に揃える：リポジトリは論理削除にして 90 日は復元でき、その後に消去する。アカウント・Organization の削除は復元せず、すぐに消去に入る。バックアップは期限で消えるのを待つ**
3. 2 に加えて、**アカウント・Organization にも猶予の期間を設けて復元できるようにする**

## Decision

2 を採用する。

- 1 は、誤った削除を救えない。fork のネットワークの共有オブジェクトの扱いも、削除の操作の中でしなければならない。
- 3 は、本家の振る舞いと違い、名前の解放・課金の停止・持ち主の移譲の規則が複雑になる。利用者にとって「消したのに残っている」ことの説明も要る。必要になったら新しい ADR で足す。

### リポジトリの削除と復元

```
削除（admin、再認証を求める）
  └─▶ 同じトランザクションで：repositories.deleted_at を設定、名前を解放、監査ログ（repo.destroy）、
      outbox に削除の Event
        ├─▶ 検索：索引から消す
        ├─▶ Webhook・通知：配信の対象から外す
        └─▶ Git ストレージ：複製を「削除済み」の領域へ移す（ディスク上は残す）
90 日の間：持ち主（個人・Organization の owner）が復元できる
  └─▶ 名前が別のリポジトリに使われていれば、別の名前で復元する
90 日の後：消去のジョブ
  └─▶ 3 つの複製、S3 の LFS・リリースの成果物、Issue・PR・コメント、Actions のログ・成果物を消す
```

- 復元は、Git の中身、Issue・PR・コメント、リリース、Webhook の設定を戻す。チームの権限・コラボレーターの招待は戻さない（本家と同じ）。
- **fork のネットワーク**：
  - 削除したリポジトリの ref は消えるが、ネットワークの共有のオブジェクトは、他のリポジトリから到達できる限り残る。到達できなくなったものは、ネットワークの保守（gc）で消える。
  - ネットワークに他のリポジトリが残っている間の復元は、本家と同じく利用者の操作では許さず、運用者（サポート）が行う。自動での復元は、ネットワークに戻すときの権限と共有オブジェクトの整合の検証ができてから足す。
- 公開のリポジトリの削除は、fork を消さない。fork のネットワークの親が別の fork に移る（詳細は [git-storage.md](../architecture/git-storage.md)）。非公開のリポジトリの削除は、その fork も削除する（本家の振る舞いの細部は git-storage.md で確かめる）。

### アカウント・Organization の削除

1. 本人（Organization は owner）が依頼する。再認証を求める。唯一の owner である Organization があれば、先に移譲か削除を求める。
2. 直ちに：ログイン・トークン・SSH の鍵を無効にする。持つリポジトリを、上の「90 日の後」の消去のジョブに直接入れる（復元の期間を置かない）。
3. 他人のリポジトリへの Issue・PR・コメント・レビューは残し、作者を ghost 相当の利用者に付け替える。コミットの作者の情報は Git の中身なので変えない。
4. 名前は 90 日間、他のアカウント・Organization が使えない。人気のある公開のリポジトリの `OWNER/REPOSITORY` の組は永久に予約する（本家と同じ条件）。依存の名前の乗っ取り（repojacking）を防ぐため。
5. 個人情報（メールアドレス、認証の情報、プロフィール）を消す。完了を `platform_audit_events` に残す。

### 無効化は削除ではない

DMCA・濫用・法的な要求による無効化（[security.md](../architecture/security.md) の 6 節）は、データを残して見えなくする状態であり、削除の期限の対象にしない。持ち主が削除を選べば、上の流れに入る。

### リーガルホールド

- 法執行・訴訟のために、運用者が特定のリポジトリ・アカウントの消去を止められる。ホールドは消去のジョブに優先する。
- 顧客が設定するリーガルホールド（Slack の ADR-0019 のような）は、MVP に含めない。

### 削除の最終的な期限

- バックアップ（Aurora の自動バックアップ、Git のバックアップ、大阪へのコピー）は 35 日で消える。バックアップの中を個別には消さない。
- 顧客への説明：

  | 操作 | バックアップを含めて消えるまで |
  | --- | --- |
  | リポジトリの削除 | 復元の期間 90 日＋消去＋35 日で、最長 125 日 |
  | アカウント・Organization の削除 | 消去＋35 日で、最長 35 日（消去のジョブの時間を除く） |
  | Issue・コメントの削除 | 論理削除の後、日次の消去＋35 日で、最長 36 日 |

- バックアップから戻したときは、戻した時点の後の削除を再適用してからサービスに戻す。削除の記録（リポジトリ・アカウントの ID）をバックアップとは別に 35 日以上持つ。
- 例外は監査ログのアーカイブ（400 日。[ADR-0029](0029-audit-log.md)）。本文を含めず、ID・IP・User-Agent に限る。

### 消去のジョブ

- 冪等にし、途中で止まっても再実行で完了できるようにする。
- 消去の対象のテーブル・S3 の接頭辞・索引の一覧は、スキーマの定義から得る。テーブルの追加で消し漏れが起きないよう、CI で検査する。
- 3 つの複製の消去は、ルーティングの表から全ての複製と、作り直しの途中の複製を含めて行う。
- Git のバックアップは「最新の完全な復元点を常に残す」（[infrastructure.md](../architecture/infrastructure.md) の 5 節）。消去したリポジトリはこの例外から外し、消去から 35 日（Object Lock の期間）が過ぎたら復元点ごと消す。

## Consequences

- 良くなること：
  - 誤ったリポジトリの削除を、90 日の間は救える。本家の利用者の期待と一致する。
  - 削除の期限を数字で示せる。
  - 名前の予約で、削除した名前の乗っ取りを防げる。
- 引き受けるコスト：
  - 削除したリポジトリの複製を 90 日持つので、ストレージの容量が増える（[capacity.md](../architecture/capacity.md) に削除の率の前提を置く）。
  - fork のネットワークの復元を運用者の手作業にするので、サポートの手順が要る。
  - 消去のジョブ、削除の再適用、名前の予約の表を持つ。

## Confirmation

- 結合テスト：リポジトリの削除の直後に、Web・API・Git・検索・Webhook のどれからも中身が返らない。90 日以内の復元で、Git の中身と Issue・PR が戻り、チームの権限は戻らない。
- 結合テスト：消去の後、全テーブル・S3・索引・3 つの複製に、そのリポジトリの ID のデータが 0 件。対象の一覧はスキーマの定義から得る。
- 性質ベーステスト：任意の fork・削除・復元の列で、ネットワークに残るリポジトリから到達できるオブジェクトが消えない。
- 結合テスト：アカウントの削除の後、個人情報がどのテーブルにも残らず、他人のリポジトリのコメントは ghost 相当に付け替わる。
- 復元の訓練（runbook の `repository-restore`）に、削除の再適用を含める。
