# Intent: Figma を AI エージェント主体で再構築する

- Author: shoito
- Status: accepted
- Date: 2026-09-27

## Problem

画面のデザインは、デザイナーが作り、開発者が実装し、PM が確かめる。デザインのファイルが個人の端末にあると、最新のバージョンがどれか分からず、書き出しと受け渡しのたびに食い違いが生まれる。

本家 Figma は、これを「ブラウザで開ける 1 つのファイルを、全員が同時に見て編集できる」形にした。中身は、ブラウザの中に自前の描画エンジンを持ち、ファイルごとに 1 つのサーバーのプロセスが変更の順序を決める仕組みである（[Building a professional design tool on the web](https://www.figma.com/blog/building-a-professional-design-tool-on-the-web/)、2015-12-07。[How Figma's multiplayer technology works](https://www.figma.com/blog/how-figmas-multiplayer-technology-works/)、2019-10-16。いずれも 2026-09-27 に確認）。

この「ブラウザの中の描画エンジン」と「ファイルごとのマルチプレイヤー」を、小さなチームと AI エージェントでどこまで作り直せるかを確かめる。rebuilds の Notion（CRDT を使う共同編集）と比べられるように、中央のサーバーが順序を決める方式の設計を残すことにも意味がある。

## Proposed outcome

デザイナー・開発者・PM が、ブラウザで同じデザインのファイルを開き、同時に編集し、コメントでやり取りし、書き出せる。次の 3 つの価値を満たす。

1. **手元のアプリのように速い**：大きなファイルでも、パン・ズーム・選択・変形が 60fps で動く。入力は 1 フレームで画面に出る。
2. **一緒に作れる**：他の人の編集とカーソルが、すぐに（同じリージョンで 0.25 秒以内に）見える。競合しても全員の画面が同じ結果に収束する。
3. **失わない**：確定を返した編集は、プロセスが落ちても失わない。過去のバージョンに戻れる。

### 利用者

| 利用者 | 主な使い方 |
| --- | --- |
| デザイナー | ベクターの編集、フレームとオートレイアウト、コンポーネントとバリアント、同時編集 |
| 開発者 | 閲覧、寸法と色の確認、コメント、書き出し。MVP の後に Dev Mode 相当 |
| PM・レビュアー | 閲覧、コメント、共有のリンクでの確認 |
| チームの管理者 | チーム・プロジェクト・メンバーと権限の管理 |

**日本の市場を先に狙う。** UI は日本語を先に作る。日本語のフォント（和文の既定のフォント、欧文との混植）、IME での日本語の入力、円での請求を MVP で扱う。

### MVP に含める

- **デザインのファイルとベクターの編集**：図形（矩形・楕円・多角形・星・線）、ペンでのパスの編集（ベクターネットワーク）、ブール演算、塗りと線、グラデーション、画像の塗り、エフェクト（影、ぼかし）、ブレンドモード、マスク、テキスト（日本語を含む）、ページ
- **フレームとオートレイアウト**：フレームの入れ子、制約（constraints）、オートレイアウト（方向、間隔、余白、揃え、hug / fill / fixed）
- **コンポーネントとバリアント**：ファイルの中のコンポーネント、インスタンスと上書き（override）、バリアントとプロパティ
- **リアルタイムのマルチプレイヤー**：同時編集、他の人のカーソルと選択、在席の表示、他の人の視点を追う
- **コメント**：キャンバスの位置に付けるコメント、スレッド、メンション、解決、通知（アプリ内とメール）
- **バージョン履歴**：自動のバージョンと名前付きのバージョン、過去のバージョンの表示と復元、複製
- **チーム・プロジェクト・権限**：組織、チーム、プロジェクト、ファイル。閲覧・編集の権限、招待、ゲスト
- **共有のリンク**：「招待した人だけ」「組織の中」「リンクを知っている全員」と、閲覧・編集の水準
- **書き出し**：PNG・JPG・SVG・PDF。倍率の指定、書き出しの設定をノードに保存する
- **ファイルの一覧と検索**：最近のファイル、プロジェクトの中の一覧、ファイル名での検索

### MVP の後に扱う

| 機能 | 理由 |
| --- | --- |
| ライブラリ（コンポーネント・スタイルの公開と、他のファイルでの利用・更新） | ファイルをまたぐ参照と更新の伝え方が大きな設計になる。ファイルの中のコンポーネントを先に固める |
| 変数（variables）とモード | ライブラリと同じ参照の仕組みの上に作る |
| プロトタイピング（画面の遷移、アニメーション、プレビュー） | 編集の核の後に作る |
| Dev Mode 相当（コードの出力、注釈、開発の状態） | 閲覧と書き出しを先に作る |
| プラグイン | サンドボックスの設計（本家は QuickJS を WASM に載せた。[An update on plugin security](https://www.figma.com/blog/an-update-on-plugin-security/)、2019-10-02、2026-09-27 に確認）と、公開の審査の運用が要る |
| ホワイトボード（FigJam 相当） | 別の製品。マルチプレイヤーと描画の基盤を共有する |
| 公開の REST API と Webhook | 内部の API とドキュメントのモデルが安定してから公開する |
| 縦書き、ルビ | 描画のテキストの層を固めてから。要否は利用者の声で決める |
| デスクトップアプリ、モバイルの閲覧アプリ | Web を先に作る |

### やらないこと（範囲の外）

| 機能 | 理由 |
| --- | --- |
| スライド（Figma Slides 相当） | 別の製品 |
| Web サイトの公開（Figma Sites 相当） | ホスティングと公開の運用が別に要る |
| AI による生成（画面の生成、画像の生成） | この題材の本質（描画とマルチプレイヤー）から外れる |
| 既存のデザインツールのファイルの読み込み（本家の形式を含む） | 形式の互換は目標にしない。SVG の読み込みだけを扱う |

### 守るべき振る舞い

- 確定を返した編集は、マルチプレイヤーのプロセスや AZ の障害があっても失わない。
- 同じファイルを開いた全員の画面は、編集が止まれば同じ状態に収束する。
- 親子の関係に循環ができない。ノードは親を 1 つだけ持つ。
- 自分の入力は、サーバーの応答を待たずに画面に出る。
- 組織は、他の組織のファイル・コメント・メタデータを見られない。権限のない人に、ファイルの中身（サムネイルを含む）を返さない。
- 過去のバージョンから復元しても、それまでのバージョンは消えない。

## Affected users and systems

- 利用者：デザイナー、開発者、PM、チームの管理者、共有のリンクで見る外部の人
- 外部のシステム：メールの送信、決済（プランの課金）、フォントの提供元（オープンなフォント、組織がアップロードするフォント）
- 社内の運用：サポート、不正利用への対応、請求

## Constraints

- 実行基盤と技術は、rebuilds の他の題材の決定を引き継ぐ。描画とマルチプレイヤーのサーバーだけを Rust にする（[ADR-0001](decisions/0001-platform-and-stack.md)）。
- 動くブラウザ：Chrome・Edge・Firefox・Safari の最新の 2 バージョン。WebGL2 を必須とし、WebGPU は使えるときに使う（[ADR-0004](decisions/0004-gpu-rendering-in-wasm.md)）。
- 日本の法令（個人情報保護法、情報流通プラットフォーム対処法）への対応は、法務の確認を前提に設計する。
- 規模は段階的に広げる（[architecture/](architecture/README.md) の「規模の段階」）。

## Success criteria

MVP のリリースの判断に使う。計測の方法は [quality.md](quality.md) と [runbooks/](runbooks/README.md) にある。

| # | 基準 | 目標 |
| --- | --- | --- |
| SC-1 | 試用のチーム | 日本のデザインチーム 20 組が、4 週間、実案件のファイルを作る |
| SC-2 | 同時編集の体感 | 試用のチームの 90% が「同時編集で待たされない」と答える。NFR-001 を満たす |
| SC-3 | 大きなファイル | 10 万ノードの参照ファイルで、NFR-003〜005 を満たす |
| SC-4 | 編集の損失 | 試用の期間に、確定を返した編集の損失が 0 件（NFR-006） |
| SC-5 | 日本語 | IME での入力・変換・確定の不具合の報告が、4 週間で重大なもの 0 件 |
| SC-6 | 書き出し | 参照ファイルの書き出し（PNG・SVG・PDF）が、参照画像との差の許容範囲に収まる |

非機能要件の一覧は [architecture/README.md](architecture/README.md) の 4 節（NFR-001〜010）にある。

## Open questions

- マルチプレイヤーの方式（OT、CRDT、中央のサーバーの順序） → 中央のサーバーの順序に決めた（[ADR-0002](decisions/0002-central-authoritative-multiplayer.md)、accepted）。
- 描画のエンジンを Rust で書くか、本家と同じ C++ で書くか → Rust に決めた（[ADR-0001](decisions/0001-platform-and-stack.md)、accepted）。
- キャンバスの上のテキストで、IME の入力をどう受けるか → 全ブラウザで隠した `textarea` に決めた（[ADR-0017](decisions/0017-text-input-via-hidden-textarea.md)）。見えなくし方とイベントの順序は E4 の前の PoC で確かめる。
- 「プロジェクト」の呼び名：本家は 2026-08-03 から「フォルダー」へ改名している（中身と権限は変わらない。[Guide to sharing and permissions](https://help.figma.com/hc/en-us/articles/1500007609322-Guide-to-sharing-and-permissions)、2026-09-27 に確認）。→ S1 は「プロジェクト」のままにし、表とコードの名前も `project` にすると決めた。利用者の調査で混乱が見えたら見直す（[permissions-and-sharing.md](architecture/permissions-and-sharing.md) の 15 節）。
- 無料のプランのバージョンの履歴 → 本家の Starter と同じく 30 日に決めた（[View a file's version history](https://help.figma.com/hc/en-us/articles/360038006754-View-a-file-s-version-history)、2026-09-27 に確認）。30 日を過ぎたバージョンは消す（[ADR-0026](decisions/0026-version-history-restore-and-deletion.md)）。ファイル数などの他の範囲は、料金の設計（MVP の後）で決める。
