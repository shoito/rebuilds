# ADR-0022: コンポーネントのプロパティとバリアントは ID で束ねる。名前での対応は、切り替えと入れ替えでの上書きの引き継ぎにだけ使う

## Context

コンポーネントのプロパティ（バリアント、真偽、テキスト、インスタンスの入れ替え）は、メインのレイヤーのプロパティ（表示、テキストの中身、入れ子のインスタンスのメイン）に束ねられる。インスタンスは、プロパティの値だけを持つ。

本家では、バリアントの名前を `Property=Value` の形で表し、組を一意にする。同じ組があれば衝突として知らせる。左上のバリアントが既定である（[Create and use variants](https://help.figma.com/hc/en-us/articles/360056440594-Create-and-use-variants)）。プロパティは 5 種類（バリアント、真偽、インスタンスの入れ替え、テキスト、スロット）で、入れ替えには優先の候補を持てる（[Explore component properties](https://help.figma.com/hc/en-us/articles/5579474826519-Explore-component-properties)）。切り替えでの上書きの引き継ぎは、レイヤーの名前の一致と、元の値の一致で決める（[Apply changes to instances](https://help.figma.com/hc/en-us/articles/360039150733-Apply-changes-to-instances)）。いずれも 2026-09-27 に確認。

満たすべきことは次のとおり。

- プロパティの名前を変えても、インスタンスの値と束縛が切れない。
- 同時編集で、1 つのプロパティの定義の変更が、他の定義の変更を消さない（[ADR-0002](0002-central-authoritative-multiplayer.md)）。
- 導出が決定的で、クライアントとサーバー（Worker）で同じ結果になる（[ADR-0021](0021-derived-instances-and-override-keys.md)）。

## Options

1. **ID で束ねる**：定義に作成時の ID を振り、束縛・インスタンスの値・バリアントの値を ID で持つ。名前は表示だけ
2. **名前で束ねる**：本家の見た目どおり、`Property=Value` の文字列をコンポーネントの名前に持ち、束縛も名前で持つ

## Decision

1 を採用する。詳細は [components-and-libraries.md](../architecture/components-and-libraries.md) の 4・5 節。

- 定義 `PropDef` は `NodeId` と同じ形 `(session_id, local_id)` の ID（`PropKey`）を持つ。定義の集まり `component_props` は document-model.md の `kind = map` で、定義ごとに競合の単位にする。
- バリアントは `variant_props: PropKey → String` を持つ。表示名はここから作る。
- 組の一意は、サーバーで強制しない。同時の編集で一時的に重なりうるため。クライアントが衝突を示す。重なったときの選択は、子の並びの先頭。
- 既定のバリアントは、子の並び（分数インデックス）の先頭にする。本家の「左上」は、レイアウトの結果に導出が依存するので採らない（本家との差異）。
- バリアントの切り替えとインスタンスの入れ替えでは、元のノードの ID が合わないので、名前の経路で上書きを引き継ぐ。規則は本家と同じ（名前が一致し、元の値が同じ。テキストは名前の一致だけ）。
- 定義を消すと、インスタンスの値は孤立として残し、定義が戻れば効く。
- 2 を採らない理由：名前の変更のたびに、全インスタンスの値と束縛を書き換える変更が要る。書き換えの途中の同時編集で、値が外れる。

## Consequences

- 良くなること：
  - 名前の変更が、定義の 1 項目の変更で済む。
  - 導出が、レイアウトの結果に依存しない。
- 引き受けるコスト：
  - 既定のバリアントが本家（左上）と違う。パネルに「既定にする」を用意する。
  - 名前の経路による引き継ぎの規則（切り替え・入れ替え）と、ID による束縛の 2 つの仕組みを持つ。
  - 組の衝突が、一時的に起こりうる。

## Confirmation

- 決定表のテスト：バリアントの選択（components-and-libraries.md の 5.2 節）、引き継ぎ（5.3 節）。
- 性質ベーステスト：任意の定義の名前の変更の列で、インスタンスの導出の結果が変わらない。
- 性質ベーステスト：任意の並行の定義の変更で、全クライアントの定義の集まりが一致する。
