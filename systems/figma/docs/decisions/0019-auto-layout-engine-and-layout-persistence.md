# ADR-0019: オートレイアウトは自前の flexbox に近い計算にし、Taffy を差分のテストの参照にする。結果は derived_layout に保存するが、画面は手元の計算で出し、食い違いは修復の担当が直す。制約は親の大きさを変えた人が当てる

## Context

フレームの中の子の位置と大きさは、制約（親の大きさを変えたときの子の動き）とオートレイアウト（hug・fill・fixed、間隔、余白、揃え、折り返し、最小・最大）で決まる（[Guide to auto layout](https://help.figma.com/hc/en-us/articles/360040451373-Guide-to-auto-layout)、2026-09-27 に確認）。

[document-model.md](../architecture/document-model.md) の 9.2 節は、レイアウトの結果を `derived_layout` に保存し、入力を変えた本人が同じ `ChangeSet` で書く既定案を置いた。同時の編集で入力と結果が食い違うときの収束の規則は、この領域に任された。[export-and-assets.md](../architecture/export-and-assets.md) の 5.2 節と 7.5 節は、Render Worker とフォントのない人が、保存された `derived_layout` で行の位置を合わせることを前提にしている。インスタンスの中身は保存されず、クライアントと Worker で導出する（[ADR-0021](0021-derived-instances-and-override-keys.md)）。

満たすべきこと：

- 同じファイルを開いた全員の画面が、編集が止まれば同じ状態に収束する（intent）。
- 自分の編集は 1 フレームで画面に出る（NFR-002）。
- 開く時間（NFR-003）。

計算の部品の事情（2026-09-27 に確認）：

- Taffy（0.14）は CSS の Block・Flexbox・Grid を実装する Rust の crate で、Servo・Bevy・Zed などが使う。10 万ノードの flexbox で、深さ 5 なら約 39 ms、深さ 1（幅の広い木）なら約 247 ms（M1 Pro。テキストの測定を含まない）（[DioxusLabs/taffy](https://github.com/DioxusLabs/taffy)）。
- 本家のオートレイアウトは flexbox に近いが、縮まない、負の間隔、線の太さを含めるなどの違いがある。本家は、自動の間隔を 0 より小さくせず（収まらなければ先頭に詰める）、内側の線を既定でレイアウトに含める（CSS の `border-box`）形に揃えた（[Use auto layout with CSS Flexbox in mind](https://help.figma.com/hc/en-us/articles/42031586813719-Use-auto-layout-with-CSS-Flexbox-in-mind)、2026-09-27 に確認）。細部の一致は [layout.md](../architecture/layout.md) の 2 節と E5 で確かめる。

## Options

計算：

1. **自前の flexbox に近い計算。Taffy は差分のテストの参照**
2. Taffy をそのまま使い、本家の意味を CSS のスタイルに写す

保存と収束：

- a. **`derived_layout` に保存する。画面は手元の計算で出す。食い違いは、決まった 1 人（修復の担当）が直す**
- b. 保存しない。全員とサーバーがいつも計算する
- c. 保存し、画面も保存された値で出す（届いた値を正とする）
- d. Document Server が計算して書く

制約：

- x. **親の大きさを利用者が変えたときに、変えた人が子の入力（`transform`・`size`）を書き換える**
- y. 制約も `derived_layout` として、いつも計算する

## Decision

1、a、x を採用する。

### 計算

- `layout` の crate に、[layout.md](../architecture/layout.md) の 7 節の手順を書く。縮みなし、負の間隔、線の太さ、`space_between` の子 1 つ、横の折り返し、最小・最大の凍結の繰り返し。
- 測定は `measure(node, available_width)` の 1 つの関数にし、`(ノード, 条件)` で 4 つまでキャッシュする。
- Taffy（バージョンを固定）を、CSS に写せる範囲の差分のテストの参照にする。

### 保存と収束

- 入力を変えた本人が、値の変わったノードの `derived_layout` を同じ `ChangeSet` に入れる（document-model の既定案のまま）。
- どのクライアントも、画面には `DocView` から手元で計算した結果を出す。保存された値は、開いた直後の最初の描画、Render Worker、測定が「仮」のテキスト（フォントがない）だけに使う。
- 他の人の変更を当てた後、手元の計算と確定した `derived_layout` をビットで比べ、違えば**修復の担当**（編集の権限を持ち、今つながっているセッションのうち `session_id` が最小のもの）が、500ms の静止の後に正しい値を書く。
- 測定が「仮」のテキストや、端末のフォントを使うテキストを含む部分木は、修復しない。
- 同じノードの修復が続けて食い違ったら、`layout_divergence` を記録して修復をやめる。
- Undo は入力だけを戻し、`derived_layout` は計算し直して入れる。
- サーバーは `derived_layout` の型と範囲だけを検証する。編集の権限を持つ人なら誰の書き込みも受ける（document-model の 4.4 節の「本人のクライアントからだけ」を改める）。

### 制約

- 利用者が親のフレームの大きさを変えたとき、その人のクライアントが、制約（左・右・左右・中央・拡大縮小）で子の `transform`・`size` を計算し、同じ `ChangeSet` で書く。再帰的に当てる。
- オートレイアウトの結果の大きさ（hug）が変わったときは、絶対配置の子に制約を当てない。

### 採らない理由

- 2 を採らない理由：
  - 本家の意味（縮まない、負の間隔、線の太さ、`space_between` の子 1 つ、fill の折り返し）を CSS に写すには、Taffy の外側に補正が要り、結局 2 つの意味を持つことになる。
  - Taffy のバージョンの更新で結果が変わると、保存した `derived_layout` と食い違う。固定するなら、保守の利点が薄い。
  - 導出したインスタンスのノード（保存しない ID）と、測定のキャッシュを、Taffy の木に写し直す費用がかかる。
- b を採らない理由：フォントのない人（端末のフォント、読み込み中）と Worker が、同じ行の位置を得られない。開いた直後に、全体の計算を待つことになる（NFR-003）。
- c を採らない理由：同時の編集で、画面に古い結果（A の余白と B の子の組み合わせを反映しない値）が出る。自分の編集の直後に届いた他の人の値で、画面が戻ることもある。
- d を採らない理由：Document Server が、フォントの読み込み、整形、インスタンスの導出を持つことになり、メモリと CPU（NFR-001 の遅延）に響く。ADR-0021 の「Document Server は導出しない」とも合わない。
- y を採らない理由：制約は「大きさを変えたとき」の動きで、同じ子の位置は利用者が直接も動かす。いつも計算すると、利用者が置いた位置をどこに持つか（基準の大きさ）が別に要る。本家も、大きさを変えたときの動きとして説明している。

## Consequences

- 良くなること：
  - 画面は、全員が同じ入力から同じ結果を出すので、同時の編集でも正しく収束して見える。
  - 保存された値で、開いた直後の描画と Worker の書き出しが速く、フォントがなくても行の位置が合う。
  - 本家の意味に合わせた振る舞いを、1 つのコードで持てる。
- 引き受けるコスト：
  - 修復の `Set` がジャーナルに増える（同時の編集の頻度に比例）。
  - 修復は計算の決定性（[ADR-0020](0020-deterministic-layout-arithmetic.md)）に依存する。破れると修復が繰り返されうる（10 秒に 1 回の上限と記録で抑える）。
  - 編集者がいないあいだの食い違いは、Worker の書き出しに残りうる。
  - 制約の同時の編集は、LWW で片方が勝つ。
  - 自前の計算を保守する。

## Confirmation

- 性質ベーステスト：任意の 2 クライアントの同時の編集の列の後、修復が終わると、保存された `derived_layout` と全員の手元の計算が一致する（PROP-LAYOUT-008）。増分と一からの計算が一致する（PROP-LAYOUT-002）。Taffy に写せる範囲で差が 1/1024 px 以内（PROP-LAYOUT-007）。
- 決定表：[layout.md](../architecture/layout.md) の 7.1 節の組み合わせと、8.1 節の制約の表。
- 本家との比較：代表の 50 の場面（E5）。
- 本番の計測：`layout_divergence` が 0 件。
