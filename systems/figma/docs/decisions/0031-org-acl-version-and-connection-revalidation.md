# ADR-0031: 実効権限は組織の acl_version をキーにキャッシュする。長く続く接続は、acl.changed と 5 分ごとの再検証で判定し直し、下げる・切る

## Context

判定は、ファイルを開くとき、一覧の各行、サムネイル、コメント、通知、Realtime の購読で呼ばれる。取り消しの後に古い権限で読めると、NFR-010 に反する。

Figma には、他の題材より長く続く接続がある。マルチプレイヤーの WebSocket は、ファイルを開いている間（数時間）続く。接続の時に判定しただけでは、権限を外した人が編集し続けられる。

rebuilds の Notion は、ワークスペースに単調に増える `acl_version` を持ち、権限の変更と同じトランザクションで上げ、キャッシュのキーに含めた（[Notion の ADR-0019](../../../notion/docs/decisions/0019-workspace-acl-version-cache.md)）。

## Options

キャッシュ：

1. **組織の `acl_version`**（Notion と同じ）
2. **資源ごとのバージョン**（ファイル・プロジェクト・チームのバージョンを組み合わせる）
3. **キャッシュしない**

長く続く接続：

- a. **`acl.changed` の出来事で判定し直し、5 分ごとの再検証で取りこぼしを拾う**
- b. **接続を短い期限（例：5 分）で切り、再接続で判定し直す**
- c. **Document Server が変更ごとに判定する**

## Decision

1 と a を採用する。詳細は [permissions-and-sharing.md](../architecture/permissions-and-sharing.md) の 9 節。

- 組織ごとに `acl_version` を持ち、権限に影響する変更（役割、一般アクセス、期限による戻し、移動、ゴミ箱、チームの参加、組織の行・シート・方針）と同じトランザクションで上げる。キャッシュのキーは、すべて `acl_version` を含む。
- ゲストや匿名の判定も、ファイルを持つ組織の `acl_version` を使う（[ADR-0005](0005-tenancy-and-document-routing.md) の「ファイルを持つ組織の文脈」）。
- 同じトランザクションで outbox に `acl.changed { org_id, acl_version, file_ids? }` を積む。Gateway は、その組織の接続を API の一括の判定に問い合わせ、編集できなくなった接続を読み取りに下げ、読めなくなった接続を切る。Realtime も同じ出来事で購読を判定し直す。
- Gateway は 5 分ごとに全接続を判定し直す。目標は、権限を外してから接続が切れるまで p99 10 秒、取りこぼしても 5 分以内。
- 2 を採らない理由：1 回の判定で 3〜4 つのバージョンを読むことになり、1 の「1 つのバージョンが同じなら入力が同じ」より正しさを示しにくい。階層が浅く、組織の中の権限の変更が少ない（大きな組織で毎分数十件の見込み）ので、組織の単位の無効化で足りる。
- 3 を採らない理由：ファイルの一覧（数百行）と通知で、判定の読み取りが増えすぎる。本家も、判定が DB の読み取りの約 20% を占めた（[How we rolled out our own permissions DSL at Figma](https://www.figma.com/blog/how-we-rolled-out-our-own-permissions-dsl-at-figma/)、2026-09-27 に確認）。
- b を採らない理由：5 分ごとに全員が再接続し、ファイルの状態を送り直す。取り消しの反映も最大 5 分かかる。
- c を採らない理由：Document Server に DB の読み取りと判定を持ち込む（[ADR-0030](0030-single-policy-engine-and-signed-capabilities.md) に反する）。変更の確定の時間（NFR-001）に判定の時間が加わる。

## Consequences

- 良くなること：
  - 取り消しが、次の要求から必ず効く。開いている接続にも 10 秒で効く。
  - 正しさの議論が「バージョンが同じなら入力が同じ」の 1 点になる。
- 引き受けるコスト：
  - 組織のどこかで権限が変わると、その組織のキャッシュがすべて無効になる。大きな組織でヒット率が落ちる。
  - `acl_version` の行が、組織の中の権限の変更を直列にする。S2 で競合を測る。
  - 組織の全接続の再検証（組織の行・方針の変更）で、API への一括の問い合わせが集中する。500 件ずつに分ける。

## Confirmation

- 性質ベーステスト：任意の権限の変更と判定の並行の列で、変更の確定の後に始まった判定は、変更後の権限で判定される。
- 結合テスト：編集中の人の役割を閲覧に下げると、10 秒以内にその人の変更が拒否される。役割を外すと、10 秒以内に接続が切れる。
- 障害注入のテスト：`acl.changed` を捨てても、5 分以内に接続が切れる。
- lint・レビュー：権限に影響する書き込みの関数が、`acl_version` を上げる共通の関数を通る。
- メトリクス：キャッシュのヒット率、取り消しから接続が切れるまでの時間。
