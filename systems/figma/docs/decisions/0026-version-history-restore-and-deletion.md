# ADR-0026: 版はチェックポイントに印を付けたもので、復元は差分を 1 つの変更として当てて履歴を消さない。削除はゴミ箱と完全な削除の 2 段で、完全な削除はジョブで S3・ジャーナル・版を消す

## Context

[intent.md](../intent.md) は、自動の版と名前付きの版、過去の版の表示と復元、複製を MVP に含め、「過去の版から復元しても、それまでの版は消えない」を守るべき振る舞いにしている。[ADR-0003](0003-journal-and-checkpoints.md) は、版をチェックポイントから選んで残し、復元は過去の中身を今のファイルへの変更として当てる方針を決め、間隔と日数をこの領域に任せた。削除の期間は法務の確認待ちである（intent の L4）。

本家は、自動の版を 30 分ごとと、接続が切れたときやアプリが落ちたときに作る。Starter と下書きは 30 日、有料のプランはすべての履歴を見られる。復元は、今の状態と復元した版の 2 つの自動の版を足し、履歴を消さない。版から新しいファイルを作れるが、コメントと履歴は写らない（[View a file's version history](https://help.figma.com/hc/en-us/articles/360038006754-View-a-file-s-version-history)）。削除したファイルはゴミ箱に残り、完全に消すと戻せない。消したチームは 28 日以内なら戻せる（[Delete and restore files](https://help.figma.com/hc/en-us/articles/360047512294-Delete-and-restore-files)）。いずれも 2026-09-27 に確認。

## Options

版：

1. **チェックポイントに印を付け、版の一覧を Aurora に持つ**
2. **版ごとにファイル全体の写しを別に保存する**
3. **ジャーナルを長く残し、任意の時点を作り直す**

復元：

- a. **今の状態から版への差分を、1 つの変更として当てる（前後に版を作る）**
- b. **今のファイルを版の中身で置き換える（`seq` を巻き戻す）**

削除：

- x. **ゴミ箱と完全な削除の 2 段。完全な削除はジョブで消す**
- y. **削除の印だけを付け、中身は残す**

## Decision

1・a・x を採用する。詳細は [file-storage-and-history.md](../architecture/file-storage-and-history.md) の 8〜11 節。

- 版の種類は `auto`・`named`・`restore_before`・`restore_after`。`auto` は、チェックポイントを書いたときに最後の `auto` から 30 分以上たって変更があれば付ける。手放すときは 5 分。
- 版の一覧は Aurora の `file_versions`（`org_id`、`FORCE ROW LEVEL SECURITY`）。中身はマニフェストを指す（[ADR-0025](0025-content-addressed-checkpoints-and-loading.md)）。
- 版の閲覧は、API が判定してチャンクの署名付き URL を出す。Document Server を通さず、ファイルの状態を変えない。
- 保持：無料のプランは 30 日（最新の 1 つを除いて消す）、有料はすべて残す。本家の Starter と同じ。
  - > 2026-09-27 の注記：仮置きとしていた無料のプランの 30 日を、推奨案で確定した。見えなくするだけでなく、掃除で消す。
- 復元：`restore_before` の版を作り、版との差分を `session_id = 0` の 1 つの `ChangeSet` としてジャーナルに書いて配り、`restore_after` の版を作る。差分が 4 MiB を超えたら、クライアントに読み込み直させる。ノードの ID は版のものを使う。
- 複製：チャンクを S3 の中で新しいファイルのキーへコピーし、`seq = 0` のマニフェストを書く。ノードの ID と `next_session_id` を引き継ぎ、セッションの表・コメント・版は写さない。
- 削除：`active → trashed → purging → purged`。ゴミ箱は自動で消さない。チームの削除は 28 日で戻せなくなる。完全な削除のジョブは、Router のファイルの割り当て（`file_leases`）を `deleted` にし（[ADR-0047](0047-router-task-liveness-and-file-assignment.md)）、ジャーナル・S3（古い版を含む）・版・コメント・索引・サムネイルを手順ごとに冪等に消す。`files` には ID・組織・日時だけを残す。
- バックアップ（DynamoDB の PITR 35 日、S3 の古い版 30 日、Aurora のバックアップ）に最大 35 日残ることを、法務の確認（L4）に回す。
- 2 を採らない理由：同じ中身を版の数だけ持つ。チャンクで共有する 1 が安い。
- 3 を採らない理由：ジャーナルを長く残すと、読み出しの時間と費用が伸びる。版の表示のたびに作り直しが要る。
- b を採らない理由：`seq` の巻き戻しは、ジャーナル・クライアントの確定した状態・セッションの表の前提を壊す。復元の後の版が消える。
- y を採らない理由：利用者が消したつもりの中身が残り続ける。法務の論点（L4）と、ストレージの費用の両方で不利。

## Consequences

- 良くなること：
  - 復元は、通常の変更の経路（検証、ジャーナル、配信）を通るので、同時編集中でも全員が同じ結果になる。
  - 版の閲覧が、Document Server の負荷にならない。
  - 完全な削除は、途中で止まっても続きから進められる。
- 引き受けるコスト：
  - 大きな差分の復元では、全員が読み込み直す。
  - 完全な削除の後も、バックアップの期間は中身が残る。
  - 無料のプランの保持の変更（見えなくするだけにする、など）は、掃除の規則の変更になる。

## Confirmation

- 性質ベーステスト（PROP-FS-003）：任意の版への復元の後、状態が版と一致し、それまでの版がすべて残る。
- 性質ベーステスト（PROP-FS-006）：複製の状態が元の版と一致する。
- 結合テスト：ゴミ箱に入れると接続中の人が切られ、新しく開けない。戻すと開ける。
- 結合テスト：完全な削除のジョブを各手順の間で止めてやり直し、最後に S3・ジャーナル・版・コメントが残らない。
