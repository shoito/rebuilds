# ADR-0027: コメントは Aurora に置き、ノードの ID と相対の位置で固定する。通知は送る時点で受け手を判定し直し、メールは受け手とファイルごとにまとめる

## Context

コメントは、キャンバスの位置か領域に固定し、最上位のフレーム・コンポーネント・グループの中なら、それを動かすと一緒に動く。閲覧以上の人は誰でも読み書きでき、削除は本人だけ、解決は誰でもできる。メンションされた人には、アプリ内の通知と、デザインのプレビュー付きのメールが届く。ファイルごとに「すべて」「メンションと返信だけ」「なし」を選べ、所有者は既定で全コメント、他の人は 2 件以上書くと通知を受ける（[Add comments to files](https://help.figma.com/hc/en-us/articles/360041068574-Add-comments-to-files)、[View and manage comments](https://help.figma.com/hc/en-us/articles/360041547593-View-and-manage-comments)、[Manage email notifications for comments on files](https://help.figma.com/hc/en-us/articles/360041547813-Manage-email-notifications-for-comments-on-files)、いずれも 2026-09-27 に確認）。

[architecture/README.md](../architecture/README.md) の 1 節は、ファイルの中身（ノードの木）とメタデータを分け、コメントをメタデータに置くとした。

rebuilds の Notion は、コメントをブロックの木に入れず、ページのトランザクションの操作として送った（Notion の comments-and-notifications.md）。Figma のファイルの中身は Document Server のメモリとジャーナルにあり、Aurora の外にある。

## Options

置き場所：

1. **Aurora のメタデータ。位置はノードの ID と相対の座標で持ち、クライアントが解決する**
2. **ファイルの中身（ノードの木）にコメントのノードとして入れ、マルチプレイヤーで配る**
3. **Aurora に置き、ノードが動くたびにサーバーがコメントの絶対座標を書き換える**

メール：

- a. **受け手とファイルごとに短くまとめ、送る直前に判定し直す。読んだものは除く**
- b. **コメントごとにすぐ送る**

## Decision

1 と a を採用する。詳細は [comments-and-notifications.md](../architecture/comments-and-notifications.md) の 3・4 節。

- コメントは `comment_threads`・`comments` などの表に置き、`org_id` と FORCE RLS を付ける。
- 固定は `anchor_node_id`（最上位のフレーム・コンポーネント・グループ）、その座標系の `offset`、作成時の絶対座標 `abs` の 3 つで持つ。表示の位置はクライアントがファイルの中身から計算する。固定先が消えたら `abs` で出す。
- 閲覧以上でログインした人が読み書きできる。匿名の閲覧者には出さない（本家は未検証）。削除は本人だけ、解決は誰でも（本家と同じ）。
- 通知の受け手は、`comment.created` の outbox から Worker が決める。アプリ内の通知の行は ID だけを持ち、表示のたびに判定して読み直す。
- メールは、メンションはすぐ、それ以外は受け手とファイルごとに 2 分まとめる。送る直前に判定し直し、アプリで読んだコメントを除く。プレビューは Worker が描いてメールに埋め込み、組織の設定で外せる。
- 2 を採らない理由：
  - コメントの書き込みが、ファイルの `seq` とジャーナル、チェックポイントの大きさを使う。閲覧だけの人の書き込みを、編集の経路に通すことになる。
  - バージョンの復元でコメントが巻き戻る。
  - ファイルを開かずにコメントを読む経路（通知、メール、ファイルブラウザ）で、ファイルの中身を読む必要がある。
- 3 を採らない理由：Document Server が、ノードの変更のたびに Aurora へ書くことになる。ファイルの中身とメタデータの境界を崩す。
- b を採らない理由：会話が続くと、メールの数が増えすぎる。送る直前の判定と、読んだものの除外ができない。

## Consequences

- 良くなること：
  - コメントを、ファイルの中身を読まずに一覧・通知・メールで扱える。
  - フレームを動かしても、サーバーの書き込みが増えない。
  - 権限を外した後に、古い判定でメールが届かない。
- 引き受けるコスト：
  - メールのプレビューと通知の画面の位置を出すために、Worker がチェックポイントから位置を計算する。
  - メンション以外のメールが最大 2 分遅れる。
  - 本家と違う振る舞い（匿名に出さない、読んだものをメールから除く）を持つ。

## Confirmation

- 決定表のテスト：comments-and-notifications.md の 3.3・4.2 節。
- 性質ベーステスト：送った時点でファイルを読めない人に、本文が出ない。同じ受け手に同じコメントのメールは 1 回まで。
- 性質ベーステスト：任意のノードの移動の列で、表示の位置 = ノードの変換 × offset。
