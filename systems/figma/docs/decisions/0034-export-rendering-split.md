# ADR-0034: 画面からの書き出しはクライアントのエンジンで描き、サムネイル・API・大きな一括の書き出しはネイティブのエンジンの Render Worker で描く

## Context

書き出し（PNG・JPG・SVG・PDF）は MVP に含む（[intent.md](../intent.md)）。書き出した画像は、画面の見た目と一致する必要がある（SC-6）。加えて、誰もファイルを開いていなくても、サムネイルと公開 API の画像を描く必要がある。

描画のエンジンは Rust で書き、ブラウザ（WASM）とネイティブの両方で動く（[ADR-0001](0001-platform-and-stack.md)、[ADR-0004](0004-gpu-rendering-in-wasm.md)）。本家も、エンジンの C++ をネイティブにビルドしてサーバーで使う（[Figma rendering: Powered by WebGPU](https://www.figma.com/blog/figma-rendering-powered-by-webgpu/)、2025-09-18、2026-09-27 に確認）。本家が画面からの書き出しをどちらで描くかは、公開の資料で確かめられなかった（**未検証**）。

条件は次のとおり。

- 端末のフォントは、その人のブラウザにしかない（[ADR-0036](0036-font-sources-and-licensing.md)）。
- タブのメモリは 1.5 GB 以内（NFR-004）。大きな一括の書き出しは、これを超えうる。
- サーバーには GPU がない（ECS Fargate）。

## Options

1. **すべてクライアントで描く**（サムネイルは、ファイルを開いた人のクライアントが描いて上げる）
2. **すべてサーバーで描く**
3. **画面からの書き出しはクライアント、サムネイル・API・大きな一括はサーバー**

## Decision

3 を採用する。詳細は [export-and-assets.md](../architecture/export-and-assets.md) の 4 節と 5 節。

- **画面からの書き出し（1 回 500 個・合計 200 メガピクセルまで）は、クライアントのエンジンで描く。** 待たずに出せて、端末のフォントを使え、サーバーの費用がかからない。クライアントが持つ状態（未確定の自分の変更を含む）を描く。
- **サムネイル・公開 API の画像・大きな一括の書き出しは、Render Worker で描く。** Render Worker は、エンジンの crate をネイティブでビルドした Rust のサービスで、ECS Fargate の CPU の上で、wgpu のソフトウェアの描画で描く。
- **Render Worker は、チェックポイントとジャーナルを読むだけで、Document Server に問い合わせない。** 描く版（`seq`）をジョブに入れる。レイアウトは保存された `derived_layout` を使う。
- **1 ジョブを 1 つの子プロセスで描く。** メモリと時間の上限を子プロセスに付け、組織をまたいでメモリに中身を残さない。
- **権限の判定はジョブを作る API で行い、Render Worker は判定しない**（[ADR-0005](0005-tenancy-and-document-routing.md) の「Worker はジョブを作るときに判定する」）。
- 1 を採らない理由：サムネイルが、誰かがファイルを開くまで古いままになる。利用者のクライアントが描いた画像を他の人に配ると、改ざんした画像を上げられる。API の画像を描けない。
- 2 を採らない理由：端末のフォントを使えない（代わりのフォントになる）。画面からの書き出しのたびにサーバーの往復と待ちが入る。Render Worker の量が、画面の操作に比例して増える。

## Consequences

- 良くなること：
  - 画面からの書き出しが速く、端末のフォントの見た目のまま出せる。
  - サムネイルと API の画像が、ファイルを開いていなくても最新になる。
  - Render Worker の障害が、画面からの書き出しを止めない。
- 引き受けるコスト：
  - 同じ書き出しを 2 か所で描くので、GPU（WebGL2・WebGPU）とソフトウェアの描画の差を、参照画像のテストで抑え続ける必要がある。
  - ソフトウェアの描画の性能は **未検証**。足りなければ GPU のインスタンスを別の ADR で検討する。
  - サーバーの書き出しは、端末のフォントを代わりのフォントで描く。結果に `substituted_fonts` を付けて知らせる。

## Confirmation

- 参照画像のテスト：参照ファイルの集合を、WebGL2・WebGPU・Render Worker で描き、参照画像との差が許容に収まる（SC-6）。CI で毎回走らせる。
- 障害注入のテスト：Render Worker の子プロセスを途中で殺すと、ジョブが 1 回だけ再試行され、該当のノードが `null` になる。
- 結合テスト：Render Worker のタスクから、インターネットと Document Server に届かない。
- 計測：`render-export` の待ち時間 p95、子プロセスの最大のメモリ。
