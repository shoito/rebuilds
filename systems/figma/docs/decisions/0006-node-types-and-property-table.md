# ADR-0006: ノードの種類とプロパティを 1 つの表で定義し、競合の単位・検証・持ち主の領域を表に書く

## Context

[ADR-0002](0002-central-authoritative-multiplayer.md) で、変更の単位を `(node_id, property)` の値の置き換えにし、同じ単位の競合は LWW で解くと決めた。この方式では、プロパティの切り方がそのまま競合の振る舞いになる。1 つのプロパティに別々に編集されうる値を詰めると、同時の編集で片方が黙って消える。

プロパティは、描画・レイアウト・コンポーネント・書き出しの各領域が足していく。定義が散らばると、次のことが起きる。

- クライアント（WASM）とサーバー（ネイティブ）で、検証の規則や既定値が食い違う。
- 直列化のコードを手で書き、プロパティの追加のたびに書き漏らす。
- 競合の単位が、レビューで見えないまま決まる。

本家は、文書を `Map<ObjectID, Map<Property, Value>>` として持ち、変更はプロパティの値の境界で原子的である（[How Figma's multiplayer technology works](https://www.figma.com/blog/how-figmas-multiplayer-technology-works/)、2019-10-16、2026-09-27 に確認）。プロパティの定義の管理の仕方は公開されていない（**未検証**）。

## Options

1. **1 つの表（宣言的なスキーマ）から、型・直列化・検証のコードを生成する**
2. **Rust の型（構造体と列挙）を正とし、手で書く**
3. **プロパティを自由な文字列の鍵と JSON の値にする（スキーマなし）**

## Decision

1 を採用する。詳細は [document-model.md](../architecture/document-model.md) の 3・4 節。

- 表（開発リポジトリの `schema/properties.toml`）に、プロパティごとに `id`（`u16`、再利用しない）、`name`、`type`、`kind`（`scalar` か `map`）、持てるノードの種類、既定値、検証、`derived`、持ち主の領域、追加したバージョンを書く。
- ノードの種類と、親子の組み合わせの表も同じ場所に置く。
- 表から、Rust の型、TypeScript の型、符号化・復号（[ADR-0008](0008-canonical-binary-serialization.md)）、検証のコードを生成する。生成したコードを手で直さない。
- **競合の単位**：`scalar` は値全体、`map` は要素の鍵ごと。別々に編集されうる値は、別のプロパティか `map` にする。インスタンスの上書き（`overrides`）は `map` にする。
- **テキスト**：文字と書式の範囲を `text_content` の 1 つの単位にする（ADR-0002 の「テキストは LWW」）。分けると、文字の添字と範囲がずれる。
- **ノードの種類は変えられない**：種類の変更は、作り直しの変更の集まりで表す。
- 2 を採らない理由：TypeScript の型と直列化を手で写すことになる。競合の単位が表の 1 列として見えず、レビューしにくい。
- 3 を採らない理由：検証が弱く、型の誤りがサーバーで見つからない。JSON は大きく遅い（10 万ノードのチェックポイント）。

## Consequences

- 良くなること：
  - 競合の単位・検証・既定値を、1 か所でレビューできる。
  - クライアントとサーバーの規則が食い違わない（ADR-0001）。
  - 他の領域は、表に行を足すだけでプロパティを足せる。
- 引き受けるコスト：
  - コード生成の仕組みを持つ。生成の結果を CI で検査する（表と生成物がずれていたら失敗）。
  - 塗りの配列や `transform` のように、1 つの単位にまとめた値は、同時の編集で片方が消える。まれとみなし、バージョンの履歴と Undo で戻す。

## Confirmation

- CI：表から生成し直した結果が、コミットされた生成物と一致する。
- lint：表の `id` の重複・再利用、`kind` の未指定、持ち主の領域の未指定を拒否する。
- レビューの観点：プロパティを足す PR で、「別々に編集されうる値を 1 つの `scalar` に入れていないか」を確かめる。
- 性質ベーステスト：任意の変更の列で、別のプロパティ・別の `map` の要素への同時の変更が、両方とも残る。
