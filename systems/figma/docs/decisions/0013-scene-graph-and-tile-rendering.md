# ADR-0013: 描画用のシーングラフを別に持ち、256 px のタイルに描いてキャッシュする。パスは CPU で線分にし、GPU で面積の被覆率を求めてアンチエイリアスする

## Context

[ADR-0004](0004-gpu-rendering-in-wasm.md) で、描画は WASM の中の自前のエンジンにし、シーングラフとタイルとカリングを自前で持つと決めた。この ADR は、その形と、ベクターのパスをどう画素にするか（アンチエイリアスを含む）を決める。

満たすべきこと：

- 10 万ノードのファイルで、パン・ズームのフレーム時間 p95 16.7ms（NFR-005）。自分の入力を 1 フレームで画面に出す（NFR-002）。
- WebGL2 だけの端末でも同じ見た目（compute shader、storage buffer がない。wgpu の `Limits::downlevel_webgl2_defaults()`、2026-09-27 に確認）。
- 細い線、ほぼ水平な辺、小さな文字がきれいに出る。書き出しと画面が一致する。

本家は WebGL の上の自前のタイルの描画エンジンで、すべてを GPU で描き、アンチエイリアスする（[Building a professional design tool on the web](https://www.figma.com/blog/building-a-professional-design-tool-on-the-web/)、2015-12-07、2026-09-27 に確認）。パスのラスタライズの方式は公開されていない（未検証）。

パスの描き方の候補の事情（2026-09-27 に確認）：

- Pathfinder 3 は、WebGL2 で動く「D3D9」の段で、CPU でタイルに振り分け、GPU のラスタライズで画素ごとの厳密な台形の面積を求める（実質 256xAA）（[servo/pathfinder](https://github.com/servo/pathfinder)）。開発は止まっている。
- Vello GPU（旧 `vello_hybrid`、0.2.0、2026-08-07）は、CPU で前処理し GPU で描く Sparse Strips の方式で、WebGL2 に対応した。ただし、マスクの層、複雑なフィルター、非分離のブレンドの一部は未対応で panic する。WebGL2 には wgpu を通らない独自の経路を使う（[vello_gpu の README](https://github.com/linebender/vello/tree/main/vello_gpu)）。
- lyon（1.0.19）は、パスを三角形に分割する。アンチエイリアスは MSAA などを別に要る（[nical/lyon](https://github.com/nical/lyon)）。

## Options

シーングラフ：

1. **`doc-model` とは別に、描画用の木（アリーナ）を持つ**
2. `doc-model` のノードに、描画の派生値（世界座標、ジオメトリ）を持たせる

描画の単位：

- a. **画面を固定の大きさのタイルに分け、描いたタイルを GPU のテクスチャにキャッシュする**
- b. 毎フレーム、見えるノードをすべて描き直す（即時の描画）

パスのラスタライズ：

- i. **CPU で平坦化と振り分け、GPU で面積の被覆率（Pathfinder の D3D9 の系統）**
- ii. lyon の三角形の分割と MSAA（4x）
- iii. ステンシルで塗る範囲を決めてから覆う（stencil-then-cover）と MSAA
- iv. Vello GPU に任せる

## Decision

1、a、i を採用する。

- **シーングラフ**：`RenderNode` のアリーナを持つ。欄は `world_transform`（f64）、`world_bounds`（エフェクトを含む）、`subtree_bounds`、`draw_ops`、`dirty` のビットなど（[rendering-engine.md](../architecture/rendering-engine.md) の 4 節）。変更は dirty のビットで伝え、影響する部分木と祖先の境界だけを計算し直す。子が 64 を超える親は子の R-tree を持つ。
- **タイル**：256×256 の画面の画素、RGBA8。鍵は `(page_id, zoom_key, tx, ty)`。キャッシュは GPU で 256 MB（メモリの少ない端末は 128 MB）。ズームの途中は近い倍率のタイルを拡大・縮小して見せ、止まって 120ms で描き直す。描き終わらないタイルは古いタイルで埋め、空白を見せない。
- **パス**：
  1. 3 次ベジェを、画面の上の誤差 0.2 px 以内の線分にする（倍率の段ごとにキャッシュ）。
  2. 線は kurbo の線の展開で輪郭にする。
  3. 線分を 16×16 px の区画に振り分け、完全に内側の区画は塗りつぶしにする。
  4. GPU で、線分が画素に与える符号付きの面積を R16F に加算で足す。
  5. 塗りの規則（非ゼロ・偶奇）を当てて、塗りを掛ける。
- R16F の加算のブレンドを使えない WebGL2 の端末では、RGBA8 の 4 チャンネルに固定小数点で分けて足す。
- グリフのアトラス（[ADR-0015](0015-text-shaping-and-glyph-rendering.md)）も、同じ面積の計算を CPU で行う。画面と書き出しで、同じ式で被覆率を出す。
- エフェクト・ブレンドモード・マスクは、オフスクリーンの層に描いて合成する。層の入れ子は 1 タイルあたり 8 段まで。
- 2 を採らない理由：`doc-model` はサーバー（Document Server）と共有し、描画の派生値を持つと、サーバーのメモリと直列化の費用が増える。描画の都合で `doc-model` を変えることにもなる。
- b を採らない理由：10 万ノードの画面で、エフェクトとテキストを毎フレーム描き直すと、NFR-005 を守れない。本家もタイルにしている。
- ii を採らない理由：4x MSAA の被覆率は 5 段しかなく、細い線とほぼ水平な辺が荒れる。書き出し（高い倍率）と画面の見た目の差も大きくなる。
- iii を採らない理由：アンチエイリアスは MSAA に頼るので ii と同じ。ステンシルの切り替えで描画の呼び出しが増える。
- iv を採らない理由：マスクの層と非分離のブレンドで panic する。WebGL2 で wgpu を通らない経路になり、GPU の抽象（ADR-0004）とバックエンドの切り替え（[ADR-0014](0014-gpu-backend-selection-and-fallback.md)）の外に出る。タイルのキャッシュとカリングは、どのみち自前で要る。ただし、比較の対象（参照の実装）には使い、成熟したら置き換えを検討する。

## Consequences

- 良くなること：
  - 小さな変更は、影響するタイルだけを描き直す。パン・ズームは、キャッシュしたタイルを並べるだけの時間になる。
  - アンチエイリアスが画素ごとの厳密な面積になり、WebGL2・WebGPU・ネイティブで同じ式になる。
- 引き受けるコスト：
  - ズームの途中は、キャッシュの拡大・縮小で一時的にぼやける。
  - 平坦化と振り分けが CPU の仕事になり、点の多いパスで重い。ジオメトリのキャッシュ（200 MB の予算）で抑える。
  - 背景のぼかしは、タイルの縁を足して描く費用がかかる。
  - 被覆率の計算を自前で持ち、保守する。

## Confirmation

- 参照画像のテスト：ネイティブ（lavapipe）、Chromium の WebGPU と WebGL2 で、参照の場面を描き、判定の値（[rendering-engine.md](../architecture/rendering-engine.md) の 16.1 節）に収まる。
- 性質ベーステスト：任意のパスで、被覆率が 0〜1 に収まり NaN がない。CPU と GPU の被覆率の差が 1/255 以内。増分で更新したシーングラフと、一から作ったものが一致する。無効にしたタイルが、見た目の変わったタイルを必ず含む。
- 差分のテスト：同じ場面を Vello CPU で描き、差を記録する。
- 性能：10 万ノードの参照ファイルのパン・ズームで、フレーム時間 p95 16.7ms（NFR-005）。
