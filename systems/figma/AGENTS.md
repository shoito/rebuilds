# AGENTS.md — Figma

Figma の再構築の設計。リポジトリ共通のルールはルートの [AGENTS.md](../../AGENTS.md) にある。このリポジトリには設計だけを置き、実装は Figma の開発リポジトリで行う（[リポジトリ共通の ADR-0005](../../docs/decisions/0005-design-record-repository.md)）。

## 最初に読むもの

- [docs/intent.md](docs/intent.md) — 何を、なぜ作るか
- [docs/architecture/](docs/architecture/README.md) — 全体像、規模の段階、非機能要件、領域ごとの設計
- [docs/decisions/](docs/decisions/README.md) — ADR。特に 0002（マルチプレイヤーの方式）、0003（ジャーナルとチェックポイント）、0004（描画）

## この題材に固有の規則（開発リポジトリで守る）

- ドキュメントのモデル（ノード、プロパティ、変更の適用と検証）は、共有の Rust の crate（`crates/doc-model`）にだけ書く。クライアント（WASM）とマルチプレイヤーのサーバーは、同じコードで変更を当てる。片方にだけ規則を書かない（ADR-0001、ADR-0002）。
- プロパティを足すときは、プロパティの表に登録し、競合の単位（LWW で上書きする単位）を明記する。1 つのプロパティに、別々に編集されうる値を詰め込まない（ADR-0002）。
- 子の並びは分数インデックスの鍵だけで決める。親の付け替えで循環ができる変更は、サーバーで拒否する（ADR-0002）。
- マルチプレイヤーのサーバーは、変更をジャーナルに永続化してから、送り手に確定を返し、他の人へ配る。永続化の前に確定を返す近道を作らない（ADR-0003）。
- ジャーナルへの書き込みは、ファイルの `seq` を条件にした書き込みにする。条件の失敗は「別のプロセスがこのファイルを持っている」とみなし、そのプロセスはファイルを手放す（ADR-0003、ADR-0005）。
- 描画のコードは、GPU の抽象（`gpu` のインターフェース）だけを呼ぶ。WebGL2 や WebGPU の API を直接呼ばない。描画の変更には、参照画像との比較のテストを付ける（ADR-0004）。
- メタデータのテナントテーブルには `org_id` と `FORCE ROW LEVEL SECURITY` を付ける（ADR-0005）。
- ファイルの中身（ノードの名前、テキスト、画像）を、ログ・トレース・メトリクスのラベルに書かない。書いてよいのは ID と大きさだけにする。
- 本家の名前を、ドメイン・ヘッダー・ファイルの拡張子・API の名前空間・トークンの接頭辞に使わない。`<brand>` で書き、実際の名前は開発リポジトリの作成時に決める（[リポジトリ共通の ADR-0006](../../docs/decisions/0006-brand-neutral-identifiers.md)）。

## このリポジトリでの規則

- ADR を追加・更新したら、`docs/decisions/README.md` の一覧を生成し直す。
- 本家の振る舞いや数値を書くときは、出典と確認した日付を付ける。確かめられなかったものは「未検証」と書く。
