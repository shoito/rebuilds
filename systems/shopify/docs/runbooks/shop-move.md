# Runbook: ショップの移し替え

- Owner: Ops
- 対応するアラート: 移し替えの失敗、停止の時間の超過、照合の不一致、スロットの遅れ、KeyValueStore の更新の失敗。定期作業（偏りの直し、隔離のポッドへの移し替えと戻し）
- 最終確認日: 2026-10-10

仕組みは [shops-and-pods.md](../architecture/shops-and-pods.md) の 7・8 節、[ADR-0011](../decisions/0011-shop-placement-and-rebalancing.md)、[ADR-0012](../decisions/0012-shop-mover-logical-decoding-and-cutover.md)。目標は NFR-015：書き込みの停止 p99 10 秒、データの不一致 0。

## 症状

- 定期作業：週次の `placement-planner` の候補（使用率 85% 超のポッド）か、セールの 3 日前の隔離のポッドへの移し替え、セールの後 7 日の戻し。
- `shop_moves.phase` が `failed`、停止の待ち（3 秒）の超過が 1 時間に 3 回、スロットの遅れが 20 GB、照合の不一致。

## 影響

- 正常：そのショップの書き込みが 4〜9 秒（p99 10 秒）止まり、チェックアウトと Admin API は 503 と `Retry-After: 5` を返す。ストアフロントのキャッシュのあるページは影響を受けない。
- 失敗：切り替えないので、データは元のポッドのまま。元のポッドの DB にスロットの WAL の留めの負荷がかかる。

## 確認

1. 始める前：元と先のポッドのスキーマのバージョンが同じ（`pod_schema_versions`）、先のポッドの使用率と段、元のポッドで同時の移し替えが 2 未満、全体で 4 未満、そのショップに進行中のセールがない、平日の 10〜16 時。
2. 進行中：`shop_moves` の段、追いかけの遅れ、スロットの遅れ、コピーの速さ（目安 1 時間 50 GB。**初期見積もり**）、元のポッドの DB の負荷。
3. 停止の後：停止の時間、変わった行の照合と在庫の不変条件の結果、KeyValueStore の更新と中継の窓（`shop_relocations`）。

## 対処

### 実行（承認は Ops。エージェントに任せない）

1. `shop-mover` に移し替えを依頼する（ショップ、先のポッド、承認者）。
2. コピーと全量の照合が終わり、遅れ 1 秒未満が 30 秒続くと自動で停止へ進む。一括の操作の書き込みは、停止の 60 秒前から新しく始めない。
3. 切り替えの後、元のポッドが 15 分の中継の窓を持つ。`canary` か手で、そのショップの購入と表示を確かめる。

### 失敗のとき

| 段 | 振る舞いと手で行うこと |
| --- | --- |
| コピー・追いかけの途中 | `shop-mover` がスロットと公開を消し、先の行を削除の作業で消す。元は変わらない。原因（DB の負荷、長いトランザクション）を見て、別の時間にやり直す |
| 停止の待ちの超過 | 印を書かずに追いかけに戻る（自動）。1 時間に 3 回で止まる。そのショップの長いトランザクション（一括の操作、ジョブ）を探す |
| 停止の中の照合の不一致 | 切り替えない。印を消して元の書き込みを開ける（自動）。不一致の表と行の主キーを `shop_moves` で見て Dev に渡す。再開は原因の後 |
| スロットの遅れ 20 GB | 移し替えを止めてスロットを消す（自動）。元のポッドの DB を守る |
| 元のポッドの DB のフェイルオーバー | スロットを失いうる（Aurora の扱いは**未検証**）。移し替えを最初からやり直す |
| `shop-mover` の停止 | `shop_moves.phase` と、先の `shop_move_progress` の LSN から再開する（冪等） |
| KeyValueStore の更新の失敗 | `shop-directory` が再試行する。10 分を超えたら呼び出し。中継の窓を延ばす（最大 24 時間） |
| 切り替えの後 7 日以内の問題 | 逆向きの移し替え（先 → 元）を新しい移し替えとして最初から行う。元の行は古いので使わない |

## エスカレーション

- 照合の不一致：Dev のテックリード（移し替えの正しさの問題）。そのショップのデータの調べを、事業者の許可なしにしない（[security.md](../architecture/security.md) の 8 節）。
- セールの 24 時間前に隔離のポッドへ移せない：Ops の責任者と事業者で、共有のポッドのまま行うか延期するかを決める。

## 事後

- 停止の時間、コピーの速さ、失敗の段を記録し、`shop-move-poc` の値と PU の容量を直す。
- 原因を `changes/` に起票し、この手順と [shops-and-pods.md](../architecture/shops-and-pods.md) の 8.6 節を直す。
