# ADR-0048: ストアフロントのスクリプトは、テーマの資産（本システムの CDN）、アプリの埋め込み（`app-registry` に登録した配信元）、事業者が許可した配信元だけにし、CSP の `script-src` を配信元の一覧とインラインのハッシュで組む。外部送信の公表のページは、スクリプトの一覧から自動で作る枠を用意し、文言と同意の取り方は法務の確認の後に決める

## Context

- ストアフロントでは、テーマのスクリプト、アプリのピクセル・部品、事業者の計測のタグが動く。任意の配信元のスクリプトは、買い手のページで何でもできる。
- キャッシュするページは応答ごとに同じなので、応答ごとに変わる `nonce` を使えない。
- 電気通信事業法の外部送信規律で、買い手の端末から外部へ情報を送るスクリプトについての通知・公表の義務を負う者と形は法務の確認待ち（L6）。
- チェックアウトのページは別の厳しい CSP を持つ（[ADR-0006](0006-payments-via-providers.md)、`cart-and-checkout.md`）。

## Options

1. **配信元の一覧（資産、登録したアプリ、事業者の許可）とインラインのハッシュで CSP を強制する。外部送信の一覧を登録から作る**
2. CSP を持たない（テーマとアプリの自由）
3. `nonce` の CSP を使い、ページをキャッシュしない

## Decision

1 を採用する。詳細は [storefront-themes.md](../architecture/storefront-themes.md) の 9 節。

- `script-src 'self' <資産の CDN> <有効なアプリの埋め込みの配信元> <事業者の許可の一覧（20 まで）> <インラインのハッシュ>`。
- インラインのスクリプトのハッシュは、テーマのバージョンの翻訳の時に集める。`{{ }}` を含むインラインは `json` の出力だけ。
- アプリの埋め込みは、送信先と目的の宣言を `app-registry` に持つ。
- 違反の報告を数える（中身は保存しない）。
- 外部送信の公表のページの枠を用意する。同意の仕組みは種類（必須・計測・広告）ごとに読み込みを止められる形にする。文言・同意の要否は L6 の後。

### 他の案を選ばなかった理由

- **2（なし）**：事業者の知らないスクリプトが買い手のデータを送れる。外部送信の一覧も作れない。
- **3（`nonce`）**：ストアフロントのキャッシュ（NFR-003）を捨てることになる。

## Consequences

- 良くなること：ストアフロントで動くスクリプトの出どころが一覧になり、外部送信の公表の材料になる。
- 引き受けるコスト：事業者が新しいタグを使うには許可の一覧に足す手間がある。CSP のヘッダーの長さ（CloudFront の応答のヘッダーの方針の上限は 1,783 文字。[CloudFront quotas](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html)、2026-10-10 に確認）を超えないよう、CSP は元の応答で付け、許可の一覧の数を絞る。

## Confirmation

- 結合テスト：許可の外の配信元のスクリプトが CSP で止まる。テーマのバージョンのハッシュの一覧が、インラインのスクリプトと一致する。
- E2E：既定のテーマで CSP の違反 0。
