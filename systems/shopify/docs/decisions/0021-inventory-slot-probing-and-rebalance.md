# ADR-0021: 引き当ては `hash(checkout_id) mod N` の枠から始め、失敗したら残りの多い枠を 1 回の読み出しで 3 つ選んで試す。1 つの枠で足りなければ寄せ集める。枠の直しは、空の枠が出たときに 2 つの枠の間で半分を移す操作だけで行い、セールの後に 1 つの枠へまとめる

## Context

- [ADR-0004](0004-inventory-reservation-model.md) は、枠が 0 行なら次の枠を試す（最大で全枠）と決めた。終盤は全枠を順に試すことになり、枠 32 で最大 32 回の更新の往復になる。引き当て 1 回 p99 50ms（NFR-001）を守りにくい。
- 戻しは、引き当てた枠に数を戻す。セールの途中で、枠ごとの残りが偏る。
- 枠の数の変更と枠の間の移し替えは、合計を変えない操作だけで行う（ADR-0004、[AGENTS.md](../../AGENTS.md)）。

## Options

1. **最初の枠はハッシュで選ぶ。失敗したら、残りの多い枠を読んで 3 つまで試す。偏りは背景の処理で直す**
2. 全枠を順に試す（ADR-0004 の草案のまま）
3. 空でない枠の一覧を Valkey に持ち、そこから選ぶ

## Decision

1 を採用する。詳細は [inventory-and-reservations.md](../architecture/inventory-and-reservations.md) の 6 節。

- **最初の試し**：`s0 = hash(checkout_id) mod N` の枠に、`UPDATE ... WHERE slot_no = s0 AND available >= n`。
- **次の試し**：0 行なら、`SELECT slot_no FROM inventory_slots WHERE ... AND available >= n ORDER BY available DESC, slot_no LIMIT 3` を読み、その順に試す。読み出しはロックを取らない。3 つとも 0 行なら、和を読み、和が `n` 以上なら 1 回だけ読み出しからやり直す。和が `n` 未満なら在庫切れを返す。
- **寄せ集め**：1 行の数（`n`）は 1 つの枠からだけ取る。和は足りるが 1 つの枠では足りないときは、同じトランザクションで、残りのある枠を枠の番号の順にロックし、最も多い枠へ残りを寄せてから取る（終盤の数個に限る）。ロックが取れなければ（`lock_timeout`）`409 inventory_busy` を返し、買い手の再試行に任せる。
- **直し（rebalance）**：枠の `available` が 0 になったとき、`inventory-rebalancer` に依頼を出す（Valkey のキュー。失っても次の依頼で直る）。直しは、最も多い枠 `a` から 0 の枠 `b` へ `floor(a.available / 2)` を、1 つのトランザクションの 2 つの更新で移す。
- **まとめ（merge）**：セールの後（[flash-sales-and-queueing.md](../architecture/flash-sales-and-queueing.md) の 9 節）、枠 1〜N−1 の 3 つの数を枠 0 へ足し、枠 1〜N−1 を消す。引き当ての行の `slot_no` は、確定・戻しで使う前に枠がなければ枠 0 と読み替える。
- **枠の数の変更**：増やすときは、新しい枠を 0 で作り、直しで配る。減らすときは、まとめと同じ操作を行う。

### 他の案を選ばなかった理由

- **2**：終盤の往復が枠の数に比例する。
- **3**：Valkey の一覧は目安で、古い一覧で空の枠を試す往復が残る。正本にはできない（ADR-0004）。

## Consequences

- 良くなること：
  - 引き当ての往復が、多くても 1 回の更新＋1 回の読み出し＋3 回の更新で終わる。
- 引き受けるコスト：
  - 終盤に「和はあるが 1 つの枠では足りない」ことが起き、寄せ集めで複数の枠をロックする。
  - 直しの処理とまとめの処理を持つ。

## Confirmation

- 性質ベーステスト：任意の直し・まとめ・枠の数の変更を引き当てと並行に流し、和と不変条件が変わらない（PROP-INV-004）。
- `inventory-hot-row-poc`：枠 1・8・32・64 で、引き当ての往復の回数の分布と p99 を測る。
