# ADR-0041: 送料は、ショップの送料の表（都道府県を地域に分け、地域 × 重さかサイズの帯の税込みの額）で決める。重さは行の合計、サイズは最大の品目の帯で選び、最大の帯を超えたら箱の数を掛ける。無料の閾値は割引の後の商品の小計で判定する。離島などの追加の料金は、郵便番号の一覧で足す

## Context

- 日本の送料は、都道府県（地帯）と荷物の大きさ（サイズ・重さ）で決まり、離島などで追加の料金がある。
- 送料は 10% の課税の対価で、税は税率ごとの集計に入る（taxes-and-invoices の領域）。
- 送料の無料の閾値と、割引の順序の関係（[ADR-0032](0032-discount-classes-order-and-combination.md)）を決める。
- 送料の計算は、チェックアウトの段の p99 500ms に入る（NFR-001）。

## Options

1. **ショップの表（地域 × 帯）。箱の数は単純な規則**
2. 運送会社の運賃の API を毎回呼ぶ
3. 箱詰めの最適化（3 次元）で箱の数を決める

## Decision

1 を採用する。詳細は [orders-and-fulfillment.md](../architecture/orders-and-fulfillment.md) の 6 節。

- 表：`shipping_profiles`（品目の集まり）× `shipping_zones`（都道府県の集まり）× `shipping_rates`（方法、帯の種類 `weight`・`size`、帯の上限、税込みの額）。
- 帯の選び方：重さの帯は行の重さの合計、サイズの帯は品目の `size_class` の最大で選ぶ。最大の帯を超えたら、`箱の数 = ceil(合計 / 最大の帯の上限)` で最大の帯の額を掛ける。
- 品目の集まりが複数あるカートは、集まりごとに送料を計算して足す（集まりは別の箱）。
- 無料の閾値：割引の後の商品の小計（税込み）で判定する（[ADR-0032](0032-discount-classes-order-and-combination.md) の送料の割引と同じ時点）。
- 追加の料金：`shipping_surcharges`（郵便番号の前方一致の一覧、額）。一覧の中身は事業者が入れる。本システムは一覧の形と取り込みを持つ。
- 送料の関数（配送のカスタマイズ。[ADR-0008](0008-extension-sandbox-wasm.md)）は、表で出した方法を隠す・名前を変える・並べ替えるだけで、額は変えない。

### 他の案を選ばなかった理由

- **2**：運送会社の API の遅れと障害がチェックアウトを止める。事業者の契約の運賃は API の公開の運賃と違う。
- **3**：品目の寸法の入力の手間が大きく、結果を事業者が予測できない。

## Consequences

- 良くなること：送料の計算が DB の表だけで、速く決定的。
- 引き受けるコスト：実際の箱の数と違う送料になりうる。事業者は帯を調整する。

## Confirmation

- 表駆動テスト：帯の境目（上限ちょうど、1 g 超え）、閾値の境目、追加の料金の前方一致。
- 性質ベーステスト：送料は行の重さの増加で減らない（PROP-ORD-003）。
