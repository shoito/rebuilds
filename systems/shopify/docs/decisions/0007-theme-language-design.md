# ADR-0007: テーマの言語を自前で設計する（`{{ }}`・`{% %}` の形、副作用なし、既定で HTML をエスケープ、歩数・出力・ループ・入れ子・データの読み出しの上限）。中間表現に翻訳し、インタープリターで動かす。Liquid の実装は使わない

## Context

ストアフロントの見た目は、事業者・テーマの開発者が書くテンプレートで決まる。テンプレートは本システムのサーバーで動くので、次を守る。

- **任意のコードを動かさない**：他人の書いたテンプレートが、DB・ネットワーク・ファイル・他のショップに触れない。
- **止まる**：無限のループ、巨大な出力、深い入れ子、データの読み出しの嵐で、レンダラーと DB を食いつぶさない（NFR-012）。
- **安全な HTML**：商品の名前やレビューの文字列が、そのまま HTML として出て XSS にならない。
- **速い**：キャッシュに外れたページの TTFB p95 500ms の中で描画する（NFR-003）。
- **非プログラマーが書ける**：事業者が編集する。

本家の Liquid は「評価せず、安全である」ことを目標にした言語で、MIT で公開されている（[Liquid](https://github.com/Shopify/liquid)、2026-10-10 に確認）。テーマの言語は題材の核なので、本家の実装もその移植も使わない（[リポジトリ共通の ADR-0007](../../../../docs/decisions/0007-no-reuse-of-original-implementation.md)）。文法をどこまで似せてよいかは法務の確認待ち（L9）。

## Options

1. **自前の言語（`{{ }}`・`{% %}` の形）。副作用なし、上限を意味に含め、既定でエスケープ。中間表現（IR）に翻訳してインタープリターで動かす**
2. 汎用の言語（JavaScript）を砂場で動かす（関数の砂場と同じ WebAssembly、または V8 の isolate）
3. 既存の汎用のテンプレートのエンジン（Nunjucks、Handlebars など）を使う
4. テンプレートを JavaScript のソースに翻訳して実行する

## Decision

1 を採用する。仮の名前は **Loom**、拡張子は `.loom`。

### 言語の形

- **出力**：`{{ product.title }}`、`{{ product.price | money }}`。値は既定で HTML のエスケープをして出す。
- **タグ**：`{% if %}`・`{% elsif %}`・`{% else %}`、`{% unless %}`、`{% case %}`、`{% for x in xs limit: n %}`（`forloop` の値つき）、`{% assign %}`、`{% capture %}`、`{% render 'snippet', key: value %}`（呼び出し先は自分の変数だけを見る。呼び出し元の変数を見せない）、`{% section 'name' %}`、`{% paginate %}`、`{% form %}`（決めた種類のフォームだけ）、`{# コメント #}`。
- **持たないもの**：変数の範囲を共有する取り込み、利用者の定義する関数・マクロ、再帰（`render` の入れ子の深さで止める）、`while`、任意の属性の呼び出し、`eval` にあたるもの、時計（`now` は要求の開始の時刻に固定）、乱数。
- **型**：null、真偽、整数（53 ビット）、十進の数（文字列で持ち、四則は決めた桁で丸める）、文字列、配列、マップ、**お金**（整数の最小単位＋通貨。浮動小数点にしない）、**drop**（許可したオブジェクト）。
- **drop**：`shop`・`product`・`variant`・`collection`・`cart`・`customer`（ログインした買い手）・`page`・`blog`・`article`・`settings`・`section`・`block`・`request`・`localization`。各 drop の公開の属性は、スキーマ（`packages/loom/schema`）に列挙したものだけで、型と読み出しの費用を持つ。drop はショップの RLS の中でだけ値を引く。
- **フィルター**：文字列（`upcase`、`truncate`、`escape`、`url_encode`）、配列（`map`、`where`、`sort`、`first`）、お金（`money`、`money_with_currency`）、画像（`image_url: width:`）、日付（`date: format`、タイムゾーンはショップ）、`json`（`<script>` に安全な形で出す。`</` をエスケープ）、`raw`（エスケープを外す。テーマのチェックで警告）。フィルターの一覧は言語のバージョンで固定する。
- 文法の細部は storefront-themes の領域で、文法の定義（EBNF）と試験のベクトルとして確定する。`{{ }}`・`{% %}` の形は、Jinja・Django にもある公開の形として使う（法務の L9 で似せる範囲を確かめる）。

### 上限

上限は言語の意味の一部で、超えたら決めたエラーになる。値は運用のパラメーターで、既定は次のとおり（`theme-renderer-poc` で見直す）。

| 対象 | 既定 | 超えたとき |
| --- | --- | --- |
| 歩数（IR の命令の数） | 1 ページ 100 万、1 セクション 20 万 | そのセクションを空にする |
| 出力 | 1 ページ 2 MB | 描画を止め、エラーのページ |
| ループの回数 | 1 つの `for` で 1,000 要素、1 ページの合計 5 万 | 1,000 で切る（`paginate` を勧める） |
| `render` の入れ子 | 深さ 10 | そのセクションを空にする |
| 文字列の長さ | 1 MB | 切る |
| データの読み出し（drop の費用） | 1 ページ 200（コレクションの 1 ページの読み出しは 1） | そのセクションを空にする |
| テンプレートのファイル | 1 ファイル 256 KB、テーマ全体 50 MB | 保存の時に拒む |

- **セクションごとの隔離**：ページはセクションの並びで、各セクションを自分の歩数の予算で描く。1 つのセクションの失敗は、そのセクションを空にしてページを返す（本番）。テーマの編集の画面では、エラーの位置を見せる。
- 描画の時間の上限（壁の時計 1 秒）も置くが、これは本システムの異常の検出のためで、テンプレートの上限は歩数で決める（同じ入力なら同じ所で止まる）。

### 実行

- テーマの保存で、テンプレートを字句解析・構文解析し、型と drop の属性を検査し、IR（命令の列と定数の表）に翻訳して保存する。IR の形は `loom_ir_version` で固定する。
- **データの先読み**：翻訳の時に、テンプレートが読む drop の属性の道（例：`product.variants.price`）を静的に集め、要求ごとに 1 回のまとめた読み出しの計画にする。描画の途中の DB の往復を減らす。
- インタープリター（TypeScript）は IR を実行し、命令ごとに歩数を数える。テンプレートを JavaScript のソースに翻訳しない。`eval`・`new Function`・`vm` を使わない。
- 言語のバージョン（`loom_version`）をテーマの定義に書き、フィルターとタグの意味をバージョンで固定する。新しい振る舞いは新しいバージョンで足し、古いバージョンを残す。

### 他の案を選ばなかった理由

- **2（JavaScript）**：非プログラマーに難しい。描画の上限を燃料で付けても、データの読み出しの形を静的に知れず、先読みができない。
- **3（汎用のエンジン）**：Nunjucks・Handlebars は、任意の JavaScript のオブジェクトの属性・関数の呼び出しを許す設計で、砂場として作られていない。歩数の上限を持たない。テーマの言語は題材の核で、自前で設計する。
- **4（JS への翻訳）**：速いが、翻訳器の誤り 1 つが任意のコードの実行になる。上限の数え方も生成したコードに頼る。

## Consequences

- 良くなること：
  - テンプレートは、許可した値の読み出しと決めたフィルターしかできず、上限で必ず止まる。
  - 既定のエスケープで、XSS の多くを書き手の注意に頼らずに防げる。
  - データの先読みで、描画の DB の往復が読める。
- 引き受けるコスト：
  - 言語・IR・インタープリター・テーマのチェックの道具（エディターの補完、エラーの表示）を自前で持つ。
  - インタープリターは JS への翻訳より遅い。セクションの結果のキャッシュとエッジのキャッシュで補う。速さは `theme-renderer-poc` で確かめる。
  - 本家のテーマはそのまま動かない（目標にしない）。

## Confirmation

- ファジング：任意の文字列のテンプレートと任意の drop の値で、構文解析・翻訳・実行が上限の中で終わり、例外でプロセスが落ちない（[quality.md](../quality.md) の 2.2.1 節 E）。
- 性質ベーステスト：任意のテンプレートの値の出力が、`raw` を通らない限り、HTML の要素・属性を作らない（エスケープの性質）。同じテンプレート・同じ値で、同じ出力と同じ歩数になる。
- 試験のベクトル：文法の定義に沿ったテンプレートと期待する出力の集まり。言語のバージョンごとに固定し、以後のバージョンで変わらない。
- lint：`packages/loom` と `storefront-renderer` で `eval`・`new Function`・`vm` を禁止する。
