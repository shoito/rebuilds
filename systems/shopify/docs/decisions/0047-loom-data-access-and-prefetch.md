# ADR-0047: drop の属性はスキーマに列挙し、属性ごとに読み出しの費用と「キャッシュしてよいか」を持つ。翻訳の時に読む道を集めて、要求ごとのまとめた読み出しの計画にする。計画の外の動的な読み出しも費用を数える（1 ページ 200）。キャッシュするページのテンプレートは、`customer`・`cart` と個人のメタフィールドを読めない（翻訳のエラー）

## Context

[ADR-0007](0007-theme-language-design.md) は、drop の属性をスキーマに列挙し、データの読み出しの上限（1 ページ 200）と、翻訳の時の先読みを決めた。決めることは次である。

- 費用の数え方（何を 1 と数えるか）。
- 静的に決まらない読み出し（変数の添え字）の扱い。
- キャッシュするページに個人の値が入る事故を、どこで止めるか（[architecture/README.md](../architecture/README.md) の 6 節の「キャッシュの漏れ」）。

## Options

1. **スキーマに費用とキャッシュの可否。静的な計画＋費用を数える遅延の読み出し。キャッシュするページの個人の drop は翻訳のエラー**
2. 遅延の読み出しだけ（drop の属性に触れた時に読む）
3. 個人の値の漏れは、エッジのキャッシュの設定（Cookie のある要求をキャッシュしない）で防ぐ

## Decision

1 を採用する。詳細は [storefront-themes.md](../architecture/storefront-themes.md) の 5 節。

- 属性は型、費用、キャッシュの可否を持つ。ページの主（商品・コレクション）は 0、1 回のまとめた読み出しは 1、名前での参照（`all_products['x']`）は 1 で 1 ページ 20 回まで。
- 翻訳の時に読む道を集め、テーマの設定の値を埋めてから、表ごとの `WHERE id = ANY($1)` の段（3〜5 回の往復）にする。決まらない道は遅延の読み出しで費用を数える。
- ページの種類にキャッシュの可否を持ち、キャッシュする種類のテンプレート（と呼び出し先）が `customer`・`cart`・非公開のメタフィールドを読めば翻訳のエラー。カートと買い手の値は島で出す（[ADR-0051](0051-dynamic-islands-and-uncached-personal-data.md)）。
- drop の属性の引きは地図の表で行い、JavaScript のオブジェクトの属性を参照しない。

### 他の案を選ばなかった理由

- **2（遅延だけ）**：商品の一覧の中の読み出しが N 回の往復になり、TTFB を守れない。
- **3（エッジだけ）**：ログインした買い手の Cookie のない要求でも、元が個人の値を描く誤りを止められない。設定の誤り 1 つで漏れる。

## Consequences

- 良くなること：描画の DB の往復が読め、個人の値のキャッシュへの混入を翻訳で止められる。
- 引き受けるコスト：drop のスキーマに費用とキャッシュの可否を書き続ける。テーマの開発者は、個人の値を島で書く必要がある。

## Confirmation

- 性質ベーステスト PROP-LOOM-005（キャッシュの可否）、PROP-LOOM-006（プロトタイプの名前）。
- 結合テスト：既定のテーマの各ページの往復の数と費用（費用 10 以下）。
- lint：drop のスキーマの全属性に費用とキャッシュの可否がある。
