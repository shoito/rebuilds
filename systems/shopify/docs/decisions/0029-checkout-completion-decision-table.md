# ADR-0029: 完了の決定表 DT-CHK-001 を 11 行で確定する。引き当ての取り直しは別の枠と別の拠点を試す。割引の使用の回数と 1 人あたりの上限は、決済が済んだ後は取り直せなくても注文を作り、超過の印を付ける。`payment_pending` のまま 60 分を超え、提供者に支払いがなければ、照合の処理が `expired` にする

## Context

- [ADR-0005](0005-checkout-state-machine-and-exactly-once-orders.md) は、完了の決定表の草案（11 行）を置き、確定を cart-and-checkout の領域の spec に任せた。
- 草案は、引き当ての「取り直し」の範囲、割引の使用の回数と 1 人あたりの上限の扱い、`payment_pending` から `expired` への遷移の条件を決めていない。
- 決済が済んだ後に、割引の回数の上限を理由に返金すると、買い手は表示どおりの額を払ったのに注文がない。これは売り越しと違い、事業者の損が小さい。

## Options

1. **11 行を確定し、取り直しの範囲と、割引・上限の超過の扱いを足す**
2. 割引・上限の取り直しの失敗も、在庫と同じく返金にする
3. 決定表を手段ごとに分ける

## Decision

1 を採用する。表は [cart-and-checkout.md](../architecture/cart-and-checkout.md) の 7 節。

- 行の並びと条件は ADR-0005 の草案のままにする。上から順に評価し、最初に一致した行を使う。
- 「取り直せた」は、同じ品目を、元の枠 → 他の枠（[ADR-0021](0021-inventory-slot-probing-and-rebalance.md)）→ 他の拠点（[ADR-0022](0022-location-selection-and-lock-order.md)）の順に試して、全行が取れたこととする。一部の行だけ取れたときは取り直せないとする（注文を分けない）。
- 割引の使用の回数（[ADR-0034](0034-discount-usage-counters.md)）と 1 人あたりの上限（[ADR-0026](0026-bot-defense-and-purchase-limits.md)）は、行 7・8・10 で引き当てが戻されていたら取り直しを試し、取れなくても注文を作る。超過の印（`over_limit_reasons`）を注文に付け、事業者に示す。
- `expired` への遷移：照合の処理が、`payment_pending` のまま送信から 60 分を超えたチェックアウトを照会し、提供者の結果が「支払いなし・セッションの期限切れ」なら、セッションを取り消し、引き当てを戻して `expired` にする。この遷移は決定表の外の、照合の処理の規則である。
- 照会の結果が「不明・処理中」の間は行 3 で待つ。照会の予定は [ADR-0036](0036-payment-webhook-inbox-and-inquiry-schedule.md)。

### 他の案を選ばなかった理由

- **2**：払った買い手に「割引の回数が尽きた」と返金するのは、買い手と事業者の両方に悪い。超過は数件で、事業者が判断できる。
- **3**：手段ごとに表が分かれると、行の漏れが見えにくい。手段の差は提供者の結果の正規化（[ADR-0035](0035-payment-attempt-states-and-result-normalization.md)）で吸収する。

## Consequences

- 良くなること：決定表が 1 つで、全手段に効く。払った買い手が割引の上限で返金されない。
- 引き受けるコスト：割引の回数と 1 人あたりの上限は「決済が済んだ数件の超過」を許す。売り越しは許さない。

- 性質ベーステスト：PROP-CHK-001〜004。全行に到達することを生成器で確かめる（[quality.md](../quality.md) の 2.2.1 節 B）。
