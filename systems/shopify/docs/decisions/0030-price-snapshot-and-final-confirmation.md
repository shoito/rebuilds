# ADR-0030: 価格の写しは、行・単位ごとの按分・税率ごとの集計・合計を正規の JSON にし、SHA-256 のハッシュを持つ。最終確認画面はこの写しだけから描き、送信の要求は画面に出した写しのハッシュを持つ。ハッシュが今の写しと違えば送信を拒み、画面を出し直す。画面の項目は、法務の確認待ち（L1）の項目を差し込める枠で持つ

## Context

- [ADR-0005](0005-checkout-state-machine-and-exactly-once-orders.md) は、送信で価格の写しを固定し、最終確認画面・注文・決済の金額を写しから取ると決めた。
- 最終確認画面を出した後、送信の前に、価格・在庫・割引の期限が変わりうる。買い手が見た金額と、写しの金額がずれてはいけない（NFR-013）。
- 最終確認画面に出す事項（特定商取引法の第 12 条の 6）は、法務の確認待ち（L1）である。
- 返品・返金は、単位ごとの支払いの額から計算する（[returns-and-refunds.md](../architecture/returns-and-refunds.md)）。

## Options

1. **写しを確認の段で作り、ハッシュで画面と送信を結ぶ**
2. 送信の時点で計算し直し、画面と違えばそのまま請求する
3. 画面の金額を送信の要求の本文で受け取り、比べる

## Decision

1 を採用する。詳細は [cart-and-checkout.md](../architecture/cart-and-checkout.md) の 6 節。

- 確認の段（`review`）に入るたびに、写しを計算して `checkout_price_snapshots` に入れる（追記）。写しは正規の JSON（キーの順を固定、整数の金額、通貨）で、`snapshot_hash = SHA-256(正規の JSON)`。
- 写しの中身：行（品目、数、単価、行の割引、税の区分）、単位ごとの按分（商品の割引、注文の割引、支払いの額。[ADR-0033](0033-discount-allocation-and-rounding.md)）、送料と送料の割引、手数料、税率ごとの対価の合計と税額、合計、通貨、写しの作成の時刻、適用した割引の ID とバージョン。
- 最終確認画面は写しだけから描き、`snapshot_hash` を送信の要求に入れる。送信は、チェックアウトの今の写しのハッシュと一致するときだけ受ける。違えば `409 snapshot_changed` と新しい写しを返す。
- 送信の時点で、写しの価格・割引が今も有効かを確かめる（価格のバージョン、割引の期限と状態）。変わっていれば新しい写しを作り、409 を返す。在庫は引き当てで確かめる。
- 画面の項目は、`final_confirmation_fields`（分量、価格、支払いの時期と方法、引き渡しの時期、申込みの期間、申込みの撤回と解除）の枠を持ち、ショップの設定と写しから埋める。出す事項・文言・配置は法務の確認待ち（L1）で、確認の後に spec で確定する。関数・アプリはこの枠の中身を変えられない。

### 他の案を選ばなかった理由

- **2**：買い手の見ていない金額を請求する。
- **3**：本文の金額は改ざんできる。比べる値として信じられない。

## Consequences

- 良くなること：画面・注文・決済の金額が 1 つの写しから出る。
- 引き受けるコスト：価格の変更の直後は、送信が 409 で 1 回戻る。

## Confirmation

- 性質ベーステスト：任意の価格の変更・割引の期限切れの時点で、注文の金額が、送信に使ったハッシュの写しの合計と一致する（PROP-CHK-003）。
- E2E：最終確認画面の金額と、注文・決済の金額の一致。
