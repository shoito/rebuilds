# ADR-0046: テーマは、レイアウト・テンプレート（JSON のセクションの並び）・セクション（`.loom` と `.schema.json`）・スニペット・資産・言語のファイル・設定で作る。テーマの保存は全ファイルを検査・翻訳した不変の「テーマのバージョン」にし、公開はショップの公開中のテーマのバージョンの ID を 1 つの更新で入れ替える。1 テンプレート 25 セクション、1 セクション 50 ブロック

## Context

- 事業者は、コードを書かずにページの部品を並べ替え、設定を変えたい（[intent.md](../intent.md) の「テーマの編集（セクションとブロック）」）。
- [ADR-0007](0007-theme-language-design.md) は、セクションごとに歩数の予算を持ち、失敗したセクションを空にすることを決めた。
- 編集の途中のテーマや、翻訳に失敗したファイルが、公開中のストアフロントに出てはならない。
- テーマの公開は、エッジのキャッシュの世代を上げる（[ADR-0050](0050-edge-cache-keys-and-generations.md)）。

## Options

1. **ファイルの集まりを、検査・翻訳を通した不変のバージョンにし、公開は ID の入れ替え**
2. ファイルごとに保存し、公開中のテーマのファイルを直接書き換える
3. テンプレートを DB の行（ページの部品の木）で持ち、ファイルを持たない

## Decision

1 を採用する。詳細は [storefront-themes.md](../architecture/storefront-themes.md) の 7 節。

- テンプレートは JSON（セクションの並び、設定、ブロックの並び）。セクションは `.loom` と、設定とブロックの定義の `.schema.json`。テンプレートの中にスキーマを埋めない。
- 保存は全ファイルを検査・翻訳し、通れば不変の `theme_versions` を作る。通らなければ保存しない。
- ショップは `published_theme_version_id` を 1 つ持つ。公開・戻しは、この列の 1 つの更新と `themes/publish` の事象。
- 上限：1 テンプレート 25 セクション、1 セクション 50 ブロック、1 ショップ 20 テーマ、1 テーマ 100 バージョン、テーマ全体 50 MB。
- 資産は内容のハッシュの URL で `immutable` に配る。

### 他の案を選ばなかった理由

- **2（直接の書き換え）**：複数のファイルの変更の途中の状態が出る。壊れたファイルが公開される。戻しができない。
- **3（DB の木）**：テーマの開発者の道具（ファイルの編集、バージョンの管理の道具）が使えない。

## Consequences

- 良くなること：公開と戻しが 1 つの更新で、途中の状態がない。キャッシュの鍵にテーマのバージョンを入れられる。
- 引き受けるコスト：小さな設定の変更でも新しいバージョンができ、翻訳の時間（数百 ms）がかかる。ファイルの内容のハッシュで、変わらないファイルの翻訳を使い回す。

## Confirmation

- 結合テスト：不正なテーマの保存が拒まれる。公開の後の最初の要求から新しいバージョンで描かれる。戻しで前のバージョンになる。
- 性質ベーステスト PROP-LOOM-004（セクションの隔離）。
