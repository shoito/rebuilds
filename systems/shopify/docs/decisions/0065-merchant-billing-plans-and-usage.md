# ADR-0065: 本システムから事業者への請求は全体の面の `billing` が持つ。プランの月額、アプリの課金、従量の利用量を、ポッドが出した利用量の事象（経路 P3）から月次に締め、決済の提供者に預けた支払いの手段で請求する。未払いは 1・3・7 日に再試行し、14 日でショップを `frozen` にする

## Context

- 事業者はプランの料金を払う。アプリの課金の代金は、本システムの事業者への月次の請求に載せて受け取る（[ADR-0057](0057-app-billing.md)）。
- アプリの課金の行（購読）はポッドの DB（ショップのデータ）にあり、全体の請求の集計は、各ポッドが SNS に出したものを全体で集める（[ADR-0002](0002-pods-and-shop-placement.md) の P3）。
- プランはショップごとの上限（Admin API のバケット、スタッフの数、ショップごとの上限の値）を決める（[ADR-0009](0009-admin-api-graphql-and-cost-limits.md)、[shops-and-pods.md](../architecture/shops-and-pods.md) の 11 節）。
- 本システムはカード番号に触れない（[ADR-0006](0006-payments-via-providers.md)）。
- 本システム自身のインボイスの形は法務の確認待ち（L4）。代金の受け渡しの位置づけは法務の確認待ち（L5）。

## Options

1. **全体の `billing` が購読・利用量・請求を持ち、P3 の事象で集め、月次に締める**
2. 各ポッドがショップの請求を作る
3. 外部の請求の SaaS に任せる

## Decision

1 を採用する。詳細は [merchant-admin-and-staff.md](../architecture/merchant-admin-and-staff.md) の 8 節。

- プラン（ベーシック・アドバンス・プラス）と上限は `plan_limits`（全体）を正本にし、P5 でポッドへ写す（[ADR-0010](0010-shop-routing-hot-set-and-custom-domains.md)）。
- ポッドの `workers` が日次に、アプリの課金と従量の利用量を、（ショップ、日、種類、冪等キー）の事象で SNS に出す。`billing` は冪等キーで重複を除いて `billing_usage` に入れる。
- 毎月 1 日 03:00 に締め、`merchant_invoices` と行を作る。行は不変で、直しは訂正の行を足す。プランの変更は日割り（上げは即時、下げは次の締め）。
- 請求は、提供者に預けた支払いの手段（提供者の参照の ID だけを持つ）に冪等キー `<invoice_id>:charge:<attempt>` で行う。失敗は 1・3・7 日に再試行し、未払い 14 日で [ADR-0013](0013-shop-lifecycle-and-data-deletion.md) の `frozen` にする。提供者の障害による失敗は日数に数えない。
- 開発者の取り分と支払いは [ADR-0057](0057-app-billing.md) のとおり（支払いの実行は法務の L5 まで手で）。本システムのインボイスの記載と税の扱いは法務の確認待ち（L4）。

### 他の案を選ばなかった理由

- **2（ポッドごと）**：事業者の組織は複数のショップ（複数のポッド）を持ちうる。請求の番号と支払いの手段は全体で 1 つにしたい。移し替えで請求の行が動く。
- **3（外部の SaaS）**：プランの上限と凍結のステートマシンと強く結び、利用量の事象の冪等の扱いを自分で持つ必要は変わらない。インボイスの形の法務の結論に合わせにくい。MVP の後に、締めた請求の書き出しとしての連携は検討する。

## Consequences

- 良くなること：
  - 請求の額が、冪等な利用量の事象の和として検証できる。
  - 未払いからの凍結が、ライフサイクルの 1 つの遷移で閉じる。
- 引き受けるコスト：
  - 請求の締め・再試行・訂正の仕組みを自前で持つ。
  - 締めの後に届いた事象の翌月への繰り越しを、事業者に説明する画面が要る。

## Confirmation

- 性質ベーステスト：PROP-BILL-001（重複・遅れ・順の入れ替えの事象で、請求の額が重複を除いた和と一致）。
- 結合テスト：提供者の模型で、再試行の 1・3・7 日と 14 日の凍結、提供者の障害の除外。
- 本番：月次の締めの後、利用量の事象の数・額と請求の行の照合（差 0）。
