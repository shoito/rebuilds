# ADR-0008: アプリの関数は WebAssembly のモジュールにし、`checkout` の隣の Rust のプロセスの Wasmtime で、燃料・メモリー・入出力の上限を付けて動かす。WASI の機能を渡さない。失敗は種類ごとの「効果なし」

## Context

事業者は、アプリで割引・送料・決済の手段の見せ方・カートの検証の規則を足したい。この規則はチェックアウトの価格の計算の中で、買い手の要求ごとに動く。

- アプリの開発者のコードは信用できない。悪意か不具合で、無限のループ、メモリーの食いつぶし、他のショップのデータの読み出し、外への送信を試みうる。
- チェックアウトの 1 段の p99 500ms（NFR-001）の中で、複数の関数を動かす。1 回の実行は数 ms で終わる必要がある（NFR-012）。
- 上限で止める位置が、同じ入力で揺れると、事業者とアプリの開発者が再現できない。
- アプリのサーバーへ同期で問い合わせる形（外部の HTTP）は、相手の遅れと障害がチェックアウトを止める。
- 本家の Functions は WebAssembly で、命令 1,100 万、線形メモリー 10,000 kB、モジュール 256 kB、入力 128 kB、出力 20 kB の上限を持つ（[Shopify Functions](https://shopify.dev/docs/api/functions)、2026-10-10 に確認）。本家の失敗のときの振る舞いは確かめられなかった（**未検証**）。
- rebuilds の Salesforce の題材は、利用者のコードを Wasmtime の燃料で動かす形を選んだ（[Salesforce の ADR-0048](../../../salesforce/docs/decisions/0048-user-code-engine-quickjs-ng-on-wasmtime-fuel.md)）。そこで調べた Wasmtime の燃料と決定性の性質を引き継ぐ。

## Options

形：

1. **WebAssembly のモジュール（アプリの開発者が好きな言語から作る）を、本システムの中の砂場で動かす**
2. アプリのサーバーへの同期の HTTP の呼び出し
3. 宣言の規則（JSON の条件と効果）だけを許す

実行系と場所：

- a. **Rust のプロセスの Wasmtime。`checkout` のタスクの隣のコンテナで、UNIX ドメインソケットでつなぐ**
- b. Node.js の中の V8 の WebAssembly
- c. 別の ECS のサービス

## Decision

1 と a を採用する。Wasmtime は本家と関係のない第三者の汎用の部品で、核の外の実行系として使う（[ADR-0001](0001-platform-and-stack.md)）。関数の入出力の設計、上限、失敗の扱い、モジュールの検査は自前の核である。

### 関数の種類（MVP）

| 種類 | 入力 | 出力 | 失敗のとき |
| --- | --- | --- | --- |
| 割引（商品・注文・送料） | カートの行、買い手の区分、関数の設定 | 割引の提案（対象の行、額か率、メッセージ） | その関数の割引なし |
| 配送のカスタマイズ | 配送先、配送の方法の一覧 | 隠す・名前を変える・並べ替える | 変更なし |
| 決済の手段のカスタマイズ | カート、決済の手段の一覧 | 隠す・並べ替える | 変更なし |
| カートの検証 | カート、買い手の区分 | 拒む理由（メッセージ） | 既定は通す。事業者が「必須」にした関数は、決めた文言で送信を止める |

- 入力は、関数ごとの入力のクエリ（チェックアウトのスキーマへの GraphQL の部分集合。3,000 バイト・費用 30 まで）で決めた値だけを JSON で渡す。買い手の氏名・住所の詳細・メールアドレスは、アプリのスコープ（[ADR-0009](0009-admin-api-graphql-and-cost-limits.md)、法務の L3）が許すときだけ入れる。
- 出力は種類ごとの JSON スキーマで検証し、外れたら失敗として扱う。割引の額は、行の価格以下・0 以上に切る（discounts-engine の領域）。
- カートの変換（行の組み替え）と拠点の振り分けの関数は MVP の後。

### 砂場

- **モジュール**：WebAssembly のコアのモジュール（`wasm32`）。輸出は `run` の 1 つ。輸入は自前の殻の 3 つの関数（入力を読む、出力を書く、ログを書く）だけ。WASI の実装（時計、乱数、ファイル、ソケット、環境変数、引数）を渡さない。標準入出力を使う言語の道具のために、`fd_read(0)`・`fd_write(1, 2)` だけを殻の関数へつなぎ、他の WASI の関数の輸入はリンクの時に拒む。
  > 2026-10-10 の注記：言語の実行時が終わりに呼ぶ `proc_exit`（0 は正常の終わり、他はトラップ）も許した（[ADR-0058](0058-function-io-contract.md)）。
- **上限**（既定。`wasm-function-poc` で見直す）：燃料 1,000 万、線形メモリー 10 MB（実体化の時に最大で確保し、伸長の成否を揺らさない）、スタック 512 KB、テーブル 4・1 万要素、モジュール 256 KB、入力 128 KB、出力 20 KB、ログ 1 KB。カートの行が 200 を超えたら、燃料・入力・出力を比例して広げる。
- **決定性**：`consume_fuel` を有効、NaN の正規化を有効、relaxed SIMD・threads を無効。同じモジュール・同じ入力なら、同じ出力・同じ燃料で止まる。epoch の中断は、本システムの異常（Wasmtime のホストの詰まり）の検出のための 50ms の安全網としてだけ使い、それで止まったら本システムの障害として数える。
- **事前の翻訳と署名**：アプリの公開の時に、`app-registry` がモジュールを検査し（輸入の一覧、大きさ、検証）、Cranelift で機械語（`.cwasm`）にし、KMS で署名して S3 に置く。`function-runner` は署名と Wasmtime のバージョンを確かめてから読み込む。開発者から受け取った機械語を直接読み込まない（`Module::deserialize` は信用した入力にだけ使う）。
- **プロセス**：`function-runner` は `checkout` のタスクの別のコンテナで、root でない利用者で動く。環境変数に秘密を持たない。IAM の権限はモジュールの読み出し（S3 の読み取り）だけ。Wasmtime のプーリングのアロケーターで、呼び出しごとに新しい実体を作り、使い回さない。
- **呼び出し**：`checkout` は 1 段の関数を、決めた順（関数の種類、導入の時刻、関数の ID）で呼ぶ。1 段の関数の合計に 50ms の予算を置き、超えたら残りの関数を「失敗」として扱う。
- **ログ**：関数のログ（1 KB）と燃料の使用量、失敗の理由を、アプリの開発者の画面に出す。入力の写しは、事業者の同意の設定があるときだけ、個人のデータを除いて残す（法務の L3）。

### 他の案を選ばなかった理由

- **2（同期の HTTP）**：アプリのサーバーの遅れと障害がチェックアウトを止める。フラッシュセールで 1 秒数百の呼び出しがアプリのサーバーに行く。
- **3（宣言の規則だけ）**：まとめ買いの組み合わせ、会員の区分ごとの規則など、事業者の求める表現に足りない。本システムの割引のエンジンの組み込みの種類は宣言の規則として別に持つ（discounts-engine の領域）。
- **b（V8）**：燃料の仕組みがなく、止める位置が決定的でない。
- **c（別のサービス）**：1 段で複数回の網の往復が p99 を押し上げる。

## Consequences

- 良くなること：
  - アプリのロジックがチェックアウトの中で数 ms で動き、外部の障害に依らない。
  - 上限の判定が燃料で決定的で、開発者が再現できる。
  - 砂場の出口が入出力の 3 つの関数だけになる。
- 引き受けるコスト：
  - Rust の `function-runner`、モジュールの検査、事前の翻訳と署名、Wasmtime の更新の流れ（セキュリティの修正を 7 日以内に入れる）を持つ。
  - 開発者は WebAssembly を作る道具が要る。Rust のひな形と、本システムの入力の型の生成を用意する（functions-sandbox の領域）。
  - Wasmtime のバージョンを上げると、機械語を作り直す。全モジュールの再翻訳の流れを持つ。

## Confirmation

- 脱出の試験：時計・乱数・ファイル・ソケット・環境変数・WASI の他の関数を輸入するモジュールが、公開の時に拒まれる。上限ちょうどで通り、超えたら止まる。線形メモリーの外への読み書き、テーブルの外の呼び出し、スタックの溢れが、ホストを落とさずに失敗になる（[quality.md](../quality.md) の 2.2.1 節 F）。
- 性質ベーステスト：任意のモジュール（生成した命令の列）と入力で、2 回の実行の出力と燃料が同じ。
- 結合テスト：関数の失敗・上限の超過・不正な出力で、チェックアウトが続き、表の「失敗のとき」の結果になる。
- IaC の検査：`function-runner` のコンテナに、S3 の読み取りの外の IAM の権限と秘密がない。
- PoC（E15 の前）：`wasm-function-poc` で、実体化と実行の時間、燃料 1,000 万の実際の時間、1 タスクの同時の数を測る。
