# ADR-0023: 在庫の数を変える操作は、すべて `inventory_movements` に追記の行（理由のコード、数の差分、参照）を同じトランザクションで書く。毎時の照合は、数の行と移動の行の和と注文の行を突き合わせる。引き当て・戻しは移動の行に書かず、引き当ての行を記録とする

## Context

- 事業者は「なぜ数が変わったか」を見たい（調整、入荷、移動、注文、キャンセル、返品）。
- ADR-0004 は毎時の照合を決めた。照合には、数の行とは独立した記録が要る。
- 引き当てと戻しは 1 ショップ 100 件/秒で起きる。すべてを移動の行にすると、書き込みが倍になる。

## Options

1. **数を変える操作（引き当て・戻しを除く）を追記の移動の行に書く。引き当て・戻しは引き当ての行を記録とする**
2. すべての操作を移動の行に書く
3. 移動の記録を持たず、監査ログだけにする

## Decision

1 を採用する。詳細は [inventory-and-reservations.md](../architecture/inventory-and-reservations.md) の 9・10 節。

- `inventory_movements` は追記だけ。列は、拠点・品目・理由のコード・`on_hand`・`available`・`committed`・`unavailable` の差分・参照（注文、配送、返品、調整の ID）・主体・時刻。
- 確定（`reserved` → `committed`）は移動の行に書く（理由 `order_committed`）。引き当てと戻しは書かない。
- 照合（毎時、ポッドごと）：
  - R1：品目ごとに、不変条件の式。
  - R2：`Σslot.committed` と、未配送・未キャンセルの注文の行の数の和。
  - R3：`on_hand` と、ある時点の写し（日次）＋その後の移動の行の差分の和。
  - R4：`Σslot.reserved` と、`state = 'reserved'` の引き当ての行の数の和。
- 不一致は `inventory-mismatch` の呼び出し（[runbooks/](../runbooks/README.md)）。直しは調整の操作（理由 `reconciliation_fix`）だけで行う。

### 他の案を選ばなかった理由

- **2**：熱い品目の書き込みが倍になる。
- **3**：照合ができない。

## Consequences

- 良くなること：事業者に理由つきの履歴を見せられる。照合が独立した記録で行える。
- 引き受けるコスト：移動の行は月ごとに分割し、13 か月で消す（記録の保持は法務の L3 の後に見直す）。

## Confirmation

- 性質ベーステスト：任意の操作の列の後、R1〜R4 が成り立つ（PROP-INV-005）。
- 本番：照合の不一致 0 を SLI にする。
