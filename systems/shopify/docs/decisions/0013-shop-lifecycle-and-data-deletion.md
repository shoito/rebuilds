# ADR-0013: ショップのライフサイクルを `trial`・`active`・`frozen`・`closed`・`deleting`・`deleted` の状態の機械にし、`shop-directory` が正本を持つ。閉店から 90 日はデータを残して再開でき、その後に削除の作業を段ごとに進める。法令で残す文書は `retained_until` まで削除から外す

## Context

- 事業者は、試用で始め、プランを選んで売り、未払いや規約の違反で止められ、閉店する。閉店の後に戻る事業者もいる。
- ショップのデータは、ポッドの DB、Valkey、OpenSearch、S3、全体の面、大阪の写し、アプリの側に散らばる。どれかに残ると、削除の約束を守れない。
- 領収書・注文の記録など、法令で保存が要るものがある（法務の確認待ち L4）。削除の請求の扱いと保持の期間は法務の確認待ち（L3）。
- [ADR-0002](0002-pods-and-shop-placement.md) の `shop-directory` の状態（`active`・`moving`・`frozen`）は、振り分けとライフサイクルが混ざっている。

## Options

1. **ライフサイクルを独立の状態の機械にし、振り分けの値（KeyValueStore の `state`）はそこから作る。閉店の後の猶予の後に、段ごとの冪等な削除の作業**
2. 閉店で即時に消す
3. 消さずに、ショップを無効にするだけ

## Decision

1 を採用する。詳細は [shops-and-pods.md](../architecture/shops-and-pods.md) の 9・10 節。

- 状態：`trial`（14 日。ストアフロントはパスワードの保護、決済は試験の環境）→ `active`（プランと支払いの手段）。`active` → `frozen`（未払い 14 日・規約の違反・法令の要請）→ `active`（解除）。`active`・`frozen`・`trial` → `closed`。`closed` → `active`（90 日以内の再開）。`closed` → `deleting`（90 日の後）→ `deleted`。
- 遷移は `shop-directory` の 1 つの関数だけが書き、`shop_lifecycle_events` に理由と主体を残し、ポッドへ outbox で知らせる。移し替えの停止（`moving`）はライフサイクルに入れず、ポッドの DB の `shop_freeze` で表す（[ADR-0012](0012-shop-mover-logical-decoding-and-cutover.md)）。
- `frozen`・`closed` の間も、`payment_pending` のチェックアウトの `completeCheckout` と、事業者のデータの書き出し（Admin API の読み出し）は通す。支払い待ちの注文が残る間は `deleting` に進めない。
- 削除の作業：エッジ → ポッドの DB（1 万行ずつ）→ Valkey → OpenSearch → S3（大阪を含む）→ 全体の行を墓標に → アプリへ `shop/redact`。段ごとに冪等で、30 日で終わらなければ Ops を呼ぶ。
- 保持の対象（領収書・返還インボイスの写し、注文の記録、監査ログ、本システムの請求の記録）は、削除の前に保持の置き場所（Object Lock）へ写し、`retained_until` まで残す。範囲と期間は法務の確認待ち（L3・L4）。
- 凍結の理由のうち「規約の違反・法令の要請」の判断と手順は法務の確認待ち（L8・L10）。

### 他の案を選ばなかった理由

- **2（即時の削除）**：閉店を取り消す事業者と、決済の後始末（返金、支払い待ち）を受けられない。
- **3（無効だけ）**：個人のデータを持ち続け、削除の約束（法務の L3）に対応できない。ポッドの容量も減らない。

## Consequences

- 良くなること：
  - 状態ごとに、ストアフロント・管理画面・チェックアウト・Webhook の振る舞いが 1 つの表で決まる。
  - 削除の進み具合が段ごとに見え、やり直せる。
- 引き受けるコスト：
  - 削除の作業と保持の置き場所を持つ。表を足すたびに削除の対象に含める（表の目録の検査）。
  - バックアップに残る期間の扱いは、法務の確認まで決まらない。

## Confirmation

- 表駆動テスト：DT-SHOP-001（状態 × 操作）。
- 結合テスト：削除の作業の後、生成したショップの ID でポッドの全表・Valkey・OpenSearch・S3（東京・大阪）を走査して 0 件（保持の対象を除く）。
- 表の目録の検査：ポッドの DB のすべての表が、削除の作業の対象か、保持の対象の一覧にある。
