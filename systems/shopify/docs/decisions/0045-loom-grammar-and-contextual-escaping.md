# ADR-0045: Loom の文法を EBNF で固定し、演算子の優先の順位と括弧、`not`、`null`、空白の制御（`{{-`・`-}}`）を持つ。エスケープは、翻訳の時に静的な HTML を字句解析して出力の位置の文脈を決め、文脈ごとのエスケープを差し込む。引用のない属性の中の出力、`<script>`・`<style>` の中の `json`・`css_value` 以外の出力は翻訳のエラーにする

## Context

[ADR-0007](0007-theme-language-design.md) は、Loom の形（`{{ }}`・`{% %}`）、副作用なし、既定で HTML をエスケープ、上限を決め、文法の細部を storefront-themes の領域に任せた。

- HTML の本文の文脈だけのエスケープでは、属性の中（引用なし）、URL の属性（`javascript:`）、`<script>` の中、`<style>` の中で XSS が残る。
- 事業者とテーマの開発者は非プログラマーを含む。演算子の評価の規則が直感と違うと、条件の誤りが起きる。
- 文法をどこまで本家に似せてよいかは法務の確認待ち（L9）。本家の Liquid の実装は使わない（[リポジトリ共通の ADR-0007](../../../../docs/decisions/0007-no-reuse-of-original-implementation.md)）。
- 文脈に応じたエスケープは、Go の `html/template` などで公開されている考え方である。

## Options

エスケープ：

1. **翻訳の時に文脈を決めて差し込み、危ない文脈は翻訳のエラー**
2. 本文の文脈のエスケープだけ（全部の出力に同じエスケープ）
3. 出力の後の HTML を安全化の道具に通す

文法：

- a. **EBNF で固定、普通の優先の順位、括弧、`not`**
- b. 本家の Liquid の評価の規則に寄せる（括弧なし、右から評価）

## Decision

1 と a を採用する。詳細は [storefront-themes.md](../architecture/storefront-themes.md) の 4 節。

- 文法の骨格は EBNF。四則の演算子は持たず、フィルター（`add`・`sub`・`mul`・`div`・`mod`）で書く。
- 型は null、真偽、整数、十進、文字列、安全な HTML、配列・地図、お金、drop。暗黙の型の変換をしない。空と偽は `null` と `false` だけ。
- 文脈は、本文、引用した属性、URL の属性、イベントと `style` の属性、`<script>`、`<style>`。文脈ごとのエスケープかスキームの許可を差し込む。イベントの属性への出力、引用のない属性への出力、`<script>` への `json` 以外の出力はエラー。
- 分岐で文脈が変わるテンプレートは、分岐ごとに計算し、違えばエラー。
- `raw` は本文の文脈だけ。テーマのチェックで警告。
- 言語の確定（`loom_version` 1）は L9 の確認の後。名前を変える余地を残す。

### 他の案を選ばなかった理由

- **2（1 つのエスケープ）**：URL の属性の `javascript:`、`<script>` の中の値で XSS が残る。
- **3（後の安全化）**：テーマが意図したスクリプトと、値が作ったスクリプトを区別できない。
- **b（本家の評価の規則）**：直感と違う評価の順で条件の誤りが起き、L9 の論点も増える。

## Consequences

- 良くなること：XSS の多くを、書き手の注意でなく翻訳器で防げる。条件の書き方が普通の言語と同じになる。
- 引き受けるコスト：
  - 翻訳器が HTML の字句解析を持つ。字句解析の誤りがエスケープの抜けになるので、試験のベクトルとファジングを厚くする。
  - 一部の書き方（引用のない属性、イベントの属性の値）が使えず、テーマの開発者が書き換える。

## Confirmation

- 性質ベーステスト PROP-LOOM-002（エスケープ）、PROP-LOOM-003（決定性）。
- 表駆動テスト DT-LOOM-001（文脈 × 出力の形）。
- 試験のベクトル：文法の各規則、文脈のエスケープ。言語のバージョンごとに固定。
