# ADR-0032: 割引は商品・注文・送料の 3 つの種別に分け、商品 → 注文 → 送料の順に適用する。組み合わせは割引ごとの「組み合わせてよい種別」の印の両側の一致で決め、両立する割引の集まりのうち、買い手の割引の合計が最大のものを選ぶ。同じ額なら割引の数の少ない方、次に割引の ID の昇順の辞書順で選ぶ

## Context

- 同じカートと同じ割引の集まりから、同じ結果を出す（[AGENTS.md](../../AGENTS.md)、NFR-013）。ハッシュの表の順序・壁の時計・乱数に依らせない。
- 本家は、商品の割引 → 注文の割引 → 送料の割引の順に適用する。注文の率の割引は、それぞれ商品の割引の後の小計で計算し、率の割引の後に額の割引を引く。1 つの注文で使えるコードは、商品・注文の割引 5 つ、送料の割引 1 つ。自動の割引は 25 まで（[Discount combinations](https://help.shopify.com/en/manual/discounts/discount-combinations)、2026-10-10 に確認）。両立しない割引のうちどれを選ぶかの規則は、確かめられなかった（**未検証**）。
- 関数の割引（[ADR-0008](0008-extension-sandbox-wasm.md)）も同じ組み合わせの規則で合わせる。

## Options

1. **3 つの種別と固定の順序。両立の印の両側の一致。買い手の得の最大を、決めた探索で選ぶ**
2. 割引に優先の順位の数を持たせ、上から貪欲に足す
3. 入力の順（コードの入力の順）に足す

## Decision

1 を採用する。詳細は [discounts-engine.md](../architecture/discounts-engine.md) の 4・5 節。

- 種別：`product`（行の割引。額・率・まとめ買い）、`order`（注文の小計の割引。額・率）、`shipping`（送料の割引。無料・額・率）。
- 両立：割引 `a` と `b` は、`b.class ∈ a.combines_with` かつ `a.class ∈ b.combines_with` のとき両立する。同じ行に商品の割引は 1 つだけ。別の行の商品の割引どうしは常に両立する（MVP）。送料の割引は 1 つだけ。
- 計算の順：(1) 行ごとに商品の割引、(2) 注文の率の割引（どれも商品の割引の後の小計で計算し、足す）、(3) 注文の額の割引、(4) 送料の割引。
- 選び方：注文の割引の候補（単独の額の大きい順に上位 8 つ）の部分集合 × 送料の割引の候補（上位 2 つ＋なし）を計画として並べる。計画ごとに、両立する商品の割引を行ごとに最大のものを選び、合計を計算する。合計が最大の計画を選ぶ。同じ額なら割引の数の少ない方、次に割引の ID（UUIDv7）の昇順の列の辞書順で小さい方。
- 条件（最低の金額・数）は、その割引を適用する直前の小計で判定する。注文の割引の条件は商品の割引の後の小計、送料の割引の条件は注文の割引の後の小計で判定する。
- コードの数の上限は本家に寄せる（商品・注文 5、送料 1）。自動の割引は有効なもの 25 まで。

### 他の案を選ばなかった理由

- **2**：事業者が順位を付ける手間が増え、得の最大にならない組み合わせを選ぶ。
- **3**：入力の順で結果が変わり、決定性の性質を満たさない。

## Consequences

- 良くなること：結果が入力の順に依らない。買い手に最も得な組み合わせを選ぶ。
- 引き受けるコスト：計画の数は最大 256 × 3。行 250 で 1 回の計算が増える。注文の割引の候補が 8 を超えると、9 番目以降は選ばれない（事業者の画面で警告）。
- 別の行の商品の割引どうしを常に両立させる点は、本家（組み合わせの設定に従う。未検証）と違いうる。
