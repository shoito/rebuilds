# ADR-0028: カートはポッドの Valkey に置き（期限 14 日）、チェックアウトの作成で Aurora の `checkouts` に写す。カートの値は目安で、価格・在庫・割引はチェックアウトで計算し直す。Valkey を失ったらカートは空になる

## Context

- カートへの追加は、フラッシュセールで最も多い書き込みである。買わない人のカートも多い。
- [architecture/README.md](../architecture/README.md) の 1.2 節は、Valkey にカートを置き、失ってよい部品とした。E6 の Story `cart` は「Valkey と DB」と書いた。どちらを正本にするかを決める。
- チェックアウトの段からは、お金と在庫に関わるので、DB を正本にする（[ADR-0005](0005-checkout-state-machine-and-exactly-once-orders.md)）。

## Options

1. **カートは Valkey、チェックアウトから DB**
2. カートも DB に置く
3. カートをブラウザーの cookie・ローカルの保存に置く

## Decision

1 を採用する。詳細は [cart-and-checkout.md](../architecture/cart-and-checkout.md) の 3 節。

- カートの鍵は `{<shop_id>}:cart:<cart_token>`（先頭はショップのハッシュタグ）。値は行（品目、数、行の属性）、カートの属性、割引のコード、買い手の ID（ログインしたとき）、バージョンの番号。期限は最後の更新から 14 日。
  > 2026-10-10 の注記：最初の鍵は `cart:{shop_id}:{cart_token}` だった。Valkey の鍵は全部 `{<shop_id>}:` で始める規則（[data-model.md](../architecture/data-model.md)）に揃えた。
- 更新はバージョンの番号つきの比べて入れ替え（Lua）で行う。並行の更新は後の側を再試行させる。
- 行は最大 250、1 行の数は最大 9,999、行の属性は 1 行 10 個・合計 4 KB。
- カートの価格は表示のための目安。チェックアウトの作成で、最新の価格・在庫の有無・割引を計算する。
- ログインした買い手のカートは、Valkey の失効に備えて、30 分ごとに DB の `saved_carts` へ写す（失っても 30 分ぶん）。
- Valkey の障害の間、カートの読み出しは空、書き込みは 503 を返す。チェックアウトは DB で続く。

### 他の案を選ばなかった理由

- **2**：フラッシュセールのカートへの追加が、ポッドの DB の書き込みを数倍にする。
- **3**：Storefront API と複数の端末から同じカートを使えない。改ざんを毎回確かめる必要がある。

## Consequences

- 良くなること：カートの書き込みがポッドの DB を使わない。
- 引き受けるコスト：Valkey のフェイルオーバーで、ログインしていない買い手のカートが消えうる（お金と在庫には影響しない）。

## Confirmation

- 結合テスト：Valkey を止めても、作成済みのチェックアウトの送信と完了が続く。
- 性質ベーステスト：並行の行の追加で、バージョンの番号の比べにより失われる更新がない。
