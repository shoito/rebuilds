# ADR-0053: 順位は、欄ごとの重みの BM25 に、売れ行き（`log1p(直近 30 日の数)`）と在庫ありの係数を掛ける決めた式で付け、同じ得点は商品の ID の順にする。同義語はショップごとの表を、索引の解析器でなく問い合わせの時の展開で使う。関連の商品は、直近 90 日の注文の共起の `lift`（共起 3 以上）を主に、同じコレクションの人気で埋める

## Context

- 順位付けとおすすめの規則は自前で持つ（[ADR-0001](0001-platform-and-stack.md)）。MVP のおすすめは共起と人気の基本（[intent.md](../intent.md)）。
- 同じ得点の並びが揺れると、ページングで重なりと抜けが出る。
- 解析器は索引の単位で、ショップごとの同義語を解析器に入れられない。
- おすすめが少数の注文から作られると、特定の買い手の買い物の組み合わせを推測させうる。

## Options

順位：

1. **BM25 × 売れ行き × 在庫の係数、同点は ID の順**
2. BM25 だけ
3. 学習した順位（Learning to Rank）

おすすめ：

- a. **共起の `lift`（共起 3 以上）＋コレクションの人気**
- b. 同じコレクションの人気だけ
- c. 個人の閲覧の履歴

## Decision

1 と a を採用する。詳細は [search-and-recommendations.md](../architecture/search-and-recommendations.md) の 5・7 節。

- 重み：`title` 3、`vendor` 2、`tags` 2、`product_type` 1.5、`body` 0.5、2-gram 1、読み 0.8、SKU の完全一致 10。係数：`log1p(sales_30d) × 0.3`、在庫あり 1.2。並び：得点、`product_id`。
- 同義語は 1 ショップ 500 組、問い合わせの時に `should` に足す。
- 結果が 0 件なら、2-gram だけ（50%）で取り直して「近い結果」にする。
- `lift(A,B) = count(A∧B) × N / (count(A) × count(B))`、`count(A∧B) >= 3`、上位 20、日次。足りなければ同じコレクションの `sales_30d` の上位。
- 合わせて買う商品は事業者の手の選択を先にする。
- 個人の履歴のおすすめは MVP で持たない。

### 他の案を選ばなかった理由

- **2（BM25 だけ）**：売れていない商品・在庫切れが上に来る。
- **3（学習）**：学習のデータ（クリックと購入）と評価の仕組みが要り、MVP の範囲を超える。
- **b（人気だけ）**：商品の関係を表さない。
- **c（個人の履歴）**：キャッシュの鍵が個人に依り、外部送信と個人の情報の論点が増える。

## Consequences

- 良くなること：順位が決定的で、参照の実装と比べられる。
- 引き受けるコスト：重みと係数は経験の値で、E16 の評価の集まり（合成のショップの問い合わせと期待する上位）で見直す。

## Confirmation

- 性質ベーステスト PROP-SRCH-004（決定性とページング）、PROP-REC-001（`lift` の参照の実装との一致、共起 3 未満の除外）。
- 評価の集まり：日本語の表記の揺れの試験のベクトルで、期待する商品が上位 10 に入る。
