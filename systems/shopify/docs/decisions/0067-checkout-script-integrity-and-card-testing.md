# ADR-0067: チェックアウトのページはテーマで描かず、テーマ・アプリ・事業者のスクリプトを載せない。CSP は応答ごとの `nonce` と、本システムの資産と選んだ決済の提供者だけの配信元の一覧で強制する。アプリの計測は DOM に触れない砂場の iframe へ事象だけを渡す。スクリプトの目録の変化を見張りで検出する。カードテストは、チェックアウト・セッション・IP・ショップの単位の支払いの試みの上限と、失敗の率の急増での自動のチャレンジで抑え、提供者の不正の検出と重ねる

## Context

- 決済の画面へのスクリプトの差し込み（スキミング）は、EC の主な攻撃である。入口は、乗っ取ったスタッフのアカウント、悪意のアプリ、事業者のタグの管理の道具、依存の配信元の乗っ取り。
- カードの入力は提供者の iframe か決済ページだけ（[ADR-0006](0006-payments-via-providers.md)）。それでも、ページのスクリプトは、偽の入力欄を重ねる、住所を抜く、iframe の外の操作を盗む、ことができる。
- ストアフロントは、事業者・アプリのスクリプトを許す（[ADR-0048](0048-storefront-scripts-csp-and-external-transmission.md)）。キャッシュするので `nonce` を使えない。
- 事業者とアプリは、購入の完了などの事象を計測したい（広告の成果の計測）。
- PCI DSS v4.0.1 には、決済のページのスクリプトの管理に関する要件がある（6.4.3、11.6.1。解釈は**未検証**、QSA と法務の L7 で確かめる）。
- 盗んだカードの有効さの試し（カードテスト）は、チェックアウトの決済の送信を大量に使う。決済の提供者は不正の検出を持つが、能力は提供者ごとに違う（[payments-integration.md](../architecture/payments-integration.md)）。

## Options

チェックアウトのスクリプト：

1. **テーマとアプリのスクリプトを載せない。`nonce` の CSP。計測は砂場の iframe**
2. ストアフロントと同じ形（配信元の一覧とハッシュ）で、アプリの埋め込みを許す
3. スクリプトを許し、変化の検出だけに頼る

カードテスト：

- a. **本システムの多層の上限と自動のチャレンジ ＋ 提供者の不正の検出**
- b. 提供者の不正の検出だけ

## Decision

1 と a を採用する。詳細は [security.md](../architecture/security.md) の 3.1・3.4・4 節。

- チェックアウト（`/checkouts/…`）は本システムの画面で、テーマで描かない。見た目は設定（色、ロゴ、文言）と関数だけで変える。
- CSP：`script-src 'nonce-<応答ごと>'` と資産の CDN と提供者のスクリプトの配信元、`frame-src` は提供者と計測の砂場の起点、`connect-src 'self'` と提供者の API、`frame-ancestors 'none'`、`form-action`、`base-uri 'none'`、`require-trusted-types-for 'script'`。本システムの資産に SRI。違反の報告は 1 件から Ops に知らせる。
- アプリの計測：チェックアウトの起点と別の起点の iframe（`sandbox="allow-scripts"`）に、スコープと保護のデータの範囲の事象を `postMessage` で渡す。iframe の `connect-src` はアプリの登録した送信先だけ。外部送信の公表は法務の L6。
- 見張りが 5 分ごとに、チェックアウトのページの読み込んだスクリプトの URL とハッシュを、リリースの目録（`checkout_script_manifest`）と比べる。不一致は呼び出し。
- カードテストの上限：1 チェックアウトの支払いの試み 5 回、失敗の試みはセッション 1 時間 5 回・IP 1 時間 20 回、ショップの直近 10 分の失敗の率が 7 日の同じ時刻の 3 倍かつ 20 件以上で、支払いの送信に WAF の Challenge を 1 時間付ける。少額の多数のカードの試みを事業者と Ops に知らせる。

### 他の案を選ばなかった理由

- **2**：アプリの埋め込みと事業者の配信元の 1 つの乗っ取りが、決済の画面に届く。
- **3**：検出は事後で、検出までの間の買い手の入力が抜かれる。
- **b**：提供者の能力に依り、提供者を足すたびに守りが変わる。提供者の手数料とチャージバックの率は事業者の損になる。

## Consequences

- 良くなること：
  - 決済の画面に載るスクリプトが、本システムのリリースの目録だけになる。
  - カードテストの守りが提供者に依らない最低の線を持つ。
- 引き受けるコスト：
  - 事業者とアプリは、チェックアウトの見た目と計測の自由度が小さい（ストアフロントとの違いを説明する）。
  - 正規の買い手が、失敗の続いたときにチャレンジや待ちを受ける。

## Confirmation

- 性質ベーステスト：PROP-SEC-004（任意のテーマとアプリの組み合わせで、チェックアウトの HTML と CSP に、テーマ・アプリ・事業者のスクリプトが現れない）。
- E2E：計測の砂場の iframe から、親の DOM と入力の値を読めない。
- 結合テスト：カードテストの各上限と、自動のチャレンジの付け外し。
- 本番：見張りのスクリプトの目録の比べ、CSP の違反の数（[observability.md](../architecture/observability.md) の 5 節）。
