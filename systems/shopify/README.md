# Shopify

事業者（ショップ）がネットショップを開き、商品を売り、注文を配送するまでを支える、複数のテナントの EC の基盤を、「数百万のショップをポッドに分けて置き、移し替えられる多テナントの構成」「フラッシュセールでも売り越さない在庫の引き当てと、待合室・ボット対策」「決済の提供者とつなぎ、注文をちょうど 1 回作るチェックアウト」「任意のコードを持たない自前のテーマの言語と、エッジのキャッシュ」「燃料で上限を付けた WebAssembly の砂場で動くアプリの関数と、費用で絞る Admin API」として作り直す設計。日本を最初の市場にし、消費税の軽減税率とインボイス制度、日本の決済手段と配送に合わせる。

主な論点：

1. ショップ単位のポッド（セル）への分け方、ショップの移し替え、フラッシュセールのうるさい隣人
2. カタログ（商品、バリエーション、オプション、コレクション、メディア、拠点ごとの在庫）、複数の通貨、税込みの価格、軽減税率、インボイス
3. フラッシュセールの在庫：引き当てと確定、売り越しの防止、熱い行、待合室、ボット対策
4. カートとチェックアウト：状態の機械、送料・税・割引（スタックの規則）、決済の提供者の連携、注文の一回性、日本の決済手段
5. 注文と配送：注文のライフサイクル、配送の指示、送り状と運送会社の連携、返品と返金
6. ストアフロント：自前のテーマの言語、エッジのキャッシュと無効化、ヘッドレスの Storefront API、SEO
7. アプリの基盤：OAuth とスコープ、GraphQL の Admin API と費用の上限、Webhook、WebAssembly の関数、アプリの課金
8. 検索とおすすめ（基本）
9. 管理画面、スタッフと権限、監査
10. 日本の法令（特定商取引法、景品表示法、個人情報保護法、インボイス、資金決済法）。法務の確認待ち
