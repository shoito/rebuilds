# ADR-0004: 4 つのチャンネルと 4 週ごとのリリース、段階的な自動更新にする

## Context

ブラウザの脆弱性は、見つかってから悪用されるまでが短い。本家 Chrome は、Canary・Dev・Beta・Stable のチャンネルと、4 週ごとのメジャーリリース、段階的な自動更新で、変更と修正を速く安全に配る。

## Options

1. **4 つのチャンネル、4 週ごとのリリース、段階的な自動更新**
2. **四半期ごとのリリースと、利用者の手動の更新**

## Decision

1 を採用する。詳細は [update-and-release.md](../architecture/update-and-release.md) にある。

- Canary は毎日、Dev は毎週、Beta と Stable は 4 週ごとのメジャーリリース。Stable には、その間に修正の版を出す。
- 自動更新は、差分の配信と、段階的な配信（1% → 10% → 50% → 100%）で行う。クラッシュ率などの指標が悪化したら、配信を止める。
- 重大な脆弱性の修正は、段階を短くして配る（NFR-006）。
- 2 は、修正が届くまでの時間が長すぎる。

## Consequences

- 良くなること：
  - 変更を小さく、頻繁に届けられる。修正の配信が速い。
- 引き受けるコスト：
  - 4 週ごとのリリースの運用（ブランチ、検証、承認）を回し続ける必要がある。

## Confirmation

- 更新の配信のサービスで、チャンネルごとの版の分布と、配信の段階を監視する。
- NFR-006 の達成を、重大な修正のたびに記録する。
