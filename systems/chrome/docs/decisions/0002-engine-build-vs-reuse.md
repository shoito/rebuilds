# ADR-0002: ブラウザの構造は自作し、成熟した部品を使う

## Context

本家 Chrome のエンジン（Blink・V8 と周辺）は、長い年月をかけた巨大なコードである。すべてを作り直すのは現実的でない。

一方、既存のエンジンをそのまま使う（Chromium の上に作る）と、「作り直す」ことにならず、設計の論点がなくなる。Servo と Firefox は、スタイル計算（Stylo）と描画（WebRender）を、独立した Rust の部品として持つ。

## Options

1. **構造を自作し、成熟した部品を使う**
2. **Chromium の content layer の上に作る**（本家と同じ土台）
3. **すべてを自作する**（JavaScript エンジンまで）

## Decision

1 を採用する。

| 区分 | 対象 |
| --- | --- |
| 自作する（設計の中心） | 複数プロセスの構成と IPC、サイトの隔離、ナビゲーションと履歴、ネットワークのスタックの組み立て（キャッシュ、Cookie、プライバシーの制限）、保存領域、DOM とイベント、レイアウト、UI、拡張機能の API、更新・同期のクライアント |
| 部品を使う（候補。領域の文書で確定する） | JavaScript：V8。スタイル：Stylo（Servo）。描画：WebRender か Skia。文字：HarfBuzz と FreeType・各 OS のフォント。国際化：ICU4X。TLS：rustls か BoringSSL。HTTP/3：quinn などの QUIC の実装。画像・動画：各形式の復号器と OS の機能 |

- 部品は、バージョンを固定し、脆弱性の修正に追従する責任を持つ（[update-and-release.md](../architecture/update-and-release.md)）。
- 2 は、プロセスの構成・隔離・ナビゲーションといった設計の中心を、既存のコードに委ねることになる。
- 3 は、JavaScript エンジンの性能と互換性に、何年もかかる。

## Consequences

- 良くなること：
  - ブラウザの安全と構造を、自分たちの設計で決められる。
  - 成熟した部品で、性能と互換性の土台を得る。
- 引き受けるコスト：
  - 部品の組み合わせ（V8 と自作の DOM のバインディング、Stylo と自作のレイアウト）の境界に、大きな設計の作業がある。
  - 部品ごとの脆弱性への追従が要る。

## Confirmation

- 部品の一覧と版を、1 か所（`third_party` の目録）で管理し、脆弱性の通知を自動で受ける。
