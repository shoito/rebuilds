# ADR-0005: クラウドのサービスは送るデータを最小にし、同期は暗号化する

## Context

ブラウザは、閲覧の履歴やパスワードという、最も機微なデータを扱う。クラウドのサービス（同期、Safe Browsing、クラッシュの収集、テレメトリ）が集めるデータは、利用者の信頼に直結する。

## Options

1. **送るデータを最小にし、同期はエンドツーエンドで暗号化し、テレメトリは同意に基づく**
2. **本家と同じ既定（同期は既定でサーバー側の鍵、テレメトリは既定で有効）**

## Decision

1 を採用する。詳細は [sync-and-accounts.md](../architecture/sync-and-accounts.md) と [safe-browsing-and-permissions.md](../architecture/safe-browsing-and-permissions.md) にある。

- **同期は、パスワードを必ず、その他のデータも既定で、エンドツーエンドで暗号化する**（利用者の鍵。サービスは暗号文だけを持つ）。
- **Safe Browsing は、URL のハッシュの接頭辞で照会し、URL そのものを送らない**（本家の Update API と同じ考え方）。
- **クラッシュの報告とテレメトリは、初回に選ばせ、既定では送らない。** 送る場合も、内容の範囲を公開する。
- 2 は、本家に寄せるが、閲覧のデータの扱いに対する懸念を、そのまま引き継ぐ。

## Consequences

- 良くなること：
  - サービスの侵害や、運営者によるデータの閲覧の危険を減らせる。
- 引き受けるコスト：
  - 鍵を失った利用者は、同期のデータを取り戻せない。回復の手段（回復用のコード）を用意する。
  - テレメトリの量が少なく、品質の判断に使える情報が減る。

## Confirmation

- 同期のサービスの DB に、平文の閲覧データ・パスワードが無いことを、定期の検査で確かめる。
