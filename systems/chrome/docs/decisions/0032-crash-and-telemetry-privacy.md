# ADR-0032: クラッシュとテレメトリは同意した人だけが送り、利用者の ID を持たせない

## Context

ADR-0005 で、クラッシュの報告とテレメトリは初回に選ばせ、既定では送らないと決めた。この ADR では、何を・どう送り・どう持つかを決める。条件は次のとおり。

- クラッシュのダンプは、プロセスのメモリの一部を含み、閲覧の内容が混ざりうる。
- 品質の判断（自動の停止、NFR-001・005 の計測）には、版ごとの率が要る。利用者ごとの追跡は要らない。
- 同意と無関係に送るもの（更新の確認）と、同意が要るものの境界をはっきりさせたい。
- フィールドトライアル（機能の段階的な有効化）は、同意と無関係に動かしたい（止める手段として使うため）。

## Options

1. **同意した人だけが送り、永続の ID を持たせない。ダンプはスタックだけにし、注釈を許可リストにする**
2. **本家に近い形**（永続のクライアントの ID を持ち、利用者単位で集計する。ダンプの範囲を広くする）

## Decision

1 を採用する。詳細は [update-and-release.md](../architecture/update-and-release.md) の 4.1・9・10・12 節と [observability.md](../architecture/observability.md)。

| 送るもの | 同意 | 識別子 | 中身の範囲 |
| --- | --- | --- | --- |
| 更新の確認・結果のイベント | 不要（更新の機能） | なし（リクエストごとの乱数、0〜999 の区画、プロトコル 4 の活動の数え方） | 版、チャンネル、OS、結果。表を公開する |
| フィールドトライアルの設定の取得 | 不要 | なし（ETag だけ） | 送るものはない。割り当ては端末の中で行い、サーバーに送らない |
| クラッシュの報告 | 要 | レポートごとの乱数 | スタック、レジスタ、モジュール、許可リストの注釈。ヒープ、URL、タイトル、パスは入れない |
| テレメトリ | 要 | ブラウザのセッションの中だけの乱数 | 登録簿にある指標だけ。登録簿を公開する |

- **ダンプ**：Crashpad の handler がプロセスの外で取る（[Crashpad の設計](https://chromium.googlesource.com/crashpad/crashpad/+/HEAD/doc/overview_design.md)）。スタックの内容に閲覧のデータが残りうるので、生のダンプは 30 日で消し、読める人を限り、読むたびに記録する。
- **同意がないとき**、ダンプはローカルに 7 日だけ置き、利用者が 1 件ずつ選んで送れる。自動では送らない。
- **指標の登録簿**：名前・種類・単位・持ち主・期限・プライバシーの区分を必須にし、期限の切れた指標は受け取らない。本家のヒストグラムの規則に倣う（[histograms の README](https://chromium.googlesource.com/chromium/src/+/HEAD/tools/metrics/histograms/README.md)）。新しい指標と、区分の高い指標の追加は、プライバシーのレビューを要する。
- **IP アドレス**は、アプリのログとデータに保存しない。WAF と CDN のアクセスログは 7 日で消す。
- **フィールドトライアル**：seed は署名した静的なファイルで、割り当ては端末の乱数で行い、送らない。同意した人のテレメトリにだけ、有効なグループが載る。
- 2 は、利用者単位の分析（継続率など）ができるが、閲覧のデータと結び付く ID をサービスが持つことになる。ADR-0005 の考え方に反する。

## Consequences

- 良くなること：
  - サービスが侵害されても、特定の利用者のクラッシュや利用の状況をたどれない。
  - 送る範囲を公開でき、利用者に説明しやすい。
- 引き受けるコスト：
  - 利用者単位の分析（1 人がどれだけクラッシュに遭うか、継続率）ができない。率はすべてセッションあたりになる。
  - 同意した人が少なく偏るので、クラッシュ率の標本が小さく、自動の停止の判定が遅れる（ADR-0029）。
  - ダンプがスタックだけなので、ヒープの破壊などの一部の不具合は原因を追いにくい。社内の Canary（同意した社員の端末）でだけ、範囲の広いダンプを取れるようにするかを、S2 の前に検討する。

## Confirmation

- テスト：ダンプの注釈に、許可リストにない鍵が入ったら、handler が捨てること。URL の形をした値が注釈に入らないこと。
- テスト：同意がない状態で、クラッシュとテレメトリの送信が 0 件であること（ネットワークの記録で確かめる）。
- CI：登録簿にない指標を記録するコードを失敗させる。期限を過ぎた指標のコードを失敗させる。
- 定期の検査：crash-ingest・telemetry-ingest のログと保存データに、IP アドレスと URL の形をした値がないこと。
