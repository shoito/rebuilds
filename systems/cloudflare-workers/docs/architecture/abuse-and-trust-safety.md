# Abuse and Trust & Safety: Cloudflare Workers

基盤の不正な利用への対応の設計。既定のサブドメインと公開のバケットでのフィッシング・マルウェア、暗号資産の採掘、外向きの通信の悪用（プロキシ、大量の送信、攻撃）、通報と停止の流れ、捜査機関からの照会、新しいアカウントのリスクの点数と `c0-untrusted` への結び付け、`<Brand>-Worker` による送り元の特定を決める。

| 関連 | 決定 |
| --- | --- |
| [ADR-0010](../decisions/0010-process-sandbox-and-egress-invariants.md) | 外への経路は外向きのプロキシだけ |
| [ADR-0011](../decisions/0011-cordon-tiers-and-placement.md) | cordon はアカウントの状態から決め、信頼を下げる変更は届いた時点で反映する |
| [ADR-0020](../decisions/0020-pingora-ingress-and-egress-proxies.md) | 外向きのプロキシは `<Brand>-Worker` のヘッダーを付け、送信元の IP と `<Brand>-Ray` を結び付けて記録する |
| [ADR-0022](../decisions/0022-sequenced-change-log-relays-and-lmdb.md) | アカウントの状態・停止は優先の印で全ノードへ配る |
| [ADR-0043](../decisions/0043-hosted-content-abuse-and-takedown.md) | ホストした内容は、アップロードの静的な検査・巡回・外部の一覧・通報で見つけ、警告の頁・関数の停止・アカウントの停止の段で止める。通報は 1 つの事件の流れで扱い、異議を別の担当が見る |
| [ADR-0044](../decisions/0044-egress-abuse-controls.md) | 外向きの悪用は、cordon ごとのアカウントの外向きの方針（宛先ごとの速さ、宛先の数）で抑え、採掘・プロキシは静的な印と通信の形で見つける。`<Brand>-Worker` は既定のホスト名を必ず付ける |
| [ADR-0045](../decisions/0045-new-account-risk-scoring.md) | 新しいアカウントのリスクの点数を規則で出し、ADR-0011 の `c0-untrusted` の条件に「リスクが高い」を足す。点数は信頼を下げる方にだけ働く |

**法令の上の扱いは法務の確認待ち。** 削除の義務と手順、発信者の情報の開示、捜査機関の照会、許容される利用の方針（AUP）は、[intent.md](../intent.md) の L1・L2・L4 にあたる。この文書は、どの結論にも合わせられる仕組みを決め、結論は出さない。**L1 の確認までは E4 の既定のサブドメインの公開と E8 の公開のバケットの spec を、L4 の確認までは E12 の GA の判定を承認しない。**

## 1. 目的と範囲

- 目的：無料の枠と既定のサブドメインが、フィッシング・マルウェアの配布・攻撃の中継に使われる時間を短くする。正当な利用者を誤って止めたときに、すぐ戻せる。通報した人と受け手が、送り元を特定できる。

| --- | --- |

| 採掘、プロキシ、大量の送信、攻撃の中継の検知と抑え | 外向きのプロキシの実装（edge-network-and-routing） |
| 通報の窓口、事件の流れ、異議、透明性 | 利用規約・AUP の文面（法務） |

| `<Brand>-Worker` と送信元の IP の記録 | 基盤への DDoS の防御（edge-network-and-routing、infrastructure） |

## 3. 原則

- **ホストしている内容には、自分たちが責任を持つ。** 利用者の関数とオブジェクトは、この基盤がホストしている。通報を回すだけで済ませない（本家と同じ扱い）。
- **止め方は段にし、軽い段から自動にする。** 確度の高いものだけ自動で止め、残りは人が見る。止めたものは 1 回の操作で戻せる。
- **ノードは手元の印だけで止める。** 停止は、変更のログの優先の印で配る（ADR-0004）。要求の処理の経路で、不正な利用の判定のサービスを呼ばない。
- **通信の中身を見ない。** 関数の利用者（エンドユーザー）の要求・応答の本文を、不正な利用の判定のために読まない。使うのは、公開の URL の巡回、アップロードされたコード、通信の件数と宛先の集計（宛先の扱いは L2 の確認待ち。13 節）。
- **信頼を下げる方にだけ自動で働く。** リスクの点数と検知は、cordon を下げ、制限を強めるが、ADR-0011 の条件より緩めない。

## 4. 脅威と対象

| 脅威 | 主な場所 | 主な印 | 既定の措置 |
| --- | --- | --- | --- |
| フィッシング | 既定のサブドメイン、カスタムドメイン、公開のバケットの HTML | 巡回の分類、保護する名前を含むホスト名、外部の一覧、通報 | 警告の頁 → 関数の停止 → アカウントの停止 |
| マルウェアの配布 | 公開のバケット、関数の応答 | 外部の一覧のハッシュ、巡回で得たファイルのハッシュ、通報 | 関数・バケットの停止 |
| 暗号資産の採掘 | 関数（有料の長い CPU 時間、cron、キュー） | Wasm・JavaScript の採掘の印、CPU の形、採掘の中継の宛先 | 関数の停止 |
| 開いたプロキシ・VPN の中継 | 関数 | 既知のプロキシの印、宛先の数、WebSocket の長い中継 | 外向きの制限 → 関数の停止 |
| 大量の送信（フォーム・コメント・メールの API） | 外向きの通信 | 同じ宛先への速さ、`<Brand>-Worker` での通報 | 外向きの制限 |
| 攻撃の中継（HTTP の洪水、資格情報の詰め込み） | 外向きの通信 | 同じ宛先 IP への速さ、通報 | 外向きの制限 → 関数の停止 |
| 著作権・商標の侵害 | 公開のバケット、関数の応答 | 通報 | 法務の手順（L1） |
| 児童の性的な搾取の内容 | 公開のバケット | 通報、ハッシュの照合（S2） | 即時の停止、証拠の保全、法務（L1・L4） |
| 無料の枠の使い回し | アカウントの作成 | リスクの点数（8 節） | 作成の拒否、`c0-untrusted` |

## 5. ホストした内容の検知

[ADR-0043](../decisions/0043-hosted-content-abuse-and-takedown.md)。

### 5.1 流れ

```
起点                                   検査                              判定                        措置（6 節）
─────────────────────────────         ──────────────────────           ───────────────────        ─────────────
版の ready（既定のサブドメイン有効）─┐   静的な検査（バンドル）            点数 0〜1 と理由            自動（確度が高く、
公開のバケットへの書き込み ─────────┤   巡回（ヘッドレスの Chromium）──▶ 規則 ＋ 分類のモデル ──┬──▶ c0・c1 のアカウント）
新しいホスト名の最初の要求 ─────────┼─▶ 外部の一覧の照合                                        ├──▶ 人の確認の行列
c0 のアカウントの関数の毎日の再巡回 ─┤   ホスト名の字面の検査                                    └──▶ 記録だけ
外部の一覧の更新・通報 ─────────────┘
```

### 5.2 静的な検査（アップロードの時）

- 検証のフリート（[runtime-and-isolates.md](runtime-and-isolates.md) の 7.3 節）の後に、別の非同期の検査で行う。デプロイを止めない（デプロイの 30 秒の SLO を守る）。
- 対象：バンドルの全モジュールの SHA-256 と、テキストのモジュールの中身。
  - 既知の悪用の道具（フィッシングの雛形、プロキシ・VPN の中継の雛形、採掘のライブラリ）の印（YARA の形の規則）。
  - Wasm の採掘の印（ハッシュの関数の既知の形）。
  - **関係のないアカウントの間での同じバンドル**：同じ `bundle_sha256` が、支払い手段・メール・IP の共通しない 5 つ以上の新しいアカウントからデプロイされたら印を付ける。悪用の道具は使い回される。
- 印の規則は開発リポジトリの非公開の場所に置き、セキュリティと Trust & Safety の担当が承認する。

### 5.3 巡回

- 巡回は、エッジと制御プレーンと別の AWS アカウントのヘッドレスの Chromium で行う。内部の網に届かない。
- 対象：既定のサブドメインの `/`、通報・外部の一覧にある URL、公開のバケットの HTML と実行ファイル。
- 記録：描画した頁の画面の写し、HTML、網の要求の一覧、フォームの送り先、ダウンロードしたファイルのハッシュ。証拠として 180 日持つ（事件があれば保全。10 節）。
- 巡回の元の IP は、他の利用者の IP と同じく見えるよう、エッジの入口を通して要求する（内部の近道を使わない）。ただし、巡回の IP を見分けて違う内容を返す手口（cloaking）は防げない。通報と外部の一覧で補う。

### 5.4 判定

- S1 は、規則と、頁の特徴（保護する名前の文字・画像の一致、パスワードの入力欄、フォームの送り先が別のドメイン、既知の雛形の構造）を入れた分類のモデルで点数を出す。点数とともに理由の一覧を残す（人の確認と異議の説明に使う）。

| 点数 | c0・c1 のアカウント | c2・c3 のアカウント |
| --- | --- | --- |
| 0.95 以上 | 自動で警告の頁（フィッシング）・関数の停止（マルウェア） | 人の確認の行列（優先） |
| 0.70〜0.95 | 人の確認の行列（優先） | 人の確認の行列 |
| 0.70 未満 | 記録だけ | 記録だけ |

- 閾値は E12 で、既知の良い頁・悪い頁の集まりで誤検知の率を測って決める。目標：自動の措置の誤りが月 0.5% 未満（異議で覆った割合）。

### 5.5 ホスト名の字面

- 保護する名前の一覧（国内の金融・通信・物流・電子商取引の大手、行政、自分たちのブランド）を持つ。一覧は Trust & Safety の担当が保つ。
- `c0-untrusted` のアカウントは、保護する名前を含む関数の名前・アカウントのサブドメインの名前を作れない（作成を拒否する）。それ以外のアカウントは作れるが、巡回を即時に行い、人の確認の行列に入れる。
- 異なる文字体系を混ぜた名前は、既定のサブドメインでは使えない（名前は `[a-z0-9-]` だけ）。カスタムホスト名の IDN の制約は [edge-network-and-routing.md](edge-network-and-routing.md) の 6.2 節。

### 5.6 外部の一覧

- 取り込む：Google の Web Risk（商用の利用の条件は E12 で確かめる）、公開のフィッシングの一覧、JPCERT/CC とフィッシング対策協議会からの依頼。取り込みの頻度は 15 分。
- 既定のドメインは Public Suffix List に載せる（[edge-network-and-routing.md](edge-network-and-routing.md) の 6.1 節）。一覧の多くは、PSL の境の下（アカウントのサブドメイン）で登録するので、1 つの悪用で既定のドメイン全体が止められる危険を下げる（一覧ごとの扱いは未検証）。
- 既定のドメインが外部の一覧で丸ごと止められたときの runbook を持つ（18 節）。

## 6. 措置の段と停止

[ADR-0043](../decisions/0043-hosted-content-abuse-and-takedown.md)。

### 6.1 段

| 段 | 対象 | 効果 | 自動で出せるか | 配り方 |
| --- | --- | --- | --- | --- |
| `flag` | 関数・バケット・アカウント | 記録と人の確認の行列。巡回を増やす | ○ | — |
| `interstitial` | 既定のサブドメインのその関数、公開のバケットの既定のドメイン | 入口のプロキシが警告の頁を返す。「理解して進む」で 1 時間進める（疑いの段なので） | ○（c0・c1 で 0.95 以上） | `script_state/`（優先） |
| `block_script` | 関数（全てのホスト名）、バケット | 1203。cron・キューの consumer・アラームも止める。デプロイは受け付けるが公開しない | ○（マルウェア・採掘の既知の印の一致） | `script_state/`（優先） |
| `suspend_account` | アカウント | 全ての関数が 1203、公開のバケットが 403、ストレージの操作・デプロイ・新しいトークンを拒否。管理 API は読み込みだけ（データの取り出しのため） | 人（1 人） | `account_state/`（優先） |
| `terminate` | アカウント | 契約の終了と削除の予約（30 日）。法的な保全があれば削除しない | 人（2 人） | 同上 |

- どの段でも、`interstitial` 以上を出したら、そのアカウントの信頼を下げる：`account_state` に `abuse_hold` を書き、cordon を `c0-untrusted` に下げ、isolate を捨てる（ADR-0011 の信頼を下げる変更）。
- 全ての段の出し入れは、監査ログ（`platform.abuse.*`）と事件（9 節）に残す。
- 停止の配信は p99 10 秒（設定の変更の SLO。[deployment-and-config-distribution.md](deployment-and-config-distribution.md) の 9.1 節）。

### 6.2 警告の頁

- 既定のサブドメインと公開のバケットの既定のドメインだけで出す。カスタムドメインは利用者のドメインなので、警告の頁ではなく `block_script` で止める。
- 頁は `<brand>` の頁で、`<Brand>-Ray`、疑いの種類（フィッシング・マルウェア）、通報の誤りの申し出の窓口を出す。関数の持ち主の情報は出さない。
- 「理解して進む」の印は、そのホスト名だけの Cookie（1 時間）。フィッシングの確認が済んだら（人の確認）`block_script` に上げ、進めなくする。

### 6.3 持ち主への連絡と異議

- 措置のたびに、アカウントの `owner`・`admin` にメールとダッシュボードで知らせる：種類、対象、URL、理由の要約、異議の窓口。
- 知らせないのは、児童の性的な搾取の内容と、捜査機関から知らせないよう求められたときだけ（法務の判断。10 節）。
- 異議はダッシュボードから出す。最初の判断と別の担当が、営業日 2 日以内に見る。覆ったら、同じ操作で戻し（`platform.abuse.restore`）、誤りの理由を判定の規則の見直しに回す。

### 6.4 時間の目標

| 種類 | 通報・検知から措置まで | 本家（2 節） |
| --- | --- | --- |
| フィッシング・マルウェア（確度の高いもの） | 中央値 1 時間、p90 4 時間 | 中央値 1 時間未満（2024 年の後半） |
| 攻撃の中継 | 中央値 1 時間 | 未検証 |
| 児童の性的な搾取の内容 | 確認から 1 時間以内に停止と保全 | 未検証 |
| 著作権・商標 | 法務の手順（L1） | 未検証 |
| その他 | 営業日 3 日 | 未検証 |

## 7. 外向きの悪用

[ADR-0044](../decisions/0044-egress-abuse-controls.md)。

### 7.1 アカウントの外向きの方針

外向きのプロキシ（[edge-network-and-routing.md](edge-network-and-routing.md) の 10.1 節の 4 の数の強制）に、アカウントの単位の方針を足す。値はノードごと（ノードの間で数を共有しない。要求の処理の経路に同期の依存を足さないため）。

| 項目 | `c0-untrusted` | `c1-free` | `c2-paid` | `c3-dedicated` |
| --- | --- | --- | --- | --- |
| 同じ宛先 IP への要求（1 秒） | 20 | 50 | 1,000 | 契約 |
| 10 分に接続した宛先のホストの数 | 100 | 300 | 制限なし（集計だけ） | 制限なし |
| 外向きの帯域（ノードあたり） | 10 Mbps | 20 Mbps | 200 Mbps | 契約 |
| 宛先のポート | 80・443 | 80・443・8080・8443 | 80・443・1024〜65535 | 同じ |
| 採掘の中継の既知の宛先 | 拒否 | 拒否 | 拒否 | 拒否 |

- 超えたら、その `fetch` を失敗させ（`TypeError`。関数から見える理由の文は「egress limit」）、数を数える。10 分続いたら `flag` を立てる。
- 方針は `account_egress/<account_id>`（器。設定の写し）で、cordon から既定を決め、個別の上書き（事件の対応）を配る（配り方は次の項）。
- ポートの値は、[edge-network-and-routing.md](edge-network-and-routing.md) の 10.3 節の S1 の既定（80・443 と 1024〜65535、25 は拒否）を、有料だけに残し、無料で狭める。統合の工程（2026-09-27）で、edge-network-and-routing の 10.3 節の既定をこの表に揃えた。
- `account_egress/` はアカウントごとの器だが、基盤の外向きの方針を上書きするので、基盤の器と同じ段階と 2 人の承認で配る。制限を厳しくする上書きは、段の待ちを 5 分に縮められる（[ADR-0056](../decisions/0056-platform-config-staging-and-flags.md)、[data-model.md](data-model.md) の 8 節）。
- 数値は既定案。E12 で、本番の分布（c1・c2 の上位 1% の値）を見て、正当な利用を止めない値に直す。

### 7.2 暗号資産の採掘

| 印 | 取り方 | 確度 |
| --- | --- | --- |
| 採掘の Wasm・JavaScript の既知の印 | 5.2 節の静的な検査 | 高い |
| 採掘の中継（stratum の中継）の既知の宛先への接続 | 外向きのプロキシの宛先と、脅威の情報の一覧 | 高い |
| CPU の形：1 時間の中で、要求の 80% 以上が CPU の上限の 90% 以上を使い、CPU 時間 ÷ 壁時計の時間が 0.9 以上、応答の転送が CPU 時間に比べて小さい | 呼び出しの記録の集計（スーパーバイザー → 集計） | 中 |
| cron・キューの consumer が毎回上限まで CPU を使う | 同上 | 中 |
| 少数の送り元の IP からの、同じ形の要求の繰り返し（自分で負荷をかけている） | 入口の集計 | 中 |

- 高い確度の印は `block_script` を自動で出す。CPU の形だけでは人の確認にする（圧縮・暗号・画像の処理など、正当な重い処理がある）。
- 無料の 10ms の上限では採掘の採算が合わない。採掘は、盗んだカードでの有料のアカウントで起きやすい。採掘の印のあるアカウントは、支払いの確認（8 節）を必ず行う。
- sandbox-and-security の性能カウンターでの検知（[sandbox-and-security.md](sandbox-and-security.md) の 6.3 節）とは別に扱う。性能カウンターの閾値は Spectre の対策のために秘すもので、不正な利用の判定に混ぜない。

### 7.3 開いたプロキシ・VPN の中継

- 印：既知のプロキシ・VPN の雛形の静的な印、要求のクエリ・パスから宛先を作る形（静的な検査で `fetch(new URL(request.url).searchParams.get(...))` などの形を見る）、宛先のホストの数、多数の送り元の IP × 多数の宛先、WebSocket での長い双方向の中継（WebSocket の接続時間と転送の量）。
- 措置：c0・c1 は 7.1 節の宛先の数の制限でまず抑え、印が重なれば `block_script`。c2 以上は人の確認。
- 汎用のプロキシ・VPN としての利用を AUP で禁じるか、どこまで禁じるかは法務の確認待ち（L4）。自分の API の前に置く正当なプロキシ（本家の代表的な使い方）と区別できるよう、「宛先を利用者が自由に指定できる」ことを禁止の核にする案を法務に出す。

### 7.4 大量の送信

- MVP は TCP のソケット（`connect()`）を持たない（[intent.md](../intent.md) の MVP の後の Epic）。`fetch` は HTTP だけなので、SMTP は話せない。25 番のポートはすでに拒否している。
- **`connect()` を足すときは、25・465・587 を全ての cordon で既定で拒否し、465・587 は有料のアカウントの申請と確認の後だけ開ける。** これを `connect()` の Epic の前提にする。
- HTTP の送信（フォーム・コメントの投稿、メールの送信の API）は、7.1 節の同じ宛先への速さで抑え、`<Brand>-Worker` での受け手の通報（11 節）で見つける。

### 7.5 攻撃の中継

- 7.1 節の同じ宛先 IP への速さと、帯域の制限で、1 つのアカウントが 1 つのノードから出せる量を抑える。5 つのリージョンの全ノードを合わせた量は抑えきれないので、集計で見る：1 つのアカウントから 1 つの宛先 IP への合計が、1 分に 10 万要求を超えたら `flag`、通報と重なれば `block_script`。
- 受け手からの攻撃の通報（`<Brand>-Worker` の値、送信元の IP と時刻）は、優先度 P1 の事件にする。

## 8. 新しいアカウントのリスクの点数

[ADR-0045](../decisions/0045-new-account-risk-scoring.md)。

### 8.1 印

| 分類 | 印 | 取る時 |
| --- | --- | --- |
| メール | 使い捨てのメールのドメイン、確認していないメール、同じ受け手の別名（`+` の付け足し）での多数の登録 | 登録 |
| 網 | ホスティング・VPN・Tor の AS からの登録、同じ /24（IPv6 は /48）から 1 日の登録の数 | 登録、ログイン |
| 端末 | 同じ端末の印（ファーストパーティの Cookie の ID）からの複数のアカウント | 登録 |
| 支払い | カードの発行国と請求先・IP の国の違い、失敗した試みの数、プリペイドのカード、決済の代行の事業者の不正の点数 | 支払い手段の登録 |
| 振る舞い | 登録から最初のデプロイまでの時間が極端に短い、保護する名前の使用、5.2 節の同じバンドル、印のあるバンドル | デプロイ |
| つながり | 停止したアカウントと、メール・端末・支払い手段・IP を共有する | 常に |

- 端末の印に、ブラウザの指紋（多数の属性の組み合わせ）は使わない。ファーストパーティの Cookie の ID と、IP・支払い手段のつながりに留める（個人の情報の扱いを小さくする）。
- S1 は規則の点数（重み付きの和と、単独で決まる規則）。機械学習のモデルは、ラベルのある事件がたまった S2 で検討する。

### 8.2 段と効果

| `risk_level` | 条件の例 | 効果 |
| --- | --- | --- |
| `blocked` | 停止したアカウントとの強いつながり（同じ支払い手段・同じ端末） | 登録を拒否する、または作った直後に `suspend_account` |
| `high` | 点数 0.8 以上 | 期間・計画によらず `c0-untrusted`。既定のサブドメインの公開は、支払い手段の確認（少額の与信）か人の確認の後。関数は 5 つまで。新しい版は毎回巡回する |
| `medium` | 点数 0.5〜0.8 | ADR-0011 の `c0-untrusted` の条件（30 日、確認）に加え、支払い手段の確認まで `c0-untrusted` に残す。新しい版は毎回巡回する |
| `low` | それ以外 | ADR-0011 のとおり |

- **点数は信頼を下げる方にだけ働く。** `low` でも、ADR-0011 の条件（作成から 30 日未満など）で `c0-untrusted` になる。
- 全てのアカウントで、既定のサブドメインの公開はメールの確認の後にする。
- 点数は、登録・支払い手段の登録・デプロイのたびと、毎日 1 回計算し直す。`risk_level` と理由を `account_risk` に残し、`account_state` の cordon の入力に `risk_level` を足す（優先の印。下げる変更はすぐ反映される）。
- 点数の理由は利用者に見せない（回避を学ばせない）。制限の中身（関数の数、公開の条件）は見せる。

### 8.3 ADR-0011 との関係

- ADR-0011 の `c0-untrusted` の定義は「無料で、作成から 30 日未満、または支払い手段・本人の確認がない」。この文書は、これに「`risk_level` が `high`・`medium`（計画によらない）」を足す。
- これは ADR-0011 の表の条件を広げる変更なので、ADR-0045 に記録した。統合の工程（2026-09-27）で、[ADR-0011](../decisions/0011-cordon-tiers-and-placement.md) の注記と [sandbox-and-security.md](sandbox-and-security.md) の 5.1 節の表に足した。
- 支払いに失敗した有料のアカウントは `c1-free` に下げる（`risk_level` が `high` なら `c0-untrusted`）。

## 9. 通報と削除の流れ

[ADR-0043](../decisions/0043-hosted-content-abuse-and-takedown.md)。

### 9.1 窓口

| 窓口 | 対象 | 認証 |
| --- | --- | --- |
| Web の通報の形 `https://abuse.<console-domain>/report` | 誰でも | なし（ボットの対策は CAPTCHA ではなく、送信の速さの制限と確認のメール） |
| メール `abuse@<console-domain>` | 誰でも | なし |
| 通報の API | 信頼できる通報者（JPCERT/CC、フィッシング対策協議会、ブランドの保護の事業者など） | 通報者ごとの API トークン。優先度を上げる |
| 法務の窓口 | 捜査機関、裁判所、弁護士 | 10 節 |

- 通報に求めるもの：種類、URL（または `<Brand>-Worker` の値、`<Brand>-Ray`、送信元の IP と時刻）、説明、証拠（任意）、連絡先。著作権・商標は、権利者であることと侵害の内容（法令の求める形は L1 の確認待ち）。

### 9.2 事件の状態

```
received ─▶ triaged ─┬─▶ auto_actioned ─────────────────────────────┐
                     ├─▶ under_review ─┬─▶ actioned ─────────────────┤
                     │                 ├─▶ no_violation ─────────────┤
                     │                 └─▶ forwarded（持ち主へ照会）─▶ actioned | no_violation
                     └─▶ duplicate ──────────────────────────────────┤
                                                                     ▼
                                                                   closed ─(異議)─▶ appeal_review ─▶ upheld | reversed ─▶ closed
```

- **仕分け**：URL のホストから、既定のサブドメイン・カスタムホスト名・公開のバケットを引き、アカウントと関数・バケットに結び付ける。同じ対象の開いた事件があれば、1 つにまとめる。
- **優先度**：P0 児童の性的な搾取の内容、P1 フィッシング・マルウェア・攻撃の中継、P2 著作権・商標、P3 その他。
- **自動の処理**：フィッシング・マルウェアは、通報の URL を即時に巡回し、5.4 節の判定を行う。
- **持ち主への照会**（`forwarded`）：著作権・名誉などの権利の侵害の申し出は、持ち主に照会し、7 日の返答の期間を置く（法令の手順と期間は L1 の確認待ち。値は既定案）。通報者の身元を持ち主に渡すかは、法務の方針に従う。
- **通報者への返事**：受け付け、結果（措置の有無）。持ち主の個人の情報は渡さない。
- **証拠**：巡回の記録、バンドルの SHA-256、事件の時点の版の ID、関係する監査ログを事件に結び付けて保存する（180 日。保全があれば延ばす）。

### 9.3 透明性

- 半年ごとに、種類ごとの通報の数、措置の数（段ごと）、異議の数と覆った数、捜査機関の照会の数を公開する（GA の後）。公開の中身は法務と決める。

## 10. 捜査機関の照会と法的な保全

**法務の確認待ち（L1・L4）。** 仕組みだけを決める。

- 照会は法務の窓口だけで受ける。Trust & Safety や サポートの担当は、照会に直接応じない。
- 受けたら `legal_requests` に記録する：依頼の元、根拠の文書、求める情報、期限、知らせないことの求めの有無、法務の判断。
- **応じるかどうかと、何を出すかは、法務が判断する。** 出す作業は、法務の承認の記録（2 人）を条件に、読み出しの道具で行い、監査ログに残す。自動で開示する仕組みは作らない。
- **保全**：法務は `legal_holds` を作れる。保全のあるアカウントは、`terminate` の削除、版の `purged`、バンドルの掃除（[deployment-and-config-distribution.md](deployment-and-config-distribution.md) の 7.4 節）、監査ログの 18 か月の削除を止める。保存するログ（ClickHouse の TTL）は行ごとに止められないので、保全の対象の期間のログを、S3 の Object Lock のバケットに書き出す。
- **利用者への知らせ**：既定は知らせる。法令・裁判所の命令で知らせてはならないときだけ知らせない（法務の判断）。利用者の監査ログへの載せ方も同じ（[dashboard-and-api.md](dashboard-and-api.md) の 7.3 節）。
- 生命・身体の危険の急ぎの依頼は、法務の当番を呼ぶ。
- 発信者の情報の開示の請求（プロバイダの責任を定める法律の上のもの。2025 年の改正後の名称と義務の範囲は未検証。intent の L1）への対応も、法務の手順に従う。

## 11. `<Brand>-Worker` と送り元の特定

[ADR-0044](../decisions/0044-egress-abuse-controls.md)。

- 外向きのプロキシは、インターネットへの全てのサブリクエストに `<Brand>-Worker: <worker>.<account>.<brand>.<domain>` を付ける（[edge-network-and-routing.md](edge-network-and-routing.md) の 10.3 節）。
  - 値は、そのサブリクエストを出したコードの関数の既定のホスト名。関数が既定のサブドメインを無効にしていても、カスタムドメインで呼ばれても、同じ値にする（関数と 1 対 1 で、通報からすぐ関数を引ける）。
  - cron・キュー・アラーム・Durable Objects から出たサブリクエストも、コードの持ち主の関数の値。
  - 利用者のコードが同じ名前のヘッダーを付けても、プロキシが上書きする。消せない。
  - 自分たちのホスト名への内部の経路（サービスのバインディングを含む）には付けない（外に出ないため）。
- 送信元の IP：ノードの公開の IPv4（NAT を通さない。[ADR-0049](../decisions/0049-aws-accounts-and-network.md)。ノードの入れ替えで変わる）。`(egress_ip, 時刻, 送信元のポート, <Brand>-Ray, account_id, script_id, 宛先)` を記録し、90 日持つ。`node_public_ips` と合わせて、IP と時刻からノードを引ける。通報の「IP と時刻」から関数を引くため。この記録は通信の構成要素を含むので、保持の期間と使い道は L2 の確認待ち。
- 公開の文書に、`<Brand>-Worker` の意味、受け手が止めたいときの方法（ヘッダーでの遮断）、通報の窓口を書く。

## 12. 障害の型

| 障害 | 検知 | 振る舞い |
| --- | --- | --- |
| 自動の措置の誤り（正当な関数を止めた） | 異議、急な異議の増加 | 戻す（1 回の操作、p99 10 秒）。規則の見直し。同じ規則の誤りが 1 日 3 件を超えたら、その規則の自動の措置を止め、人の確認に落とす |
| 分類・巡回の停止 | 行列の詰まり | 自動の措置が止まる。通報は人の確認に回る。4 時間で当番 |
| 外部の一覧が既定のドメイン全体を載せた | 合成監視（主なブラウザの警告の検査） | runbook `default-domain-blocklisted`：一覧の運営者への連絡、原因の関数の停止の確認 |
| 停止の配信の遅れ | 伝搬の SLI | [deployment-and-config-distribution.md](deployment-and-config-distribution.md) の runbook |
| 通報の洪水（嫌がらせの大量の通報） | 通報の速さ | 送り元ごとの速さの制限。同じ対象の通報はまとめる。自動の措置は通報の数ではなく判定で決める |
| 外向きの制限で正当な利用が止まる | 利用者の問い合わせ、制限に当たった数の分布 | 個別の上書き（`account_egress/`）。閾値の見直し |

## 13. セキュリティとプライバシー

| 脅威・懸念 | 対策 |
| --- | --- |
| 巡回の道具からの内部への到達 | 巡回は別の AWS アカウント、エッジの入口を通して要求し、内部の網に届かない。Chromium は毎回捨てる |
| Trust & Safety の道具の内部の乱用 | 役割ごとの権限。`suspend_account` は 1 人、`terminate` と法的な開示は 2 人。全ての操作を監査ログに残し、月ごとに見直す |
| 判定の規則の漏れ（回避の学習） | 規則は非公開の場所。点数の理由を利用者に見せない |
| 担当者の心の負担（児童の性的な搾取の内容） | S1 は通報に基づく確認だけで、画像はぼかして見せる。能動のハッシュの照合は、照合の一覧の入手と法務の確認の後に S2 で検討する |
| 通信の秘密（L2） | 要求・応答の本文を判定に使わない。宛先・件数の集計を使うこと、送信元の IP の記録の保持は、利用規約での同意の形と合わせて法務の確認待ち |
| 個人の情報（リスクの点数） | 印（IP、端末の ID、支払いの国）は 1 年で消す。目的をプライバシーの方針に書く（法務の確認待ち） |
| 誤った停止による利用者の損害 | 段を分ける、自動は確度の高いものだけ、異議を 2 営業日、戻すのは 1 回の操作 |

- 措置の配信（`script_state/`・`account_state/`・`account_egress/`）、外向きの方針の強制、`<Brand>-Worker` の付与の変更は `security:sensitive` にする（[AGENTS.md](../../AGENTS.md)）。

## 14. テスト

| 種類 | 対象 | 確かめること |
| --- | --- | --- |
| 表駆動 | 措置の段 | 各段で、入口のプロキシの応答（警告の頁・1203・403）、cron・キューの停止、ストレージの操作の拒否、管理 API の読み込みだけ |
| 表駆動 | リスクの点数 | 各規則の印の組み合わせで、期待の `risk_level` になる |
| 性質ベース | 信頼は下げる方だけ | 任意の印の列で、`risk_level` と検知が、ADR-0011 の条件で決まる cordon より高い信頼の cordon を作らない |
| 性質ベース | 戻せること | 任意の措置の列と戻す操作の列で、全て戻した後の状態が、措置の前と同じ |
| 結合 | 停止の配信 | `block_script` から 10 秒以内に全リージョンで 1203 |
| 結合 | `<Brand>-Worker` | 利用者が付けた同じ名前のヘッダーが上書きされる。cron・Durable Objects からのサブリクエストにも付く。内部の経路には付かない |
| 結合 | 外向きの方針 | 各 cordon の値ちょうどで通り、超えると `fetch` が失敗し、数が記録される |
| 結合 | 通報 | 通報から対象の関数を引き、同じ対象の通報がまとまり、巡回が走る |
| 判定の評価 | 分類 | 既知の良い頁・悪い頁の集まりで、自動の措置の閾値の誤検知の率が目標以下（E12、判定の規則の変更ごと） |
| 訓練 | 法的な保全 | 保全のあるアカウントで、削除・掃除・TTL の書き出しが止まる（四半期） |

テスト名には要件 ID（開発リポジトリの `REQ-ABUSE-*`・`PROP-ABUSE-*`）を含める。

## 17. 未解決の問い

- 削除の義務と手順、発信者の情報の開示、持ち主への照会の期間（L1）。
- 宛先・件数の集計と、送信元の IP の記録の保持が、通信の秘密の上で許されるか。利用規約での同意の形（L2）。
- AUP で禁じる用途（採掘、汎用のプロキシ・VPN、スクレイピングの中継）の線引きと、捜査機関の照会への対応の方針（L4）。
- 外向きの方針のポートを、edge-network-and-routing の既定より cordon ごとに狭めてよいか。
- 警告の頁に「理解して進む」を置くか（本家の振る舞いは未検証）。
- 児童の性的な搾取の内容の能動のハッシュの照合を、いつ、どの一覧で行うか。
- Google の Web Risk など外部の一覧の商用の利用の条件と費用。
- 巡回を見分けて内容を変える手口への対策。

### 決定

2026-09-27 の既定案。

- L1・L2・L4 の確認まで、該当の spec（E4 の既定のサブドメインの公開、E8 の公開のバケット、E6 の tail とログ、E12 の GA）は承認しない。設計は、法務の結論に合わせて値（期間、保持、禁止の範囲）だけを変えられる形にしておく。
- ポートは、無料の cordon を 80・443（c1 は 8080・8443 も）に狭める。edge-network-and-routing の持ち主に、10.3 節の既定の更新を依頼する。
- 警告の頁は、疑いの段（人の確認の前）だけ「理解して進む」を置く。確認の後は止める。
- 能動のハッシュの照合は S2。S1 は通報に基づく確認。
- 外部の一覧は、E12 の前に商用の条件を確かめ、使えるものから取り込む。
- 巡回の見分けは、S1 は通報と外部の一覧で補う。S2 で、巡回の送り元を増やす（別のリージョン、別の AS）かを検討する。
- ADR-0011 の `c0-untrusted` の条件に `risk_level` を足すことは、統合の工程で ADR-0011 の注記と sandbox-and-security の 5.1 節に反映した。点数は信頼を下げる方にだけ働くので、ADR-0011 の約束（異なる cordon を混ぜない、下げる変更はすぐ反映）は破らない。

## 18. quality.md・runbooks・data-model に載せるもの

**quality.md**

- リスク：正当な利用者の誤った停止。自動の措置の誤りの率（異議で覆った割合、月 0.5% 未満）、異議の処理の時間（2 営業日）。
- リスク：既定のドメイン全体が外部の一覧で止められる。PSL への掲載、合成監視、runbook。
- リスク：措置の配信の遅れ。停止から全リージョンの 1203 までの時間（p99 10 秒）。
- リスク：法令の手順の不備。L1・L2・L4 の確認を spec の承認の条件にする。
- 本番での検証：フィッシング・マルウェアの通報から措置までの中央値と p90、行列の滞留、外向きの制限に当たった正当な利用の数（問い合わせ）。

**runbooks**

- `phishing-report-surge`：同じ雛形の大量のフィッシング。同じバンドルの一括の措置と、印の規則の追加。
- `default-domain-blocklisted`：既定のドメイン全体の遮断。一覧の運営者への連絡と、原因の特定。
- `abuse-false-positive`：誤った停止の戻しと、規則の自動の措置の停止。
- `csam-report`：児童の性的な搾取の内容の通報。停止、保全、法務への連絡（手順は法務の確認の後に確定）。
- `law-enforcement-request`：照会の受け付け、記録、保全、法務の判断の待ち（手順は法務の確認の後に確定）。
- `egress-attack-report`：`<Brand>-Worker` での攻撃の通報。関数の特定、外向きの方針の上書き、停止。
- `crypto-mining-detected`：採掘の確認、支払いの確認、停止。
- SLI の追加の依頼（Ops へ）：通報から措置までの時間（種類ごと）、行列の滞留と最古の年齢、自動の措置の数と覆った数、外向きの制限に当たった数（cordon ごと）、巡回の成功率。
