# ADR-0040: 料金は円で原価を下回らない値にし、転送を課金する。月末締めの後払いで適格請求書を出し、前払いのクレジットは S1 で売らない

詳細は [limits-and-billing.md](../architecture/limits-and-billing.md) の 6〜9 節。

## Context

intent は、料金を円で示し、無料の枠を持ち、要求数と CPU 時間で数える従量の課金を求める（MVP）。K8 は、最小の関数の 100 万要求あたりの基盤の費用を、その料金の 50% 以下にすることを求める。

本家（2026-09-27 に確認）：

- 有料は月 5 ドルに 1,000 万要求と 3,000 万 CPU ミリ秒を含み、超過は 100 万要求 0.30 ドル、100 万 CPU ミリ秒 0.02 ドル。ストレージは製品ごとの従量で、転送は無料（[Pricing](https://developers.cloudflare.com/workers/platform/pricing/)）。
- 予算の警告は知らせるだけで、止めない（[Budget alerts](https://developers.cloudflare.com/billing/manage/budget-alerts/)）。

この基盤の原価の違い：

- 外向きの転送に、EC2 の外向きの料金（東京 0.114 ドル/GB）と Global Accelerator の DT-Premium（アジア太平洋 0.010 ドル/GB）がかかる（[Global Accelerator pricing](https://aws.amazon.com/global-accelerator/pricing/)）。オブジェクトストレージの領域は、転送を課金すると決めている（[object-storage.md](../architecture/object-storage.md) の 10 節）。
- KV の書き込みの原価は、本家の料金を上回る（[kv-store.md](../architecture/kv-store.md) の 13 節）。

日本の法令：適格請求書は 6 つの記載事項を持ち、端数の処理は 1 つの請求書で税率ごとに 1 回（[国税庁](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/invoice_about.htm)、[Q&A 問 57](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/57.pdf)）。前払いのクレジットを売ると、資金決済法の前払式支払手段に当たりうる（自家型は基準日の未使用残高 1,000 万円超で届出。[関東財務局](https://lfb.mof.go.jp/kantou/kinyuu/pagekthp00400036.html)）。扱いは法務の確認待ち（[intent.md](../intent.md) の L5）。

## Options

1. **円の単価を原価の 1.3 倍以上で決め、転送を課金する。月末締めの後払い。前払いのクレジットは売らない。予算の警告に加え、任意の費用の上限（既定は切る）**
2. 本家の単価を為替で換算して同じ構造・同じ値にする（転送は無料）
3. 前払いのクレジットを売り、残高から引く

## Decision

1 を採用する。

- 有料の計画は月 800 円（税抜）に、1,000 万要求、3,000 万 CPU ミリ秒、10GB の外向きの転送、2,000 万件のログを含む。超過は 100 万要求 50 円、100 万 CPU ミリ秒 3 円、1GB 25 円など（値は既定案。原価の実測と PM の承認で確定）。
- 各行の単価は、その行の原価の 1.3 倍以上にする。本家の値に合わせることを目標にしない。単価は効力の開始日を持つ版で持ち、値上げは 30 日前に知らせる。
- 請求は JST の月末締め、翌月 3 日までに確定。適格請求書の記載事項を持つ PDF と JSON。消費税は 1 つの請求書で 1 回だけ切り捨て。
- 前払いのクレジットは S1 で売らない。販促のクレジット（無償、12 か月）は値引きとして扱い、台帳で持つ（前払いの販売に移れる形）。
- 予算の警告は知らせるだけ。費用の上限は任意で、達したら関数とバインディングの操作を止める（保存は消さない）。既定は切る。
- L5（海外の利用者の消費税）の確認までは、請求先が日本のアカウントだけに有料の計画を売る。
- 2 を採らない理由：転送と KV の書き込みで原価割れになり、K8 を満たせない。為替で毎月の請求が揺れる。
- 3 を採らない理由：前払式支払手段の届出・発行保証金・払い戻しの制限の検討が要る。後払いで足りる。

## Consequences

- 良くなること：
  - 原価割れの行がない。転送の多い使い方も採算が合う。
  - 資金決済法の論点を S1 で避けられる。
  - 利用者が、止めてでも費用を抑える選択を持てる。
- 引き受けるコスト：
  - 「転送は無料」の本家と比べて、転送の多い利用者には高く見える。価値は日本での近さと統合で示す。
  - 後払いは未回収の危険を持つ（未払いの流れと、新しい有料のアカウントの一時の上限で抑える）。
  - 費用の上限で利用者のサービスが止まる事故がありうる（既定は切り、画面で明示する）。

## Confirmation

- 性質ベーステスト：任意の使用量の列で、行の金額が単価×超過量の合計の切り捨てと等しく、消費税が 1 回だけの切り捨て。
- 表駆動テスト：請求書に適格請求書の 6 つの記載事項がそろう。
- 月ごとの確認：各行の請求の合計と原価（AWS の請求の按分）の比が 1.3 以上。下回った行は単価の見直しを PM に諮る。

## 注記（2026-09-27、統合の工程）

上の既定案の単価のうち、次の行は「原価の 1.3 倍以上」の規則を満たしていなかったので、既定案を改めた。値の確定は PM の確認事項のまま（[limits-and-billing.md](../architecture/limits-and-billing.md) の 6.3 節）。

- **CPU 時間**：100 万 ms あたり 3 円 → **7 円**。c7i.24xlarge（東京 5.3928 ドル/時、96 vCPU）の 1 vCPU-ms の原価は、利用率 100% で 5.3928 ÷ 96 ÷ 3,600,000 ≒ 1.56×10⁻⁸ ドル、100 万 vCPU-ms で約 0.0156 ドル（約 2.34 円。1 ドル 150 円）。設計点の利用率 50%（[ADR-0054](0054-capacity-design-point-and-region-sizing.md)）で約 4.68 円、その 1.3 倍は約 6.09 円で、切り上げて 7 円にする。S1 の東京の平常の利用率（約 23%）では原価が約 10.2 円で、7 円でも下回る。S1 の利用率の低さは国内の DR の台数による（K8 と同じく S2 の利用率で測る）。
- **S1 の CPU の行の原価割れ**（2026-09-27 の追記）：S1 の間、CPU 時間の行は上の「月ごとの確認」の比 1.3 を満たさない（利用率 23% で 100 万 ms あたり約 3.2 円の赤字）。これは受け入れ、月額（含む CPU の原価 約 306 円を払っても約 494 円が残る）と外向きの転送の差益（1GB あたり 6.4 円）で回収する。回収できない形（応答 1KB あたり CPU 約 2ms を超える関数）と式は [limits-and-billing.md](../architecture/limits-and-billing.md) の 6.5 節。確定は PM（[intent.md](../intent.md) の P3）。
- **KV の書き込み・削除・一覧**：100 万あたり 1,100 円 → **1,120 円**（原価 約 5.7 ドル ≒ 855 円の 1.3 倍は約 1,112 円。本家の 5.00 ドルより高い）。
- **KV の保存**：1GB-月あたり 110 円 → **115 円**（原価 約 86 円の 1.3 倍は約 112 円）。
- 月額 800 円（税抜）は変えない。
- 関数の応答（利用者への転送）も外向きの転送の行（1GB 25 円）で課金する。本家は課金しない。
