# ADR-0027: 公開の配信はカスタムドメインと別の登録可能なドメインの開発用の URL で行い、署名付きの URL は S3 互換の口だけで受ける

詳細は [object-storage.md](../architecture/object-storage.md) の 7 節。

## Context

オブジェクトストレージの主な用途に、画像・静的なファイルの公開の配信と、ブラウザからの直接のアップロード・ダウンロードがある。

本家（2026-09-27 に確認）：

- 公開は、同じアカウントのカスタムドメイン（キャッシュ、WAF、アクセスの制御を使える）と、開発用の `r2.dev`（速さの制限つき、本番に使わない）の 2 つ。根の一覧は出さない（[Public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/)）。
- カスタムドメインでキャッシュを有効にすると、上書き・削除がキャッシュの期間だけ見えない。404 も既定でキャッシュする（[R2 consistency](https://developers.cloudflare.com/r2/reference/consistency/)）。
- 署名付きの URL は SigV4、1 秒〜7 日、GET・HEAD・PUT・DELETE。S3 の API の口だけで使え、カスタムドメインでは使えない（[Presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)）。

この題材は、CDN としてのキャッシュを MVP の範囲の外にし、キャッシュを公開の配信の範囲に限る（intent）。利用者が置いた HTML・スクリプトを、自分たちのドメインや他の利用者と同じサイトから配ると、クッキーや同じ出どころの権限を通じた攻撃に使われる。

## Options

1. **カスタムドメイン（キャッシュは選べる、既定は無効）と、別の登録可能なドメインの開発用の URL（既定は無効）。署名付きの URL は S3 の API の口だけ**
2. **1 に加え、署名付きの URL をカスタムドメインでも受ける**
3. **開発用の URL を関数の既定のドメイン（`*.<brand>.<domain>`）の下に置く**

## Decision

1 を採用する。

- カスタムドメイン：同じアカウントで確認済みのドメインを付ける。GET・HEAD だけ。根の一覧は出さない。
  - キャッシュはドメインごとに選べ、既定は無効。有効にすると、入口のプロキシのリージョンのキャッシュに置く。`Cache-Control` に従い、ないときは 1 時間、404 は 60 秒。
  - 消去の API（URL、接頭辞、ドメインの全体）を、設定の配信の経路で p99 10 秒で届ける。
- 開発用の URL：`pub-<32 桁の 16 進>.<brand>usercontent.<domain>`。既定は無効。バケットあたり 1 秒に 100 要求（仮）の制限。キャッシュしない。`<brand>usercontent.<domain>` を Public Suffix List に登録する。
- 公開の応答には `X-Content-Type-Options: nosniff` を付ける。
- 署名付きの URL は、S3 の API の口（`<account_id>.storage.<brand>.<domain>`）だけで受ける。鍵を消すと、その鍵の URL はすべて無効になる。
- 2 を採らない理由：カスタムドメインの要求は、近いリージョンの入口のプロキシで受け、キャッシュを通る。署名の検証をキャッシュの前に置く必要があり、キャッシュの鍵と署名の組み合わせが複雑になる。本家も受けない。必要になったら、関数で検証して読む形を勧める。
- 3 を採らない理由：利用者の HTML が、関数の既定のドメインと同じ登録可能なドメインで配られ、クッキーの範囲やサイトの判定を共有する。

## Consequences

- 良くなること：
  - 公開の配信を、本家に近い使い方で提供できる。
  - 利用者の内容を、自分たちのドメインと他の利用者から切り離せる。
  - キャッシュの緩み（ADR-0005）は、利用者が選んだドメインにだけ起きる。
- 引き受けるコスト：
  - 開発用の URL のドメインの取得、Public Suffix List への登録の手続き。PSL は処理の時間を約束せず（「時間の SLA はない」）、登録ドメインの残りの期間 2 年以上を求める。利用者の側への反映は、各ソフトや OS の更新の周期に依る（[PSL Guidelines](https://github.com/publicsuffix/list/wiki/Guidelines)、2026-09-27 に確認）。E1 の `default-domain-and-psl` で早めに出す。
  - 公開の配信は、フィッシング・マルウェアの置き場に使われやすい。通報と削除の手順は abuse-and-trust-safety の領域で決め、法務の L1 の確認まで E8 の公開のバケットの spec は承認しない（intent）。
  - キャッシュの消去の配信の経路を、設定の配信と共有する。

## Confirmation

- 結合テスト：カスタムドメインで GET・HEAD だけが通る。根の一覧が出ない。キャッシュを有効にしたドメインで、消去の後 10 秒以内に新しい内容が返る。
- 結合テスト：署名付きの URL の期限の前後、別のアカウントのバケット、鍵の削除の後。
- 設定の検査：開発用の URL のドメインが Public Suffix List にあることを、公開の開始の前に確かめる。
