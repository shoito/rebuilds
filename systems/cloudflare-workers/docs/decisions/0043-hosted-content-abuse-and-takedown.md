# ADR-0043: ホストした内容の不正は複数の起点で見つけ、段にした措置で止め、通報は 1 つの事件の流れで扱う

詳細は [abuse-and-trust-safety.md](../architecture/abuse-and-trust-safety.md) の 5・6・9・10 節。

## Context

無料の枠と既定のサブドメイン（`<worker>.<account>.<brand>.<domain>`）は、フィッシング・マルウェアの配布に使われやすい（[architecture/README.md](../architecture/README.md) の 6 節）。この基盤は、利用者の関数とオブジェクトをホストしている。

本家（2026-09-27 に確認）：

- ホスティング（Pages・Workers）では、違反の内容を削除・遮断し、運営者に知らせる（[Abuse approach](https://www.cloudflare.com/trust-hub/abuse-approach/)）。
- フィッシングの通報の処理を自動化し、2024 年の後半に 78% を自動で処理し、対処まで中央値 1 時間未満にした。URL の走査、機械学習の分類、脅威の情報、過去の判断の規則を使う（[How Cloudflare is using automation to tackle phishing](https://blog.cloudflare.com/how-cloudflare-is-using-automation-to-tackle-phishing/)）。

制約：

- 停止はノードの手元の印だけで効かせる（[ADR-0004](0004-config-and-code-distribution.md)）。
- 削除の義務と手順、発信者の情報の開示、捜査機関の照会は法務の確認待ち（[intent.md](../intent.md) の L1・L4）。

## Options

1. **静的な検査・巡回・外部の一覧・通報の 4 つの起点、点数と cordon で自動と人の確認を分け、`flag`・`interstitial`・`block_script`・`suspend_account`・`terminate` の段で止める**
2. 通報だけを起点に、人がすべて判断する
3. 確度によらず、疑いのある関数をすぐ止める

## Decision

1 を採用する。

- 起点：版の `ready`（既定のサブドメインが有効）と公開のバケットへの書き込みでの非同期の静的な検査、ヘッドレスの Chromium の巡回（別の AWS アカウント）、外部の一覧の 15 分ごとの取り込み、通報。関係のないアカウントの間の同じバンドルを印にする。
- 判定：規則と分類のモデルで 0〜1 の点数と理由を出す。0.95 以上かつ `c0-untrusted`・`c1-free` のアカウントは自動で措置する。0.70〜0.95、または有料のアカウントは人が見る。
- 措置の段：`interstitial`（既定のドメインだけ、疑いの段は「理解して進む」あり）、`block_script`（1203）、`suspend_account`（人 1 人）、`terminate`（人 2 人）。`interstitial` 以上でアカウントの信頼を下げ、cordon を `c0-untrusted` にする。印は優先の印で配る（p99 10 秒）。
- 措置は持ち主に知らせ、異議を最初と別の担当が 2 営業日で見る。戻すのは 1 回の操作。知らせないのは、児童の性的な搾取の内容と、法令・命令で求められたときだけ（法務の判断）。
- 通報は Web・メール・信頼できる通報者の API で受け、対象で 1 つの事件にまとめ、`received` から `closed` までの状態で扱う。権利の侵害の申し出は、持ち主への照会（既定 7 日。L1 の確認で直す）を挟む。
- `c0-untrusted` のアカウントは、保護する名前（金融・通信・物流・行政など）を含む関数・サブドメインの名前を作れない。
- 捜査機関の照会は法務の窓口だけで受け、開示は法務の承認（2 人）の後に手作業で行う。保全は `legal_holds` で削除・掃除を止め、ログは Object Lock のバケットへ書き出す。
- 2 を採らない理由：本家の自動化の前の中央値 3.4 日では、フィッシングの被害の大半が起きた後になる。
- 3 を採らない理由：正当な利用者の誤った停止が増え、有料の利用者の信頼を失う。確度と cordon で自動の範囲を絞る。

## Consequences

- 良くなること：
  - 確度の高いフィッシング・マルウェアを、人を待たずに止められる。
  - 新しい無料のアカウントに自動の措置を集め、有料の利用者の誤った停止を減らす。
  - 法務の結論（期間、知らせ方）が変わっても、値を変えるだけで合わせられる。
- 引き受けるコスト：
  - 巡回・分類・事件の道具を自前で持つ。
  - 巡回を見分けて内容を変える手口は防げない。通報と外部の一覧で補う。
  - 担当者の体制（異議の 2 営業日、P0 の 1 時間）が要る。

## Confirmation

- 表駆動テスト：各段の効果（警告の頁、1203、cron・キューの停止、ストレージの拒否、管理 API の読み込みだけ）。
- 性質ベーステスト：任意の措置と戻しの列で、全て戻した後の状態が措置の前と同じ。
- 判定の評価：既知の良い頁・悪い頁の集まりで、自動の措置の閾値の誤検知の率が目標以下（規則の変更ごと）。
- 本番の指標：通報から措置までの中央値 1 時間、自動の措置の覆った割合 月 0.5% 未満。
