# AGENTS.md — Cloudflare Workers

- [docs/architecture/](docs/architecture/README.md) — 全体像、規模の段階、非機能要件、領域ごとの設計
- [docs/decisions/](docs/decisions/README.md) — ADR。特に 0001（ランタイム）、0002（隔離）、0004（設定とコードの配信）、0005（ストレージの一貫性）

## この題材に固有の規則（開発リポジトリで守る）

- **利用者のコードは、常に悪意があるものとして扱う。** isolate の中から届くもの（API の引数、バインディングへの要求、Wasm のモジュール、ログの本文）を、境界の外側で必ず検証する。isolate の境界だけに頼る設計をしない（ADR-0002）。
- **隔離に触れる変更には、サンドボックスの脱出のテストを付ける。** ランタイム、サンドボックス（seccomp・名前空間）、cordon、バインディング、タイマー、Wasm の設定に触れる PR は、脱出のテストの集まりを通す。次のどれかが観測できたら失敗にする（ADR-0002）。
  - ファイルシステムへのアクセス、許可していない宛先への通信、ほかの isolate・ほかのテナントのデータへの到達
  - 実行中に進む時計（`Date.now()`・`performance.now()`）、`SharedArrayBuffer`、スレッド、ネイティブのコードの読み込み
  - 修正済みの V8 の脆弱性の再現コード（回帰用。隔離した CI の環境でだけ動かす）
- **ファズを止めない。** バインディング（C++ と JavaScript の境界）、ワーカーの設定とバンドルの解析、エッジの入口の HTTP の解析、設定の配信の形式は、ファズの対象として登録する。JavaScript エンジンには Fuzzilli などの文法を知るファザーを、自分たちがビルドした V8 に対して回し続ける。ファズで見つかった落ち方は、回帰テストにしてから直す。
- **V8 のセキュリティの修正は 24 時間以内に全ノードへ届ける。** 上流の Critical・High の修正の公開から、全エッジのノードで修正済みの版が動くまでを 24 時間以内にする（NFR-007。本家の公開の目標と同じ）。この経路（取り込み、ビルド、テスト、段階的な配信）を、通常のリリースと別の、常に動く状態に保つ。経路を壊す変更は、V8 の修正の訓練（runbooks）を通してからマージする（ADR-0001）。
- **workerd の上流との差分を最小に保つ。** 上流に送れる修正は上流に送る。自分たちの差分は、パッチの一覧に理由とともに記録し、上流の版の更新のたびに当て直せることを CI で確かめる（ADR-0001）。
- **エッジのノードで、制御プレーンに同期で依存しない。** リクエストの処理の経路から、制御プレーン（API、Aurora）を呼ばない。ノードは、手元の設定の写しだけで処理を続けられるようにする（ADR-0004）。
- **ストレージの一貫性の約束を、製品ごとに守る。** KV は結果整合、オブジェクトストレージはホームのリージョンでの強い整合、Durable Objects は 1 つの実体と書き込みの確定の後の出力。性能のためにこの約束を弱める変更は、ADR-0005 を更新してからにする。
- **テナントテーブルには `account_id` と RLS を付ける。** 制御プレーンの DB は、他の題材と同じく共有スキーマと RLS で分ける（ADR-0001）。
- **本家の名前を識別子に使わない。** ドメイン（`*.<brand>.<domain>`）、ヘッダー（`<Brand>-*`）、CLI の名前（`<brand>`）、設定ファイルの名前、ランタイムの API の名前空間（`request.<brand>` など）、キーの接頭辞は `<Brand>`・`<brand>` で書く（[リポジトリ共通の ADR-0006](../../docs/decisions/0006-brand-neutral-identifiers.md)）。
- **セキュリティに関わる変更は、追加のレビューを受ける。** ランタイム、サンドボックス、cordon、V8 の更新、エッジの TLS と証明書、シークレット、テナントの分離に触れる PR には `security:sensitive` のラベルを付ける。Dev のテックリードに加え、セキュリティの担当の承認を必須にする。エージェントは承認しない。

## このリポジトリでの規則

- ADR を追加・更新したら、`docs/decisions/README.md` の一覧を生成し直す。
- 領域の文書で ADR を起票するときは、[architecture/README.md](docs/architecture/README.md) の 7 節で領域に割り当てた番号の範囲の中で採番する。
- 本家の振る舞い・数値を書くときは、出典と確認日を付ける。確かめられないものは「未検証」と書く。
