# Runbooks: Uber

Ops が持つ運用の文書。これから書く。SLO の元になる非機能要件は [architecture/](../architecture/README.md) の 3 節にある。個別の手順は [templates/runbook.md](../../../../docs/templates/runbook.md) から作る。

書く予定の主な内容：

- SLI と SLO（都市ごとの配車の可用性、配車の判断の速さ、位置の鮮度、二重の割り当ての検査、緊急の通報の受け付け）
- リリースとロールバック（配車の変更の影の実行と、都市単位のフラグでの展開）
- アラートと手順（索引の持ち主の切り替え、位置の取り込みの遅れ、配車の成立率の低下、PSP の障害、緊急の通報の滞留）
- 定期作業と訓練（大阪への切り替え、索引の再構築、運賃の規則の更新）
