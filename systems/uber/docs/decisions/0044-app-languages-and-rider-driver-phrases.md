# ADR-0044: アプリの言語と、乗客とドライバーの言葉の壁の越え方

詳細は [rider-and-driver-apps.md](../architecture/rider-and-driver-apps.md) の 3.4 節。

## Context

- 日本の配車では、訪日の旅行者の乗客と、日本語だけを話すドライバーの組が多いと見込む（数は**未検証**。提携先の事業者の実績で確かめる）。言葉が通じないと、乗車地での合流、行き先の確かめ、荷物の扱いで遅れと取り違えが起きる。
- 本システムには、乗客のアプリの言語、乗客とドライバーのメッセージの訳、住所の検索の言語の決まりがない。メッセージは定型文と 200 文字までの自由な文で、走行中のドライバーは定型文だけを送れる（[safety-and-trust.md](../architecture/safety-and-trust.md) の 6.2 節、[rider-and-driver-apps.md](../architecture/rider-and-driver-apps.md) の 3.2 節）。
- メッセージの本文を外の翻訳の提供者に送ると、乗車の中のやり取りを外の提供者（国外のことがある）に渡すことになる。個人情報保護法の外国にある第三者への提供は法務の確認待ち（[intent.md](../intent.md) の L4）。
- 訪日の旅行者を MVP の対象にするか、どの言語を持つかは PM が決める（[intent.md](../intent.md) の Open questions）。この ADR は、どの結論にも合う仕組みの形を決める。

## Options

1. **UI の言語を切り替えられる形にし、乗客とドライバーのやり取りは、人が訳した定型文の対訳で行う。** 定型文は ID と引数で送り、受け手のアプリが自分の言語で出す。自由な文は訳さずに原文のまま出す。外の翻訳の提供者を使わない。
2. **1 に加えて、自由な文を機械翻訳する。** 自前の API の後ろに翻訳の提供者を置き、受け手の言語に訳した文と原文の両方を出す。`legal.l4.chat_translation` の裏に置く（[ADR-0043](0043-flag-taxonomy-legal-gates-and-safety-defaults.md)）。
3. **日本語だけにする。** 訪日の旅行者は対象の外とする。

## Decision

1 を採用する（推奨）。2 は、L4 の結論と、1 の運用で自由な文の量と内容を見てから、別の ADR で決める。3 は、PM が訪日の旅行者を MVP の外とした場合も採らない（UI の文言を後から切り替えられる形にする費用は小さく、後から入れる費用は大きい）。

- **UI の言語**：乗客のアプリは OS の言語に従う。MVP の言語は PM が決める（既定の案は日本語と英語。中国語の簡体・繁体、韓国語などを足すかも PM）。日本語だけと決まった場合も、文言を切り替えられる形で作る。ドライバーのアプリは日本語（英語は持てる形にするだけ）。文言は Swift の String Catalog と Android のリソースで持ち、件数・語順の違う文を連結で作らない。
- **言語の印**：乗客は依頼のときに `rider_locale`（BCP 47）を送る。ドライバーのアプリは、受諾の後の迎車の画面にだけ「乗客の言語：英語」を出す。オファーには出さない（受諾の判断に使わせない。降車地を受諾の後に出すのと同じ扱い。[dispatch-and-matching.md](../architecture/dispatch-and-matching.md) の 8.4 節）。
- **定型文の対訳**：`phrase_catalog`（ID、乗客向けか・ドライバー向けか、言語ごとの文、引数の型、バージョン）を持つ。メッセージは `{template_id, args, catalog_version}` で送り、受け手のアプリが自分の言語で組み立てる。引数は時間（分）・車両の色と番号・場所の種類など、型の決まった値だけにし、自由な文を引数にしない。各言語の文は、その言語を母語とする人が確かめる。
- **自由な文**：訳さず、原文と「翻訳されていません」の印を出す。OS の翻訳の機能（端末の中で動くもの）を使うかは利用者に任せ、本システムは本文を外に送らない。
- **行き先を見せる画面**：乗客のアプリに、行き先の名前と住所を日本語で大きく出す画面（「ドライバーに見せる」）を持つ。日本語の名前は住所の検索の結果から取る。
- **住所の検索**：乗客は自分の言語で検索できる。`places-service` は乗客の言語を提供者に渡し、結果に日本語の表示名も持たせる。ドライバーには常に日本語の名前と住所を出す。英語・ローマ字での的中の率を、住所の検索の PoC の基準に足す（[ADR-0034](0034-geocoding-provider-and-pickup-points.md) の PoC の必須の基準ではなく、参考の基準として）。

## Consequences

- 良くなること：
  - 外の提供者に乗車の中のやり取りを送らずに、合流と行き先の確かめの多くを言葉なしで済ませられる。
  - 走行中のドライバーは定型文だけなので、ドライバーの側の送信はすべて訳せる。
  - L4 の結論の前に作り始められる。
- 引き受けるコスト：
  - 定型文の対訳の作成と確かめ（言語 × 約 60 文）、カタログのバージョンの管理。古いアプリが新しい ID を受けたときの代わりの文（「メッセージがあります。アプリを更新してください」）が要る。
  - 乗客の自由な文はドライバーに訳されずに届く。ドライバーが読めないことがある。
  - 乗客の言語の印を受諾の後に見せるので、ドライバーの取り消しの偏りが起きうる。監視と運用の対応が要る。

## Confirmation

- 定型文のベクター：すべての `template_id` が、持つすべての言語で引数を埋めて組み立てられ、未訳の文がないことを CI で確かめる（両方のアプリで同じベクターを読む。[ADR-0006](0006-native-apps-contracts-vectors-and-release-train.md) と同じ形）。
- UI の試験：英語の設定で、依頼から評価までの画面に未訳の文言がないこと。長い英語の文言の折り返し（[rider-and-driver-apps.md](../architecture/rider-and-driver-apps.md) の 11.4 節）。
- メッセージの経路の結合テスト：自由な文の本文が、本システムの外の宛先（翻訳の提供者を含む）に送られないこと。
- オファーの事象の契約の試験：オファーの本文に `rider_locale` が入らないこと。
- 月次：`rider_locale` ごとの、受諾の後のドライバーの取り消しの率の差を運用が見る。
