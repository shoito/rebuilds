# ADR-0025: 複式簿記の台帳で事業者ごとの預り金を持ち、月 2 回の締めで精算し、台帳・PSP の精算・銀行の明細を 3 者で照合する

詳細は [payments-and-payouts.md](../architecture/payments-and-payouts.md) の 8・11・12 節。

## Context

乗客から受け取った運賃は、手数料を引いて事業者に払う。事業者への精算の合計は、乗客から受け取った額と手数料の合計と一致しなければならない（[intent.md](../intent.md)）。返金、運賃の訂正、キャンセル料、追加の請求の失敗、車内で払った乗車の手数料が、同じ事業者の精算に混ざる。

Stripe の題材は、同じ問題を複式簿記の台帳（[ADR-0003](../../../stripe/docs/decisions/0003-double-entry-ledger.md)）、勘定体系（[ADR-0015](../../../stripe/docs/decisions/0015-chart-of-accounts-and-balance-transactions.md)）、3 者照合と仮勘定（[ADR-0017](../../../stripe/docs/decisions/0017-three-way-reconciliation-with-suspense.md)）、銀行経由の払い出し（[ADR-0018](../../../stripe/docs/decisions/0018-payout-execution-via-banking-partner.md)）で解いている。

## Options

### 記録

1. **複式簿記の台帳（仕訳は合計 0、追記のみ、冪等キー）**
2. **乗車ごとの精算の表（運賃・手数料・返金の列）を足し上げる**

### 精算の周期

1. **月 2 回の締め（既定）、契約で週 1 回・月 1 回に変えられる**
2. **乗車ごとに即時**
3. **月 1 回だけ**

## Decision

記録は 1、周期は 1 を採用する。照合は Stripe の題材と同じ 3 者照合にする。

- 口座は、`psp_receivable`、`bank_cash`、`payouts_in_transit`、`rider_receivable`、`operator_payable:{operator_id}`（事業者の預り金。借方に振れてよい）、`fee_revenue`、`consumption_tax_payable`、`promotion_expense`、`processing_cost`、`bad_debt_expense`、`suspense`。
- お金が動く操作（確定・手数料・返金・訂正・振込）は、状態の更新と同じトランザクションで仕訳を書く。仕訳は合計 0 をコミットの時に確かめ、追記のみにする。
- 追加の請求の成否に関わらず、事業者には確定した運賃の全額を精算する。回収できなかった分は `rider_receivable` から `bad_debt_expense` に償却する。
- 精算は、締めの時点の預り金の残高を払う。借方なら繰り越し、2 回続けば請求書を出す。締めの翌営業日に明細と手数料の適格請求書を確定し、締めから 5 営業日目に振り込む。
- 照合は、精算の照合（台帳 × PSP の精算のファイル）、着金の照合（PSP のバッチ × 銀行の入金）、振込の照合（振込 × 銀行の出金）の 3 つ。期限は T+2 営業日。説明のつかないお金は仮勘定に置き、預り金を動かす解消は 2 人の承認を要する。
- 事業者の日報との乗車ごとの照合は、明細に乗車の ID とメーターの記録の番号を載せ、事業者の申し出で行う。
- 記録の 2 を採らない理由：返金や訂正が締めをまたぐと、どの締めでいくら払ったかを後から説明しにくい。PSP と銀行との照合の相手になる口座がない。
- 周期の 2 を採らない理由：振込の手数料が乗車の数に比例し、返金を相殺できない。
- 周期の 3 を採らない理由：事業者の資金繰りへの影響が大きい。

## Consequences

- 良くなること：
  - 事業者ごとの預り金の残高が、いつでも仕訳の合計として説明できる。
  - Stripe の題材の台帳・照合の実装と手順を使い回せる。
- 引き受けるコスト：
  - 締め、明細、振込、照合のブレイクを扱う運用の担当と画面が要る。
  - 回収の損失をこの基盤が負う。損失の率を監視し、事業者との契約で見直す。

## Confirmation

- 性質ベーステスト：PROP-PAY-003（台帳の釣り合い）、PROP-PAY-004（事業者の精算の一致）、PROP-PAY-005（照合の冪等）。
- DB：合計が 0 でない仕訳のコミットが失敗する。`ledger_postings` の更新と削除が権限とトリガーで失敗する。
- 本番の監視：T+2 営業日を過ぎたブレイクと、5 営業日続く仮勘定の残高のアラート。
