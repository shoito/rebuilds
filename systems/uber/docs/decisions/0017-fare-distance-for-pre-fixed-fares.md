# ADR-0017: 事前確定運賃の推計走行距離は、確認の済んだ商用の地図の提供者だけで求め、2 つ以上のルート・有料道路の選択・同じルートの提示を API で守る

## Context

事前確定運賃は、配車アプリ等に搭載された電子地図（一般的に流通しており、地図情報が定期的に更新される仕組みを持ったものに限る）を用いて、旅客が入力した乗車地点と降車地点との間の推計走行距離を基に算定した距離制運賃に、地方運輸局長等が定めた係数を乗じ、1 円単位を四捨五入して算定する。アプリには少なくとも次の機能が要る（[国土交通省 自動車局長 通達「一般乗用旅客自動車運送事業の事前確定運賃に関する認可申請の取扱いについて」](https://www.mlit.go.jp/jidosha/content/001617012.pdf)、平成 31 年 4 月 26 日、令和 5 年 6 月 27 日一部改正、2026-09-27 に確認）。

- 旅客が、最短距離ルートや最短時間ルートなど 2 以上の走行予定ルートから 1 つを選べ、選んだルートで推計走行距離を推計する。
- 旅客と運転者に同じ走行予定ルート（または主要経由地点）を示し、そのルートに基づいて運賃を算定・提示できる。
- 旅客が有料道路の利用の有無を選べる。
- 運転者は、原則として示したルート（主要経由地点）を逸脱しない。

[ADR-0005](0005-maps-and-routing.md) は、OSM がこの電子地図に当たるかが法務と運輸局の確認待ち（[intent.md](../intent.md) の L3）の間、商用の提供者の距離を使うと決めた。

商用の提供者の条件（2026-09-27 に確認）：Google Maps Platform では、Directions API・Distance Matrix API の内容を Google 以外の地図と一緒に使ってはならず、Directions API の緯度経度のキャッシュは 30 日まで（[Service Specific Terms](https://cloud.google.com/maps-platform/terms/maps-service-terms) の 4.2・4.3・5.2）。ゼンリンと Amazon Location Service の経路の結果の保存の条件は **未検証**。

## Options

1. **確認の済んだ商用の提供者だけで求める。障害のときは事前確定運賃を出さない**
2. **商用の提供者が答えないときは、Valhalla の距離で代える**
3. **Valhalla（OSM）だけで求める**

## Decision

1 を採用する。詳細は [eta-and-routing.md](../architecture/eta-and-routing.md) の 7 節。

- `FareDistance.Estimate(pickup, dropoff, toll, departure_time)` → `quote_id`、`options`（`SHORTEST_DISTANCE` と `FASTEST` を必ず含む）、`provider`、`provider_map_version`、有効の期限（既定 10 分）。距離は m の整数。
- 2 つのルートが得られなければ、事前確定運賃を出さない。
- `toll` は必須の引数にする。
- 乗客が選んだ `option_id` を乗車に保存し、ドライバーのアプリに同じ主要経由地点と表示用の線を渡す。外部のナビには主要経由地点を経由地として渡す（`rider-and-driver-apps.md` への申し送り）。
- 乗車の軌跡の当てはめで、選んだルートからの逸脱の距離を記録する。
- 提供者が答えない・遅い（1.5 秒）ときは、事前確定運賃を出さず、メーターの運賃の依頼だけを受ける。日本版ライドシェアの配車もその間は止まる（事前確定運賃が要るため）。
- 事前確定運賃の距離の型を、Valhalla の距離の型と分け、変換できないようにする。
- 保存：距離・時間・有料道路・提供者・地図の版・主要経由地点の名前は運賃の記録と同じ期間。表示用の線（緯度経度の列）は、提供者の条件の期間だけ。
- 2 を採らない理由：L3 の確認が済んでいない地図で運賃を決めることになる。2 つのエンジンの距離が食い違い、同じ乗車地・降車地で運賃が変わる。
- 3 を採らない理由：L3 の結論が出ていない。結論が「OSM でよい」なら、この ADR を置き換える。

## Consequences

- 良くなること：
  - 通達の要件が API の形と型で守られ、テストで確かめられる。
  - 運賃の根拠（提供者、地図の版、ルート）が記録に残る。
- 引き受けるコスト：
  - 提供者の障害が、事前確定運賃と日本版ライドシェアの停止に直結する。提供者の SLA を選定の基準にする。
  - 推計走行距離の 1 件ごとに提供者の料金がかかる。
  - 提供者の条件で、表示用の線を長く持てないことがある。運賃の根拠として距離と経由地点の名前を長く保存してよいかは、法務の確認待ち（L3）。

## Confirmation

- 性質ベーステスト：PROP-ETA-003（`options` に 2 種のルート、正の整数の距離、登録済みの提供者）、PROP-ETA-004（事前確定運賃の距離は `fare-distance` の応答からだけ来る）。
- レビュー：事前確定運賃の計算に、法務の確認が済んだ提供者以外の距離を使うコードを差し戻す（ADR-0005 の Confirmation）。
- 結合テスト：提供者の障害の注入で、事前確定運賃の見積もりが作られず、日本版ライドシェアの候補が出ないこと。
