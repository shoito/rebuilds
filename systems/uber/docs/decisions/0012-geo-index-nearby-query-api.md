# ADR-0012: 近くの空車の検索は、`street` の輪を広げ、外周までの距離で打ち切る gRPC の API にする。依頼の前の地図の車は丸めて返す

> 2026-09-28 の注記：H3 の `gridDisk` から、自前の `geogrid` の `Disk`・`Ring` に改めた（ADR-0002 の同じ日の注記）。検索と打ち切りの決定は変えない。

## Context

配車は、依頼ごとに、近くの割り当て可能なドライバーを直線の距離で上位 N 人（既定 10）に絞り、その N 人の ETA を求める（[ADR-0004](0004-batched-dispatch-and-offers.md)）。候補の検索は、1 回のバッチで依頼の数だけ呼ばれる（S1 のピークで 30 回/秒、S3 で 600 回/秒）。

自前の格子 `geogrid` の `Disk(origin, k)` は、格子の距離が k 以内のセルを返す（ちょうど `1 + 3k(k+1)` 個）。日本を 1 つの平面に写した格子なので五角形がなく、どこでも穴が空かない（[ADR-0002](0002-hex-grid-geospatial-model.md)、[geospatial-index.md](../architecture/geospatial-index.md) の 2.1 節）。距離は投影の平面で測る。

輪の番号は、直線の距離と一致しない。輪 k の角のセルのドライバーより、輪 k + 1 の辺の中ほどのドライバーの方が近いことがある。

乗客のアプリは、依頼の前に近くの車を地図に出したい。一方で、乗車の相手でない人に正確な位置を見せない（NFR-009）。

## Options

打ち切りの規則：

1. **輪を 1 つずつ広げ、点から disk の外周までの距離 `r_k` の内側に N 人そろったら返す**
2. **輪 k の中に N 人そろったら返す**
3. **固定の半径（k_max）の中を全部集めて並べる**

依頼の前の地図：

- a. **`street` のセルの中心に丸め、ID を付けず、10 秒キャッシュして返す**
- b. **正確な位置を返す（本家と同じ見た目）**
- c. **台数だけを返す**

## Decision

1 と a を採用する。詳細は [geospatial-index.md](../architecture/geospatial-index.md) の 6 節。

- `FindNearby(lat, lng, limit, k_max, filter)` → 直線の距離の近い順の `Candidate`（`assignment_epoch` を含む）、`guaranteed_radius_m`、`truncated`、`generation`、`lease_epoch`。
- 既定は `limit` 10・`k_max` 5（約 2 km）。上限は 50・30（約 10 km）。`max_staleness_ms` は 15,000 を超えられない（NFR-002）。
- 返すのは有効な状態が空車のドライバーだけ。フィルターは、索引が持つ属性（車両の種類、サービスの種類、事業者、席の数、除外の一覧）での粗い絞り込みに限る。営業区域と運行枠の判定は配車の側で行う。
- 1 回のバッチの検索は、同じ写しの `generation` を使い、判断の記録に残す。
- 割り当て済みのドライバーの最新の位置は `GetDriverLocation(driver_id, trip_id)` で返す。呼べるのは Trips と ETA だけで、索引の割り当ての状態がその乗車と一致するときだけ答える。
- **依頼の前の地図**（`SupplyPreview`）：`street` のセルの中心と 45 度に丸めた向きだけ、最大 10 台、半径 k = 8。乗客の位置の `block` のセルごとに 10 秒キャッシュする。
- 2 を採らない理由：近い人を取りこぼし、配車の組が悪くなる。性質ベーステストで「総当たりと一致」を書けない。
- 3 を採らない理由：多くの場合、k = 1〜2 で足りる。毎回 k_max まで集めるのは無駄が大きい。
- b を採らない理由：NFR-009 に反する。依頼の前の乗客は、乗車の相手ではない。
- c を採らない理由：車がどちらの方向にいるかが分からず、乗車地を選ぶ助けにならない。郊外で 1 台しかいないときの扱いは持ち越す。

## Consequences

- 良くなること：
  - 打ち切りの正しさを「`guaranteed_radius_m` の内側は総当たりと一致」という 1 つの性質で確かめられる。
  - 依頼の前の地図から、特定のドライバーを追いかけられない。
- 引き受けるコスト：
  - 輪ごとに外周までの距離を計算する（k = 30 で数千回の距離の計算。問題にならない見込み）。
  - 依頼の前の地図の車は、実際の位置と最大約 200 m ずれ、10 秒遅れる。本家の見た目（車が道路の上を動く）とは違う。
  - 郊外で 1 セルに 1 台のとき、約 200 m の精度で居場所が分かる（持ち越し）。

## Confirmation

- 性質ベーステスト：PROP-GEO-001（`guaranteed_radius_m` の内側の総当たりと一致）、PROP-GEO-006（`SupplyPreview` に ID とセルの中心以外の座標がない）。
- 負荷試験（E3）：検索 1,000 回/秒で、索引の中の処理の p99 が 5 ms 以内。
- レビュー：乗客の API から `FindNearby` を呼ぶコード、`SupplyPreview` の応答に項目を足す変更を差し戻す。
