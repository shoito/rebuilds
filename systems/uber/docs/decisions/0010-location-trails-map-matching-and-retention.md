# ADR-0010: 軌跡は保持の期間を持つストアに分けて置き、道路への当てはめは Valhalla で遅れて行う。ログは H3 に丸め、人が見る操作は監査する

## Context

位置の軌跡は、次の用途で要る。

- 運賃の問い合わせ、事前確定運賃のルートからの逸脱の確認、事故と安全の調べ、領収書の地図（乗車ごと）
- ETA のための道路の区間ごとの速度（[ADR-0005](0005-maps-and-routing.md)）
- 地図の誤りの検出

一方で、位置の履歴は、個人の行動を強く表す。乗客とドライバーの正確な位置は、乗車の相手にだけ、その乗車の間だけ見せる（NFR-009）。位置の履歴が個人情報に当たるか、保持の期間、事業者との関係は、法務の確認待ち（[intent.md](../intent.md) の L4）。

本家は、隠れマルコフモデルと Viterbi で GPS の点の列を道路に当てはめ、当てはめの異常から地図の誤り（右折の禁止、一方通行、欠けた道路）を見つけている（[CatchME](https://www.uber.com/us/en/blog/mapping-accuracy-with-catchme/)、2019-04-25、2026-09-27 に確認）。Valhalla の当てはめ（Meili）も、Newson と Krumm の HMM の方式を使う（[Meili の algorithms](https://github.com/valhalla/valhalla/blob/master/docs/docs/contributing/architecture/meili/algorithms.md)、2026-09-27 に確認）。

## Options

保存：

1. **用途ごとにストアを分け、それぞれに保持の期間を持たせる（生の点・乗車の軌跡・ID を持たない集計）**
2. **生の点を 1 つのストアに長く置き、用途ごとに都度切り出す**
3. **生の点を保存しない（乗車の軌跡と集計だけ）**

当てはめ：

- a. **遅れて（乗車の終わり、1 分の窓）Valhalla の `trace_attributes` で当てはめる。索引には使わない**
- b. **受信のたびに 1 点ずつ当てはめ、索引に当てはめた位置を入れる**
- c. **当てはめをしない**

## Decision

1 と a を採用する。詳細は [location-ingestion.md](../architecture/location-ingestion.md) の 7〜9 節。

- **ストアと保持（既定案。L4 の結論で置き換える）**：

| ストア | 保持 |
| --- | --- |
| Kinesis（位置の流れ） | 24 時間 |
| S3 `loc-raw/`（生の点） | 30 日 |
| S3 `trip-trails/` と Aurora `trip_trails`（乗車の軌跡） | 1 年 |
| S3 `speed-samples/`・`supply-heat/`（ドライバーの ID を持たない集計） | 2 年 |

- 位置のストアは専用の KMS の鍵で暗号化する。鍵を使えるのは、パイプラインのロールと、監査つきの閲覧の窓口のロールだけ。
- **当てはめ**：trail-builder が、乗車の終わりから 60 秒後に 1 回、空車を含む走行は 1 分の窓ごとに、Valhalla の `trace_attributes` を呼ぶ。当てはめ専用の Valhalla のタスクを、ETA のタスクと分けて置く。
- **ログ・トレース・メトリクス・エラーの報告**に緯度経度を書かない。書くのは H3 の解像度 8 のセルまで。lint と試験のログの検査で守る。
- **人が軌跡を見る操作**は、サポートのツールの窓口だけにし、理由の入力、1 乗車の区間だけ、監査ログ 100% を必須にする。
- **分析の写し**では、`driver_id` を 90 日ごとに替わる鍵の HMAC に置き換える。
- 2 を採らない理由：保持の期間を用途ごとに変えられず、最も長い用途に合わせることになる。
- 3 を採らない理由：速度の表と地図の誤りの検出に、空車の走行も要る。
- b を採らない理由：熱い経路に、遅れと失敗の原因が増える。候補は直線の距離で絞り、ETA は道路の上で求めるので、索引の位置を道路に載せる効果は小さいと見込む（**未検証**。E3 の再生で確かめる）。
- c を採らない理由：速度の表と、事前確定運賃のルートからの逸脱の確認が作れない。

## Consequences

- 良くなること：
  - 生の点が 30 日で消え、長く残るのは乗車の区間と、ID を持たない集計だけになる。
  - 当てはめの量と遅れが、配車の熱い経路に影響しない。
- 引き受けるコスト：
  - 当てはめの計算（S1 のピークで約 170 回/秒）の Valhalla のタスクを別に持つ。必要な台数は **未検証**（E3 で計る）。
  - 保持の期間が法務の結論で変わったら、ライフサイクルの設定と既存のオブジェクトの扱いを変える。
  - 1 年の根拠は、事業者の乗務の記録の保存の義務との釣り合いで置いた仮の値である（条文は **未検証**）。

## Confirmation

- Terraform の S3 のライフサイクルの値と、この ADR の表の一致をテストで確かめる（PROP-LOC-005）。
- lint：緯度経度をログの項目に書くコードを拒否する。結合試験のログ全体で、緯度経度の形の値が 0 件。
- 監査：軌跡の閲覧の API の呼び出しと、監査ログの件数の一致を、毎日の照合で確かめる。
- レビュー：保持の期間を持たないストアに位置を書く変更を差し戻す。
