# ADR-0031: ナレッジの記事は記事の行とバージョンの行で持ち、公開中と編集中のバージョンをそれぞれ高々 1 つにする。レビューに出した本文を固定し、承認した本文だけを公開する。本文は制限付きの Markdown だけにする

詳細は [knowledge.md](../architecture/knowledge.md) の 3・4 節。

## Context

ナレッジの記事は、公開の後も直される。直している間も、利用者は公開中のバージョンを読む。承認の要るナレッジベースでは、承認者が見た本文と公開される本文が同じでなければならない。記事の番号は、担当者と依頼者の会話で使う。

本家は、公開済みの記事を編集すると新しい下書きのバージョンを作り（チェックアウト）、バージョンの番号を「主.副」で持ち、即時の公開と承認を経る公開の流れを持つ（チェックアウトで新しいバージョンを作ること、「廃止の予定」「取り消し」のバージョンの状態は [Article versioning](https://www.servicenow.com/docs/r/servicenow-platform/knowledge-management/article-versioning.html)、2 つの公開の流れと、却下で下書きに戻ることは [Knowledge workflows](https://www.servicenow.com/docs/r/servicenow-platform/knowledge-management/r_KnowledgeWorkflows.html)、2026-09-28 に確認。「主.副」の番号の増やし方は KB0713200 の題名とコミュニティの記事だけで、未検証）。本家の記事の本文は HTML である。

本システムはテナントの HTML を描かない（[intent.md](../intent.md) の Non-goals）。承認は 1 回だけ反映する（[ADR-0016](0016-approvals.md)）。

## Options

### 行の形

1. **記事の行（番号・評価の合計）と、バージョンの行（本文・状態）**
2. バージョンごとに記事の行を作り、番号をバージョンで共有する
3. 1 つの行を書き換え、バージョンは監査の履歴だけ

### 承認の対象

- a. **レビューに出した時点で本文を固定し、公開の時に内容のハッシュを確かめる**
- b. レビューの間も本文を直せ、承認の時点の本文を公開する

### 本文の形式

- x. **制限付きの Markdown**
- y. サニタイズした HTML

## Decision

1、a、x を採用する。

- `kb_article` と `kb_article_version`。部分一意索引で、`published` のバージョンと、`draft`・`review` のバージョンを、それぞれ記事ごとに高々 1 つにする。
- バージョンの状態は `draft`・`review`・`published`・`outdated`・`pending_retirement`・`retired`・`cancelled`（DT-KB-001）。`review` と `published` の本文は変えない。
- バージョンの番号は整数だけ。記事の番号はバージョンで変えない。
- 公開の方針はナレッジベースごとに `instant` か `approval`。承認は組み込みのフローで行い、著者の本人の承認を既定で禁止する。
- `valid_to` で廃止のタイマー、`review_interval_days` で見直しのタスク。
- 本文は制限付きの Markdown で、許可の一覧のタグの HTML に変換してサニタイズの後に描く。

2 を採らない理由：評価・閲覧の数・リンクがバージョンごとに分かれる。同じ番号の行が複数あると、番号での参照があいまいになる。

3 を採らない理由：編集の途中の本文が、公開中の記事として読まれる。承認の前の本文が利用者に見える。

b を採らない理由：承認の後、公開の前に本文を差し替えられる。承認の証跡が意味を失う。

y を採らない理由：HTML のサニタイズの漏れは XSS になる。テナントの HTML を描かない方針と合わない。Markdown なら入力の段で表せる要素が限られる。

## Consequences

- 良くなること：
  - 利用者は常に承認済みの本文を読み、編集の途中は見えない。
  - 記事の番号と評価がバージョンをまたいで安定する。
- 引き受けるコスト：
  - 誤字の修正も新しいバージョンと公開の流れを通る（軽微な修正の操作は持ち越し）。
  - 本家の HTML の記事は、変換の道具で Markdown にする。表現の一部を失う。

## Confirmation

- 決定表 DT-KB-001 と否定の表。
- 性質ベーステスト PROP-KB-001（バージョンの数）、PROP-KB-002（承認した本文を公開する）。
- XSS の試験：既知の攻撃の文字列の一覧を本文に入れ、描いた HTML に許可の一覧の外のタグ・属性が出ない。
