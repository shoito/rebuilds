# ADR-0052: 鍵はセルごと・用途ごとの KMS のマルチリージョンの鍵にし、テナントの秘密をテナントごとの DEK で包む。運用者はテナントのデータへの常設の権限を持たず、テナントが出すサポートの参照の許可と期限付きの権限でだけ読む。AI エージェントは本番に経路を持たない

詳細は [security.md](../architecture/security.md) の 5・7・8 節。

## Context

日本の大企業の審査は、暗号の鍵、データの所在、運用者のアクセスを問う（[ADR-0002](0002-tenancy-and-isolation.md)）。専用のセルは、DB・キャッシュ・検索の索引・暗号の鍵を他の顧客と共有しない（NFR-009）。テナントは秘密（Webhook の署名の秘密、フローの資格情報、OIDC の IdP の秘密）を持つ。メールの受信の原本とチケットの本文は、通信の秘密と個人の情報に関わる（[intent.md](../intent.md) の L1・L2）。

他の題材（Auth0 の ADR-0045・ADR-0056）は、用途ごとの KMS の鍵、期限付きの運用者の権限、AI エージェントの本番への経路のなさを決めている。

## Options

### 鍵の単位

1. **セルごと・用途ごとの鍵。テナントの秘密はテナントごとの DEK**
2. テナントごとの KMS の鍵
3. 全体で用途ごとの鍵（セルで分けない）

### 運用者のテナントのデータの参照

- a. **テナントの管理者が出す期限付きの許可と、期限付きの権限。読み取り専用の主体で Record Service から読む。参照をテナントに見せる**
- b. 期限付きの権限だけ（テナントの許可を要らない）
- c. 運用者はテナントのデータを一切読まない

## Decision

1 と a を採用する。

- 鍵：`<brand>-<cell>-data`（Aurora、S3、SQS、OpenSearch、バックアップ）、`<brand>-<cell>-tenant-secrets`（テナントの DEK を包む）、`<brand>-<cell>-signing`（パッケージの署名、内部の HMAC の鍵を包む）、log-archive の `<brand>-audit`。どれもマルチリージョン（主は東京、レプリカは大阪）。専用のセルは専用のアカウントの鍵。
- テナントの秘密は、テナントごとの DEK で AES-256-GCM（AAD に `tenant_id` と秘密の ID）。テナントの削除で DEK を消す。
- 運用者の常設の権限は、ダッシュボード・メトリクス・秘密と個人データを含まないログだけ。DB・シェル・KMS の管理は期限付き（最長 4 時間）。
- テナントのデータの参照は、テナントの管理者の「サポートの参照の許可」（対象、最長 72 時間、読み取りだけ）の範囲で、読み取り専用の主体から Record Service を通して読む。参照したレコードをプラットフォームの監査に残し、テナントが見られる。
- インシデントで許可を待てないときは、2 人の承認で期限付きの権限を得て、24 時間以内にテナントへ知らせる。
- AI エージェントは本番とそのテレメトリーに経路を持たない。

2 を採らない理由：S3 の 3 万テナントで、KMS の鍵の数と要求の数が大きくなる（クォータと費用。未検証）。Aurora と S3 の保存の暗号化は鍵の単位で分けられない（1 つのクラスタ・バケットは 1 つの鍵）ので、テナントごとの鍵の効果は秘密の暗号化に限られる。それは DEK で得られる。

3 を採らない理由：セルの障害や鍵の誤操作の影響が全セルに広がる。専用のセルの「鍵を共有しない」を満たせない。

b を採らない理由：テナントの知らないうちに運用者がデータを読める。日本の大企業の審査と、通信の秘密（L2）の説明に耐えない。

c を採らない理由：障害の調査とテナントの問い合わせ（「このチケットが見えない」）に答えられない。

## Consequences

- 良くなること：
  - 運用者の参照が、テナントの許可と記録で説明できる。
  - 専用のセルの鍵の分離を説明できる。
- 引き受けるコスト：
  - 調査のたびにテナントの許可を待つ。許可の画面と手順を用意する。
  - 顧客の管理する鍵は持ち越す（専用のセルの契約の条件と一緒に）。

## Confirmation

- IaC のポリシー検査：`tenant-secrets` の鍵の `Decrypt` を App・Engine・Notifier のタスクのロール以外に与えない。人のロールに与えない。
- 結合テスト：DEK の暗号文を別のテナントの行に差し込むと復号できない（SEC-091）。
- 拒否の側のテスト：許可のない運用者の参照を拒否し、許可の範囲の参照を記録する（SEC-095）。
- 四半期のアクセスのレビュー。
