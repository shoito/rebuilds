# ADR-0006: 辞書は組み込みの定義とテナントの定義を重ねて持ち、フィールドの型を 14 種に限る。子のクラスは属性を上書きできるが型は変えられない

詳細は [data-dictionary-and-tables.md](../architecture/data-dictionary-and-tables.md) の 3・5・6 節。

## Context

[ADR-0003](0003-table-hierarchy-and-extensible-schema.md) は、テーブルをクラスの継承の階層として辞書に持つと決めた。細部（辞書の置き場所、型の集合、子のクラスでの変更の範囲、名前の扱い）は data-dictionary-and-tables の領域に残した。

本家は、子のテーブルだけで継承したフィールドの既定値・読み取り専用・必須・参照の絞り込みを変える「上書き」を持つ（[Define a dictionary override](https://docs.servicenow.com/en-US/bundle/vancouver-platform-administration/page/administer/data-dictionary-tables/task/t_DefineADictionaryOverride.html)、2026-09-28 に検索の結果の抜粋で確認。本文は未検証）。

決めることは次のとおり。

- 組み込みのテーブル（インシデントなど）の定義を、テナントごとの DB の行に写すか、コードの版に持つか。
- テナントに許す型の範囲。
- 名前の変更を許すか。

## Options

### 組み込みの定義の置き場所

1. **コードの版に持ち、テナントの定義を DB に持って重ねる**
2. テナントの作成のときに、組み込みの定義を DB の行として写す

### 型

1. **14 種に限る**（文字列、長文、整数、10 進数、真偽、日付、時刻、長さ、選択肢、参照、メール、URL、作業メモ、条件）
2. 本家に近い多くの型（通貨、複数選択、HTML、スクリプトなど）を持つ

## Decision

置き場所は 1、型は 1 を採用する。

- 組み込みの定義はコードと一緒にリリースし、全テナントで同じにする。テナントは、フィールドの追加、子のクラス、独立のテーブル、上書きだけを DB に持つ。実効の辞書は `(tenant_id, meta_version)` ごとにコンパイルする。
- 上書きは、ラベル・既定値・必須・読み取り専用・選択肢の集合・参照の絞り込み・説明だけを変えられる。型・保存の場所・参照先は変えられない。
- テナントの名前は `c_` で始め、作成の後に変えない。ラベルは変えられる。値のキーはフィールドの ID。
- テナントのフィールドの型の変更は、互換のある変更だけを即時に許し、それ以外は新しいフィールドと写すジョブで行う。
- フィールドの削除は、非表示の後 30 日で値を消す 2 段にする。
- 階層の深さは 6 段まで。レコードのクラスは作成の後に変えない。

置き場所の 2 を採らない理由：

- 組み込みの定義の変更（新しいフィールドの追加）を、全テナントの行に写すマイグレーションが要る。3 万テナントで、テナントごとの失敗の扱いが重い。
- 全テナントを同じ版に保つ方針（[ADR-0002](0002-tenancy-and-isolation.md)）と合わない。

型の 2 を採らない理由：

- HTML とスクリプトの型は、テナントの任意のコードと XSS に当たる（[ADR-0001](0001-platform-and-stack.md)、[intent.md](../intent.md) の Non-goals）。
- 型ごとに、検証・索引・ACL の出口・レポート・API の表現が要る。MVP の範囲の業務に要る型から始める。

名前を固定する理由：REST API、フロー、パッケージが名前で参照する。名前を変えると、外の連携が黙って壊れる。

## Consequences

- 良くなること：
  - 組み込みの定義の変更がコードの版の変更だけで済む。
  - 型が少なく、出口（画面・API・レポート・検索）ごとの扱いを網羅して試せる。
- 引き受けるコスト：
  - 通貨・複数選択が要る顧客は、MVP では数値と選択肢の組み合わせ、または関連のテーブルで代える。
  - 名前の誤りを直すには、新しいフィールドを作って写す。

## Confirmation

- 性質ベーステスト PROP-DICT-001（保存と読み出し）。
- 決定表 DT-DICT-001（値の検証）、DT-DICT-002（型の変更）。
- 結合テスト：フィールドの追加・削除で DDL が発行されない。
- lint：組み込みの定義のファイルに、`c_` で始まる名前がないこと。
