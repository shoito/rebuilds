# ADR-0059: 可用性はエッジで、画面の速さはサーバーの計測と自前の RUM で数える。タイマーと SLA の違反の発火の遅れはコミットの時刻と期限の差で数え、期限を過ぎた未発火の数を別に数える。正しさの監視を SLI と同じ扱いにする

詳細は [observability.md](../architecture/observability.md) の 3〜5 節。

## Context

NFR-001 は、フォームを開くまで p95 1 秒（画面の表示）とサーバーの処理の p99 を求める。NFR-003 は、SLA の警告と違反の発火を期限から p99 60 秒以内に、NFR-004 は、止まった実行を 60 秒以内に再開することを求める。タイマーの発火は平日 9 時に集中する（[architecture/README.md](../architecture/README.md) の 2 節）。

この題材の約束の多くは「0 件」である：承認なしの実施、監査の欠け、重複の CI、読めない値の漏れ（K3・K4・K6、NFR-010）。各領域の文書は、それぞれ本番の突き合わせのジョブを置くと決めた（[ADR-0005](0005-cmdb-identification-and-reconciliation.md)、[ADR-0009](0009-record-audit-history-and-journal.md)、[ADR-0015](0015-flow-execution-and-timers.md)、[ADR-0024](0024-change-models-risk-and-cab.md)）。

## Options

### タイマーの遅れの数え方

1. **発火のコミットの時刻 − `due_at` のヒストグラム ＋ 期限を過ぎて残っているタイマー・未発火の違反の数（毎分の突き合わせ）**
2. ワーカーが取った時刻 − `due_at` のヒストグラムだけ

### 画面の速さ

- a. **サーバーのヒストグラム ＋ 自前の RUM の送信**
- b. サーバーのヒストグラムだけ
- c. 外部の RUM の事業者

### 正しさの約束

- x. **突き合わせのジョブの値をメトリクスにし、SLO と同じくアラートとダッシュボードで扱う。本番の漏れの合成監視を足す**
- y. ジョブの結果をチケットにするだけ

## Decision

1、a、x を採用する。

- 可用性の正本は CloudFront のリアルタイムのログ（セルごと、本番のテナントだけ）。4xx・429・421 は成功、503・5xx・タイムアウトは失敗。メールの受信も可用性に含める。
- タイマーの遅れは発火のトランザクションのコミットの時刻で数え、優先度・種類で分ける（テナントのラベルは付けない）。毎分、期限を 60 秒過ぎて残っているタイマー（優先度別）と、期限を過ぎた未発火の違反（`in_progress` かつ `breached = false` かつ `planned_end < now() − 60 秒`）を数える。どちらも 0 が正常。9 時の山を別の系列にする。
- RUM は `/ui/v1/rum` へ、画面の種類・テーブル・時間・端末の種類だけを送る。利用者の ID・URL・レコードの ID は送らない。
- 正しさの監視：期限を過ぎた未発火（毎分）、止まった実行（毎分）、承認なしの実施（日次）、監査の鎖（日次）、重複の CI・存在しない参照・索引の食い違い（日次）、SLA の期限の抜き取りの計算し直し（日次）、本番の漏れの合成監視（5 分。監視用のテナントの「漏れの印」を、読めない利用者で各出口から探す）。
- テナントのラベルは上位 200＋「その他」で、件数の系列にだけ付ける。

2 を採らない理由：取った後の失敗・再試行の遅れを数えない。取られないタイマー（取得の抜け、全ワーカーの停止）はヒストグラムに現れない。

b を採らない理由：NFR-001 の「画面の表示まで p95 1 秒」は、ブラウザの描画を含み、サーバーでは測れない。

c を採らない理由：画面の操作の記録を外部の事業者に送ることになり、個人の情報とデータの所在の論点（L1・L3）を増やす。

y を採らない理由：「0 件」の約束の破れは、SLO の違反と同じくすぐに気づくべきで、チケットの列に埋もれさせない。

## Consequences

- 良くなること：
  - 発火しないタイマーと、画面の描画の遅れを見落とさない。
  - 正しさの約束の破れが、デプロイの直後に気づける。
- 引き受けるコスト：
  - 毎分の突き合わせが reader に読み取りを足す（索引の上で小さい。E4 で測る）。
  - 監視用のテナントと漏れの印の保守。出口を足す Epic は、合成監視の対象も足す。

## Confirmation

- CI：新しいタイマーの種類・出口を足す PR で、ヒストグラムの種類のラベルと合成監視の対象の一覧が更新されていること。
- E12：9 時の山の負荷試験で、遅れのヒストグラムと期限を過ぎた数の両方が、試験のツールの測った値と合うこと。
