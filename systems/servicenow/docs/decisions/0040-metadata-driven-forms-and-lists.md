# ADR-0040: フォームとリストはサーバーがコンパイルした画面のモデルを描く。画面の規則は画面とサーバーで同じ評価器を使いサーバーを正とし、リストはキーセットのページ送りと上限付きの件数にする

詳細は [portal-and-ui.md](../architecture/portal-and-ui.md) の 4 節。

## Context

テナントはテーブル・フィールド・配置を足す（[ADR-0003](0003-table-hierarchy-and-extensible-schema.md)、[ADR-0006](0006-data-dictionary-and-field-types.md)）。フォームとリストは、どのテナントのどのテーブルでも同じ画面の束で描く必要がある。NFR-001 は、フォームを開くまで p95 1 秒、リストの 1 ページのサーバーの処理 p99 500ms を求める。ACL で読めない値は画面に出さない（[ADR-0012](0012-acl-enforcement-at-every-exit.md)）。

本家の UI の方針（UI policy）は、ブラウザで条件を評価し、フィールドを表示・必須・読み取り専用にする（[Using UI policies](https://www.servicenow.com/docs/bundle/zurich-platform-administration/page/administer/form-administration/task/t_CreateAUIPolicy.html)、2026-09-28 に確認）。本家は、クライアントのスクリプトで任意の処理も書ける。本システムは書かせない（[ADR-0001](0001-platform-and-stack.md)）。

## Options

### 組み立ての場所

1. **サーバーが辞書・配置・規則・ACL から画面のモデルを作り、画面は描くだけ**
2. 画面が辞書と ACL の規則を受け取り、画面の中で組み立てる

### 画面の規則の評価

- a. **画面とサーバーで同じ評価器。サーバーを正とする**
- b. 画面だけで評価する（本家に近い）

### リストのページ送り

- x. **キーセット、件数は 10,000 で打ち切る**
- y. `OFFSET` と正確な総数

## Decision

1、a、x を採用する。

- 画面のモデルは、配置、フィールドの属性（利用者の言語のラベル）、画面の規則、読めるレコードの値、書けるフィールドの集合、今の状態で出せる操作を持つ。値と書けるフィールドは同じ要求・同じ `acl_version` で作る。
- 配置の部分は `(tenant_id, meta_version, table, view, 言語)` でキャッシュする。
- 画面の規則は式の言語で書き、評価器は画面の束とサーバーで同じパッケージを使う。保存の時にサーバーが評価し直し、DT-UI-001 で必須と読み取り専用を強制する。隠したフィールドの値は捨てない（守るのは ACL）。
- `set_value` は画面の入力の補助だけにする。サーバーの値の設定はレコードのルールで行う。
- リストは 1 ページ 50 行（最大 100）、飛び越しは 10,000 行まで、件数は 10,001 行で打ち切る。

2 を採らない理由：ACL の規則と辞書の全体を画面に配ると、読めないフィールドの存在や規則の中身（どの条件で誰が読めるか）を画面に渡す。判定の実装が 2 つになり、1 つの判定の関数の原則（[AGENTS.md](../../AGENTS.md)）に反する。

b を採らない理由：API から保存すると、必須と読み取り専用が効かない。

y を採らない理由：大きなテナントで、ACL の述語を入れた正確な総数と深い `OFFSET` が NFR-001 を超える（`task` は S1 で年 7,000 万行）。

## Consequences

- 良くなること：
  - 画面の束は全テナントで同じで、テナントのファイルを配らない。
  - 画面に出る値は、単体の取得と同じ判定を通る。
- 引き受けるコスト：
  - フォームを開くたびにサーバーの往復が要る。配置の部分のキャッシュで抑える。
  - 「全 123,456 件」のような正確な総数は出せない。要る場合はレポート（[reports.md](../architecture/reports.md)）で数える。
  - 画面の規則で隠した値を API で書けることを、利用者向けの文書に書く。

## Confirmation

- 決定表 DT-UI-001。
- 性質ベーステスト PROP-UI-001（画面とサーバーの一致）、PROP-UI-002（画面のモデルは漏らさない）、PROP-UI-003（件数の上限）。
- lint：画面の束が ACL の規則の型を読み込まないこと。
- 計測（E2）：7,000 万行の `task` で、フォームを開く p95 1 秒、リストの p99 500ms。
