## この題材に固有の規則（開発リポジトリで守る）

### アクセス制御

- **レコードを読む・書く経路は、1 つのアクセスの判定の関数だけを通す。** フォーム、リスト、REST API、レポート、検索、エクスポート、通知の本文、ワークフローの中の参照が対象である。経路ごとに判定を書き直さない。
- **ACL の規則は、決定表で書き、表駆動テストで確かめる。** 条件の列は、ロール、操作（作成・読み取り・書き込み・削除）、対象（テーブル・レコード・フィールド）、レコードの条件、継承したクラスの規則とする。表は `spec.md` から直接読み込む。テストに書き写さない。
- **既定は拒否にする。** 一致する規則がないとき、判定の途中で失敗したときは、拒否する。この振る舞いを決定表の最後の行に必ず置く。
- **フィールドの ACL は、値を返すすべての出口で効かせる。** リストの列、集計、並べ替え、検索の結果、API の応答、通知の差し込みで、読めないフィールドの値が漏れないことを、出口ごとのテストで確かめる。並べ替えや絞り込みで値を推測できる経路も含める。

### SLA とカレンダー

- **SLA の計時は、純粋な関数で行う。** 「開始の時刻＋業務時間の長さ → 期限の時刻」と「2 つの時刻の間の業務時間」を、カレンダー（営業時間、タイムゾーン、祝日、会社の休日）を引数に取る関数にする。現在の時刻、DB、キャッシュを関数の中で読まない。
- **計時の関数は、性質ベーステストで確かめる。** 少なくとも次の性質を持たせる。
  - 足してから測ると、元の長さに戻る（加算と測定が逆の関係にある）。
  - 長さについて単調である。長さを延ばすと、期限は前に戻らない。
  - 一時停止の区間をどう分けても、合計の経過時間は変わらない。
  - 祝日と営業時間の外は、経過時間に数えない。
- **ジェネレーターは、カレンダーとタイムゾーンも生成する。** 日本の祝日（振替休日・国民の休日を含む）、年末年始の会社の休日、夏時間のあるタイムゾーン（呼び出し元が海外の拠点のとき）、日付をまたぐ営業時間、うるう年の 2 月 29 日を含める。
- **祝日のデータを、コードに埋め込まない。** 内閣府の CSV から取り込んだバージョン付きの表として持ち、テストでは固定のバージョンを使う。

### ワークフローとレコードの状態

- **状態の遷移は、レコードのバージョンの番号で守り、1 回だけ行う。** 承認・却下・ステップの完了・タイマーの発火は、同じトランザクションで、レコード、フローの実行の状態、outbox を書く（ADR-0004）。
- **外への呼び出しは、少なくとも 1 回として扱う。** 冪等のキーを付け、受け手の側の重複に備える。
- **ワークフローの耐久性のテストを持つ。** ステップの途中、コミットの直前と直後、タイマーの発火の途中で、プロセスを落とす障害の注入を行う。どの時点で落としても、次を確かめる。
  - 各遷移がちょうど 1 回だけ起きる。
  - タイマーは失われない。
  - 同じ承認の二重の反映が起きない。
- **公開したフローの定義は変えない。** 変更は新しいバージョンにする。実行中のフローは、開始したときのバージョンで最後まで進む。

### CMDB

- **CI の作成・更新は、識別と調整の 1 つの入口だけを通す。** 取り込み元ごとに CI を直接書く経路を作らない（ADR-0005）。
- **識別と調整は、性質ベーステストで確かめる。** 少なくとも次の性質を持たせる。
  - 同じ内容の取り込みを何回送っても、結果は 1 回と同じになる（冪等）。
  - 同じ CI を指す取り込みを並行に送っても、重複の CI を作らない。
  - 属性ごとの最終の値と関係の有無は、到着の順序によらない。取り込み元ごとの最新の観測の状態（max の結合）から、優先度・鮮度（その属性の最新の観測の時刻から測る）・観測の時刻・正準の値の順の純粋な関数で選ぶ（ADR-0038）。「最後に書いた取り込み元」だけを来歴に持つ形にしない（順序に依存する）。
  - 一致は、使えるすべての識別の項目の一致の和集合で決める。2 つ以上の CI に一致したら、推測で選ばず、重複の候補として止める（ADR-0037）。統合は人だけが行う。
- **識別そのものは、到着の順序で変わりうる。** 識別の値を共有しないペイロードが先に届くと 2 つの CI ができ、後で保留と人の統合になる。順序によらない性質は、調整と、識別の値を共有する入力について確かめる。識別の性質のテストで、任意の順序の不変を求めない（ADR-0005 の注記）。

### そのほか

- **テナントテーブルには `tenant_id` と RLS を付ける。** セルの解決（ホスト名 → テナント → セル）の前に、テナントのデータを読まない（ADR-0002）。
- **`tenant_id` が NULL の行は、次の表の組み込みの行だけに許す**（ADR-0002・ADR-0054 の注記、[data-model.md](docs/architecture/data-model.md) の 3 節）：`dict_table`、`dict_field`、`dict_choice_set`、`dict_choice`、`role`、`acl_rule`、`holiday_set`、`holiday_set_version`、`holiday`、`number_def`、`ci_relation_type`、`ci_attribute`、`ci_identification_rule`、`flow_def`、`flow_version`。NULL の行は読み取りだけで、`catalog_loader` のロールだけが書く。表を足すときは、この一覧・data-model・security の 10.2 節・マイグレーションの CI の許可の一覧を同じ PR で直し、`security:sensitive` の承認を受ける。
- **テナントをまたいで読む処理は、識別子だけを返す関数を通す**（ADR-0054）。タイマーの候補は `engine_scheduler` の `claim_due_timers` で受け取り、本文はテナントのコンテキストで読む。
- **本家のスクリプトの API と互換にしない。** 本家のサーバーの API やスクリプトの言語に似せた層を作らない。テナントが任意のコードを書ける仕組みは MVP に入れない（[リポジトリ共通の ADR-0007](../../docs/decisions/0007-no-reuse-of-original-implementation.md)、ADR-0003、ADR-0004）。
- **本家の名前を識別子に使わない。** ドメイン、ヘッダー、メールの参照の印、API のパス、テーブルとフィールドの内部の名前は、本家のものを写さない。ブランドの部分は `<Brand>`・`<brand>` で書く（[リポジトリ共通の ADR-0006](../../docs/decisions/0006-brand-neutral-identifiers.md)）。
- **テストに本物の個人情報を使わない。** 実在の社員の名前・メールアドレス、実在の機器のシリアル番号を、テスト・フィクスチャー・シードに書かない。

## このリポジトリでの規則

- ADR を追加・更新したら、`docs/decisions/README.md` の一覧を生成し直す。
- 領域の文書で ADR を起票するときは、[architecture/README.md](docs/architecture/README.md) の 7 節で領域に割り当てた番号の範囲の中で採番する。
- 本家の振る舞い・数値を書くときは、出典と確認日を付ける。確かめられないものは「未検証」と書く。
- ITIL の用語は、実務の一般的な言葉として使う。製品の名前や画面の文言に「ITIL」の商標を入れるかは、法務の確認待ち（[intent.md](docs/intent.md) の L6）。
