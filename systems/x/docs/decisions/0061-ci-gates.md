# ADR-0061: PR の必須の関門に、漏れの経路の表、`visible()` の決定表、fan-out の性質、出来事の再生、本人だけの表の RLS、ランキングのオフラインの評価、本家の実装の検査、契約の互換を入れ、変更のパスで足す。外すラベルを持たない

## Context

- この題材で最も危ないのは、エラーにならずに、見てはいけない投稿が出る・届くはずの投稿が届かない・数がずれたまま残ることで、特定の順序や量でしか起きない（[quality.md](../quality.md)）。
- QA は、漏れの経路の表、fan-out とカウンターの性質、出来事の再生、ランキングのオフラインの評価を、テストのレベルとして決めている（[quality.md](../quality.md) の 2.2・2.3 節）。
- 本家の実装（`twitter-text`、Snowflake、`the-algorithm`・`x-algorithm`）を依存にも写しにも使わない（[ADR-0001](0001-platform-and-stack.md)、リポジトリ共通の ADR-0007）。
- エージェントがテストの削除・skip・期待値の緩和で通したことにしない（AGENTS.md）。

## Options

1. **変更のパスで関門を自動で足し、外すラベルを持たない。性質の失敗は回帰の種にする**
2. 全部の関門を全部の PR で回す
3. 重い関門は夜間だけ

## Decision

1 を採用する。詳細は [delivery.md](../architecture/delivery.md) の 1・2 節。

- 区分（見える範囲、ID、タイムライン、出来事の消費者、ランキング、文字数、マイグレーション、契約、セキュリティの機微、運営の重い値）ごとに、足す関門を決める。
- 全部の PR に、静的な検査、本家の実装の検査（依存、写し、重みの値）、依存とライセンスの検査、表駆動、性質の短縮版、結合（漏れの経路の行）、出来事の再生、マイグレーション、契約の互換、E2E、テストの緩和の検出を入れる。
- 性質ベーステストの失敗を再実行で緑にしない。縮めた種を回帰の種に足す。
- テストの削除・skip・期待値の緩和・漏れの経路の行の削除・ガードレールの値の緩和は、差分から見つけて 2 人の承認を求める。
- 2 を採らない理由：PR の CI が 1 時間を超え、変更が大きくなる。
- 3 を採らない理由：漏れと届かないの誤りがマージされてから見つかる。

## Consequences

- 良くなること：
  - 危ない区分の変更だけに重い関門がかかり、PR の時間を抑えられる。
  - エージェントが関門を外して通すことができない。
- 引き受けるコスト：
  - パスの区分の表の保守。新しいサービスを足すときに区分に入れる必要がある。
  - コードの写しの検出の道具の選定と、誤検知の扱い。

## Confirmation

- CI の設定の検査：区分の表のパスにある全サービスが、少なくとも 1 つの区分に入っている。
- eval（[quality.md](../quality.md) の 3 節）：「テストが落ちるのを直せ」のタスクで、緩和をしない。
