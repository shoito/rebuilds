# ADR-0020: ランキングの変更はオフラインの評価と利用者の単位の A/B で判定し、返した投稿の理由を記録して示す。利用者の操作と個人化しない設定を持つ

詳細は [ranking-and-recommendation.md](../architecture/ranking-and-recommendation.md) の 12 節。

## Context

[ADR-0006](0006-ranking-boundary.md) は、ランキングの変更をオフラインの評価と A/B（1% → 5% → 50% → 100%）で出し、ガードレールの指標（通報、ミュート・ブロック、「興味がない」、スパムの表示）が 5% 悪化したら止めると決めた。また、返した投稿ごとに源と理由を記録すると決めた。残っているのは次の点である。

- **評価の限界**：記録にある並びの行動しか分からない。S1 の式の変更は、オフラインでは良し悪しを決めきれない。
- **A/B の単位と判定**：要求の単位で割り当てると、同じ人の画面が揺れる。指標の揺れが大きく、点の値だけで比べると誤って止める・広げる。
- **透明性と利用者の操作**：推薦の理由の説明と、利用者が推薦を弱める手段。閲覧の履歴の利用の説明は L4 の確認待ち。

## Options

1. **オフラインの評価は足切り、採否は A/B。A/B は利用者の単位、層で分け、各段 7 日以上、ガードレールは 95% の信頼区間で判定する。理由を記録して示し、利用者の操作を持つ**
2. オフラインの評価だけで採否を決める
3. 要求の単位の割り当て、または交互に混ぜる比較（インターリービング）を主にする

## Decision

1 を採用する。

- オフラインの評価（CI）：配信の記録の候補を新しいバージョンで並べ直し、NDCG@20、行動ごとの AUC と対数損失（S2）、作者の多様さ、フォロー外の割合、スパムの点の高い作者の割合、新しさを前のバージョンと比べる。NDCG の 1% 以上の悪化と、安全の指標の悪化で PR を失敗させる。
- A/B：
  - 割り当ては `hash(salt, viewer_id) mod 10000`。実験は層（源・スコア・混ぜ合わせ）に分け、同じ層の中で重ねない。
  - 各段 7 日以上。主な指標は K8 と 7 日の再訪の率。
  - ガードレールは 95% の信頼区間の上端で 5% 以上の悪化を「悪化」とする。
  - 標本の比の不一致（カイ二乗検定で p < 0.001）で結果を無効にする。
  - 100% にする判断は PM。
- 透明性：返した投稿ごとに、源・理由のコード・点・`model_version`・`weights_version`・`ranking_mode` を配信の記録に書く。画面の「なぜ表示されるか」で理由のコードを示す。閲覧の履歴の説明の範囲は L4 の後に決める。
- 利用者の操作：「興味がない」、「この作者をおすすめに出さない」、「この話題を減らす」、個人化しないおすすめの設定、ホームの既定のタブ。個人化しない設定の既定の値は L4 の結論で決め、それまでは個人化を既定にする。
- 2 を採らない理由：記録にない並びの行動は分からず、S1 の式の変更の良し悪しを決めきれない。
- 3 を採らない理由：要求の単位では同じ人の体験が揺れ、再訪の率のような長い指標が測れない。インターリービングは感度が高いが、混ぜ合わせの規則（作者・フォロー外の上限）を壊す。S2 で、スコアの層の足切りとして足すかを決める。

## Consequences

- 良くなること：
  - 安全の指標の悪化を、揺れと区別して止められる。
  - 利用者が推薦を弱める手段と、理由の説明を持てる。
- 引き受けるコスト：
  - 1 つの変更が 100% になるまで最短 4 週かかる。
  - 層の管理と、信頼区間の計算の集計を運用する。
  - 理由の表示は、L4 の確認が済むまで本番で有効にできない（`release.ranking_reasons` の裏）。

## Confirmation

- CI：ランキングの変更の PR に評価の報告がなければ失敗（[ADR-0006](0006-ranking-boundary.md)）。
- 性質ベーステスト：PROP-RANK-003（理由のコードと源の一致）、PROP-RANK-007（割り当ての固定と比）。
- 本番：実験ごとの標本の比の検査、ガードレールの判定の記録、`ranking_experiments` の停止の理由。
