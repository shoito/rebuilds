# ADR-0017: プロフィールの一覧は作者の最近の投稿の写しと作者の索引から読む。会話は会話の索引から読み、返信を段と規則の点で並べる。直接の返信が 1,000 件を超える会話は上位 200 件の候補の写しを持つ

## Context

ホームの他に、時刻の順の読み出しが 2 つある。

- **プロフィールの投稿の一覧**：作者の投稿・返信・メディアのタブ。人気の作者のプロフィールは多くの人が開く。
- **会話**：投稿を開いたときの返信の一覧。人気の投稿には数十万件の返信が付き、全部を時刻の順で返すと、最初の画面が新しい返信（スパムを含む）で埋まる（[architecture/README.md](../architecture/README.md) の 6 節の「大きな会話」）。

会話の返信の並びはランキングの一種だが、おすすめのパイプライン（[ADR-0006](0006-ranking-boundary.md)）ほどの重さは要らない。ML の点で見える範囲を変えない規則は、ここにも当てる。

## Options

会話の並び：

1. **段（作者の続き、自分、フォロー中、その他、畳むもの）と、段の中の規則の点。大きな会話は上位の候補の写し**
2. 時刻の順だけ
3. おすすめのパイプライン（`packages/ranking`）を会話にも使う

プロフィール：

- a. **`ar:` と `posts (author_id, id DESC)`**
- b. プロフィールごとの写しを別に持つ

## Decision

1 と a を採用する。詳細は [timeline-fanout.md](../architecture/timeline-fanout.md) の 9 節。

- プロフィール：直近 7 日・200 件は `ar:`、続きは作者の索引。メディアは部分索引。固定の投稿を先頭に出す。鍵アカウントは `visible()` の利用者の判定で、見えない人には何も返さない。
- 会話：段の順は「作者の続き → 自分 → フォロー中 → その他 → 畳むもの（ミュート、スパムの点が高い作者）」。段の中の点は `(いいね + 2 × 返信 + 1) / (経過時間 + 2)^1.5`。重みは `ops.conversation.*`。変更は記録した出来事での再生の評価と A/B（`experiment.conversation.*`）を通す。
- 直接の返信が 1,000 件を超えたら、上位 200 件の候補を `cv:{post_id}` に持ち、30 秒ごとに数の写しから作り直す。
- 全件に `visible()`（`surface = conversation`）。スパムの点は T&S の分類の結果を入力に使うが、出すか出さないかは `visible()` が決め、点は畳むかどうかだけに使う。
- 2 を採らない理由：大きな会話で、最初の画面が新しい返信とスパムで埋まる。
- 3 を採らない理由：会話の読み出しは件数が多く、候補の源・特徴・スコアの段の予算（800ms）は重すぎる。S2 で学習済みのモデルを会話にも使うかは、`ranking-and-recommendation.md` で決める。
- b を採らない理由：`ar:` が直近を持ち、古い部分は索引で足りる。

## Consequences

- 良くなること：
  - 大きな会話でも、作者の続きと知り合いの返信が先に出る。
  - 会話の並びの変更も、評価と A/B を通る。
- 引き受けるコスト：
  - 段 2・3 の閲覧者ごとの読み出し（自分とフォロー中の人の返信）。フォローが 2,000 人を超える人は段 3 を省く。
  - `cv:` の作り直しのジョブ。
  - 点の式は人の目で決めた初期値で、評価で直していく。

## Confirmation

- 表駆動テスト：段の決定（作者、自分、フォロー中、ミュート、スパムの点）の全組み合わせ。
- 結合テスト：ブロックした・された人の返信が、どの段にも出ない（漏れの経路の表の「会話」）。
- 性質ベーステスト：会話の全ページを辿ると、見てよい返信が重なりなく全部出る（畳んだものを開いた場合を含む）。
- CI：会話の点の重みの変更の PR は、再生の評価の結果を添えないと失敗する。
