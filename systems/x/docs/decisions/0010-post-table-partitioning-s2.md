# ADR-0010: S2 で投稿の表を投稿の ID のハッシュで分割する。作者・会話ごとの一覧は、出来事から作る別の索引の表に、それぞれ作者・会話の ID で分割して持つ

## Context

S2 では、投稿が 1 日 1,500 万件、S3 では 1 億件になる（[architecture/README.md](../architecture/README.md) の 2 節）。Aurora の 1 つの writer で受けきれないので、投稿の表を分割する。分割の鍵は、[ADR-0002](0002-post-ids-and-ordering.md) で持ち越した。

投稿の読み出しの型は次の 3 つである。

| 読み出し | 鍵 | 主な利用 |
| --- | --- | --- |
| ID で 1 件・複数件 | 投稿の ID | 状態の写しの元、本体の写しの元、埋め込み、公開 API、通知、検索の結果 |
| 作者の一覧 | 作者の ID | プロフィール、写しの作り直し（作者の最近の投稿の写しがないとき） |
| 会話の一覧 | 会話の ID | 会話の表示 |

ID での読み出しは、写し（`ps:`・`pb:`）の取りこぼしで起き、量が最も多い。作者の一覧は、作者の最近の投稿の写し（`ar:`、[timeline-fanout.md](../architecture/timeline-fanout.md)）が大部分を受ける。ID の中に分割の番号を入れる案は ADR-0002 で退けた。

## Options

1. **`posts` を投稿の ID のハッシュで分割。作者・会話の一覧は、出来事から作る別の表（`author_posts`・`conversation_posts`）を、作者・会話の ID で分割**
2. `posts` を作者の ID のハッシュで分割。ID での読み出しは、ID → 作者の対応表を引く
3. 分割しない（Aurora の最大の構成と読み出しの写しで受ける）

## Decision

1 を採用する。詳細は [posts-and-ids.md](../architecture/posts-and-ids.md) の 9 節。

- `posts` と、投稿に付く抜き出しの表（`post_mentions`・`post_hashtags`・`post_urls`・`post_media`）は、同じ投稿の ID の分割に置き、書き込みを 1 つのトランザクションに保つ。
- 冪等の記録 `post_requests` は作者の ID で引くので、作者の ID のハッシュで分割した別の表にする。書き込みは 2 段にする：(1) `post_requests` に、振った `tid` を `reserved` の状態で先に書く（主キーの重複なら、既にある `tid` を使う）。(2) その `tid` で投稿の分割に書く（`posts.id` の主キーで、2 回目は何もしない）。(3) `post_requests` を `committed` にする。再送で `reserved` の記録を見つけたら、同じ `tid` で (2) からやり直す。`reserved` のまま 24 時間たった記録は、投稿の分割に行がなければ捨てる。
- `author_posts`・`conversation_posts` は `posts` の流れの消費者が冪等に書く。遅れの目標は p99 5 秒。新しい部分は `ar:` が補う。
- リポスト：S2 では `reposts`（エンゲージメントのクラスタ、投稿の ID で分割）を正本にして先に書き、出来事からリポストの `posts` の行を冪等に作る（ID は `reposts` の行に振った `tid`）。
- 分割の数：論理の分割を 1,024 にし、物理のクラスタへの対応表で持つ（[follow-graph.md](../architecture/follow-graph.md) の [ADR-0013](0013-graph-partitioning.md) と同じ形）。S2 の初めは 4 クラスタ。
- 2 を採らない理由：最も多い ID での読み出しが、対応表の往復を常に伴う。対応表そのものが投稿の数だけ大きくなる。
- 3 を採らない理由：S2 の書き込み（ピーク 3,000 件/秒、瞬間 3 万件/秒）と保存の量を、1 つの writer で受ける余裕がない（capacity の領域で数値を確かめる）。

## Consequences

- 良くなること：
  - 最も多い読み出しが 1 つの分割で済む。書き込みも投稿ごとに 1 つの分割で確定する。
  - 作者の分布の偏り（多く投稿する作者）が書き込みの分割に偏らない。
- 引き受けるコスト：
  - 作者・会話の一覧が非同期になり、投稿の直後に作者の一覧と会話に出るまで遅れがある。`ar:` と、会話の表示での自分の投稿の補い（クライアント）で隠す。
  - 索引の表の照合（`posts` と `author_posts` の差）のジョブが要る。
  - リポストの `posts` の行が `reposts` から遅れて作られる。

## Confirmation

- 性質ベーステスト：任意の投稿・削除・再送の出来事の列を当てた後、`author_posts`・`conversation_posts` が `posts` から作ったものと一致する。
- 結合テスト：索引の作成役を止めて再開しても、欠けと重複がない。
- 本番（S2）：照合のジョブで索引の表の差を測り、索引の遅れの p99 を計測する。
- S1 の計測（読み出しの型の比率）を S2 の前に記録し、前提が崩れていれば見直す。
