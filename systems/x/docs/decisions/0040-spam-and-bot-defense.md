# ADR-0040: スパムとボットは、エッジ・登録・レート制限・行動の規則・アカウントの危険の点の層で防ぎ、点の帯ごとに決まった扱いをする。点は見える範囲を変えない

詳細は [trust-and-safety.md](../architecture/trust-and-safety.md) の 8 節。

## Context

- ホームのスパムの割合を 0.5% 以下にする（NFR-011）。公開の登録と公開 API は、スパムとボットの入口になる（[architecture/README.md](../architecture/README.md) の 6 節）。
- スパムの判定の部品（自前の規則と第三者の分類のサービスの組み合わせ）は trust-and-safety の領域で選ぶ（同 6 節の持ち越し）。
- ランキングはスパムの点を入力として使うが、落とす判断は規則で行う（[ADR-0006](0006-ranking-boundary.md)）。トレンドは作者の重みに点を使う（[ADR-0027](0027-trends-burst-detection.md)）。
- DM の中身は使えない（L3）。
- 誤って正当な利用者を止めると、信頼を失う。

## Options

1. **層の防御（エッジ、登録、レート制限、行動の規則、危険の点）。S1 の点は規則の信号とアカウントの特徴のロジスティック回帰。点の帯ごとに決まった扱い**
2. 第三者のスパムの分類のサービスに判定を任せる
3. 規則だけ（点を持たない）

## Decision

1 を採用する。

- エッジ：WAF の Bot Control と IP の一覧（[security.md](../architecture/security.md)）。
- 登録：電話番号かメールの OTP、使い捨てのドメインの拒否、同じ電話番号のアカウント 5 つまで、端末の証明の結果を信号にする。
- レート制限：[api-and-rate-limits.md](../architecture/api-and-rate-limits.md) の桶。T&S は利用者ごとの係数で絞れる。
- 行動の規則：Valkey の滑る窓で、同じ文の連投、メンションの爆撃、大量のフォローと解除、大きなアカウントへの貼り付け、危ないリンク、登録の直後の活動、ブロックと通報の集中、DM の申請の反応（中身は使わない）。
- 危険の点：S1 はロジスティック回帰（Python で学習、ONNX で推論。ランキングと同じ基盤）。ラベルは措置と異議の結果。
- 帯：0.9 以上は `read_only`（電話番号の確認で解除）と P2 の審査、0.7〜0.9 は `reduce_account`・トレンドの重み 0・おすすめの点 0.3 倍と P3 の審査、0.5〜0.7 はレート制限の係数 0.25。措置は `moderation_actions` に規則の主体で書く（[ADR-0038](0038-moderation-action-model.md)）。
- 点は `visible()` に入らない。見える範囲を変えるのは措置の行だけ。
- 第三者の分類のサービスは S1 で買わない。NFR-011 を外したら候補を比べる。
- 2 を採らない理由：題材の主な論点（スパムとボットの防御）を外に出すことになる。投稿の本文を外部に送ることになり、L4 の確認が要る。点の理由を説明しにくく、異議に答えにくい。
- 3 を採らない理由：信号の組み合わせ（新しいアカウントで、リンクが多く、ブロックが集中する）を 1 つの規則で表しにくい。規則の数が増え、閾値の調整が難しくなる。

## Consequences

- 良くなること：
  - 層が独立で、1 つが破られても次の層で止まる。
  - 点の帯の扱いが決まっていて、説明と異議ができる。
  - ランキング・トレンドと同じ点を使い、扱いが揃う。
- 引き受けるコスト：
  - 規則と点の閾値の調整を、抜き取りの評価で続ける必要がある。
  - S1 の線形のモデルでは、巧妙なスパムの取り逃がしがある。7 日・30 日後に見つかった割合で測る。
  - 電話番号の確認は、電話番号を持たない利用者の登録を難しくする（メールも選べる）。

## Confirmation

- 性質ベーステスト：PROP-TS-006（点がどの値でも、措置の行がなければ `visible()` が変わらない）、PROP-TS-007（規則の措置の種類）。
- 合成の試験：スパムの行動の列で規則が働き、点が上がり、帯の扱いになる。
- 本番：週ごとのホームの抜き取り（NFR-011）、取り逃がしの割合、規則ごとの措置の件数の急な変化、点の分布。
