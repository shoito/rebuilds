# ADR-0030: プッシュは送る直前に見える範囲・設定・送る量の上限を確かめる。本文を載せない形を既定にし、端末が API で中身を取る。まとめの通知は collapse の鍵で上書きする。メールは日ごとの要約だけ

## Context

プッシュ（APNs・FCM）は、事業者に渡すと取り消せない。通知の行を作った時から送る時までに、ブロック・削除・措置が起きうる。漏れの経路の表は、通知を「送る時に判定し直す。ブロック・措置の後のプッシュを送らない」と決めている（[quality.md](../quality.md) の 2.2.1 節）。

プッシュの事業者は外国にある第三者で、そこに投稿の本文や相手の名前を渡すことの扱いは法務の確認待ち（[intent.md](../intent.md) の L4）。

人気の投稿のいいねのまとめは、行為者が増えるたびに送ると、受け手の端末が鳴り続ける。メールは、プッシュと同じ頻度で送ると、迷惑になる。

## Options

送る判断：

1. **送る直前（Push Sender）に、見える範囲・ブロック・設定・静かな時間・既読・量の上限を判定する**
2. 作る時（Worker）だけで判定する

中身：

- a. **本文を載せない形を既定にし、端末が API から中身を取る。本文を載せる形はフラグの後ろに置く**
- b. 本文と相手の名前を載せる

メール：

- x. **未読がたまり、アプリを開いていない人に、日ごとの要約だけを送る**
- y. 通知ごとにメールを送る

## Decision

1、a、x を採用する。詳細は [notifications.md](../architecture/notifications.md) の 6 節と 8 節。

- 送る直前の判定は 6.2 節の決定表（`DT-NOTIF-002`）。投稿の状態と閲覧者の集合の写しで判定する。
- 量の上限：まとめの行は 10 分に 1 回、受け手ごとに 1 時間 30 件（フォローしている人からの返信・メンションと措置の知らせを除く）。collapse の鍵（APNs の `apns-collapse-id`、FCM の `collapse_key`）にまとめの行の ID を入れ、端末の上で前の通知を置き換える。
- 中身：種類、通知の ID、まとめの鍵、一般の短い文だけ。iOS は通知のサービスの拡張、Android はデータのメッセージで、端末が API から中身を取る。`release.push.rich_payload` は L4 の結論まで有効にしない。
- 30 分より古いプッシュの仕事は送らない。事業者の障害の後に古い通知で端末を鳴らさない。
- メールは SES（東京）。1 日 1 通まで、未読の上位 10 件。送る直前に同じ判定をする。広告・宣伝のメールに当たるかと同意の取り方は法務の確認待ち。
- 2 を採らない理由：作る時から送る時までの変化（ブロック、削除、措置）を見落とす。
- b を採らない理由：L4 の結論の前に、外国の第三者へ本文と人の名前を渡すことになる。端末で取る形なら、L4 の結論がどちらでも、フラグで切り替えられる。
- y を採らない理由：迷惑になり、配信の停止とメールの評判の低下を招く。

## Consequences

- 良くなること：
  - ブロック・措置の後のプッシュが 0 件になる（送る直前の判定）。
  - L4 の結論の前でも、プッシュを出せる。
  - 端末が鳴りすぎない。
- 引き受けるコスト：
  - 端末で中身を取る往復が増える。iOS の拡張の時間の制限の中で取れなければ、一般の文のまま出る。
  - 送る直前の判定のための読み出し（写し）が、プッシュごとに要る。
  - 事業者の応答のコードと上限は、E8 で公式の文書を確かめる（未検証）。

## Confirmation

- 性質ベーステスト：PROP-NOTIF-002（送らない）。
- 結合テスト：プッシュの事業者の模擬に渡った中身に、本文・相手の名前・メールアドレスが含まれない（`release.push.rich_payload` がオフのとき）。
- 表駆動テスト：`DT-NOTIF-002` の全行。
- 本番：送らなかった理由の内訳、送信の失敗の率、トークンの失効の数、プッシュの遅れの p95 を計測する。
