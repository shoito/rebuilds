# ADR-0049: クライアントは共通のパッケージとデータの層を持ち、ホームの 200 件を手元に保存する。DM の中身は手元に置かない。オフラインの投稿は `Idempotency-Key` つきの待ち行列にする。公開の URL は App API が最小の HTML を返す

## Context

- クライアントは Web（React、PWA）と React Native（Expo）の iOS・Android（[ADR-0001](0001-platform-and-stack.md)）。型・API のクライアント・文字数・見える範囲の表示の規則を同じパッケージにする方針がある。
- 日本の利用は電車の中など、回線が途切れる場面が多い。ホームを開いて何も出ない時間を短くしたい。
- 手元に残したデータは、削除・ブロック・措置の後も、オフラインの間は残る（NFR-009）。DM は本人だけのデータで、通信の秘密に当たりうる（法務の L3）。
- 公開の投稿の URL は、リンクのカード（OGP）と検索エンジンのために、台本を動かさずに読める HTML が要る。この経路も `visible()` を通す（[quality.md](../quality.md) の 2.2.1 節の「埋め込み・リンクのカード」）。

## Options

手元の保存：

1. **データの層（TanStack Query）に正規化した保存を持ち、ホーム・プロフィール・通知の一部を手元の DB に保存する。DM は保存しない**
2. 手元に保存しない（毎回サーバーから）
3. DM を含めて全部を手元に保存する（暗号化した DB）

公開の URL：

- a. **App API が、ログインしていない人として `visible()` を通した最小の HTML を返す**
- b. SSR の枠組み（Next.js など）で画面を全部サーバーで描く

## Decision

1 と a を採用する。詳細は [clients.md](../architecture/clients.md) の 2〜4・9 節。

- 共通のパッケージ：`api-client`、`text`、`visibility-ui`、`client-data`、`i18n`、`design-tokens`。見える範囲の判定（`packages/visibility`）はクライアントに置かない。
- 手元の保存：ホームの写し 200 件（7 日）、おすすめの最後の 1 ページ、自分の投稿、通知 50 件、下書き、送信の待ち行列。アプリは SQLite、Web は IndexedDB、アカウントごとに 1 つ。ログアウトで消す。
- 手元の写しは、最初のページを取り直した時にサーバーが返さなかった範囲の投稿、`not_found` の投稿、ブロック・ミュートした作者の投稿、Gateway の `hidden` の知らせの投稿を消す。
- オフラインでは、投稿だけを待ち行列に入れ、いいね・フォローは押せなくする。待ち行列は `Idempotency-Key`（UUIDv7）で二重の作成を防ぎ、24 時間で下書きに戻す。
- 公開の URL は CloudFront から App API の口へ送り、`show` のときだけ OGP と本文の最小の HTML、`hide` のときは存在を明かさない 404。60 秒のキャッシュと、削除・措置の時の無効化。
- 2 を採らない理由：回線の途切れでホームが空になる。
- 3 を採らない理由：DM を端末に残す危うさ（共有の端末、盗難）が大きく、端末の鍵の暗号化は盗難への効き目が小さい。
- b を採らない理由：画面の大部分はログインした人の個別の表示で、SSR の利点が小さい。必要なのは公開の URL の最小の HTML だけ。

## Consequences

- 良くなること：
  - ホームがすぐ出る。オフラインでも読める。
  - 文字数の数え方と表示の規則が Web とアプリとサーバーで同じ。
- 引き受けるコスト：
  - 手元の写しの中の、見えなくなった投稿を消す規則と試験。
  - DM がオフラインで読めない。
  - 公開の URL の HTML の経路が、漏れの経路の 1 つとして増える。

## Confirmation

- 性質ベーステスト：PROP-CLI-001（合わせても重複なく ID の降順）、PROP-CLI-002（再送しても確定は 1 件以下）。
- E2E：ログアウトの後に DB が空、DM が手元に残らない、オフラインの投稿が回線の回復で 1 件だけ出る。
- 結合テスト：公開の URL が鍵アカウント・削除・措置の投稿で 404。
