# ADR-0012: 閲覧者の集合（ブロックの両向き、ミュート、承認済みの鍵アカウントのフォロー先、ミュートの語）を Valkey にバージョンつきの写しで持ち、書き込みの確定の直後に更新する。寿命は 1 時間。ミュートは逆向きの表を持たない

## Context

`visible(viewer, post)` は、閲覧者ごとのブロック・ミュート・承認済みの鍵アカウント・ミュートの語を `ViewerContext` として要る（[ADR-0004](0004-single-tenant-and-visibility.md)）。タイムラインの 1 ページで数十〜数百件を判定するので、毎回 Aurora を引けない。ADR-0004 は、ブロックを数万件持つ人の扱いをこの領域に任せた。

ブロックは、確定の直後から効いてほしい（ブロックした直後に相手の投稿が出ると、利用者の安全を損なう）。NFR-009 は全経路で p99 60 秒を求める。写しの更新を出来事の経路（Relay → Kinesis → 消費者）だけに頼ると、数秒の遅れが常にあり、経路が止まると上限がない。

[ADR-0007](0007-follow-graph-storage.md) は「ブロックとミュートは同じ 2 つの向きを持つ」と書いた。ミュートは本人だけの表で、相手に知られてはならない。

## Options

1. **Valkey に閲覧者ごとの集合をバージョンつきで持つ。書き込みのサービスが確定の直後に差分を当て、出来事の消費者と修復の仕事が補う。寿命 1 時間**
2. 出来事の消費者だけで写しを更新する
3. 写しを持たず、読み出しのたびに Aurora を引く
4. ブロックの集合だけ Bloom filter にし、当たりを Aurora で確かめる

## Decision

1 を採用する。詳細は [follow-graph.md](../architecture/follow-graph.md) の 6 節。

- 鍵は `vb:`（ブロックの両向きの和）・`vm:`（ミュート）・`vp:`（承認済みの鍵アカウント）・`vw:`（ミュートの語の照合器）・`vv:`（バージョン）。同じスロットに置き、1 回の Function で読む。
- バージョンは `users.graph_version`。辺を変える全てのトランザクションで上げる。写しへの書き込みは、バージョンが今以上のときだけ。reader のバージョンが古ければ writer から読み直す。
- 確定の直後の更新が失敗したら、3 回まで再試行し、修復の仕事（SQS）に入れる。`graph` の流れの消費者も同じ差分を当てる（冪等）。
- 寿命は 1 時間（読み出しで延ばさない）。修復の仕事の遅れが 30 秒を超えたら、閲覧者の集合を読み出しの時に Aurora から読む劣化の運転に切り替える。
- 大きな集合も全件を Set に持つ。読み込みは single flight。
- **ミュートは逆向きの表を持たない。** ミュートを使う読み出しは、すべて本人（ミュートした人）を起点にする。逆向きの表は、ミュートされた側から「誰にミュートされているか」を引ける形を作る。ADR-0007 の「同じ 2 つの向き」はブロックだけに当てる。
- 2 を採らない理由：ブロックの直後の数秒、相手の投稿が出る。経路が止まると上限がない。
- 3 を採らない理由：読み出しのピークに、閲覧者ごとの 4 つの問い合わせが乗る。
- 4 を採らない理由：ブロックの判定は「当たらない」が大部分で Bloom filter の利点が出るが、ミュート・鍵の集合には別の仕組みが要り、2 種類の形を持つことになる。Set の全件で足りる大きさ（10 万件で数 MB）である。

## Consequences

- 良くなること：
  - ブロックが確定の直後の読み出しから効く。
  - 出来事の経路が止まっても、修復の仕事と劣化の運転で上限がある。
- 引き受けるコスト：
  - 書き込みの経路に Valkey への書き込みが入る（予算 10ms）。
  - バージョンの規則を、辺を変える全ての経路（鍵の切り替えの一括の承認、アカウントの削除、T&S の措置による関係の解除）で守る必要がある。
  - S1 で、写しの読み込みが毎秒 300 回前後 reader に乗る。
  - [ADR-0007](0007-follow-graph-storage.md) の「ミュートも 2 つの向き」から外れる。

## Confirmation

- 性質ベーステスト：PROP-GRAPH-004（バージョンが減らない、確定の直後の一致）、PROP-GRAPH-005。
- 結合テスト：ブロックの直後の写しの更新を失敗させ、修復の仕事の後に全経路で相手の投稿が出ない。修復の仕事も止めたとき、30 秒で劣化の運転に入る。
- lint：`users.graph_version` を上げずに関係の表を変える SQL を拒否する。`mutes` の逆向きの索引（`target_id` を先頭にする索引）を作るマイグレーションを拒否する。
- 本番：修復の仕事の年齢、写しの読み込みの回数、劣化の運転の時間を計測する。
