# ADR-0026: 投稿の索引は月ごとに分けて `tid` の時刻で書き先を決め、`state_version` を外部の版にする。問い合わせは 1 つの組み立て関数で見える範囲の条件を必ず含め、返す前に `visible()` で判定し直す

詳細は [search-and-trends.md](../architecture/search-and-trends.md) の 6・7 節。

## Context

- 投稿は S1 で 1 日 100 万件、S3 で 1 億件。検索の多くは直近の投稿を探す（「最新」のタブ、トレンドの例）。1 つの索引に全期間を入れると、シャードが大きくなり、古い投稿の移し替え（安い保存へ）もしにくい。
- 索引は出来事の流れで更新する。流れは少なくとも 1 回届き、鍵（作者）をまたぐ順を保証しない（[ADR-0005](0005-event-log-and-outbox.md)）。古い出来事で新しい状態を上書きしてはいけない。投稿の状態は `state_version` で版を持つ（[ADR-0009](0009-post-state-tombstones-and-state-cache.md)）。
- 見える範囲は読み出しの時に `visible()` で決め、索引には粗い印だけを入れる（[ADR-0004](0004-single-tenant-and-visibility.md)）。印だけで絞ると、索引の更新の遅れの間に、削除・措置の投稿が出る。
- 後から絞ると、ページの件数が足りなくなる。

## Options

索引の形：

1. **月ごとの索引（`posts-YYYYMM`）。書き先は投稿の `tid` の時刻で決める。読み出しは全月の別名**
2. 1 つの索引（別名の裏で版だけ替える）
3. 日ごとの索引

版：

- a. **`state_version` を外部の版（`external_gte`）にする。削除は墓石**
- b. 出来事の時刻で比べる
- c. 版を持たず、最後に届いたものを書く

見える範囲：

- x. **組み立て関数で印の条件を必ず含め、返す前に `visible()` で判定し直す。足りなければ 2 回まで取り直す**
- y. 印の条件だけ
- z. `visible()` の後の絞り込みだけ（印を持たない）

## Decision

1、a、x を採用する。

- 月ごとの索引。`tid` の時刻から索引の名前が決まるので、古い投稿の削除・措置も正しい索引に届く。S2 で直近 3 か月より前を UltraWarm に移す。
- 書き込みは `version_type = external_gte`・`version = state_version`。削除・非表示は墓石（本文を空にし、印を立てる）にして 7 日後に消す。数（いいね）の部分更新は版の外で、単調に大きい値だけを書く。
- 作者の鍵・凍結の切り替えは `update_by_query` で作者の文書を更新する。更新の間は返す前の判定で守る。
- 問い合わせは `buildPostSearch` だけで作る。削除・措置・検索の除外・凍結・地域・鍵（閲覧者と承認済みの作者を除く）の `filter` と、ブロック・ミュートの `must_not` を必ず含める。OpenSearch のクライアントの直接の利用は lint で禁止する。
- 返す前に、投稿の状態の写し（`ps:`）で `visible()` を通す。落ちた件数を理由ごとに数える。
- 検索はログインした人だけにする。
- 2 を採らない理由：シャードが大きくなり、古い投稿を安い保存へ移せない。作り直しが全期間の一度の作業になる。
- 3 を採らない理由：S1 の量では索引の数が多すぎ、シャードの数の管理が重い。
- b を採らない理由：作者をまたいで順がなく、時計のずれもある。版は正本の DB が決めるのが確か。
- c を採らない理由：重複と順の入れ替えで、削除の後に古い文書が戻る。
- y を採らない理由：索引の更新の遅れ（p95 15 秒）の間、削除・措置の投稿が出る（NFR-009）。
- z を採らない理由：鍵アカウントの投稿の多くが候補に入って落ちるため、ページが埋まらず、件数の差から存在が漏れうる。

## Consequences

- 良くなること：
  - 削除・措置の投稿が、索引の遅れの間も返らない。
  - 古い出来事が新しい状態を壊さない。
  - 古い月の索引を、安い保存へ移しやすい。
- 引き受けるコスト：
  - 全月をまたぐ「話題」の検索は、索引の数だけ問い合わせが広がる。既定の範囲を直近 7 日にして抑える。
  - 作者の状態の変更で、作者の文書の数だけ更新が走る。
  - 返す前の判定で、ページの件数が足りないことがある。

## Confirmation

- 性質ベーステスト：PROP-SRCH-001（返す投稿はすべて `show`）、PROP-SRCH-002（版の比較と墓石）、PROP-SRCH-003（組み立ての条件）。
- 結合テスト：漏れの経路の表の検索の行（[quality.md](../quality.md) の 2.2.1 節）。
- 本番：`search_visibility_drop` の理由ごとの数。ブロック・鍵の理由で落ちた件数が続けば、組み立ての漏れとして調べる。
