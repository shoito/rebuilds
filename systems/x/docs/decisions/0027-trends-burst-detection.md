# ADR-0027: トレンドは地域ごとに 5 分の区切りで「重み付きの一意の投稿者の数」を数え、基準との差をポアソンの揺れで割った点で急上昇を決める

詳細は [search-and-trends.md](../architecture/search-and-trends.md) の 9 節。

## Context

トレンドは、日本の利用者が「今、何が起きているか」を知る入口で、災害やテレビの実況で特に使われる。5 分ごとに更新する（NFR-007）。同時に、操作の的になる。

- 投稿の数で数えると、1 人の連投やボットの群れで、どの語でも上に出せる。
- 「多い語」を出すと、毎日同じ語（「おはよう」）が並ぶ。「今増えている語」を出す必要がある。
- 地域ごとに違う出来事がある（地方の地震、地方の催し）。地域の推定には個人データ（IP アドレス）が関わる（L4）。
- 措置・スパムの語を出してはいけない（NFR-011）。

## Options

数え方：

1. **語ごとに、区切りの中で 1 人 1 回、作者の信頼の重みで足した数**
2. 投稿の数
3. 一意の作者の数（重みなし、HyperLogLog）

検出：

- a. **直近 15 分の数 `c` と基準 `e`（指数移動平均、半減期 24 時間）から `z = (c − e) / sqrt(e + β)`、最低の人数と増え方の比の条件**
- b. 直近の数の上位
- c. 学習した異常検知のモデル

## Decision

1 と a を採用する。

- 語：ハッシュタグと、連続する名詞の 1〜3 の並び。1 投稿 10 語まで。リポストは数えない。
- 区切りは 5 分。`SET NX td:{bucket}:{author}:{term}` で 1 人 1 回にし、初めてのときだけ `ZINCRBY tc:{region}:{bucket}` に重み `w` を足す。
- 重み：`w = min(1, 経過日数/30) · (1 − spam_score)`。登録 7 日未満、スパムの点 0.7 以上、凍結・読み取りだけの措置、電話番号もメールも未確認のアカウントは 0。
- 検出：`β = 5`。`c ≥ 30`（全国）・`10`（地方）、`c / (e + 1) ≥ 3`。上位 50 を候補にし、除外の後に全国 30・地方 20 を出す。前回の語は `z < 0` か 2 時間まで残す。
- 候補の語ごとに、寄与した作者の新しいアカウントの割合と、本文の近さ（SimHash）の割合を測り、どちらかが 50% を超えたら出さずに T&S の待ち行列へ送る。
- T&S は `trend_overrides` で語を外せ、60 秒以内に反映する。
- 地域は全国と 8 つの地方。作者の設定の地方を使う。設定がない作者の IP アドレスからの推定は、L4 の確認まで使わない（全国にだけ数える）。トレンドは個人化しない。
- 値は自前の初期値で `ops.trends.*` に持つ。
- 2 を採らない理由：連投とボットで簡単に動く。
- 3 を採らない理由：新しいアカウント・スパムの作者を下げられない。語ごとに HyperLogLog を持つ記憶も大きい。
- b を採らない理由：毎日同じ語が並び、「今」の出来事が埋もれる。
- c を採らない理由：S1 は学習のデータがない。操作への強さを、説明できる規則で確かめたい。S2 で、a の上にモデルの点を足すかを検討する。

## Consequences

- 良くなること：
  - 1 人・新しいアカウント・スパムの作者が、トレンドを動かしにくい。重み 0 の作者はまったく動かせない。
  - 毎日の定番の語が出ず、急な増加が出る。
  - 説明できる式で、T&S が理由を調べられる。
- 引き受けるコスト：
  - 本当に新しい利用者の多い出来事（新しい催しの参加者）が、立ち上がりで低く出る。
  - 基準の写しと、毎時の書き出しを運用する。
  - 地方のトレンドは、L4 の確認まで設定のある作者だけで数えるので、件数が少ない。

## Confirmation

- 性質ベーステスト：PROP-TRND-001（1 人の寄与の上限）、PROP-TRND-002（重み 0 の作者で結果が変わらない）、PROP-TRND-003（除外の語が出ない）。
- 合成の試験：新しいアカウントの群れ・同じ文の貼り付け・連投が、トレンドに出ない。
- 本番：週ごとのトレンドの抜き取りの評価（操作・スパムと判断した割合）、待ち行列へ送った語の数。
