# Intent: Mercari を AI エージェント主体で再構築する

- Author: shoito
- Status: draft（2026-10-10 に土台の設計、領域の文書、統合と検証の工程を終えた。PM の受理を待つ）
- Date: 2026-10-10

## Problem

家にある使わない品を、知らない個人に売るには、次のところで困る。

- **出すのが面倒。** 写真を撮り、名前・説明・カテゴリ・状態を書き、値段を決めるのに時間がかかる。相場がわからず、安すぎるか高すぎて売れない。
- **相手が信用できない。** 先に払うと品が届かない。先に送ると代金が払われない。届いた品が説明と違う。偽ブランドや盗品が混ざる。
- **住所と名前を知られたくない。** 個人どうしの取引で、自宅の住所・氏名・電話番号を相手に渡したくない。
- **見つからない、売れ残る。** 似た品が数億件ある中で、欲しい品にたどり着けない。欲しい品が出たときに、すぐ知りたい。
- **お金の扱いがわからない。** 売れたお金がいつ手元に来るか、手数料がいくらか、売上金をそのまま次の買い物に使えるかが、わかりにくい。
- **売れた瞬間に取り合いになる。** 人気の品は、出た直後に数百人が同時に「購入」を押す。二人に売れたら、片方への謝罪と返金になる。

本家 Mercari は、これらを大きな規模で解いている。日本のマーケットプレイスの 2026 年 6 月期の第 4 四半期の月間の利用者は 2,419 万人、通期の流通総額（GMV）はおよそ 1.29 兆円である（出典は末尾）。代金は運営が預かり、買い手の受取評価の後に売り手の売上金になる。匿名の配送で住所を伏せる。この題材では、日本の市場を最初の対象に、小さなチームと AI エージェントで、これをどこまで作り直せるかを確かめる。核（取引の状態の機械、台帳、検索の順位付け、T&S のパイプライン、配送の指揮）は自分で設計する（[リポジトリ共通の ADR-0007](../../../docs/decisions/0007-no-reuse-of-original-implementation.md)）。

## Proposed outcome

個人が、スマートフォンで 1 分ほどで品を出し、知らない相手と安心して売り買いでき、売れたお金を次の買い物や口座への振込に使えるフリマを作る。次の 7 つの価値を満たす。

1. **二人に売らない**：1 つの出品から進行中の取引は、どんな並行度でも 1 つだけ（NFR-003）。
2. **お金が合う**：台帳の仕訳は常に釣り合い、預かり・手数料・売上金・返金の和が、決済の提供者と銀行の明細と一致する（NFR-004）。
3. **預かったお金は 1 回だけ動く**：1 つの取引の代金は、売り手の売上金への振り替えか、買い手への返金の、どちらか一方だけが 1 回起きる（NFR-005）。
4. **住所を知られない**：匿名の配送で、相手の住所・氏名・電話番号が、どの画面・通知・メッセージにも出ない（NFR-014）。
5. **出せばすぐ見つかる**：出品から検索に出るまで p95 10 秒（NFR-001）。欲しい品の新着が p95 5 分で届く（NFR-008）。
6. **偽物と禁止品が残らない**：偽ブランド・禁止品の出品の多くを公開の前後 60 秒で止め、通報で確かめたものを 24 時間以内に消す（NFR-009）。
7. **期限が守られる**：支払い・発送・受取評価・評価の期限が、決めた時刻から 1 分以内に必ず働く。紛争の間は止まる（NFR-012）。

### MVP（S1）に含める

- **アカウント**：電話番号の SMS による確認、メールアドレス、ログイン（パスキーと SMS の一時コード）、セッション、端末の一覧と取り消し、プロフィール、ブロック、退会
- **出品**：写真（1 出品 10 枚まで）の受け取りと処理（向きの補正、位置情報の除去、縮小、変換）、題名・説明、カテゴリ（3 階層）、状態（6 段階）、ブランド、サイズ、配送の方法と負担、発送までの日数、価格（300 円〜999 万 9,999 円）、下書き、編集、公開の停止、削除、再出品
- **価格の提案**：同じカテゴリ・ブランド・状態の、売れた品の直近の価格の分布から出す参考の値（統計。ML は MVP の後。[ADR-0010](decisions/0010-ml-boundary-for-pricing-and-recommendations.md)）
- **出品の質の検査**：必須の項目、写真の質（暗さ、小ささ）、禁止の語、題名とカテゴリの食い違いの警告
- **検索と発見**：日本語の全文検索（題名・説明・ブランド・カテゴリ）、絞り込み（カテゴリ、ブランド、価格、状態、配送料の負担、配送の方法、販売中・売り切れ）、集計（件数）、並べ替え（新しい順、価格、おすすめ）、売れた品の検索（相場の参考）、いいね、閲覧の履歴、基本のおすすめ（閲覧の履歴のカテゴリ・ブランドの新着と人気）
- **保存した検索**：検索の条件の保存（1 人 30 件まで）、新着の通知（まとめた通知）
- **取引**：購入（一品の一回の購入）、支払い（カード、コンビニ払い、売上金・ポイント）、発送の通知、配達、受取評価、相互の評価、売上金への振り替え、取引のメッセージ、キャンセル（双方の合意と期限切れ）、紛争（問題の報告と運用の介入）、自動の完了
- **値下げ交渉**：商品のコメントでの交渉と、売り手の価格の変更（決まった形の「オファー」の機能は MVP の後）
- **台帳と売上金**：複式簿記の台帳（預かり、手数料、売上金、ポイント、振込、返金）、売上金の残高と明細、売上金の期限（値は法務の L1 の後）、売上金・ポイントでの購入
- **振込**：口座の登録、振込の申請、振込の手数料、提携銀行の API での振込、振込の失敗の戻し
- **配送**：運送会社 2 社の匿名の配送（`<Brand>便`。QR・番号の発行、サイズと料金の表、追跡、配送の状態の Webhook）、匿名でない配送（追跡の番号の入力）、住所の秘匿
- **メッセージとコメント**：商品のコメント（公開）、取引のメッセージ（2 者）、悪用の絞り込み（禁止の語、連絡先の交換・外部の取引への誘導の検出）、通報
- **評価と信用**：取引ごとの相互の評価（良い・普通・残念）、評価の数、本人確認の印
- **T&S**：出品の同期の検査（禁止の語、禁止のハッシュ）、非同期の分類器（文字、画像、偽ブランドの疑い、価格の外れ値）、規則のエンジン、審査の待ち行列と画面、措置（非公開、削除、アカウントの制限・停止）、通報、異議の申し立て、不正（乗っ取りの兆し、偽の発送、チャージバック）
- **本人確認**：外部の eKYC の提供者（マイナンバーカードの IC と、書類と顔の照合）、確認の済んだ利用者の上限の引き上げ（範囲は法務の L1・L2 の後）
- **通知**：プッシュ（iOS・Android）、メール、アプリの中のお知らせ、取引の通知、いいねした品の値下げの通知、保存した検索の新着、配信の設定
- **運用と CS**：問い合わせの受け付け、取引への介入（期限の停止、キャンセル、返金、売上金の保留）、監査ログ、運用者の権限
- **アプリ**：iOS・Android・Web（買い手と売り手の両方）

| 越境の販売（海外の買い手） | 関税、海外の配送、データの所在の設計が要る |

| オークションの形式、ライブの販売 | 状態の機械と負荷の形が別になる |
| 梱包・集荷の代行、大型の品の配送 | 運送会社との別の契約が要る |

### 守るべき振る舞い

- 1 つの出品について、進行中の取引（キャンセル・期限切れで終わっていない取引）は 0 か 1。同時に 1 万人が購入を押しても 1。
- 購入で作る取引の価格は、買い手が購入の画面で見た価格と一致する。違えば取引を作らない。
- 台帳の各仕訳の借方と貸方の和は等しい。全口座の残高の和は 0。
- 1 つの取引の預かりは、売り手の売上金への振り替え（手数料を引く）か、買い手への返金の、どちらか一方に 1 回だけ動く。
- 売り手の売上金は、取引の完了から 1 分以内に残高に出る。
- 期限（支払い、発送、受取評価の自動の完了、評価）は、期限の時刻から 1 分以内に働く。紛争・運用の保留の間は働かない。
- 匿名の配送では、相手の住所・氏名・電話番号が、相手の画面・通知・メッセージ・API の応答に出ない。運用者にも、理由と監査のない閲覧を許さない。
- 運送会社の配送の状態の事象が、どんな順序・重複で届いても、取引の状態は後ろに戻らない。
- 措置した出品（偽ブランド、禁止品）は、措置から 60 秒以内に検索・おすすめ・通知から消え、購入できない。
- 本人だけのデータ（住所、売上金、口座、本人確認、閲覧の履歴、保存した検索）と、取引の 2 者だけのデータ（取引のメッセージ、配送の状態）は、他の利用者のどの経路にも出ない。

## Affected users and systems

- **売り手**：家の使わない品を売る個人。スマートフォンが中心。初めて売る人が多い。一部は数多く出す「多く売る個人」と、事業者に当たりうる人（法務の L3）。
- **買い手**：中古の品を安く探す個人。欲しい品の新着を待つ人、相場を調べる人を含む。
- **運用者・CS**：問い合わせの対応、取引への介入（キャンセル、返金、売上金の保留）、出品の審査、偽ブランドの確かめ、本人確認の例外、法令の照会への対応。
- **ブランドの権利者**：偽ブランドの通報、権利の侵害の申し出。運用と協力して確かめる。
- **運送会社**：匿名の配送の受け付け（QR・番号）、引き受け、配達、配送の状態の通知。ヤマト運輸と日本郵便を想定する（契約と API の能力は未確認）。
- **外部のシステム**：決済の提供者（カード、コンビニ払い）、提携銀行（振込）、eKYC の提供者、SMS の送信、プッシュ（APNs、FCM）、メールの送信、捜査機関・行政からの照会の窓口。

## Constraints

- **核を自前で設計する。** 取引の状態の機械、台帳、検索の順位付けと保存した検索の照合、T&S のパイプライン、配送の指揮は自分で作る。本家のコード・データ・モデルは使わない。検索のエンジン（OpenSearch）、機械学習の枠組み、決済・eKYC・運送会社の API は、核の外の汎用の部品・外部のサービスとして、理由を ADR に書いて使う（[リポジトリ共通の ADR-0007](../../../docs/decisions/0007-no-reuse-of-original-implementation.md)、[ADR-0001](decisions/0001-platform-and-stack.md)）。
- 実行基盤と技術は、rebuilds の他の題材の決定（AWS 東京・大阪、TypeScript・Hono、Aurora PostgreSQL、Valkey、S3、SQS・SNS、ECS Fargate、Terraform、OpenTelemetry、AppConfig のフラグ、FORCE RLS と `SET LOCAL`、UUIDv7、outbox）を引き継ぐ。外れるところ（分類器の学習と推論を Python で書くこと、検索のエンジン）は ADR に理由を書く。
- **カード処理を設計し直さない。** カード情報の保管、アクワイアラへの接続は Stripe の題材の論点である。この題材は、決済の提供者の API を使う側として設計する（[ADR-0005](decisions/0005-payments-via-providers-and-capture-at-purchase.md)）。
- 本家の名前は識別子に使わない。ドメインは `<brand>.<domain>`、配送の商品は `<Brand>便`、ヘッダーは `X-<Brand>-Client` の形で書く（[リポジトリ共通の ADR-0006](../../../docs/decisions/0006-brand-neutral-identifiers.md)）。
- データは日本（東京、DR は大阪）に置く。
- 日本の法令への対応は、法務の確認を前提に設計する。結論は出さない（下の「法務の確認待ち」）。
- 規模は段階的に広げる（[architecture/](architecture/README.md) の 2 節）。

## Non-goals

| 機能 | 理由 |
| --- | --- |
| カード情報の保管、アクワイアラへの直接の接続 | Stripe の題材の論点。提供者を通す（[ADR-0005](decisions/0005-payments-via-providers-and-capture-at-purchase.md)） |
| 本家の API・アプリとの互換、本家のデータの移し替え | 振る舞いは寄せるが、名前と形式は独自にする（リポジトリ共通の ADR-0006） |
| 自前の物流（倉庫、集荷、配達） | 運送会社の連携までにする（[ADR-0006](decisions/0006-shipping-orchestration-via-carriers.md)） |
| 自前の eKYC（書類の真贋、顔の照合のモデル） | 提供者を使う。本システムは結果と状態を持つ（identity-verification の領域） |
| 新品の小売、本システムによる仕入れと在庫 | C2C の場の提供にする |
| ML の結果だけでの自動の措置（アカウントの停止、売上金の没収） | 誤りの影響が大きい。規則と人の審査を通す（[ADR-0009](decisions/0009-trust-and-safety-pipeline-boundary.md)） |

### 選定・計測で決めるもの（法務以外）

- 人気の商品で、出品の行の条件つきの更新に同時に何件の要求を通してよいか、Valkey の先着の印の効き方：E7 の前の `hot-listing-purchase-poc`（[ADR-0002](decisions/0002-transaction-state-machine-and-single-purchase.md)）。
- 保存した検索の照合の方式（逆索引での候補の絞り込み）の速さと、1 日の新着の通知の量：E6 の前の `saved-search-matcher-poc`（search-and-discovery、saved-searches-and-alerts の各領域）。
- 日本語の解析（Sudachi の辞書と分割の単位、2-gram との組み合わせ）と、売れた品を含む索引の大きさ：E5 の前の `search-index-poc`（[ADR-0008](decisions/0008-search-engine-and-index.md)）。
- 偽ブランドの分類器の最初の評価：E14 の前の `counterfeit-classifier-poc`（[ADR-0009](decisions/0009-trust-and-safety-pipeline-boundary.md)）。
- 決済の提供者、提携銀行、eKYC の提供者、SMS の送信、運送会社の API（匿名の配送の受け付け、QR の発行、状態の Webhook）の選定：各 Epic の選定の Story。候補の名前は例で、能力は未確認である。
- 本家の振る舞いのうち、購入の後に決済が失敗したときの出品の戻し方、発送の期限を過ぎたときのキャンセルの規則、手数料の端数の扱い、振込の着金までの日数、偽ブランドの検出の方式は、公式の資料で確かめられなかった（**未検証**）。本システムの値を使う。売り手が評価しないときの完了（本家は受取評価の翌日以降に自動で完了）は、統合の工程で確かめた（出典）。本システムは 72 時間にした（[architecture/README.md](architecture/README.md) の 1.4 節）。
