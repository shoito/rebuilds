# Runbook: アカウントの乗っ取り（個別と大規模）

- Owner: Ops（当番）、T&S、セキュリティ
- 対応するアラート: 新しい端末の SMS のログインと口座の変更の急増、`account_holds` の始まりの急増、「これは私ではない」の急増、同じ口座の HMAC が多くのアカウントに登録された（page）
- 最終確認日: 2026-10-10

守りの設計は [accounts-and-devices.md](../architecture/accounts-and-devices.md) の 7 節（[ADR-0066](../decisions/0066-sign-in-sessions-and-devices.md)、[ADR-0067](../decisions/0067-account-takeover-step-up-and-payout-holds.md)）、脅威は [security.md](../architecture/security.md) の 3.1 節、不正の規則は [trust-and-safety.md](../architecture/trust-and-safety.md) の 13 節、ダッシュボードは [observability.md](../architecture/observability.md) の 6 節。

## 症状

- 新しい端末での SMS のログイン、電話番号・メール・口座の変更、振込の申請が、短い間に続くアカウントが増えた。
- SMS のコードの要求が、番号・IP・端末の帯で急増した（偽の SMS・偽のサイトでのコードの詐取の波）。
- 本人から「これは私ではない」が押された、または CS に申し出が来た。

## 影響

- 乗っ取りの狙いは売上金・残高の振込、残高での購入と転売、信用の高いアカウントでの詐欺の出品。
- 72 時間の振込の待ち（口座・電話番号・メールの変更、新しい端末の SMS のログイン、回復の後）で、多くは振込の前に止まる。

## 確認

1. 不正のダッシュボードで、`account_holds` の始まりの理由ごとの数、待っている振込の数と額、新しい口座の数、同じ口座の HMAC が 2 つ以上のアカウントにある数。
2. 攻撃の入口：SMS のコードの詐取（番号・IP の帯）、番号の再利用、端末の証明の失敗、データセンターの IP。
3. 影響のアカウントの数を、ID と数と理由のコードだけで数える。電話番号・メール・口座の番号を調べの記録に書かない。

## 対処

1. **個別のアカウント**：本人が「これは私ではない」を押すと、`locked`（全セッションの取り消し、振込の停止、口座と電話番号の変更を元に戻す依頼の CS の案件）になる（自動）。進行中の取引は続け、発送の画面と受取評価は CS が代わりに進められる。
2. **錠を解く**：パスキー＋CS の確認、または本人確認（eKYC）＋CS の確認。口座の番号の全桁を見るのは `vault.reveal_bank`（2 人目の承認）だけ。
3. **大規模**：
   - 72 時間の待ちは全員に効いているので、待ちを延ばす・自動で `locked` にする操作はしない（危険の点だけで錠をかけない。[ADR-0067](../decisions/0067-account-takeover-step-up-and-payout-holds.md)）。
   - T&S の規則（`payout_request` の `review`、4 時間）で、待ちの終わる前に人が審査する。売上金の保留と `locked` は審査員の判定（保留は 2 人の承認）。
   - SMS の要求の急増は、WAF の規則とチャレンジで絞る（[accounts-and-devices.md](../architecture/accounts-and-devices.md) の 4.2 節の上限）。
   - 新しい口座への振込を全体で止める判断は、Ops の責任者と T&S の責任者が行う。必要なら `ops.payouts_enabled` で振込の実行を止める（申請は受け付ける）。
4. **利用者への知らせ**：待ちの始まりの `security` の通知（全経路）が届いているかを確かめる。パスキーの登録を強く勧める知らせを出す（文言は CS と PM）。

## エスカレーション

- 1 時間に数百を超える `account_holds`、または待ちを越えた振込の不正の疑い：SEV2。T&S の責任者、セキュリティ、財務。
- 個人のデータの漏えいの報告の要否：**法務の確認待ち（L5）**。疑わしい取引の届出の要否：**法務の確認待ち（L2）**。

## 事後

- 入口（SMS の詐取、番号の再利用、端末の盗難）ごとに数え、守りの不足を `changes/` の `intent.md` に起票する。
- 一時に強めた WAF の規則と、全体の振込の停止を戻したことを確かめる。
- 72 時間の待ちの中で本人が気づいた割合（「これは私ではない」の数）を記録し、待ちの長さの見直しの材料にする。
