# Runbook: デプロイとロールバック

- Owner: Ops
- 対応するアラート: デプロイ中の自動ロールバック、デプロイの後の SLO の悪化
- 最終確認日: 2026-10-10

方針は [README.md](README.md) の 3 節、仕組みは [delivery.md](../architecture/delivery.md) の 4〜7 節（[ADR-0078](../decisions/0078-pipeline-schema-ordering-ledger-migrations-and-flag-governance.md)、[ADR-0079](../decisions/0079-app-release-trains-min-versions-and-model-releases.md)）。

## 症状

- 段階のデプロイ（見張りの利用者 → 5% → 25% → 100%）の中で、自動のロールバックが働いた。
- デプロイの後に、購入の 5xx・p99、照合の不一致、期限の遅れ、措置の反映の遅れ、検索の 5xx が悪化した。
- アプリの新しいバージョンのクラッシュのない率が 99.5% を下回った。

## 影響

- サービスの段階のデプロイでは、新しい組の割合の利用者に影響する。正しさの指標（照合、台帳の不変条件）は組で分けられないので、全体に影響しうる。

## 確認

1. デプロイの記録（`deployments`）で、対象のサービス、イメージのダイジェスト、段、ロールバックの理由を見る。
2. 新旧の組の指標を比べる（ALB の重みつきのターゲットグループごと）。
3. 同じ時間帯のマイグレーション（`schema_migrations`）、フラグ、`legal.*` の変更の有無。
4. 正しさの指標が 1 件でも出ていれば、[incident-response.md](incident-response.md) の SEV1 の候補として扱う。

## 対処

1. **フラグで戻せるものはフラグで戻す**（`release.*` を 0% に）。お金・取引の状態・期限の規則はフラグにしていないので、コードを戻す。
2. **サービス**：新しい組の重みを 0 にし、前のイメージのタスクで受ける。自動のロールバックが働かなかったときは、デプロイの関門の「戻す」の操作で同じことを行う（Ops の承認）。
3. **マイグレーション**：戻さない。広げる段だけなので、前のイメージが今の DB で動く。縮める段の後は前へ戻さない。
4. **台帳（`ledger`・`reconcilers`・`deadline-runner`）**：単独の日に出しているので、そのサービスだけを前のイメージに戻す。仕訳の誤りは打ち消しの仕訳で直す（財務の承認。[ledger-reconciliation-mismatch.md](ledger-reconciliation-mismatch.md)）。
5. **ML のモデルと T&S の規則**：`models.<name>.active_version`・`rules.<set>.active_version` を前のバージョンに戻す（デプロイなし）。
6. **アプリ**：App Store の段階のリリース・Google Play の段階の公開を止める。修正は臨時のバージョンで出す。お金と法令の表示、安全の修正のときだけ `ops.app_force_version_<platform>` を上げる（安全の修正を除き 14 日前から知らせる）。
7. **ホットフィックス**：`main` に入れて通常の段で出す。各段の 30 分は Ops の判断で 10 分に縮めてよい。凍結の中は作成者と別の Ops の承認。

## エスカレーション

- 戻しても正しさの指標が戻らない：IC を立て、Dev のテックリードと財務を呼ぶ（SEV1）。
- 守る物（部分一意の索引、仕訳の釣り合いのトリガー、RLS のポリシー）に触れたマイグレーションの後の異常：テックリード（ledger は財務も）。

## 事後

- 自動のロールバックの理由と、CI で捕まえられなかった理由を `changes/` の `intent.md` に起票する。
- 戻したイメージ・フラグ・モデルのバージョンの記録を確かめ、次のデプロイの前に修正を出す。
