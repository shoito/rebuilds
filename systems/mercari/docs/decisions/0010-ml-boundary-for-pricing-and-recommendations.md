# ADR-0010: 価格の提案とおすすめの ML は助言と順位だけにする。MVP の価格の提案は売れた品の統計、おすすめは規則にする。ML のモデルは MVP の後に、影の評価を通してから出す。出品の価格・手数料・見える範囲を ML で変えない

## Context

- 売り手は値段の決め方がわからない。売れた品の相場を出品の画面で示すと、出品が速くなり、売れ残りが減る（K10）。
- 買い手には、閲覧の履歴・いいね・保存した検索に近い新着と人気の出品を示したい。
- 本家は価格の提案とおすすめを持つ（方式は公式の資料で確かめられなかった。**未検証**）。
- MVP の始めには、本システムの取引のデータがない。ML のモデルを学習できるのは、取引が貯まってからである。
- 価格の表示は、景品表示法（二重価格表示、誤認）の観点で法務の確認待ち（L4）。閲覧の履歴の利用は個人情報保護法の観点で法務の確認待ち（L5）。
- YouTube の題材は、ML の出力を順位だけにし、見える範囲を ML で変えない、とした（[YouTube の ADR-0010](../../../youtube/docs/decisions/0010-recommendation-boundary.md)）。

## Options

1. **ML は助言と順位だけ。MVP は統計と規則で始め、ML は MVP の後に影の評価を通して出す**
2. MVP から ML のモデル（外部の汎用のモデル）で価格を提案する
3. 価格の提案を出さない

## Decision

1 を採用する。

### 価格の提案（MVP）

- 同じカテゴリ（最も深い階層）・ブランド・状態の、直近 90 日に売れた出品の価格の四分位（25%・50%・75%）と件数を出す。件数が 20 に満たなければ、状態を外し、次に親のカテゴリへ広げ、広げたことを示す。
- 値は `ml-inference` の統計の関数が、検索の索引の売れた品から日次で計算し、Valkey に置く。出品の画面は値を読むだけ。
- 出品の画面には「同じような品が売れた価格」として幅を出し、価格の欄には自動で入れない。売り手が選ぶ（「中央の値を使う」のボタンは置いてよい）。表示の文言は法務の L4 の後に確定する。
- 売れた品が少ないカテゴリ（件数が親のカテゴリまで広げても 20 未満）では出さない。

### おすすめ（MVP）

- 規則の候補：閲覧の履歴・いいねの直近のカテゴリ × ブランドの新着、保存した検索の新着、同じカテゴリの人気（いいねの数の増え方）。
- 並べ方は決めた式（新しさ、人気、閲覧の履歴との近さ）。式は search-and-discovery の領域で決める。
- 閲覧の履歴を使わない設定を持ち、選んだ利用者には履歴を使わない候補だけを出す。範囲は法務の L5 の後に確定する。

### ML（MVP の後）

- ML のモデル（価格の回帰、学習した順位の式、おすすめの候補の生成）は、データレイクの仮名にした取引・閲覧の事象で、自前で学習する。
- 出す前に、オフラインの評価（価格の提案の誤差、順位の指標）と、影の評価（本番の要求で計算し、表示しない）で、統計・規則の方式との差を確かめる。
- **境界**：
  - 価格の ML の出力は、提案の幅と信頼の度合いだけ。出品の価格、手数料、送料、売上金の計算に使わない。
  - 順位の ML の出力は、候補の並べ替えだけ。`listingVisible()`、絞り込みの条件、措置、ブロックを ML の点で変えない。絞り込みは点の後にもう一度通す（[ADR-0007](0007-single-tenant-and-party-visibility.md)）。
  - T&S の分類器は別の境界（[ADR-0009](0009-trust-and-safety-pipeline-boundary.md)）。

### 他の案を選ばなかった理由

- **2（MVP から ML）**：本システムの取引のデータがなく、汎用のモデルはフリマの相場（状態、付属品、季節）を知らない。誤った提案は売り手の損になる。
- **3（出さない）**：出品の速さ（K10）と、相場のわからない売り手の困りごとを放置する。

## Consequences

- 良くなること：
  - MVP で、データなしに説明のつく価格の提案とおすすめを出せる。
  - ML を入れても、お金と見える範囲の規則は変わらない。
- 引き受けるコスト：
  - 統計の提案は、件数の少ない品・状態の差の大きい品で外れる。幅と件数を示して、売り手に判断を残す。
  - ML を入れるときに、影の評価の仕組みとデータレイクの準備が要る。

## Confirmation

- 単体テスト：四分位の計算、件数の不足での広げ方、出さない条件。
- 性質ベーステスト：価格の提案の値が、出品の価格・手数料・売上金の計算の入力に現れない（依存の lint と、計算の関数の入力の型）。順位の後の結果が、順位の前の絞り込みの結果の部分集合である。
- ML を出すときの合否の基準は、MVP の後の Epic の `quality.md` で決める。
