# ADR-0070: 運用者は案件に結び付く 2 時間の JIT の権限で見る。住所・口座の番号・本人確認の記録は「見せる」操作に分け、2 人目の承認、1 回 1 件、運用者ごとに 1 日 20 件までにし、持ち主のサービスが 1 件だけ復号して返す。本番の DB への人の接続は 2 人の承認の break-glass の読み出しだけ。監査の事象は操作と同じトランザクションで書き、ハッシュの鎖で別のアカウントの Object Lock に写す

## Context

- CS・T&S・財務は、紛争・配送の事故・措置・照会で、取引の情報、ときに住所・口座・本人確認を見る必要がある。
- [ADR-0007](0007-single-tenant-and-party-visibility.md) は、運用者は RLS を外す役割を持たず、案件に結び付く JIT の権限で見るとした。住所・本人確認・口座の番号は権限の種類を分けるとした。
- 住所の金庫は、内部の者が大量に持ち出すと、利用者の安全に直結する。1 件ずつの正当な閲覧と、大量の持ち出しを分けたい。
- 取引のメッセージを運用者が見る範囲は法務の確認待ち（L11）。照会への回答は法務の確認待ち（L6・L7）。
- Gmail の題材は、運用者に中身の読みの権限を与えず、監査を流れごとのハッシュの鎖で別のアカウントの Object Lock に写した（[Gmail の ADR-0061](../../../gmail/docs/decisions/0061-operator-access-cross-tenant-paths-and-audit.md)）。

## Options

1. **案件の JIT の権限、見せる操作の承認と上限、持ち主のサービスが 1 件だけ復号、同じトランザクションの監査とハッシュの鎖**
2. 運用者の役割に金庫の復号の権限を置き、監査ログで後から見る
3. 運用者に住所を一切見せない（運送会社の窓口に任せる）

## Decision

1 を採用する。詳細は [security.md](../architecture/security.md) の 6 節。

- 権限の種類：`case.view`、`case.view_messages`（通報・紛争のメッセージに限る）、`vault.reveal_address`、`vault.reveal_bank`、`kyc.view`、`ledger.adjust`、`legal.respond`。
- JIT：`ops-api` が案件に結び付けて 2 時間で発行。理由のコードと短い自由文（監査の中に暗号化）。運用者のログインは SSO とフィッシングに強い MFA、運用の画面はエッジで社の出口の IP に絞る。
- 見せる操作：2 人目（別のリーダー）の承認。`ops-api` が持ち主のサービスを権限の証（署名つき、5 分）とともに呼び、持ち主のサービスが 1 件だけ復号して返す。画面は運用者の ID の透かしつき、`no-store`。1 日 20 件を超える依頼は `legal.respond` の書き出しの手順を通す。見せた数を毎週確かめる。
- 本番の DB・タスクへの人の接続：break-glass の読み出しの権限のセットを、2 人の承認で 4 時間。Session Manager の記録を残す。金庫の復号の権限を含めない。データの修正はレビューを通したスクリプトを CI から流す。台帳は打ち消しの仕訳だけ。
- 監査：操作と同じトランザクションで、そのクラスタの `audit_events` に書く。`relay` が流れごとに `prev_hash` の鎖を付けて log-archive の S3（Object Lock のコンプライアンスのモード）へ 5 分ごとに写す。日次で鎖と件数を照らす。保持の既定は 7 年（法務の確認待ち：L5・L2）。

### 他の案を選ばなかった理由

- **2（運用者に復号の権限）**：監査は事後で、大量の持ち出しを止められない。運用者の資格の盗難が、そのまま全利用者の住所の漏れになる。
- **3（一切見せない）**：配送の事故・紛争・照会で、本システムが運送会社と話す手段がなくなる。正当な閲覧を止められない用途がある。

## Consequences

- 良くなること：
  - 1 人の運用者の資格の盗難で見られる住所は、1 日 20 件と承認者の数で限られる。
  - 監査の欠けと改ざんを日次で見つけられる。
- 引き受けるコスト：
  - 見せる操作のたびに 2 人目が要り、CS の対応が遅れる。リーダーの当番を置く。
  - 照会で多くの件数が要るときは、別の手順（`legal.respond`）が要る。

## Confirmation

- 表駆動テスト：見せる操作の拒否（承認なし、期限切れ、別の案件、21 件目）。
- 性質ベーステスト：監査の鎖の欠け・入れ替え・書き換えを検出する（PROP-SEC-003）。
- plan のポリシー検査：人の権限のセットに金庫の復号の権限がない。
- E18 の外部のペンテストで運用の画面を対象にする。
