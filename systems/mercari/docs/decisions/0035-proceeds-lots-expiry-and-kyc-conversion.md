# ADR-0035: 売上金を入った単位のロットで持ち、使うときは期限の近い順に消す。期限・期限の後の扱い・本人確認での残高への移し替えは `legal.*` の値で動かし、有効にした日より前に遡って期限を付けない。本番の既定はすべて無効

## Context

- [ADR-0004](0004-proceeds-model-under-payment-services-act.md) は、売上金（`proceeds`）・残高（`balance`）・ポイントを別の口座の種類にし、期限の日数・期限の後の扱い・本人確認の要否を `legal.*` に置くと決めた。法務の L1 の結論まで本番では期限・失効・移し替えを無効にする。
- 本家は、売上金に 180 日の振込の申請の期限を置き、本人確認で期限のない残高にする。期限の後は自動で振り込み（2 回まで）、口座がないか 200 円以下なら失効する（[ヘルプの記事 96](https://help.jp.mercari.com/guide/articles/96/)、2026-10-10 に確認）。
- 期限は入ったお金ごとに違う。口座の残高 1 つでは、どの部分がいつ期限になるかわからない。
- 振込の失敗・保留の解除・購入の失敗で、出たお金が戻る。戻ったお金の期限を決める規則が要る。
- 期限を後から有効にしたとき、過去に入った売上金がすぐ期限切れになりうる。

## Options

1. **ロット（入った単位）で持ち、期限の近い順に消す。戻しは消した記録の通りに元のロットへ**
2. 口座の残高だけを持ち、期限は「最後に入った日から N 日」とする
3. 入った単位の口座（ロットごとの口座）を作る

## Decision

1 を採用する。詳細と例は [ledger-and-proceeds.md](../architecture/ledger-and-proceeds.md) の 6 節。

- `seller_proceeds` への入りはロット（額、残り、入った時刻、期限）を作る。出は「期限の近い順（期限なしは最後）→ 入った順」で消し、`proceeds_lot_consumptions` に記録する。
- 出を戻す仕訳は、消した記録の通りに元のロットへ戻す。ロットの期限は変えない。
- 不変条件：利用者ごとに、ロットの残りの和 = `seller_proceeds` の残高。照合の第 2 段で確かめる。
- 期限は `legal.proceeds_expiry_enabled` が真のときだけ付ける。期限 = 入った日 ＋ `legal.proceeds_expiry_days` 日の 23:59:59（日本時間）。有効にした日より前のロットは「有効にした日 ＋ 日数」から数える（遡らない）。遡りの可否は法務の確認待ち（L1）。
- 期限の処理は毎日 00:10。`legal.proceeds_expiry_actions` の順（開発の値は `auto_payout`、`auto_payout`、`forfeit`）で扱う。`auto_payout` は口座があり額が振込の手数料を超えるときだけ。`forfeit` は `legal.proceeds_forfeit_enabled` のときだけ書き、無効なら CS の待ち行列に出す。
- 本人確認の水準が `legal.balance_requires_kyc_level` に届き、`legal.balance_enabled` なら、残りのロットを `user_balance` に移す（型 `proceeds_to_balance`）。以後の release も直後に移す。`legal.balance_max_yen` を超える分はロットに残す。
- 本番の既定は、期限・失効・移し替え・売上金での購入のすべてを無効にする。

### 他の案を選ばなかった理由

- **2**：本家の振る舞い（入ったお金ごとの期限）と違い、売れ続ける売り手の売上金は永遠に期限にならない。法務の結論がロットの形を求めたときに作り直しになる。
- **3**：口座の数が取引の数に比例して増え、残高の読み出しが口座の和になる。ロットは台帳の口座の外の補助の表で足りる。

## Consequences

- 良くなること：
  - 法務の結論（期限あり・なし、残高への移し替え）に、値の変更だけで合わせられる。
  - 戻しで期限が延びないので、振込の失敗を繰り返して期限を延ばす道がない。
- 引き受けるコスト：
  - 出のたびにロットの消費を書く。1 つの出で消すロットの数は、多く売る売り手で数百になりうる。1 回の出で消すロットを 500 までにし、超える額の出は分けて書く。
  - ロットと口座の残高の一致を照合で見続ける。

## Confirmation

- 性質ベーステスト：PROP-LED-005（ロットの和 = 残高、戻しで期限が変わらない）、PROP-LED-006（`legal.*` の全組み合わせ）。
- 仮想の時計の試験：180 日の数え方、通知の日（30・7・1 日前）、自動の振込の失敗と 2 回目、失効の有効・無効、本人確認の移し替え。
- 設定の検査（CI）：本番の構成で `legal.proceeds_expiry_enabled`・`legal.proceeds_forfeit_enabled`・`legal.balance_enabled` が、法務の承認の記録なしに真にならないこと。
