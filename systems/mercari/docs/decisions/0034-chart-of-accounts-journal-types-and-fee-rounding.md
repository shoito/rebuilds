# ADR-0034: 勘定科目を 22 の口座の種類に確定し、仕訳の型を 30（表の 28 行）に固定する。手数料は `floor(価格 × 率の基点 / 10,000)`、率と送料はバージョンの付いた表で取引の作成の時に固定する。売上金が負になる送料の組み合わせは出品と発送の時に止める

## Context

- [ADR-0003](0003-escrow-and-double-entry-ledger.md) は MVP の口座の種類（14）と取引の仕訳（5）を決め、手数料の端数を「1 円未満は切り捨て」とした（[architecture/README.md](../architecture/README.md) の 6 節）。
- payments-and-escrow・payouts-and-points・disputes-and-customer-support の各領域で、口座と型が要る場面が増えた：チャージバックの引き落とし、期限の後の入金、売上金の保留、提供者の手数料、ポイントと売上金の失効、振込の失敗と組戻し、提供者の精算、運送会社への支払い、仮勘定の解消。
- 型の追加が領域ごとにばらばらだと、照合と監査が型の一覧を持てない。型は `release.*` のフラグで切り替えない規則がある（AGENTS.md）。
- 手数料の率を小数で持つと、端数の誤りが出る。最低価格 300 円の出品に高い送料を選ぶと、売上金が負になる。

## Options

1. **口座の種類と型を 1 つの表に固定し、型の追加を ADR の更新とする。率は基点の整数、端数は切り捨て。売上金が負になる組み合わせは入口で止める**
2. 領域ごとに口座と型を足す
3. 売上金が負になったら、売り手の未収（`seller_receivable`）として持つ

## Decision

1 を採用する。表は [ledger-and-proceeds.md](../architecture/ledger-and-proceeds.md) の 4・5 節。

- 口座の種類は 22。ADR-0003 の 14 に、`psp_chargeback_held`、`seller_proceeds_held`、`user_balance`（ADR-0004 の `balance`）、`unapplied_payments`、`chargeback_loss_expense`、`psp_fee_expense`、`points_breakage`、`proceeds_forfeiture` を足した。`fee_revenue` は手数料の種類（`sales`・`payment`・`payout`）を副の鍵に持つ。
- 残高の行は口座の「正常な側」で正の数に直して持ち、売上金・保留・残高・引き当て・ポイント・預かり・振込中・チャージバックの持ち分は負にならない（CHECK）。
- 仕訳の型は 30。型ごとに冪等キーの形と借方・貸方の口座を固定する。型の追加・変更は、この ADR の後継か改訂と、表の更新を要する。
- 手数料：`sales_fee = floor(price × sales_fee_bp / 10,000)`。率は基点の整数で、カテゴリごとの行を持つ手数料の表のバージョンで固定する（既定 1,000 bp）。支払いの手数料・振込の手数料も同じ表に持つ。取引は作成の時のバージョンを記録し、完了でもそれを使う。
- 売上金 = 価格 − 販売の手数料 − 送料（売り手の負担のとき）。これが負になる出品と、発送の時のサイズの変更を止める。
- 消費税の扱いは法務の確認待ち（L8）。表に税率の列を置き、値は確認の後に入れる。

### 他の案を選ばなかった理由

- **2**：照合の規則（どの型がどの外部の行に当たるか）が型の一覧を持てない。
- **3**：負の売上金の回収の流れ（督促、振込の停止）が要り、最低価格の取引で毎回起きうる。入口で止めるほうが単純。

## Consequences

- 良くなること：
  - 口座と型の一覧が 1 つで、照合・監査・会計の出力の対応を作れる。
  - 手数料の計算が 1 か所で、表のバージョンで再現できる。
- 引き受けるコスト：
  - 新しいお金の流れ（MVP の後の事業者の出品、後払い）は、型の追加の ADR から始まる。
  - 低い価格の出品で選べる配送の方法が減る。出品の画面で理由を示す（listings-and-photos の領域）。

## Confirmation

- 表駆動テスト：型の全行の借方・貸方、手数料の端数の試験のベクトル（価格 300、333、9,999,999 など）。
- 性質ベーステスト：PROP-LED-001・003・004。
- CI：仕訳を書くコードが、型の表にない型・口座の組を書かないこと（`packages/ledger` の型の検査）。
