# ADR-0025: DT-TXN-001 を 38 行で確定する。期限は 5 つの列と `next_deadline_at` で持ち、紛争・運用の保留の間は止め、再開で止めた時間だけ全部の期限をずらす。期限を前に動かす変更はしない

## Context

- [ADR-0002](0002-transaction-state-machine-and-single-purchase.md) は、取引の状態と、決定表 DT-TXN-001 の草案（17 行）と、期限の表を決めた。確定した表は transactions-and-state-machine の領域で書く、とした。
- 草案にない場面がある：運用の保留、支払いの期限の照会が不明のとき、T&S の措置による取り消し、発送の期限切れの後の申し出、申し出の間の引き受け、運送会社の例外、`received` の後のチャージバック、運用の判断の結論の種類。
- 紛争の停止は「止めた時間を足して延ばす」とだけ決まっている。期限が複数あるとき、紛争と保留が重なるとき、遅れた事象が期限を早めうるときの規則がない。
- 本家は、問い合わせで自動の完了が止まる（[ヘルプの記事 61sell](https://help.jp.mercari.com/guide/articles/61sell/)、2026-10-10 に確認）。止めた後の延び方は書いていない（**未検証**）。

## Options

停止の後の期限：

1. **止めた時間だけ、生きている期限をすべて後ろへずらす**
2. 再開の時に、期限を決め直す（例：再開から 24 時間の下限を置く）
3. 再開で期限を最初から数え直す

## Decision

1 を採用する。決定表の全行は [transactions-and-state-machine.md](../architecture/transactions-and-state-machine.md) の 6.2 節。

- DT-TXN-001 は 38 行。草案の 17 行の意味は変えず、上の場面の行を足した。最後の行は「どれにも当たらなければ 422」。
- 期限の列は `payment_due_at`・`ship_due_at`・`cancel_response_due_at`・`auto_receive_at`・`seller_rating_due_at`。状態ごとに生きている列の最小を `next_deadline_at` に書き、`deadline-runner` はこの 1 列の部分索引で拾う。
- 止める（紛争・保留）：`paused_at` を記録し、`next_deadline_at` を NULL にする。列の値は変えない。
- ずらす（紛争の解消・保留の解除）：`d = now() − paused_at` を生きている列すべてに足し、`paused_seconds` に積む。紛争と保留が重なったら、両方が解けたときに 1 回だけずらす。
- 期限を前に動かさない。遅れて届いた引き受けの事象の時刻で `auto_receive_at` を早めない。引き受けの時刻は、受け取った時刻より 48 時間を超えて前なら、受け取った時刻に置き換える。
- 支払いの期限で照会の結果が不明なら、遷移せず 5 分後に再び拾う。1 時間でチケット。
- 期限の遷移も、他の事象と同じ遷移の関数と決定表を通る。期限の行は「期限の列が `now()` より後なら何もしない」を持ち、ずらした後の古い起動を無害にする。

> 2026-10-10 の注記：大阪への切り替え（[ADR-0073](0073-aurora-layout-osaka-dr-and-ledger-rpo.md)）の間も、同じ「ずらす」を全体に当てる。切り替えの間は `deadline-runner` を止め、再開の前に、終わっていない取引の生きている期限を止まった時間だけ後ろへずらす（`dr_events` に時刻を記録）。利用者の責任でない期限切れを作らないため（統合の工程で [infrastructure.md](../architecture/infrastructure.md) の 7.3 節の提案を採った）。

### 他の案を選ばなかった理由

- **2（下限を置く）**：期限の直前の紛争で、期限が「3 日延びる」ではなくなる。品質の試験（[quality.md](../quality.md) の 2.2.1 節 C）の期待と合わず、利用者への説明も複雑になる。
- **3（数え直す）**：紛争を開くだけで期限を伸ばせる。悪用の道になる。

## Consequences

- 良くなること：
  - 期限の拾い方が 1 つの索引になり、停止と再開が列の更新だけで済む。
  - 全行が表になり、表駆動テストで全行に到達できる。
- 引き受けるコスト：
  - 期限の直前に紛争を開き、すぐ解消すると、利用者に残る時間は短い。通知で残りの時間を示す（notifications の領域）。
  - 自動の完了の 13:00 の揃いは、ずらした取引では崩れる。

## Confirmation

- 表駆動テスト：DT-TXN-001 の全 38 行。
- 仮想の時計の試験：期限の 1 時間前の紛争を 3 日後に解消すると、期限が 3 日延びる。紛争と保留の重なり。遅れた引き受けの事象で期限が早まらない。
- 性質ベーステスト：PROP-TXN-006（期限は前に働かない）、PROP-TXN-007（受取評価を経る）。
