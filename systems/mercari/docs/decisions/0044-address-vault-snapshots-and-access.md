# ADR-0044: 購入の時に配送先と差出人を配送ごとの写し（`shipment_addresses`）にし、以後の住所録の変更から切り離す。復号は `openAddress(purpose, subject)` の 1 つの関数だけが、5 つの目的のコードで行い、すべて監査に残す。写しは取引の終わりから 180 日で消し、保全の印があれば残す（期間は法務の確認待ち L5）

## Context

- [ADR-0006](0006-shipping-orchestration-via-carriers.md) は、住所・氏名・電話番号を core の金庫（`address_vault`）に封筒の暗号化で置き、復号は `shipping` の役割だけ、運送会社へ渡すときだけ、運用者は JIT の権限と理由と監査でだけ、と決めた。
- 鍵の配置（利用者ごと・金庫ごとの鍵、`kms-vault-address`、平文の鍵の 5 分のキャッシュ、鍵の破棄による消去）は security の領域が決めた（[ADR-0069](0069-key-layout-and-vault-envelope-encryption.md)）。運用者の「見せる」操作（`vault.reveal_address`、2 人目の承認、1 回 1 件）も同じ領域が決めた（[ADR-0070](0070-operator-access-vault-reveal-and-audit.md)）。保持の既定（配送の受け付けに使った住所は取引の終わりから 180 日）は [ADR-0071](0071-data-classes-and-lifecycle.md)。
- 配送の側に残る問いがある。購入の後に住所録を直したら、どの住所に送るか。返送・事故・照会で、終わった取引の住所をどう読むか。匿名でない配送で、売り手に買い手の住所をどう出すか。復号の経路が増えたときに、目的の外の復号をどう止めるか。
- 運送会社へ渡すことの整理と保存の期間は法務の確認待ち（L5）。

## Options

1. **購入の時に配送ごとの写しを作る。復号は目的のコードを持つ 1 つの関数だけ。写しは保持の期間で消し、保全の印で残す**
2. 配送は住所録の行を指し、写しを作らない
3. 住所を運送会社に渡した後、本システムでは持たない

## Decision

1 を採用する。詳細は [shipping-integrations.md](../architecture/shipping-integrations.md) の 7 節。

- `transaction.created` を受けて、買い手の配送先と売り手の差出人を `shipment_addresses` に写す。暗号化は ADR-0069 の形（それぞれの利用者の鍵）。以後の住所録の変更・削除は、進行中の配送と返送の宛先を変えない。
- 復号は `packages/shipping` の `openAddress(purpose, subject)` だけが行う。目的のコードは `create_shipment`、`return_shipment`、`owner_view`、`reveal_to_counterparty`、`ops_reveal`。目的ごとに、呼べる主体と渡す先を固定する（運送会社の API、本人の端末、売り手の取引の画面、運用の画面）。
- `reveal_to_counterparty` は、匿名でない配送で双方が同意し、売り手の本人確認が済んだ後だけ。`ops_reveal` は ADR-0070 の `vault.reveal_address`（2 人目の承認、1 回 1 件、1 日 20 件まで）。
- 復号のたびに、目的・主体・対象の ID を監査の事象に書く（値は書かない）。
- 写しは取引の終わりから 180 日で行を消す（ADR-0071 の既定）。紛争・法令の照会の保全（`legal_hold`）がある取引は消さず、解いた日から数え直す。
- 運送会社の Webhook の生の本文は、住所の欄を落としてから保存する。

### 他の案を選ばなかった理由

- **2**：住所録の変更・削除・退会で、進行中の配送と返送の宛先が変わるか消える。
- **3**：返送・事故・照会のたびに運送会社から住所を取り戻す手順が要り、運送会社の能力に依る（未確認）。

## Consequences

- 良くなること：
  - 住所の出口が 1 つの関数と目的のコードに絞られ、目的ごとに監査と試験ができる。
  - 配送の宛先が購入の時に固定される。
- 引き受けるコスト：
  - 写しの分、住所の暗号文が増える（取引の数に比例。180 日で消える）。
  - 保全の印の付け外しを、紛争と法令の照会の手順に入れる。

## Confirmation

- 単体・表駆動テスト：目的のコードごとの主体と渡す先。目的のない復号の呼び出しは型の検査で書けない。
- 漏れの経路の表（[quality.md](../quality.md) の 2.2.1 節 G）の全行。
- 結合テスト：住所録の変更の後も配送の宛先が変わらない、180 日の後に写しがない、保全の印のある取引は残る、復号の監査の事象が目的ごとに残る。
