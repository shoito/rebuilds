# ADR-0075: SLI は runbooks の定義ごとに 1 つの指標の名前と数える場所を持つ。速さの SLI は全件の時刻の差で測り、見張りは可用性と端から端の確かめに使う。正しさの SLI は照合の不一致の数と、照合の最後の成功からの時間の対で見て、照合が止まった間の 0 を良いとしない。計装は属性の許可の一覧で、利用者・出品・取引の ID をメトリクスのラベルにしない

## Context

- [runbooks/](../runbooks/README.md) の 1 節は、購入の可用性と速さ、出品から検索まで、二重の販売、振り替えの一回性、台帳の不変条件、3 者の照合、期限の遅れ、通知の遅れ、措置の反映、見える範囲などの SLI と SLO を決めた。計り方はこの領域で決める。
- この題材の最悪の障害（二重の販売、二重の振り替え）は、エラーにならず、照合でしか見つからない（[quality.md](../quality.md) の冒頭）。照合のジョブが止まると、不一致の数は 0 のまま見える。
- 見張りの出品だけで「出品から検索まで」を測ると、1 分に 1 件の標本で p95・p99 を語ることになり、実際の出品の遅れの分布を見落とす。
- ログとトレースに利用者のデータを出さない（[AGENTS.md](../../AGENTS.md)）。利用者の ID をメトリクスのラベルにすると、基数が爆発し、個人の行動の記録にもなる。

## Options

1. **全件の時刻の差で速さを測り、正しさは不一致と最後の成功の対で見る。見張りは可用性。属性は許可の一覧**
2. 見張り（合成）で SLI を測る
3. ログの集計（ログから後で数える）で SLI を測る

## Decision

1 を採用する。詳細は [observability.md](../architecture/observability.md) の 2〜4 節。

- SLI ごとの指標の名前と数える場所を表で持つ（`purchase_requests_total{outcome}`、`listing_searchable_seconds`、`recon_listing_txn_mismatches`、`recon_txn_ledger_mismatches{kind}`、`ledger_invariant_violations{check}`、`ledger_suspense_yen{age}`、`deadline_lag_seconds`、`notification_delay_seconds{class,channel}`、`moderation_propagation_seconds{surface}`、`visibility_audit_mismatches{surface}` など）。
- 速さの SLI は、処理の持ち主が全件の時刻の差をヒストグラムで出す。購入の速さは提供者のスパンの時間を引く。
- 正しさの SLI は、不一致の数と `..._last_success_timestamp_seconds` の対で出し、照合の間隔の 2 倍を過ぎたら不一致と同じ重さで呼び出す。
- 見張りの利用者・出品は `sentinel` の印で SLI から除き、`canary_*` の指標にする。canary のアカウントから 15 分ごとに、出品 → 検索 → 購入 → 発送 → 完了 → 売上金 → 通知を確かめる。
- 計装は属性の許可の一覧（`packages/telemetry`）。金庫と 2 者の型をロガーに渡せない。ラベルに利用者・出品・取引の ID、IP、検索の語を使わない。熱い出品は「枠」の番号で見る。
- アラートの規則は runbooks の表から生成する。

### 他の案を選ばなかった理由

- **2（見張りで測る）**：標本が少なく、実際の利用者の分布を表さない。見張りの経路だけが速い（キャッシュに乗る）ことがある。
- **3（ログの集計）**：ログの遅れと抜き取りで SLI が遅れ、欠ける。ログに個人のデータを出さない規則のもとで、必要な欄を全部ログに出すことになる。

## Consequences

- 良くなること：
  - 照合の停止を、二重の販売の見逃しと同じ重さで扱える。
  - 実際の出品・通知の遅れの分布を見られる。
  - 計装から個人のデータが漏れない形を型で守れる。
- 引き受けるコスト：
  - 各処理の持ち主が、時刻の差の計測を実装する。
  - 熱い出品の枠と出品の対応を運用の画面で引く手間がある。

## Confirmation

- 性質ベーステスト：ログ・スパンの属性は許可の一覧だけ（PROP-OBS-001）。
- CI：全 SLI のアラートの規則が、バーンレートと最後の成功の対を持つ。注釈に手順の URL がある。
- staging：照合のジョブを止めて、最後の成功のアラートが鳴る。
