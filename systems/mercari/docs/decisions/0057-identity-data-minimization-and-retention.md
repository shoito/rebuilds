# ADR-0057: 本システムは確認の結果・方式・提供者の参照・時刻と、確認した属性（氏名、カナ、生年月日、住所）を `identity` の鍵の封筒の暗号化で持つ。書類と顔の画像は本システムの S3 に置かない。同じ人の検出はカナの氏名と生年月日の秘密の鍵の HMAC の指紋で行う。保存の期間と削除は `legal.kyc_*` に置き、結論まで記録を消さない

詳細は [identity-verification.md](../architecture/identity-verification.md) の 6.3・7 節。

## Context

- 本人確認の書類と顔の画像は、漏れたときの害が最も大きいデータの 1 つ。本システムは書類の画像を長く持たない（[architecture/README.md](../architecture/README.md) の 6 節）。
- 振込の口座の名義の照合、年齢の判定、同じ人の複数のアカウントの検出に、確認した属性が要る。
- 確認の記録の保存の期間（犯罪収益移転防止法）、利用目的と退会の後の保持（個人情報保護法）は法務の確認待ち（L2・L5）。
- 本人確認のデータは本人だけのデータで、運用者は別の種類の権限で見る（[ADR-0007](0007-single-tenant-and-party-visibility.md)）。

## Options

1. **結果と属性を封筒の暗号化で持ち、画像は提供者だけ。指紋は HMAC**
2. 画像を本システムの S3 に写して持つ
3. 結果の真偽だけを持ち、属性を持たない

## Decision

1 を採用する。

- `kyc_records`：水準、方式、提供者、提供者の参照、確認の時刻、`attributes_ct`（`identity` の KMS の鍵の封筒の暗号化）、`age_band`。FORCE RLS。運用者は `kyc_viewer` の JIT と監査で見る。
- 画像と IC の読み取りの中身は、提供者の SDK と提供者のサーバーの間だけで流れ、本システムのサーバー・ログ・S3 を通らない。提供者の保存の期間は法務の結論の後に設定する（`legal.kyc_provider_retention_days`）。
- 属性の使い道：口座の名義の照合（真偽だけを返す）、年齢、同じ人の検出。配送の住所と結ばない。
- 指紋：`HMAC-SHA256(k_identity, normalize(カナの氏名) | 生年月日)`。鍵は `identity` だけが使う。データレイクに入れない。
- 削除：法令の保存の期間の後に属性・指紋を消し、提供者の `deleteData` を呼ぶ。期間（`legal.kyc_*`）は結論の後。結論まで消さない。
- マイナンバーカードの電子証明書のシリアルは、法務の結論まで持たない。

### 他の案を選ばなかった理由

- **2（画像を写す）**：漏れの害が大きく、本システムで使い道がない。保存が法令で要るなら、提供者の保存か、別の鍵の隔離の置き場を結論の後に決める。
- **3（真偽だけ）**：名義の照合と同じ人の検出ができない。

## Consequences

- 良くなること：最も危ないデータ（画像）を本システムに置かない。属性の読み出しを鍵と権限で絞れる。
- 引き受けるコスト：審査で書類を見るときは提供者の画面を使う。提供者を替えると古い画像の参照が使えなくなる（移行の手順を選定の Story で決める）。
