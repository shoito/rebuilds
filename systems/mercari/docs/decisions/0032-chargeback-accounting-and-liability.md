# ADR-0032: チャージバックは、提供者の引き落としを `psp_chargeback_held` に移して記録し、結果で戻すか負担を決める。完了の前は refund として預かりで埋め、完了の後は売り手の売上金を保留し、負担の表 DT-CB-001 で売り手か本システムが持つ

## Context

- [ADR-0005](0005-payments-via-providers-and-capture-at-purchase.md) は、チャージバックを inbox で受けて取引に結び付け、完了の前なら `disputed`、完了の後なら売り手の売上金から `chargeback_receivable` で回収する、と決めた。仕訳の形と、誰が負担するかの規則は決めていない。
- 提供者は、チャージバックの開始で額を引き落とし、勝てば戻す。結果は数週間後になる。
- 完了の前は、預かりにお金がある。預かりは release か refund の一方でしか動かせない（[ADR-0003](0003-escrow-and-double-entry-ledger.md)）。
- 完了の後は、売り手が売上金を振込・購入に使いうる。開始の時に回収すると、勝ったときに戻す仕訳が要る。
- 匿名の配送で正しく送った売り手に、盗んだカードのチャージバックを負わせると、匿名の配送の価値がなくなる。本家の負担の規則は確かめられなかった（**未検証**）。

## Options

1. **開始で `psp_chargeback_held` に移す。完了の前の負けは refund の型で預かりから埋める。完了の後は売り手の売上金を保留し、負けの時に負担の表で決める**
2. 開始で売り手の売上金から回収し、勝ったら戻す
3. すべて本システムの負担にする

## Decision

1 を採用する。仕訳と表は [payments-and-escrow.md](../architecture/payments-and-escrow.md) の 10 節。

- 開始：`psp_chargeback_held` 借方 / `psp_receivable` 貸方。提供者のチャージバックの手数料は `psp_fee_expense`。
- 勝ち：逆の仕訳で `psp_receivable` に戻す。
- 完了の前の負け：取引の預かりを refund の型（行き先 `chargeback`）で決着させ、`psp_chargeback_held` を埋める。`escrow_settlements` の 1 行になり、release との排他はそのまま効く。提供者に返金を依頼しない。
- 完了の後：開始の時に売り手の売上金を額まで保留する（`seller_proceeds_held`。[ADR-0060](0060-ops-money-interventions-and-proceeds-hold.md)）。負けたら DT-CB-001 で負担を決める。売り手の負担なら `chargeback_receivable:<seller>` に移し、保留から回収する。足りない分は以後の release から先に引き、残る間は振込を止める。本システムの負担なら `chargeback_loss_expense` にし、保留を解く。
- DT-CB-001 の既定：匿名の配送で引き受けと配達済みがある不正利用、配達済みのある「届かない」は本システムの負担。措置を受けた売り手、証拠のない配送、紛争で買い手の主張を認めた取引は売り手の負担。運用が根拠を案件に書いて確定する。
- 反証の証拠は、追跡の状態と時刻、取引の事象、メッセージの有無と時刻だけ。住所・氏名・本文を渡すかは法務の確認待ち（L5）で、確認まで渡さない。

### 他の案を選ばなかった理由

- **2**：勝ちの率が高い理由（不正でない買い手の誤解）でも売り手のお金が先に消え、勝ったときの戻しの仕訳と通知が増える。売り手がすでに振り込んでいれば回収できず、結局保留と不足の扱いが要る。
- **3**：偽の発送・説明と違う品の売り手の損を本システムが持ち、悪用の動機になる。

## Consequences

- 良くなること：
  - 提供者の引き落としが常に 1 つの口座で見え、提供者の精算との照合が合う。
  - 完了の前のチャージバックが、預かりの排他の中に収まる。
  - 匿名の配送の売り手を守る規則が表で説明できる。
- 引き受けるコスト：
  - 完了の後の保留で、売り手の売上金が数週間使えない。通知と案件の画面で理由を示す。
  - 本システムの負担の額を、費用のモデルと T&S の信号で見続ける。

## Confirmation

- 性質ベーステスト：PROP-PAY-005（`psp_chargeback_held` は決着で 0、預かりの排他を保つ）。
- 表駆動テスト：DT-CB-001 の全行。
- 3 者の照合：提供者の精算の行のチャージバックと、`psp_chargeback_held` の動きが一致する。
