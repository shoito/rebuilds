# ADR-0068: 退会は、進行中の取引、完了から 14 日の中の取引、未完了の振込、0 円でない売上金・残高・ポイント、開いた紛争・T&S の案件があれば受け付けない。受け付けたら 30 日の `deleting` の後に仮名にし、住所の金庫は鍵の破棄で消す。生年月日を登録で求め、18 歳未満は保護者の同意の確認を記録し、年齢の制限は `ageOf()` の 1 つの関数で判定する

## Context

- 退会の時に取引が残っていると、相手の買い手・売り手が取り残される。売上金が残っていると、預かったお金の行き先がない。
- 本家は、出品中の商品、取引中の商品、取引の完了から 2 週間たたない売却済みの商品、完了していない振込の申請、登録したお支払い用の銀行口座などがあると退会できない（[ヘルプの記事 250](https://help.jp.mercari.com/guide/articles/250/)、2026-10-10 に確認）。
- 退会の後の保持の期限は、法務の確認待ち（L5）。売上金の残りの扱いは、法務の確認待ち（L1）。
- 本家は規約の上の最低の年齢を置かず、未成年に保護者の包括の同意を求め、自動車などの一部のカテゴリを 18 歳未満に閉じる（[公式のコラム](https://jp-news.mercari.com/contents/26374)、2025-10-20、2026-10-10 に確認。掲載当時の内容）。未成年の扱いの法的な整理（同意、取消し、上限）は法務の確認が要る（[intent.md](../intent.md) の L12）。
- 住所は封筒の暗号化で金庫にある（[ADR-0006](0006-shipping-orchestration-via-carriers.md)）。バックアップにも暗号文が残る。

## Options

退会：

1. **条件を満たすまで受け付けない。受け付けたら 30 日の取り消しの期間の後に仮名にし、鍵の破棄で消す**
2. いつでも受け付け、残った取引を運用が片付ける
3. 行を物理に消す

未成年：

- a. **生年月日の申告、同意の確認の記録、`ageOf()` の 1 つの関数、上限は `legal.*` の枠**
- b. 本人確認（eKYC）で年齢を確かめるまで、未成年に見える利用者を止める
- c. 年齢を持たない

## Decision

1 と a を採用する。詳細は [accounts-and-devices.md](../architecture/accounts-and-devices.md) の 9・10 節。

- 受け付けない条件：進行中の取引、完了・取り消しから 14 日たたない取引、未完了の振込、売上金・残高・ポイントが 0 円でない（法務の L1 の結論まで）、開いた紛争・`chargeback_receivable` の残り、開いた T&S の案件、`suspended`・`locked`。出品中の出品と口座の登録は、退会の流れで止めて消す。
- 流れ：強い確認 → `deleting`（セッションの取り消し、非公開、通知の停止。30 日の間はログインで取り消せる）→ `account-eraser` の段ごとの冪等な処理 → `deleted`。
- 消し方：公開のプロフィールと出品を外し、住所の金庫の利用者の鍵を破棄し、電話番号・メールの平文と、閲覧の履歴・いいね・保存した検索・通知・端末を消す。台帳、取引の記録、措置、監査ログは利用者の ID のまま残す。`phone_hmac` は再登録の制限のために残す。どの期間も法務の確認待ち（L5）。
- 未成年：登録で生年月日を求める。18 歳未満は保護者の同意の確認と、日時と文のバージョンを記録する。年齢は `ageOf(user, at)` だけが計算する。カテゴリの年齢の制限は出品の作成と `purchaseListing` で判定する。上限は `legal.minor_purchase_limit_yen`・`legal.minor_payout_limit_yen` の枠を作り、法務の結論まで本番で有効にしない。生年月日の変更は CS を通す。

> 2026-10-10 の注記：未成年の扱い（同意の取り方、取消し、上限、年齢で制限するカテゴリ）は、法務の確認待ち **L12** として [intent.md](../intent.md) に足した。

### 他の案を選ばなかった理由

- **2（いつでも受け付け）**：相手の取引が止まり、売上金の行き先を運用が 1 件ずつ決めることになる。
- **3（物理に消す）**：台帳と取引の相手の記録が壊れる。バックアップに残る。鍵の破棄なら、バックアップの暗号文も読めなくなる（バックアップの保持の期間の後に鍵の写しも消える）。
- **b（eKYC まで止める）**：本家の振る舞いから遠く、登録が重くなる。申告と同意の記録で枠を作り、法務の結論で強める。
- **c（年齢なし）**：年齢で制限するカテゴリ（法務の L10）を判定できない。

## Consequences

- 良くなること：
  - 退会で相手とお金が取り残されない。
  - 住所の消去が、鍵の破棄の 1 回で確かになる。
  - 年齢の判定が 1 か所に集まる。
- 引き受けるコスト：
  - 売上金が数円残った利用者は退会できない。法務の L1 の結論で、少ない額の扱いを決める。
  - 申告の生年月日は偽れる。制限の強いカテゴリは、eKYC の年齢と照らす形を [identity-verification.md](../architecture/identity-verification.md) で検討する。

## Confirmation

- 性質ベーステスト：条件のどれかを満たすアカウントは `deleting` にならない。`deleted` のアカウントの平文と金庫の鍵が残らない（PROP-ACC-005）。
- 単体：`ageOf()` の誕生日の境（前日、当日、うるう日）。
- 法務の L5・L1 と未成年の確認の結論を、この ADR の後継の ADR で値として確定する。
