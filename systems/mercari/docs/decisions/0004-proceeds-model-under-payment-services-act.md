# ADR-0004: 売上金・残高・ポイントを別の口座の種類にし、期限・使い道・本人確認の要否・保全を `legal.*` の設定で決める。収納代行・資金移動業・前払式支払手段のどれに整理されても切り替えられる形にし、法務の L1 の結論まで本番の値を有効にしない

## Context

売り手の売上金は、本システムが買い手から受けた代金のうち、売り手に渡す分である。売り手は、売上金を口座に振り込む、次の購入に使う、（本家では）ポイントに替える。この扱いが資金決済法のどの枠組みに当たるかで、本システムの義務と、作るべき振る舞いが変わる。**どの枠組みに当たるかは、法務の確認待ち（[intent.md](../intent.md) の L1）である。この ADR は法的な結論を出さない。**

枠組みの候補と、設計への影響は次のとおり（どれも法務の確認待ち）。

| 枠組み（候補） | 考え方の例 | 設計への影響の例 |
| --- | --- | --- |
| 収納代行 | 本システムは売り手の代わりに代金を受け取り、売り手に渡す。売上金は売り手への支払いの債務 | 売上金を長く持ち続けないこと（期限、自動の振込）が求められうる。次の購入への使い道は、売り手への支払いと買い手の代金の相殺として整理が要る |
| 資金移動業 | 売上金を、利用者が送金・支払いに使える資金として持つ | 登録、利用者の資金の保全（供託、保証、信託）、1 回の送金の上限、取引時確認（犯罪収益移転防止法、L2）、滞留する資金の扱い |
| 前払式支払手段 | 売上金から替えたポイント、本システムが売るポイント | 自家型か第三者型か、届出・登録、未使用の残高の半額の保全、表示、払い戻しの制限 |

本家は、売上金に振込の申請の期限 180 日を置き、本人確認で期限のない「残高」にする。期限の後は登録した口座へ自動で振り込み（2 回まで）、口座がないか 200 円以下なら失効する（[ヘルプの記事 96](https://help.jp.mercari.com/guide/articles/96/)、2026-10-10 に確認）。本家の法的な整理（どの会社がどの登録で持つか）は、公式の資料で確かめられなかった（**未検証**）。

Uber の題材は、運賃の受け取りを収納代行の形を既定にし、代わりの形を持ち、法務の結論まで本番で有効にしない、とした（[Uber の ADR-0024](../../../uber/docs/decisions/0024-fare-collection-model.md)）。

## Options

1. **売上金・残高・ポイントを別の口座の種類にし、法的に決まる値を `legal.*` の設定に出す。どの枠組みでも動く仕訳の型を先に作る**
2. 1 つの枠組み（例：資金移動業）を前提に作り、違ったら作り直す
3. 売上金を持たない（取引の完了ごとに必ず口座へ振り込む）

## Decision

1 を採用する。

### 口座の種類

| 種類 | 意味 | 法的に決まる値（`legal.*`） |
| --- | --- | --- |
| `proceeds`（売上金） | 取引の完了で売り手に入るお金 | 期限の日数（`legal.proceeds_expiry_days`。本家は 180）、期限の後の扱い（`auto_payout`・`forfeit` の順と回数）、次の購入に使えるか（`legal.proceeds_spendable`） |
| `balance`（残高） | 期限のない残高。本人確認の済んだ利用者の売上金を移す先 | 移す条件（`legal.balance_requires_kyc_level`）、上限（`legal.balance_max_yen`）、次の購入・振込に使えるか、保全の方法 |
| `points`（ポイント） | 本システムが付ける・替えるポイント | 売上金から替えられるか（`legal.proceeds_to_points_enabled`）、期限、払い戻しの可否、未使用の残高の計算の基準日 |

- どの種類も `ledger` の口座で、仕訳の型（移し替え、期限切れ、自動の振込）は種類ごとに固定のコードで持つ。値と有効・無効だけを `legal.*` で切り替える。
- `legal.*` の値は、AppConfig の別の構成にし、変更は法務と財務の承認を要する（delivery の領域）。値を変えた時刻と値のバージョンを、移し替え・期限切れの仕訳に記録する。
- **既定値（法務の結論まで）**：開発と検証の環境では本家に寄せた値（期限 180 日、本人確認で残高へ、期限の後は自動の振込 2 回）で試す。本番では、期限切れ・失効・売上金からポイントへの交換・残高への移し替えを無効にする。本番の MVP の売上金は、振込と、次の購入への使用（`legal.proceeds_spendable` の結論の後）だけを開く。
- **失効の仕訳**は作るが、`legal.proceeds_forfeit_enabled` が真になるまで、どの環境の本番でも動かさない。失効は利用者のお金を消すので、法務・財務の承認と、事前の通知（期限の 30 日・7 日・1 日前）を条件にする。
- **保全**：利用者の資金の合計（`proceeds`・`balance`・`points` の未使用の残高）を、日次で口座の種類ごとに集計する表を作る。保全の方法（供託、保証、信託）と基準日は法務の結論の後に決める。
- **滞留**：残高の上限を超えたときの扱い（自動の振込、受け入れの停止）は、`legal.balance_max_yen` が決まってから、payouts-and-points の領域で決める。

### 結論ごとの移し方

法務の結論が出たら、次のように移す。どれも仕訳の型の追加か設定の変更で、取引のステートマシンと台帳の構造は変えない。

| 結論の例（法務の確認待ち） | 本システムの変更 |
| --- | --- |
| 売上金は収納代行で整理でき、期限を置ける | `proceeds` の期限と自動の振込を有効にする。`balance` は使わない |
| 残高は資金移動業の資金として持つ | 本人確認の済んだ利用者の `proceeds` を `balance` へ移す仕訳を有効にし、保全・上限・取引時確認（L2）をつなぐ |
| ポイントは前払式支払手段 | `points` の未使用の残高の集計と保全を有効にし、売上金からの交換を開く |

### 他の案を選ばなかった理由

- **2（1 つの枠組みを前提）**：結論が違えば、台帳の口座と、売上金の画面・振込の流れを作り直す。法務の結論は MVP の途中で出る見込みで、作り直しの費用が大きい。
- **3（売上金を持たない）**：毎回の振込の手数料が売り手に重く、売上金での購入（フリマの循環）がなくなる。本家の振る舞いから遠い。

## Consequences

- 良くなること：
  - 法務の結論を待つ間も、台帳と取引の流れを作り進められる。
  - 結論が出た後の変更が、設定と仕訳の型の追加に収まる。
- 引き受けるコスト：
  - 3 つの種類と `legal.*` の組み合わせの試験が要る（設定の組み合わせごとの性質ベーステスト）。
  - 本番の MVP は、売上金の期限と残高への移し替えを持たずに始まりうる。本家の振る舞いと違う間、画面の説明を変える。

## Confirmation

- 性質ベーステスト：`legal.*` の全組み合わせで、台帳の不変条件（釣り合い、和 0、負の残高なし）が成り立つ。無効の設定の仕訳の型が、一度も書かれない（[quality.md](../quality.md) の 2.2.1 節 B）。
- 設定の検査（CI）：本番の構成で `legal.proceeds_forfeit_enabled` などが偽であることを、法務の承認の記録なしに変えられないこと。
- 法務の L1 の結論の記録を、[intent.md](../intent.md) の L1 の行に残し、この ADR の後継の ADR で値を確定する。
