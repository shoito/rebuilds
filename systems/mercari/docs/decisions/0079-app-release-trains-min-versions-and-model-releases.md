# ADR-0079: アプリは週 1 回の列車で出し、App Store の段階のリリースと Google Play の段階の公開で広げ、バージョンごとのクラッシュと API の誤りで止める。最小のバージョンは更新を促すバージョンと 426 で止めるバージョンの 2 つで持ち、`X-<Brand>-Client` で判定し、直近 26 の列車を支える。ML のモデルと T&S の規則は、署名した成果物を評価の集まりの関門 → 7 日の影 → 5% → 100% で出し、戻しは設定の切り替えで行う

## Context

- アプリ（iOS・Android の React Native、[ADR-0066](0066-sign-in-sessions-and-devices.md)）は、ストアの審査を通るので、サーバーのように数分で戻せない。古いバージョンは数か月残る。
- 購入の確認の画面の事項（法務の確認待ち：L3）や、お金の表示が変わると、古いバージョンのまま使わせられないことがある。
- App Store は 7 日の段階のリリース（1%・2%・5%・10%・20%・50%・100%）を持ち、止められる（合計 30 日まで）。Google Play は割合を選ぶ段階の公開を持ち、止められる（出典は [delivery.md](../architecture/delivery.md)、2026-10-10 に確認）。
- 分類器と規則の誤りは、正しい出品の `hold` と、偽ブランドの見逃しになる。影の評価と評価の集まりを通してから出す（[ADR-0009](0009-trust-and-safety-pipeline-boundary.md)）。[runbooks/](../runbooks/README.md) の 3 節は、戻しを前のバージョンへの切り替え（デプロイなし）とした。

## Options

アプリ：

1. **週 1 回の列車、段階のリリース、促すバージョンと止めるバージョンの 2 つ、26 の列車を支える**
2. 機能ごとに随時出す
3. 最小のバージョンを 1 つだけ持ち、毎回強制する

モデルと規則：

- a. **署名した成果物、評価の関門、7 日の影、5% → 100%、設定で切り替え**
- b. モデルをイメージに入れて、サービスのデプロイで出す

## Decision

1 と a を採用する。詳細は [delivery.md](../architecture/delivery.md) の 6・7 節。

- 列車：月曜に切り出し、月〜火に E2E と QA、水曜に審査に出す。iOS は 7 日の段階のリリース、Android は 1% → 5% → 20% → 50% → 100%。クラッシュのない率 99.5% 未満、バージョンの API の誤りの率が前のバージョンの 2 倍、購入の失敗の率が 1 ポイント高いときに止める。
- 新しい機能は `release.*` で閉じて入れ、普及の後にサーバーで開ける。
- 最小のバージョン：`ops.app_min_version_<platform>`（更新を促す）と `ops.app_force_version_<platform>`（`app-api` が 426）。判定は `X-<Brand>-Client`。支える範囲は直近 26 の列車。強制の引き上げは、安全の修正、お金と法令の表示（L3）、API の契約の削除のときだけで、安全を除き 14 日前から知らせる。
- API の互換：応答は足すだけ。経路ごとに `min_client` を持ち、古いバージョンの呼び出しの数を見る。
- モデルと規則：登録簿に、重み、前処理のバージョン、評価の結果、学習のデータの出どころ、署名を置く。評価の集まりの関門（NFR-009）→ 7 日の影 → 出品の ID のハッシュで 5% → 100%。`models.<name>.active_version`・`rollout_percent`、`rules.<set>.active_version` で切り替え、戻しは前のバージョンへの設定の変更。規則の変更は T&S の責任者の承認。

### 他の案を選ばなかった理由

- **2（随時）**：審査と QA の回数が増え、バージョンの数が増えて、互換の範囲が広がる。
- **3（1 つの最小のバージョンで毎回強制）**：利用者の多くが毎週止められ、離脱する。
- **b（イメージに入れる）**：モデルの戻しにデプロイが要る。影の評価と割合の出し方を、サービスのデプロイの段と別に持てない。

## Consequences

- 良くなること：
  - アプリの誤りの影響を、段階の初めの数 % で止められる。
  - 古いバージョンの範囲が決まり、API の欄の削除の条件が明らかになる。
  - モデルと規則を、デプロイなしに戻せる。
- 引き受けるコスト：
  - 機能の公開は、アプリの普及（数週間）を待つ。
  - 26 の列車分の API の互換を持ち続ける。
  - モデルの影の評価の 7 日の間、新しいモデルの効果が出ない。

## Confirmation

- 表駆動テスト：`force` より古いバージョンとヘッダーなしのアプリに 426。
- 本番の指標：バージョンごとのクラッシュのない率、支える範囲より古いバージョンの DAU の率 2% 以下（[delivery.md](../architecture/delivery.md) の 9 節）。
- モデル：評価の集まりの関門の CI、影の評価の記録、署名のないモデルを `ml-inference` が読まないこと。
