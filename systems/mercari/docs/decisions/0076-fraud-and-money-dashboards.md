# ADR-0076: 不正・T&S・お金のダッシュボードは、低い基数のラベルの集計を AMP に、日次の集計をデータレイクの Athena から出す。個別の利用者・取引の調べは案件の画面（JIT）でだけ行い、ダッシュボードのフォルダーは T&S・セキュリティ・財務の役に絞る。アプリの計測は本システムの受け口にだけ送り、第三者の計測の部品を既定で入れない

## Context

- 乗っ取り（売上金を狙う）、偽の発送、チャージバック、振込の不正、ボットの購入、スクレイピング、偽ブランドの波は、数の急な変化で気づくことが多い（[security.md](../architecture/security.md) の 3 節、[runbooks/](../runbooks/README.md) の 4 節の `fraud-surge.md`・`ts-surge.md`）。
- 不正の調べには個別の利用者・取引を見る必要があるが、ダッシュボードに個人を指す値を出すと、広い人が見る場所に個人のデータが置かれる。運用者の閲覧は案件に結び付く JIT にする（[ADR-0070](0070-operator-access-vault-reveal-and-audit.md)）。
- 振込とお金の数（仮勘定の残り、待っている振込の額）は、財務の判断の材料で、広く見せるものではない。
- アプリの計測の送信は、外部送信規律の公表の対象になりうる（法務の確認待ち：L11）。

## Options

1. **低い基数の集計（AMP）と日次の集計（Athena）、個別は案件の画面、フォルダーを役で絞る**
2. 不正の分析の外部のサービスに事象を送り、そこでダッシュボードと調べを行う
3. ダッシュボードから個別の利用者へ掘り下げられるようにする（ラベルに ID）

## Decision

1 を採用する。詳細は [observability.md](../architecture/observability.md) の 6・8 節。

- 面：乗っ取り、振込、チャージバック、偽の発送、ボットの購入、偽ブランド・禁止の品、お金、スクレイピング。
- ラベル：理由のコード、支払いの方法、運送会社、アカウントの年齢の帯、カテゴリの最上位など、低い基数のものだけ。
- 実時間の数は各サービスの指標を AMP へ。率と額の帯は data のアカウントの Athena で日次に集計し、数と額だけを Grafana に出す。
- 個別の調べは T&S・CS の案件の画面（`ops-api` の JIT）で行う。
- Grafana のフォルダー「不正」「お金」は Identity Center の T&S・セキュリティ・財務の組だけに見せる。
- アプリの計測（性能、クラッシュの要約、操作の数）は `api.<brand>.<domain>/telemetry` にだけ送り、利用者の ID を送らない。第三者の計測・広告の部品は既定で入れず、入れるときは PM と法務の確認を経る（L11）。

### 他の案を選ばなかった理由

- **2（外部の不正の分析のサービス）**：利用者の行動の事象が第三者に渡る（法務の L5）。T&S の規則のエンジンと審査は題材の核で、自前で持つ（[ADR-0009](0009-trust-and-safety-pipeline-boundary.md)）。
- **3（ID のラベル）**：メトリクスの基数が爆発し、費用が増える。ダッシュボードを見られる人が、案件なしに個人の行動を見られる。

## Consequences

- 良くなること：
  - 不正の波に数で気づき、案件の画面で個別を調べる流れが、監査の範囲に収まる。
  - お金の数を見る人を財務などに絞れる。
- 引き受けるコスト：
  - ダッシュボードから個別へ 1 クリックで行けない。案件を作る手間がある。
  - 日次の集計は 1 日遅れる。実時間が要る数は AMP に出す。

## Confirmation

- CI：Grafana のダッシュボードの定義（IaC）に、基数の大きいラベルの問い合わせがない。フォルダーの権限が組に絞られている。
- 性質ベーステスト：アプリの計測の中身に、利用者の ID と画面の文が現れない。
- 第三者の計測の部品の追加は、依存の許可の一覧（[ADR-0001](0001-platform-and-stack.md)）で止まり、PM と法務の確認を求める。
