# ADR-0049: 評価は取引ごとに向きごとに 1 つ（`good`・`normal`・`bad` と 150 文字の文）。買い手の評価は受取評価と同時に必ず付け、自動の完了では付けない。どちらの評価も取引の完了まで相手と他の人に見せず、完了で同時に公開する。出した評価は直せない

詳細は [ratings-and-reputation.md](../architecture/ratings-and-reputation.md) の 4 節。

## Context

- 取引は `received`（買い手の受取評価か自動の完了）→ `completed`（売り手の評価か、受取評価から 72 時間の期限）と進む（[ADR-0002](0002-transaction-state-machine-and-single-purchase.md)、`transactions-and-state-machine.md` の 9 節）。
- 先に出た評価を見て仕返しの評価を付けると、評価が取引の質を表さなくなる。
- 自動の完了に既定の「良い」を付けると、問題があって受取評価をしなかった取引まで良い評価になる。
- 本家の評価の公開の時と、自動の完了の時の評価の扱いは、公式の資料で確かめられなかった（**未検証**）。

## Options

1. **評価は完了まで伏せ、完了で同時に公開。自動の完了と売り手の期限では評価を作らない。直せない**
2. 出したらすぐ公開する
3. 自動の完了に既定の `good` を付ける

## Decision

1 を採用する。

- 評価の行は、遷移の関数を呼ぶ同じ core のトランザクションで `sealed` で書く。`completed` の遷移の同じトランザクションで、その取引の評価を全部 `published` にする。
- 買い手は受取評価と同時に評価する（必須）。売り手は `received` の後に評価する。売り手は買い手より先に評価できない。
- 自動の完了・売り手の期限の完了は、評価の行を作らない。完了の後に評価は足せない。
- 出した評価は利用者が直せない・消せない。外すのは T&S の措置 `rating_exclude` だけ（[ADR-0050](0050-reputation-score-and-manipulation-review.md)）。
- `bad` は 10 文字以上の文を求める。文は悪用の絞り込みを通す（[ADR-0047](0047-send-time-abuse-filter-and-scan-modes.md)）。
- 受け付けの決定表 DT-RAT-001 を spec で確定する。

### 他の案を選ばなかった理由

- **2（すぐ公開）**：売り手が買い手の評価を見て評価を決められ、仕返しを生む。
- **3（既定の good）**：評価の数が問題のある取引を隠す。

## Consequences

- 良くなること：仕返しの評価を減らせる。評価が取引の完了と 1 つのトランザクションで結び付き、評価だけ・遷移だけの半端が起きない。
- 引き受けるコスト：買い手の評価は完了まで最長 72 時間見えない。本家と違う振る舞いになりうる（本家は未検証）。

## Confirmation

- PROP-RAT-001〜003（完了は受取評価を経る、`sealed` が漏れない、向きごとに 0 か 1）。
- DT-RAT-001 の表駆動テスト（E13 の合否）。
- 仮想の時計：売り手の期限での完了。
