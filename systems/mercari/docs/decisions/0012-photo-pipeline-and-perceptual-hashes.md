# ADR-0012: 写真は署名つきの URL で S3 に直接上げ、`media-processor` が sharp で検査・向きの補正・メタデータの全部の除去・3 つの大きさの WebP と JPEG への変換を行う。出力を読み直して位置情報がないことを確かめてから使う。知覚ハッシュは 64 ビットの pHash と dHash を持つ

詳細は [listings-and-photos.md](../architecture/listings-and-photos.md) の 5 節。

## Context

- 1 出品 10 枚まで、S1 で 150 万枚/日。上げ終わりから変換の完了まで p95 5 秒（NFR-015）。
- 写真の EXIF の GPS は売り手の自宅を明かす。配る写真に位置情報が 1 件も残ってはならない（E3 の合否）。
- 禁止のハッシュの一覧と、他の売り手の写真の使い回しの検出に、写真の近さの指標が要る（[ADR-0009](0009-trust-and-safety-pipeline-boundary.md)）。
- 写真の変換は sharp を汎用の部品として使う（[ADR-0001](0001-platform-and-stack.md)）。sharp は既定で出力からすべてのメタデータを除く（[sharp の Output options](https://sharp.pixelplumbing.com/api-output)、2026-10-10 に確認）。

## Options

写真の受け方：

1. **署名つきの URL で S3 に直接上げ、S3 の通知で Worker が処理する**
2. `listings` の API が本体を受けて S3 に書く

位置情報の守り：

- a. **sharp の既定（除く）に頼り、さらに出力を読み直して確かめる。元は 24 時間で消す**
- b. sharp の既定だけに頼る
- c. EXIF から GPS の項目だけを消す

ハッシュ：

- x. **pHash と dHash の 64 ビットを 2 つ**
- y. 暗号のハッシュ（SHA-256）だけ
- z. 学習した画像の埋め込み（ベクトル）

## Decision

1、a、x を採用する。

- 受け付け：署名つきの URL（10 分、20 MB、`image/jpeg`・`png`・`webp`）。アプリは端末で JPEG にし、長辺 4,096 に縮める。サーバーで HEIC を受けない。
- 処理：形式と大きさの検査（5,000 万画素、短辺 320）、Orientation での回転、sRGB への変換、`thumb` 240・`medium` 640・`large` 1,280 の WebP（品質 80）と JPEG（品質 82）。メタデータを残す sharp の関数の呼び出しを lint で禁じる。
- 確かめ：6 つの出力を読み直し、EXIF・XMP・IPTC の塊と `GPS` の印がないことを確かめる。残れば写真を `failed` にし、配信しない。
- 元（`photos-incoming`）は 24 時間で消す。
- ハッシュ：向きを直した画素から pHash（32×32 の DCT の左上 8×8、直流を除く中央の値で 2 値）と dHash（9×8 の隣の比べ）を作る。完全な一致は両方の距離 0、近いは pHash の距離 1〜6。濃淡の標準偏差 8 未満はハッシュを使わない。

### 他の案を選ばなかった理由

- **2（API が受ける）**：20 MB × 70 枚/秒を API のタスクが通すと、API の待ちと費用が増える。
- **b（既定だけ）**：部品の更新・設定の誤りで残ったときに気づけない。
- **c（GPS だけ消す）**：XMP・メーカーの独自の項目に位置が入りうる。全部を消すほうが確か。
- **y（暗号のハッシュ）**：再圧縮・縮小で変わり、使い回しを見つけられない。
- **z（埋め込み）**：MVP に学習のデータがなく、近さの閾値の説明もしにくい。分類器（ADR-0009）の側で使うのはよい。

## Consequences

- 良くなること：位置情報の残りを、処理のたびに機械で確かめられる。写真の近さを決まった計算で比べられる。
- 引き受けるコスト：読み直しの分だけ処理が延びる（p95 0.4 秒の見込み）。ハッシュは回転・大きな切り抜きに弱い。閾値は `counterfeit-classifier-poc` で確かめる。

## Confirmation

- PROP-LST-004（合成の写真の全部で、出力に位置情報がない）。
- 試験のベクトル（固定の画像と期待するハッシュのビット列）。
- 負荷：70 枚/秒で p95 5 秒（NFR-015）。
- 外からの見張り：見張りの出品の写真の位置情報の検査。
