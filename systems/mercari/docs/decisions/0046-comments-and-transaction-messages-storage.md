# ADR-0046: 商品のコメントは content の公開の表に置き、出品の `listingVisible()` に従って出し、`on_sale` の間だけ書ける。取引のメッセージは content の 2 者の RLS の表に置き、取引の終わりから 14 日で読み取りだけにする。MVP は文字だけ。削除は論理の削除で、本文の暗号化した写しを保持の期間だけ持つ

詳細は [messaging-and-comments.md](../architecture/messaging-and-comments.md) の 4 節。

## Context

- 商品のコメントは公開、取引のメッセージは取引の 2 者だけのデータ（[ADR-0007](0007-single-tenant-and-party-visibility.md)）。どちらも量が多く、content のクラスタに置く（[ADR-0001](0001-platform-and-stack.md)）。
- 取引のメッセージは、紛争の証拠になる。消せると、紛争の判断ができない。
- 措置・通報・法令の照会のために、消した本文が要ることがある。保持の期間は法務の確認待ち（L5・L9・L11）。
- 画像のメッセージは、住所の写った写真などの漏れの経路を増やし、絞り込みが効かない。

## Options

1. **コメントは公開の表、メッセージは 2 者の RLS の表。メッセージは利用者が消せない。画像なし。本文の保持の写しは別の鍵**
2. コメントとメッセージを 1 つの表にし、種類の列で分ける
3. メッセージに画像を許し、画像の分類器で検査する

## Decision

1 を採用する。

- `listing_comments`：300 文字、`on_sale` の間だけ書ける。書いた人と売り手が消せる（論理の削除）。ブロックの関係では書けない。1 出品 500 件。
- `transaction_messages`：1,000 文字。FORCE RLS（`buyer_id`・`seller_id`）。書き込みは `messaging` が取引の 2 者かを確かめる。取引の終わり（`completed`・`cancelled`・`payment_expired`）から 14 日で読み取りだけ。利用者は消せない。1 取引 500 件。
- 送信は冪等キー（`client_message_id`）で再送できる。
- 通知の文に本文を入れない。
- 削除・措置の後も、本文の写しを T&S の KMS の鍵で暗号化して `retained_bodies` に保持の期間だけ持つ。期間は法務の結論の後（開発の環境は仮に 180 日）。

### 他の案を選ばなかった理由

- **2（1 つの表）**：公開の表と 2 者の RLS の表が混ざり、RLS の誤りが漏れに直結する。
- **3（画像）**：住所・電話番号の写った画像を、文字の絞り込みで止められない。問題の写真は紛争の報告で受ければ足りる。

## Consequences

- 良くなること：2 者のデータの漏れを DB の RLS で防げる。紛争の証拠が残る。
- 引き受けるコスト：誤って送った文を消せない（取引の相手には残る）。保持の写しの鍵と期限の管理が要る。
