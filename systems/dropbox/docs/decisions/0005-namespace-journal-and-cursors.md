# ADR-0005: 名前空間ごとに単調な `ns_seq` と `ns_journal` を持ち、すべての書き込みを `packages/committer` で載せる。カーソルは載せた名前空間ごとの位置の組を署名した不透明な文字列で、90 日で取り直しを求める

## Context

木の変更を、次の相手に差分で届ける必要がある。

- **デスクトップのクライアント**：載せたすべての名前空間の変更を、数秒で受ける（NFR-002）。オフラインから戻ったら、続きから受ける。
- **モバイルと Web**：開いているフォルダーの変更を受ける。
- **公開 API の利用者**：カーソルで前回からの変更だけを取る。Webhook で「変わった」を受けて取りに来る。
- **社内の処理**：プレビュー、索引、一斉の変更の検知、監査、容量の集計。

本家の API は、`list_folder` でカーソルを返し、`list_folder/continue` で続きを取り、`list_folder/longpoll` で変化を待つ。Webhook の通知は変更のあったアカウントの一覧だけを持ち、アプリはカーソルで取りに来る（[Webhooks](https://docs.dropboxapi.com/dropbox-api/docs/webhooks)、2026-10-09 に確認）。カーソルの中身と有効の期間は、公開の資料で確かめられなかった（**未検証**）。

名前空間（[ADR-0004](0004-tenancy-namespaces-and-rls.md)）は、共有の単位であり、複数の利用者の木に現れる。経路ごとに別の差分の仕組みを作ると、どれかの経路で変更が欠ける。

## Options

順序の単位：

1. **名前空間ごとに単調な `ns_seq` を振る**
2. テナントごとに単調な番号を振る
3. 利用者ごとに、見える変更を写したフィードを持つ（書き込みの時に配る）
4. 時刻（`updated_at`）で差分を取る
5. DB の論理レプリケーション（WAL）から変更を取る

## Decision

1 を採用する。

### ジャーナル

- `namespaces` の行に `ns_seq` を持つ。`packages/committer` は、書き込みのトランザクションの最初に名前空間の行をロックし（`UPDATE ... SET ns_seq = ns_seq + n RETURNING`）、操作ごとに番号を振る。
- 番号を振った操作を `ns_journal(tenant_id, ns_id, seq, op, node_id, parent_id, name, rev_id, is_folder, size, content_sha256, actor_id, device_id, committed_at)` に、ノードとリビジョンの変更と outbox と同じトランザクションで書く。行は「操作の後のノードの状態」を持ち、読む側は前の状態を知らなくても当てられる。
- `op` は `upsert`（作成・変更・移動・名前の変更）、`delete`、`mount`（名前空間を載せた）、`unmount`（外した）。
- **1 回の commit は 1 つの名前空間への最大 1,000 の操作で、全部が通るか全部が通らない。** 操作の条件（`base_rev`、名前の一意）は [ADR-0006](0006-sync-conflict-model.md)・[ADR-0008](0008-node-identity-and-names.md) にある。
- **ジャーナルを通らない書き込みを作らない。** 復元、巻き戻し、管理者の操作、保持の期限での削除、一括の修正も、`packages/committer` を通して番号を振る。
- ジャーナルは日で分割し（`pg_partman`）、90 日を過ぎた分割を落とす（保持の期間は法務の L6 の後に確定する）。名前空間ごとに、保持の下限の番号（`floor_seq`）を持つ。
- 1 つの名前空間の書き込みは、行のロックで直列になる。1 名前空間 1 秒 200 件の commit を上限と見込み、E3 の前の `namespace-write-throughput-poc` で確かめる。上限を超えたら 429 と `Retry-After` を返す。チームのスペースは、チームのフォルダーをそれぞれ別の名前空間にして、ロックを分ける。

### 載せる・外す

- 利用者が共有フォルダーに参加したら、利用者のルートの名前空間に `mount` の操作を書く（招かれた人の文脈）。クライアントは `mount` を受けたら、その名前空間を番号 0 から読む。番号 0 からの読み出しは、ジャーナルではなく木の今の状態の一覧（ページつき）を返す。
- 共有フォルダーから外されたら、まず `ns_access` を消して読めなくし、次に外されたメンバーのルートの名前空間に `unmount` を書く（[ADR-0004](0004-tenancy-namespaces-and-rls.md) の X5）。クライアントの手元の扱い（変更のないファイルは消し、手元で変えたファイルは残して知らせる）は sync-engine の領域で決める。

### カーソル

- カーソルは不透明な文字列で、中身は `{v, account_id, root_ns, positions: {ns_id → seq}, mount_hash, epoch}` を圧縮して HMAC の署名を付けたもの。利用者が他人の名前空間の位置を作れない。要求の本文で送り、URL に入れない。
  - `positions`：載せた各名前空間の、読み終えた番号。
  - `mount_hash`：カーソルを出した時点の載せた名前空間の集合と役割。`list/continue` の時点の集合と違えば、足された名前空間は番号 0 から、外された名前空間は `unmount` として返す。
  - `epoch`：DR の切り替え、時点への復元で上げる。古い `epoch` のカーソルは取り直し（409 `reset`）。
- `list/continue` は、各名前空間の `seq` より後の操作を読み、載せた場所のパスに直して返す。同じノードが何度変わっても、最後の状態の 1 件にまとめる。名前空間の中の順序は保つ。名前空間をまたぐ順序は保証しない。件数が多ければページに分け、最後のページで新しいカーソルを返す。
- `seq` がその名前空間の `floor_seq` より古ければ、取り直しを求める。最後の利用から 90 日は使える（NFR-010）。取り直しでは、クライアントは木の全体を読み直し、Synced の木と比べて差を当てる。Synced があるので、取り直しで手元の変更を失わない（[ADR-0006](0006-sync-conflict-model.md)）。
- 開いているフォルダーだけを見る Web とモバイルは、そのフォルダーの名前空間だけの位置を持つカーソルを使う。

### 合図

- Relay が outbox の後に、名前空間ごとの「`ns_seq` が S になった」を Valkey の pub/sub に流す。Notify は、端末が載せた名前空間を購読し、WebSocket で合図だけを送る。中身は送らない。
- 合図が落ちても、端末は再接続のときと 60 秒ごとに `list/continue` で確かめる。公開 API には long-poll（変化があるか、時間切れまで待つ）を出す（api-and-webhooks の領域）。
- Webhook は、合図をアプリと利用者の組にまとめて送る。通知に中身を入れない。受け手はカーソルで取る。

### 社内の処理

- 社内の処理は、ジャーナルではなく outbox から SNS・SQS で受ける。outbox はジャーナルと同じトランザクションで書くので、両者は食い違わない。

### 他の案を選ばなかった理由

- **2（テナントごとの番号）**：大きなチームのすべての書き込みが 1 つのロックで直列になる。テナントをまたぐ共有フォルダーの順序を表せない。
- **3（利用者ごとのフィード）**：共有フォルダーのメンバーが 1 万人なら、1 回の書き込みで 1 万の行を書く。チームのスペースで書き込みが増幅する。名前空間ごとのジャーナルを読む側で合わせるほうが、書き込みが一定になる。
- **4（時刻）**：同じ時刻の書き込みと、コミットの順序と時刻の入れ替わりで、差分が欠ける。削除を表せない。
- **5（WAL）**：権限で絞った形と、載せた場所のパスへの直しを、行の変更から作り直す必要がある。DR の切り替えやシャードの移動で、位置が引き継げない。

## Consequences

- 良くなること：
  - デスクトップ・モバイル・Web・API・Webhook が、同じ順序と同じ保持で差分を受ける。
  - 共有フォルダーの変更は、1 回だけジャーナルに書き、メンバーの数に比例して書き込みが増えない。
  - 合図や Webhook が落ちても、カーソルで取り戻せる。
- 引き受けるコスト：
  - 1 つの名前空間の書き込みが直列になる。書き込みの多い名前空間が上限に当たりうる。
  - 載せた名前空間が多い利用者（数百の共有フォルダー）のカーソルが大きくなり、`list/continue` が多くの名前空間を読む。読み出しを名前空間ごとにまとめて並べ、空の名前空間は `ns_seq` の比べだけで飛ばす。
  - 90 日を超えて同期しない端末は、木の全体を読み直す。

## Confirmation

- 性質ベーステスト：任意の書き込みの列（並行、載せる・外す、名前空間をまたぐ移動を含む）と、任意の時点のカーソルで、差分を順に当てた木が、全件を読み直した木と一致する。
- 性質ベーステスト：任意の共有の変更の列で、外された名前空間の操作が、外された後のカーソルの応答に出ない。
- 結合テスト：`packages/committer` を通らない書き込み（`nodes` への直接の `UPDATE`）を、DB のロールの権限で拒否する。
- 本番：名前空間ごとの番号の欠け（ジャーナルの連続）を監視する。合成監視の 2 つの端末で、確定から差分の到着までを測る（NFR-002）。
