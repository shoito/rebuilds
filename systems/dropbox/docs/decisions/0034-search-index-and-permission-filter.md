# ADR-0034: 索引はノードごとの文書で、名前の索引（全プラン）と本文の索引（チームのプランの名前空間）に分け、テナントの ID で経路を決める。照会は `packages/access` が求めた読める名前空間の集合で絞り、上位の結果を Aurora で `can()` と今の名前・場所に確かめ直してから返す。索引の更新は outbox の合図で `ns_journal` を読み、`ns_seq` を外部のバージョンにして当てる。パスは返す時に Aurora で作る

## Context

[ADR-0001](0001-platform-and-stack.md) は、名前と本文の索引に OpenSearch を足し、索引は写しで、権限の判定を持たせず、返す前に `can()` で確かめ直すと決めた。名前は日本語の n-gram、本文は形態素と n-gram。

S1 で名前は 25 億ノード、変更は 1 秒 1 万件の規模になる（[architecture/README.md](../architecture/README.md) の 2 節）。検索は漏れの経路の 1 つで、結果・件数・抜粋から、読めない名前空間の有無が分かってはいけない（[quality.md](../quality.md) の 2.2.1 節 F）。

決めることは次である。

- 権限を、照会の時に絞るか、索引の文書に読める人を持たせるか。共有の変更は頻繁で、1 万人のグループへの付与がある。
- 索引の更新の順序。outbox の合図は落ちうる、重なりうる。
- パスを索引に持つか。大きなフォルダーの名前の変更で、子孫のパスがすべて変わる（[ADR-0008](0008-node-identity-and-names.md)）。

## Options

権限：

1. **照会の時に読める名前空間の集合で絞り、上位を Aurora で確かめ直す**
2. 文書に読める主体の一覧（ACL）を持たせる
3. 絞らずに照会し、結果を確かめ直して落とす

更新：

- a. **outbox の合図でジャーナルを読み、`ns_seq` を外部のバージョンにする**
- b. outbox の行の中身をそのまま当てる
- c. 定期的に Aurora と突き合わせる

パス：

- x. **索引に表示のパスを持たず、`ancestor_ids` だけを持ち、返す時に作る**
- y. 表示のパスを持ち、祖先の変更で子孫を直す

## Decision

1、a、x を採用する。詳細は [search.md](../architecture/search.md) の 4〜7 節。

- `names-v<N>`（全プラン）と `content-v<N>`（持ち主のテナントがチームのプランの名前空間）。文書の ID は `node_id`、経路は `tenant_id`。
- 照会：読める名前空間の集合で `terms` の絞り込み、経路はその持ち主のテナントの集まり。上位 100 件を Aurora で、ある・削除されていない・`ns_id` が同じ・`can(actor, read)` を確かめ、今の名前とパスで返す。件数は「約」で、1,000 を超えたら「1,000 件以上」。
- 抜粋は確かめ直しの後に、S3 の抽出のテキストから作る。索引の `_source` に本文を持たない。
- 更新：outbox の合図（`ns_id`、`seq` の範囲）を FIFO の SQS（グループは `ns_id`）で受け、`ns_journal` を読み、ノードごとに畳んで、`ns_seq` を外部のバージョンにして当てる。`index_checkpoints` で追いつきを確かめる。
- 祖先の移動は `update_by_query` で子孫の `ancestor_ids` を直す。名前の変更だけでは直さない。
- 作り直しは新しい番号の索引に木の一覧から入れ、ジャーナルで追いつかせてから別名を切り替える。

### 他の案を選ばなかった理由

- **2（文書に ACL）**：共有の変更・グループの変化・方針の変更のたびに、名前空間の全文書を書き換える。1 万ファイルの共有フォルダーへの 1 人の追加で 1 万文書になる。
- **3（絞らない）**：読めない文書が上位を占めると、読める結果が返らない。件数と速さから有無を推測されうる。
- **b（outbox の中身）**：outbox に名前を持たせることになり、社内の待ち行列に名前の写しが増える。重なりと順序の入れ替わりで古い状態が勝ちうる。
- **c（定期の突き合わせだけ）**：NFR-011 の 60 秒に届かない。
- **y（表示のパス）**：10 万ファイルのフォルダーの名前の変更で 10 万文書を書き換える。名前空間をまたぐ場所の違い（マウントの場所は人ごとに違う）も表せない。

## Consequences

- 良くなること：
  - 共有の変更で索引を直さない。取り消しは次の照会から効く。
  - 古い更新で新しい状態を戻さない。合図が落ちても追いつける。
  - 結果の名前とパスが、常に今の値になる。
- 引き受けるコスト：
  - 照会のたびに Aurora の読み出しが 1〜3 回増える。
  - 祖先の移動の後しばらく、フォルダーの中だけの検索の範囲が古い。
  - 件数を正確に出せない。
