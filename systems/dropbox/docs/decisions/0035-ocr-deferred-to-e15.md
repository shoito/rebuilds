# ADR-0035: 画像と走査した PDF の OCR は MVP で持たず、E15 で、日本語の試験の集まりでの文字の誤りの率と 1,000 頁あたりの費用を測ってから決める。MVP の索引には OCR のための別の項目（`body_ocr`）と抽出器のバージョンだけを用意し、本文と混ぜない

## Context

[intent.md](../intent.md) は、画像と走査した PDF の日本語の OCR での検索を MVP の後の Epic（E15）にし、精度と計算の費用を測ってから決めるとした。[architecture/README.md](../architecture/README.md) の 6 節は、これを search の領域で ADR にするとした。

日本語の OCR は、縦書き、手書き、表、低い解像度の走査で精度が大きく変わる。チームの利用者（設計・建設）の図面や、走査した請求書は量が多く、全部を OCR すると費用が本文の抽出の何倍にもなりうる。中身を機械で読む処理であり、法務の L1 の論点でもある。

## Options

1. **MVP で持たない。索引の項目と抽出器のバージョンだけを用意し、E15 で測って決める**
2. MVP で、汎用の OCR の部品（オープンソース）を隔離の変換で動かす
3. MVP で、クラウドの OCR のサービスを使う

## Decision

1 を採用する。

- `content-v<N>` に `body_ocr`（本文と別の項目）を用意し、MVP では空のままにする。本文の `body` と混ぜない。OCR の誤りの多い文字が本文の一致の点数を乱さないよう、点数の重みを別に決められるようにする。
- `extracted_texts` に `extractor_version` を持ち、OCR を足すときは別の抽出器として足す。
- E15 で決めるための計測：
  - 日本語の試験の集まり（合成の文書を印刷して走査したもの、写真の看板・ホワイトボード、図面の文字。実在の人の文書を使わない）で、文字の誤りの率（CER）を測る。目安は活字で 5% 以下。
  - 1,000 頁あたりの計算の費用と時間。
  - OCR の部品を隔離の変換（[ADR-0032](0032-sandboxed-preview-pipeline.md)）で動かせるか。外のサービスを使う案は、中身を外へ送ることになり、法務の L1・L4・L5 の確認が要る。
- 有効にするのは、計測の結果と法務の L1 の結論の後。

### 他の案を選ばなかった理由

- **2（MVP で部品を動かす）**：精度を測る前に費用と運用を引き受ける。MVP の検索の合否（名前と本文の取りこぼし）に関係しない。
- **3（クラウドのサービス）**：中身を別のサービスへ送る。データの所在（L5）と委託（L4）の論点が増える。

## Consequences

- 良くなること：
  - MVP の索引の形を、OCR を足すときに変えずに済む。
  - 精度と費用を測ってから決められる。
- 引き受けるコスト：
  - MVP では、走査した PDF と画像の中の文字で検索できない。名前で探すことになる。

## Confirmation

- E15 の `ocr-evaluation` で、計測の結果を記録してから、有効にする Story の spec を承認する。
- 索引の項目の検査：MVP の間、`body_ocr` に値を書くコードがないこと。
