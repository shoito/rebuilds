# ADR-0046: マルウェアの検査と違法なコンテンツのハッシュの照合は、隔離した `content-scanner` の枠だけを作り、範囲を AppConfig の `content_scan_policy` で切り替える。法務の L1・L2 の結論まで本番の範囲は空。見つけても中身を消さず、共有と配信の経路だけを止めて人が確かめる

## Context

- 共有フォルダーと共有リンクで、マルウェアや違法なコンテンツが他の人へ届きうる（[intent.md](../intent.md) の L2）。
- 中身を機械で読むこと（プレビュー、索引、検査）が通信の秘密に当たるか、同意が要るかは法務の L1 の確認待ち。違法なコンテンツのハッシュの照合をどの範囲で行ってよいかは L2 の確認待ちである。
- 本システムは同期で中身を黙って変えない・消さない（[ADR-0006](0006-sync-conflict-model.md)）。検査の誤検知で中身を消すと、この約束を破る。
- 利用者のファイルを開く処理は、ネットワークを持たない隔離したタスクで動かす（[AGENTS.md](../../AGENTS.md)、[security.md](../architecture/security.md) の 3.4 節）。
- リビジョンはファイル全体の SHA-256（`content_sha256`）を持つ（[ADR-0002](0002-chunking-and-block-addressing.md)）。完全一致の照合は中身を読まずにできる。

## Options

1. **枠だけを作り、範囲を構成で切り替え、法務の結論まで空にする。見つけたら共有と配信だけを止める**
2. MVP で、すべての新しいリビジョンを検査する
3. 検査を持たない

## Decision

1 を採用する。

- `content-scanner` を sandbox のサブネットで動かす（ネットワークなし、S3・DB・KMS の権限なし、ジョブごとの署名つき URL）。マルウェアの検査は第三者の汎用の部品を使い、定義は毎日イメージを作り直して入れる。
- ハッシュの照合は、指定の機関から受けたハッシュの一覧と、**サーバーが計算したファイル全体の SHA-256（`verified_sha256`）** の完全一致で行う。クライアントが申告した `content_sha256` は使わない。知覚的なハッシュは、部品と許諾を決めてから足す。
  - 各ブロックの SHA-256 は、`block-verifier` が S3 の計算したチェックサムで確かめている（[ADR-0007](0007-block-storage-layout-on-s3.md)）ので信用できる。信用できないのは、ブロックの一覧から作るファイル全体の `content_sha256` の申告だけである（サーバーは commit で中身を読まない）。
  - 検査の範囲に入るリビジョンは、`content-scanner` が sandbox の中でブロックを順に読んでつなぎ、ファイル全体の SHA-256 を計算して `verified_sha256` に書く。申告の `content_sha256` と違えば `scan_state = integrity_mismatch` にし、`hash_match` と同じく共有と配信の経路を止めて人の確認へ回す（クライアントの不具合か、照合を逃れる試み）。
  - 検査の範囲に入る経路（`link_public` なら `anyone` の共有リンク）は、そのリビジョンの検査が済むまで中身とプレビューを配らない（Link は「確認中」を返す）。照合の前に外へ出さないため。

> 2026-10-09 の注記：最初の起票は、申告の `content_sha256` で照合していた。申告を偽るクライアントは照合を逃れられる（サーバーは抜き取りでしか確かめない。[block-storage.md](../architecture/block-storage.md) の 6 節）。統合の工程で、照合にサーバーが計算した値を使い、範囲に入る経路では検査の前に配らない形に改めた。範囲（`link_public` か `all_uploads` か）は法務の L1・L2 の確認待ちのまま。
- 範囲は AppConfig の構成 `content_scan_policy` で、検査ごとに `none`・`link_public`（共有リンクで外の人へ配るファイル）・`all_uploads`。法務の L1・L2 の結論まで本番は `none`。変更はプラットフォームの事象に残す。
- 結果はリビジョンの `scan_state`（`pending`・`clean`・`malicious`・`hash_match`・`integrity_mismatch`）。
  - `malicious`：共有リンクでの配信とプレビューを止め、持ち主に知らせる。持ち主と名前空間のメンバーのダウンロードは警告つきで続ける。
  - `hash_match`・`integrity_mismatch`：共有リンク・プレビュー・共有の追加を止め、信頼と安全の担当の確認へ回す。届出と保全は L2 の手順。
- 中身を消さない・変えない。同期の経路は止めない（持ち主の同期を止めるかは L2）。
- 判定は `can()` の入力（`scan_state`）にし、経路ごとに条件を書かない（[ADR-0004](0004-tenancy-namespaces-and-rls.md)）。

### 他の案を選ばなかった理由

- **2（すべてを検査）**：法務の L1・L2 の前に、通信の秘密に当たりうる処理を広く始めることになる。
- **3（持たない）**：L2 の結論で照合が求められたとき、隔離・`scan_state`・`can()` の入力・人の確認の流れを後から作ると、共有リンクの公開（E6）に間に合わない。

## Consequences

- 良くなること：
  - 法務の結論が出たら、構成を変えるだけで範囲を広げられる。
  - 誤検知でも中身を失わない。
- 引き受けるコスト：
  - 結論まで、マルウェアと違法なコンテンツの共有リンクでの拡散を、通報の入口と人の対応だけで抑える。
  - 定義の更新はイメージの作り直しで、最大 1 日遅れる。

## Confirmation

- 結合テスト：`content_scan_policy` が `none` のとき、検査のジョブが作られない。
- 決定表の表駆動テスト：`scan_state` と経路（共有リンク、プレビュー、ダウンロード、同期、共有の追加）の組の全行（`can()` の決定表）。
- 隔離の検査：`content-scanner` のタスクのロールに S3・DB・KMS の権限がない。外への通信ができない。
- 性質ベーステスト：任意の検査の結果の列で、リビジョンの中身と木（同期の経路）が変わらない。
- 結合テスト：申告の `content_sha256` を偽ったリビジョンが `integrity_mismatch` になり、範囲の経路で配られない。検査の済んでいないリビジョンを `anyone` のリンクで配らない。
