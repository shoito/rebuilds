# ADR-0039: OAuth 2.0 は認可コードと PKCE（S256）だけで、秘密を持つアプリにも PKCE を求める。アクセストークン `<brand>_at_`（4 時間）とリフレッシュトークン `<brand>_rt_`（使うたびに替え、再使用を検知したら系列ごと無効）。スコープは対象と読み書きで分ける。アプリのフォルダーのアプリは、専用の名前空間だけに届くトークンを持つ。レート制限は（アプリ, アカウント）・アプリ・アカウント・名前空間の 4 つの桶

## Context

公開 API の利用者（バックアップ、業務のシステム、ワークフロー）は、利用者のファイルに長く届くトークンを持つ（[intent.md](../intent.md)）。本家は PKCE（`S256` を勧め、`plain` もある）、短命のアクセストークン、`token_access_type=offline` でのリフレッシュトークンを持つ（[OAuth Guide](https://docs.dropboxapi.com/dropbox-api/docs/oauth)、2026-10-09 に確認）。スコープの名前とレート制限の値は確かめられなかった（**未検証**）。

決めることは次である。

- フローとトークンの形・期限。トークンの接頭辞は本家のものを使わない（リポジトリ共通の [ADR-0006](../../../../docs/decisions/0006-brand-neutral-identifiers.md)）。
- スコープの粒度。
- 利用者の木の一部だけに届くアプリ（アプリのフォルダー）を、どう閉じるか。[ADR-0004](0004-tenancy-namespaces-and-rls.md) の名前空間の種類は 4 つで、RLS は名前空間の単位で絞る。
- レート制限の単位。

## Options

フロー：

1. **認可コード＋PKCE（S256）だけ。すべてのアプリに PKCE**
2. 本家と同じく、秘密を持てないアプリだけに PKCE、`plain` も許す

アプリのフォルダー：

- a. **専用の `shared_folder` の名前空間（`app_folder=true`）を作り、トークンをその名前空間に固定する**
- b. 利用者のルートの中のフォルダーのノードを根にし、`can()` で子孫かを確かめる
- c. 新しい名前空間の種類を足す

## Decision

1 と a を採用する。詳細は [api-and-webhooks.md](../architecture/api-and-webhooks.md) の 7・8 節。

- 認可コード（1 回、10 分）＋PKCE（`S256` だけ）。暗黙・パスワードのフローは持たない。`redirect_uri` は完全一致、`state` は必須。
- アクセストークン：`<brand>_at_` ＋ 32 文字の base62 ＋ 6 文字の CRC32、4 時間。リフレッシュトークン：`<brand>_rt_`、`offline` のときだけ、使うたびに替え、再使用で系列を無効、90 日使わなければ切れる。DB はハッシュだけを持つ。接頭辞をシークレットの走査に登録する。
- スコープ：`account.read`、`files.metadata.read`・`write`、`files.content.read`・`write`、`sharing.read`・`write`、`team.members.read`、`team.policies.read`・`write`、`team.audit.read`。書きは読みを含む。
- アプリのフォルダー：利用者のルートの `アプリ/<アプリの名前>` に、利用者だけが `owner` の `shared_folder`（`app_folder=true`）を作って載せる。トークンの `root_ns` をそこに固定し、`app.ns_ids` はその 1 つだけ。共有とリンクの作成を許さない。
- チームの管理者はアプリを許す・止める。止めたらメンバーのトークンを無効にする。
- レート制限（既定）：（アプリ, アカウント）1 分 1,200・瞬間 200、そのうち中身の計画 1 分 120、アプリ 1 分 100,000、アカウント 1 分 3,000、名前空間の commit 1 秒 200、long-poll 同時 4。429 に `reason` と `Retry-After`。

### 他の案を選ばなかった理由

- **2（本家と同じ）**：秘密を持つアプリでも、認可コードの横取りの守りを PKCE に頼れるほうが安全で、実装の分岐も減る。
- **b（子孫の確かめ）**：差分の取得（ジャーナル）を子孫かどうかで絞るのが重く、RLS の守りが効かない。
- **c（種類を足す）**：ADR-0004 の種類の一覧と `can()` の決定表が増える。`shared_folder` の 1 人の名前空間で同じ守りが得られる。

## Consequences

- 良くなること：
  - アプリのフォルダーのアプリは、RLS で他の名前空間に届かない。
  - 盗まれたリフレッシュトークンの再使用を検知できる。
  - 1 つのアプリ・1 つのアカウント・1 つの名前空間の暴走が、他に広がらない。
- 引き受けるコスト：
  - 秘密を持つアプリの開発者にも PKCE の実装を求める。
  - アプリのフォルダーごとに名前空間とカーソルの位置が増える。

## Confirmation

- 性質ベーステスト：PROP-API-003（アプリのフォルダーの外を返さない）。
- 決定表：DT-API-002（スコープ）。
- 結合テスト：`plain` の PKCE を拒む。リフレッシュトークンの再使用で系列が無効になる。レート制限の各桶。
