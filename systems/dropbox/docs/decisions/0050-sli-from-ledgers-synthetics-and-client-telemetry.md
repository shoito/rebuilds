# ADR-0050: 正しさと伝播の SLI は、業務の記録と合成監視の端末から全件で数える。伝播はサーバーの時計だけで測る受け渡しの遅れと、合成監視の端末で測る開けるまでの 2 層にする。端末の計測は、30 日で替える計測の ID で数・ヒストグラム・理由のコードだけを送り、名前・パス・中身のハッシュ・アカウントを送らない。利用者とチームは断れる

## Context

- この題材の最も危ない壊れ方は、エラーにならずに中身が消える・古い中身で上書きされる・端末の木が食い違うことで、利用者の端末で起きる（[quality.md](../quality.md)）。サーバーの 5xx の率だけでは見つからない。
- SLO の値とアラートの正本は [runbooks/README.md](../runbooks/README.md) で、伝播（p99 5 秒）、小さなファイルの届き（p95 10 秒）、中身の耐久性（0）、ジャーナルの連続（0）、端末の健全さ（99.5%）を持つ。計測の実装は observability の領域で決める。
- 端末と利用者の時計はずれる。端末の報告する時刻で伝播を測ると、ずれが混ざる。
- 端末から計測を受けるのは、外部送信規律の公表の対象になりうる（法務の L1）。名前・パス・中身をログに出さない規則がある（[AGENTS.md](../../AGENTS.md)）。ブロックのハッシュは、他人のファイルの有無の確かめに使える（[ADR-0003](0003-dedupe-scope-and-privacy.md)）。
- 他の題材（Google Calendar の ADR-0046）は、SLI をトレースの抜き取りでなく業務の記録から全件で数えると決めた。

## Options

伝播の測り方：

1. **サーバーの時計だけの受け渡しの遅れ（全体）と、合成監視の端末の開けるまで（正本）の 2 層**
2. 端末が報告する受け取りの時刻
3. 合成監視だけ

端末の計測：

- a. **30 日で替える計測の ID、数と理由のコードだけ、断れる**
- b. 端末の ID とアカウントに結んだ詳しい計測
- c. 端末の計測を持たない

## Decision

1 と a を採用する。

- **受け渡しの遅れ**：`api` が `list/continue` で返した操作のうち、書いた端末と別の端末へのものを、端末と名前空間の組ごとに最も古い 1 つだけ、`committed_at` から応答の時刻までを `delivery_samples` に数える。WebSocket がつながっていた端末だけを数える。
- **開けるまで**：合成監視の 2 台（macOS と Windows）で、保存から他の端末で開けるまでを測る。SLO の正本はこちら。
- **アップロード**：S3 のリクエストのメトリクスと、`upload_blocks` の状態の移りから数える。
- **耐久性・ジャーナル**：照合のジョブの結果（`integrity_audit_runs`）とジャーナルの番号の連続から数える。ジョブが動かなかった日は「不明」として呼び出す。
- **端末の計測**：送るのは状態・同期の数・速さ・送受信の結果・資源・環境・異常終了のスタックの跡。送らないのは名前・パス・中身・中身とブロックのハッシュ・ノードの ID・アカウント・端末の名前と ID・IP アドレス。計測の ID は 30 日ごとに作り直す。受けた側は資格情報を確かめた後にアカウントと端末と IP アドレスを捨てる。利用者は設定で、チームは方針で止められる。範囲は L1 の後に確定する。
- ログ・トレース・メトリクスにブロックのハッシュを出さず、`block_id` で指す。

### 他の案を選ばなかった理由

- **2（端末の時刻）**：端末の時計のずれが混ざり、p99 の 5 秒を判定できない。
- **3（合成監視だけ）**：4 台の端末で、利用者の全体の分布（大きなチーム、購読の多い名前空間）を見られない。
- **b（詳しい計測）**：アカウントに結ぶと、利用者の行動の記録になり、L1・L4 の論点が広がる。調査には、利用者の同意を得たサポートの経路を別に使う。
- **c（持たない）**：競合・消しすぎの止め・走査し直しの率で、クライアントの段階の配布を止める判断（[runbooks/README.md](../runbooks/README.md) の 3 節）ができない。

## Consequences

- 良くなること：
  - 伝播を全体の分布と端末の実感の両方で見られ、どちらも時計のずれを含まない。
  - 端末の計測から、利用者の名前・中身・行動を辿れない。
- 引き受けるコスト：
  - 受け渡しの遅れは、端末で置くまでの時間を含まない（端末の計測のヒストグラムで別に見る）。
  - 計測を止めた端末の健全さは見えない。止めた割合を別に見る。
  - 計測の ID を替えるので、1 台の端末の長い期間の振る舞いを追えない。

## Confirmation

- 試験：端末の計測の送信の本文に、試験の木の名前・パス・ハッシュ・ノードの ID が含まれない。
- lint：ログ・トレース・メトリクスの呼び出しに、名前・パス・ハッシュ・トークンの印の付いた型を渡すコードを禁止する。
- 性質ベーステスト：`delivery_samples` が端末と名前空間の組ごとに 1 つだけで、書いた端末を数えない。
- 本番：ログの走査で、ハッシュ（64 桁の 16 進数）や名前の形が見つかったら呼び出す。
