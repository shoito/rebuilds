# ADR-0023: 木の一覧は `node_id` の順のページで、始めの番号（`snapshot_seq`）と終わりの番号（`listing_end_seq`）を返す。クライアントは一覧の後に `snapshot_seq` からジャーナルを当て、`listing_end_seq` まで読んでから親のない行を捨てる。ジャーナルは日の分割で 92 日を過ぎたら落とし、カーソルは最後の利用から 90 日で取り直しにする

## Context

[ADR-0005](0005-namespace-journal-and-cursors.md) は、番号 0 からの読み出し（同期の最初、`mount`）を、ジャーナルではなく木の今の状態の一覧（ページつき）で返すと決めた。ジャーナルは日で分割して 90 日を過ぎた分割を落とし、名前空間ごとに `floor_seq` を持つとした。

詳細を決めると、次の問題がある。

- 10 万〜数百万ノードの一覧は数分かかり、その間も書き込みがある。ページの間で木が動くと、移動したノードを 2 回読む・読み落とす。
- 一覧で祖先の削除を 1 行ずつ調べると、深さの分だけ引く（[ADR-0021](0021-committer-operations-and-conditions.md) のフォルダーの削除は根の 1 行）。
- 日の分割を落とすたびに、数百万の名前空間の `floor_seq` を数え直すのは重い。

## Options

一覧：

1. **`node_id` の順のページ。始めと終わりの番号を返し、クライアントがジャーナルを当てて収束させる**
2. 一覧の間、名前空間を読み取りの写し（同じトランザクション）に固定する
3. 一覧を S3 の写し（夜間に作る）から返す

保持：

- a. **カーソルの最後の利用から 90 日、分割は 92 日。`floor_seq` は特別な場合だけ**
- b. 分割を落とすたびに名前空間ごとの `floor_seq` を数え直す

## Decision

1 と a を採用する。詳細は [metadata-and-journal.md](../architecture/metadata-and-journal.md) の 7・8 節。

- `list_tree` は `deleted_at IS NULL AND hidden_batch_id IS NULL` の行を `node_id` の順に 2,000 件ずつ返す。祖先の削除は調べない。最初のページで `snapshot_seq`、最後のページで `listing_end_seq` を返す。ページのカーソルは 24 時間。
- クライアントは、一覧の後に `snapshot_seq` から `list/continue` で当てる。行は操作の後の状態を持つので、順に当てれば収束する。`listing_end_seq` まで当てた後で、根から届かない行を捨てる。
- `list/continue` は、位置を今の `ns_seq` まで進めたカーソルを毎回出し直す。`issued_at` から 90 日を過ぎたカーソルは取り直し。分割は 92 日で落とす。
- `floor_seq` は、名前空間ごとに行を落とす特別な場合（テナントの削除、名前空間の作り直し、手での修復）だけ上げる。
- 取り直しの理由は `expired`・`truncated`・`epoch` の 3 つ。

### 他の案を選ばなかった理由

- **2（写しに固定）**：数分の長いトランザクションが、Aurora の掃除（vacuum）を止め、reader の遅れを生む。
- **3（S3 の写し）**：写しの古さの分だけジャーナルを長く当てる。写しを作る仕組みと費用が増える。最初の同期の速さが要るなら、S2 の前に測って足す。
- **b（数え直し）**：S1 で数百万の名前空間を毎日数える。最後の利用で決めれば、保持の約束は同じに守れる。

## Consequences

- 良くなること：
  - 一覧が長いトランザクションを持たない。書き込みと並べられる。
  - 一覧の読み出しが 1 つの索引の範囲の読み出しになる。
  - 保持の判断が、カーソルの中の時刻だけで済む。
- 引き受けるコスト：
  - クライアントは一覧の後に、一覧の間の変化を当てる手間を持つ（`sync-core` と SDK の両方）。
  - 一覧に、祖先が削除された行も入る（クライアントが捨てる）。保持の期限の `purge` までの分だけ量が増える。
  - ジャーナルの保持が 2 日分長い。

## Confirmation

- 性質ベーステスト：PROP-META-002（一覧の途中に任意の書き込みを混ぜても、手順で作った木が `listing_end_seq` の後の全件と一致）、PROP-META-001。
- 表駆動テスト：DT-META-002（取り直しの理由）。
- 結合テスト：89 日前に使ったカーソルで、`list/continue` が欠けなく返る。91 日前のカーソルは `reset`。
- 本番：カーソルの取り直しの率を理由ごとに見る（`cursor-reset-spike.md`）。
