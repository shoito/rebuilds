# ADR-0014: デスクトップのクライアントは、資格が効かなくなったら同期を止め、端末の鍵で状態を確かめる。切り離しでは手元のファイルとローカルの状態の DB を残し、同じアカウントで入り直せば続きから同期する。消去では、同期のルートの登録を先に外し、意図の記録を通して同期のフォルダーの中だけを消し、DB を最後に消して結果を報告する

## Context

端末の資格（認可コード＋PKCE の登録、端末の鍵に結んだ回転する更新トークン）、取り消しの速さ（60 秒以内）は [ADR-0041](0041-accounts-auth-and-device-credentials.md) が決めた。切り離しと消去の状態の機械（`active` → `unlinked`、`wipe_pending` → `wiping` → `wiped`・`wipe_failed`）、消去で消すもの、`POST /device/status` での受け取りは [ADR-0043](0043-admin-roles-device-wipe-and-member-access.md) が決めた。本家は、切り離しのときに遠隔の消去を選べ、端末が次にオンラインになったときに行う（同 ADR の出典）。

デスクトップのクライアントの側で、次が決まっていない。

- 切り離されたとき、手元のファイルとローカルの状態の DB（3 つの木、意図の記録）をどうするか。
- 消去の途中で落ちたとき、二重に消す・同期のフォルダーの外を消す・消し残すことを、どう防ぐか。
- 消去の間に OS（File Provider、Cloud Files）がプレースホルダーの取り出しを求めたら、どうするか。

## Options

切り離し：

1. **手元のファイルと DB を残す。同じアカウントで入り直せば続きから**
2. 手元のファイルを残し、DB を消す（入り直しは最初の同期から）

消去の手順：

- a. **同期のルートの登録を先に外し、意図の記録を通して同期のフォルダーの中だけを消し、DB を最後に消す**
- b. 同期のフォルダーを 1 回の再帰の削除で消す

## Decision

1 と a を採用する。詳細は [desktop-client.md](../architecture/desktop-client.md) の 7 節。

- 資格が効かなくなった（401）ら、転送と commit を止め、端末の鍵で署名した `POST /device/status` を呼ぶ（[ADR-0043](0043-admin-roles-device-wipe-and-member-access.md)）。
- `unlinked`：資格と端末の鍵を消し、ログインの画面にする。手元のファイル・プレースホルダー・DB を残す。同じアカウントで入り直したら、DB の Synced を使って続きから同期する（[ADR-0010](0010-local-state-db-and-intent-log.md)）。別のアカウントで入ったら、DB を消し、同期のフォルダーを別の場所にする。
- `wipe`：
  1. `wiping` を報告する。
  2. 同期のルートの登録（Cloud Files の同期のルート、File Provider の領域）を外し、OS からの取り出しの要求を止める。
  3. 同期のフォルダーの中を、`intents` に 1,000 件ずつ意図を書いて、子から親の順に消す。OS のゴミ箱を通さない。パスは同期のルートの下にあることを、正規化した絶対パスで毎回確かめる。シンボリックリンクはたどらない。
  4. staging・ローカルのブロックの索引・キャッシュ・ログを消す。
  5. 消した数と、消せなかった数を報告する（`wiped`・`wipe_failed`）。
  6. 資格と端末の鍵を消し、最後に DB を消す。
- 消去の途中で落ちたら、起動で DB の `wipe_in_progress` を見て、3 から続ける。DB を消した後に落ちたら、同期のフォルダーの残りは手で消すよう表示する（パスは表示しない、場所だけ）。

### 他の案を選ばなかった理由

- **2（DB を消す）**：入り直しのたびに 100 万ファイルの木を読み直し、手元とサーバーで中身の違うものがすべて競合のコピーになる（[ADR-0010](0010-local-state-db-and-intent-log.md) の DB の作り直し）。
- **b（1 回の再帰の削除）**：途中で落ちたときに、どこまで消したか分からない。登録を外す前に消すと、OS が取り出しを求めて中身を書き戻す。リンクをたどって同期のフォルダーの外を消すおそれがある。

## Consequences

- 良くなること：
  - 誤った切り離しから、続きから戻せる。
  - 消去が途中で落ちても続けられ、同期のフォルダーの外を消さない。
- 引き受けるコスト：
  - 切り離した端末に、DB（ファイルの名前と木）が残る。消去を選ばない限り、利用者の端末のデータとして扱う。
  - 消去は、ファイルの数に比例して時間がかかる（100 万ファイルで数分）。

## Confirmation

- 表駆動テスト：DT-DESK-002（切り離しと消去 × 端末の状態）。
- 結合テスト：消去の各段でクラッシュさせ、起動の後に同期のフォルダーの中が消え、外が残る。同期のフォルダーの中のシンボリックリンクの先が残る。
- 性質ベーステスト：PROP-DESK-002（切り離しの後、その端末の資格での要求がどの経路でも通らない）。
