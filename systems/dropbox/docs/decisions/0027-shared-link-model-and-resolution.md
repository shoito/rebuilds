# ADR-0027: リンクは名前空間とノードの ID を指し、見せる相手（`anyone`・`team`・`members`）、パスワード、期限、ダウンロードの可否を持つ。トークンは `<brand>_sl_` の接頭辞、190 ビットの乱数、6 文字の検査の値で、ハッシュだけを持つ。解決のたびに、リンクの状態・今の方針・見せる相手・パスワード・ノードの今の場所を確かめ、使えない理由を利用者に区別して見せない

## Context

[ADR-0004](0004-tenancy-namespaces-and-rls.md) は、共有リンクの主体を「リンクを持つ人」とし、`view` だけを与え、パスワード・期限・方針を `can()` の入力にすると決めた。`link_tokens` は RLS の外の表で、解決は X2 の経路で行う。[architecture/README.md](../architecture/README.md) の 6 節は、リンクを閲覧だけにし、パスワード・期限・ダウンロードの禁止を有料のプランにし、チームの方針で絞れると決めた。

本家は、パスワード・期限・ダウンロードの設定を有料の区分（Professional、Essentials、Standard、Advanced、Business、Business Plus、Enterprise）で提供し、見せる相手に「リンクを知っている全員」と「チームのメンバー」を持つ（[Link expiration and passwords](https://help.dropbox.com/share/link-expiration)、2026-10-09 に確認）。トークンの形は公開されていない（**未検証**）。

決めることは次である。

- リンクが何を指すか（パスか ID か、リビジョンか）。
- トークンの形と持ち方。
- 方針・設定を、作った時と解決の時のどちらで評価するか。
- 拒否の理由をどこまで見せるか。

## Options

指す先：

1. **名前空間とノードの ID。解決の時の最新のリビジョン**
2. パス
3. 作った時のリビジョン

評価の時：

- a. **解決のたびに、今の方針と設定で評価する**
- b. 作った時に方針で設定を決め、解決では設定だけを見る

拒否の理由：

- x. **訪問者に区別して見せない（パスワードの画面を除く）**
- y. 「期限切れ」「無効」などを見せる

## Decision

1、a、x を採用する。詳細は [shared-links.md](../architecture/shared-links.md) の 4〜7 節。

- `shared_links(tenant_id, ns_id, link_id, node_id, audience, password_hash, expires_at, download_allowed, state, …)` を名前空間の表に置く。ノードが同じ名前空間の中で動いても使え、別の名前空間へ移ったら使えない。
- 見せる相手は `anyone`・`team`（持ち主のチームのメンバー）・`members`（その名前空間を既に読める人）。`members` は本家にない。
- トークンは `<brand>_sl_` ＋ 32 文字の base62（約 190 ビット）＋ 6 文字の base62 の CRC32。`link_tokens` に SHA-256 を持ち、`shared_links` に KMS で暗号化した値を持つ。URL は `www.<brand>.<domain>/s/<token>` で、名前を含めない。
> 2026-10-09 の注記：最初の起票の接頭辞は `<brand>sl_` だった。統合の工程で、他のトークン（`<brand>_at_`・`<brand>_rt_`・`<brand>_whsec_` など）と同じ形の `<brand>_sl_` に揃えた。

- パスワードは Argon2id。確かめた印は `password_version` 付きの署名つきの Cookie（12 時間）。
- 解決のたびに `can()` に、状態、期限、今の方針（キャッシュ 60 秒）、見せる相手とログインの主体、パスワードの印、ノードの今の場所、中身の検査の結果（[ADR-0046](0046-content-scanning-framework.md) の `scan_state`）を渡す。方針を広げても、無効にしたリンクを戻さない。
- 拒否は、理由に関わらず同じ 404 の画面にする。理由はアクセスの記録にだけ残す。
- 中身の URL はプレビュー 5 分、ブロック 15 分。ダウンロードの禁止のリンクでは、ブロックの URL を出さない。

### 他の案を選ばなかった理由

- **2（パス）**：名前の変更・移動でリンクが切れる。同じパスに別のファイルが置かれると、別の中身を見せる。
- **3（作った時のリビジョン）**：持ち主が直したファイルを見せられない。本家の振る舞いとも違う（本家はリンクで最新を見せる。**未検証**）。
- **b（作った時に決める）**：方針を狭めても、既にあるリンクが外へ出続ける。
- **y（理由を見せる）**：期限切れと無効化を区別すると、トークンを拾った人に、そのリンクが本物だったことと持ち主の操作を教える。持ち主への説明はアクセスの記録で足りる。

## Consequences

- 良くなること：
  - 方針・無効化・期限・共有の解除が、次の解決から効く。
  - トークンの漏えいの影響を、ハッシュの保存と検査の値で抑えられる。
- 引き受けるコスト：
  - 解決のたびに方針と名前空間の文脈を引く（キャッシュで p99 300ms に収める）。
  - 訪問者は、リンクが使えない理由を知らずに持ち主へ問い合わせることになる。
  - 出した中身の URL は、無効化の後も最長 15 分使える。
