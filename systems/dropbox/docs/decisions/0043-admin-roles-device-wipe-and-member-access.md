# ADR-0043: 管理の役割を 7 つにし、`can()` の入力にする。端末の切り離しと消去は状態の機械で持ち、消去は切り離しの時にだけ選べ、端末が次につながったときに端末の鍵で確かめて行う。管理者によるメンバーのフォルダーへのアクセスは、法務の L7 の結論まで `release.admin-member-access` の裏に置き、期限つきの許可・`can()` の入力・監査ログの仕組みだけを作る

## Context

- チームの管理者は、メンバー、グループ、チームのフォルダー、共有の方針、端末、監査ログを扱う（[intent.md](../intent.md) の MVP）。本家は 8 つの管理の役割を持ち、上位のプランだけ役割を分けられる（[Change admin rights for your Dropbox team](https://help.dropbox.com/security/change-admin-rights)、2026-10-09 に確認）。
- 本家は、端末を切り離すときに遠隔の消去を選べ、消去は端末が次にオンラインになったときに行う。既に切り離した端末には後から消去を足せない。状態を Pending・In progress・Succeeded・Failed で示す（[How to remote wipe files from a computer](https://help.dropbox.com/delete-restore/delete-dropbox-device)、同日に確認）。
- 本家の管理者は「メンバーとしてログイン」で、メンバーのフォルダーを開き、削除・復元できる（[Can admins see my account?](https://help.dropbox.com/account-access/admin-control)、同日に確認）。本システムで同じことをしてよいかは、法務の L7（労働者のプライバシー、社内の規程での周知）の確認待ちである。
- [ADR-0006](0006-sync-conflict-model.md) は、サーバーからの削除で手元を消すとき、OS のゴミ箱へ移すとした。消去は利用者・管理者の明示の操作で、ゴミ箱に残すと消去にならない。
- 権限は `can()` だけで判定する（[ADR-0004](0004-tenancy-namespaces-and-rls.md)）。

## Options

消去の指示の渡し方：

1. **切り離した端末が、端末の鍵で署名した要求で状態を確かめ、`wipe` を受ける**
2. 切り離しを遅らせ、端末の資格情報が効くうちに消去の命令を同期の経路で送る
3. 消去を持たない（切り離しだけ）

管理者のアクセス：

- a. **期限つきのアクセスの許可を `can()` の入力にし、法務の L7 まで出さない**
- b. メンバーとしてログインする（本家の形）を作り、L7 まで出さない
- c. 作らない

## Decision

1 と a を採用する。

### 管理の役割

| 役割 | 範囲 |
| --- | --- |
| `team_admin` | すべて。役割の付与と外し、SSO・SCIM、請求、チームの削除 |
| `user_admin` | メンバー、グループ、引き継ぎ、端末の切り離しと消去 |
| `content_admin` | チームのフォルダー、共有の持ち主の付け替え、チームのフォルダーの復元と巻き戻し |
| `security_admin` | 共有・共有リンク・端末・セッションの方針、一斉の変更の知らせ |
| `support_admin` | サインインの手助け（セッションの取り消し、端末の切り離し）。中身に触れない |
| `billing_admin` | 請求と席 |
| `auditor` | 監査ログと報告の閲覧・書き出し。変更しない |

- `team_standard` は `team_admin` だけ、`team_advanced` で役割を分ける。最後の `team_admin` は外せない。委任の範囲（グループの単位）は持たない。
- 役割は `can()` の入力にする。管理の API で役割の名前を比べない。

### 端末の切り離しと消去

- 状態：`active` → `unlinked`、または `active` → `wipe_pending` → `wiping` → `wiped`・`wipe_failed`。`wipe_pending` のまま 180 日つながらなければ `wipe_expired`。
- 消去は切り離しの時にだけ選べる。有料のプランとチームだけ。
- 切り離しは直ちに資格情報を取り消す（[ADR-0041](0041-accounts-auth-and-device-credentials.md)）。端末は資格情報が効かなくなったら、端末の鍵で署名した `POST /device/status` を呼び、`wipe` か `unlinked` を受ける。
- 消去で消すもの：同期のフォルダーの中のファイルとフォルダー（プレースホルダーを含む）、ローカルの状態の DB、ローカルのブロックの索引とキャッシュ、資格情報、ログ。サーバーに上げていない手元だけの変更も消す。**OS のゴミ箱を通さない**（ADR-0006 の例外）。同期のフォルダーの外は消さない。安全な消去（上書き）はしない。
- 消した数と、消せなかったノードの ID（手元だけのものは数）を報告する。
- モバイルは、切り離しで、オフラインのファイル（端末の鍵の保管庫の鍵で暗号化して持つ）・キャッシュ・待ちの一覧・資格情報を消す。

### 管理者によるメンバーのフォルダーへのアクセス

- `release.admin-member-access` の裏に置き、L7 の結論まで本番で有効にしない。
- 許可 `admin_member_access_grants` は、管理者、対象のメンバー、`scope`（`read`・`read_write`）、理由、最長 24 時間の期限を持つ。許可は `can()` の入力で、対象のメンバーのルートの名前空間に効く。他のテナントの名前空間（対象が参加している外部の共有フォルダー）は既定で含めない。
- 許可の作成、許可の下での読み出し（ノードの ID と数）と書き込み（`actor_id` は管理者、`on_behalf_of` は対象）を、監査ログに残す（[ADR-0045](0045-audit-log-and-data-lifecycle.md)）。
- 対象への知らせ、`read_write` を出すか、理由の選択肢は L7 で決める。

### 他の案を選ばなかった理由

- **2（切り離しを遅らせる）**：盗まれた端末の同期が、消去が届くまで続く。消去が届かないうちに中身を読まれる。
- **3（消去なし）**：本家にあり、チームの管理者が退職者や紛失の端末で求める（[intent.md](../intent.md) の MVP の「端末の一覧と遠隔の切り離し」）。
- **b（メンバーとしてログイン）**：管理者がメンバーとして振る舞うので、監査ログで「誰が」がぼやける。メンバーのセッションの全部の力（共有の変更、端末の切り離し）を持たせてしまう。許可の範囲と期限を絞れない。
- **c（作らない）**：L7 の結論が「持ってよい」なら、仕組みの設計から始めることになる。監査ログと `can()` の形を先に決めておく。

## Consequences

- 良くなること：
  - 盗まれた端末の同期はすぐ止まり、消去は端末がつながったときに確実に届く。
  - 管理者のアクセスを、範囲・期限・理由・監査で絞れる形にしておける。
- 引き受けるコスト：
  - 端末がつながらなければ消去は起きない（本家と同じ）。
  - 消去は手元だけの変更も消す。管理の画面で示す。
  - 本家の「メンバーとしてログイン」と違う形になりうる。L7 の後に [architecture/README.md](../architecture/README.md) の 1.4 節に行を足す。

## Confirmation

- 状態の機械のテスト：全部の移りと、許されない移り（`unlinked` に消去を足す、`wiped` から `active`）を拒むこと。
- ファイルシステムの端の場合の試験（実機）：消去が同期のフォルダーの外を消さない。開いたままのファイル・読み取り専用のファイルで `wipe_failed` と報告が出る。
- 結合テスト：`release.admin-member-access` が無効のとき、許可の API が 404 を返し、`can()` が許可を入力にしない。
- 決定表の表駆動テスト：役割と操作の全行（`can()` の決定表）。
- 漏れの経路の表に「管理者の許可の期限切れの後」を足し、期限の後に何も返さないことを確かめる。
