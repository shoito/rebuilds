# ADR-0037: モバイルのオフラインの保存は、利用者が指定したファイルとフォルダーだけを、その名前空間のカーソルで追い、アプリの中で読み取り専用で持つ。端末の切り離しで消す。通知は、APNs・FCM に種類と ID だけを渡し、名前などの中身はアプリが API から取って端末の中で組み立てる

## Context

[ADR-0001](0001-platform-and-stack.md) は、モバイルが木の全体の同期をしないと決めた。[intent.md](../intent.md) の MVP は、モバイルに「一覧、プレビュー、オフラインの保存（指定したファイルだけ）、カメラのアップロード」を求める。

決めることは次である。

- オフラインの保存をどう新しく保つか。モバイルで編集を受けるか。
- 端末を失くしたときの扱い。
- 通知の文（「佐藤さんが『2026 年度の予算』を共有しました」）を、APNs・FCM に渡すか。これらは外国の事業者のサービスで、渡すことが外国にある第三者への提供に当たるかは**法務の確認待ち：L4**である。

## Options

オフラインの保存：

1. **指定したものだけを、名前空間のカーソルで追い、読み取り専用で持つ**
2. 指定したものを、手元で編集できる形で持ち、`sync-core` の 3 つの木で同期する
3. 開いたものをキャッシュするだけ（指定なし）

通知：

- a. **種類と ID だけを渡し、文は端末で API から取って作る**
- b. 文を APNs・FCM の本文に入れる
- c. 通知を使わず、アプリを開いたときに一覧を見せる

## Decision

1 と a を採用する。詳細は [mobile-and-camera-upload.md](../architecture/mobile-and-camera-upload.md) の 10・11 節。

- オフラインの保存は、指定したファイルとフォルダーの名前空間ごとにカーソルを持ち、前景・背景の更新・前景の合図で差分を受け、新しいリビジョンを取る。端末の空きの 20% かつ既定 5 GB まで。
- アプリの領域に、iOS のデータ保護・Android の専用の領域で置く。他のアプリへは写しを渡すだけ。端末の切り離しで消す。
- 通知は `{type, event_id}` だけを APNs・FCM に渡す。iOS は通知の拡張、Android はデータのメッセージで受け、API の `notifications/get` で文を取って組み立てる。取れなければ決まった文を出す。
- APNs・FCM の使用は、L4 の結論まで `release.mobile-push` の裏に置く。それまではアプリの中の通知の一覧だけ。

### 他の案を選ばなかった理由

- **2（編集できる形）**：モバイルの OS の背景の制約の中で、3 つの木の計画と衝突の扱いを動かすことになる。File Provider の経験（E5）の前に、モバイルへ広げない。
- **3（キャッシュだけ）**：回線のない場所で使えるという約束にならない。
- **b（文を渡す）**：ファイルの名前と人の名前が外の事業者を通る。L4 の結論に依らず、中身を外へ出さない形を選ぶ。
- **c（通知なし）**：共有の招待やアップロードの停止に、利用者が気づかない。

## Consequences

- 良くなること：
  - モバイルで手元の変更を失う場面がない（編集を持たない）。
  - 通知の経路に、名前と中身が流れない。
  - 端末の紛失のとき、切り離しで手元の写しを消せる。
- 引き受けるコスト：
  - モバイルで、オフラインのファイルを直接編集できない。
  - 通知の文の取得で、API の呼び出しが 1 回増え、取れないと決まった文になる。

## Confirmation

- 結合テスト：APNs・FCM に送る直前の本文に、名前・メールアドレス・パスが含まれない。
- 結合テスト：端末の切り離しの後、オフラインの保存と一時のファイルが消える。
- 性質ベーステスト：指定したファイルの名前空間で、差分を当てた手元の写しが、サーバーの今のリビジョンと一致する（[ADR-0005](0005-namespace-journal-and-cursors.md) の性質の、モバイルの部分集合）。
