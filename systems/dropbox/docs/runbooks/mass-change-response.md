# Runbook: 一斉の削除・ランサムウェアからの回復

- Owner: Ops（チームの管理者と利用者への案内はサポート）
- 対応するアラート: 一斉の変更の検知の `alert`、一斉の変更の検知の急増（1 時間の数が前の週の 5 倍）、利用者・管理者からの「ファイルが一斉に消えた・暗号化された」の連絡（[README.md](README.md) の 4 節）。訓練
- 最終確認日: 2026-10-09

手順の設計は [versions-and-recovery.md](../architecture/versions-and-recovery.md) の 6・7 節、[ADR-0030](../decisions/0030-restore-and-rewind-as-journaled-batches.md)、[ADR-0031](../decisions/0031-mass-change-detection.md)。

## 症状

- ある名前空間 × 端末で、10 分の窓に多くの中身の変更・削除・拡張子の変わる名前の変更が起きた（`mass_change_events` の `alert`）。
- 利用者が、多くのファイルの消失や、`.locked` などの拡張子と身代金の要求の文書（`README_DECRYPT.txt` など）を見つけた。
- 多くの端末で同時に `alert` が出ている（広い攻撃か、検知の誤り）。

## 影響

- 中身は失われていない。変更は新しいリビジョン、削除は「削除したファイル」として、保持の期間（30・180・365 日）の中で残る。
- 感染した端末が同期を続ける間、暗号化と削除がサーバーと他の端末へ広がる。
- 端末の消しすぎの止め（5 分の窓で 1,000 ファイルか木の 10%）が手元からの削除を止めていることがある。中身の書き換え（暗号化）は止めない。

## 確認

1. `alert` の名前空間・端末・主体・窓の始まり、信号ごとの数（[versions-and-recovery.md](../architecture/versions-and-recovery.md) の 7.2 節）。名前と中身は見ない。
2. 同じ主体の新しい端末のログイン、新しい OAuth のアプリの許可がないか（乗っ取りなら `account-takeover.md`）。
3. 同じ時間に、その端末の他の名前空間（載せた共有フォルダー・チームのフォルダー）にも変化があるか。共有フォルダーは持ち主ごとに別の名前空間で、それぞれ巻き戻す。
4. 検知の誤り（写真の整理、ビルドの出力、大きなリファクタリング）でないかを、持ち主・管理者に確かめる。本システムは自動で同期を止めず、巻き戻さない。

## 対処

1. **広がりを止める**：持ち主（チームは `user_admin`・`security_admin`）が、感染した端末を切り離す（必要なら消去も。[ADR-0043](../decisions/0043-admin-roles-device-wipe-and-member-access.md)）。乗っ取りの疑いなら、すべてのセッションと端末を取り消す。他の端末の手元の同期は続けてよい（巻き戻しの差分を受けるため）。
2. **時点を選ぶ**：画面の活動のグラフで、窓の始まりの 5 分前（検知が示す候補）を基に選ぶ。保持の期間の外は選べない。
3. **対象を絞る**：名前空間の全体かフォルダーを選び、「時点の後に変わったファイル」を端末・人・拡張子で絞って、感染した端末の変更だけを対象にする。他のメンバーの正しい保存を戻さない。
4. **巻き戻す**：`restore-runner` が差を求め、1,000 操作ずつ commit する（名前空間の書き込みの上限の半分まで）。途中の利用者の変更は `skipped` に出る。`epoch` は上げず、端末は普通の差分として受ける。100 万ファイルで約 17 分（1 時間以内、NFR-009）。
5. **確かめる**：結果の `applied`・`skipped` の数、身代金の文書が「削除したファイル」に移ったこと、拡張子が戻ったことを、持ち主が画面で確かめる。暗号化された中身のリビジョンはバージョン履歴に残る。
6. **誤りに気づいたら**：巻き戻しの直前の番号（`rewind_jobs.before_seq`）への巻き戻しで取り消す。
7. **削除だけのとき**：消えたのがフォルダーなら、削除したフォルダーの復元（根の `undelete`）で、削除の時点の子孫がそろって戻る（秒の単位）。

### 止まったとき

- 巻き戻しが `paused`（権限の変更、書き込みの上限、障害）：原因を除いて再開する。記録した位置から差を求め直すので、二重に当てない（`restore-job-stuck.md`）。
- 保持の期限が近いリビジョンを戻すときは、作業の間ブロックにピンが付く（[block-storage.md](../architecture/block-storage.md) の 5.3 節）。

## 訓練

- E13 の `rewind-drill` と半年ごと：合成の「暗号化らしい変更」を 100 万ファイルの名前空間に流し、検知の通知 p95 5 分、巻き戻し 1 時間以内、取り消しで元に戻ることを確かめる。

## エスカレーション

- 多くのテナントで同時の `alert`：SEV1 の候補。[incident-response.md](incident-response.md) で IC を立て、検知の誤りか広い攻撃かを決める。
- 乗っ取り・データの持ち出しの疑い：セキュリティの担当。個人データなら法務（L4）。
- 保持の期間を過ぎて戻せないもの：サポートが持ち主に説明する。S3 のバージョニングの 30 日は GC の誤りのための守りで、利用者の巻き戻しには使わない。

## 事後

- 検知の閾値と誤検知の率を見直す（[quality.md](../quality.md) の 2.2.1 節 H）。
- `changes/` の新しい `intent.md` として起票する。
