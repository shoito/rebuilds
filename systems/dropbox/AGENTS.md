## この題材に固有の規則（開発リポジトリで守る）

### 本家の実装と名前

- **同期エンジン・分割・ブロックの索引・メタデータのジャーナルを自前で作る。** 本家のクライアント・サーバーのコード、本家の同期のプロトコル（API の内部の形を含む）、本家のクライアントのバイナリの解析の結果を、核にも依存にも使わない。本家の技術ブログ（dropbox.tech）の考え方を読むのはよいが、設計の文書に出典を書く。S3 は汎用のオブジェクトストアとして使ってよい（[リポジトリ共通の ADR-0007](../../docs/decisions/0007-no-reuse-of-original-implementation.md)、ADR-0001）。
- **本家の名前を識別子に使わない。** ドメイン（`<brand>.<domain>`、利用者の中身を返す `<brand>usercontent.<domain>`）、HTTP ヘッダー（`<Brand>-Signature`、`<Brand>-API-Arg`）、トークンの接頭辞（`<brand>_at_`）、デスクトップのフォルダーの名前（`~/<Brand>`）、アプリのバンドル ID、URL のスキーム、競合のコピーの名前の文言は `<Brand>`・`<brand>` で書く（[リポジトリ共通の ADR-0006](../../docs/decisions/0006-brand-neutral-identifiers.md)）。

### 中身を失わない

- **同期で黙って上書きしない。** サーバーへの書き込み（作成・変更・移動・削除）は、必ず元にしたリビジョン（`base_rev`）か「その名前がまだない」の条件を付ける。条件が合わなければサーバーは 409 を返し、クライアントは競合のコピーを作るか計画を立て直す。条件なしの上書きの API を作らない（ADR-0006）。
- **削除より変更を勝たせる。** 一方の削除と他方の変更がぶつかったら、変更を残す。フォルダーの削除と、その中への追加がぶつかったら、追加したものを残してフォルダーを作り直す。どちらを残すか迷う規則は、中身が残るほうを選ぶ（ADR-0006）。
- **クライアントの計画は 3 つの木から作る。** 同期エンジンは、サーバーの木（Remote）、手元の木（Local）、最後にそろった木（Synced）の 3 つを持ち、Synced を共通の祖先にして変化を求める。「手元にないからサーバーから消す」「サーバーにないから手元から消す」を、Synced を見ずに決めない（ADR-0006）。
- **ローカルの状態の DB の書き込みは、ファイルの操作と順序を決めて行う。** 操作の前に意図を記録し、操作の後に結果を記録する。途中で落ちても、再起動で意図の記録から再開し、二重に消す・二重に作ることを起こさない（sync-engine の領域）。
- **ブロックは検証してから索引に入れる。** ブロックの索引の行は、S3 に置いたオブジェクトの SHA-256 が番地のハッシュと一致することを確かめてから書く。クライアントが「置いた」と言っただけで索引に入れない。参照のあるブロックを消さない。消すのは、参照が 0 になってから猶予（7 日）を過ぎたものだけで、消した後も S3 のバージョニングで 30 日戻せる（ADR-0002、ADR-0007）。
- **分割の規則はバージョンで固定する。** 分割の母数（最小・平均・最大の大きさ、ギアの表）は `chunker_version` に結び付け、同じバージョンで同じ入力から同じ境界が出ることを守る。母数を変えるときは新しいバージョンを足し、古いバージョンの読み出しを消さない（ADR-0002）。

### メタデータとジャーナル

- **書き込みは、同じトランザクションでジャーナルに載せる。** ノード（ファイル・フォルダー）を変える書き込みは、名前空間ごとの `ns_seq` を振り、`ns_journal` と outbox を、変更と同じ DB のトランザクションで書く。ジャーナルを通らない書き込み（直接の `UPDATE` の一括の修正、復元、巻き戻しを含む）を作らない（ADR-0005）。
- **ノードは ID で指す。パスは表示と入口の解決のためだけに使う。** 移動・名前の変更は、ノードの `parent_id` と `name` を変えるだけにする。大きなフォルダーの名前空間の中の移動で、子孫の行を書き換えない。パスを主キーや外部キーにしない（ADR-0008）。
- **名前の一意は「NFC＋大文字小文字の畳み込み」の鍵で決める。** 同じフォルダーの中で、`name_key`（NFC に正規化して Unicode の case folding をかけたもの）が同じ名前を 2 つ作らない。表示の名前は NFC で持つ。比べるのは `name_key` だけにし、OS やライブラリの照合順序に任せない（ADR-0008）。
- **クライアントは OS の名前をそのまま信用しない。** macOS（NFD で返すことがある）・Windows（予約の名前、末尾の空白とピリオド、使えない文字）で表せない名前は、サーバー側の名前を変えずに、その端末だけ「同期できない名前」として示す。手元で表すために、黙ってサーバーの名前を変えない（ADR-0008）。

### テナントと権限

- **名前空間の表には `tenant_id`・`ns_id` と RLS を付ける。** `FORCE ROW LEVEL SECURITY` を外さない。名前空間の表は、`packages/access` が要求ごとに決めた `app.ns_ids` の中だけを読める。名前空間の外の表（アカウント、ブロックの索引の全体の集計など）は ADR-0004 の一覧の表だけにし、ファイルの名前と中身の列を持たせない。
- **権限は 1 つの関数で判定する。** 共有フォルダー・チームのフォルダー・共有リンク・チームの外への共有の方針は `packages/access` の `can()` だけで判定する。Web・API・同期・共有リンク・プレビュー・検索・Webhook・監査の画面で、別に条件を書かない（ADR-0004）。
- **重複排除で他人のファイルの有無を漏らさない。** 「そのブロックはもうある（送らなくてよい）」と答えるのは、要求した人が読める名前空間がそのブロックを参照しているときだけにする。それ以外は、テナントの中にあっても「送れ」と答え、受け取った後に保存だけを重ねる。テナントをまたいで重複を排除しない（ADR-0003）。

### 運用と入力

- **中身をログに出さない。** ファイルの名前、パス、中身、共有リンクのトークン、検索の語は、ログ・メトリクス・トレースの属性に書かない。ID と数と理由のコードだけを書く。
- **利用者のファイルを信用しない。** プレビュー・サムネイル・全文の抽出は、ネットワークを持たない隔離したタスクで、時間・メモリー・出力の大きさの上限を付けて動かす。利用者の中身を返すのは `<brand>usercontent.<domain>` からだけにし、本体のドメインから返さない。
- **同期・名前・権限の規則をフラグにしない。** 衝突の規則、`name_key` の作り方、分割の規則、`can()` の変更はコードのバージョンとして出す。`release.*` のフラグで経路ごとに切り替えない。
- **フラグの名前**：`release.*` は kebab-case（`release.shared-link-passwords`）、`ops.*` は snake_case（`ops.uploads_enabled`）。`release.*` は 100% の後 30 日で消す。
- **テストに本物のデータを使わない。** 実在の人のファイル、本家から書き出したファイルの一覧、本物の写真を、テスト・フィクスチャー・シードに書かない。ファイルの木と中身は生成する。

## このリポジトリでの規則

- ADR を追加・更新したら、`docs/decisions/README.md` の一覧を生成し直す。
- 領域の文書で ADR を起票するときは、[architecture/README.md](docs/architecture/README.md) の 7 節で領域に割り当てた番号の範囲の中で採番する。
- 本家の振る舞い・数値を書くときは、出典と確認日を付ける。確かめられないものは「未検証」と書く。
- OS の仕様（macOS の File Provider、Windows の Cloud Files API、ファイルシステムの正規化）と本家の振る舞いが違うときは、両方を書き、本システムがどちらに寄せるかを明記する。本家と違う振る舞いを選んだら、[architecture/README.md](docs/architecture/README.md) の 1.4 節の「本家との意図した違い」に行を足す。
