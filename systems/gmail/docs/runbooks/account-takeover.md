# Runbook: アカウントの乗っ取り（個別と大規模）

- Owner: Ops（乱用の対策の当番）、セキュリティ
- 対応するアラート: 乗っ取りの大規模な発生（サインインの失敗の急増、転送の規則の大量の作成。page）、乗っ取りの疑いの送信の急増の一部
- 最終確認日: 2026-10-10

ステートマシンと `locked` の動作は [accounts-and-security.md](../architecture/accounts-and-security.md) の 9 節（[ADR-0057](../decisions/0057-account-takeover-response.md)）、送信の点は [ADR-0021](../decisions/0021-sending-limits-and-compromised-account-detection.md)、回復は [ADR-0056](../decisions/0056-sign-in-risk-and-account-recovery.md)。

## 症状

- サインインの失敗が、IP の範囲をまたいで急増した（クレデンシャルスタッフィング）。
- 転送の先・フィルター（転送・削除・既読）の作成が急増した。
- 送信の点 0.9 以上で `locked` になるアカウントが急増した。
- 本人から「自分ではない」の申し出が来た。

## 影響

- 乗っ取られたアカウントのメールの持ち出し、転送の仕込み、本人の連絡先へのフィッシング。
- 共有の送信の IP の評判の崩れ（[ip-blocklisted.md](ip-blocklisted.md)）。

## 確認

1. 影響のアカウントの数と、`risk_state` の分布（`at_risk`・`locked`）。`account_risk_events` の理由のコード。
2. 攻撃の元の範囲・ASN、使われた入口（Web のサインイン、OAuth のアプリ、回復の手段）。
3. 直近 7 日の転送の先・フィルター・送信の別名・回復の手段の変更の数。中身・アドレスのローカル部は見ない。

## 対処

1. **個別のアカウント**：運用の手順で `account_risk` を出し、`locked` にする。`locked` の段（セッションとトークンの失効と IMAP の切断、送信と予約の送信の保留、直近 7 日の設定の変更を `suspended_pending_review`、古い回復の手段と組織の `security_admin` への知らせ）は自動で、冪等に回る。受信は止めない。
2. **大規模**：`risk_version` の緊急の出し方で、危険度の閾値を一時に下げる（中の帯を広げる）、範囲ごとのサインインを一時に止める、影響のアカウントを `at_risk` へ一括で移す。影 1 時間、Dev と Ops の 2 人の承認、7 日で失効。`ops.*` のフラグでは行わない。
3. **送信の評判**：疑いの間は共有のプールから送らない（`suspect` のプール）。掲載が出たら [ip-blocklisted.md](ip-blocklisted.md)。
4. **第三者のアプリ**：悪用のアプリなら、そのクライアントのトークンを失効させ、確かめの級を下げる（[ADR-0058](../decisions/0058-oauth-scopes-and-app-verification.md)）。
5. 本人の回復は、パスキー → 回復のコード → 回復のメール（72 時間の待ち）→ 組織の管理者の順。SMS・電話は使わない。

## エスカレーション

- 1 時間に数百を超えるアカウントの `locked`、または組織の管理者のアカウントの乗っ取り：セキュリティの担当と Dev のテックリード。SEV2。
- 個人のデータの漏えいの報告の要否：**法務の確認待ち**（L3）。

## 事後

- 入口（パスワードの使い回し、フィッシング、回復の悪用、アプリ）ごとに数え、守りの不足を `changes/` の新しい `intent.md` として起票する。
- 緊急の閾値を戻したことを確かめる（7 日で失効）。
