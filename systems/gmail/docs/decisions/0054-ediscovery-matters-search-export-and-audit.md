# ADR-0054: eDiscovery は案件（matter）の単位で行い、担当は案件ごとに割り当てた範囲の中だけを X7 の専用のロールで検索する。検索は `search-node` の受け持ちに案件の印を付けて広げ、本文の閲覧と書き出しは別の権限にする。書き出しは EML と目録で、書き出しごとの鍵で暗号化し、15 日の署名つきの URL で渡す。すべての操作をハッシュの鎖の監査ログに残し、書き出しの記録が書けなければ書き出しを止める

詳細は [retention-and-ediscovery.md](../architecture/retention-and-ediscovery.md) の 6・7 節。

## Context

- 組織の法務・監査の担当は、組織の中の複数のアカウントのメールを横断して検索し、書き出す（[intent.md](../intent.md)）。
- テナントをまたぐ処理は一覧の経路だけで、eDiscovery は X7（組織の中だけ、担当の役割、保留の案件、監査の記録）である（[ADR-0007](0007-tenancy-accounts-orgs-and-rls.md)）。検索の索引はアカウントごとで、`account_id` を先頭に持つ（[ADR-0009](0009-search-index-design.md)）。
- 担当は組織のメールを大量に見られる。1 人の担当の誤りや悪意で、範囲の外のメールが出る・持ち出される危険が最も大きい（[quality.md](../quality.md) の 1 節の順位 2）。
- 書き出しの形は、受け取ったバイトのままであることが証拠として要る（[ADR-0003](0003-message-storage-layout-and-dedupe.md)）。
- 本家の書き出しの形と検索の上限は確かめなかった（**未検証**）。

## Options

1. **案件の範囲の X7 のロールで `search-node` に広げ、閲覧と書き出しを別の権限にし、監査を同期で書く**
2. 組織ごとに eDiscovery の専用の索引（全アカウントの横断の索引）を作る
3. 担当に、範囲のアカウントへの委任（読みの権限）を一時に与える

## Decision

1 を採用する。

- 案件：`open`・`closed`・`deleted`。担当は `matter_members` と `matter_scope` で、範囲の外のアカウントを検索に出さない。
- 資格：`admin-api` の X7 のロールが、案件・範囲・期限 10 分を含む署名つきの内部の資格を出し、`search-node` と `mailstore` が検証する。X7 の資格は `PRESERVED` を含めて答える。
- 権限：検索と一覧（ヘッダーの要約）、本文の閲覧（`ediscovery.read_body`）、書き出し（`ediscovery.export`）を分ける。書き出しは既定で別の `ediscovery_admin` の承認を要る。
- 検索の負荷：`search-node` の CPU の 20% まで。件数は正確に数える。結果は案件ごとに S3 に置く。
- 書き出し：アカウントごとの EML（受け取ったバイト）と編集の表、目録（SHA-256）、`export.json`。1 GiB ごとの zip、書き出しごとの鍵（担当に 1 回だけ見せる）、専用のバケット、15 分の署名つきの URL、15 日で消す。
- 監査：案件・保留・検索（IR は案件の鍵で暗号化）・閲覧・書き出しの各操作を、ハッシュの鎖の監査ログ（[ADR-0061](0061-operator-access-cross-tenant-paths-and-audit.md)）に先に書き、書けなければ操作を 503 で返す。
- 本システムの運用者は eDiscovery の役割を持たない。捜査機関への対応は別の手順（法務の L4）。

### 他の案を選ばなかった理由

- **2**：組織の全メールの横断の索引は、アカウントの分離（[ADR-0009](0009-search-index-design.md)）の外に大きな置き場所を作る。保存と作成の費用が倍になる。
- **3**：担当に通常の読みの経路（JMAP・IMAP）を開くことになり、監査と範囲の制限が利用者の経路に混ざる。委任は MVP の後。

## Consequences

- 良くなること：
  - 索引を増やさずに横断の検索ができる。範囲の制限が資格で効く。
  - 閲覧と持ち出しを別の権限と 2 人の承認で抑えられる。
  - 記録のない操作が起きない。
- 引き受けるコスト：
  - 冷えたアカウントの多い案件の検索は遅い（1 万アカウントで p95 60 秒）。
  - 監査ログの停止で eDiscovery が止まる。
  - 書き出しの鍵を担当が失うと、書き出しを作り直す。

## Confirmation

- 性質ベーステスト：PROP-RET-004（範囲の外が出ない）、PROP-RET-005（記録のない操作がない）。
- 結合：資格の期限切れ・範囲の改ざん（署名の検証の失敗）、承認なしの書き出し、範囲の一部の `search-node` の停止。
- 監査：毎月、書き出しの記録と S3 の書き出しのオブジェクトを突き合わせる（記録のない書き出し 0）。
