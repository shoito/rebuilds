# ADR-0028: 外部の画像は表示の時に usercontent の代理が取得し、配送の時には取りに行かない。代理はクッキー・Referer・利用者の IP を送らず、私的な IP の範囲を拒み、5 秒・10 MiB・転送 3 回の上限で取り、隔離したタスクで描き直して返す。キャッシュの鍵は account_id を先頭に持ち、アカウントをまたいで共有しない。迷惑メールの箱とフィッシングの画像は取らない

詳細は [attachment-and-url-scanning.md](../architecture/attachment-and-url-scanning.md) の 7 節。

## Context

- 外部の画像は `<brand>usercontent.<domain>` の代理で取得して表示し、利用者の IP と既読を送り手に渡さない、迷惑メールの箱の画像は表示しないと決めた（[architecture/README.md](../architecture/README.md) の 6 節）。いつ取るか、何を送るか、キャッシュをどう持つかは決めていない。
- 配送の時に取ると、受け取りの合図を送り手に渡し、利用者が開かないメールの画像まで取る。表示の時に取ると、開いた時刻を送り手が知りうる（追跡の画像）。
- 代理は、本システムの網から任意の URL に取りに行く部品で、SSRF の入口になりうる。画像の解析器の脆弱性を突く入力を、利用者の端末に渡しうる。
- キャッシュをアカウントで共有すると費用は下がるが、キャッシュの有無の時間の差で、他のアカウントが同じ画像を開いたかを推し量らせうる（NFR-010）。
- 外部の画像の代理の取得と利用者への説明は、外部送信規律の論点がある（法務の L8）。

## Options

1. **表示の時に取り、描き直し、アカウントごとのキャッシュ**
2. 配送の時に取って保存する
3. 表示の時に取り、アカウントをまたいでキャッシュを共有する
4. 代理を使わず、利用者の端末から直接取る

## Decision

1 を採用する。

- 描画の時に、`img@src` を `https://<brand>usercontent.<domain>/img/<token>` に書き換えて見せる。`token` は `(account_id, message_id, URL の SHA-256, 期限 24 時間)` の署名。URL は `token` に入れず、メッセージの行から引く。blob は変えない。
- 代理はクッキー・Referer・利用者の IP・利用者の User-Agent を送らない。名前の解決の後の IP が私的・ループバック・リンクローカル・メタデータの範囲なら拒み、転送 3 回の各回で確かめる。5 秒、10 MiB、PNG・JPEG・GIF・WebP（SVG は PNG に描き直す）。メールの送受信と別の egress の IP から取る。
- 取った画像は隔離した変換のタスクで解いて描き直し、メタデータを除いて返す（アニメーションは 200 コマ）。
- キャッシュの鍵は `account_id` を先頭に持ち、24 時間。アカウントごとの速さは 1 分 600。
- 迷惑メールの箱、`spam_phish`、フィッシングの点の高い `inbox_warn` の画像は取らない。
- 利用者は「表示する前に確かめる」を選べる。既定は表示。説明の文と既定は法務の L8 の後に確定する。

### 他の案を選ばなかった理由

- **2**：開かないメールの画像も取り、受け取りの合図を送り手に渡す。保存の費用が増える。
- **3**：キャッシュの時間の差で、他のアカウントの閲覧を推し量らせうる。
- **4**：利用者の IP・端末・既読が送り手に渡る。画像の解析器の脆弱性を突く入力が端末に届く。

## Consequences

- 良くなること：
  - 送り手に利用者の IP と端末を渡さない。
  - SSRF と画像の解析の攻撃を、代理と変換のタスクで止める。
  - アカウントをまたぐ推し量りを作らない。
- 引き受けるコスト：
  - 同じ画像をアカウントごとに取るので、取得とキャッシュの費用が増える。
  - 送り手は開いた時刻を知りうる（追跡の画像の時刻）。
  - 描き直しで、画像の見た目が少し変わることがある。
