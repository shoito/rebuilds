# ADR-0061: 運用者は利用者のメールの中身を読む経路を持たない。本番の操作は 2 人の承認の時間を限った昇格だけで、メールボックスのシャードと blob の読みの権限を人に与えない。ADR-0007 のテナントをまたぐ経路に、X4 の中身として時刻の仕事（送信の解放、スヌーズの起こし、不在の返信の終わり）・保持の期限・ドメインの検査を含め、X9（報告の取り込みの `fbl_trace` の引き）と X10（法務の手順の保全と書き出し）を足す。監査ログは流れごとのハッシュの鎖で、別の AWS アカウントの Object Lock に写す

詳細は [security.md](../architecture/security.md) の 6〜8 節。

## Context

- 本システムの運用者が利用者のメールの中身を見る経路は作らない。例外は同意のある報告と法務が承認した手続き（[ADR-0008](0008-spam-pipeline-boundary-and-secrecy.md)、法務の L1・L4）。経路の不在を、権限の形で確かめられる必要がある。
- テナントをまたぐ処理は [ADR-0007](0007-tenancy-accounts-orgs-and-rls.md) の X1〜X8 だけにする。group B の領域で、次の 2 つの持ち越しが出た。
  - 時刻の仕事（[ADR-0049](0049-timed-jobs-vacation-and-scheduled-send.md)）の見張りが X4 のロールで `timers` を引くこと。X4 の例に書き足すかを決める必要がある。
  - `report-ingest` が苦情の報告の `trace_token` から `fbl_trace` を引くこと（[outbound-smtp-and-reputation.md](../architecture/outbound-smtp-and-reputation.md) の 18 節）。X6 に含めるかを決める必要がある。
- 法務の手順（捜査機関への対応、法務の L4）は、組織の eDiscovery（X7）と違い、本システムが 1 つのアカウントを扱う。
- 組織の管理・eDiscovery・運用者の操作の監査は、欠けと改ざんを検出できる必要がある（[quality.md](../quality.md) の 5 節の E15）。

## Options

運用者のアクセス：

1. **中身の読みの権限を人に与えない。昇格は 2 人の承認と 1 時間で、系の表と運用の道具だけ**
2. 昇格で中身を読めるが、すべてを監査する
3. 本番の人のアクセスを一切なくす（すべてを自動化）

時刻の仕事：

- a. **X4 に含める**
- b. 新しい経路 X9 として別にする

## Decision

1 と a を採用する。加えて X9・X10 を足す。

- 人のロール：本番の読みは指標・ログ・トレース・設定だけ。変更は CI/CD とフラグの経路だけ。昇格（break-glass）は Ops の 2 人（依頼と承認）、1 時間、理由とインシデントの番号、セッションの記録。昇格でも、メールボックスのシャードの表（`SELECT` を含む）、blob・スプール・索引の `GetObject`、KMS の `tenant-root` の `Decrypt` を与えない。
- サポートの道具は A1・C1・ID・理由のコードだけを出す。届かないメールの調べは `Message-ID` の HMAC と時刻の範囲で行う。
- 経路：X4 は、ゴミ箱・迷惑メールの箱の期限、保持の期限と保全の評価し直し、パック、GC、時刻の仕事、ドメインの検査を含む。`sys_worker` のロールは期限の行の ID と期限の列だけを読め、操作はアカウントの文脈を設定して `mailstore` を呼ぶ。送信の解放は送信者の文脈で `outbound-gate` に渡す。
- X9：`report_lookup` のロールで `fbl_trace` を `trace_token` の一致で読むだけ（X6 に含めない）。
- X10：`lawful_access` のロールで 1 つのアカウントの保全と書き出し。法務と Ops の 2 人の承認の記録を要る。法務の L4 の結論まで有効にしない。
- 監査：流れ（`tenant_admin`・`tenant_ediscovery`・`account_security`・`operator`）× テナントのハッシュの鎖。directory に同じトランザクションで書き、1 分ごとに監査のアカウントの S3（Object Lock のコンプライアンスのモード、既定 7 年）へ写し、1 時間ごとの先頭を KMS で署名する。毎日突き合わせる。eDiscovery と昇格は同期で書けなければ操作しない。
- ADR-0007 の本文の一覧の書き換えは Dev（テックリード）が行う。それまでこの ADR を一覧の補いの正本とする。

> 2026-10-10 の注記：統合の工程で、[ADR-0007](0007-tenancy-accounts-orgs-and-rls.md) の本文の一覧に、X4 の中身と X9・X10 を書き足した。以後は ADR-0007 の一覧が正本で、この ADR は理由を持つ。

### 他の案を選ばなかった理由

- **2**：監査は事後にしか効かず、経路の不在を確かめられない。通信の秘密の約束（法務の L1）が監査の運用に依る。
- **3**：障害の復旧（DLQ の戻し、シャードの手での切り替え）で人の操作が要る。手段がないと、緊急時に広い権限を作ることになる。
- **b（時刻の仕事を別の経路に）**：期限の行を探してアカウントの文脈で操作する形は、ゴミ箱の期限（X4）と同じで、経路を分けても守りが増えない。

## Consequences

- 良くなること：
  - 運用者が中身を見られないことを、IAM と DB のロールの静的な検査で確かめられる。
  - テナントをまたぐ経路の一覧が、group B の持ち越しを含めて閉じる。
  - 監査の欠けと改ざんを毎日見つけられる。
- 引き受けるコスト：
  - 中身を見ずに障害を調べる道具（ID と HMAC で引く道具）を作り、保守する。
  - 監査ログの書き込みの停止で、eDiscovery と昇格が止まる。
  - ADR-0007 の一覧と、この ADR の補いの 2 か所を読む期間がある。

## Confirmation

- IAM の静的な検査：PROP-SEC-004。DB のロールの照合：PROP-SEC-005。
- 性質ベーステスト：PROP-SEC-003（監査の鎖の改ざんの検出）。
- 演習：半年ごとの DR の訓練で、昇格の手順を通して使う。
