# ADR-0024: 学習のデータは、配送の時に作る C2 の特徴の記録に利用者の報告をラベルとして結び付けたもの、同意のある報告のサンプル、合成のメールだけにする。特徴の記録を学習に使うことの既定の有効化は法務の L1 の後。モデルと規則は評価の集まりの合否、影 7 日、段の出し方で出す。大きな波の対応の規則だけは誤り 0 と影 1 時間の速い道で出し、7 日で失効させる

詳細は [spam-and-abuse-filtering.md](../architecture/spam-and-abuse-filtering.md) の 9・12・13 節。

## Context

- [ADR-0008](0008-spam-pipeline-boundary-and-secrecy.md) は、学習を C2 と同意のある報告のサンプルと合成のメールで行い、受け取ったメールの C3 を同意なしに学習の置き場所へ写さないと決めた。報告と特徴をどう結び付けるか、どれだけ残すかは決めていない。
- 報告は配送の後、数分から数週間で来る。報告の時に特徴を作り直すには、C3 をもう一度読む必要がある。
- C2 を全員のメールから学習に使うこと自体が、通信の秘密の論点に当たりうる（法務の L1）。
- 選別のモデルと規則の誤りは、利用者が気づかない誤判定になる（[quality.md](../quality.md) のリスクの 3）。一方、フィッシングの波は数時間で広がり、通常の出し方（影 7 日）では間に合わない。

## Options

1. **配送の時に C2 の特徴の記録を作って 30 日残し、報告でラベルを付ける。通常は影 7 日、緊急の規則だけ速い道**
2. 報告の時に、メッセージから特徴を作り直す
3. 報告のサンプル（同意のあるもの）だけで学習する
4. 緊急の規則も通常の出し方だけ

## Decision

1 を採用する。

- 配送の時に、メッセージごとの特徴の記録（C1・C2）を `feature_id` で作り、特徴のストア（S3 の Parquet と、30 日の索引）に置く。メッセージの行が `feature_id` を持つ。
- 報告（明示の報告は重み 1、手で動かしたものは 0.3）で記録にラベルを付け、学習の行（アカウントの ID を含まない）を学習のアカウントに送る。
- 学習の置き場所に入るのは、ラベルつきの特徴の記録、同意のある報告のサンプル（C3、別のアカウント、1 年、取り消し 30 日）、合成のメール、評判の出来事だけ。IAM でこの経路に限る。
- ラベルつきの特徴の記録を学習に使うことの既定の有効化は、法務の L1 の後。それまでは選別の範囲の設定で同意を示した利用者の分だけを使う。
- モデル・閾値・規則・特徴の作り方を `filter_version` にまとめ、評価の集まりの合否 → 影 7 日 → 1% → 10% → 50% → 100% で出す。外れたら `ops.filter_model_pinned` で戻し、直近 24 時間の新しいバージョンの `spam` を前のバージョンで判定し直す。
- 緊急の規則：迷惑メールに寄せる向きだけ、正規のメールの評価で当たり 0、影 1 時間で「迷惑メールではない」0、Dev と QA の 2 人の承認、7 日で失効。SMTP の時点の規則は影 24 時間。

### 他の案を選ばなかった理由

- **2**：報告のたびに C3 を読み直すことになり、受け手のメールボックスから学習の経路を作る。配送の時の判定と同じ特徴にならない。
- **3**：サンプルの数が少なく偏る。新しい型への追随が遅い。
- **4**：波の間、見逃しが続く。

## Consequences

- 良くなること：
  - 報告と、配送の時の判定の特徴を正しく結び付けられる。
  - C3 を学習に流す経路がない形を、IAM で確かめられる。
  - 波に数時間で対応できる。
- 引き受けるコスト：
  - 特徴の記録を全メッセージで作って 30 日置く費用。
  - 法務の結論まで、学習のデータが少ない。
  - 緊急の規則の承認の当番が要る。

## Confirmation

- 性質ベーステスト：PROP-FLT-005（C3 が特徴のストアに書かれない）、PROP-FLT-007（指紋から戻せない）。
- 評価の集まりの合否（[quality.md](../quality.md) の 2.2.1 節 H）と影の比べ。
- レビュー：学習のアカウントへの書き込みの IAM の方針（security.md）。
- 監査：報告のサンプルの置き場所の操作の毎月の抜き取り。
