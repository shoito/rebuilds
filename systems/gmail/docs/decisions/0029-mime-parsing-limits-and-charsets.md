# ADR-0029: MIME の解析は上限の層（入れ子 32 段、パート 1,000、ヘッダーの部 256 KiB、時間 2 秒、メモリー 256 MiB など）で包み、超えたら解析を打ち切って理由のコードを残す。blob は受け取ったバイトのまま保つ。文字コードは WHATWG の Encoding Standard のラベルと復号器に寄せ、`Shift_JIS` は CP932、`ISO-2022-JP` は機種依存の文字の拡張を受けて読む。encoded-word は隣り合う同じ文字コードのものをバイトで繋いでから復号する

詳細は [message-parsing-and-storage.md](../architecture/message-parsing-and-storage.md) の 5・6 節。

## Context

- 受け付けた後のメッセージは、外部の誰でも送れる、壊れた・悪意のある入力である。入れ子の爆弾、巨大なヘッダー、base64 の展開で、解析の時間とメモリーが尽きうる（[quality.md](../quality.md) の 2.2.1 節 A）。
- 受け付けた後は拒めない（[ADR-0002](0002-accept-then-filter.md)）。解析に失敗したメールも、配送して利用者に見せる必要がある。
- 日本のメールには、宣言と違う文字コード、ISO-2022-JP の中の CP932 の文字（丸数字、`㈱`）、多バイトの文字を 2 つに分けた encoded-word、RFC 2231 の継続の欠けが多い。表示の崩れは、検索とスレッドの崩れにもなる（[intent.md](../intent.md)）。
- 解析のライブラリは汎用の部品を使う（[ADR-0001](0001-platform-and-stack.md)）。ライブラリによって、上限と文字コードの扱いが違う。
- HTML メールはブラウザーで描画する。メールの文字コードの解釈がブラウザーと違うと、同じメールが Web とアプリで違って見える。

## Options

上限：

1. **自前の上限の層で、バイト・木・時間・メモリーを数え、超えたら打ち切って配送は続ける**
2. ライブラリの既定の上限に任せる
3. 上限を超えたら、そのメッセージを隔離する

文字コード：

- a. **WHATWG の Encoding Standard のラベルと復号器に寄せ、メールに固有のもの（UTF-7、推定）だけを足す**
- b. IANA の文字コードの登録の名前どおりに厳密に読む（`Shift_JIS` は JIS X 0208 の範囲だけ）
- c. 宣言を見ずに、毎回推定する

## Decision

1 と a を採用する。

- 上限：ヘッダーの部 262,144 バイト、欄 1,000、1 欄 65,536 バイト、入れ子 32、パート 1,000、境界 200 文字、復号の後の大きさは元の 4 倍かつ 64 MiB、取り出す文字は 1 パート 1 MiB・全体 4 MiB、CPU 2 秒、メモリー 256 MiB。
- 超えたら、そこまでの木を残して打ち切り、理由のコード（`mime_too_deep` など）を `parse_flags` に付け、選別に渡す。blob は受け取ったバイトのまま保ち、利用者は元のメッセージを取れる。
- 文字コードは Encoding Standard のラベルの表で復号器を決める。`Shift_JIS` の類は CP932 の範囲で、`ISO-2022-JP` は半角カナと機種依存の文字の拡張を受ける。UTF-7 を足す。宣言がない・誤りが 1% を超えるときだけ推定する。
- encoded-word は、空白を挟んで隣り合う同じ文字コード・同じ符号化のものを、デコードしたバイトで繋いでから復号する。引用の文字列と引数の中の encoded-word も復号する。
- 携帯の事業者のアドレス（dot-atom に合わないローカル部）は、誤りとして捨てず、そのまま持つ。
- 値と規則はコードのバージョンで出し、`release.*` のフラグにしない（`AGENTS.md`）。

### 他の案を選ばなかった理由

- **2**：ライブラリを選び直すたびに上限が変わり、試験で約束できない。
- **3**：古い業務のアプリが深い入れ子を作る。正規のメールを隔離することになり、NFR-009 に反する。
- **b**：業務のアプリが送る丸数字や `㈱` が化ける。ブラウザーの表示ともずれる。
- **c**：宣言の正しいメールまで推定の誤りにさらす。

## Consequences

- 良くなること：
  - どの入力でも、解析は決めた時間とメモリーで終わる。
  - Web・アプリ・検索・スレッドが、同じ復号の結果を使う。
- 引き受けるコスト：
  - 寛容な読み方は、選別のすり抜けの余地になる（解析器の違いを突くメール）。差分のファジングで見張る。
  - Encoding Standard の更新に追従する（ラベルの表の試験のベクトルで確かめる）。

## Confirmation

- PROP-MSG-001・004・005（MIME のファジング、差分のファジング、encoded-word の分け方）。
- 文字コードの試験のベクトル（ISO-2022-JP の欠け、半角カナ、丸数字、宣言の誤り、UTF-7、波ダッシュ）を QA が持つ。期待する値の変更は QA の承認を要する。
- 監視：理由のコードごとの打ち切りの率。急な増加は解析器の退行か、新しい攻撃の形として調べる。
