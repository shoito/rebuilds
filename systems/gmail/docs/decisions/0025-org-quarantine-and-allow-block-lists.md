# ADR-0025: 組織の隔離はメールボックスに配らず、スプールを quarantine に写して directory の quarantine_items に置き、管理者の解放で判定の上書きつきの配送の依頼に戻す。30 日で消し、送り手に知らせない。管理者の画面はヘッダーの要約をスプールの写しから都度読み、DB に件名を持たない。組織の許可の一覧の送り手のドメインは、認証が通ったときだけ効く

詳細は [spam-and-abuse-filtering.md](../architecture/spam-and-abuse-filtering.md) の 10・11 節。

## Context

- [ADR-0002](0002-accept-then-filter.md) は、受け付けた後の判定の 1 つに「隔離（組織の方針）」を置いた。組織の管理者は、フィッシングやマルウェアを利用者に見せず、管理者が確かめてから渡したい。
- メールボックスのモデルはラベルが正で、迷惑メールとゴミ箱は排他のシステムのラベル（[ADR-0004](0004-labels-as-primary-mailbox-model.md)）。隔離を利用者のメールボックスのラベルにすると、利用者の同期（JMAP・IMAP）と容量と検索の全部に「見せないメッセージ」の扱いが要る。
- 隔離のメールを管理者が見るのは、組織の中の扱いで、本システムの運用者は見ない（[ADR-0008](0008-spam-pipeline-boundary-and-secrecy.md)、法務の L7）。RLS の外の表や directory に件名を置きたくない（[ADR-0007](0007-tenancy-accounts-orgs-and-rls.md)）。
- 組織の許可の一覧は、取引先の誤判定を避けるために要る。From のドメインだけで許すと、なりすましを素通りさせる。

## Options

隔離の置き場所：

1. **配らずに、スプールの写しと directory の行で持つ**
2. 受け手のメールボックスに、見せないシステムのラベルで配る
3. 組織ごとの共有の隔離のメールボックス（管理者のアカウント）に配る

許可の一覧：

- a. **認証が通ったときだけ効く**
- b. From のドメインで効く

## Decision

1 と a を採用する。

- 組織の方針で、`spam_phish`・`spam`・`attachment_blocked`・拒否の一覧・DMARC の `reject` の失敗を隔離に置き換えられる。既定は置き換えない。
- 隔離は `quarantine/<tenant_id>/…/<quarantine_id>` へのスプールの写し（テナントの隔離の鍵）と、directory の `quarantine_items`（`tenant_id` で FORCE RLS、件名を持たない）。受け手の配送は「隔離」として終わる。
- 管理者の画面は、行の一覧と、選んだ 1 件のヘッダーの要約（写しから都度読み、`<brand>usercontent.<domain>` から描く）。本文は別の役割で、監査に残す。
- 解放は `(spool_id, recipient)` の配送の依頼を `released_by_admin` の上書きで載せ直す（冪等）。`attachment_blocked` の印は残す。
- 削除と 30 日の期限で写しを消す。送り手には知らせない。受け手への要約の知らせは組織の方針で選ぶ（既定は送らない）。
- 許可の一覧の送り手のドメインは、DMARC の `pass` か From に揃う認証の `pass` のときだけ効く。IP の範囲の許可（前段のゲートウェイ）は接続の情報で効く。一覧は組織あたり 1 万件。

### 他の案を選ばなかった理由

- **2**：同期・容量・検索・IMAP の UID の全部に、見せないメッセージの例外が入る（[ADR-0004](0004-labels-as-primary-mailbox-model.md)、[ADR-0006](0006-sync-protocol-jmap-imap-and-modseq.md)）。
- **3**：管理者のメールボックスに、他人あてのメールが入る。受け手の文脈で書く決まり（[ADR-0007](0007-tenancy-accounts-orgs-and-rls.md)）に反する。
- **b**：From を騙るなりすましを素通りさせる。

## Consequences

- 良くなること：
  - メールボックスのモデルと同期に例外を入れない。
  - 解放は普通の配送の道で、冪等。
  - 件名を DB に持たない。
- 引き受けるコスト：
  - スプールの写しの置き場所と鍵を、隔離のために持つ。
  - 管理者の画面がスプールを都度読むので、表示が少し遅い。
  - 認証のない取引先は、許可の一覧で救えない（IP の範囲の許可か、取引先の設定の直しが要る）。
