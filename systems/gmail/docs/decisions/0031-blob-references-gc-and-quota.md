# ADR-0031: blob の参照は数ではなく参照の行の集合で持ち、配送の間はスプールの借り（lease）を参照に数える。借りが外れ参照が 0 になった blob は二度と参照されないので、1 時間の確かめの後に包んだ鍵を消し、7 日の後に物理で消す。容量はアカウントの論理の大きさで、メールボックスの変更と同じトランザクションで数える

詳細は [message-parsing-and-storage.md](../architecture/message-parsing-and-storage.md) の 8・9 節。

## Context

- [ADR-0003](0003-message-storage-layout-and-dedupe.md) は、参照の数え、outbox での減らし、参照 0 で鍵の破棄（24 時間以内）、7 日の猶予の後の物理の消去を決めた。
- blob の目録のシャードとメールボックスのシャードは別で、1 つのトランザクションに入らない。outbox は少なくとも 1 回届き、順序が入れ替わりうる。
- 1 つの配送の受け手は、別々のシャードに別々の時刻にコミットする。最初の受け手の削除が、2 人目の配送より先に届くと、数の形では一時的に 0 になる。
- 容量は受け手ごとの論理の大きさで数える（[ADR-0003](0003-message-storage-layout-and-dedupe.md)）。受信を止める判定（RCPT の 452）に使うので、ずれは誤った拒否になる。

## Options

1. **参照の行の集合と、配送の間の lease**
2. 参照の数（整数）を outbox で増減する
3. 参照を持たず、メールボックスの行を定期に走査して、どこからも指されない blob を消す

容量：

- a. **メールボックスの変更と同じトランザクションで足し引きし、週に 1 回照らす**
- b. 定期に集計する

## Decision

1 と a を採用する。

- 参照の種類は `lease`（`spool_id`・`submission_id`）、`mailbox`（メッセージの行）、`hold`、`outbound`。足す・外すは行の挿入・削除で冪等にする。
- lease は blob を作る時に足し、すべての受け手の `mailbox` の参照が目録に届いたことを確かめてから外す。
- lease が外れた後に参照の行が 0 になった blob は、新しい参照を得ない（共有は同じ配送の中だけ、保留は参照のあるメッセージにだけ掛かる）。`zero_since` から 1 時間の後、メールボックスのシャードに元の行がないことを確かめてから、包んだ鍵を消す。行があれば参照を足し直して警報を出す。
- 物理の消去は鍵の破棄から 7 日の後。
- 容量は `account_usage` に、メールボックスの変更と同じトランザクションで足し引きする。迷惑メール・ゴミ箱・下書き・予約の送信を数える。100% で directory の `quota_state` を `over` にし、95% を下回ったら戻す。

### 他の案を選ばなかった理由

- **2**：重複の届きと順序の入れ替わりで、数がずれる。ずれを直すには、結局どの参照があるかの集合が要る。
- **3**：270 億行の走査を回す費用と、走査と配送の競合（走査の途中の配送を消す）がある。
- **b**：受信の拒否の判定が集計の間隔だけ遅れる。

## Consequences

- 良くなること：
  - 参照のずれが、行の有無として確かめられる。
  - 「参照 0 は戻らない」ので、鍵の破棄を安全に早くできる。
- 引き受けるコスト：
  - 参照の行が、メッセージの行と同じ数だけ目録のシャードに要る（S1 で 270 億。1 行 60 バイトとして 1.6 TB）。
  - lease が外れない配送（outbox の止まり）を見張る。

## Confirmation

- PROP-MSG-006・007（参照と容量の性質）。
- 障害の注入：outbox の重複・順序の入れ替え・遅れで、参照のある blob の鍵が消えない。
- 監視：24 時間を超えた lease の数、1 時間の確かめで参照が見つかった数（0 が正常）、`account_usage` の週の照合のずれ。
