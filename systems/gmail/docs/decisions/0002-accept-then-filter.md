# ADR-0002: SMTP の時点では、接続の評判・宛先・容量・認証の失敗・既知のマルウェアのような安く確かなものだけを拒む。中身の選別は、スプールと待ち行列に確定して 250 を返した後に行い、迷惑メールの箱か隔離に入れる。受け付けた後に迷惑メールを送り返さない。グレーリストは使わない

## Context

受信の MX は、送り手の MTA との SMTP の会話の中で、メッセージを拒むか受け付けるかを返す（RFC 5321）。

- **拒む（5xx）**と、送り手の MTA が送り手に DSN を返す。責任は送り手の側に残る。拒んだメッセージは保存しない。
- **一時の拒否（4xx）**は、送り手に後で送り直させる。
- **受け付ける（250）**と、責任は本システムに移る。RFC 5321 の 6.1 節は、受け付けたメッセージを配送するか、配送できないことを知らせることを求める。

受け付けた後に迷惑メールと判定して DSN を返すと、偽の差出人（迷惑メールの MAIL FROM の多くは偽）へ DSN が飛ぶ。これは後方散乱で、本システムが迷惑メールの送り手になり、送信の評判を落とす。

一方、中身を深く見る判定（分類器、URL の評判、添付の検査）を SMTP の会話の中ですべて行うと、DATA の終わりの応答が遅れる。送り手の MTA は DATA の終わりの応答を 10 分待つ（RFC 5321 の 4.5.3.2 節）が、遅い応答は接続を長く占め、選別の部品の障害がそのまま受信の停止になる。

さらに、受け付けた後の消失は、利用者にも送り手にも見えない。250 は、耐久の置き場所に書いてから返さなければならない。

グレーリスト（知らない送り元の最初の試行を 4xx で断る）は、一部の迷惑メールの送信の道具を止めるが、正規のメールを送り手の再試行の間隔（数分〜数十分）だけ遅らせる。NFR-001（p95 10 秒）を満たせない。

## Options

1. **SMTP の時点では安く確かなものだけを拒み、中身の選別は受け付けた後に行う。受け付けた後の迷惑メールは箱に分ける**
2. すべての判定を SMTP の会話の中で行い、迷惑メールは 5xx で拒む
3. すべてを受け付け、判定は後で行い、迷惑メールは捨てるか DSN を返す

グレーリスト：

- a. **使わない。評判の分からない送り元の急な量だけを一時の拒否で絞る**
- b. 知らない（IP、MAIL FROM、宛先）の組をすべてグレーリストに入れる

## Decision

1 と a を採用する。

### SMTP の時点で判定するもの

上から順に評価し、最初に当たったものを返す。値は inbound-smtp の領域で決める。

| # | 段 | 条件 | 応答 |
| --- | --- | --- | --- |
| 1 | 接続 | 送り元の IP の評判が「拒否」（自社の評判と外部のブロックリストを合わせた判定） | 554 5.7.1 で切る |
| 2 | 接続 | IP・/24・ASN ごとの接続の速さの上限を超えた | 421 4.7.0 |
| 3 | 接続 | 評判の分からない IP の急な量（新しい IP の 1 時間の量の上限） | 421 4.7.0（同じ IP を 15 分まで） |
| 4 | EHLO | 逆引きと正引きが揃わない IPv6 の送り元 | 550 5.7.25 |
| 5 | RCPT | 宛先がない | 550 5.1.1 |
| 6 | RCPT | 宛先のアカウントが停止 | 550 5.2.1 |
| 7 | RCPT | 宛先の容量の超過 | 452 4.2.2 |
| 8 | RCPT | 宛先ごと・送り元ごとの受信の速さの上限 | 452 4.2.1 |
| 9 | DATA | 大きさが SIZE（50 MiB）を超えた | 552 5.3.4 |
| 10 | DATA の終わり | RFC 5322 の形の致命的な誤り（From がない、ヘッダーの行の長さの上限など） | 550 5.7.1 |
| 11 | DATA の終わり | DMARC の評価が失敗で、ドメインの方針が `p=reject`（転送の ARC で救えないもの） | 550 5.7.26 |
| 12 | DATA の終わり | 既知のマルウェアの添付（ハッシュの一覧に当たる） | 550 5.7.0 |
| 13 | DATA の終わり | 確信の高い規則に当たる（例：本システムのドメインを騙る From で、本システムからの送信でない） | 550 5.7.1 |
| 14 | DATA の終わり | スプールか待ち行列の確定に失敗 | 451 4.3.0 |
| 15 | — | それ以外 | 250 2.0.0 |

- DATA の終わりの検査（10〜13）には 10 秒の予算を置く。予算を超えた検査は「判定なし」として受け付け、受け付けた後の選別に任せる。選別の部品の障害で受信を止めない。
- DMARC の `p=quarantine` の失敗は拒まず、受け付けて迷惑メールの箱に入れる。
- 1 つのトランザクションの宛先は 100 まで。宛先ごとに判定が違うときは、宛先ごとに RCPT の応答で返す。DATA の後に宛先ごとに違う結果を返す仕組み（LMTP の形）は、SMTP にないので使わない。

### 受け付けの確定

1. DATA の終わりで、生のメッセージ（受け取ったバイトそのまま）と、封筒（MAIL FROM、宛先の一覧）、接続の情報（送り元の IP、EHLO、TLS）、同期の検査の結果を、S3 のスプール（`spool/<yyyy>/<mm>/<dd>/<hh>/<spool_id>`、SSE-KMS）に PUT する。
2. SQS に配送の依頼（`spool_id`、宛先の一覧）を載せる。
3. 両方が成功したら `250 2.0.0 OK <spool_id>` を返す。どちらかが失敗したら 451 を返す。スプールに残ったオブジェクトは掃除の役が消す。
4. 掃除の役は、10 分を過ぎても配送の記録のないスプールを見つけたら、依頼を載せ直す（SQS の欠けに備える）。

### 受け付けた後の選別と配送

- `inbound-pipeline` は、選別の判定を受け手ごとに当てる。判定は「受信箱」「迷惑メール」「隔離（組織の方針）」「添付を止めて受信箱か迷惑メール」のどれかで、**送り返さない**。
- 受け付けた後に DSN を作るのは、配送の不能（宛先のアカウントが受け付けの後に消えた、転送の先が恒久のエラーを返した）だけにする。DSN は、MAIL FROM が空でなく、SPF か DKIM で MAIL FROM のドメインが確かめられたときだけ送る。確かめられなければ記録だけ残す（後方散乱の抑え）。
- 配送の鍵は `(spool_id, recipient)`。`mailstore` は同じ鍵の 2 回目の配送を何もせずに成功とする。SQS の読み直しで重複しない。
- 送り手の再送（250 が送り手に届かず、送り手が同じメッセージを送り直す）は、受け手ごとに（`Message-ID`、本文のハッシュ）の組を 24 時間覚え、同じなら 2 通目を配送しない（RFC 5321 の 6.1 節の重複の問題への対処）。`Message-ID` がないメッセージには当てない。

### グレーリスト

- 使わない。代わりに、上の表の 3 の「評判の分からない IP の急な量」だけを 421 で絞る。正規の事業者の新しい IP は、少ない量から増やす（ウォームアップ）ので、急な量の上限に当たりにくい。
- 本家のグレーリストの使い方は、公式の資料で確かめられなかった（**未検証**）。

### 他の案を選ばなかった理由

- **2（すべてを SMTP の中で）**：分類器・URL・添付の検査の遅れと障害が、そのまま受信の遅れと停止になる。5xx は送り手に知らせられる利点があるが、確信の高いものは 1 で拒める。
- **3（すべてを受け付け、迷惑メールに DSN）**：後方散乱を作る。捨てる形は、誤判定の正規のメールを利用者が取り戻せない。
- **b（グレーリスト）**：NFR-001 を満たせない。最近の迷惑メールの送り手の多くは再試行するので、効きも限られると見込む（**未検証**）。

> 2026-10-10 の注記：上の表の 11 行には例外がある。受け手の組織が方針の組 `quarantine_on_reject` を選んでいるときは、`p=reject` の失敗でも SMTP の時点で拒まず、受け付けて隔離する（[ADR-0015](0015-dmarc-policy-and-organizational-domain.md)、[sender-authentication.md](../architecture/sender-authentication.md) の DT-AUTH-001 の 8 行、[inbound-smtp.md](../architecture/inbound-smtp.md) の 8.4 節）。

## Consequences

- 良くなること：
  - 受信の速さと可用性が、選別の部品の障害から切り離される。
  - 誤判定のメールを、利用者が迷惑メールの箱から取り戻せる。
  - 後方散乱を作らない。
  - 250 の意味（耐久の置き場所に確定した）が、試験で確かめられる形になる。
- 引き受けるコスト：
  - 受け付けた迷惑メールの保存と選別の費用を持つ（SMTP の時点の拒否で減らす）。
  - 送り手は、迷惑メールの箱に入ったことを知らない。
  - S3 の PUT と SQS の送信の遅れが、DATA の終わりの応答に足される（NFR-003 の p99 2 秒の中に収める）。

## Confirmation

- 障害の注入：S3 と SQS の失敗・遅れを注入し、確定していないメッセージに 250 が返らないことを確かめる（[quality.md](../quality.md) の 2.2.1 節 F）。
- 性質ベーステスト：任意の配送の依頼の重複・順序の入れ替え・途中の停止で、受け手のメールボックスに各メッセージがちょうど 1 通入る。
- 決定表：上の SMTP の時点の判定の表を `spec.md` に置き、表駆動テストで全行を確かめる。
- 監視：受け付けた後の DSN の数と、その宛先の確かめの結果（確かめられないものに送っていないこと）。
- lint：`inbound-pipeline` で、選別の判定から DSN を作るコードを禁止する。
