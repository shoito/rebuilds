# ADR-0018: 送信の IP を、個人・組織（org-a・org-b）・通知と DSN・転送・疑い・ウォームアップの 6 つのプールに分け、プールごとに SQS の待ち行列と mta-out の台を持つ。選び方は決定表で決める。新しい IP は 14 日の段で上げ、外部の苦情・不達・絞りの関門を満たしたときだけ進める。量は評判の良い送信から回す。IPv6 は宛先の組ごとに温めてから使う

詳細は [outbound-smtp-and-reputation.md](../architecture/outbound-smtp-and-reputation.md) の 5 節。

## Context

- 送信の IP の評判は、相手の事業者が IP と範囲の単位で決める。1 つのアカウントの乗っ取りで共有の IP が掲載されると、全員のメールが届かなくなる（[architecture/README.md](../architecture/README.md) の 6 節のリスク）。
- プールを 6 つに分けると決めた（同 6 節の決定）。分け方の詳しい条件、選び方、ウォームアップの段は決めていない。
- 新しい IP からの急な量は、相手の事業者に絞られ、迷惑メールの箱に入れられる。ウォームアップの段と関門の値は、本家の値ではなく本システムが決める（本家のウォームアップの推奨は公式の資料で確かめられなかった。**未検証**）。
- IPv6 は、相手の事業者が IPv4 より厳しく扱うことがある（**未検証**）。

## Options

1. **6 つのプールと決定表、14 日の段と関門、評判の良い送信を回す**
2. 1 つの共有のプール（アカウントの上限だけで守る）
3. 組織ごとに専用の IP

## Decision

1 を採用する。

- プール：`personal`、`org`（`org-a`・`org-b`）、`system`、`forward`、`suspect`、`warmup`。1 つの IP は 1 つのプールにだけ属し、プールごとに `outbound-<pool>` の SQS と、それを読む `mta-out` の台を持つ。
- 選び方は DT-OUT-001（`system` → 乗っ取りの疑い → 送信の選別の疑い → 転送 → 組織の評判 → 個人）。
- ウォームアップは 500 から 14 日で 5 万。関門は、苦情の率 0.1% 未満、`hard_invalid_recipient` 2% 未満、大手の事業者ごとの絞り 5% 未満、見張りのメールの受信箱。外れたら 2 日とどまり、2 つ以上外れるか掲載されたら 2 段戻す。
- `warmup` に回すのは、評判の良い組織と、作成から 30 日以上の評判の良い個人の送信だけ。
- IPv4 を既定にし、IPv6 は宛先の組ごとに 7 日の記録ができてから使う。
- 逆引きと HELO の名前をプールの IP ごとに揃える。

### 他の案を選ばなかった理由

- **2**：1 つの乗っ取りや迷惑な利用者で、全員の到達が落ちる。通知と DSN まで届かなくなる。
- **3**：S1 の 2,000 組織に IP を配れない。量の少ない組織の IP は評判が育たない。

## Consequences

- 良くなること：
  - 乱れを、プールの単位で隔てられる。本システムの通知の到達を守れる。
  - 新しい IP の評判を、良い送信で作れる。
- 引き受けるコスト：
  - プールごとに IP と台を持ち、量の偏りで空きが出る。
  - ウォームアップの間、新しい IP は使える量が少ない。MVP の前に温める時間が要る。

## Confirmation

- 決定表：DT-OUT-001 を表駆動テストで全行確かめる。
- 性質ベーステスト：PROP-OUT-006（疑いのアカウントは共有のプールから送られない）。
- 本番：プールごとの苦情の率（NFR-012）、ウォームアップの関門の記録、見張りのメールの受信箱の率。
