# ADR-0016: 送信はすべて、From に揃うドメインと送信の基盤のドメインの 2 つで、それぞれ RSA-2048 と Ed25519 で署名する。鍵は KMS で包んで directory に置き、署名は部品のメモリーの中で行う。鍵は半年ごとに作成・公開・有効・退役・失効の段で入れ替え、組織のドメインは CNAME の委任で交換を本システムが持つ

詳細は [sender-authentication.md](../architecture/sender-authentication.md) の 6 節。

## Context

- 本家の送信者への要件は、DKIM の鍵を 1024 ビット以上、2048 ビットを推奨し、大量の送信者に From の揃いを求める（[Email sender guidelines](https://support.google.com/a/answer/81126)、2026-10-10 に確認）。
- 本システムは、個人の `<brand>.<domain>` と、多くの組織のドメインで署名する。組織の DNS を交換のたびに変えさせると、交換が進まない。
- 外部の事業者は、フィードバックループと評判を、DKIM の署名のドメインの単位で扱うことが多い（**未検証**）。組織のドメインだけで署名すると、本システムの送信の基盤の評判を 1 つにまとめられない。
- Ed25519（RFC 8463）は署名が小さく速いが、検証できない受け手がある（**未検証**の割合）。
- 署名は S1 のピークで 150 通/秒の送信に付く。1 通ごとに KMS を呼ぶと、遅れと要求の速さの上限が送信の遅れに足される。
- 送信の再試行は最大 5 日。退役した鍵の署名が、その間に検証される。

## Options

鍵と署名の場所：

1. **鍵を KMS で包んで置き、部品のメモリーで署名する**
2. 1 通ごとに KMS の署名の API を呼ぶ
3. 鍵を平文の秘密の置き場所（Secrets Manager）に置く

組織のドメイン：

- a. **CNAME の委任を推奨し、TXT の手での公開も受ける**
- b. 組織が TXT を自分で置くだけ

## Decision

1 と a を採用する。

- 署名は From に揃うドメイン（個人は `<brand>.<domain>`、組織は委任のある組織のドメイン）と、基盤のドメイン `<brand>mail.<domain>` の 2 つ。それぞれ `rsa-sha256`（2048 ビット）と `ed25519-sha256`。
- `c=relaxed/relaxed`、`l=` と `x=` なし。From・Subject・`List-Unsubscribe-Post` を過剰署名する。署名の後にバイトを変えないため、署名の前に 7 ビットで安全な形に直す。
- 鍵は `dkim-keyring` が作り、KMS の専用の鍵で包んで directory の `dkim_keys` に置く。`outbound-gate` は起動で解いてメモリーに持つ。
- セレクターは `<brand>-<yyyymm>-r`・`-e`。半年ごとに交換し、次の鍵を 14 日前に公開、公開を 48 時間確かめて有効、退役から 7 日で失効（`p=` を空）、失効から 30 日で消す。漏えいの疑いは即時に失効し、待ち行列の中の送信を署名し直す。
- 組織のドメインは、委任の名前（`<brand>-r._domainkey.<orgdomain>` など）を本システムの名前へ CNAME してもらい、中の鍵を本システムが替える。委任も公開もない組織は、基盤の署名だけで送り、管理者に知らせる。

### 他の案を選ばなかった理由

- **2**：送信の遅れと KMS の上限に依る。Ed25519 の扱いを KMS に依らせたくない。
- **3**：鍵の平文が置き場所に残り、読める主体が増える。
- **b**：交換のたびに組織の DNS の変更が要り、交換が止まる。

## Consequences

- 良くなること：
  - From の揃いと、基盤の単位の評判の両方を持てる。
  - 組織の DNS を変えずに鍵を入れ替えられる。
  - Ed25519 を読まない受け手も RSA で検証できる。
- 引き受けるコスト：
  - 1 通に 4 つの署名が付き、ヘッダーが大きくなる（約 2 KiB）。
  - 鍵がプロセスのメモリーにある。プロセスの侵害で鍵が漏れうる（security.md の脅威モデルで扱う）。
  - 委任の CNAME が消えたことを、毎日確かめる運用が要る。

## Confirmation

- 性質ベーステスト：PROP-AUTH-002、PROP-AUTH-004。
- 相互の検証：外部の独立した実装で、4 つの署名を検証する（夜間）。
- 訓練：半年ごとの交換と、即時の失効の訓練（検証の環境）。
- 監視：署名の失敗の数（0）、委任の確かめの失敗、`published` のまま 7 日を過ぎた鍵。
