# ADR-0043: Web はアカウントごとの IndexedDB に箱・スレッド・メッセージの見出しと直近の本文と JMAP の状態の文字列を持ち、最初の表示を手元から出してから差分で追いつく。操作は手元の変更の待ち行列に入れて画面に先に当て、JMAP の差分（集合の足し引き）で送り、サーバーの差分を受けたら未確定の操作を上に当て直す。共有の端末では手元に保存しない設定を出し、サインアウトで消す

詳細は [web-client.md](../architecture/web-client.md) の 4・5 節。

## Context

- NFR-013 は、受信箱の最初の表示 p95 1.5 秒、操作の画面の反映 100ms 以内（楽観の更新）を求める。サーバーの往復（p99 500ms の要求もある）を待つと 100ms を満たせない。
- 同じアカウントを、他の Web のタブ、アプリ、IMAP のアプリが同時に変える（NFR-006）。手元の楽観の状態が、他の変更とぶつかる。
- 楽観の状態とサーバーの状態の食い違いは、利用者には「操作が消えた」「メールが戻ってきた」に見える。
- ブラウザーの保存は、共有の端末で他の人に読まれうる。

## Options

1. **IndexedDB の手元の保存と、JMAP の差分の待ち行列と、載せ直し**
2. 手元に保存せず、毎回サーバーから取り、操作はサーバーの応答を待つ
3. 手元の状態を正にし、サーバーとの衝突を CRDT で合わせる

## Decision

1 を採用する。

- IndexedDB（アカウントごとのデータベース）に、`mailboxes`、各箱の直近 500 件の見出し、直近 14 日・200 MB までの浄化した本文、型ごとの状態の文字列、変更の待ち行列を持つ。添付は保存しない。
- 最初の表示は手元から出し、`*/changes` で追いつく。手元がないときは、1 回の JMAP の要求（`Mailbox/get`、`Email/query`、後ろの参照の `Email/get`）で出す。
- 操作は JMAP の差分（`mailboxIds/<id>`、`keywords/<kw>` の足し引き）か `<Brand>Thread/set` にし、全体の置き換えを使わない。待ち行列の状態は `queued` → `inflight` → `confirmed`・`rejected`・`canceled`。
- サーバーの差分を受けたら、手元をサーバーの値で置き換え、未確定の操作を上に当て直す。
- 「この端末にメールを保存しない」を出し、選んだらメモリーだけで動く。サインアウト・セッションの失効で消す。組織は Web のオフラインを禁止できる。

### 他の案を選ばなかった理由

- **2**：NFR-013 の 100ms と 1.5 秒を満たせない。オフラインで読めない。
- **3**：メールボックスの状態の書き手は `mailstore` だけ（[ADR-0006](0006-sync-protocol-jmap-imap-and-modseq.md)）。ラベルと旗は集合の足し引きで当てれば順序に依らないので、CRDT の仕組みは要らない。

## Consequences

- 良くなること：
  - 操作がすぐ画面に出て、他の端末の変更とも収束する。
  - オフラインでも読み、操作を溜められる。
- 引き受けるコスト：
  - 手元の保存の消し方（サインアウト、失効）と、共有の端末の設定を保守する。
  - 拒否された操作の取り消しを、画面で知らせる必要がある。

## Confirmation

- 性質ベーステスト：PROP-WEB-001（同期の収束の模型に Web の模型を足す）。
- E2E：オフラインの操作と復帰、他の端末の同時の変更。
- 計測：受信箱の最初の表示の段ごとの時間（[web-client.md](../architecture/web-client.md) の 4.2 節）。
