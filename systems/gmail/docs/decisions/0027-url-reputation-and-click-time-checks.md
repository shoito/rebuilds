# ADR-0027: URL は配送の時に取り出して正規化し評判を当てるが、取りに行かない。開くときの確かめは、Web とアプリが正規化した URL の表現のハッシュの先頭 32 ビットで url-check を引き、全体のハッシュを手元で比べる。配った後 72 時間の中に URL が悪いと分かったら、索引からメッセージを探して未読は迷惑メールの箱へ、既読は警告の帯にする。IMAP のクライアントには開くときの確かめがない

詳細は [attachment-and-url-scanning.md](../architecture/attachment-and-url-scanning.md) の 6 節。

## Context

- 本文の URL を書き換えないと決めた（[architecture/README.md](../architecture/README.md) の 1.4 節）。書き換えると DKIM と転送が壊れ、通信の中身への介入が増える（法務の L1）。そのため、URL の書き換えで開くときに確かめる形は使えない。
- フィッシングの URL は、配送の時には悪いと知られていないことが多い。配った後、数時間で報告と外部の情報が集まる。
- 配送の時に本システムが URL へ取りに行くと、受け取りの合図を送り手に渡し、購読の確認や配信停止のような動作を起こしうる。
- 開くときに URL をサーバーへ送ると、利用者がどのリンクを開いたかをサーバーが知る。これは通信の内容に近い情報で、残したくない（[ADR-0008](0008-spam-pipeline-boundary-and-secrecy.md)）。
- IMAP のクライアントのリンクの処理は、本システムが持たない。

## Options

1. **配送の時の評判、開くときのハッシュの先頭の照会（Web・アプリ）、配った後の手当て**
2. 開くときに URL の全体をサーバーに送って確かめる
3. 開くときの確かめをしない（配送の時の判定だけ）
4. 配送の時に URL へ取りに行って解析する

## Decision

1 を採用する。

- 取り出し：`text/plain` の URL、HTML の `href`・`src`・`action`・`meta refresh`・`base`・CSS の `url()`、本文の画像の QR コード（2 MiB、5 枚）。1 通 500 まで。表示の文字と宛先の食い違い、混ざった文字体系の IDN、`javascript:`・`data:` を印にする。
- 正規化：スキームとホストの小文字、IDNA、数の IP の正規の形、既定のポートの除去、パスの畳み、`%` の符号化の 1 回の解きと付け直し、フラグメントの除去。照会の表現はホストの後ろの 5 つまでとパスの前の 6 つまでの組み合わせ。
- 配送の時：ドメインとハッシュの評判、確かなフィッシングの一覧。取りに行かない。短縮の URL は展開しない。
- 開くとき：Web とアプリは悪い一覧の先頭 32 ビットの集合を 30 分ごとに差分で取り、手元で当たった表現の先頭だけを `url-check` に送り、返った全体のハッシュを手元で比べる。一致したら警告の画面。`url-check` は要求をアカウントに結び付けて残さない。
- 配った後：72 時間、`url_hash`・`url_domain` → `(account_id, message_id)` の索引を持つ。URL が悪い一覧に載ったら、未読で受信箱のものは迷惑メールの箱へ（`post_delivery_phish`）、他は警告の帯。`mailstore` の普通の変更として同期に乗せる。10 万通を超える手当ては運用の確かめを待つ。
- IMAP のクライアントには開くときの確かめがないことを、設定の画面で示す。

### 他の案を選ばなかった理由

- **2**：サーバーが利用者の開いたリンクを知る。
- **3**：配った後に分かったフィッシングから守れない。NFR-008 のフィッシングの捕捉を、配送の時の判定だけで満たすのは難しい。
- **4**：受け取りの合図を送り手に渡し、相手のサイトの動作を起こしうる。攻撃者に本システムの egress を見せる。

## Consequences

- 良くなること：
  - URL を書き換えずに、開くときにも守れる。
  - サーバーは利用者の開いたリンクを知らない。
  - 配った後に分かったフィッシングを、IMAP の利用者にも箱の移動で届ける。
- 引き受けるコスト：
  - Web とアプリに先頭の集合を配り、手元で比べる処理を持つ。
  - IMAP で読む利用者は、開くときの確かめを受けない。
  - 72 時間の URL の索引を持つ。

## Confirmation

- 性質ベーステスト：PROP-SCAN-004（正規化）、PROP-SCAN-005（`url-check` に届く値）。
- 結合：配った後の手当てが、JMAP と IMAP の両方の同期で見えること。
- 監視：`url-check` の p99、手当ての数、誤登録の戻しの数。
