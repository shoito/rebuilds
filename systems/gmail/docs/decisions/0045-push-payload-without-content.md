# ADR-0045: APNs・FCM に送るプッシュの中身は、端末の登録の ID、端末の中のアカウントの番号、`modseq`、新しいメッセージの数、スレッドの HMAC の鍵だけにし、差出人・件名・本文・アドレスを入れない。iOS は Notification Service Extension、Android はアプリの受け手が JMAP で見出しを取り、端末の中で通知を作る。中身を入れる形は、法務の L3・L5 の後に足せる枠だけを持つ

詳細は [mobile-and-push.md](../architecture/mobile-and-push.md) の 6 節。

## Context

- [ADR-0006](0006-sync-protocol-jmap-imap-and-modseq.md) は、モバイルに「状態が変わった」だけを送り、中身を入れるかは法務の L3 の後に決めるとした。
- APNs・FCM は国外の事業者である。差出人・件名を送ると、外国にある第三者への提供（法務の L3）とデータの所在（法務の L5）の問いになる（**法務の確認待ち**）。
- 一方、利用者は通知で差出人と件名を見たい。中身のない通知だけでは使いにくい。
- 両方の OS に、通知を表示の前に端末の中で変える・作る仕組みがある（iOS の Notification Service Extension、Android のデータのメッセージ）。仕組みの細部と時間の上限は、公式の文書で着手の前に確かめる（**未検証**）。

## Options

1. **中身を入れず、端末が JMAP で見出しを取って通知を作る**
2. 差出人と件名を通知に入れる
3. 端末の公開鍵で暗号化した中身を入れる
4. 中身のない決まった文だけを出す

## Decision

1 を採用する。3 は枠だけを持ち、法務の L3・L5 の結論で足せるようにする。

- 送る値：`d`（端末の登録の ID）、`a`（端末の中のアカウントの番号）、`m`（`modseq`）、`n`（新しいメッセージの数）、`thread-id`・まとめの鍵（スレッドの ID のアカウントごとの HMAC の先頭 8 文字）、決まった文の鍵。
- iOS は `mutable-content` の通知、Android は優先度の高いデータのメッセージ。端末が取れなかったら決まった文（「新しいメールがあります」）を出す。
- 送るかの判定（受信箱、ミュート、通知の設定、静かな時間、自分の送信でない）を `push-notifier` で行う。2 秒まとめ、1 分 30 通を超えたら絞る。
- Web Push も同じ規則にする。

### 他の案を選ばなかった理由

- **2**：法務の L3・L5 の結論の前に、国外の事業者へ中身を渡す。
- **3**：成り立つが、鍵の管理と端末の入れ替えの設計が要り、L3 の結論（暗号化しても提供に当たるか）にも依る。枠だけを先に持つ。
- **4**：通知で差出人と件名が見えず、使いにくい。

## Consequences

- 良くなること：
  - 国外の事業者に中身もアドレスも渡さずに、差出人と件名の通知を出せる。
  - 法務の結論で、作り直さずに中身を足せる。
- 引き受けるコスト：
  - 通知ごとに端末から JMAP の要求が出る（S1 のピークで、配送の波に合わせた要求の山）。
  - 端末が取れない環境（電波、OS の背景の制限）では、決まった文の通知になる。
