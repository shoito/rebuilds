# ADR-0037: セグメントの形式 v1 は、語の辞書（FST）、128 文書の塊の転置の並びと位置、doc values の列、`doc_no` から `message_id` への表、墓標のビットマップから成り、アカウントの索引の鍵で 1 MiB ごとに暗号化する。CJK の文字の連なりは 2-gram と連なりの最後の 1 文字の 1-gram で索引し、1 文字の検索は前方一致の 2-gram と 1-gram の和で引く。状態のビットマップは Roaring で、要求の `modseq` まで追いついてから答える。1 回の検索は CPU 500ms・読む量 64 MiB の予算で止める

詳細は [search.md](../architecture/search.md) の 4・6・7・8 節。

## Context

- [ADR-0009](0009-search-index-design.md) は、アカウントごとの不変のセグメント、2-gram、doc values、状態のビットマップ、`search-node` の受け持ちを決めた。ファイルの形、1 文字の検索の扱い、検索の予算は決めていない。
- 2-gram だけでは、1 文字の語（`年`、`様`）と、連なりの最後の文字の 1 文字の検索を取りこぼす。[ADR-0009](0009-search-index-design.md) は「1 文字の語には 1-gram も」と書いたが、長い連なりの中の 1 文字の検索は決めていない。
- 取りこぼし 0 を、全走査の参照の実装との一致で確かめる（[quality.md](../quality.md) の 2.2.1 節 I）。
- 波ダッシュのように、文字コードの表で違う文字になるものがある（[ADR-0029](0029-mime-parsing-limits-and-charsets.md)）。

## Options

1 文字の検索：

1. **連なりの最後の 1 文字の 1-gram を足し、1 文字の検索は前方一致の 2-gram と 1-gram の和で引く**
2. すべての文字の 1-gram を入れる
3. 1 文字の検索を全走査にする

形式：

- a. **自前の小さな形式（FST の辞書、塊の並び、列）を形式のバージョンで固定する**
- b. 汎用の検索のライブラリのファイルの形を使う

## Decision

1 と a を採用する。

- 形式 v1：`meta`、`terms.fst`、`postings`（128 文書の塊、飛ばしの表、頻度、位置）、`docvalues`（`received_at`、`size`、`flags`、アドレスの語の集合、`list_id`、`msgid`）、`docmap`、`tombstones`（Roaring）。各ファイルを 1 MiB の塊で AES-256-GCM にし、鍵はテナントの KEK で包む（[ADR-0030](0030-blob-format-v1-and-envelope-keys.md)）。
- 正規化（`analyzer_version = 1`）：NFKC、大文字小文字の畳み込み、波ダッシュとハイフンの類の畳み込み。ひらがなとカタカナは揃えない。
- CJK の連なりは 2-gram と最後の 1 文字の 1-gram。1 文字の検索は「その文字で始まる 2-gram」と 1-gram の和。
- 状態のビットマップは Roaring で、ラベル・旗・`hidden`・`SPAM`・`TRASH` ごと。要求の `modseq` まで 1 秒待ち、超えたら `mailstore` で状態を当てる遅い経路にする。10 分か 1 万の変更ごとにスナップショット。
- 実行は、文書の数の少ない語から交わりを取り、セグメントの日付の範囲で飛ばし、doc values とビットマップで絞り、新しい順に上位を取る。1 回の予算は CPU 500ms・読む量 64 MiB で、超えたら途中の結果に `partial` を付けて返す。1 アカウントの同時の検索は 4。

### 他の案を選ばなかった理由

- **2**：1-gram の並びは最も長く、索引の大きさが増える。1 の方式で取りこぼしなく引ける。
- **3**：1 文字の検索が 10 万通のアカウントで NFR-005 を超える。
- **b**：形式がライブラリのバージョンに縛られ、試験のベクトルで固定できない。暗号化とアカウントの単位の置き場所を後から足すことになる。

## Consequences

- 良くなること：
  - 1 文字を含むどの部分の文字列でも、取りこぼしなく引ける（PROP-SRCH-003）。
  - 形式を試験のベクトルで固定できる。
  - 重い検索が他の検索を巻き込まない。
- 引き受けるコスト：
  - 前方一致の 2-gram の和は、よく使う文字（`の`）で並びが多くなる。予算で止める。
  - 形式の読み書きを自前で保守する。

## Confirmation

- 性質ベーステスト：PROP-SRCH-001〜003、005。
- 試験のベクトル：セグメントの形式 v1 を固定し、以後のバージョンで読める。
- 負荷：`search-index-poc` と E17 で、10 万通のアカウントの p95 300ms・p99 1 秒、冷えたアカウントの p99 3 秒。
