# Distributions and sketches: Datadog

分布の指標の形を決める。OpenTelemetry の指数のヒストグラムを保存とクエリの形にし、スケールと区間の数の上限、スケールの下げ方、合わせ方、パーセンタイルの求め方と誤差、保存の符号化（`codec_id` 16）、ロールアップでの扱い、StatsD・OTLP（指数・明示の境界・Summary）・本システムの API からの受け方を扱う。

前提となる決定は次のとおり。

- 分布は OpenTelemetry の指数のヒストグラム（底 2、最大 512 の区間、既定のスケール 5、相対誤差およそ 1.1%）。DDSketch は使わない（[architecture/README.md](README.md) の 1.4 節と 6 節の決定）
- ロールアップは生の点から決まる値だけ（[ADR-0004](../decisions/0004-tsdb-storage-engine.md)）
- パーセンタイルの相対誤差 1.1% 以内（スケール 5 を保てる範囲）（NFR-010）
- 型の固定と累積の直し（[ADR-0016](../decisions/0016-metric-types-and-cumulative-conversion.md)）、ブロックの形式と `codec_id` の範囲（[ADR-0021](../decisions/0021-block-format-v1.md)）、空間の分位はヒストグラムを合わせてから（[ADR-0024](../decisions/0024-query-ir-default-semantics.md)）

この文書で決めたことは次の ADR にある。

| ADR | 決定 |
| --- | --- |
| [0028](../decisions/0028-exponential-histogram-storage-and-percentiles.md) | 保存のスケールは 5 を上限にし（上のスケールは 5 に下げる）、正と負の区間はそれぞれ 512 まで（超えればスケールを下げる）。合わせは小さいほうのスケールに下げてから区間ごとに足す。パーセンタイルは近い順位の区間を選び、区間の両端の幾何平均を値にし、最小・最大で挟む。相対誤差の上限は `2^(2^(−scale−1)) − 1`（スケール 5 で 1.089%）で、使ったスケールと上限を応答に入れる。保存は `codec_id` 16（汎用の圧縮を使わない可変長の整数の列） |
| [0029](../decisions/0029-distribution-ingest-conversions.md) | StatsD の `d`・`h`・`ms` はエージェントが 10 秒の窓でスケール 5 のヒストグラムにする（標本の率は重みで、区間ごとに丸める）。OTLP の明示の境界のヒストグラムは、区間ごとの代表の値（両端の幾何平均、端の区間は最小・最大）の区間へ移して指数のヒストグラムにし、精度の印を付ける。OTLP の Summary は分位ごとの gauge と、個数・合計の count にする。本システムの API は値の列（1 点 1,000 個まで）か指数のヒストグラムを受ける |

## 1. 範囲

- 扱う：
  - 指数のヒストグラムの定義、スケール、区間の数、ゼロの区間
  - 合わせ、スケールの下げ方、パーセンタイルの求め方と誤差の上限
  - 保存の符号化（`codec_id` 16）、ロールアップ
  - 取り込みでの変換（StatsD、OTLP の 3 つの形、本システムの API）
  - 応答の精度の印
- 扱わない：
  - 空間の集計・時間の集計の順序（[metrics-query-engine.md](metrics-query-engine.md)）
  - 分布の課金の数え方（usage-and-billing.md）
  - トレースの所要時間の分布（RED メトリクス）の作り方（traces-and-sampling.md）。そこで作る分布もこの形を使う

## 4. 指数のヒストグラム（ADR-0028）

### 4.1 本システムの値

| 項目 | 値 |
| --- | --- |
| 保存のスケールの上限 | 5（底 `2^(1/32)` ≈ 1.0219） |
| 区間の数の上限 | 正・負それぞれ 512（番号の幅 `max − min + 1`） |
| ゼロの区間 | `zero_threshold` は既定 0。OTLP の値があれば持つ |
| 番号 | 符号つき 32 ビット |
| 正確に持つ値 | 個数（u64）、合計（f64）、最小、最大（f64） |

- SDK の既定（160 区間、スケール 20）より区間の数を多く、スケールを低くしたのは、保存の量と誤差の釣り合い（スケール 5 で 1.1%）のため。スケール 5 は 1 区間あたり 1 オクターブの 1/32。

### 4.2 番号の求め方

- 正の値 `v` の番号は `i = ceil(log2(v) × 2^scale) − 1`。浮動小数点の `log2` の丸めで境界（`base` のちょうどの累乗）がずれるので、求めた `i` の区間の両端と `v` を比べ直し、外れていれば 1 つずらす。
- 境界の値（`base^i` のちょうど）を含む試験のベクトルを持つ（DT-HIST-001）。
- 負の値は絶対値で番号を求め、負の区間に入れる。

### 4.3 スケールとその範囲

| スケール | 底 | 誤差の上限 `√base − 1` | 512 区間で持てる最大と最小の比 |
| --- | --- | --- | --- |
| 5 | 1.02190 | 1.089% | 2^16（約 6.5 万） |
| 4 | 1.04427 | 2.190% | 2^32 |
| 3 | 1.09051 | 4.427% | 2^64 |
| 2 | 1.18921 | 9.051% | 2^128 |

- 例：所要時間 1ms〜60 秒（6 万倍）は、スケール 5 で 509 区間に収まる。1µs〜100 秒（1 億倍）はスケール 5 では 852 区間で収まらず、スケール 4（427 区間）に下がる。

### 4.4 スケールの下げ方

- スケール `s` の番号 `i` は、スケール `s − d` で `i >> d`（算術の右のシフト、つまり床の割り算）。正確で、何度に分けて下げても同じ結果になる。
- 区間の幅（正・負それぞれ）が 512 を超えたら、収まるまでスケールを 1 ずつ下げる。

## 5. 合わせとパーセンタイル（ADR-0028）

### 5.1 合わせ

1. 目標のスケール = 2 つのスケールの小さいほう。
2. 両方を目標のスケールに下げる（4.4 節）。
3. 正・負それぞれ、合わせた番号の幅が 512 を超えるなら、さらに下げる。
4. 区間ごとに個数を足す。`zero_count` を足す。`zero_threshold` は大きいほうにし、上の端がそれ以下の区間をゼロの区間へ移す。
5. 個数・合計を足し、最小・最大を比べる。

- 最後のスケールは「入力のスケールの最小」と「合わせた全体の幅が収まる最大のスケール」の小さいほうで決まり、合わせる順序に依らない（シフトは合成できる）。区間の個数・個数・最小・最大は順序に依らない。合計は浮動小数点の足し算なので、正規の順序（系列の鍵、時刻の順）で足す。

### 5.2 パーセンタイル

- `q`（0〜1）の分位は、近い順位 `r = max(1, ceil(q × N))`（`N` は個数）の値の見積もり。
- 区間を値の順（負の区間を絶対値の大きい順、ゼロの区間、正の区間を小さい順）にたどり、個数を足して `r` に届いた区間を選ぶ。
- 値：正の区間 `i` は `2^((i + 0.5) × 2^(−scale))`（両端の幾何平均）、負の区間はその符号を変えたもの、ゼロの区間は 0。最後に `[最小, 最大]` で挟む（`q = 0` は最小、`q = 1` は最大になる）。
- **誤差の上限**：本当の値 `v` と見積もり `e` は同じ区間 `(lb, ub]` にあり、`e = √(lb × ub)`。`|e − v| ÷ v ≤ √base − 1 = 2^(2^(−scale−1)) − 1`。スケール 5 で 1.089%、NFR-010 の 1.1% の中。
- 応答の `meta` に、使ったスケール、誤差の上限、精度の印（9 節）を入れる。

### 5.3 例

ホスト A のスケール 5 のヒストグラムに 12.3、15、18、22、30（ms）、ホスト B のスケール 4 のヒストグラムに 45、60、100、250、1000（ms）がある。`p90:latency{*}` と `p50` を求める。

| 値 | スケール 5 の番号 | スケール 4 の番号 | 見積もり（スケール 4） | 相対誤差 |
| --- | --- | --- | --- | --- |
| 12.3 | 115 | 57 | 12.073 | 1.84% |
| 15 | 125 | 62 | 14.993 | 0.04% |
| 18 | 133 | 66 | 17.830 | 0.94% |
| 22 | 142 | 71 | 22.143 | 0.65% |
| 30 | 157 | 78 | 29.987 | 0.04% |
| 45 | — | 87 | 44.285 | 1.59% |
| 60 | — | 94 | 59.973 | 0.04% |
| 100 | — | 106 | 100.863 | 0.86% |
| 250 | — | 127 | 250.514 | 0.21% |
| 1000 | — | 159 | 1002.058 | 0.21% |

1. 目標のスケールは 4。A の番号を 1 つ右にシフトする（115 → 57、125 → 62、…）。
2. 合わせた番号の幅は 57〜159 の 103 で、512 の中。
3. `N = 10`。p90 は `r = 9`。9 番目の区間は 127 → 250.514。本当の値 250 との差は 0.21%。
4. p50 は `r = 5` → 区間 78 → 29.987（本当の値 30、0.04%）。
5. 応答はスケール 4、誤差の上限 2.19% を示す。スケール 5 のまま合わせられれば上限は 1.09% だが、B が 4 で来たので 4 になる。

- 例のように、送り手のスケールが 5 より低いと、上限は 1.1% を超える。NFR-010 の 1.1% は「スケール 5 を保てる値の範囲の中」の約束で、低いスケールで来たデータは応答で示す。

## 6. 取り込みでの変換（ADR-0029）

### 6.1 StatsD（エージェントの中）

- `d`・`h`・`ms` の値を、10 秒の窓（[intake-and-agent.md](intake-and-agent.md) の 4.3 節）ごとにスケール 5 のヒストグラムに足す。
- 標本の率 `ρ` の値の重みは `1 ÷ ρ`。区間ごとに重みを浮動小数点で足し、窓の終わりに四捨五入して整数の個数にする。個数は丸めた区間の個数の和、合計は `Σ v ÷ ρ`、最小・最大は見た値から。丸めで 0 になった区間は捨てる。
- 例：`ρ = 0.1` で 100ms が 3 回届くと、区間の重みは 30、個数 30、合計 3,000ms。

### 6.2 OTLP の指数のヒストグラム

- スケールが 5 より上なら 5 に下げる（4.4 節）。5 以下ならそのまま。区間の幅が 512 を超えれば下げる。
- `min`・`max` がなければ、端の区間の端から見積もり、`min_max_estimated` の印を付ける。
- `zero_threshold` はそのまま持つ。

### 6.3 累積の指数のヒストグラム

- [ADR-0016](../decisions/0016-metric-types-and-cumulative-conversion.md) のとおり、ブロックを作るときとヘッドを読むときに、時刻の順の前の点との差を求める。
- 前の点と今の点を小さいほうのスケールに下げ、区間ごとに引く。どれかの区間・ゼロの区間・個数が負になれば戻りとみなし、今の点をそのまま差にする（[metrics-model-and-cardinality.md](metrics-model-and-cardinality.md) の 6 節の決定表）。
- 最小・最大は累積の点からは差を求められない。差の点の最小・最大は、累積の点の値を使い、`min_max_estimated` の印を付ける。

### 6.4 OTLP の明示の境界のヒストグラム

- 境界 `b_0 < b_1 < … < b_{n−1}` と個数 `c_0 … c_n`。区間 `(b_{j−1}, b_j]` の個数を、代表の値の指数のヒストグラムの区間へ移す。

| 区間 | 代表の値 |
| --- | --- |
| 両端が正 | `√(b_{j−1} × b_j)`（幾何平均） |
| 0 を含む（`b_{j−1} ≤ 0 < b_j`） | `b_j ÷ 2` |
| 最初（`(−∞, b_0]`） | `min` があれば `min`、なければ `b_0` |
| 最後（`(b_{n−1}, +∞)`） | `max` があれば `max`、なければ `b_{n−1}` |
| 両端が負 | `−√(b_{j−1} × b_j)` |

- 個数・合計・最小・最大はそのまま持つ。
- 誤差は元の区間の幅で決まり、1.1% の約束の外。指標の情報 `metric_metadata.source` に `explicit_buckets` を入れ、点にも印を付ける。応答の `meta` で「明示の境界から変換」と示す。
- 例：境界 `[0, 5, 10, 25, 50, 75, 100, 250, 500, 1000]`（ms）で、`(50, 75]` の個数 12 は、代表の値 `√3750 = 61.24` の区間（スケール 5 で番号 189）に 12 として入る。p 値がこの区間に落ちれば 61.24 付近を返し、本当の値は 50〜75 のどこか。

### 6.5 OTLP の Summary

- 分位ごとの値は gauge `<名前>.quantile`（タグ `quantile:0.99` など）、個数は count `<名前>.count`、合計は count `<名前>.sum`（累積なら差に直す）にする。分布の型は作らない。
- 分位の gauge は合わせられない。空間の集計（`avg by {service}`）は分位の平均になり、正しい分位ではない。画面と文書でそう示す。

### 6.6 本システムの API

- 分布の点は、値の列（1 点 1,000 個まで）か、指数のヒストグラム（OTLP と同じ欄）で受ける。値の列はゲートウェイがスケール 5 のヒストグラムにする。
- 1 つの系列で同じ時刻の分布の点は後勝ち（合わせない）。

## 7. 保存の形（`codec_id` 16）

チャンク（最大 120 点）の頭は浮動小数点のチャンクと同じ（点の数、`codec_id`、長さ）。時刻は `codec_id` 1 の時刻の符号化を使う。点ごとの本体：

```
flags: u8          // has_negative, has_zero_threshold, min_max_estimated, lossy_source
scale: i8
count: varint, sum: f64, min: f64, max: f64
zero_count: varint, [zero_threshold: f64]
positive: offset zigzag-varint, len varint, counts varint x len
[negative: same]
```

- 汎用の圧縮（zstd など）を中に使わない。符号化が `codec_id` の仕様だけで決まり、ライブラリのバージョンで出力のバイトが変わらないようにするため（2 つの写しのバイトの一致。[ADR-0004](../decisions/0004-tsdb-storage-engine.md)）。
- 大きさの目安：所要時間の分布で、空でない区間 60・幅 100 の点は約 150 バイト。10 秒ごとの点で、1 系列 1 時間に約 54 KB。`tsdb-codec-poc` で区間の個数の差分の符号化と比べる。

## 8. ロールアップとクエリ

- 1 分・1 時間のロールアップは、区間の中の生の点のヒストグラムを、時刻の順に合わせたもの（5.1 節）。個数・合計・最小・最大も同じ順で。
- 合わせで区間の幅が 512 を超えるとスケールが下がる。1 時間のロールアップは値の幅が広がりやすいので、スケール 4 以下になりうる。応答の `meta` に、区間ごとの最も低いスケールと誤差の上限を返す。
- `avg`・`sum`・`count`・`min`・`max` は、ヒストグラムの外の正確な値から求める（[metrics-query-engine.md](metrics-query-engine.md) の 4.3 節）。
- 空間の分位は、グループの全系列の区間のヒストグラムを合わせてから求める（[ADR-0024](../decisions/0024-query-ir-default-semantics.md)）。

## 9. 失敗と上限

| 対象・事象 | 値・扱い |
| --- | --- |
| 区間の数 | 正・負それぞれ 512。超えればスケールを下げる |
| スケール | 保存の上限 5、下限 −10（それより下が要る値の幅は拒む：`invalid_histogram`） |
| 番号が 32 ビットを超える | 拒む（`invalid_histogram`）。標準のとおり |
| 個数と区間の個数の和が合わない（OTLP） | 区間の和を個数にし、`<brand>.otlp.histogram_count_mismatch` に数える |
| 値の列の数 | 1 点 1,000 個まで。超えれば点を拒む |
| 精度の印 | `scale_reduced`（5 より下）、`explicit_buckets`、`min_max_estimated` |

## 11. テスト

決定表：

- **DT-HIST-001（番号）**：`base` のちょうどの累乗、その前後の 1 ULP、非正規化数、最大の有限の値、負の値、0、`zero_threshold` の境界。
- **DT-HIST-002（変換）**：6.4 節の区間の種類ごと、`min`・`max` の有無。6.5 節の Summary。6.1 節の標本の率と丸め。

性質ベーステスト：

- **PROP-HIST-001（合わせの結合と可換）**：任意のヒストグラムの集まりを、任意の順序・任意の分け方で合わせて、スケール・区間の個数・個数・最小・最大が同じ。合計は相対 1e-12 の中（quality.md の 2.2.1 節 B）。
- **PROP-HIST-002（誤差の上限）**：任意の値の列（正・負・0、広い幅）で、すべての `q` の見積もりが、正確な近い順位の値に対して `√base − 1`（使ったスケールの）以内。スケール 5 で 1.089% 以内。
- **PROP-HIST-003（スケールの下げの合成）**：`d1` 下げてから `d2` 下げた結果と、`d1 + d2` を一度に下げた結果が同じ。
- **PROP-HIST-004（符号化の可逆と決定性）**：任意のヒストグラムの列で、`codec_id` 16 で符号化して戻すと同じ。同じ入力で同じバイト。
- **PROP-HIST-005（累積の差）**：任意の累積のヒストグラムの列（戻りを含む）で、差の和が最後の累積と一致する（戻りのない区間で）。

試験のベクトル：`codec_id` 16 の固定のチャンク。5.3 節の例。

ファジング：OTLP のヒストグラムの欄（負の幅、巨大な `offset`、個数の不一致）、`codec_id` 16 の復号。
