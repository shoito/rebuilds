# Runbook: デプロイとロールバック

- Owner: Ops
- 対応するアラート: デプロイ中の自動ロールバック、影の比べの失敗（`ops.rollout_paused` の自動の設定）、写しの不一致・ヘッドの要約の食い違いがデプロイの直後に出たとき
- 最終確認日: 2026-10-09

方針は [README.md](README.md) の 3 節、手順の設計は [delivery.md](../architecture/delivery.md) の 4・6 節と [ADR-0065](../decisions/0065-stateful-rollout-with-replica-handoff.md)・[ADR-0066](../decisions/0066-format-versioning-and-compatibility-windows.md) にある。

## 症状

- 自動のロールバックの条件（取り込みの 5xx、202 の p99、取り込みからクエリまでの p99、評価の遅れ、写しのチェックサムの不一致、見張りの照合の不一致）に当たった。
- `rollout-controller` が影の比べの失敗で入れ替えを止めた。
- デプロイの直後に、ブロックの写しの不一致・ヘッドの要約の食い違い・拒んだ点の急な増加が出た。

## 影響

デプロイした部品とセルによる。状態を持つ部品は、入れ替えの間も 2 つの写しを保つ設計なので、止めても利用者の影響は小さい。

## 確認

1. どの部品・どのセル・どの段（検証のセル → 社内の見張りのセル `apne1-c0` → 本番のセル）で起きたか。
2. 管理の面か、データの面（状態なし・状態あり）か、エージェントの配布か、形式の書く側の切り替えか。
3. `rollouts` の行（段、影の比べの結果、状態）と、`svc_formats_readable{format, version}`。

## 対処

### 管理の面・データの面（状態なし）

1. まずフラグで戻す（`release.*` を前の割合に）。
2. 次に 1 つ前のイメージへ戻す。マイグレーションは広げる段だけなので、前のバージョンが今の DB で動く。縮める段の後は前へ戻さない。

### 状態を持つ部品

1. `ops.rollout_paused` を立て、入れ替えを止める（自動で立っていればそのまま）。
2. 影の比べ・要約が違った新しいタスクを止める。古いタスクは残っている（新しいタスクを先に起こす形なので）。
3. 既に入れ替え終えた写しは、同じ手順（予備に古いイメージを先に起こし、追いつき、影の比べの後に止める）で戻す。組の写し A と B を同時に入れ替えない。
4. 毎時 :08〜:20（書き出しの窓）は、貸し出しの持ち主を止めない。
5. 予備のインスタンスがなければ、戻しも始めない。予備を空けてから進める（`ec2-fleet-capacity.md`、予定）。

### 形式の書く側の切り替え

1. 書く側を前の番号に戻す。読む側は新しい番号を読み続けるので、既に書いた新しい形式のブロック・セグメントも読める（[ADR-0066](../decisions/0066-format-versioning-and-compatibility-windows.md)）。
2. 読む側のコードを戻してはならない。新しい番号を読めないタスクが出ると、そのデータが読めなくなる。
3. インジェスターは、1 つの組の 2 つの写しを同じ時間の区切りから戻す。

### エージェントの配布

1. 段階の配布（社内 → 1% → 10% → 50% → 100%）を止め、前のバージョンを配布の目録の最新に戻す。
2. 利用者が自分で入れた分は戻せない。ゲートウェイが受けられることを確かめる（6 か月前までのバージョンを受ける）。

## エスカレーション

- 写しの不一致・要約の食い違い・見張りの照合の不一致が戻しの後も続く：[incident-response.md](incident-response.md) の場面 2、Dev のテックリード。
- 戻せない（縮める段の後のマイグレーション、新しい形式しか読めない状態）：テックリードと前へ直す修正（ホットフィックス）を決める。

## 事後

- 原因を `changes/` の新しい `intent.md` として起票する。
- 影の比べで見つからなかった誤りなら、比べの系列の数と要約の範囲を見直す（[delivery.md](../architecture/delivery.md) の 11 節）。
- この手順で足りなかったことを、ここに反映する。
