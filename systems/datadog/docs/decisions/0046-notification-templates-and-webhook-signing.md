# ADR-0046: 本文の雛形はロジックのない自前の雛形の言語で、遷移の写しの値だけから描き、チャネルごとに逃がす。既定ではログの抜粋・スパンの中身を入れない（L2 の後に決める）。Webhook は `<Brand>-Signature` に時刻と HMAC-SHA256 を入れる。外への接続では、私的なアドレス・メタデータのアドレスを拒み、リダイレクトを追わない

## Context

- 利用者は通知の本文に、モニターの名前、グループのタグ、値、状態ごとの文、宛先を書きたい。本家は二重の波括弧の変数と状態の節（`{{#is_alert}}`）を持つ（[Notifications](https://docs.datadoghq.com/monitors/notify/)、2026-10-09 に確認）。
- 雛形が任意のコード（ループ、関数、外の呼び出し）を持つと、描く時間と結果が読めず、再送で本文が変わり、雛形からデータを引き出す経路になる。
- 本文は外の宛先（国外のチャット・オンコールのサービスを含む）に出る。ログの抜粋を入れるかは法務の判断が要る（**法務の確認待ち：L2**）。
- Webhook の受け手は、送り手が本システムであることと、本文が変えられていないことを確かめたい。ヘッダーの名前に本家の名前を使わない（[リポジトリ共通の ADR-0006](../../../../docs/decisions/0006-brand-neutral-identifiers.md)）。
- 利用者が書く Webhook の URL は、SSRF の入口になる（内部のアドレス、メタデータのアドレス）。

## Options

雛形：

1. **ロジックのない自前の雛形の言語（変数、状態の節、タグの一致の節、宛先）**
2. 汎用の雛形のエンジン（Handlebars など）をそのまま
3. 雛形を持たず、決まった本文だけ

署名：

- a. **`t=<時刻>,v1=<HMAC-SHA256(秘密, t.本文)>`**
- b. 本文だけの HMAC
- c. 相互 TLS

## Decision

1 と a を採用する。詳細は [notifications-and-integrations.md](../architecture/notifications-and-integrations.md) の 6〜8 節。

- 雛形：`{{変数}}`、状態の節（`is_alert` など）、否定の節、`is_match`、宛先（`@email:`・`@chat:`・`@webhook:`・`@oncall:`・`@team:`）。逃がさない出力とループを持たない。未定義の変数は空。
- 描く入力は、モニターのバージョンと通知の依頼の出来事の写しだけ。描くときにクエリを実行しない。値は評価の主体の制限の中。
- チャネルごとに逃がす（HTML、mrkdwn、JSON）。雛形 8 KiB、描いた後 32 KiB、件名 200 文字。
- 既定でログの抜粋・スパンの中身を入れない。組織の設定 `notification_data_level`（`minimal`・`samples`）を用意し、`samples` は L2 の後まで `release.notification-samples` の裏に置く。
- 署名：`<Brand>-Signature: t=<UNIX 秒>,v1=<16 進>`。秘密は 32 バイトの乱数、入れ替えの間 24 時間は `v1` を 2 つ。`<Brand>-Delivery-Id`、`<Brand>-Event-Type`、`<Brand>-Retry-Count` を付ける。
- egress：`notifier` は egress のサブネットの専用の NAT（公開する Elastic IP）から出る（[ADR-0058](0058-untrusted-senders-egress-and-operator-access.md)）。名前を 1 回引いたアドレスに接続し、私的・ループバック・リンクローカル・CGNAT・ULA・本システムの VPC の範囲を拒む。`https` と 443・8443 だけ。リダイレクトを追わない。応答の本文は 4 KiB まで読んで捨てる。

### 他の案を選ばなかった理由

- **2（汎用のエンジン）**：ヘルパーやパーシャルで表現が広く、描く時間と出力の上限を守りにくい。逃がしを外す書き方を持つ。
- **3（決まった本文）**：利用者が対応の手順やリンクを本文に書けない。
- **b（本文だけ）**：同じ本文を後から送り直す攻撃（再送）を受け手が拒めない。
- **c（相互 TLS）**：受け手の多く（チャットの受け口、小さなサーバー）が設定できない。

## Consequences

- 良くなること：
  - 本文が決まり、再送で変わらない。描く時間が雛形の大きさに比例する。
  - 受け手が送り手と改ざんと再送を確かめられる。
  - Webhook を使った内部への到達を防ぐ。
- 引き受けるコスト：
  - 雛形の言語を自前で保守する。本家の雛形をそのまま貼る利用者は、宛先の書き方を直す必要がある。
  - 法務の結論まで、通知の本文で原因の手がかり（ログの行）を見せられない。

## Confirmation

- 試験のベクトル：署名の固定の値。雛形の入力と出力（逃がしを含む）。
- 性質ベーステスト：PROP-NTF-002（描く結果が決まる）、PROP-NTF-003（漏れ 0）。
- SSRF の試験：アドレスの範囲、DNS の付け替え、リダイレクト、IPv6 の表し方の揺れ。
- 外部のペンテストの対象に Webhook の宛先の登録を含める（E13）。
