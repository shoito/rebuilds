# ADR-0016: 型は gauge・count・rate・分布の 4 つで、組織と指標の名前ごとに最初に見た型で固定する（Aurora の `metric_metadata` に「無ければ入れ、あれば読む」）。rate は取り込みで count（値 × 間隔）に直し、表示だけを rate にする。指標の名前は小文字にする。累積の指標は、ブロックを作るときとヘッドを読むときに、時刻の順に並べた点と、前の時間のブロックの末尾の値から差を求める。読む順序に依らない

## Context

[ADR-0004](0004-tsdb-storage-engine.md) は、累積の指標（OTLP の cumulative sum）をインジェスターが前の点との差に直して持つと決め、細部をこの領域に任せた。

- 差を「パーティションで届いた順の前の点」で求めると、読み直しの位置（ヘッドの作り直しは途中のオフセットから始まる）と、遅れて届いた点で、前の点が変わる。2 つの写しのバイトの一致（ADR-0004）と、読み直しで同じ結果（[ADR-0002](0002-intake-log-on-msk.md)）が崩れる。
- 同じ指標の名前に、送り手によって違う型（gauge と count）が来うる。集計の既定は型で決まるので（[ADR-0007](0007-query-language.md)）、型が混ざると値の意味が壊れる。
- 本システムの API の rate（間隔あたりの量）を rate のまま持つと、ロールアップの合計が意味を持たない。
- OpenTelemetry は計器の名前の大文字小文字を区別しない。
- 本家の型の食い違いの扱いと名前の大文字小文字は、公式の資料で確かめられなかった（**未検証**）。

## Options

累積の直し：

1. **累積のまま持ち、差は時刻の順に並べた点と前の時間のブロックの末尾から、読むたび・書き出しのときに求める**
2. 届いた順に差に直して、差を持つ
3. 累積のまま持ち、差をクエリのエンジンが求める（ロールアップは累積の値）

型の決め方：

- a. **最初に見た型で固定（Aurora に不変の行）**
- b. 最後に見た型にする
- c. 型を系列の鍵に入れる（同じ名前で型ごとに別の系列）

## Decision

1 と a を採用する。詳細は [metrics-model-and-cardinality.md](../architecture/metrics-model-and-cardinality.md) の 4・6 節。

- 型は gauge・count・rate・分布。インジェスターは新しい指標の名前で `metric_metadata` に `INSERT ... ON CONFLICT DO NOTHING` してから読み、勝った型を使う。行の型は不変。違う型の点は拒んで `type_conflict` で数える。Aurora が使えない間の新しい指標は、ヘッドで保留する。
- rate は取り込みで count（値 × 間隔）に直し、`metric_metadata.interval_s` を持つ。表示の既定は `.as_rate()`。
- 指標の名前は小文字にしてから確かめる。
- 累積の点は `(ts, start, v)` のまま持つ。差は、`cumulative_to_delta`（決定表 DT-MET-001）で、時刻の順に並べた点から求める。時間 `H` の最初の点の前の点は、時間 `H − 1` のブロックの末尾の区画から取る。ブロックの書き出し（ロールアップの前）と、ヘッドの読み出しで同じ関数を使う。
- 前の点がないときは、始まりから 5 分以内なら累積の値をそのまま差にし、それ以外は基準の点にする。始まりの時刻が点の時刻と同じなら基準の点にする。

### 他の案を選ばなかった理由

- **2（届いた順に直す）**：読み直しと写しで結果が変わる。ADR-0004 のバイトの一致と照合が成り立たない。
- **3（クエリで求める）**：ロールアップの合計が累積の値の和になり意味を失う。count と同じ集計の道を使えない。
- **b（最後の型）**：型が変わるたびに、過去のブロックとの意味が食い違う。
- **c（型を鍵に）**：同じ名前の系列が型ごとに分かれ、クエリと課金で利用者を驚かせる。

## Consequences

- 良くなること：
  - 差の値が、届く順序・読み直し・写しに依らない。遅れた点も正しく入る。
  - 型が混ざらず、集計の既定が一定になる。
  - rate のロールアップが正確になる。
- 引き受けるコスト：
  - ヘッドの読み出しのたびに差を求める CPU が要る。
  - ブロックに、累積の系列の末尾の区画が要る。前の時間のブロックがないと、その時間の最初の差が出ない。
  - 型を変えたい利用者は、名前を変える必要がある。
  - `CPU.User` と `cpu.user` は同じ指標になる。

## Confirmation

- 表駆動テスト：DT-MET-001（累積の直し）、DT-MET-002（型）。
- 性質ベーステスト：PROP-MET-004（累積の直しが届く順序に依らない）。読み直しの位置を任意にしても、ブロックのバイトが同じ（[quality.md](../quality.md) の 2.2.1 節 B・F）。
- 試験のベクトル：OTLP の cumulative の列（戻り、送り手の再起動、欠け）の固定の入力と期待する差。
