# ADR-0021: ブロックの形式のバージョン 1：頭、記号の辞書、系列の表（系列の鍵の順）、転置の表（Roaring）、生のチャンク、1 分・1 時間のロールアップの列（合計・個数・最小・最大・最後）、累積の末尾、統計、区画の表と区画ごとの xxh3 のチェックサム。分布のチャンクは `codec_id` 16

## Context

[ADR-0004](0004-tsdb-storage-engine.md) は、ブロックの区画（頭、系列の索引と転置の表、生の点のチャンク、ロールアップ、末尾）と区画ごとの xxh3 のチェックサムを決めた。形式の細部は決めていない。

- 2 つの写しがバイトまで同じブロックを作るには、並べ方と直列化がすべて決定的でなければならない。
- クエリは S3 のブロックの必要な部分だけを範囲の GET で読みたい（[metrics-query-engine.md](../architecture/metrics-query-engine.md)）。
- 累積の指標の差は、前の時間のブロックの末尾の値から求める（[ADR-0016](0016-metric-types-and-cumulative-conversion.md)）。
- 合わせの前後の確かめに、系列ごとの統計が要る。
- 分布（指数のヒストグラム）のチャンクを、浮動小数点のチャンクと同じ入れ物に入れる（[distributions-and-sketches.md](../architecture/distributions-and-sketches.md)）。`codec_id` 2 は ALP などのために空けてある。

## Options

1. **区画の表を末尾に置く自前の形式（範囲の GET で末尾 → 必要な区画）**
2. Parquet などの汎用の列指向の形式
3. 系列ごとに 1 つのオブジェクト

## Decision

1 を採用する。区画の一覧は [tsdb-storage-engine.md](../architecture/tsdb-storage-engine.md) の 7 節。

- 区画：頭（64 バイト、魔法の数 `TSB1`、形式のバージョン 1、区分、`tenant_id`、時刻の範囲、`codec_id`、系列と点の数）、記号の辞書（バイトの順、前方の共通の省略）、系列の表（系列の鍵の順）、転置の表（記号 → Roaring、正規の直列化）、生のチャンク、1 分と 1 時間のロールアップの列（時刻、合計、個数、最小、最大、最後）、累積の末尾、統計（系列ごとの点の数、生の値の合計、正規の点の列の xxh3_64）、区画の表（種類、位置、長さ、xxh3_64）、全体の xxh3_128。
- 系列の表に、削除の請求の墓標のための欄を予約する（法務の L5 の結論まで使わない）。
- `codec_id` の範囲：1〜15 を浮動小数点、16〜31 を分布。`codec_id` 16 は指数のヒストグラムのバージョン 1。
- 形式のバージョンを変えるときは新しい番号を足し、古い番号の読み出しを消さない（ADR-0004 の `codec_id` と同じ規則）。

### 他の案を選ばなかった理由

- **2（Parquet など）**：系列ごとのチャンクと時系列の圧縮の効きを活かしにくい。直列化の決定性（同じ入力で同じバイト）をライブラリのバージョンに頼ることになる。
- **3（系列ごと）**：オブジェクトの数が系列の数になり、S3 の要求の費用と最小の課金の大きさで合わない。

## Consequences

- 良くなること：
  - 末尾を読めば必要な区画だけを読める。
  - 写しのバイトの比べと区画ごとの破損の検出ができる。
  - 統計の区画で、合わせの前後を中身を全部比べずに確かめられる。
- 引き受けるコスト：
  - 形式のバージョンの管理と、試験のベクトルの保守が要る。
  - 自前の形式なので、外の道具で読めない（調べるための読み出しの道具を開発リポジトリに持つ）。

## Confirmation

- 試験のベクトル：バージョン 1 の固定のブロックを持ち、以後のバージョンで読めて同じ値になる。
- 性質ベーステスト：PROP-TSDB-003（同じ入力で同じバイト）。
- ファジング：ブロックの復号に壊れた入力を与えても、パニックせず誤りを返す。
