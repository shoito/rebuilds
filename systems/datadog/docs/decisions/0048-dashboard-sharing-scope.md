# ADR-0048: 共有は組織の中のリンクだけにし、見る人の権限（データのアクセスの制限）で描く。リンクの状態（時間の範囲、変数の値）はサーバーに置き、URL に値を入れない。公開（認証なし）の共有と、外部への埋め込みは MVP に入れず、法務の L1・L2・L7・L9 の後に別の ADR で決める

## Context

- intent は、MVP のダッシュボードの共有を「組織の中の共有のリンク」としている（[intent.md](../intent.md)）。
- 本家は、公開（リンクを知っていれば誰でも）、招待、埋め込みの共有を持ち、見る人には作った人の権限でデータを見せる（[Shared Dashboards](https://docs.datadoghq.com/dashboards/sharing/shared_dashboards/)、2026-10-09 に確認）。
- ダッシュボードには、利用者の顧客の個人のデータ（ログの一覧、タグの値）が出うる。認証なしで誰にでも見せることは、委託の範囲（L1）、国外からの閲覧（L2）、利用規約（L7）、画面の寄せ方（L9）に関わる。
- 作った人の権限で描くと、制限の強い人が、制限の弱い人の作ったリンクで制限の外のデータを見られる（[ADR-0003](0003-tenancy-cells-and-isolation.md) のデータのアクセスの制限）。
- 変数の値（タグの値）を URL に入れると、ブラウザーの履歴・プロキシーの記録・チャットの貼り付けに残る。

## Options

1. **組織の中のリンクだけ。見る人の権限で描く。状態はサーバー。公開は MVP の後**
2. 本家に寄せて公開・招待・埋め込みを MVP に入れ、作った人の権限で描く
3. 組織の中のリンクで、作った人の権限で描く

## Decision

1 を採用する。詳細は [dashboards.md](../architecture/dashboards.md) の 8 節。

- 組織の中で `dashboards_read` を持つ人が見られる。データは見る人の役割の制限で描く。
- 共有のリンクは `/s/<短い ID>`（128 ビットの乱数の base62）。状態（時間の範囲、変数の値、選んだウィジェット）は `dashboard_share_links` に置く。開くには組織へのログインが要り、セッションの組織で引く。作成から 1 年で失効（延長できる）。
- 公開（認証なし）・招待（組織の外のアドレス）・埋め込みは MVP に入れない。**法務の確認待ち：L1・L2・L7・L9** の後に別の ADR で決める。そのときの候補は、ダッシュボードに結んだ読み取りのサービスのアカウントの権限、期限の既定 30 日、窓の選び方の制限、ログの一覧のウィジェットを出さないこと。

### 他の案を選ばなかった理由

- **2（本家に寄せる）**：法務の確認の前に、利用者のテレメトリーを組織の外へ出す仕組みを作ることになる。作った人の権限で描くと、制限を回り込む経路になる。
- **3（作った人の権限）**：組織の中でも、制限の強い人が制限の外のデータを見られる。

## Consequences

- 良くなること：
  - データのアクセスの制限を回り込む経路がない。
  - URL に利用者のデータが残らない。
  - 法務の結論のどれにも、後から足す形で対応できる。
- 引き受けるコスト：
  - 組織の外の人（協力会社、経営層の外部の画面）に見せる手段が MVP にない（意図した違い）。
  - 同じリンクでも、見る人の制限で違う内容になる（画面で「あなたの権限で表示しています」と示す）。

## Confirmation

- 漏れの経路：制限の違う 2 人が同じリンクを開き、互いの制限の外のデータが出ない。他の組織のセッションで短い ID を開くと「見つからない」（[quality.md](../quality.md) の 2.2.1 節 G）。
- lint：画面の URL を作るコードで、変数の値をクエリの文字列に入れることを禁止する。
