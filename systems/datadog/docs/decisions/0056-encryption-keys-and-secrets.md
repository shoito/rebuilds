# ADR-0056: 転送中は TLS 1.2 以上（データの面の内部は mTLS）。保存時は、データの種類ごと・リージョンごとのカスタマー管理の KMS の鍵にし、S3 はバケットキー、NVMe はハードウェアの暗号化に任せる。組織ごとの鍵は持たない。アプリの秘密は鍵の ID つきで 2 つを並べて回す

## Context

- データの面の正本は S3（ブロック、セグメント、アーカイブ）で、MSK・インジェスターのメモリー・読み手の NVMe にも利用者のテレメトリーがある（[ADR-0002](0002-intake-log-on-msk.md)、[ADR-0004](0004-tsdb-storage-engine.md)、[ADR-0009](0009-retention-tiers-on-s3.md)）。
- S3 の要求の数は多い（小さなセグメント、範囲の GET）。SSE-KMS の要求ごとの KMS の呼び出しは費用と上限に効く。ADR-0009 はバケットキーを決めた。
- 組織ごとの鍵（BYOK）は MVP の後（ADR-0003、ADR-0009）。
- NVMe のインスタンスストアは、インスタンスのハードウェアの XTS-AES-256 で暗号化され、鍵は止めるか終えると消える。無効にも、自分の鍵にもできない（[Data protection in Amazon EC2](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/data-protection.html)、2026-10-09 に確認）。
- 通知の連携の資格（チャットの Webhook の URL、オンコールの鍵）、Webhook の署名の秘密、PII のマスクの HMAC の鍵（[ADR-0031](0031-pii-scrubbing-before-routing.md)）は、取り出せる形で持つ必要がある。

## Options

1. **データの種類ごと・リージョンごとの鍵。組織ごとの鍵なし。NVMe はハードウェアに任せる**
2. 1 つのリージョンの鍵にすべてを載せる
3. 組織ごとの鍵（S3 の接頭辞・MSK のメッセージごとに鍵を変える）

## Decision

1 を採用する。

- 鍵：`kms-telemetry`（ブロック、セグメント、トレース、評価の記録、ヘッドのチェックポイント）、`kms-archive`（アーカイブ）、`kms-msk`、`kms-aurora`、`kms-audit`（log-archive のアカウント）、`kms-secrets`、`kms-cache`、`kms-selfmon`（自己監視のアカウント）。東京と大阪で別の鍵。大阪の写しは大阪の鍵で暗号化し直す。マルチリージョンの鍵は使わない。
- 鍵の方針で復号を決めたサービスのロールだけに許す。人のロールは break-glass だけ。鍵の削除の予約・無効化は SCP で break-glass に限る。1 年で自動で回す。
- 転送中：送り手 → 取り込みは TLS 1.2 以上（NLB の TLS のリスナーで終端し、ゲートウェイまでは TLS を張り直す）。MSK はクライアントとブローカーの間の TLS とブローカーの間の暗号化。データの面の RPC は mTLS（AWS Private CA、1 日の証明書）。S3 は `aws:SecureTransport` を必須にする。
- アプリの秘密は Aurora に `kms-secrets` での封筒の暗号化で持ち（鍵の ID つき）、Webhook の署名は新旧を 24 時間並べる。取り込みのキー・アプリケーションキー・SCIM のトークンはハッシュだけ（[ADR-0015](0015-key-format-validation-and-revocation.md)）。

### 他の案を選ばなかった理由

- **2（1 つの鍵）**：アーカイブの読み出し（再水和）の権限と、ブロックの読み出しの権限を鍵の方針で分けられない。鍵の問題の影響がすべてに及ぶ。
- **3（組織ごとの鍵）**：組織の数だけ鍵と鍵の方針が要り、バケットキーの効きが組織ごとに分かれて KMS の要求が増える。消去は接頭辞ごと消すことで行えるので、鍵の破棄による消去（crypto-shredding）の利点が MVP では小さい。BYOK を求める組織には MVP の後に足す。

## Consequences

- 良くなること：
  - 鍵の影響の範囲がデータの種類とリージョンで閉じる。
  - バケットキーで KMS の要求を抑えられる。
- 引き受けるコスト：
  - 組織が自分で鍵を消してデータを読めなくする手段がない（BYOK を求める組織に合わない）。
  - 鍵の方針とロールの組み合わせの検査を保守する。

## Confirmation

- Terraform の plan の方針の検査：鍵の方針の復号の主体が決めたロールだけ。人のロールに復号がない。マルチリージョンの鍵がない。
- 結合テスト：`aws:SecureTransport` のない要求を S3 が拒む。mTLS の証明書のないデータの面の RPC を拒む。
- 年 1 回の鍵のレビュー（使っていない鍵、広すぎる方針）。
