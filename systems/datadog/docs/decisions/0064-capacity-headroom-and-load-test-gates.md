# ADR-0064: 部品ごとにピークの使用率の上限を 60% にし、AZ を 1 つ失っても 90% に収める。MSK の書き込みはピークの 2 倍以上にする。急増は割り当てとエージェントの待ち行列で受ける。負荷試験とうるさい隣人の試験を、夜間・段階を上げる前・E13 の 3 つの関門にし、他の組織の SLI が SLO の中であることを合否にする

## Context

- 量は利用者の障害のときに急に増え、監視が最も要るときに本システムが詰まると、利用者は自分の障害に気づけない（[intent.md](../intent.md)）。割り当ての 10 倍を送る組織がいても、他の組織の NFR-002・NFR-003 を満たす（NFR-007、K6）。
- MSK の余裕はピークの 2 倍（[architecture/README.md](../architecture/README.md) の 6 節、[ADR-0002](0002-intake-log-on-msk.md)）。MSK は CPU を 60% 未満に保つことを勧めている（[Best practices for Standard brokers](https://docs.aws.amazon.com/msk/latest/developerguide/bestpractices.html)、2026-10-09 に確認）。
- 状態を持つ部品は 2 つの写し（インジェスター）か、残る 2 AZ で最大負荷をさばく形（読み手、組み立て）である（[infrastructure.md](../architecture/infrastructure.md) の 3.3 節）。
- 全体の同時の急増（クラウドの広い障害で全組織が 3 倍）を、容量だけで受けると、平常の費用が 3 倍になる。エージェントはディスクに 2 GB まで溜めて待てる（[ADR-0010](0010-agent-disk-queue-and-retry.md)）。割り当てを超えている組織から 429 を返す（[ADR-0012](0012-intake-quota-coordination.md)）。
- うるさい隣人の振る舞いは、少数の例示テストでは見つからない。負荷の生成器を E2 で作り、縮めた規模の場面を夜間に流す（[roadmap.md](../roadmap.md)、[quality.md](../quality.md) の 2.2.1 節 E）。

## Options

1. **ピーク 60%・AZ を失って 90% の上限。急増は割り当てと待ち行列で受ける。3 つの関門の負荷試験**
2. 全体の同時の急増（3 倍）を容量で受ける
3. オートスケールに任せ、上限を決めない

## Decision

1 を採用する。

- 使用率の上限（ピーク、全 AZ）：インジェスターのメモリー 60%、状態を持つ部品の CPU 60%（AZ を 1 つ失って 90%）、読み手の NVMe 80%、Fargate のオートスケールの目標 CPU 50%、Aurora の writer 50%（4 週の p95）。MSK の書き込みはピークの 2 倍以上（S1 で 2.7 倍、AZ を失って 1.8 倍）。
- 急増は、割り当て（429）、エージェントのディスクの待ち行列、クエリの受け付け（費用の見積もり、並行の上限、公平なキュー）で受ける。組織の割り当ての合計は、容量の 1.5 倍（売りすぎの比）までにする。
- 関門：
  - 夜間（E2 から、S1 の 1/20、組織 100）
  - 段階を上げる前と大きな構成の変更の前（新しい構成の 1/4）
  - E13（S1 のピークの 2 倍、障害の注入を重ねる）
- 合否：他の組織の SLI（202 の p99、取り込みからクエリまでの p99、クエリの p99、評価の遅れ）が SLO の中、送った数と読める数の差 0、上の使用率の上限の中。

### 他の案を選ばなかった理由

- **2（容量で受ける）**：平常の費用が大きく増える（S1 で月 数十万 USD）。急増の多くは数十分で、待ち行列で受けられる。
- **3（オートスケールに任せる）**：状態を持つ部品（インジェスター、読み手）は、広げるのに MSK からの作り直し・キャッシュの温めの時間がかかり、急増に間に合わない。MSK のブローカーも同じ。

## Consequences

- 良くなること：
  - 全体の急増の間も、割り当ての中の組織の取り込みとクエリが守られる。
  - 構成の変更の前に、うるさい隣人の振る舞いを確かめられる。
- 引き受けるコスト：
  - 平常の使用率が低く（ピークで 60%）、費用が上がる。
  - 全体の急増の間、割り当てを超えている組織のデータは遅れる（失わない）。
  - 実の MSK・S3 を使う試験の費用（E13 の 2 倍の試験で 1 回 約 2 万 USD の見込み）。

## Confirmation

- 夜間の関門の結果を毎朝の CI のダッシュボードで見て、落ちたらその日のデータの面のデプロイを止める。
- E13 の合否基準（[quality.md](../quality.md) の 5 節）に、この ADR の合否を足す。
- 月次のキャパシティのレビューで、使用率の上限と売りすぎの比を見る。
