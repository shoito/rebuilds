# ADR-0033: セグメントの形式 `LSEG` 1 は、8,192 行のページの列、65,536 行の行のブロック、末尾のフッター（列の表、統計、辞書、オフセット）とブルームフィルターの節を持つ。語の分け方 `tokenizer_version` 1 は NFKC と小文字、英数字の語、CJK の 1-gram と 2-gram。3 桁以下の数字だけの語はブルームフィルターに入れず、引く側は絞り込みに使わない

## Context

[ADR-0005](0005-log-storage-columnar-with-bloom.md) は、ログとトレースを列指向のセグメントとブルームフィルターで持つと決めた。形式の細部と語の分け方を決める。

- 形式は利用者のデータの正本で、後から変えるには全セグメントの書き直しが要る。形式はコードのバージョンとして出し、フラグにしない（[AGENTS.md](../../AGENTS.md)）。
- S3 からは範囲の GET で読む。絞り込みの情報（統計、辞書、ブルームフィルター）を、少ない GET で先に読める必要がある。
- ブルームフィルターは偽陰性を許さない。作る側と引く側の語の分け方が 1 文字でもずれると、取りこぼす。
- 日本語は空白で語に分かれない。1 文字の検索（「株」）もある。
- 数字の短い語（`200`、`42`）はどのログにもあり、ブルームフィルターに入れても絞れず、大きさを食う。

## Options

形式：

1. **自前の `LSEG`（ページと行のブロックの 2 段、末尾のフッター、別の節のブルームフィルター）**
2. Apache Parquet をそのまま使い、ブルームフィルターを別のファイルにする
3. 行の向きの形式（JSON の行を zstd で）＋別の索引

語の分け方：

- a. **NFKC と小文字、英数字の語、CJK の 1-gram と 2-gram、短い数字を除く**
- b. 形態素の解析
- c. すべての文字の 3-gram

## Decision

1 と a を採用する。詳細は [log-storage-and-search.md](../architecture/log-storage-and-search.md) の 4 節。

- ページ 8,192 行（圧縮と読み出しの単位）、行のブロック 65,536 行（ブルームフィルターと統計の単位）。行は時刻の順。
- 決まった列と、属性の道と型ごとの列。1 つのセグメントの列は 2,000 まで、超えたら `_rest`。宣言したファセットは必ず独立の列。
- フッターに、列の表、行のブロックごとの統計とオフセット、値の種類が 1,000 以下の列の辞書と値ごとの件数、`tokenizer_version`、各ページの CRC32C。末尾の 64 KiB を先に読む。
- ブルームフィルターは分割ブロックの形（256 ビットのブロック、語あたり 10 ビットを目安）。セグメントと行のブロックの 2 段。合計が圧縮の後のセグメントの 10% を超えるときは行のブロックのものを省く。
- `tokenizer_version` 1：NFKC、単純な畳み込みで小文字、英数字と `_` の連なりを語（64 バイトで切る）、CJK の連なりの 1-gram と 2-gram、ID の属性は `道=値`。3 桁以下の数字だけの語は入れず、引く側はその語を「ある」とみなす。
- 語の分け方を変えるときは `tokenizer_version` を上げ、古いバージョンの関数を残す。引く側はセグメントのバージョンで語を作る。
- トレースのスパンのセグメントも同じ形式を使う（[ADR-0040](0040-trace-storage-and-id-lookup.md)）。

### 他の案を選ばなかった理由

- **2（Parquet）**：列の形は近いが、ページの統計・辞書の件数・ブルームフィルターの置き方を本システムの検索に合わせにくい。属性の道が組織ごとに数千あり、スキーマの扱いが重い。形式の正本を外部の仕様の解釈に任せると、互換の判断が増える。
- **3（行の向き）**：ファセットと集計で、要らない列まで読む。
- **b（形態素）**：辞書の更新で語の分け方が変わり、古いセグメントとずれる（偽陰性）。未知の語を取りこぼす。
- **c（3-gram）**：2 文字の日本語の語（「決済」）を引けない。英語の語では語の数倍の要素になり大きい。

## Consequences

- 良くなること：
  - 1〜2 回の GET で絞り込みの情報がそろう。
  - 日本語の 1 文字・2 文字以上の部分一致を取りこぼさない。
  - 語の分け方のバージョンで、変更しても古いセグメントを正しく引ける。
- 引き受けるコスト：
  - 形式を自前で保守する（試験のベクトル、ファジング）。
  - 短い数字だけの検索（`200`）はブルームフィルターで絞れない（統計と他の条件で絞る）。
  - CJK の 1-gram の分だけブルームフィルターが大きくなる。

## Confirmation

- 性質ベーステスト：PROP-LSTO-001（絞った結果と全走査の一致）。
- 試験のベクトル：`tokenizer_version` 1 の入力と語、`LSEG` 1 の固定のファイル。期待する値の変更は QA の承認。
- ファジング：フッター・ページの復号。
- `log-bloom-poc`：誤検出の率、大きさの比、日本語の効き。
