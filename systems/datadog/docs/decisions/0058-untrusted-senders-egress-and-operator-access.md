# ADR-0058: 取り込みの送り手は信頼せず、取り込みのキーは書き込みだけにして、漏れたときの被害をデータの注入と量の消費に限る。外への送信は egress のサブネットの `notifier` だけから出し、SSRF を拒む。社内の運用者は利用者のテレメトリーを日常の権限で読めず、読むには組織のサポートの許可と JIT と監査を要る

## Context

- 取り込みのキーは、利用者のホスト・コンテナのイメージ・CI の設定に置かれ、漏れやすい（[ADR-0015](0015-key-format-validation-and-revocation.md)）。送り手（エージェント、OTLP の送り手）は、乗っ取られたホストのこともある。
- 外への送信は、利用者が決める宛先（汎用の Webhook）を含む。宛先の名前で内部の網やメタデータのアドレスを狙われうる（SSRF）。
- 運用者が障害の調査で利用者のデータを見たくなる場面はある。一方、利用者のテレメトリーには個人のデータが含まれ、委託の扱い（法務の L1）によっては、アクセスの記録と制限が求められる。
- 本システムのデータの面は、外へ出る必要がない。

## Options

取り込みのキー：

1. **書き込みだけ。読み出しはアプリケーションキーとセッションだけ**
2. 1 本のキーで書き込みと読み出しの両方（スコープで絞る）

運用者のアクセス：

- a. **日常は読めない。読むのは組織のサポートの許可＋JIT＋監査**
- b. Ops の当番は常に読める（監査だけ）

## Decision

1 と a を採用する。

- 取り込みのキーは書き込みだけで、ゲートウェイは読み出しの経路を持たない。キーごとの量・送り元・新しい系列の数の急な変化を組織に知らせる。シークレットスキャンの通報では、取り込みのキーは組織に知らせて 24 時間の後に失効し（組織が「すぐ」「残す」を選べる）、アプリケーションキーはすぐ失効する。
- 送り手の入力は信頼しない：解析器のファジング、流しながらの展開と上限、本文の `tenant_id` と予約の名前空間 `<brand>.*` を拒む、受け付けの窓、系列の上限。画面は利用者の値をテキストとして描き、CSV の式を引用する。
- 外への送信は egress のサブネットの `notifier` だけ。データの面と管理の面の他の部品は、インターネットへの経路を持たない。`notifier` は送信の直前に名前を引き、私的・リンクローカル・メタデータのアドレスへの接続を拒み、リダイレクトを追わない。連携の資格は `notifier` だけが復号できる。
- 運用者：日常の権限はメタデータ（ID、数、状態、SLI）だけ。読み出しは、組織の管理者が付けるサポートの許可（72 時間まで）＋ JIT（4 時間）＋ 組織の監査ログと本システムの監査の両方への記録。break-glass は 2 人の承認と即時の知らせ。人のロールに S3 のテレメトリーの読み出し、テレメトリーとアーカイブの鍵の復号、MSK の読み出しを与えない。

### 他の案を選ばなかった理由

- **2（読み書きのキー）**：エージェントの設定から漏れたキーで、利用者のすべてのテレメトリーが読める。
- **b（常に読める）**：委託の扱い（L1）次第で求められる統制を満たせない。利用者が誰に見られたかを知れない。

## Consequences

- 良くなること：
  - 最も漏れやすい取り込みのキーの被害が小さい。
  - 外への送信の経路が 1 つで、SSRF と宛先の統制を 1 か所で行える。
  - 運用者のアクセスが、組織に見え、記録に残る。
- 引き受けるコスト：
  - 障害の調査で利用者のデータを見るまでに、組織の許可を待つ。調査は、まず ID と数と理由のコードで行う。
  - 取り込みのキーの失効を 24 時間待つ間、注入されうる。

## Confirmation

- 方針の検査（Terraform の plan）：`notifier` の他にインターネットへの経路がない。人のロールにテレメトリーの読み出し・復号がない。
- 結合テスト：取り込みのキーで読み出しの API が 401。SSRF の試験のベクトル（私的のアドレス、DNS の再結合、リダイレクト）をすべて拒む。
- 監査：サポートの許可のない組織のデータへの運用者の読み出しが 0 件であることを、毎週 `operator_access_log` で確かめる。
