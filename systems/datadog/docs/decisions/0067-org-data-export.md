# ADR-0067: 組織のデータの書き出し（設定とテレメトリー）

## Context

- 利用者は、自分の組織の設定（ダッシュボード・モニター・SLO・パイプライン・索引・役割など）とテレメトリー（メトリクス・ログ・トレース）を、本システムの外へ持ち出せる必要がある。解約の前、他の道具への移行、監査、社内の分析のためである。
- 今ある部品はばらばらである。ダッシュボードの定義は公開 API と Terraform のプロバイダーで同じ JSON の形を使う（[dashboards.md](../architecture/dashboards.md) の 4.1 節）。ログの検索は 1 回 10 万行までの非同期のエクスポートを持つ（[log-storage-and-search.md](../architecture/log-storage-and-search.md) の 11 節）。監査ログは書き出せる（[tenancy-and-rbac.md](../architecture/tenancy-and-rbac.md) の 8.2 節）。解約の `suspended` では「書き出しのため」に管理者だけが画面に入れる（[ADR-0057](0057-data-lifecycle-and-deletion-framework.md)）が、何をどう書き出すかは決めていない。
- [intent.md](../intent.md) の Non-goals は「データの書き出しは API で行う」とだけ書く。組織の全部の設定を 1 回で取る手段、15 か月のメトリクスや 1 年のアーカイブを取る手段はない。
- 利用者の S3 のバケットへの書き込みは MVP の後（E18）。
- 書き出しは、データのアクセスの制限・PII のマスク・削除の請求の墓標を回り込む経路になりうる（[ADR-0003](0003-tenancy-cells-and-isolation.md)、[ADR-0031](0031-pii-scrubbing-before-routing.md)、[ADR-0036](0036-personal-data-deletion-tombstones.md)）。
- 解約の後の消去の期限と、書き出しの猶予の約束は法務の確認待ち（L5・L7）。

## Options

1. 公開 API・Terraform・ログのエクスポートだけを用意し、組織の全体の書き出しは利用者が自分で組み立てる
2. **組織の書き出しの作業（非同期）を 1 つ持つ。設定は公開 API と同じ JSON の束で、テレメトリーは信号・期間・条件を選んで開いた形式で書き出す。どちらも同じクエリの経路と制限を通す**
3. 解約のときだけ、運用者が組織のデータの写しを作って渡す

## Decision

2 を採用する。詳細は [security.md](../architecture/security.md) の 5.6 節。

> 2026-10-25 の注記：PM が範囲を決めた。MVP（E13 の `org-data-export`）に、設定の束とテレメトリーの一括の書き出しの両方を入れる。テレメトリーの書き出しの費用は、GA の時点では利用量に数えず、組織の同時 1 本の上限で抑える。

- **設定の束**：ダッシュボード（全バージョンではなく今のバージョン）、モニター、ダウンタイム、SLO、ログのパイプライン・索引・ログから作るメトリクス、テールサンプリングの規則、クエリに残すタグ、チーム・役割・データセット、通知の宛先（秘密は除き、名前だけ）を、公開 API の応答と同じ JSON（同じ Zod のスキーマ）で 1 つの ZIP にする。`manifest.json` に形のバージョンと作った時刻を持つ。公開 API にそのまま戻せる形にし、同じ組織や別の組織への作り直しに使える。キー・Webhook の秘密・SSO の証明書は入れない。
- **テレメトリー**：信号（メトリクス・ログ・スパン）、期間、条件を選ぶ。メトリクスは選んだ解像度（生・1 分・1 時間。保持の層で残っているもの）の点を Parquet（列：時刻、指標、タグの組、合計・個数・最小・最大・最後、分布は指数のヒストグラムの区間）で、ログとスパンは検索の API と同じ属性の形の JSON Lines（gzip）で書く。
- **同じ経路を通す**：テレメトリーは IR にコンパイルし、要求した人の役割のデータのアクセスの制限を AND で足してから読む（[ADR-0007](0007-query-language.md)）。マスクの後の値だけが読める。墓標の行は出ない。新しい読み出しの経路を作らない。
- **作業**：組織の同時 1 本。費用の見積もりで受け付け、評価・ダッシュボードのクエリと別の低い優先度の待ち行列で流す（うるさい隣人を作らない。[ADR-0003](0003-tenancy-cells-and-isolation.md)）。結果は本システムの S3 の書き出しの置き場所（`<cell>/<tenant_id>/exports/`）に置き、7 日の署名付きの URL で渡し、7 日で消す。利用者の S3 への直接の書き込みは E18 で足す。
- **権限と記録**：新しい権限 `org.data_export.write` を足し、管理者の役割にだけ入れる（[ADR-0051](0051-roles-permissions-and-data-access-restrictions.md)）。要求・完成・ダウンロードを組織の監査ログに書く（[ADR-0052](0052-identity-sso-scim-keys-and-audit-trail.md)）。
- **解約との関係**：`suspended` の猶予の間も、管理者は書き出しを作れる（取り込みは止まっている）。`purging` に入ると作れず、作りかけは取り消す。法的な保全の間も書き出しはできる。
- 1 を採らない理由：組織の設定は 20 種類を超え、利用者が API を順に呼んで集めると、抜けと不整合（途中で変わった設定）が出る。15 か月のメトリクスを API で取ると、クエリの上限に当たる。
- 3 を採らない理由：運用者が利用者のデータに触れる経路を増やす（[ADR-0058](0058-untrusted-senders-egress-and-operator-access.md) の運用者のアクセスの方針に反する）。解約の時にしか使えない。

## Consequences

- 設定の束が公開 API と同じ形なので、形の変更は公開 API の互換の規則に従う。束の形だけの互換の約束は持たない。
- テレメトリーの書き出しは S3 の読み出しと egress の費用がかかる。アーカイブ（Glacier Instant Retrieval）の取り出しの費用も要る。GA の時点では利用量に数えない（2026-10-25 の PM の判断）。数えるかは、GA の後の実績で見直す。
- 書き出したファイルは、本システムの外では、データのアクセスの制限・削除の請求が効かない。画面で示す。
- 解約の猶予の値（L5・L7）が決まると、書き出しに使える期間が決まる。

## Confirmation

- 性質ベーステスト（PROP-SEC-003）：任意の組織・役割の制限・削除の請求の列で、書き出しの中身が、同じ人が同じ条件で検索・クエリしたときの結果と一致し、制限の外の行・墓標の行・他の組織の行が入らない。
- 結合テスト：設定の束を空の組織に公開 API で戻すと、ダッシュボード・モニター・SLO が同じ定義になる（ID と作った人を除く）。秘密が束に入らない。
- [quality.md](../quality.md) の 2.2.1 節 G の漏れの経路の表に「組織の書き出し」の行を足す。
