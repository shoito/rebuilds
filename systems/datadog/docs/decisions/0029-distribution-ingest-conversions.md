# ADR-0029: StatsD の `d`・`h`・`ms` はエージェントが 10 秒の窓でスケール 5 のヒストグラムにする（標本の率は重みで、区間ごとに丸める）。OTLP の明示の境界のヒストグラムは、区間ごとの代表の値（両端の幾何平均、端の区間は最小・最大）の区間へ移して指数のヒストグラムにし、精度の印を付ける。OTLP の Summary は分位ごとの gauge と、個数・合計の count にする。本システムの API は値の列（1 点 1,000 個まで）か指数のヒストグラムを受ける

## Context

分布は指数のヒストグラムで持つ（[ADR-0028](0028-exponential-histogram-storage-and-percentiles.md)）。送り手は別の形で送る。

- StatsD は値を 1 つずつ送り、標本の率（`@0.1` など）を付けうる（[Datagram Format and Shell Usage](https://docs.datadoghq.com/developers/dogstatsd/datagram_shell/)、2026-10-09 に確認）。指数のヒストグラムの個数は整数で、重み（1 ÷ 率）は小数になりうる。
- OTLP には、指数のヒストグラムのほかに、明示の境界のヒストグラム（Prometheus の形に近い、多くの SDK の既定）と Summary（分位の値。合わせられない）がある（[Metrics Data Model](https://opentelemetry.io/docs/specs/otel/metrics/data-model/)、同日に確認）。
- 明示の境界の区間は粗く（例：50〜75ms）、指数のヒストグラムへ正確には変換できない。変換の誤差を隠すと、利用者は 1.1% の精度だと思い込む。
- 型は指標の名前ごとに 1 つ（[ADR-0016](0016-metric-types-and-cumulative-conversion.md)）。
- 本家の OTLP の明示の境界・Summary の扱いは、公式の資料で確かめなかった（**未検証**）。

## Options

明示の境界：

1. **区間ごとの代表の値（幾何平均、端は最小・最大）へ移し、精度の印を付ける**
2. 区間ごとの count の系列（`le` のタグ）として持つ
3. 受けない

Summary：

- a. **分位ごとの gauge と、個数・合計の count**
- b. 受けない

StatsD の標本の率：

- x. **区間ごとに重みを足し、窓の終わりに丸める**
- y. 値ごとに丸めた重み（1 ÷ 率を四捨五入）

## Decision

1、a、x を採用する。詳細は [distributions-and-sketches.md](../architecture/distributions-and-sketches.md) の 6 節。

- StatsD：エージェントが 10 秒の窓ごとにスケール 5 のヒストグラムへ足す。重みは区間ごとに浮動小数点で足し、窓の終わりに四捨五入する。合計は `Σ v ÷ ρ`、最小・最大は見た値。
- OTLP の指数のヒストグラム：スケールを 5 以下に下げ、`min`・`max` がなければ見積もって印を付ける。
- OTLP の明示の境界：区間 `(b_{j−1}, b_j]` の個数を、代表の値（両端が正なら幾何平均、0 を含むなら `b_j ÷ 2`、最初の区間は `min` か `b_0`、最後の区間は `max` か `b_{n−1}`、両端が負なら負の幾何平均）の区間へ移す。個数・合計・最小・最大はそのまま。`metric_metadata.source = explicit_buckets` と点の印。
- OTLP の Summary：`<名前>.quantile`（gauge、タグ `quantile:<q>`）、`<名前>.count`・`<名前>.sum`（count、累積は差に）。分布の型は作らない。
- 本システムの API：値の列（1 点 1,000 個まで。ゲートウェイがスケール 5 のヒストグラムにする）か、指数のヒストグラム。

### 他の案を選ばなかった理由

- **2（`le` の count の系列）**：クエリの言語に区間の系列から分位を求める別の道が要り、1 つのエンジン・1 つの分布の形（[ADR-0007](0007-query-language.md)）から外れる。境界ごとに系列が増え、課金とカーディナリティにも効く。
- **3・b（受けない）**：多くの SDK の既定の形を受けられず、OpenTelemetry の送り手が設定を変えないと送れない。
- **y（値ごとに丸め）**：率が 0.3 のとき、重み 3.33 を 3 に丸め続けて個数が 10% 少なくなる。区間ごとに足してから丸めれば、ずれは区間ごとに 0.5 以内。

## Consequences

- 良くなること：
  - 標準の 3 つの形と StatsD を、1 つの分布の形で受けられる。
  - 明示の境界から変換した分布は、印で利用者に分かる。
- 引き受けるコスト：
  - 明示の境界から変換した分布のパーセンタイルの誤差は、元の区間の幅で決まり、1.1% の約束の外。
  - Summary の分位の空間の集計は正しい分位にならない（分位の平均）。
  - 標本の率の丸めで、区間の個数は見積もりになる。

## Confirmation

- 表駆動テスト：DT-HIST-002（区間の種類ごとの代表の値、`min`・`max` の有無、Summary、標本の率と丸め）。
- 性質ベーステスト：任意の明示の境界のヒストグラムで、変換の後の個数・合計・最小・最大が元と一致し、各個数の区間の代表の値が元の区間の中にある。
- 結合テスト：OpenTelemetry の SDK（明示の境界の既定）と Collector から送り、クエリの応答に精度の印が出る。
