# ADR-0054: 課金の単位を、ホスト（時間ごとの異なるホストの、月の下位 99% の時間の最大）、カスタムメトリクス（時間ごとの異なる系列の月の平均。標準の指標と溢れを除き、タグの選択の後で数え、分布は 5）、ログの取り込みのバイトと索引の件数、スパンの取り込みのバイトと保持の件数にする。モニターは数えるが課金しない

## Context

- 利用量は、取り込んだ時点で間引く前の量を数え、参照の数え方との差を 0.1% 以内にする（NFR-012、K9）。課金の数字をサンプリングした値から推定しない。
- 本家は、ホストとカスタムメトリクスを時間ごとに数え、ホストは月の時間のうち上位 1% を除いた中の最大で請求する。ホストは監視する OS のインスタンスで、各コンテナにエージェントを入れるとコンテナごとに数える（[Billing](https://docs.datadoghq.com/account_management/billing/)、2026-10-09 に確認）。カスタムメトリクスは指標の名前とタグの値の組で、時間ごとの数の月の平均。分布は 5、パーセンタイルでさらに 5（[Custom Metrics Billing](https://docs.datadoghq.com/account_management/billing/custom_metrics/)、同日に確認）。ログは索引に入れた件数で請求する（[Log Management Billing](https://docs.datadoghq.com/account_management/billing/log_management/)、同日に確認）。取り込みのバイトの数え方は確かめられなかった（**未検証**）。
- 本システムの分布は OpenTelemetry の指数のヒストグラム 1 つで、どのパーセンタイルも同じデータから出る（[architecture/README.md](../architecture/README.md) の 6 節）。
- 原価の大きな部分は、インジェスターのメモリー（有効な系列に比例）と MSK（バイトに比例）である（同 2.1 節）。

## Options

ホストの月の数：

1. **時間ごとの異なるホストの数の、下位 99% の時間の最大（本家に寄せる）**
2. 月の平均
3. 月の最大

分布の重み：

- a. **5（パーセンタイルで足さない）**
- b. 本家と同じ（5、パーセンタイルでさらに 5）
- c. 1

## Decision

1 と a を採用する。

| 単位 | 定義 | 月 |
| --- | --- | --- |
| ホスト | エージェントの安定のホストの ID、OTLP の `host.id`（なければ `host.name`）の、時間ごとの異なる数。API の `host:` タグだけでは数えない。コンテナ・Pod・関数は数えない | 下位 99% の時間の最大 |
| カスタムメトリクス | 時間ごとの異なる系列（タグの選択の後）。標準の指標（`system.*`・`container.*`・`process.*`・`kubernetes.*`・`<brand>.*`・`trace.*`）と溢れの系列を除く。gauge・count・rate は 1、分布は 5 | 時間ごとの平均 |
| ログの取り込み | 展開した後の、本文と属性を本システムの JSON の形にしたバイト。パイプラインの前 | 合計 |
| ログの索引 | 索引に振り分けた件数。保持の区分ごと。再水和は別の単位 | 合計 |
| スパンの取り込み | OTLP の Protobuf の形のバイト（資源の属性はスパンの数で割って足す） | 合計 |
| スパンの保持 | テールサンプリングで残した件数 | 合計 |
| モニター | 有効なモニターの数と評価したグループの数（課金しない） | 最大と平均を見せる |

- 数えないもの：429、受け付けの窓・大きさの上限の拒否、溢れ、見張りの組織。

### 他の案を選ばなかった理由

- **2（平均）**：オートスケールの利用者に有利すぎ、原価（ピークに合わせた容量）と合わない。
- **3（最大）**：1 時間の急増（障害のときのスケールアウト）で月の請求が跳ね、利用者が監視を止める動機になる。
- **b（本家と同じ）**：本システムでは、パーセンタイルの有無で原価が変わらない。原価に合わない請求になる。
- **c（1）**：分布のヒストグラム（最大 512 の区間）は、gauge の系列よりメモリーと保存を多く使う。

## Consequences

- 良くなること：
  - ホストの数え方を本家に寄せ、移行する利用者の請求の予測が立つ。
  - どの単位も、取り込みの段かカタログの行で正確に数えられる。
- 引き受けるコスト：
  - 分布の数え方が本家と違う（[architecture/README.md](../architecture/README.md) の 1.4 節に行を足す必要がある）。
  - 標準の指標の一覧を、エージェントの指標の追加に合わせて保守する。
  - ログの取り込みのバイトの定義が本家と違う可能性がある（未検証）。

## Confirmation

- 表駆動テスト：ホストの鍵の決め方、下位 99% の最大（672・720・744 時間）、分布の重み、標準の指標の除外。
- 参照との比べ：生成したデータの全量を素直に数えた参照との差 0.1% 以内（[quality.md](../quality.md) の 2.2.1 節 J）。
- lint：標準の指標の一覧を 1 か所（エージェントとインジェスターが共有する定義）にだけ持つ。
