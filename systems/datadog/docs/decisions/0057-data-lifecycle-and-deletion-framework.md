# ADR-0057: 保持の期間を `retention_policies` の 1 つの表で持ち、`compactor` がカタログを先に「削除中」にしてから消す。解約は猶予の後に `tenant_id` の接頭辞ごと消し、古いバージョンと大阪の写しを含めて消えたことを確かめて記録する。削除の請求は墓標と書き直し、法的な保全は組織の単位で削除を止める。期限の値は法務の L5・L6・L7 の後に決める

## Context

- 保持の層と期間は [ADR-0009](0009-retention-tiers-on-s3.md) で決めた。保持の区分を S3 のキーに入れ、ライフサイクルを後ろの守りにし、正の削除は `compactor` がカタログで行う。バージョニングの古いバージョンは 7 日。
- 個人のデータの削除の請求は、ログ・トレースの行を墓標で隠し、合わせで書き直す（[ADR-0036](0036-personal-data-deletion-tombstones.md)）。
- 解約の後の消去の期限、削除の請求の期限、監査ログの保持、法的な保全の範囲は、法務の L5・L6・L7 で決まる（[intent.md](../intent.md)）。結論が変わっても、作り直さずに値だけを変えたい。
- データの置き場所が多い：S3（東京・大阪、区分ごと、古いバージョン）、Aurora、Valkey、MSK（24 時間）、読み手の NVMe のキャッシュ、結果のキャッシュ。

## Options

1. **期間を 1 つの表で持つ。解約は接頭辞ごと消して置き場所ごとに確かめる。削除の請求は墓標と書き直し。保全は組織の単位**
2. 組織ごとの鍵を消して読めなくする（crypto-shredding）
3. 期間をデータの種類ごとの設定の値（コードの定数・環境変数）に散らす

## Decision

1 を採用する。

- `retention_policies`（データの種類 → 既定、選べる値、法務の確認の状態）を `compactor` と画面が読む。法務の結論で変えるときは、表と [security.md](../architecture/security.md) の 5 節を同じ変更で直す。
- 保持の期限：カタログの行を「削除中」にしてクエリの計画から外し、S3 のオブジェクトを消す。ライフサイクルは保持＋1 日の後ろの守り。
- 解約：`active → suspended → purging → purged`。猶予（仮 30 日）の後、`tenant-purge` が S3 の `<cell>/<tenant_id>/`（東京・大阪、すべての区分）、Aurora の行、Valkey の鍵を消し、キャッシュの世代を上げる。古いバージョンが消える 7 日の後に、接頭辞の一覧が空・行が 0 であることを確かめ、数だけを本システムの監査に残す。
- 削除の請求：ログ・トレースは ADR-0036。メトリクスは系列ごとにブロックを書き直して点を落とす。結果のキャッシュは世代を上げて無効にする。
- 法的な保全：組織の `legal_hold` が、保持の削除・解約の消去・削除の請求の物理の消去を止める（墓標は付ける）。付け外しは 2 人。

### 他の案を選ばなかった理由

- **2（crypto-shredding）**：組織ごとの鍵が要る（[ADR-0056](0056-encryption-keys-and-secrets.md) で持たないと決めた）。行の単位の削除の請求には使えない。
- **3（散らす）**：法務の結論で値を変えるときに、変え忘れが出る。画面の説明と実際の削除がずれる。

## Consequences

- 良くなること：
  - 法務の結論で、値だけを 1 か所で変えられる。
  - 消えたことを置き場所ごとに確かめた記録が残る。
- 引き受けるコスト：
  - 解約の消去は、古いバージョンの 7 日を待つので、猶予の後さらに 7 日以上かかる。
  - アーカイブの削除の請求は、Glacier Instant Retrieval の取り出しの費用がかかる。
  - 大阪の写しは、東京の削除では消えない。

> 2026-10-09 の注記：最初の起票は「大阪の写しが削除マーカーの写しで消えるか」を未検証としていた。統合の工程で AWS の資料を確かめた。タグで絞った複製の規則（[ADR-0061](0061-dr-stage-up-and-cell-expansion.md)）では、削除マーカーは写らない（[Replicating delete markers](https://docs.aws.amazon.com/AmazonS3/latest/userguide/delete-marker-replication.html)、2026-10-09 に確認）。そこで、保持の期限・削除の請求の書き直し・解約の消去は、どれも大阪の写しを明示に消し、大阪の接頭辞の一覧が空であることを確かめる。

## Confirmation

- 性質ベーステスト：任意の書き込み・保持の変更・削除の請求・保全の列で、保持の中のデータが読め、期限の外・削除したデータが読めない。保全の間は物理の消去が起きない。
- 結合テスト（LocalStack）：解約から `purged` までに、すべての接頭辞と行が 0 になる。
- 本番：毎週の S3 Inventory とカタログの突き合わせに、`purged` の組織の接頭辞が残っていないことを足す。
