# ADR-0024: IR は、時間の窓・区間・揃えの起点・時間の集計・空間の集計・補間・変換・関数・データのアクセスの制限・`tenant_id` をすべて明示した値で持ち、正規の直列化の xxh3_128 で識別する。区間は窓 ÷ 点の数（既定 300）以上の決まった一覧の最小の値で、エポックに揃える。空間の集計は、区間に値のある系列だけで行う。gauge の時間の集計の既定は平均、count・rate は合計。分布のパーセンタイルはヒストグラムを合わせてから求める。NaN は IEEE 754 のまま伝える

## Context

[ADR-0007](0007-query-language.md) は、すべてのクエリを型付きの IR にコンパイルし、既定の意味（時間の集計を先、区間の自動の選択と UTC の 0 時の揃え、補間なし、count・rate の既定は合計、gauge は平均）を IR に書き出してから実行すると決め、細部を決定表にすることをこの領域に任せた。

- 同じ IR が同じ結果になるには、区間・揃え・欠けの扱い・NaN の扱いが決まっていなければならない。
- キャッシュの鍵とクエリのまとめ（NFR-011）に、IR の識別が要る。
- 空間の `avg` を「系列の値の平均」とするか「点の平均」とするかで、結果が大きく変わる（[metrics-query-engine.md](../architecture/metrics-query-engine.md) の 4.3 節の例）。
- 分布のパーセンタイルを系列ごとに求めて平均すると、正しい分位にならない。
- NaN を捨てるか伝えるかを、生の層とロールアップの層で同じにしなければ、層で結果が変わる。
- 本家の既定の意味は、公式の資料で確かめられなかった（**未検証**）。

## Options

空間の集計：

1. **区間に値のある系列の値（時間の集計の後）で集計する。欠けた系列は入れない**
2. 欠けた系列を 0 として入れる
3. 点を直接集計する（時間と空間を 1 段で）

NaN：

- a. **IEEE 754 のまま伝え、応答で null と印にする**
- b. 取り込みで拒む
- c. 集計で捨てる

## Decision

1 と a を採用する。決定表は [metrics-query-engine.md](../architecture/metrics-query-engine.md) の 4.3 節（DT-QRY-001）。

- IR の欄：`tenant_id`、`restriction`（必ず付く）、指標と型、正規の形のフィルター、揃えた窓、区間、揃えの起点（エポック）、時間の集計、空間の集計とグループ、補間、変換（`as_count`・`as_rate`）、関数、`timeshift`。
- 識別：正規の直列化の xxh3_128。キャッシュには窓を除いたハッシュを使う。
- 区間：一覧 `[10, 15, 20, 30, 60, 120, 300, 600, 1200, 1800, 3600, 7200, 14400, 21600, 43200, 86400]` 秒のうち `(end − start) ÷ N` 以上の最小（`N` は既定 300、最大 1,500）。`.rollup()` で 1 秒まで。
- 型ごとの時間の集計の既定：gauge は平均、count と rate は合計、分布はヒストグラムの合わせ、10 秒の区間の集計の系列は Σ合計 ÷ Σ個数。
- 空間の分位は、グループの区間のヒストグラムを合わせてから求める。
- 補間は既定なし。`.fill()` で系列ごとに、時間の集計の後・空間の集計の前に当てる。
- NaN は IEEE 754 のまま（NaN を含む区間の合計・平均・最小・最大は NaN）。ロールアップも同じ規則。応答は null と `nan: true`。

### 他の案を選ばなかった理由

- **2（欠けを 0）**：送る間隔の違う系列が混ざると、平均が下がる。利用者の意図しない値になる。必要なら `.fill(zero)` で明示する。
- **3（1 段）**：点の多い系列が平均を支配する。ダッシュボードとモニターで、利用者の期待（ホストの平均の平均）と合わない。
- **b（拒む）**：利用者のデータの事実（計測の失敗）を隠す。202 の後に拒めない経路もある。
- **c（捨てる）**：生の層では捨て、ロールアップでは合計に入る、という食い違いを生みやすい。

## Consequences

- 良くなること：
  - 同じ IR が、どの経路・層・キャッシュでも同じ結果になる。
  - 決定表と参照の実装で確かめやすい。
  - パーセンタイルが正しい分位になる。
- 引き受けるコスト：
  - 点の数の重みを付けた平均が欲しい利用者は、`sum` と `count` の式を書く必要がある。
  - NaN を 1 つ含む区間が NaN になる（印で示す）。
