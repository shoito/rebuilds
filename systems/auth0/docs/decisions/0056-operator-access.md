# ADR-0056: 社内の運用者は本番に常設の権限を持たず、テナントのデータの参照はテナントの許可と期限つきの権限で行う

## Context

このシステムは、多数のテナントのエンドユーザーの資格情報と個人データを 1 か所に持つ。社内の運用者（Ops、サポート、Dev）が本番に広い権限を持つと、次の危険がある。

- 内部の不正や、運用者のアカウントの乗っ取りで、多数のテナントのデータが一度に漏れる。
- 運用者が、テナントのユーザーになりすまして、テナントのアプリにログインできる（トークンを作れる）。
- 署名鍵の暗号文と、復号の権限が、同じ人の手に揃う。

他の題材は、SSO と MFA、最小権限、break-glass、四半期のアクセスレビューを決めている（Slack の security.md の 7 節、Stripe の ADR-0020）。本家が、サポートがテナントのデータを見るときにテナントの許可を求める機能を持つかは、未検証（本家の資料で見つかったのは、ダッシュボードの「Support Access」「Elevated Support Access」のロールで、サポートのチケットの操作と集計の指標の参照だけ。[Add Dashboard Users](https://auth0.com/docs/get-started/manage-dashboard-access/add-dashboard-users)、2026-09-27 に確認）。

## Options

1. **常設の権限は読み取りのメトリクスとダッシュボードだけにする。本番のデータ・ログ・シェルへのアクセスは、期限つきの権限（JIT）で、理由と承認を付けて得る。テナントのデータの参照は、テナントの許可を前提にする**
2. Ops に本番の読み取りの常設の権限を与え、監査ログで追う
3. Stripe の CDE と同じく、本番のすべてを JIT にし、承認を 2 人にする

## Decision

1 を採用する。

- **常設の権限**：Grafana のダッシュボード、メトリクス、アラート、秘密を含まないアプリのログ（[ADR-0061](0061-secret-free-telemetry.md) の許可リストを通したもの）の読み取り。
- **期限つきの権限（最長 4 時間）**：
  | 権限 | 承認 | 使う場面 |
  | --- | --- | --- |
  | 本番の DB の読み取り（RLS の対象のロール。テナントを指定する） | Ops の責任者（作成者と別） | 障害の調査、テナントからの問い合わせ |
  | 本番の DB の書き込み | Ops の責任者と Dev のテックリードの 2 人 | データの修復 |
  | ECS Exec、タスクへのシェル | 同上。**Signer では提供しない** | 障害の調査 |
  | KMS の鍵の管理（ローテーション、キーポリシー） | セキュリティの担当と Ops の責任者の 2 人 | 緊急の鍵の操作（[runbooks/emergency-key-rotation.md](../runbooks/emergency-key-rotation.md)） |
- **テナントのデータの参照は、テナントの許可を前提にする。** テナントの管理者が、ダッシュボードでサポートの参照を許可する（期限つき）。許可のない参照は、インシデントの対応（セキュリティの事象）に限り、プラットフォームの監査に残し、事後にテナントへ知らせる。
- **なりすましの機能を作らない。** 運用者が、テナントのユーザーとしてトークンやセッションを作る機能は作らない。Signer の API を運用者が直接呼ぶ経路も作らない。
- **署名鍵の復号の権限を人に与えない。** 署名鍵の KMS の鍵の `kms:Decrypt` は Signer のタスクのロールだけが持つ（[ADR-0003](0003-token-formats-and-signing-keys.md)）。break-glass のロールも持たない。キーポリシーの変更は、2 人の承認と CloudTrail の呼び出しのアラートで守る。
- **AI エージェントは本番に経路を持たない。** コーディング・運用のエージェントは、本番のデータ・ログ・トレース・シェル・KMS に経路を持たない。調査に使うときは、人が取り出した秘密と個人データを含まないものだけを渡す（他の題材と同じ）。
- **レビュー**：四半期ごとに、権限の割り当てと、期限つきの権限の使用の記録を見直す。
- 2 は、1 人のアカウントの乗っ取りで全テナントのログ（IP、メール）が読める。3 は、障害の調査が遅くなり、NFR-001 の 99.99% の障害の対応（月 4.3 分）に合わない。

## Consequences

- 良くなること：
  - 1 人の運用者のアカウントが乗っ取られても、読めるのは秘密を含まないメトリクスとログだけ。
  - 運用者が、テナントのユーザーになりすませない。
- 引き受けるコスト：
  - 障害の調査で、期限つきの権限を得る手間（数分）がかかる。SEV1 では、承認をオンコールの二次が行ってよい。
  - テナントの許可を待つ間、サポートの問い合わせへの回答が遅れる。

## Confirmation

- IAM の静的検査（Terraform の CI）：本番のアカウントに、期限つきの権限の仕組み以外から DB・ECS Exec・KMS の管理の権限を持つ人のロールがない。
- IAM の静的検査：署名鍵の KMS の鍵の `kms:Decrypt` を持つプリンシパルが、Signer のタスクのロールだけ。
- 週次：期限を過ぎて残る割り当てがないこと。あれば呼び出す。
- 四半期：アクセスレビューの記録。
