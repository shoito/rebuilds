# ADR-0052: 組織の文脈のトークンに `org_id` を入れ、リフレッシュの系列を組織に結んでメンバーシップを毎回確かめる

詳細は [organizations.md](../architecture/organizations.md) の 5・6 節。MVP の後（E14）。

## Context

本家は、組織の文脈のログインで、ID トークンとアクセストークンに `org_id`（設定で `org_name` も）を入れる。テナントの API には、`org_id` を既知の値と照合し、データを `org_id` で分けるよう求める（[Work with Tokens and Organizations](https://auth0.com/docs/manage-users/organizations/using-tokens)、2026-09-27 に確認）。本家が、リフレッシュのときにメンバーシップを確かめるか、組織の切り替えでセッションをどう扱うかは、資料で確かめられなかった（未検証。auth0.com/docs の全文に記述がない。E14 の着手前に試用のテナントで確かめる）。

本システムのリフレッシュトークンは系列（family）を持ち、ローテーションと再利用の検知をする（[ADR-0003](0003-token-formats-and-signing-keys.md)）。SSO のセッションはテナントに 1 つ（sessions-and-sso の領域）。

メンバーを組織から外したのに、リフレッシュトークンで最終の期限（既定 30 日）まで組織の `org_id` のトークンを得られると、退職者や契約の切れた会社の利用者が入れ続ける。

## Options

1. **組織の文脈の系列は `org_id` を持ち、リフレッシュのたびにメンバーシップを確かめる。外れていたら系列を失効させる。組織の切り替えは新しい `/authorize`**
2. リフレッシュでは確かめず、メンバーの削除のときに系列を失効させるだけ
3. 組織ごとに別の SSO のセッションを持つ

## Decision

1 を採用する。

- ID トークンとアクセストークンに `org_id`。`org_name` はテナントの設定で。組織のロールはアプリの設定で入れられる。`org_id` は予約のクレームで、Actions で変えられない。
- リフレッシュトークンの系列に `organization_id` を持たせる。リフレッシュのたびにメンバーシップを確かめ（索引 1 回の読み込み）、外れていたら `invalid_grant` で系列を失効させる。
- メンバーの削除・組織の削除のときも、その組織の系列を失効させる（非同期）。発行済みのアクセストークンは期限まで有効。
- 組織の切り替えは新しい `/authorize`。既存の SSO のセッションを使えるのは、セッションの認証に使った接続が、その組織でも有効で、利用者がメンバーであるとき。
- 招待の ticket は 256 ビット、SHA-256 で保存、1 回限り、既定 7 日・最大 30 日。招待のメールアドレスと、利用者の確認済みのメールアドレスの一致を求める。データベース接続で新しく登録した利用者だけ、受け入れでメールを確認済みにする。
- 2 は、削除の非同期の処理が遅れた間と、削除の経路を通らない変更（自動の付与の設定の誤りの修正など）で、外れた利用者が入れ続ける。
- 3 は、1 つのブラウザで複数の組織のセッションが並び、ログアウト（RP-Initiated、Back-Channel）の範囲が複雑になる。

## Consequences

- 良くなること：
  - メンバーシップの変更が、次のリフレッシュ（アクセストークンの期限）で効く。
  - SSO のセッションの形を変えずに、組織の境界を守れる。
- 引き受けるコスト：
  - 組織の文脈のリフレッシュに、DB の読み込みが 1 回増える。DB が読めない間、組織の文脈のリフレッシュは 503 になる（ADR-0005 の縮退で、リフレッシュは最優先だが、組織の境界を優先する）。
  - 本家がリフレッシュで確かめないなら（未検証）、本家より厳しい。

## Confirmation

- 性質ベーステスト：任意のメンバーの削除の後、その組織の系列のリフレッシュが失敗し、系列が失効する。
- 結合テスト：組織 A のセッションで、組織 B（メンバー、同じ接続が有効）への `/authorize` は再認証なしで通り、組織 B で無効な接続のセッションでは再認証を求める。
- 結合テスト：招待の使い回し、期限切れ、メールアドレスの不一致、確認していない IdP のメールが拒否される。
- 結合テスト：Actions で `org_id` を書き換えても、発行したトークンの `org_id` は変わらない。
