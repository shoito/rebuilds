# ADR-0041: メールのテンプレートは自動でエスケープする制限した Liquid で書かせ、リンクは本システムが作る。テナントの送信事業者は SMTP と SES（クロスアカウント）に限る

## Context

テナントは、メールの件名・本文・送信元を、自社のものにしたい。本家 Auth0 の振る舞い（2026-09-27 に確認）：

- テンプレートの種類：ブロックの通知、パスワードの変更のコード、パスワードの変更のリンク、MFA の登録、MFA の確認のコード、漏えいしたパスワードの通知、パスワードなしの OTP、招待、確認のコード、確認のリンク、ようこそ（[Email Templates](https://auth0.com/docs/customize/email/email-templates)）。
- どの欄も Liquid で書ける。送信元は任意（なければ事業者の既定）、件名、HTML の本文、リンクの有効期間（既定 432,000 秒）、戻り先の URL（`Redirect To`）。組み込みの送信ではテンプレートを変えられない（[Customize Email Templates](https://auth0.com/docs/customize/email/email-templates/customize-email-templates)）。
- テナントの送信事業者は、SES、SendGrid など 8 種と SMTP、Actions による独自の事業者（[Configure External SMTP Email Providers](https://auth0.com/docs/customize/email/smtp-email-providers)）。

テンプレートは、テナントの管理者が書く。管理者のアカウントが乗っ取られると、正規の送信ドメインから、フィッシングのリンクを含むメールを全ユーザーに送る道具になりうる。

## Options

テンプレート：

1. **LiquidJS を、自動のエスケープ・ファイルの読み込みなし・時間とサイズの上限付きで使う。確認・再設定のリンクは本システムが作る変数だけにし、テンプレートの中で URL を組み立てさせない**
2. 本家と同じく、Liquid を自由に使わせる
3. テンプレートを持たせず、文言の上書きだけにする

テナントの送信事業者：

- a. **SMTP（STARTTLS か暗黙の TLS が必須）と、テナントの AWS アカウントの SES（IAM のロールの引き受け）に限る**
- b. 本家と同じく、主要な事業者の API をそれぞれ連携する
- c. 独自の事業者を、テナントのコード（Actions に相当）で送る

## Decision

1 と a を採用する。c は Actions に相当する仕組み（E13）の後に検討する。

### テンプレート

- 種類：`verify_email_code`、`verify_email_link`、`reset_password_link`、`password_changed`、`mfa_otp`（mfa-and-passkeys の領域）、`blocked_account`、`breached_password`、`welcome`、`invitation`（E14）。
- 欄：送信元の表示名、送信元のアドレス（認証済みの送信ドメインのものだけ。[ADR-0040](0040-email-sending-platform.md)）、返信先、件名、HTML の本文、テキストの本文（なければ HTML から作る）、言語（`ja`・`en`）ごと。
- 描画：LiquidJS を、HTML の本文では出力を既定でエスケープする設定で使う（`outputEscape: 'escape'`）。`include`・`render`・`layout` のファイルの読み込みを無効にする。1 回の描画に 50 ms・出力 256 KB の上限を置く。未定義の変数は空にする（エラーにしない）が、保存の前の検証で警告する。
- 変数：種類ごとに決めた一覧だけを渡す（`user.email`、`user.name`、`application.name`、`tenant.friendly_name`、`code`、`url`、`expires_in_minutes`、`locale`）。`user.app_metadata` などは渡さない。
- **リンク**：`url` は本システムが作り、テンプレートには完成した値だけを渡す（ホスト名は [ADR-0039](0039-hostname-resolution-and-issuer.md)、トークンは [ADR-0015](0015-database-connection-password-and-enumeration.md)）。本文の中の他のリンク（`<a href>`）は、`https:` のものだけを残す。
- **戻り先（本家の `Redirect To`）**：確認・再設定の完了の後は、本システムの完了の画面を出す。そこからアプリへ戻すときは、トランザクションのアプリの登録済みの URL（ログインの途中なら `redirect_uri`、そうでなければアプリの「ログインの開始の URL」）だけを使う。テンプレートやクエリで任意の URL を指定させない（オープンリダイレクトの防止）。
- **変更の保護**：テンプレートと送信元の変更は、監査ログに残し、テナントのすべての管理者にメールで知らせる。変更の直後 24 時間は、1 通目の送信の前にダッシュボードで試験の送信を促す（強制はしない）。
- 3 は、日本の事業者が求める件名・署名・問い合わせ先の書式に足りない。

### テナントの送信事業者

- `smtp`：ホスト、ポート（465・587）、ユーザー名、パスワード（エンベロープ暗号化。[ADR-0004](0004-credential-storage.md)）。TLS を必須にし、証明書を検証する。宛先のホストは、名前の解決の後にプライベートのアドレス・リンクローカル・本システムのアドレスでないことを確かめる（SSRF の防止）。
- `ses_cross_account`：テナントの AWS アカウントの IAM のロールを、外部 ID 付きで引き受けて、テナントの SES で送る。長期の秘密を持たない。
- 送信の Worker は、テナントの事業者への接続を、本システムの SES と別のタスクの群にし、遅い SMTP が他のテナントの送信を詰まらせないようにする（テナントごとの同時接続 5）。
- テナントの事業者が失敗したとき（接続の失敗、認証の失敗、5xx が 15 分続く）は、**本システムの共有の送信ドメインに切り替えない**。テナントが自分の事業者を選んだ理由（送信元、契約、記録）を守るため。代わりにダッシュボード・メール・ログで知らせる。テナントの設定で「失敗したら共有の送信に切り替える」を選べる（既定は切り替えない）。
- 送信の結果（配信、バウンス）は、テナントの事業者からは受け取れないので、`email_messages` は「事業者が受け付けた」までを記録する。
- b は、事業者ごとの API と失敗の扱いの保守が重く、MVP の価値に比べて見合わない。主要な事業者の多くは SMTP を提供する。

## Consequences

- 良くなること：
  - テンプレートからの XSS、任意のリンク、オープンリダイレクト、ファイルの読み込みを防げる。
  - テナントの SMTP の資格情報を、他の秘密と同じ方式で守れる。
- 引き受けるコスト：
  - 本家のテンプレートの中で任意の URL を作っている移行は、そのまま動かない。
  - テナントの事業者で送ったメールの到達性は、本システムで測れない。

## Confirmation

- 結合テスト：テンプレートに `{{ user.name }}` があり、名前が `<img src=x onerror=...>` のとき、本文ではエスケープされる。
- 結合テスト：`{% include '/etc/passwd' %}`、無限のループ、巨大な出力のテンプレートは、保存の時か描画の時に拒否される。
- 結合テスト：SMTP のホストに `127.0.0.1`、`169.254.169.254`、VPC の中のアドレスに解決される名前を指定すると、保存が拒否される。
- 否定側のテスト：完了の画面からの戻り先に、登録されていない URL を指定できない。
