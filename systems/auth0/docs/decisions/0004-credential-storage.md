# ADR-0004: パスワードは Argon2id、高エントロピーの秘密はハッシュ、戻す必要のある秘密はエンベロープ暗号化で持つ

## Context

このシステムは、多数のテナントの資格情報を 1 か所に集める。DB やバックアップが漏れたときの被害を小さくする必要がある。保存するものは性質が違う。

| 種類 | 例 | 元に戻す必要 |
| --- | --- | --- |
| 人が選ぶ低エントロピーの秘密 | パスワード、リカバリーコード | ない（照合だけ） |
| システムが作る高エントロピーの秘密 | クライアントシークレット、リフレッシュトークン、認可コード、パスワードの再設定・メールの確認のトークン | ない（照合だけ） |
| 元に戻して使う秘密 | TOTP の種、ソーシャル IdP のクライアントシークレット、メールの送信・ログストリームの資格情報 | ある |
| 秘密でないもの | WebAuthn の公開鍵、署名鍵の公開鍵 | — |

指針（2026-09-27 に確認）：

- NIST SP 800-63B-4：パスワードはソルトを付けてハッシュにする（SHALL）。秘密の鍵による追加の鍵付きハッシュを行うべきで（SHOULD）、その鍵はハッシュと別に保管する（SHALL）。新しいパスワードは、よく使われる・漏えいしたパスワードの一覧と照合する（SHALL）。連続の失敗は 100 回以下に制限する（SHALL）（[SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html)）。
- OWASP：Argon2id の最小の設定は、メモリー 19 MiB、反復 2、並列度 1。bcrypt は入力が 72 バイトまで（[Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)）。
- 本家 Auth0 の漏えいしたパスワードの検知は、サインアップ・ログイン・再設定で働き、ブロックと通知ができる（[Breached Password Detection](https://auth0.com/docs/secure/attack-protection/breached-password-detection)）。
- Have I Been Pwned の Pwned Passwords は、SHA-1 の先頭 5 文字で問い合わせる k-匿名性の range API を、認証なしで提供する。応答の件数をそろえる `Add-Padding` のヘッダーがある。データセットは丸ごと取得できる（[HIBP API v3](https://haveibeenpwned.com/API/v3)）。

## Options

パスワード：

1. **Argon2id（PHC 形式）＋別に保管した鍵での鍵付きハッシュ。取り込んだ bcrypt は照合でき、ログインの成功時に Argon2id へ作り直す**
2. bcrypt だけ
3. scrypt・PBKDF2

漏えいしたパスワードの照合：

- a. 外部の range API（HIBP）を、ログインのたびに呼ぶ
- b. **データセットを取り込み、同じ k-匿名性の range API を自前でホストする**

戻す必要のある秘密：

- x. **KMS のエンベロープ暗号化**
- y. Secrets Manager にテナントの秘密を 1 件ずつ置く

## Decision

1、b、x を採用する。b は、データセットの利用条件を法務が確かめるまで有効にせず、それまでは a を使う（[ADR-0025](0025-breached-password-detection.md)）。

### パスワード

- **Argon2id で保存する。** 初期値は OWASP の最小（m=19 MiB、t=2、p=1）とし、E12 の負荷試験で、ログインの p99（NFR-002）と CPU の費用を見て引き上げる。パラメーターは PHC 形式でハッシュに含め、古いパラメーターのハッシュはログインの成功時に作り直す。
- **鍵付きハッシュ（pepper）を加える。** Argon2id の出力に、HMAC-SHA-256 をもう 1 回かける。鍵は KMS でエンベロープ暗号化し、パスワードを照合するプロセスの起動時に復号してメモリーに置く。ログインのたびに KMS を呼ばない（[ADR-0005](0005-authentication-path-availability.md)）。鍵にはバージョンを付け、ハッシュにバージョンを記録する。鍵を替えたら、ログインの成功時に新しいバージョンで作り直す。
- **取り込んだハッシュ**：bcrypt（`$2a$`・`$2b$`・`$2y$`）を MVP から照合できるようにする。ログインに成功したら Argon2id に作り直す。他の形式（PBKDF2、SHA-256 のソルト付きなど）は、ユーザーのインポートの Epic で足す。
- **パスワードのポリシー**：組み合わせの規則（記号を必須にするなど）は既定にしない。最小の長さと、一覧との照合を必須にする（NIST SP 800-63B-4）。既定の長さは connections の領域で決める。
- **ハッシュの計算は、要求を受けるイベントループの外（worker threads）で行う。** 同時に計算する数に上限を置き、上限を超えたら待たずに 503 を返す。攻撃の防御（ブルートフォース、不審な IP）の判定は、ハッシュの計算の前に行う。

### 漏えいしたパスワード

- **Pwned Passwords と同じ k-匿名性の方式で照合する。データセットを定期的に取り込み、range API を自前でホストすることを目標にする。**
  - 照合の方式は HIBP と同じにする（SHA-1 の先頭 5 文字で問い合わせ、残りを手元で比べる）。
  - 自前でホストすれば、認証の経路が外部の API に依存せず、パスワードに由来する値を国外へ送らない（[intent.md](../intent.md) の L1 との関係を避ける）。
  - **自前のホストを有効にするのは、データセットの保存と商用の利用の条件を法務が確かめてから。** 利用規約に複製・配布と類似のサービスを禁じる条項があり、Pwned Passwords への適用は明記がない（2026-09-27 に確認。[ADR-0025](0025-breached-password-detection.md)）。**確認までは公式の range API（a、`Add-Padding` 付き）を認証の経路から呼び、範囲の応答を 24 時間キャッシュする。** その間の縮退は [ADR-0005](0005-authentication-path-availability.md) の表の「漏えいしたパスワードの照合」の行に従う。
- サインアップ・パスワードの変更・再設定では、一覧にあるパスワードを拒否する。ログインでは、照合の成功の後に調べ、テナントの設定で「再設定を求める」「通知する」を選べる。
- a を恒久の形にすると、ログインのたびに外部に依存し、外部が落ちたときの扱い（照合を飛ばす）が防御の穴になる。確認までの暫定の形としてだけ使い、サインアップ・変更・再設定では照合を飛ばさずに 503 にする。

### 高エントロピーの秘密

- クライアントシークレット、リフレッシュトークン、認可コード、各種のトークンは、SHA-256 の値だけを保存する。十分な乱数（256 ビット）なので、ソルトと遅いハッシュは使わない。照合は定数時間で行う。
- **クライアントシークレットは、作成とローテーションの時に 1 回だけ表示する。** 本家はいつでも表示できる。本システムは、DB が漏れてもシークレットが漏れないことを優先する。このため、クライアントシークレットでの署名（HS256、`client_secret_jwt`）は提供しない（[ADR-0003](0003-token-formats-and-signing-keys.md)）。機密のクライアントには `private_key_jwt` を勧める。
- リカバリーコードとメールの OTP は低エントロピーなので、パスワードと同じ方式か、試行の回数の上限と短い有効期間で守る（mfa-and-passkeys の領域で決める）。

### 元に戻す必要のある秘密

- **KMS のエンベロープ暗号化（AES-256-GCM）で保存する。** テナントごとのデータキーを使い、AAD に `tenant_id`・行の ID・用途を含める。署名鍵の KMS の鍵とは別の KMS の鍵にする。
- 復号したデータキーは、使うプロセスのメモリーに短い時間だけ置く。
- y は、テナントの数×秘密の数だけ Secrets Manager の秘密ができ、費用と API の上限が見合わない。本システムの基盤の秘密（DB の資格情報、pepper の暗号文の置き場所など）には Secrets Manager を使う。

### ログ

- どの種類の秘密も、ログ・トレース・エラーの本文・メトリクスに出さない。ロガーは、許可したフィールドだけを出すスキーマで包む。

## Consequences

- 良くなること：
  - DB やバックアップが漏れても、パスワード（pepper の鍵がない限り総当たりもできない）・トークン・シークレットは使えない。
  - 他の IdP からの移行で、ユーザーにパスワードを作り直させずに済む（bcrypt）。
- 引き受けるコスト：
  - Argon2id はログインごとに CPU とメモリーを使う（S1 のピーク 1 秒 500 件）。ハッシュを計算するタスクの数を負荷試験で決める。
  - pepper の鍵を失うと、全ユーザーのパスワードが照合できなくなる。KMS の鍵の削除を防ぎ（削除の保護と、承認の 2 人の規則）、暗号文をバックアップと大阪に複製する。
  - クライアントシークレットを再表示できない。失くしたらローテーションする。

## Confirmation

- 性質ベーステスト：任意のパスワードで、保存した値に平文も、平文の SHA-1・SHA-256 も含まれない。
- 結合テスト：bcrypt のハッシュを取り込んだユーザーが、ログインの成功後に Argon2id のハッシュを持つ。
- CI とログの走査：トークンの接頭辞（`<brand>_rt_` など）、JWT の形、パスワードのフィールドの名前が、ログ・トレースに出たら失敗させる。
- 結合テスト：range API で、一覧にあるパスワードでのサインアップが拒否される。
