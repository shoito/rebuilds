# ADR-0053: RFC 9700 の要件と脅威モデルを要件 ID の表にし、要件ごとに拒否の側のテストを持つ

## Context

このシステムは認可サーバーを自前で実装する（[ADR-0001](0001-platform-and-stack.md)）。OAuth・OIDC の実装の誤り（`redirect_uri` の照合、PKCE、`state`・`nonce`、コードの再利用、mix-up、オープンリダイレクト）は、エラーにならずに脆弱性として残る。適合試験（OpenID Foundation の conformance suite）は、正しい要求への正しい応答を主に確かめる。攻撃者が送る不正な要求の拒否は、一部しか覆わない。

RFC 9700（OAuth 2.0 Security Best Current Practice、2025 年 1 月）は、認可サーバーが守るべきことを 2 節（推奨）と 4 節（攻撃と対策）にまとめている。ADR-0001 は、これをチェックリストとして security の領域に写し、要件ごとにテストを持つと決めた。

決めることは次の 3 つ。

- チェックリストをどこに、どの粒度で持つか
- テストとどう結ぶか
- 外部の検証（ペンテスト、バグバウンティ）をいつ行うか

## Options

1. **RFC 9700 の各項目と、STRIDE の脅威を、`SEC-` の ID を持つ表にする。** 各行に、本システムの対応、対応する要件 ID（`REQ-*`・`PROP-*`）、拒否の側のテストの名前を書く。CI で、表のすべての行にテストがあることを検査する
2. 文書として RFC 9700 の要約を置き、テストは各 Story に任せる
3. 外部のペンテストと適合試験だけに頼る

## Decision

1 を採用する。

- **表の正本は [security.md](../architecture/security.md) の 4 節に置く。** 行の ID は `SEC-NNN`。一度振ったら再利用しない（process.md の ID の規則に合わせる）。
- **各行は、次を持つ。** RFC 9700 の節、要件の強さ（MUST・SHOULD・本システムの追加）、本システムの対応、対応を決めた領域の文書、拒否の側のテストの名前（`SEC-NNN` を含める）。
- **拒否の側のテストを必ず書く。** 例：登録と 1 文字違う `redirect_uri`、PKCE のない公開クライアント、`plain` の `code_challenge_method`、使用済みのコード、別のクライアントのコード、`alg: none`、別のテナントの `iss`。テストは開発リポジトリの `tests/security/` に置き、名前に `SEC-NNN` を含める。
- **CI で追跡を検査する。** `security.md` の表の `SEC-NNN` のうち、テストから参照されていないものがあれば失敗させる（process.md の 7 節の追跡の検査に `SEC-` を足す）。
- **本システムが本家より厳しくする点は、表に「本システムの追加」と書く。** 例：`redirect_uri` の完全一致（ワイルドカードを許さない。本家はサブドメインのワイルドカードを許す）、HS256 を提供しない（[ADR-0003](0003-token-formats-and-signing-keys.md)）。
- **外部の検証**：E12 で、認可サーバーに詳しい外部のペンテストを 1 回受ける。High 以上が 0 件になってから GA の判定に進む。その後は年 1 回と、プロトコルの大きな変更（PAR・DPoP・Actions）の後に受ける。バグバウンティは、GA の後に招待制で始める。
- 2 は、Story をまたぐ要件（mix-up、オープンリダイレクト）が、どの Story の担当にもならずに漏れる。3 は、見つかるのが遅く、回帰を防げない。

## Consequences

- 良くなること：
  - RFC 9700 の要件と、テストの対応が 1 か所で見える。監査や顧客のセキュリティの質問票に、同じ表で答えられる。
  - 攻撃の入力への回帰を、PR ごとに防げる。
- 引き受けるコスト：
  - 表の保守が要る。新しいエンドポイント・パラメーターを足す Story は、表の行の追加を Design 段で行う。
  - RFC 9700 の改訂や、新しい攻撃の報告（例：新しい mix-up の型）に追従する担当が要る。セキュリティの担当が四半期ごとに見直す。

## Confirmation

- CI：`security.md` の `SEC-NNN` がすべてテストから参照されている。
- レビュー：`security:sensitive` の PR で、新しいエンドポイント・パラメーターに `SEC-` の行とテストがあることを、セキュリティの担当が確かめる（[ADR-0065](0065-security-sensitive-change-flow.md)）。
- E12：外部のペンテストの報告で、High 以上が 0 件。
