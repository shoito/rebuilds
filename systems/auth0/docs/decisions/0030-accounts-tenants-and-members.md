# ADR-0030: テナントの上にアカウントを置き、テナントの名前は再利用せず、環境は昇格だけを許す

詳細は [tenants-and-applications.md](../architecture/tenants-and-applications.md) の 3 節。

## Context

[ADR-0002](0002-tenancy-and-isolation.md) で、環境ごとに別のテナントにすると決めた。その結果、1 つの顧客が複数のテナントを持つ。請求、テナントの作成の権限、管理者の招待を、テナントの上でまとめる単位が要る。

本家の振る舞い（2026-09-27 に確認）：

- テナントの名前は 3〜63 文字の小文字の英数字とハイフンで、作成後に変えられず、削除しても再利用できない（[Create Tenants](https://auth0.com/docs/get-started/auth0-overview/create-tenants)）。
- 環境のタグ（Development・Staging・Production）を付け、本番のレート制限は Production のタグのテナントにだけかかる。複数のテナントを 1 つの Enterprise のサブスクリプションに結べる（[Set Up Multiple Environments](https://auth0.com/docs/get-started/auth0-overview/create-tenants/set-up-multiple-environments)）。
- ダッシュボードの管理者（テナントのメンバー）にロールを割り当てる（[Dashboard Access by Role](https://auth0.com/docs/get-started/manage-dashboard-access/feature-access-by-role)）。

## Options

1. **アカウント（請求・契約の単位）の下にテナントを置く。メンバーはテナントごとにロールを持つ。アカウントの管理者は別に持つ**
2. テナントだけを持ち、請求はテナントごとにする
3. 1 つのテナントの中に環境を持つ（ADR-0002 で退けた）

名前と環境：

- a. **名前は再利用しない。環境は `development` → `staging` → `production` の昇格だけを許す**
- b. 本家と同じく、環境のタグをいつでも変えられる

## Decision

1 と a を採用する。

- **アカウント**：請求、契約、テナントの作成・削除の権限を持つ。アカウントの管理者（`owner`・`billing`）は、テナントのメンバーとは別に持つ。表は RLS の外に置き、テナントをまたぐ処理の DB のロールで扱う（ADR-0002）。
- **テナントのメンバー**：ダッシュボードの管理用のテナントのユーザー（[ADR-0036](0036-dashboard-login-via-admin-tenant.md)）に、テナントごとのロールを割り当てる。最後の `admin` は外せない。
- **名前**：3〜63 文字、`^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]$`、リージョンの中で一意、変えない、削除後も再利用しない。予約の名前を持つ。
- **環境**：作成時に決める。後から変えられるのは昇格だけ。下げたいときは、新しいテナントを作る。
- 2 は、同じ顧客の開発と本番の請求と管理者を別々に扱うことになり、本家の利用者の期待（1 つの契約で複数の環境）と合わない。
- b は、本番のテナントを開発に下げて、本番のレート制限と SLO の対象から外す使い方を許す。本家では、タグで本番のレート制限が決まる（上の出典）。本システムでも同じなので、下げる方向を閉じる。

## Consequences

- 良くなること：
  - 請求と権限の単位がはっきりし、テナントを増やしても管理が散らばらない。
  - 名前の再利用の禁止で、古い `issuer` を信じるアプリに、別の顧客のテナントがなりすます余地がない。
- 引き受けるコスト：
  - 本家と違い、環境を下げられない。誤って本番にしたテナントは作り直しになる。作成の画面で確かめる。
  - アカウントとメンバーの 2 種類の管理者がいる。ダッシュボードで区別して見せる。

## Confirmation

- 結合テスト：削除したテナントの名前で作成すると 409。予約の名前で作成すると 400。
- 結合テスト：`production` から `development` への変更は 400。`development` から `production` は通り、監査に残る。
- 結合テスト：最後の `admin` を外す操作は 409。
- レビュー：アカウントの表に RLS がないことは意図したもので、アクセスは専用の DB のロールに限ることを、マイグレーションの許可リストで確かめる。
