# ADR-0025: 漏えいしたパスワードは k-匿名性で照合する。データの自前のホストは利用条件の確認を条件にし、確認までは公式の range API を使う

## Context

[ADR-0004](0004-credential-storage.md) で、Pwned Passwords のデータセットを取り込み、k-匿名性の range API を自前でホストすると決めた。データセットの利用条件は未検証とし、E8 の着手前に確かめるとした。

2026-09-27 に確かめたこと：

- range API は、登録も API キーも要らない。「ライセンスと帰属の要件はない」とされ、レート制限もない。`Add-Padding` で応答の件数を 800〜1,000 にそろえられる（[HIBP API v3](https://haveibeenpwned.com/API/v3)）。
- データセットの全体は、公式の downloader で取得できる（[Pwned Passwords](https://haveibeenpwned.com/Passwords)）。取得したデータを保存し、商用のサービスの中で使うことの条件は書かれていない。
- 利用規約は、HIBP のデータの複製・配布と、「実質的に同じ機能の漏えいのデータベース・検索のサービス」を作ることを禁じる条項を持つ。Pwned Passwords に適用されるかは明記がない（[Terms of Use](https://haveibeenpwned.com/TermsOfUse)）。
- 本家 Auth0 の標準の検知は、サインアップ・ログイン・再設定で働き、公開の漏えいを走査する（反映まで 7〜13 か月）。応答を外すと監視のモードになる（[Breached Password Detection](https://auth0.com/docs/secure/attack-protection/breached-password-detection)）。
- NIST SP 800-63B-4 は、新しいパスワードを漏えいしたパスワードの一覧と照合し（SHALL）、侵害の証拠があればパスワードの変更を強いる（SHALL。3.1.1.2 節）。

## Options

1. **ADR-0004 のとおり自前でホストする。ただし有効にするのは、法務の確認とデータの提供者への問い合わせで保存と商用の利用が認められてから。それまでは公式の range API（`Add-Padding`）を認証の経路から直接呼び、範囲の応答を 24 時間キャッシュする**
2. 確認を待たずに自前でホストする
3. 公式の range API だけを使い続ける
4. 他の公開の一覧（よく使われるパスワードの一覧など）だけを使う

## Decision

1 を採用する。

- 照合は SHA-1 の先頭 5 文字で範囲を引き、残りを手元で比べる。入力のままの値と NFC で正規化した値が違えば、両方を調べる。SHA-1 は保存・ログ・キューに出さない。
- サインアップ・変更・再設定では拒否する。照合できないときは 503（照合を飛ばさない。ADR-0005）。
- ログインでは照合の成功の後に調べ、テナントの設定で `block`（再設定を強いる）・`notify_user`・`notify_admin`・`monitor` を選ぶ。既定は `block`＋`notify_user`。照合できないときは飛ばし、次のログインで調べる。
- 自前のホストでは、Worker が毎月、全範囲を S3 に取り込み、版を切り替える。Auth は S3 から範囲を読み、メモリーに LRU で持つ。
- range API を使う間は、ADR-0005 の縮退の表に「漏えいしたパスワードの照合（外部の API）」を加える必要がある。この変更は ADR-0005 の持ち主のレビューを受ける。
- 2 は、利用規約に反するおそれがある。
- 3 は、認証の経路が外国の外部のサービスに同期で依存し続ける。先頭 5 文字はパスワードを特定しないが、L1 の整理が要る。
- 4 は、漏えいしたパスワードを網羅できず、NIST の「漏えいした」一覧の求めを満たさない。

## Consequences

- 良くなること：
  - 利用条件が明らかな方法で、E8 を先に進められる。
  - 確認が取れれば、外部の依存のない形に移れる。
- 引き受けるコスト：
  - range API を使う間は、外部の障害でサインアップ・変更・再設定が 503 になる。
  - パスワードだけの照合なので、よく使われるパスワードも「漏えい」として当たる。本家（ユーザー名との組）より多く当たる。
  - 取り込みには毎月約 100 万回の API の呼び出しが要る。

## Confirmation

- 性質ベーステスト：任意のパスワードで、外に出る値は 5 文字の 16 進だけ。ログ・キューに 40 文字の SHA-1 の形が出ない。
- 結合テスト：一覧にあるパスワードでのサインアップが拒否される。照合の障害を注入すると、サインアップは 503、ログインは続く。
- レビュー：自前のホストを有効にするフラグの変更は、法務の確認の記録を PR に付ける。
