# ADR-0055: データの保持の既定案を持ち、エンドユーザーの削除は資格情報を先に即時に消し、バックアップの期限を削除の最終の期限にする

## Context

このシステムは、多数のテナントのエンドユーザーの個人データ（メールアドレス、名前、IP、端末）と資格情報を持つ。保持の期間は、次の事情で決まる。

- 個人情報保護法：利用する必要がなくなった個人データは、遅滞なく消すよう努める（努力義務）。本システムが委託先か、自ら取得する事業者かで、誰が決めるかが変わる（[intent.md](../intent.md) の L1）。
- 認証のログの保持の期間は、法務の確認待ち（L5）。本家はプランで 1〜30 日（[Auth0 Pricing](https://auth0.com/pricing)、2026-09-27 に確認）。
- 攻撃の調査（クレデンシャルスタッフィング、鍵の漏えい）には、数か月前までのログが要ることがある。
- エンドユーザーからの削除の請求は、テナントを通して来る（L7）。

他の題材は、論理削除から非同期の物理削除へ流し、バックアップの期限を削除の最終の期限にしている（Slack の ADR-0019、Stripe の ADR-0024）。

## Options

1. **データの種類ごとに保持の既定案を持ち、法務の結論で置き換える。削除は、資格情報を同期で即時に消し、残りを非同期で消す。バックアップの 35 日を削除の最終の期限にする**
2. 法務の結論が出るまで、保持の期間を決めない
3. すべてを物理削除で即時に消す（バックアップを含めて）

## Decision

1 を採用する。期間の一覧は [security.md](../architecture/security.md) の 9 節に置く。

- **法務の結論が出るまで、9 節の期間は既定案とする。** L5 の結論が出るまで、E10 のログの保持とアーカイブの spec を承認しない（intent.md のとおり）。期間はテナントの設定で短くできる形にし、長くする方向は法務の結論の範囲に限る。
- **エンドユーザーの削除**（テナントの管理者、Management API、ユーザー自身の削除の操作）：
  1. 同じトランザクションで、資格情報（パスワードのハッシュ、TOTP の種、WebAuthn の資格情報、リカバリーコード）、セッション、リフレッシュトークンの系列、`user_identities` を物理削除する。以後、そのユーザーではログインもトークンの更新もできない。
  2. ユーザーの行はプロフィールを消した墓石にし、`deleted_at` を付ける。Back-Channel Logout を登録したアプリへ通知する。
  3. 非同期のジョブで、認証のイベントのログの中のそのユーザーの個人データ（メール、名前）を仮名に置き換える。`user_id` と IP は、攻撃の調査のため、ログの保持の期間まで残す（既定案。L1・L5 で確定する）。
  4. 墓石は 30 日後に物理削除する。同じメールアドレスでの再登録は、墓石の間も許す（`user_id` は新しくする）。
- **テナントの削除**：30 日の猶予（復元できる）の後、テナントのすべての行と、署名鍵・データキーの暗号文を物理削除する。監査ログ（テナントの監査）は保管庫に残す。
- **バックアップ**：Aurora の自動バックアップと AWS Backup は 35 日。削除したデータは 35 日でバックアップからも消える。これを削除の最終の期限として、テナントとの契約（DPA）に書く（L7）。長期のスナップショットは取らない（資格情報の暗号文とハッシュを長く残さないため）。
- **リーガルホールド**：法務の指示があれば、テナント単位で削除のジョブを止める。ホールドの設定と解除は、プラットフォームの監査に残す（[ADR-0054](0054-audit-log.md)）。
- 2 は、E10 と E12 の設計が止まる。3 は、誤操作の復元ができず、DR（PITR）とも両立しない。

## Consequences

- 良くなること：
  - 削除の直後から、削除したユーザーの資格情報が使えない。
  - 保持の期間の変更が、設定の値の変更で済む。
- 引き受けるコスト：
  - 仮名化のジョブと、墓石の管理が要る。
  - 35 日は、削除の請求への回答で「バックアップからの消去には最大 35 日かかる」と説明する必要がある。

## Confirmation

- 結合テスト：ユーザーの削除の後、同じ資格情報でのログイン、同じリフレッシュトークンでの更新、同じ WebAuthn の資格情報での認証が、すべて失敗する。
- 性質ベーステスト：任意のユーザーの削除の後、そのユーザーの資格情報の表に行が残らない。
- 日次：保持の期間を過ぎたパーティション・行が残っていないことを数える。
