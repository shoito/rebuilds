# ADR-0029: Meeting Actor が MLS の DS としてエポックごとの順序を決め、AS は会議の間だけ有効な証明書を出す。参加は外部コミット、退出は Actor の Remove の提案で 2 秒以内に鍵を替える

## Context

[ADR-0004](0004-encryption-and-e2ee.md) は、MLS の鍵管理で、サーバー（シグナリング）が DS、本システムが AS の役を務めると決めた。NFR-008 は、参加者の退出から 2 秒以内に鍵を更新し、以後のメディアを退出した人が復号できないことを求める。

調べて分かったこと（いずれも 2026-09-27 に確認）。

- MLS は、DS をほぼ信頼せず、AS を信頼する前提。新しい参加者は、KeyPackage なしに GroupInfo から外部コミットで入れる（[RFC 9420](https://www.rfc-editor.org/rfc/rfc9420.html)）。
- RFC 9420 は、衝突したコミットの順序付けの方式を定めない。コミットの送り手は、自分のコミットが次に適用されると分かれば（調停するサーバーの約束などで）、戻りを待たずに進めてよい。
- OpenMLS 0.9.0 は、外部コミット（`join_by_external_commit`）、`remove_members`、`leave_group_via_self_remove`、`recover_fork_by_readding` を持つ（[docs.rs の MlsGroup](https://docs.rs/openmls/latest/openmls/group/struct.MlsGroup.html)）。
- 本家は、リーダーが鍵を配り、新しい鍵に替えるまで約 2 秒待つ。退出の時の鍵の更新は最大 10 秒遅れうる（[Zoom Cryptography Whitepaper](https://github.com/zoom/zoom-e2e-whitepaper) v4.7 の 7.6.6 節）。
- 会議の状態の順序は Meeting Actor が決め、リースと `epoch` で二重化を防ぐ（[ADR-0005](0005-meeting-state-and-signaling.md)、[ADR-0007](0007-meeting-actor-lease-and-epoch.md)）。

## Options

1. **Actor が DS として、エポックごとに最初のコミットだけを受ける。AS は参加のたびに会議の間だけの X.509 の証明書を出す。参加は外部コミット、退出は Actor が外部の送り手として Remove を提案し、指名した参加者がコミットする**
2. **参加者の追加・削除のコミットを、主催者（または 1 人のリーダー）だけが作る**
3. **参加は、既にいる参加者が Add のコミットと Welcome で入れる（KeyPackage を事前に集める）**
4. **AS の資格情報を、利用者のアカウントの長期の鍵にする**

## Decision

1 を採用する。

- **DS**：
  - Actor は会議ごとに今の MLS のエポックを持つ。`e2ee.commit` の `epoch` が今と同じなら受けて `seq` 付きで配り、エポックを進め、添えられた GroupInfo を保存する。違えば `mls_stale_epoch` で返す。
  - GroupInfo とエポックは、会議の状態のスナップショットに含め、Actor の交代の後も順序を続ける。
  - Actor は MLS のメッセージの中身を解釈しない。エポックの番号、送り手、コミットの送り手の証明書の `participant_id` だけを読む（公開の情報）。
- **AS**：
  - 参加のたびに端末で Ed25519 の鍵の組を作り、API が参加の許可と同時に X.509 の証明書を出す。主体は `participant_id`、`instance_id`、`user_id`（ゲストの印）、`org_id`、表示の名前の SHA-256。有効期限は最大 24 時間。
  - 発行者は KMS で守る中間 CA。根はクライアントに同梱する。
- **作成**：最初に Admitted になった人に、Actor が作成を指示する。`group_id` は開催ごとの 16 バイトの乱数。外部の送り手に Actor の公開鍵を入れる。暗号の組は `0x0001`。
- **参加**：Admitted になった人は、最新の GroupInfo から外部コミットで入る。Actor は、コミットの送り手の証明書が、その接続の参加者と同じときだけ受ける。
- **退出**：Actor が退出を確定したら、Media Node にその人の transport を閉じさせ、外部の送り手として Remove を提案する。在席の人のうち leaf の番号が最も小さい人をコミットの担当に指名し、400ms で応答がなければ次の人に替える。100ms の中の複数の退出は 1 つのコミットにまとめる。
- **目標**：退出の確定から、残る全員が新しい鍵で送り始めるまで p95 1 秒、上限 2 秒。
- **制限**：クライアントは、外部の送り手の提案のうち Remove だけを受ける。
- **回復**：状態を失った人は、外部コミット（自分の古い leaf の Remove を含む）で入り直す。
- **定期の更新**：各参加者は 30 分ごと（±5 分）に自分の leaf を更新する。
- 2 は、主催者が落ちると鍵の更新が止まる。本家のリーダーの形に近く、退出の時の遅れも同じ問題を持つ。
- 3 は、参加のたびに既にいる人の往復が要り、参加の速さ（NFR-002）を損なう。KeyPackage を集める仕組みも要る。
- 4 は、長期の鍵の保管と端末の間の同期（複数の端末）が要り、S1 には重い。ゲストには使えない。

## Consequences

- 良くなること：
  - 鍵の更新は、1 人の参加者の遅れに縛られない（担当の交代）。
  - 参加者の往復なしに入れるので、E2EE の会議でも参加が速い。
  - 順序付けは、既存の Actor の `seq` と `epoch` の上に乗る。
- 引き受けるコスト：
  - AS を信頼する前提になる。サーバーの運営者が偽の証明書で参加者を足す攻撃は、セキュリティのコードと名簿の表示で見つける前提にする（[ADR-0030](0030-security-code-and-e2ee-feature-limits.md)）。
  - 外部コミットは、1 人の参加ごとに 1 エポックを進める。会議の開始の時の大量の参加で、エポックが多く進む。
  - 外部の送り手の鍵を、Actor Host で保管し、入れ替える。

## Confirmation

- 性質ベーステスト：任意の参加・退出・切断・担当者の無応答・Actor の交代の列で、退出が確定した後のエポックのフレームを、退出した人の状態では復号できない（PROP-E2EE-001）。全員のエポックと `epoch_authenticator` が一致する（PROP-E2EE-002）。Actor が受けるコミットはエポックごとに 1 つ（PROP-E2EE-003）。外部の送り手の Add を拒む（PROP-E2EE-004）。
- 計測：100 人の会議で、退出の確定から全員が新しい KID で送り始めるまで p95 1 秒、最大 2 秒（NFR-008）。
- 相互運用の試験：別の MLS の実装で作ったグループに、OpenMLS の参加者が外部コミットで入り、同じ `epoch_authenticator` になる。
