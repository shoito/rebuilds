# ADR-0006: 会議の ID は秘密にしない 11 桁の乱数にし、URL のフラグメントに 128 ビットの参加の鍵を置く

## Context

会議には、人が読み上げ・入力できる ID と、クリックで入れる URL が要る（[intent.md](../intent.md) の「すぐに集まれる」）。一方で、URL や ID が漏れると、知らない人が入り込む（intent.md の Problem）。

- 本家は、すぐの会議・予定の会議・繰り返しの会議に 11 桁、個人の会議の ID に 10 桁の数字を使う（[Frequently asked questions about meeting and webinar IDs](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0065196)、2026-09-27 に確認）。
- 本家は、設定でパスコードを暗号化して招待のリンクに入れ、入力を省ける（[Embedding meeting passcode in invite link](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0065979)、2026-09-27 に確認）。リンクのどの部分に入るかは書かれていない。
- 11 桁の数字の空間は 9×10^10 で、推測への強さは約 36 ビットしかない。S3 で予定を含めて有効な ID が 1,000 万あると、1 回の推測で当たる確率は約 1/9,000 になる。ID だけで守ることはできない。
- URL のクエリ文字列は、CDN・ロードバランサーのアクセスログ、ブラウザの履歴、`Referer` に残りやすい。フラグメント（`#` の後）は HTTP の要求に含まれない（[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986#section-3.5)、2026-09-27 に確認）。

## Options

1. **ID は秘密にしない 11 桁の乱数。URL のフラグメントに 128 ビットの参加の鍵を置く**
2. **ID を長い英数字（例：128 ビット）にし、ID そのものを秘密にする**
3. **ID は 11 桁。URL のクエリにパスコード（か、その派生値）を入れる（本家に近い形）**

## Decision

1 を採用する。詳細は [signaling-and-meetings.md](../architecture/signaling-and-meetings.md) の 4.1 節。

- 会議の番号は 11 桁の 10 進の数字（先頭は 1〜9）。CSPRNG から一様に選び、連番にしない。最後の開催から 2 年は再び使わない。
- 番号は秘密ではない。会議に入るには、待合室の許可か、パスコード（または参加の鍵）が要る（meeting-security.md で強制する）。
- 参加の鍵は、会議ごとの 128 ビットの乱数（base64url の 22 文字）。Aurora には SHA-256 だけを置く。
- URL は `https://<brand>.<domain>/j/<meeting-id>#k=<join-key>`。Web クライアントがフラグメントを読み、参加の要求の本文で送る。
- 参加の鍵は、パスコードの入力を省くだけにする。待合室は省かない。主催者は鍵を作り直せる。
- 2 を採らない理由：電話からの参加（MVP の後）と口頭での案内で、人が入力できない。
- 3 を採らない理由：パスコードの派生値がアクセスログと `Referer` に残る。パスコードを替えると URL も替わり、2 つの役割が結び付く。

## Consequences

- 良くなること：
  - 人が読める ID と、推測できない URL を両立できる。
  - 参加の鍵がサーバーのアクセスログに残らない。
- 引き受けるコスト：
  - フラグメントは、URL を貼り付けたチャットやメールには残る。鍵が漏れたときの防御は、待合室と主催者の操作に頼る。
  - JavaScript が動かない環境（一部のメールのプレビューなど）では、鍵が使われずパスコードを求める。
  - ID の総当たりへの流量の制限は、別に要る（meeting-security.md）。

## Confirmation

- 結合テスト：鍵のある URL で、パスコードを入れずに入れる。待合室が有効なら、待合室に入る。
- 結合テスト：ALB と CloudFront のアクセスログに、参加の鍵が現れない（試験の鍵の文字列で検索する）。
- 性質ベーステスト：作った会議の番号は 11 桁で、先頭が 0 ではなく、2 年以内の番号と重ならない。
