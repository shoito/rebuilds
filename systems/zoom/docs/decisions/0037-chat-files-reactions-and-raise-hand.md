# ADR-0037: チャットのファイルは検査を通したものだけを別のドメインから配り、リアクションは一時的なイベント、挙手は参加者の状態にする

## Context

会議の中では、ファイルの送信、絵文字のリアクション、挙手を使う（[intent.md](../intent.md) の MVP）。

- ファイルは、マルウェアや、会議の画面のオリジンで中身を描かせる攻撃（HTML・SVG のスクリプト）の経路になる。
- 本家は会議の中のファイルの送信を持ち、組織の設定で許すかを選ぶ（[Enabling file transfer in meetings](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0058822)、2026-09-27 に確認）。大きさの上限の一次の値は確かめていない（未検証）。
- 本家の絵文字のリアクションは 10 秒で消え、挙手と反応の表示は下げるまで残る（大学の IT の解説。一次は未検証）。
- シグナリングには、状態の差分（`evt`、`seq` あり）と、落としてよい一時的なイベント（`eph`）がある（[ADR-0008](0008-signaling-protocol.md)）。挙手は `self.update` の項目として既にある（[signaling-and-meetings.md](../architecture/signaling-and-meetings.md) の 6.2 節）。

## Options

ファイル：

1. **S3 に直接上げ、マルウェアの検査を通したものだけを、会議の画面と別のドメインからダウンロードとして配る。上限 100 MB**
2. **会議の画面の中で中身（画像など）を表示する**
3. **ファイルの送信を作らない**

リアクションと挙手：

4. **リアクションは `eph`（残さない）、挙手と反応の表示は参加者の状態（`seq` あり）**
5. **どちらも状態にする**

## Decision

1 と 4 を採用する。詳細は [chat-and-reactions.md](../architecture/chat-and-reactions.md) の 4〜6 節。

- **ファイル**：
  - 署名付きの PUT（10 分）で S3 に直接上げる。S3 のマルウェアの検査（GuardDuty の S3 のマルウェアの保護を想定。未検証）が `clean` を返したものだけを、宛先に配る。
  - 別のドメイン（`<brand>files.<domain>`）から、`Content-Disposition: attachment` と `nosniff` で配る。会議の画面で中身を描かない。
  - 上限は 1 ファイル 100 MB、1 人・1 会議 20 ファイル・500 MB。禁止する拡張子は組織の設定。
  - 保持はチャットと同じ（[ADR-0036](0036-in-meeting-chat-ordering-and-retention.md)）。
- **リアクション**：`eph` で配り、残さない。組織が許した絵文字の集合だけを受ける（既定 6 種）。1 人毎秒 1。100 人を超える会議では 500ms ごとに数をまとめる。
- **挙手と反応の表示**：参加者の状態（`hand_raised`、`hand_raised_seq`、`feedback`）に入れ、`seq` の差分で配る。主催者は挙げた順に見られ、下げられる。
- **E2EE**：ファイルは使えない。リアクションは MLS で暗号化する。挙手と反応の表示は平文の状態とし、サーバーに見えることを示す。
- 2 を採らない理由：画像の復号の脆弱性や、SVG・HTML のスクリプトが、会議の画面のオリジンで動く危険がある。
- 3 を採らない理由：資料の受け渡しは会議でよく使う。
- 5 を採らない理由：リアクションは数秒で意味を失う。状態にすると、`seq` の差分とスナップショットの量が増え、大きな会議で Actor の負荷になる。

## Consequences

- 良くなること：
  - 検査していないファイルが参加者に届かない。
  - 会議の画面のオリジンで、他人が上げた中身が動かない。
  - リアクションが状態の差分を増やさない。挙手の順は持ち主が替わっても残る。
- 引き受けるコスト：
  - 検査の間、ファイルが数秒〜数十秒届かない。
  - 本家より小さい上限（100 MB）になる。
  - リアクションは落ちることがある（`eph`）。
  - E2EE の会議では、挙手と反応の表示がサーバーに見える。

## Confirmation

- 結合試験：EICAR の試験のファイルが配られず、送り手に知らせが届く。
- 結合試験：HTML・SVG のファイルが、ダウンロードとして別のドメインから配られ、会議の画面のオリジンで描かれない。
- 負荷試験：100 人の会議で全員が毎秒 1 回リアクションしても、Actor の `cmd` → `ack` の p95 が他の操作と同じ範囲に収まる。
- 性質ベーステスト：挙手の順が、持ち主の交代の後も保たれる。
