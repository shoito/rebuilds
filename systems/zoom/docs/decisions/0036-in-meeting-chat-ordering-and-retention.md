# ADR-0036: 会議の中のチャットは状態の seq と別の番号で順序を決めて eph で配り、会議の後は既定で消す

## Context

会議の中のチャット（全員へのメッセージと個別のメッセージ）は MVP に入る（[intent.md](../intent.md)）。

- 会議の状態は Meeting Actor が `(epoch, seq)` の差分で全員に配り、クライアントは `seq` の飛びでスナップショットを取り直す（[ADR-0005](0005-meeting-state-and-signaling.md)、[ADR-0008](0008-signaling-protocol.md)）。個別のメッセージを同じ `seq` で配ると、宛先でない人には飛びに見える。
- チャットはスナップショットに入れない（[signaling-and-meetings.md](../architecture/signaling-and-meetings.md) の 10.1 節）。ADR-0005 は「チャットの本文を残すかは、chat-and-reactions.md で決める」としている。
- 会議の内容は通信の秘密に当たる（intent.md の L2）。残すほど、漏れたときの影響と、開示・削除の請求の扱い（L6・L8）が重くなる。
- E2EE の会議では、チャットを MLS のアプリケーションのメッセージとして暗号化する（[ADR-0004](0004-encryption-and-e2ee.md)）。

## Options

1. **Actor が別の番号（`chat_seq`、チャンネルごとの `ch_seq`）で順序を決め、`eph` で配り、飛びを `chat.fetch` で埋める。会議の間は Valkey の Stream、会議の後は既定で消す**
2. **状態の差分（`evt`、`seq`）で配る。個別のメッセージは、宛先でない人にも「本文なし」の差分を送る**
3. **Aurora を正本にして、すべてのメッセージを書いてから配る（Slack と同じ形）**

## Decision

1 を採用する。詳細は [chat-and-reactions.md](../architecture/chat-and-reactions.md) の 3 節。

- **順序**：Actor が会議の開催ごとの `chat_seq` と、チャンネル（全員・2 人の組）ごとの `ch_seq` を付ける。`client_msg_id` で重複を防ぐ。
- **配信**：`eph` の `chat.message` を宛先だけに送る。クライアントは `ch_seq` の飛びを `chat.fetch` で埋める。再接続の後も同じ。
- **会議の間**：Valkey の Stream に、会議ごとのデータの鍵で暗号化して積む。持ち主が替わったら Stream から番号を戻す。Valkey が失われたら履歴は失うが、送受信は続ける。
- **会議の後**：既定は、終了から 24 時間で消す。録画があれば、録画の区間の全員へのメッセージを録画のファイルに入れる。組織の設定 `save_chat` が真なら、全員へのメッセージを Aurora に暗号化して残す（既定 90 日）。個別のメッセージは会議の後に残さない。
- **E2EE**：暗号文を e2ee.md の `e2ee.app` で送り、同じ番号の仕組みで順序付けて配る。個別のメッセージは使えなくする（MLS のアプリケーションのメッセージはグループの全員が復号できるため）。会議の後は、設定にかかわらず残さない。
- 2 を採らない理由：宛先でない人にも、誰が誰に送ったかのメタデータを配ることになる。状態の差分の量が増え、スナップショットの対象の議論が混ざる。
- 3 を採らない理由：会議の中のチャットのほとんどは会議の後に要らない。すべてを DB に書くと、残さなくてよい通信の内容を残し、書き込みの量と遅れも増える。会議の間の Actor の順序付けで、競合の結果は 1 つに決まる。

## Consequences

- 良くなること：
  - 個別のメッセージが、宛先の 2 人以外に何も届かない。
  - 会議の後に残る通信の内容が、既定で最小になる。
  - 状態の差分とスナップショットが、チャットの量に影響されない。
- 引き受けるコスト：
  - Valkey が失われると、会議の間の履歴を失う（クライアントの表示は残る）。
  - クライアントに、チャンネルごとの番号の管理と `chat.fetch` の実装が要る。
  - シグナリングのスキーマに `chat.*` を足す必要がある（signaling-and-meetings.md の 6.2 節の表への追加）。
  - 組織が個別のメッセージを記録として残したい要求には、今は応えられない（L8 の後に再検討）。

## Confirmation

- 性質ベーステスト：任意の送信・切断・再送・持ち主の交代の後、各クライアントのチャンネルごとの列が Actor の順と一致し、重複しない（PROP-CHAT-001、003）。個別のメッセージが第三者に届かない（PROP-CHAT-002）。
- 監査：`save_chat` が偽で録画のない会議の本文とファイルが、終了から 24 時間後に残っていない（PROP-CHAT-004、毎日の監査）。
- 結合試験：E2EE の会議で、Valkey の Stream に暗号文だけがある。
