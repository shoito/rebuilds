# ADR-0033: 参加の要求を IP・会議・パスコードの誤りの軸で制限し、応答と時間をそろえ、番号を多く試す IP には CAPTCHA を求める

## Context

会議の番号は 11 桁で、推測への強さは約 36 ビットしかない。S3 の見込みで、1 回の推測で有効な番号に当たる確率は約 1/9,000 である（[ADR-0006](0006-meeting-id-and-join-url.md)）。PMI（10 桁、[ADR-0034](0034-scheduled-recurring-meetings-and-pmi.md)）は約 1/4,500 になる。

番号に当たっても、パスコードか待合室が要る（[ADR-0031](0031-waiting-room-and-passcode-rules.md)）。それでも、次の攻撃が残る。

- 当たった会議の待合室を、荒らしの参加の要求で埋める。
- 6 桁の数字のパスコードを総当たりする（空間 10^6）。
- 番号の存在と会議の題名を集める。

API は、存在しない会議とパスコードの誤りを同じ応答で返すと決めている（[signaling-and-meetings.md](../architecture/signaling-and-meetings.md) の 4.3 節）。ただし、待合室だけの会議（パスコードなし）は、参加の要求でトークンが返るので存在が分かる。

AWS WAF は、レートに基づく規則と、CAPTCHA・Challenge のアクションを持つ（AWS WAF の文書。細かい振る舞いは未検証）。

## Options

1. **API で、IP・会議・パスコードの誤りの 3 つの軸をトークンバケットで制限する。応答と時間をそろえる。番号を多く試す IP には WAF の CAPTCHA を求める**
2. **WAF のレートに基づく規則だけで制限する**
3. **会議の番号を長くする（ADR-0006 を改める）**

## Decision

1 を採用する。詳細は [meeting-security.md](../architecture/meeting-security.md) の 8 節。

- **軸と上限**：
  - IP（/32・/64）の参加の要求：毎分 30、瞬間 10。
  - IP の試した番号の種類：10 分に 20（HyperLogLog で数える）。超えたら CAPTCHA。
  - IP の存在しない会議：1 時間に 50 回。超えたら CAPTCHA。
  - 会議 × IP のパスコードの誤り：10 分に 10 回で、15 分止める。
  - 会議のパスコードの誤りの合計：1 時間に 50 回で、その会議の参加の鍵のない参加を 1 時間止め、主催者に知らせる。
- **数える場所**：Valkey。止まったら、各タスクの手元の数で、上限をタスクの数で割って続ける。参加は止めない。
- **応答をそろえる**：存在しない番号でもダミーの HMAC を比べ、応答までの時間を最小 150ms にそろえる。参加の Web の画面は番号によらず同じ HTML にし、題名はパスコードを通ったとき（または主催者が待合室で見せる設定のとき）だけ出す。
- **CAPTCHA**：API が `403 challenge_required` を返し、クライアントが WAF の CAPTCHA の組み込みで解かせる。解いた印を見て、制限を 1 時間ゆるめる（SPA での組み込みは E3 で試作する）。
- 2 を採らない理由：WAF は「会議ごと」「パスコードの誤り」のような、アプリの意味の軸で数えられない。IP のレートだけでは、多数の IP からの 1 つの会議への総当たりを止められない。
- 3 を採らない理由：人が読み上げて入力できる ID という要求（ADR-0006）を失う。電話からの参加でも困る。推測への対策は、ID の長さではなく、パスコード・待合室と流量の制限で行う。

## Consequences

- 良くなること：
  - 1 つの会議のパスコードを当てる確率を、1 時間あたり 1/20,000 以下に抑えられる（50 回 ÷ 10^6）。
  - 多数の IP からの総当たりも、会議の軸で止まる。
  - 番号の存在と題名が漏れにくい。
- 引き受けるコスト：
  - 総当たりを受けた会議では、参加の鍵のない正当な参加者も 1 時間入れない。主催者への通知と、参加の鍵のある URL の案内で補う。
  - 同じ IP を多くの人が共有する回線（大きな会社、携帯）で、正当な人が CAPTCHA を求められうる。
  - 待合室だけの会議は、存在が分かることを避けられない（既定を両方にして減らす）。
  - 応答の時間をそろえるため、参加の API の最小の遅れが 150ms になる（NFR-002 の予算の 250ms の中）。

## Confirmation

- 攻撃の試験：1 つの IP から 1,000 個の番号を試すと、21 個目から CAPTCHA、解かなければ `429`。
- 攻撃の試験：100 個の IP から 1 つの会議のパスコードを総当たりすると、1 時間 50 回で鍵のない参加が止まり、主催者に通知が届く。
- 計測の試験：存在しない番号と誤ったパスコードで、本文が同じで、応答の時間の p99 の差が 10ms 以内。
- 障害の注入：Valkey を止めても、参加が続き、制限が手元の数で効く。
