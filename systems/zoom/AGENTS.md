# AGENTS.md — Zoom

Zoom の再構築の設計。リポジトリ共通のルールはルートの [AGENTS.md](../../AGENTS.md) にある。このリポジトリには設計だけを置き、実装は Zoom の開発リポジトリで行う（[リポジトリ共通の ADR-0005](../../docs/decisions/0005-design-record-repository.md)）。

## 最初に読むもの

- [docs/intent.md](docs/intent.md) — 何を、なぜ作るか
- [docs/architecture/](docs/architecture/README.md) — 全体像、規模の段階、非機能要件、領域ごとの設計
- [docs/decisions/](docs/decisions/README.md) — ADR。特に 0002（メディアの経路）、0004（暗号化と E2EE）、0005（会議の状態）

## この題材に固有の規則（開発リポジトリで守る）

- **メディアに触れる変更は、ネットワークの劣化の試験を通す。** Media Node、帯域の推定、層の選択、符号器の設定、ジッタバッファ、ICE・TURN、Web クライアントのメディアの経路に触れる PR は、`tc netem` などで損失・揺らぎ・帯域の制限・遅れを加えた試験を回す。少なくとも次の条件を通す。条件と合否の基準の詳細は quality.md（まだない）で決める。
  - 損失 5% と 20%（ランダム、バースト）
  - 揺らぎ 30ms と 100ms
  - 下りの帯域 3 Mbps → 500 kbps → 150 kbps への低下と回復
  - RTT 200ms（海外からの参加を模す）
- **メディアの品質を数値で示す。** 上の試験の結果として、遅れ（glass-to-glass、mouth-to-ear）、音声の客観評価（MOS の推定）、映像のフリーズの回数と長さ、受けた解像度とフレームの数、帯域の変化への追従の時間を、PR に載せる。NFR-001〜003・NFR-009 を下回ったら、マージしない。「手元で聞いて問題なかった」は根拠にしない。
- **試験の期待値を緩めて通さない。** 品質の閾値、試験の回線の条件、試験の時間を変えるときは、変更の `quality.md` か `spec.md` の承認（QA）を先に取る。
- **制御の障害でメディアを止めない。** Meeting Actor、API、Valkey、Aurora のどれが止まっても、流れているメディアは止まらない形を保つ。Media Node が制御の側へ同期で問い合わせる処理を足さない（ADR-0005）。
- **会議の状態は Meeting Actor だけが変える。** 会議の中の状態を、API や Media Node から直接書き換えない。古い `epoch` の指示を受け付けるコードを書かない（ADR-0005）。
- **Media Node の網の設定を崩さない。** メディアのポートの前にロードバランサーを置かない。接続の追跡を有効にする規則に変えない。ENA の `*_allowance_exceeded` の指標を監視から外さない（ADR-0001）。
- **E2EE の鍵をサーバーに渡さない。** E2EE の会議で、MLS の秘密、SFrame の鍵、復号したメディアを、サーバー・ログ・トレース・メトリクス・クラッシュの報告に出さない。E2EE の会議で、録画・字幕・電話からの参加を動かす経路を作らない（ADR-0004）。
- **会議の内容をログに出さない。** 音声・映像のフレーム、チャットの本文、字幕の文字、パスコード、参加のトークンを、ログ・エラーの本文・トレースの属性・メトリクスのラベルに書かない。品質の診断に使うのは、RTCP と `getStats` の数値だけにする（通信の秘密。intent.md の L2）。
- **待合室もパスコードもない会議を作れる経路を足さない。** API、管理の設定、カレンダーの連携のすべてで検査する。
- **本家の名前を識別子に使わない。** ドメイン、URL、ヘッダー、SDK・パッケージの名前、API の名前空間、RTP のヘッダー拡張の URI は `<Brand>`・`<brand>` で書く（[リポジトリ共通の ADR-0006](../../docs/decisions/0006-brand-neutral-identifiers.md)）。
- **試験に実在の人の声や顔を使わない。** 試験の音声・映像は、利用の条件が明らかな公開のデータセットか、合成したものだけを使う。

## このリポジトリでの規則

- ADR を追加・更新したら、`docs/decisions/README.md` の一覧を生成し直す。
- 領域の文書で ADR を起票するときは、[architecture/README.md](docs/architecture/README.md) の 7 節で領域に割り当てた番号の範囲の中で採番する。
- 本家の振る舞い・数値を書くときは、出典と確認日を付ける。確かめられないものは「未検証」と書く。
