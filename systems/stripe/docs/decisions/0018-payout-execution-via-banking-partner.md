# ADR-0018: 入金は作成の時点で残高から引き、提携銀行の API（予備に全銀フォーマットのファイル）で振り込む

詳細は [payouts-and-reconciliation.md](../architecture/payouts-and-reconciliation.md) の 2〜4 節。

## Context

加盟店への入金（Payout）は、利用可能な残高を加盟店の銀行口座へ振り込む。本家 Stripe の日本では、自動（週次・月次）と手動の入金があり、日次はない。自動入金だけが、含まれた取引を特定できる（[Payouts](https://docs.stripe.com/payouts)、[Payout reconciliation](https://docs.stripe.com/payouts/reconciliation)）。

日本で振込を実行する手段は、次のどれかになる。

- 銀行の法人向け API（総合振込依頼、結果照会、組戻しの状態。例：[GMO あおぞらネット銀行の API 一覧](https://gmo-aozora.com/business/api-cooperation/apilineup.html)）
- 全銀フォーマットの総合振込のファイル（120 バイト固定長）
- 全銀システムへの直接の参加（2022 年 10 月から資金移動業者も参加できる）

資金決済法の上の位置づけは法務の確認待ちで、直接の参加の可否もそれに依る（[intent.md](../intent.md)）。

## Options

### 残高から引く時点

1. **入金の作成の時点**
2. 銀行への依頼の時点
3. 着金を確かめた時点

### 振込の手段

A. **提携銀行の API を主にし、全銀フォーマットのファイルを予備にする**
B. 全銀フォーマットのファイルだけ
C. 全銀システムに直接参加する

## Decision

1 と A を採用する。

- **入金の作成と同じトランザクションで、`merchant_available` から `payouts_in_transit` へ移す。** 自動入金は、含める BT に `payout_id` を付けて確定し、`reconciliation_status` を `completed` にする。手動入金は `not_applicable`（本家と同じ）。
- **状態は本家に揃える**：`pending` → `in_transit` → `paid`、`failed`、`canceled`。`paid` の後の組戻し・資金返却で `failed` にする。失敗の金額は `payout_failure` の BT で残高に戻す。
- **銀行アダプタ** の共通の口（依頼、結果照会、明細の取得）の後ろに、銀行ごとの API の実装と、全銀フォーマットのファイルの実装を置く。
- **依頼は冪等にする。** 依頼の前に `bank_request_ref` を採番して保存し、再送では同じ番号を使う。結果が不明なときは再依頼せず、結果照会で確かめる。分からなければ人が確かめる。二重の振込を防ぐことを、遅れよりも優先する。
- **即時入金は範囲外。**
- 2・3 を採らない理由：依頼・着金までの間に、同じ残高で別の入金や返金ができてしまう。
- B を採らない理由：結果の把握がファイルの往復になり、失敗・組戻しの検知が遅れる。人の手の操作（アップロード）が入りやすい。
- C を採らない理由：資金決済法の上の位置づけが決まっておらず、免許・開発・運用の負担が大きい。位置づけが決まり、件数が増えたら見直す。

## Consequences

- 良くなること：
  - 入金中の残高を二重に使えない。
  - 自動入金の照合が作成の時点で確定し、本家の入金照合レポートと同じものを作れる。
  - 銀行を増やす・替えるときに、アダプタを足すだけで済む。
- 引き受けるコスト：
  - 提携銀行の API の仕様（件数の上限、当日扱いの締め、依頼の識別子、名義照会）に依存する。銀行を選ぶ時点で確かめる必要がある（未検証）。
  - 払出口座の資金の手当て（精算の着金口座からの移動）を、人が行う。締めの前の残高の確認が要る。
  - 組戻しは数日後に届くため、`paid` の入金が後から `failed` になる。加盟店への説明（Event と画面）が要る。

## Confirmation

- 性質ベーステスト：任意の入金の作成・取り消し・失敗・返却の列で、`merchant_available`・`payouts_in_transit` の残高が仕訳と一致し、同じ残高が 2 回入金されない。
- 障害注入テスト：模擬の銀行で、依頼のタイムアウト・受付の後の不能・完了の後の組戻しを起こし、二重の振込が起きず、残高が正しく戻る。
- 結合テスト：自動入金の `GET /v1/balance_transactions?payout=` の合計が、入金の金額と一致する。
- 運用：`in_transit` のまま予定の着金日を 2 営業日過ぎた入金をアラートにする（runbooks）。
