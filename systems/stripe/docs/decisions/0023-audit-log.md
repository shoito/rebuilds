# ADR-0023: 監査ログは Slack の方式を引き継ぎ、CDE の記録は別の系統で log-archive へ直接送る

## Context

決済の基盤では、次の目的で「誰が、いつ、何をしたか」の記録が要る。

- 加盟店が、自分のアカウントで起きた重要な操作（ログイン、API キー、入金先の口座の変更、返金）を確かめる。本家は「セキュリティの履歴」でこれを見せる（[Stripe のセキュリティ](https://docs.stripe.com/security)）。
- 運用者が、不正やインシデントの影響の範囲を特定する。
- PCI DSS の監査の証跡。PCI は監査ログを 12 か月以上保持し、直近 3 か月はすぐ分析できることを求める（要件 10.5.1）。
- 審査・リザーブ・拒否など、加盟店に不利益な判断の根拠を残す。

Slack では、操作と同じトランザクションで `audit_events` に追記し、別アカウントの Object Lock のバケットへハッシュの連鎖で送る方式を決めた（Slack の [ADR-0018](../../../slack/docs/decisions/0018-audit-log.md)）。

CDE には、本体の DB がない。CDE の記録（復号、JIT のセッション、鍵の操作）は、本体の DB を経由すると本体が CDE の記録に触れることになり、境界が崩れる。

## Options

1. **本体は Slack の方式を引き継ぐ。CDE は、CDE から log-archive へ直接送る別の系統にする**
2. 本体も CDE も、ログ（CloudWatch Logs）にだけ出す
3. CDE の記録も本体の `audit_events` に送る

## Decision

1 を採用する。

### 本体（Slack の ADR-0018 と同じ方式）

- 操作と同じトランザクションで、テナントテーブル `audit_events`（`account_id`、RLS）に追記する。`app` ロールには `INSERT` と `SELECT` だけを与える。
- テナントの外の判断（審査、リザーブ、拒否、プラットフォームのルール、break-glass）は `platform_audit_events` に書く。
- エクスポーターが、加盟店ごとのハッシュの連鎖で log-archive アカウントの S3（Object Lock のコンプライアンスモード）へ送り、1 時間ごとのダイジェストに KMS の非対称キーで署名する。
- 記録する操作の一覧は [security.md](../architecture/security.md) の 6 節。秘密キーの値、カード番号、本人確認の書類の中身は記録しない。
- **加盟店は、ダッシュボードと API で自分の記録を見られる。プランによらない**（Slack では Enterprise だけにしたが、決済ではお金と口座に関わるため全員に出す）。

### CDE

- 記録するもの：復号（`card_ref`、目的、決済の試行の ID、呼び出し元のロール）、カードの消去、JIT の申請・承認・セッションの入出力、鍵の操作（CloudTrail）。
- CDE のサービスが Kinesis Data Firehose へ送り、log-archive の Object Lock のバケットへ直接書く。本体は読めない。
- 直近 3 か月は CloudWatch Logs（CDE のアカウント）ですぐ検索でき、13 か月まで S3 に残す。

### 保持

| 場所 | 期間 |
| --- | --- |
| 本体の DB の `audit_events` | 1 年 |
| 本体の監査のアーカイブ（S3） | 7 年（財務の記録の保存期間に合わせる。法務の確認。ADR-0024） |
| CDE の監査とログ | 13 か月（PCI の 12 か月に余裕を持たせる） |
| CloudTrail | 13 か月以上（[observability.md](../architecture/observability.md) に従う） |

- 2 は、記録の欠落を防げない（Slack の ADR-0018 の理由と同じ）。
- 3 は、CDE の記録が本体の DB を通り、本体の侵害で CDE の記録を消せる経路ができる。

## Consequences

- 良くなること：
  - 本体の操作は、成功すれば必ず記録が残る。
  - CDE の記録は、本体の侵害や本体の運用者の操作で消せない。
  - 加盟店が自分で不審な操作に気づける。
- 引き受けるコスト：
  - 記録の系統が 2 つになり、調査では突き合わせが要る（決済の試行の ID で結ぶ）。
  - 復号の記録は量が多い（決済ごとに 1 件以上）。13 か月を超えて残さない。
  - アーカイブの 7 年は Object Lock で短くできない。期間の法務の確認を、本番の監査用バケットを作る前に済ませる。

## Confirmation

- 本体：Slack の ADR-0018 の Confirmation と同じ（操作ごとの記録の有無の表駆動テスト、`UPDATE`・`DELETE` の拒否、Object Lock と別アカウントの IaC の検査、ハッシュの連鎖と署名の毎日の検証）。
- CDE：Connector Gateway の復号ごとに、監査の系統へ 1 件の記録があることを結合テストで確かめる。
- 本体のロールから CDE の監査のバケットを読めないことを、IAM のポリシーの静的検査で確かめる。
- 記録にカード番号の形が含まれないことを、PAN の形の走査の対象に入れる。
