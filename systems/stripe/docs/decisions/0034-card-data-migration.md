# ADR-0034: 他の決済事業者とのカード番号の移行（取り込みと書き出し）

## Context

加盟店が決済事業者を乗り換えるとき、保存したカード（継続課金・ワンクリックの決済に使うもの）を移せないと、顧客全員にカードを入れ直してもらうことになる。逆に、このシステムから出ていく加盟店がカードを持ち出せないと、加盟店を閉じ込めることになる。移行は intent の MVP にも Non-goals にも入っておらず、設計もない。

本家は、他の事業者からのカード番号の取り込みと、PCI DSS に準拠した受け手への書き出しを、手引きと申請の手続きで提供している（[Data migrations](https://docs.stripe.com/get-started/data-migrations)。手続きと形式の細部は着手時に確かめる）。

移行は、既存の決定と次の点でぶつかる。

- カード番号は CDE に閉じ込め、本体は `pm_` だけを扱う。CDE から本体を呼ばない（[ADR-0005](0005-pci-scope-segmentation.md)、[ADR-0029](0029-multi-account-and-cde-layout.md)）。
- 人は PAN を平文で見ない。AI エージェントは CDE に経路を持たない（[ADR-0020](0020-cde-access-model.md)）。
- CDE の外への送信は、許可リストの宛先だけ（[card-vault.md](../architecture/card-vault.md) の 2 節）。
- CVC は、オーソリの後に保存できない（PCI DSS 要件 3.3.1.2）。移行でも受け取らない。

## Options

1. **移行を提供しない**（Non-goal にする）
2. **取り込みと書き出しの両方を、CDE の中のファイルの受け渡しで提供する。MVP の後（E10 の後）に、運用者が仲介する手続きとして始める**
3. 書き出しだけを提供する（閉じ込めを避ける最低限）。取り込みは需要を見て後で足す

範囲と時期は PM が決める（[intent.md](../intent.md) の Open questions）。法令の扱いは法務の確認待ち（L9）。

## Decision

2 を採用する。方式は次のとおりとする。

> 2026-10-25 の注記：PM が範囲を決めた。取り込みと書き出しの両方を、MVP の後（E10 の後）に運用者が仲介する手続きとして提供する。法令の扱いは法務の確認待ち（L9）のままで、結論が出るまで `card-data-migration` の spec は承認しない。

- **受け渡しは cde-live の SFTP（AWS Transfer Family）だけで行う。** ファイルは受け手・送り手の公開鍵で PGP の暗号化をする。相手の SSH 鍵と PGP の鍵は、手続きごとに登録し、手続きが済んだら外す。CDE の外向きの許可リストは変えず、相手が取りに来る・置きに来る形にする。
- **取り込み**：
  - 前の事業者がファイルを置く。CDE の取り込みの Worker が復号し、行ごとに形式（桁数、Luhn、有効期限）を検証し、[card-vault.md](../architecture/card-vault.md) の 3.1 節の手順 3〜5 と同じく暗号化・指紋・Vault DB への保存を行う。
  - 行ごとに、`card_input` と同じ使い捨ての値を作り、取り込みの結果として SQS で本体へ送る（PAN も `card_ref` も送らない）。本体が `pm_`（と必要なら Customer）を採番し、3.1 節の手順 8 と同じ紐づけを行う。紐づけの済まない行は、1 時間ではなく取り込みの期限（7 日）で消す。
  - 加盟店には、前の事業者の ID と `pm_` の対応表を、ダッシュボードで渡す（PAN を含まない）。
  - 取り込んだカードには、元の事業者のネットワーク取引 ID（MIT の根拠）が含まれる場合だけ、加盟店が起こす決済（MIT）に使えるようにする。含まれない場合の扱いは、最初のコネクタで確かめる。
- **書き出し**：
  - 加盟店がダッシュボードで依頼し、受け手の事業者の AOC（PCI DSS の準拠の証明）を添える。運用者 2 人（作成者と別）が受け手の準拠を確かめて承認する。
  - CDE の書き出しの Worker が、対象の `pm_` のカードを受け手の PGP の鍵で暗号化してファイルにし、SFTP に置く。7 日で消す。
- **人と AI エージェント**：取り込みと書き出しの処理は自動で行い、人は PAN の平文に触れない。承認は運用者の画面で、件数と受け手だけを見て行う。AI エージェントは手続きのどこにも経路を持たない。
- **記録**：依頼・承認・ファイルの受け取りと受け渡し・件数を、CDE の監査と加盟店の監査ログの両方に残す（[ADR-0023](0023-audit-log.md)）。
- 1 は、乗り換えの障壁と閉じ込めが残る。3 は閉じ込めを避けられるが、乗り換えてくる加盟店を取れない。

## Consequences

- 良くなること：
  - 加盟店が、顧客にカードを入れ直させずに乗り換えられる。出ていくときも同じ。
  - カード番号は CDE の外に出ず、人も見ない。
- 引き受けるコスト：
  - CDE に SFTP の入口と、ファイルを扱う Worker が増える。PCI DSS の範囲と分割の検証の対象が増える。
  - 受け手の準拠の確認と承認は、運用者の手作業になる。
  - 取り込みの形式は相手ごとに違いうる。最初は 1 つの形式（CSV と項目の定義）に決め、相手にそれで出してもらう。

## Confirmation

- 結合テスト（cde-nonprod、ブランドのテスト用の番号だけ）：取り込みで、本体の DB・ログ・SQS のメッセージに PAN の形と `card_ref` が出ない（ADR-0005 の走査と同じ）。
- 結合テスト：CVC の列を含むファイルは、行ごとではなくファイルごと拒否する。
- 承認の検査：書き出しの承認者が 2 人とも依頼者と別で、承認の記録がないと Worker が動かない。
- IaC の検査：SFTP の入口が cde-live の外から本体のロールで操作できない。
