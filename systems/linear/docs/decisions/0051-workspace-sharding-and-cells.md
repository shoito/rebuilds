# ADR-0051: S2 はワークスペースを単位に Aurora のクラスタへ分け、ディレクトリとアカウントを小さな共通のクラスタに置く。移動は `sync_id` を保ち `sync_epoch` を上げない。S3 はワークスペースをセルに固定し、セルごとに主のリージョンを持つ

## Context

README の 2 節は、S2（ワークスペース 5 万、書き込み 15,000 変更/秒）で複数の Aurora のクラスタへ分け、S3（30 万、75,000 変更/秒）でセル構成と海外のリージョンにすると置いた。

- `sync_id`・`sync_actions`・`tx_results`・同期グループは、どれもワークスペースの中で閉じる（[ADR-0002](0002-sync-model.md)、[ADR-0004](0004-tenancy-and-permissions.md)）。
- アカウント（1 人が複数のワークスペース）は、ワークスペースをまたぐ（[ADR-0034](0034-accounts-with-better-auth.md)）。
- 本家は、ワークスペースを作る時にリージョンを選び、変えられない。アカウントは米国の認証のサービスに置き、前段の proxy が振り分ける（[How we built multi-region support for Linear](https://linear.app/now/how-we-built-multi-region-support-for-linear)、2024-05-23。README の 1.3 節で確認済み）。
- [ADR-0013](0013-sync-group-changes-retention-and-reset.md) は、S2 のクラスタの移動は `sync_id` を保つので `sync_epoch` を上げないと決めている。

## Options

S2 の分け方：

1. **ワークスペースを単位にクラスタへ置き、`workspace_directory` で引く**
2. 表を単位に分ける（`sync_actions` を別のクラスタへ）
3. 1 つのクラスタを大きくし続ける

S3：

- a. **セル（スタック一式）にワークスペースを固定し、セルごとに主のリージョン。アカウントとディレクトリは Global**
- b. リージョンごとに 1 つの大きなスタック

## Decision

1 と a を採用する。詳細は [infrastructure.md](../architecture/infrastructure.md) の 10 節。

- `workspace_directory`（ワークスペース → クラスタ・リージョン・状態）とアカウント（`auth` スキーマ）は、小さなディレクトリのクラスタ（Global Database で大阪へ）に置く。各サービスは 60 秒の写しと変更の知らせで引き、クラスタごとの接続のプールを使う。Writer・Relay はクラスタごとに動く。
- 移動：移動先へ `workspace_id` で絞ってコピーし追いかけ、`moving` の数秒だけ書き込みを止めて（Writer は `retry`）、ディレクトリを切り替え、そのワークスペースの接続を逃がす。`sync_id` と `sync_actions` を保ち、`sync_epoch` を上げない。追いかけの方式は S2 の着手の前に別の ADR で決める。
- S3：セルにワークスペースを固定する。振り分けは CloudFront Functions と KeyValueStore で、同期の経路にセルを引く同期の依存を足さない。リージョンの障害では、そのリージョンを主とするセルだけを切り替え、そのセルのワークスペースの `sync_epoch` だけを上げる。
- 海外のリージョンは、本家と同じく作る時に選び、変えない。
- 2 を採らない理由：Writer の 1 つの DB のトランザクション（モデルの行と `sync_actions` を原子的に書く。ADR-0006）が、クラスタをまたぐ分散トランザクションになる。
- 3 を採らない理由：最大のインスタンスでも S2 の書き込みを受けきれない見込み。1 つの障害で全ワークスペースが止まる。
- b を採らない理由：1 つのリージョンの障害の範囲が、そのリージョンの全ワークスペースになる。大口の顧客の専用の置き場所を作りにくい。

## Consequences

- 良くなること：
  - 同期の核（Writer の原子性、`sync_id` の順）を変えずに広げられる。
  - 移動でクライアントのやり直しが起きない。
  - 障害の範囲がクラスタ・セルに閉じる。
- 引き受けるコスト：
  - ディレクトリのクラスタが全体の依存になる。写しで引き、ディレクトリが落ちても既知のワークスペースは続ける。
  - ワークスペースをまたぐ機能（MVP の後のワークスペースの間の移動など）は、クラスタをまたぐ処理になる。
  - 移動の追いかけの方式が未決。

## Confirmation

- S2 の着手の前の PoC：1 つのワークスペースの移動で、書き込みの停止が 10 秒以内、クライアントのやり直し 0 件、収束の監査の不一致 0 件。
- 静的な検査：モデルの表を読む問い合わせが、ワークスペースの ID から決まる接続のプールを使う。
