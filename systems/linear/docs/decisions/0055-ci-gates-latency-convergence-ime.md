# ADR-0055: PR の必須の関門に、遅延の予算（固定の機械）、収束のシミュレーターと回帰の種、オフラインと再送の 3 つの場面、IME のテスト、生成とマイグレーションの検査を入れ、変更のパスで重さを足す。関門を外すラベルを持たず、シミュレーターの失敗を再実行で緑にしない

## Context

この題材の AGENTS.md は、次を開発リポジトリの規則にしている。

- 遅延の予算（NFR-001：p99 50ms）を CI で守り、超えた PR を失敗させる（[ADR-0018](0018-render-path-and-latency-budget.md)）。
- 同期エンジン・競合の規則・ブートストラップに触れる変更に、決定的なシミュレーターの性質ベーステストを付け、失敗した種を回帰テストに残す（[ADR-0010](0010-deterministic-sync-simulator.md)）。
- outbox・再接続・スキーマの移行に触れる変更に、オフラインの 3 つの場面の試験を付ける（[ADR-0005](0005-client-persistence-and-offline.md)）。
- 日本語の変換の途中でショートカットを発火させない（[ADR-0017](0017-keymap-command-menu-and-ime.md)）。
- テストの削除・skip・期待値の緩和で通したことにしない（リポジトリ共通）。

これらを、どの PR に、どの重さで、どの機械で回すかを決める。遅延のベンチマークは機械の揺れに弱く、シミュレーターは回数と時間の釣り合いが要る。

## Options

関門の掛け方：

1. **全 PR に軽い関門を必須にし、変更のパスで重い関門（シミュレーター 20 万、オフラインの場面、全場面の遅延）を足す。外すラベルを持たない**
2. 全 PR に全部の重い関門
3. 重い関門は夜間だけ

遅延のベンチマークの機械：

- a. **型番を固定した自前のランナーと較正**
- b. クラウドの共有のランナー

## Decision

1 と a を採用する。詳細は [delivery.md](../architecture/delivery.md) の 1・2 節。

- 全 PR の必須：静的な検査（権限の条件の lint を含む）、単体・表駆動（DT-* を spec から）、生成の検査と `schema_version` の上げ忘れ、マイグレーションの比較（FORCE RLS、RLS の外の許可リスト）、シミュレーター 2,000 の列と `sim/regressions/` の全部の種、結合、IME の表駆動と合成の組み立てのテスト（3 つのブラウザ）、遅延のベンチマーク（Chrome、固定の機械）、E2E。
- パスで足す関門：同期の核はシミュレーター 20 万の列とオフラインの 3 つの場面、手元の保存はオフラインの 3 つの場面、権限は同期グループの性質ベーステストの全部、画面の入力の経路は遅延の全場面。
- シミュレーターの失敗は再実行で緑にせず、縮めた種を `sim/regressions/` に足す PR を先に出す。
- 遅延のベンチマークは、型番を固定した自前のランナーで、毎回の較正で 5% ずれた回を無効にする。フォークの PR では動かさず、秘密を置かない。
- テストの削除・skip・期待値の緩和を差分から見つけ、2 人の承認を求める。
- 夜間：シミュレーター 20 万、Firefox・Safari の遅延、7 日のオフラインの耐久、障害注入、DAST、1 つ前のリリースのクライアントとの互換。
- 2 を採らない理由：PR の待ちが 1 時間を超え、関係のない変更の流れを止める。
- 3 を採らない理由：同期の核の誤りが main に入り、夜間に見つかった時には原因の PR が分かりにくい。
- b を採らない理由：隣の負荷で揺れ、p99 50ms の判定が偶然で決まる。

## Consequences

- 良くなること：
  - AGENTS.md の規則が機械で守られる。
  - 同期の核の誤りを PR の中で見つけやすい。
- 引き受けるコスト：
  - 自前のランナー（6 台）の運用と、較正の基準の保守。
  - 同期の核の PR の CI が 20〜30 分かかる。

## Confirmation

- CI の設定の検査：必須のチェックの一覧が branch protection と一致する。パスと関門の表が設定と一致する。
- 指標：CI の PR の関門の時間 p90 30 分、夜間に見つかった新しい種を 7 日以内に直す。
