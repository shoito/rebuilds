# ADR-0005: ワークスペースごとの IndexedDB に、モデルと、送る前に保存する outbox を持つ。スキーマの版ごとに移行し、outbox は移行で消さない

## Context

クライアントは、ワークスペースのデータを手元に持ち、2 回目以降はそこから起動する（NFR-003）。オフラインで書いた変更は、再起動・クライアントの更新をまたいでも失わず、つながったときに 1 回だけ反映しなければならない（NFR-004）。

本家の文書は、オフラインを「完全な機能ではなく、失敗への備え」と位置付け、送れなかった変更を手元に持ち、再起動の後も送り直すと書いている（[Download Linear](https://linear.app/docs/get-the-app)、2026-09-28 に確認）。第三者の解析によれば、本家はワークスペースごとの IndexedDB に、モデルの表、`lastSyncId` などを持つ表、未送信のトランザクションの表を持つ（[reverse-linear-sync-engine](https://github.com/wzhudev/reverse-linear-sync-engine)、2026-09-28 に確認。本家の保証ではない）。

Notion の題材は、手元の保存に SQLite（WASM）と OPFS を選び、書くタブを 1 つに限った（Notion の ADR-0008）。Notion はデータベースのビューの問い合わせを手元の SQL で行うためである。この題材では、フィルターと並べ替えを、メモリーのオブジェクトプールの上で行う（views-and-filters の領域）。手元の保存に求めるのは、モデルの出し入れ、部分の索引の単位での読み出し、未送信のトランザクションの確実な保存である。

## Options

保存の場所：

1. **IndexedDB**（ラッパーは `idb`）
2. SQLite（WASM）＋ OPFS（Notion の形）
3. Electron だけネイティブの SQLite、Web は保存しない

未送信の変更の扱い：

- a. **送る前に outbox に保存し、確定を差分で確かめてから消す**
- b. メモリーに持ち、送れなかったときだけ保存する

## Decision

1 と a を採用する。詳細は client-store-and-offline の領域で決める。

### データベースの構成

- **アカウントとワークスペースの組ごとに、別の IndexedDB のデータベースを持つ。** 名前は `<brand>_<hash(account_id, workspace_id)>` の形にする（[リポジトリ共通の ADR-0006](../../../../docs/decisions/0006-brand-neutral-identifiers.md)）。どのデータベースがあるかは、登録用の小さなデータベース（`<brand>_registry`）に記録する。
- 各データベースに、次の object store を置く。

| store | 中身 |
| --- | --- |
| モデルごとの store | そのモデルの行（キーは `id`）。部分の索引に使うフィールドに索引を張る。各行は `updated_sync_id` を持つ |
| `_meta` | 手元の `last_sync_id`、受けた範囲、購読する同期グループ、スキーマの版とハッシュ、最後のブートストラップの種類 |
| `_outbox` | 未確定のトランザクション。`client_tx_id`、作った順の番号、`base_sync_id`、トランザクションの形の版、状態（未送信・送信済み・確定の `sync_id`） |
| `_partial_indexes` | 遅延の読み込みで取り終えた単位（[ADR-0003](0003-bootstrap-and-partial-sync.md)） |
| `_rejected` | 拒否されたトランザクションと理由（本人に示すまで持つ） |

- 添付ファイルのオフラインの送信は、client-store-and-offline の領域で決める（上限と、未送信の間の表示）。

### 書き込みの順序

- **操作から描画まで（入力の経路）**：操作 → トランザクションを作る → メモリーのモデルに当てる → 描画。ここで IndexedDB もネットワークも待たない（NFR-001）。
- **outbox への保存**：同じイベントループの回の中で作ったトランザクションをまとめ、1 つの IndexedDB のトランザクション（`durability: "strict"`）で `_outbox` に書く。コミットの後に初めて送る。**保証の起点は outbox のコミットである。** 操作から outbox のコミットまでの間（通常は数十ミリ秒）にタブが落ちると、その操作は失われる。1 秒以上コミットできなければ、画面に「保存していない変更」を示す。
- **差分の保存**：差分のパケットは、1 つの IndexedDB のトランザクションで、モデルの行・`_meta` の `last_sync_id` と受けた範囲・確定した outbox の行の削除を、まとめて書く。途中で落ちても、手元の状態と `last_sync_id` がずれない。そのうえでメモリーに当てる。
- outbox の行は、その確定の `sync_id` までの差分を保存した時に消す（[ADR-0002](0002-sync-model.md) の載せ直し）。
  > 2026-09-28 の注記：outbox の行は、確定の `sync_id` までの差分を保存した時に消さず、`done` の状態で 15 分残してから消すことにした（[ADR-0014](0014-indexeddb-layout-durability-and-migrations.md)、[ADR-0013](0013-sync-group-changes-retention-and-reset.md)）。リージョンの切り替えで直近の確定を失ったとき（NFR-007 の RPO 1 分）、確定を確かめて消した変更は送り直せず、README の NFR-007 の「outbox に残っていれば送り直される」が成り立たなかったため。`sync_epoch` のやり直しでは `done` の行も送り直し、生き残った変更は `tx_results` で前の結果が返り、失われた変更は 1 回だけ当たる。差分の保存のトランザクションは、outbox の行を消す代わりに `done` にする。未確定の数（画面の件数、上限の 5 万件）に `done` は数えない。

### 複数のタブ

- 同じワークスペースを開いたタブ（Electron の複数のウィンドウを含む）のうち、1 つを**書き手**にする。Web Locks API で選ぶ。書き手が WebSocket を持ち、outbox の送信と差分の保存をする。
- 他のタブは、自分のトランザクションを `_outbox` に直接書き（IndexedDB は複数のタブからの書き込みを扱える）、BroadcastChannel で書き手に知らせる。書き手は、保存した差分と確定を BroadcastChannel で配る。
- 書き手のタブが閉じたら、ロックが外れ、別のタブが書き手になる。outbox は IndexedDB にあるので、引き継ぎで失わない。
- SQLite の OPFS（`opfs-sahpool`）は 1 つの接続しか開けず、Notion は SharedWorker を経由させた。IndexedDB では、どのタブも読み書きでき、書き手はネットワークの役割だけになる。

### 手元の DB のスキーマの移行

- クライアントのコードは、手元の DB のスキーマの版（整数）とハッシュを持つ。起動の時に `_meta` の版と比べる。
- **store と索引の追加・削除**は、IndexedDB の版の更新（`onupgradeneeded`）で行う。
- **モデルの形の変更**は、モデルごとの移行の関数で行う。足すだけの変更は、既定値で埋めるか、そのモデルだけをサーバーから取り直す。形が合わない変更は、そのモデルの store を捨てて取り直す。移行できなければ、やり直しのブートストラップをする（[ADR-0003](0003-bootstrap-and-partial-sync.md)）。
- **どの移行でも `_outbox` を消さない。** トランザクションは形の版を持ち、クライアントのコードは古い版から今の版への変換（upcast）を持つ。
- **サーバーは、1 つ前のトランザクションの形の版を、リリースから 30 日は受ける。** それより古いクライアントには `upgrade_required` と最低の版を返す。クライアントは送信を止めるが、手元の読み書きと outbox への保存は続け、更新を促す。更新の後に、outbox を今の版に変換して送る。
- サーバーのスキーマの変更は、足す → クライアントを更新する → 古いものを消す、の順にする（delivery の領域）。

### オフライン

- 同期グループから外れたとき（非公開のチームから外された、チームが非公開になった）、そのグループのモデルへの未確定のトランザクションは outbox に残し、送ってサーバーが `forbidden` で拒否するまで待つ。拒否されたら `_rejected` に理由を残す。
  > 2026-09-28 の注記：この行を足した。ADR-0003 は「拒否されるので outbox から外す」としていたが、拒否の判断をサーバーの 1 か所に保つため、クライアントは先回りして外さない（[ADR-0013](0013-sync-group-changes-retention-and-reset.md)、[bootstrap-and-partial-sync.md](../architecture/bootstrap-and-partial-sync.md) の 7.4 節）。ワークスペースから除外されたときだけは、送れないので outbox ごと消し、件数を示す（同 7.6 節）。
- 手元にあるモデルへの操作は、オフラインでもすべてできる。サーバーが要る操作（手元にないデータの検索と読み込み、招待、連携の設定、インポート）は、オフラインでは使えないと示す。
- 未送信のトランザクションの数を画面に出す（本家の「Syncing」の表示と同じ考え方）。
- outbox のトランザクションは、7 日のオフラインの後も送れる（NFR-004）。同期のログの保持（30 日）を超えたら、やり直しのブートストラップの後に送る。サーバーは `client_tx_id` の記録を 90 日持ち、それより古いトランザクションは、自動では送らずに本人に確かめる（重複の検出ができないため）。

### 保存の消去への備え

- Web では `navigator.storage.persist()` で永続の保存を求める。Electron では、アプリのデータの場所に保存され、ブラウザの消去の方針を受けない。
- 起動の時に `_meta` がない、または登録と食い違うときは、消去されたとみなし、やり直しのブートストラップをする。outbox が消えていたら、取り戻せないので、そのことを本人に示す。
- 未送信の outbox がある間に保存の上限に近づいたら、警告する。ブラウザごとの上限は、Chrome でディスクの 60% まで、Firefox で既定 10%（か 10 GiB）・永続 50%、Safari で約 60%（[Storage quotas and eviction criteria](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)、2026-09-28 に確認。[client-store-and-offline.md](../architecture/client-store-and-offline.md) の 2 節）。
- ログアウトでは、そのアカウントのデータベースをすべて消す。未送信の outbox があれば、先に本人に確かめる（security の領域）。

- 2 を採らない理由：手元で SQL の問い合わせをしないので、SQLite の利点が小さい。WASM の読み込み（1 MB 前後）と、OPFS の 1 つの接続の制約（書き手のタブ以外は中継が要る）を払う意味が薄い。IndexedDB は、どのブラウザと Electron にも組み込まれている。一括の書き込みの遅さは、ブートストラップで大きなトランザクションにまとめて抑え、E3 の PoC で測る。遅すぎれば、2 に替える ADR を書く。
- 3 を採らない理由：Web で手元から起動できず、オフラインの保証が Electron だけになる。保存の層が 2 つになる。
- b を採らない理由：送れなかったと判断する前にタブが落ちると失う。確定を確かめる前に消すと、応答が失われたときに失う。

## Consequences

- 良くなること：
  - Web と Electron で、同じ保存の層とオフラインの保証を持てる。
  - 保証の起点（outbox のコミット）がはっきりし、試験で確かめられる。
  - 複数のタブで outbox を共有し、書き手の交代で失わない。
- 引き受けるコスト：
  - IndexedDB の一括の書き込みと読み出しは遅い。大きなワークスペースのブートストラップと起動の時間に効く。
  - 手元の DB の移行とトランザクションの形の変換を、スキーマを変えるたびに書いて試す必要がある。
  - 操作から outbox のコミットまでの短い間の喪失は残る。
  - ブラウザの保存の消去は防げない。Electron を勧める理由になる。

## Confirmation

- オフラインと再送の試験（Playwright と、IndexedDB の上のシミュレーター）：
  - オフラインで操作し、タブを閉じて開き直し、つないだら、全トランザクションが 1 回ずつ確定する。
  - 送信の途中（送った後、応答の前）でタブを落としても、再送で重複しない。
  - 差分の保存の途中で落としても、手元の `last_sync_id` と状態がずれない。
  - 1 つ前の版のクライアントで outbox を作り、今の版に更新してから送っても、全トランザクションが確定する。
  - 書き手のタブを閉じても、他のタブの outbox が送られる。
- 性質ベーステスト：任意の操作・落ちる時点・再起動の列で、outbox にコミットしたトランザクションは、最終的にちょうど 1 回確定するか、拒否されて本人に示される（NFR-004）。
- CI：手元の DB のスキーマの版を上げる PR に、移行の関数と、1 つ前の版の outbox の変換のテストがなければ失敗させる。
- lint：モデルの store へ書くコードを、差分の保存とブートストラップの層だけに限る（画面の操作から直接書かない）。
