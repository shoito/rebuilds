# ADR-0039: Slack はワークスペースごとに 1 つのインストールで、トークンの入れ替えを有効にする。メッセージからの作成は結び付けた利用者が書けるチームにだけ行い、チャンネルへの通知とリンクの展開は公開のチームに限る。スレッドの同期は MVP の後にする

## Context

intent の MVP は、Slack のチャンネルへの通知、個人への通知、メッセージからイシューを作ることを求める。本家は、それに加えてスレッドの双方向の同期、リンクの展開、プロジェクト・イニシアチブのチャンネルを持つ（[Slack](https://linear.app/docs/slack)、2026-09-28 に確認）。

Slack の仕様（いずれも 2026-09-28 に確認）：

- 操作には 3 秒以内に応答し、`trigger_id` は 3 秒で切れる（[Handling user interaction](https://docs.slack.dev/interactivity/handling-user-interaction)）。
- トークンの入れ替えを有効にすると 12 時間で切れ、リフレッシュトークンは 1 回限りで、有効にすると戻せない（[Using token rotation](https://docs.slack.dev/authentication/using-token-rotation)）。
- `chat.postMessage` はチャンネルごとに 1 秒 1 回（[Rate limits](https://docs.slack.dev/apis/web-api/rate-limits)）。

Slack のチャンネルのメンバーは、ワークスペースのメンバーやチームのメンバーと一致しない。非公開のチームの中身をチャンネルへ出すと、[ADR-0004](0004-tenancy-and-permissions.md) の分離を外へ持ち出すことになる。

## Options

非公開のチームの扱い：

1. **チャンネルへの通知と展開は、公開のチーム（と公開のチームだけのプロジェクト）に限る**
2. 非公開のチームも、チームのメンバーが設定すれば許す
3. チャンネルのメンバーが全員チームのメンバーの時だけ許す

トークン：

- a. **トークンの入れ替えを有効にする**
- b. 期限のないボットのトークン

スレッドの同期：

- x. **MVP の後にする。MVP は作成の時の permalink と返信だけ**
- y. MVP に入れる

## Decision

1・a・x を採用する。詳細は [integrations.md](../architecture/integrations.md) の 5・6 節。

- インストールは管理者が OAuth v2 で行う。1 ワークスペースに 1 つの Slack のワークスペース。メッセージの履歴を読むスコープは求めない。
- メッセージのショートカットは、受け口が署名を確かめ、結び付けた利用者（`ExternalAccountLink`）を引き、書けるチームだけを候補にしたモーダルを 3 秒以内に開く。送信は保存と SQS を経て、Worker が Writer で作る（`actor` は結び付いた利用者、`origin = worker`）。Triage の入り口は DT-ISSUE-002 に従う。返信は識別子と URL だけ、非公開のチームなら本人だけに見える返信。
- チャンネルへの通知とリンクの展開は公開のチームに限る。送る直前にチームがまだ公開かを確かめる。展開は本文を載せず、Slack Connect の共有のチャンネルでは行わない。
- トークンの入れ替えを有効にし、更新はインストールの行のロックの中で 1 つの Worker だけが行う。
- 個人への通知は [ADR-0037](0037-notification-delivery-channels.md) の規則で送り、この領域は送る口を持つ。
- 2 を採らない理由：チャンネルに、チームのメンバーでない人やワークスペースの外の人がいても、止める仕組みがない。
- 3 を採らない理由：チャンネルのメンバーの変化を追い続ける必要があり、MVP の費用に見合わない。MVP の後に検討する。
- b を採らない理由：漏えいした時の影響が長く続く。
- y を採らない理由：履歴を読むスコープと、ワークスペースの外の人の書いた中身の取り込みが、法務の L1・L2 に関わる。

## Consequences

- 良くなること：
  - 非公開のチームの中身が Slack に出ない。
  - トークンの漏えいの影響が 12 時間に限られる。
- 引き受けるコスト：
  - 非公開のチームは Slack の通知を使えない（個人への DM は使える）。本家より狭い（本家の振る舞いは**未検証**）。
  - スレッドの同期がない。
  - トークンの入れ替えは戻せないので、本番のアプリで有効にする前に dev で確かめる手順が要る。
  - [architecture/README.md](../architecture/README.md) の 7 節の範囲（スレッドの同期）とずれる。README の持ち主に依頼する。

## Confirmation

- 性質ベーステスト：PROP-INT-003（外へ出さない）。
- 結合テスト：受け口のモーダルを開くまでの p99 が 3 秒の中に収まる。トークンの更新が並んで走らない。
- E10 の spec は法務の L1 の結論まで承認しない。
