# ADR-0012: 遅延の読み込みは被覆の鍵の単位で求め、そろったら部分の索引に記録する。読み込みと差分の順序の揺れは、行の `updated_sync_id` と、15 分持つ削除の墓標で解く

## Context

[ADR-0003](0003-bootstrap-and-partial-sync.md) で、遅延の読み込みを `(モデル, 索引のフィールド, 値)` の単位で求め、読んだ単位を部分の索引に記録し、読み込みの行と差分の行がぶつかったら `updated_sync_id` の大きい方を残すと決めた。残る問いは次のとおり。

- 単位（被覆の鍵）の形。部分のブートストラップの条件（未完了と 30 日以内の完了）も同じ仕組みで表したい。
- 消えた行。読み込みを求めた後に差分で行の削除が届き、その後に削除より前の写しの応答が届くと、比べる相手の行がないので、`updated_sync_id` だけでは行が生き返る。
- 参照をどこまでたどって一緒に読むか。

第三者の解析によれば、本家は `issueId-<UUID>` のような索引の値で読み、参照を 3 段までたどって索引の組を作り、読んだ索引を別のデータベースに記録し、まとめて `/sync/batch` に求める（[reverse-linear-sync-engine](https://github.com/wzhudev/reverse-linear-sync-engine)、2026-09-28 に確認。本家の保証ではない）。本家の削除と読み込みの突き合わせの方法は**未検証**。

## Options

鍵と記録：

1. **被覆の鍵を `<Model>:<field>=<value>`、`<Model>:id=<id>`、`<Model>:<field>=<value>:<条件>` の 3 つの形にし、スキーマから生成する。一緒に読むものはスキーマの `include` だけ**
2. 本家の解析と同じく、参照を 3 段までたどる

消えた行：

- a. **削除と `evict` のときに墓標を書き、15 分持つ。15 分より前に求めた応答は捨てて求め直す**
- b. 読み込みの応答の `as_of` が手元の `last_sync_id` より古ければ、差を取り戻してから当てる
- c. 墓標を無期限に持つ

## Decision

1 と a を採用する。詳細は [bootstrap-and-partial-sync.md](../architecture/bootstrap-and-partial-sync.md) の 6 節。

- API は `POST /sync/load {keys (50 まで), min_sync_id?}`。応答は NDJSON（`head` の `as_of`、`rows`、`covered`、`more` と `cursor`、`end`）。1 つの鍵で 5,000 行を超えるとページに分け、最後のページの後に被覆を記録する。
- 被覆は `_partial_indexes` に `{key, as_of, groups}` で記録する。`groups` は脱退のときに消す鍵を探すのに使う。
- 突き合わせ：読み込みの行は、手元より `_u` が大きいときだけ書く。墓標の `sync_id` が行の `_u` より大きければ書かない。差分の遅延のモデルの行は書くが、被覆は記録しない。
- 墓標は `_tombstones` に `{model, id, s, at}` で 15 分持つ。15 分より前に求めた読み込み・グループのブートストラップの応答は捨てる。
- `min_sync_id` のある求めは、reader がそこに届くまで最大 2 秒待ち、届かなければ writer から読む。
- 同期グループの絞り込みは差分と同じ関数で行い、見てよくない行は、ないのと区別せずに返さない（[ADR-0004](0004-tenancy-and-permissions.md)）。
- 2 を採らない理由：1 回の読み込みの量が読めなくなり、たどった先に大きな集まり（ラベルの全イシューなど）があると重い。要る組み合わせはスキーマで明示する。
- b を採らない理由：読み込みの度に取り戻しが挟まり、遅延の読み込みが遅くなる。取り戻しの範囲が保持の外なら使えない。
- c を採らない理由：削除の多いワークスペースで墓標が増え続ける。15 分と応答の捨て方で足りる。

## Consequences

- 良くなること：
  - 被覆の鍵が、ビューが手元だけで答えられるかの判定にもそのまま使える。
  - 読み込みと差分の順序にかかわらず、消えた行が生き返らない。
- 引き受けるコスト：
  - スキーマに `index` と `include` を書く手間。
  - 15 分を超える遅い応答は捨てられ、求め直しになる。

## Confirmation

- 性質ベーステスト（[ADR-0010](0010-deterministic-sync-simulator.md)）：PROP-BOOT-003（読み込みと差分の順序を入れ替えても結果が同じで、消えた行が生き返らない）。
- 結合テスト：スキーマにない鍵が `400`、見てよくないグループの鍵が空になる。
- 計測：遅延の読み込みの p95 と、求め直し（15 分超）の回数。
