## この題材に固有の規則（開発リポジトリで守る）

- **同期エンジンの核を自前で作る。** 本家の SDK（`@linear/sdk` など）、本家のクライアントのコード、本家の同期の実装を、核にもテストの相手にも使わない。第三者の汎用の部品（IndexedDB のラッパー、MobX などの反応型のストア、CRDT のライブラリ）は、ADR に理由を書いたうえで使ってよい（[リポジトリ共通の ADR-0007](../../docs/decisions/0007-no-reuse-of-original-implementation.md)、ADR-0001）。
- **変更はトランザクションとして送り、サーバーの順序で決める。** クライアントは DB（IndexedDB）のモデルの表を直接書き換えない。モデルの変更は、必ずトランザクションを作り、outbox に入れてから送る。サーバーが振った `sync_id` の順に当てた結果だけを正とする（ADR-0002、ADR-0005）。
- **競合の規則を、フィールドの型ごとに 1 か所で決める。** 単一値は LWW、集合は追加・削除、並びは分数インデックスの鍵、数の加算は加算の操作、イシューとプロジェクトの説明（本文）は CRDT。コメントの本文は、書くのが作った人だけなので LWW（ADR-0022）。新しいフィールドを足すときは、スキーマに競合の種類を書かないとコード生成が失敗するようにする（ADR-0002）。
- **収束は性質ベーステストで確かめる。** 同期エンジン・競合の規則・ブートストラップに触れる変更には、決定的なシミュレーター（複数のクライアント、切断、並べ替え、重複、再起動をシードから再現する）の性質ベーステストを付ける。「静かになった後、全クライアントのモデルがサーバーの状態と一致する」「確定したトランザクションは 1 回だけ効く」を必須の性質にする。失敗したシードは回帰テストとして残す。
- **オフラインと再送の試験を省かない。** outbox・再接続・スキーマの移行に触れる変更には、オフラインのまま再起動する、送信の途中で落ちる、古い版のクライアントの outbox を新しい版で送る、の 3 つの場面の試験を付ける。outbox に入ったトランザクションが失われる場面を 1 つでも見つけたら、リリースを止める（ADR-0005）。
- **権限を狭める操作を足したら、DR の記録の一覧に入れる。** 停止・除外・ロールの引き下げ・非公開への切り替え・脱退・取り消しの操作は、`packages/policy` の一覧に印を付け、DR のための追記だけの記録にも書く（ADR-0058）。
- **遅延の予算を CI で守る。** ローカルの操作（状態の変更、担当の変更、並べ替え、コマンドメニュー）の入力から描画までを p99 50ms（NFR-001）に収める。基準の端末と基準のワークスペース（イシュー 50 万件）で計測するベンチマークを CI で回し、予算を超えた PR を失敗させる。入力の経路で IndexedDB・ネットワーク・同期の待ちをしない。
- **権限は同期グループで配る前に絞る。** 非公開のチームのモデルは、そのチームの同期グループにだけ入れる。差分・ブートストラップ・遅延の読み込み・検索・ビューの問い合わせ・通知・Webhook・公開 API・書き出し・連携のどれでも、同期グループの判定（`packages/policy`）を通らない読み出しを作らない（ADR-0004、ADR-0032）。行のグループを、行の中のチームの ID の集合から決めない（結び付けのモデルに分ける。ADR-0033）。
- **ワークスペースのテーブルには `workspace_id` と RLS を付ける。** `FORCE ROW LEVEL SECURITY` を外さない。ワークスペースをまたぐ処理は、専用の DB のロールで行う（ADR-0004）。
- **クライアントの DB のスキーマを変えるときは、移行を書く。** スキーマの版を上げる変更には、1 つ前の版からの移行と、1 つ前の版の outbox を読める変換を付ける。移行で outbox を消さない（ADR-0005）。
- **キーボードの操作は IME を壊さない。** 日本語の変換の途中（`isComposing`）では、ショートカットを発火させない。
- **本家の名前を識別子に使わない。** ドメイン、HTTP ヘッダー（Webhook の署名など）、API キーの接頭辞、IndexedDB のデータベースの名前、URL のスキームは `<Brand>`・`<brand>` で書く（[リポジトリ共通の ADR-0006](../../docs/decisions/0006-brand-neutral-identifiers.md)）。
- **テストに本物のデータを使わない。** 実在の会社のイシュー、本物の GitHub・GitLab・Slack のトークン、実在の人のメールアドレスを、テスト・フィクスチャー・シードに書かない。インポートの試験のデータは合成する。

## このリポジトリでの規則

- ADR を追加・更新したら、`docs/decisions/README.md` の一覧を生成し直す。
- 領域の文書で ADR を起票するときは、[architecture/README.md](docs/architecture/README.md) の 7 節で領域に割り当てた番号の範囲の中で採番する。
- 本家の振る舞い・数値を書くときは、出典と確認日を付ける。確かめられないものは「未検証」と書く。
- 本家の同期の仕組みの説明は、公式の資料と、第三者の解析（リバースエンジニアリング）を分けて書く。第三者の解析だけで確かめたことは、そう明記する。
