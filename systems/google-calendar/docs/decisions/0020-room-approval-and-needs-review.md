# ADR-0020: 承認の要る会議室の予約は「承認の待ち」の行にして制約の外に置き、管理者の承認で承諾の行に変える。tzdb の計算し直しで承諾どうしが重なったら、後から承諾したほうを「要確認」にして制約の外に出し、主催者と管理者に知らせて自動では辞退しない

## Context

[ADR-0019](0019-room-booking-rows-and-recurring-acceptance.md) は、承諾した予約どうしの重なりを排他の制約で拒むと決めた。次の 2 つの場合は、制約の中に置くと困る。

- **承認の要る会議室**：本家では、会議室の管理者が予約の通知を受け、「はい」「未定」「いいえ」で返す（[Approve or deny Calendar room & resource bookings](https://knowledge.workspace.google.com/admin/calendar/approve-or-deny-calendar-room-and-resource-bookings)、2026-10-04 に確認）。承認の前の要求を制約の中に置くと、先に来た要求が、承認されるかわからないまま時間を塞ぐ。
- **tzdb の計算し直し**：[ADR-0012](0012-tzdb-update-recompute-and-propagation.md) で予約の区間が動き、承諾どうしが重なることがある。原因は利用者の操作ではなく、本システムのデータの更新である。[architecture/README.md](../architecture/README.md) の 1.3 節 B は、後から確定した予約を「要確認」にして主催者に知らせ、自動で辞退しないとした。

## Options

承認の待ち：

1. **制約の外の `pending` の行にし、承認の時に `accepted` にして制約を効かせる**
2. 制約の中に置く（先着で時間を塞ぐ）
3. 行を作らず、承認の時に初めて作る

tzdb の重なり：

- a. **後から承諾した（`accepted_at` の新しい）ほうを `needs_review` にして制約の外に出す。自動で辞退しない**
- b. 後から承諾したほうを自動で辞退する
- c. 重なりを許す（制約を一時的に外す）

## Decision

1 と a を採用する。詳細は [rooms-and-resources.md](../architecture/rooms-and-resources.md) の 7・8 節。

- 承認の要る会議室の予約は `pending` の行（制約の外）にし、会議室の出欠を `needs_action` にして管理者に知らせる。空き時間では `busy_tentative` にする。
- 管理者が承認すると `accepted` にする。制約に当たれば承認を失敗にし、重なる予約を示す。系列の承認では重なる回を辞退にし、ほかを承諾する（「半分・8 回」は当てない）。「未定」は出欠を `tentative` にし、行は `pending` のまま。
- 承認の待ちに期限を設けず、管理者に毎朝の一覧を送る。管理者がいない会議室の新しい予約は辞退する。
- tzdb の計算し直しで `during` の `UPDATE` が制約に当たったら、`accepted_at` の新しいほうを `needs_review` にする。`needs_review` は制約の外で、空き時間では `busy` にする。主催者と管理者に知らせ、72 時間後と開始の 24 時間前にもう一度知らせる。
- `needs_review` は、主催者が会議室・時刻を変えるか外す、管理者が辞退する、のどれかで解ける。

### 他の案を選ばなかった理由

- **2（承認の待ちを制約の中に）**：承認されない要求が時間を塞ぎ続け、他の人が予約できない。管理者が順番に承認する手間を、先着が決めてしまう。
- **3（承認まで行を作らない）**：承認の待ちが空き時間に出ず、同じ時間に要求が集まる。管理者が重なりを見られない。
- **b（自動で辞退）**：利用者の操作なしに、確定していた会議から会議室を外す。
- **c（重なりを許す）**：NFR-005 の「承諾どうしの重なり 0 件」を破る。

## Consequences

- 良くなること：
  - 承諾どうしの重なりは、承認の会議室でも tzdb の更新でも 0 件のまま。
  - 承認の待ちの要求が、時間を独占しない。
  - tzdb の更新で困る予定を、人が判断できる。
- 引き受けるコスト：
  - `needs_review` の予約は、人が直すまで同じ会議室に 2 つの会議が予定されたままになる。知らせを繰り返し、数を監視する。
  - 承認の待ちに期限がないので、管理者が放置すると待ちが溜まる。

- 本番：`needs_review` の数と、解けるまでの時間。承認の待ちの数と古さ。
