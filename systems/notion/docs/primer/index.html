Notion は何をするサービスか

チームの文書・wiki・表・タスク・議事録を、1 つの道具の中で作り、つなげるサービスです。文書の中に表を置き、表の行を開くとまた文書になる、という入れ子が特徴です。

書く

見出し・リスト・ToDo・トグル・コードなどを、/ で呼ぶメニュー（スラッシュコマンド）や Markdown の入力で並べます。

まとめる

データベースに行を足し、表・ボード・カレンダーなどの「ビュー」で見ます。タスク管理や CRM の代わりにも使われます。

一緒に使う

同じページを複数人で同時に編集し、コメントし、ページごとに共有の相手を決めます。Web にも公開できます。

規模の感覚：本家のブロックは 2021 年の 200 億から、2024 年に 2,000 億を超えました。書き込みの 90% は既存の行の更新です。本設計の S1 は、利用者 10 万・ブロック 10 億・同時接続 1 万を見込みます。

設計の文書で効くところ：intent.md の MVP の範囲と「守るべき振る舞い」、architecture/README.md の規模の段階。

すべてはブロック

段落 1 つ、見出し 1 つ、画像 1 つが、それぞれ 1 つのブロックです。ページもブロックの一種で、データベースの行もページです。どれも同じ表に、同じ形で入ります。

flowchart TD
  P["page: 議事録"] --> H["heading_1: 決定事項"]
  P --> L["bulleted_list_item: 予算を承認"]
  L --> L2["paragraph: 補足（インデントした子）"]
  P --> C["page: 子ページ"]
  C --> X["to_do: 資料を送る"]
  • content：子の ID の並び（下向き）。表示の順を決めます。
  • parent_id：親の ID（上向き）。権限の継承と、ゴミ箱からの戻し先に使います。
  • page_id：自分を含む最も近いページ。共同編集の順序・購読・履歴の単位です。

下向きと上向きの両方を持つので、両者が食い違わないこと（親はちょうど 1 つ、循環がない）を、サーバーが毎回検査します（不変条件 T1〜T8）。

設計の文書で効くところ：block-model.md の 2・5 節、ADR-0002。

ワークスペース・チームスペース・メンバーとゲスト

ワークスペースは会社やチームの単位で、テナントの境界です。その中をチームスペース（部署やプロジェクト）と、各人のプライベートの領域に分けます。

人どう参加するか見えるもの
所有者・メンバーワークスペースに所属するチームスペースと、共有されたページ
ゲストページ単位で招待される外部の人共有されたページとその子孫だけ。グループやチームスペースに入れない
連携（bot）API のトークンで動く明示的に共有されたページとその子孫だけ

1 人の人（アカウント）は、複数のワークスペースに入れます。設計では、ログインの単位のアカウントと、ワークスペースの中のメンバーを別の表に分け、ゲストと連携もメンバーの行にします。

設計の文書で効くところ：permissions-and-sharing.md の 2・3 節、ADR-0021。

ブロックのエディタとリッチテキスト

Word のような「1 枚の長い文書」ではなく、ブロックが縦に並んだ一覧を編集します。Enter でブロックが分かれ、行頭の Backspace で前のブロックとつながり、ドラッグでブロックごと動きます。

1 ブロックのテキストは、スパンの配列で持ちます。装飾（太字・色・リンク）が同じ範囲が 1 つのスパンです。

[ { "text": "会議は " },
  { "text": "明日", "marks": { "bold": true } },
  { "text": "‣", "mention": { "type": "user", ... } } ]

メンションは 1 文字（‣）として埋め込み、タイトルは持ちません。表示のたびに ID から引くので、読めない人にタイトルが漏れません。

ブロックの層（並び・選択・ドラッグ）は自前で作り、ブロックの中のテキストの編集だけを ProseMirror に任せます。テキストを持つブロック 1 つに、エディタ 1 つです。

IME で変換している間の Enter は「確定」です。ブロックの分割と取り違えないよう、変換中のキー操作を無視します。

設計の文書で効くところ：editor.md の 3 節、block-model.md の 4 節、ADR-0006・0007。

データベース：行はページ、見え方はビュー

Notion のデータベースは、表計算というより「型付きのプロパティを持つページの集まり」です。

データベース

タイトル・アイコン・置き場所を持つ入れ物。ページの中に置きます。

データソース

スキーマ（プロパティの名前と型）と行を持つ。2025 年に本家でデータベースから分かれました。

行

1 行が 1 ページ。プロパティの値と、本文のブロックを持ちます。

ビュー

表・ボード・リスト・カレンダー・ギャラリー・タイムライン。フィルタ・並べ替え・グループ化を持ちます。

プロパティの型は、テキスト・数値・選択・日付・人・チェック・URL・リレーション・ロールアップ・数式などです。別の場所から同じデータソースを見るリンクドビューもあり、権限は元のデータベースに従います。

データベースの行（ページ）は、ブロックの木のどこにありますか？

行は数十万になり、並びはビューごとに違うためです。ADR-0002 の不変条件は、行については「親のデータソースがちょうど 1 つ」と読み替えます。

設計の文書で効くところ：databases.md の 1〜4 節、ADR-0014。

リレーション・ロールアップ・数式

データベースどうしをつなぎ、つないだ先の値を集計できます。表計算の参照と集計関数に近い働きです。

行と行をつなぐプロパティ。「プロジェクト」の行から「タスク」の行を指す、など。両方向にすると、相手側にも逆向きのプロパティが出ます。設計では、1 本の辺（relation_edges の 1 行）を正本にし、両側の値をそこから導きます。片側だけ変わる状態が起きません。

リレーションの先の行のプロパティを集計します（件数・合計・平均・最古の日付など）。「プロジェクトの残りのタスク数」が典型です。ロールアップのロールアップは作れません。

行ごとに計算するプロパティ（本家の Formulas 2.0）。prop("Tasks").map(current.prop("Status")) のように、リレーションの先もたどれます。参照の深さは 15 層まで。設計では、クライアントとサーバーで同じ評価器を使い、サーバーの値を正とします。

権限が絡むロールアップは「見る人が読める行だけ」で計算します。全行で計算した値を、一部の行しか読めない人に返すと、読めない行の存在や値が合計から漏れるためです。

設計の文書で効くところ：databases.md の 6〜8・10 節、ADR-0015・0016・0017。

同時編集の方式：OT と CRDT

2 人が同じ文を同時に書き換えると、それぞれの画面では違う順で変更が届きます。どの画面も同じ内容に収束させ、入力を失わない仕組みが要ります。代表的な方式は 2 つです。

OT は「3 文字目に挿入」のような位置の操作を、先に当たった他人の操作に合わせて変換します。Google Docs の系統です。中央のサーバーと短い分岐が前提で、長いオフラインの後は、基にしたバージョンからの全操作との変換が要ります。

CRDT は、どの順で操作を当てても同じ結果になるデータ構造です。文字ごとに一意の ID を振り、位置を「この ID の文字の右」と ID で指します。長いオフラインに強い反面、ページ全体を 1 つの CRDT にすると、サーバーが結果を拒否できません。

テキストはブロックごとの CRDT、構造（ブロックの追加・移動・削除）とプロパティはサーバーの順序で決めます。テキストは必ず合わさり、木の不変条件と権限はサーバーで守れます。本家も 2025 年 7 月から、テキストに CRDT を使っています。

設計の文書で効くところ：collaboration.md の 1〜3 節、ADR-0010。

テキストの CRDT の中身

設計は、列の CRDT に Fugue、書式に Peritext を使います。押さえる点は 4 つです。

  • 文字の ID：(replica_id, counter)。位置を添字でなく ID で指すので、他人の挿入でずれません。カーソルの位置も ID で送ります。
  • 墓標：消した文字は中身だけ消し、ID は墓標として残します。何か月も前のバージョンを基にした操作でも、アンカーの文字が見つかるようにするためです。
  • 交ざり：2 人が同じ位置に長く書くと、文字単位で交ざる（interleaving）方式があります。本家の RGA より交ざりにくい Fugue を選んでいます。
  • 書式の広がり：太字の末尾で打った文字は太字になり、リンクの末尾で打った文字はリンクになりません。Peritext はこの区別を同時編集でも保ちます。

段落の分割（Enter）と結合は、文字の範囲（text slice）を別のブロックへ移す操作で表します。文字の ID は変わらないので、分割の後に届いた操作も正しい場所に当たります。

CRDT で文字を削除したとき、ID ごと消さずに墓標として残すのはなぜ？

操作は「この ID の文字の右に挿入」と書かれます。目印の ID が消えると、遅れて届いた操作の位置が決まりません。中身の文字列は消すので、残るのは ID の範囲だけです。

設計の文書で効くところ：collaboration.md の 5 節、ADR-0010。

変更はトランザクションで送り、ページごとに seq を振る

クライアントは操作（ブロックの作成、プロパティの設定、テキストの挿入など）をまとめたトランザクションを送ります。サーバーは検証してから確定し、ページごとの連番 seq を振ります。

  1. 打鍵を 100ms ごとにまとめ、端末の待ち行列に保存してから送る。ID（UUIDv7）はクライアントが振る。
  2. API が、ページの seq の行をロックする。これがページごとの書き込みの直列化になる。
  3. 権限・値・木の不変条件を検証し、ブロック・操作のログ・outbox を 1 つの DB トランザクションで書く。
  4. Relay が outbox を読み、そのページを開いている人へ配る。
  5. 受け手は seq が飛んでいたら欠けを検知し、差分を取り直す。

再送で二重に当たらないよう、端末ごとの連番 tx_counter で適用済みを判定します（冪等）。入力から他人の画面まで p99 500ms 以内が目標です（NFR-001）。

設計の文書で効くところ：collaboration.md の 4・7・8 節、ADR-0005。

構造の衝突と、兄弟のアンカー

ブロックの並びの位置は、添字ではなく「X の後、Y の前」と前後の兄弟の ID で指します（アンカー）。

添字

「3 番目に挿入」。他の人が先に 1 つ消すと、意図と違う場所に入る。

兄弟のアンカー

「A の後に挿入」。A があればその直後、なければ後ろの兄弟の直前、どちらもなければ親の末尾。

Figma などが使う分数インデックスは使いません。サーバーが順序を決める構成では要らないためです。構造とプロパティの競合は、サーバーに着いた順と決まった規則で解きます。

競合結果
同じプロパティへの同時の設定後に着いた方が勝つ（LWW）。負けた側に「上書きされた変更」を出す
複数選択への追加と削除集合として合わせる。両方の追加が残る
A を B の下へ、B を A の下へ循環になる後着の方を取り消す

オフラインで「ブロック A の後に C を挿入」した。再接続までに A は他の人に削除され、後ろの兄弟 B は残っている。C はどこに入る？

after が見つからなければ before の直前、どちらもなければ親の末尾です（ADR-0012）。「取り消す」のは個々の操作で、全体の拒否は権限や不変条件の違反に使います。

設計の文書で効くところ：collaboration.md の 6 節、ADR-0011・0012。

オフラインとブラウザの中の DB

開いたことのあるページは、ネットがなくても読めて書けます。ブラウザの中で SQLite を動かし、端末に写しと未送信の待ち行列を持ちます。

WASM の SQLite

C で書かれた SQLite を WebAssembly にしてブラウザで動かします。

OPFS

ブラウザがサイトごとに持つ、高速なファイルの置き場。SQLite のファイルをここに置きます。

Web Locks

タブが複数開いても、DB に書くのは選ばれた 1 つのタブだけにします。

どのページを持つかは、理由（明示・最近開いた・お気に入り・データベースから）ごとに記録し、最後の理由が消えたら外します。本家のオフラインはデスクトップとモバイルのアプリだけですが、本設計は Web（PWA）にも広げます。

ブラウザが消すSafari は、ホーム画面に追加していないサイトのデータを 7 日で消すことがあります。未送信の変更があるのに消えうる環境では、警告を出します。

設計の文書で効くところ：collaboration.md の 11 節、editor.md の 10・11 節、ADR-0008・0013。

権限：ページの木を継承する

共有の設定（ACL）は、設定したページにだけ持ちます。子のページは、親の設定をそのまま受け継ぎます。水準は本家と同じ 5 段です。

none < can_view < can_comment < can_edit_content < can_edit < full_access
  1. ブロックから、属するページ（page_id）を引く。
  2. ページから祖先へたどり、最初に ACL を持つページを見つける（自身を含む）。
  3. なければ最上位の暗黙の ACL を使う：チームスペースの設定か、プライベートなら本人だけ。
  4. 見つけた ACL のうち、自分（個人・グループ・チームスペース・ワークスペース）に当たる項目の最大の水準を取る。
  5. 無効化されたメンバー・ゴミ箱・連携の能力などの上限を重ねる。上限は権限を広げない。

子で共有を変えると、そのページに ACL ができ、以後は親の変更を受けません（継承を置き換える）。判定は can(actor, action, block) の 1 つの関数に集め、画面・API・検索・通知・Webhook のすべてが通ります。

子ページ C で、ある人を個別に追加した。その後、親ページ P の共有から「全員」を外した。C はどうなる？

ACL は設定したページで継承を置き換えます（ADR-0018）。親の変更が届くかは本家の文書で確かめられず、本システムの決定として書かれています。

設計の文書で効くところ：permissions-and-sharing.md の 4 節、ADR-0004・0018。

漏らさない経路：キャッシュ・検索・公開・連携

「権限のないページの中身（タイトルを含む）は、どこからも見えない」が最重要の振る舞いです（NFR-010）。判定関数の外を通る経路ごとに、守り方を決めています。

ワークスペースに acl_version（単調に増える番号）を持ち、権限の変更と同じトランザクションで上げます。キャッシュのキーに必ずこのバージョンを含めるので、変更の後に始まった要求が古い権限で判定されません。読めないページは 404、読めるが水準が足りないときは 403 にして、存在も漏らしません。

検索の索引（OpenSearch）は 1 ページ 1 文書で、「読める主体のキー」の配列を持たせて絞ります。それでも索引の権限は数秒遅れうるので、結果のページを DB で読み直し、判定関数を通ったものだけを、DB の値で表示します。日本語は N-gram で一致を判定します。

公開ページは、アプリと別の登録可能ドメイン（<brand>.site、仮）から、専用の描画サービスで配ります。利用者が作った内容が、アプリのセッションの cookie と同じサイトで動かず、フィッシングの評判もアプリと分けるためです。既定で検索エンジンに載せません（noindex）。

API の連携は、明示的に共有されたページとその子孫だけを読めます。メンバーの権限は引き継ぎません。AI エージェントには、利用者の委任で動くリモートの MCP サーバーを用意します。Webhook は中身を含めず、配送の時点で権限を判定し直します。

検索の結果に出すページのタイトルは、どこから取りますか？

索引は ID の一覧を得るためだけに使います。索引が古い間も、権限を失ったページのタイトルが出ません。

設計の文書で効くところ：permissions-and-sharing.md の 4.7・5・8 節、search.md の 5 節、api-and-integrations.md、ADR-0019・0020・0023・0024。

シャーディング：論理シャードと物理クラスタ

1 台の DB に入りきらない量を、複数の DB に分けて持つのがシャーディングです。分ける鍵はワークスペースで、1 つの操作が 1 つのシャードで閉じます。

flowchart LR
  W["workspace_id"] -- "末尾 64 ビット mod 480" --> L["論理シャード shard000 から shard479"]
  L -- "global.shard_map" --> C1["物理クラスタ 1"]
  L -. "S2 で分割" .-> C2["物理クラスタ 2..24"]
  • 論理シャード：PostgreSQL のスキーマ（shard042.blocks など）。数は 480 で、本家に合わせて S1 から変えません。
  • 物理クラスタ：実際の Aurora。S1 は 1 つに 480 スキーマを全部置き、負荷に応じて 480 を割り切れる数へ増やします。
  • 移し方：スキーマの束を論理レプリケーションで新しいクラスタへ写し、影の読み取りで一致を確かめ、書き込みを止める（フェンス）短い時間で切り替えます。

テナントの分離は、シャードとは別に RLS で行います。同じスキーマに多くのワークスペースが同居するためです。

設計の文書で効くところ：infrastructure.md の 3 節、data-model.md の 1.2〜1.4 節、ADR-0003・0027・0028。

同期ブロック・履歴・ゴミ箱と削除

同期ブロックは、同じ中身を複数のページに置く機能です。中身は元の場所に 1 つだけあり、元のページを読めない人には中身を見せません。

ページの履歴は、30 日分の操作のログと、10 分の休止か 1 時間ごとに作るスナップショットの 2 段で持ちます。復元は「巻き戻し」ではなく、今の値から過去の値へ変える新しいトランザクションです。

  1. ゴミ箱：30 日。can_edit 以上の人が戻せる。
  2. 完全に削除：利用者からは見えず、戻せない。30 日の間は、所有者の依頼で運用者だけが戻せる。
  3. 物理削除：行・ファイル・スナップショット・検索の索引を消す。
  4. バックアップ：最長 35 日残る。削除から完全に消えるまで最長 95 日。
法務の確認待ち最長 95 日を利用規約・データ処理の契約にどう書くか（L1）と、アカウントの削除でプライベートのページを消す既定案が契約・個人情報の扱いに合うか（L2）は、法務の確認待ちです。結論が出るまで、該当する Story の spec を承認しません。

設計の文書で効くところ：block-model.md の 7〜9 節、security.md の 6・7 節、ADR-0022、intent.md の「法務の確認待ち」。

データモデルの読み方

中心は blocks の 1 つの表です。ページ・データベース・行がすべてここに入り、権限・共同編集・データベースの索引が周りを囲みます。シャードの表は、主キーに workspace_id を含みます（記号は共通の資料）。

表読み方
blockscontent（子の並び）と parent_id（親）を両方持つ。alive が偽なら削除済み
page_seqs / page_opsページの順序の採番と、操作のログ（30 日）
page_acls / page_acl_entriesACL を持つページにだけ行がある
dbx_rows / dbx_valuesデータベースの問い合わせ用の写し。正本は行の properties
relation_edgesリレーションの正本。両側の値をここから導く

本家と違うところ、名前の置き換え

振る舞いは本家に寄せますが、意図して変えた点があります。文書で「差異」と書かれた箇所です。

点本家本設計
ワークスペースの所有者プライベートのページを含むデータにアクセスしうる通常の画面では所有者も読めない
テキストの列の CRDTRGAFugue（交ざりにくい）

ページの URLタイトルを含むID だけ（ログや Referer にタイトルを残さない）
検索の文書ブロック単位ページ単位

トークンの接頭辞や公開のドメインなど、ブランドを含む識別子は <brand> と書きます（例：<brand>_int_…、<brand>.site）。本家の内部の表の名前（collection など）は出典として書くだけで、識別子には使いません。

用語集

ブロック
Notion の内容の最小の単位。段落・見出し・画像・ページ・データベースなど。type・properties・content・parent を持つ。
ワークスペース
会社やチームの単位。テナントの境界で、シャードを決める鍵でもある。
チームスペース
ワークスペースの中の部署やプロジェクトの領域。既定・公開・閉鎖・非公開の種類があり、直下のページの暗黙の ACL になる。
ゲスト
ページ単位で招待される外部の人。ワークスペース全体の権限、グループ、チームスペースを持てない。
スパン
リッチテキストの、装飾が同じ連続した範囲。本設計はテキストをスパンの配列で持ち、同じ内容が同じ JSON になるよう正規化する。
ProseMirror
ブラウザのリッチテキストのエディタを作るための、オープンソースの部品集。
IME
かな漢字変換などの入力の仕組み。変換中のキー入力は、確定まで文書の操作として扱わない。
データソース
データベースのスキーマ（プロパティ）と行を持つもの。1 つのデータベースに複数置ける。
ビュー
データソースの見え方の設定。種類（表・ボードなど）とフィルタ・並べ替え・グループ化を持つ。
リンクドビュー
既存のデータソースを、別のページから参照するビュー。ビューの設定だけが独立し、権限は元に従う。
OT
Operational Transformation。位置で書いた操作を、先に当たった操作に合わせて変換して収束させる方式。
CRDT
Conflict-free Replicated Data Type。どの順で操作を当てても同じ状態に収束するように作ったデータ構造。
Fugue
テキストの列の CRDT の 1 つ。同じ位置への同時の長い入力が交ざりにくい。
Peritext
Ink & Switch による、太字やリンクなどの書式を同時編集で正しく合わせる CRDT の方式。
墓標
tombstone。削除した要素の ID を消さずに残した印。後から届く操作の位置の目印になる。
interleaving
2 人が同じ位置に同時に書いた文が、文字単位で交互に混ざってしまう現象。
text slice
ブロックのテキストの、文字の ID の範囲。分割・結合で範囲ごと別のブロックへ移す。本家の考え方に倣った。
seq
ページごとにサーバーが振る連番。順序の確定と、欠けの検知・差分の取得に使う。
アンカー
挿入や移動の位置を示す目印。ここでは前後の兄弟のブロックの ID。
分数インデックス
各要素に「0 と 1 の間の値」のような並びの鍵を持たせ、間に入れるときは間の値を作る方式。
LWW
Last Writer Wins。同じ値への競合する書き込みのうち、後のものを残す規則。
WASM
WebAssembly。C などで書いたプログラムを、ブラウザで高速に動かす形式。
OPFS
Origin Private File System。サイトごとに分かれた、ブラウザの中のファイルの置き場。
Web Locks
同じサイトのタブやワーカーの間で、排他のロックを取るブラウザの API。
PWA
Progressive Web App。インストールやオフラインに対応した Web アプリ。
ACL
Access Control List。誰にどの水準を許すかの一覧。ここではページごとの共有の設定。
OpenSearch
Elasticsearch から分かれたオープンソースの検索エンジン。AWS がマネージドで提供する。
N-gram
文字列を N 文字ずつずらして切り出し、索引にする方法。単語の区切りがない日本語でも取りこぼしにくい。
登録可能ドメイン
example.com のように、Public Suffix List で決まる「別のサイト」の単位。これが違えば cookie を共有しない。
MCP
Model Context Protocol。AI エージェントが外部の道具やデータを呼ぶための共通の手順。
シャーディング
データを鍵で分け、複数の DB に分けて持つこと。分けた 1 つをシャードと呼ぶ。
論理レプリケーション
PostgreSQL の、行の変更を論理的な形で別の DB へ流す複製。表やスキーマを選んで写せる。
影の読み取り
shadow read。同じ問い合わせを新旧の両方に投げ、結果を比べる照合。利用者には旧の結果だけを返す。
同期ブロック
同じ中身を複数の場所に置き、どこで編集しても全部に反映されるブロック。元と参照の 2 つの形がある。
