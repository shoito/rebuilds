# Intent: Notion を AI エージェント主体で再構築する

- Author: shoito
- Status: accepted
- Date: 2026-09-26

## Problem

チームの知識は、文書・表・タスク・議事録に散らばる。これらを別々の道具で持つと、つながりが切れ、探せず、古くなる。

本家 Notion は、すべてを「ブロック」として扱い、文書とデータベースを 1 つの道具の中でつなぐ。複数人の同時編集、細かな共有の設定、オフラインでの編集も備える。これらを支える次の中身を、小さなチームと AI エージェントでどこまで作り直せるかを確かめる。

- ブロックのデータモデル
- 共同編集の整合
- 権限の継承
- 大量のブロックの保存

## Proposed outcome

ブロックでできた文書とデータベース、共同編集を作り直す。次の 3 つの価値を満たす。

1. **自由に組み立てられる**：文書・表・ボードなどを、ブロックの組み合わせで作れる。
2. **一緒に書ける**：複数人の同時編集が、すぐに反映され、衝突しても壊れない。オフラインでも書ける。
3. **見つけられ、守られる**：検索でき、ページごとの共有の設定が正しく効く。

### MVP に含める

- ワークスペース、メンバー、ゲスト、チームスペース
- ページとブロック：テキスト、見出し、リスト、ToDo、トグル、コード、引用、コールアウト、画像・ファイル、埋め込み、区切り、子ページ、同期ブロック
- エディタ：リッチテキスト、メンション（人・ページ・日付）、スラッシュコマンド、ドラッグでの並べ替え、Markdown の入力
- データベース：プロパティ（テキスト、数値、選択、日付、人、チェック、URL、リレーション、ロールアップ、数式）、ビュー（表・ボード・リスト・カレンダー・ギャラリー・タイムライン）、フィルタ・並べ替え・グループ化
- 共同編集：同時編集、カーソルと在席の表示、コメントと解決、ページの履歴と復元
- オフライン：開いたことのあるページの閲覧と編集、再接続時の統合
- 共有：ページ単位の権限と継承、Web への公開、リンクの共有
- 検索、通知（メンション・コメント・更新）、インポートとエクスポート（Markdown・CSV）
- 公開 API と Webhook（連携）
- Web クライアントとデスクトップアプリ（Web の技術で包む）

### 守るべき振る舞い

- 同時に編集しても、どの利用者の画面も最終的に同じ内容に収束し、入力が失われない。
- オフラインで編集した内容は、再接続時に統合され、失われない。
- 権限のないページの中身（タイトルを含む）は、検索・通知・API・埋め込み・リレーションのどこからも見えない。
- ページを削除しても、決められた期間はゴミ箱から戻せる。

## Affected users and systems

- ワークスペースのメンバー、ゲスト、公開ページの閲覧者
- 連携（公開 API の利用者、Webhook の受け手）
- AI エージェント（API とトークンで操作する主体）

## Constraints

- 実行基盤は、rebuilds の他の題材の決定（AWS、TypeScript、Terraform、OpenTelemetry）を引き継ぐ（[ADR-0001](decisions/0001-platform-and-stack.md)）。リアルタイムの配信とテナントの分離は、Slack の設計を先例にする。
- 規模は段階的に広げる（[architecture/](architecture/README.md) の「規模の段階」）。

## Non-goals

| 機能 | 理由 |
| --- | --- |
| Notion AI（要約、生成、AI による検索） | MVP の後の Epic。ブロックのデータと権限の基盤を先に固める |
| Notion Mail、Notion Calendar、Sites の独自ドメイン | 別の製品 |
| モバイルのネイティブアプリ | Web（PWA）で代替し、MVP の後に検討する |
| フォーム、ボタン・オートメーション | MVP の後の Epic |
| Enterprise の管理（SCIM、監査ログの API、データの保管地域の選択） | MVP の後の Epic |

## Open questions
