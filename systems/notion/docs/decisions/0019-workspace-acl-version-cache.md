# ADR-0019: 実効権限は、ワークスペースの権限のバージョン（acl_version）をキーにキャッシュし、権限の変更と同じトランザクションでバージョンを上げる

## Context

[ADR-0004](0004-inherited-page-permissions.md) で、判定の結果をキャッシュし、共有とページの移動で影響を受ける部分木のキャッシュを消すと決めた。判定は、すべての読み取り・購読・検索の読み直し・通知で呼ばれ、祖先の鎖と ACL の読み取りが要る。

取り消しの後に古い権限で読めると、NFR-010（権限のないページが見える事象 0 件）に反する。部分木のキャッシュを 1 つずつ消す方式では、消し漏れ（移動と共有の競合、消去の通知の喪失）が漏洩になる。

検索は、ワークスペースの「権限のバージョン」を文書に入れ、古い文書を見つけるのに使う（[ADR-0023](0023-search-engine-and-permission-filtering.md)、[search.md](../architecture/search.md)）。

## Options

1. **キャッシュしない**：毎回、祖先の鎖と ACL を DB から読む
2. **部分木ごとの無効化**：変更のたびに、影響するページのキーを列挙して消す。TTL で消し漏れを抑える
3. **ワークスペースの権限のバージョン**：ワークスペースに単調に増える `acl_version` を持ち、権限に影響する変更と同じトランザクションで上げる。キャッシュのキーに `acl_version` を含め、要求の始めに読む

## Decision

3 を採用する。詳細は [permissions-and-sharing.md](../architecture/permissions-and-sharing.md) の 5 節。

- キャッシュは、主体のキー・ページの ACL の元（`src`）と項目・判定の結果の 3 つ。S1 は API のプロセスの中に置く。
- `acl_version` を上げる変更の一覧を持つ（同じ文書の 5.2 節）。ブロックの編集・ブロックの移動では上げない。ブロックの権限は、判定のたびに読む `page_id` で決まるため。
- Sync Gateway・検索・クライアントのローカルの保存へは、outbox の `acl.changed` で伝える（[collaboration.md](../architecture/collaboration.md)）。
- `acl_version` は検索の「権限のバージョン」と同じ値を使う。
- 1 は、1 回の画面の表示で、何百ものブロック・メンション・ロールアップの行を判定するとき、DB の読み取りが増えすぎる。
- 2 は、消し漏れが漏洩になる。移動と共有が同時に起きたときの正しさを示しにくい。

## Consequences

- 良くなること：
  - 取り消しが、次の要求から必ず効く。キャッシュの消し漏れがない。
  - 正しさの議論が「バージョンが同じなら入力が同じ」の 1 点になる。
- 悪くなること、引き受けるコスト：
  - ワークスペースのどこかで権限が変わると、そのワークスペースのキャッシュがすべて無効になる。共有や移動の多い大きなワークスペースで、ヒット率が落ちる。ミスのときの読み取りは、索引を使う 1 回の問い合わせで済ませる。
  - `acl_version` の行が、権限の変更をワークスペースの中で直列にする。S2 で競合が問題になれば、分け方（チームスペースごとのバージョンなど）を新しい ADR で決める。

## Confirmation

- 性質ベーステスト：任意の権限の変更と読み取りの並行の列で、変更の確定の後に始まった読み取りは、変更後の権限で判定される。
- lint・レビュー：5.2 節の変更をする書き込みの関数が、`acl_version` を上げる共通の関数を通る。
- メトリクス：キャッシュのヒット率と、ミスのときの判定の時間（[observability.md](../architecture/observability.md)）。
