# ADR-0025: Webhook は中身を含まない署名付きのイベントを、配送の時点の権限で、隔離した egress から送る

## Context

連携は、ページ・データベース・コメントの変化を知りたい。本家の Webhook は次の形である（[Webhooks](https://developers.notion.com/reference/webhooks)、[Event types & delivery](https://developers.notion.com/reference/webhooks-events-delivery)、2026-09-26 に確認）。

- 登録した URL に `verification_token` を送り、開発者がそれを入れると有効になる。以後は、そのトークンで本文の HMAC-SHA256 を取り、`X-Notion-Signature` に付ける。
- イベントは ID・種類・親などのメタデータだけで、内容は API で取りに行く。頻繁な変更（`page.content_updated` など）はまとめて送る。
- 連携が対象を読めるときだけ送る。コメントのイベントはコメントの読み取りの能力を要する。
- 5 分以内（多くは 1 分以内）に届け、最大 8 回、約 24 時間まで再試行する。順序は保証しない。

送り先は開発者が決める任意の URL で、SSRF の危険がある。

## Options

1. **中身を含まないイベントを、配送の時点の権限で判定し、署名して、隔離した egress から送る**（本家に寄せる）
2. **ページの内容をイベントに含めて送る**
3. **イベントの発生の時点で権限を判定し、そのまま送る**

## Decision

1 を採用する。詳細は [api-and-integrations.md](../architecture/api-and-integrations.md) の 6 節にある。

- **中身を含めない。** 2 は、共有を外した後に届く再試行が、読めなくなった内容を運ぶ。また、まとめたイベントの内容のバージョンがずれる。
- **配送の時点で判定する。** 再試行を含め、送る直前に `can(bot, read, entity)` と能力を確かめる。3 は、共有を外した後の再試行で、ページの ID と種類が漏れる。
- **署名**：`verification_token` による HMAC-SHA256 を `X-<Brand>-Signature` に付ける（リポジトリ共通の ADR-0006）。受け手は定数時間で比べる。
- **まとめ**：ページ単位で 30 秒の窓でまとめる。ロックとコメントはまとめない。
- **配送**：少なくとも 1 回、順序は保証しない。5 秒のタイムアウト、最大 8 回、最後は約 24 時間後。3 日続けて失敗した購読は停止する。
- **隔離した egress**：配送の Worker が署名し、VPC に接続しない権限のない Lambda が送る。名前解決の後の IP を検査し、リダイレクトは追わない（Slack の app-egress と同じ形）。署名の秘密は Lambda に渡さない。

## Consequences

- 良くなること：
  - 共有の取り消しが、Webhook にも即時に効く。
  - Webhook の本文から内容が漏れない。受け手のログに内容が残らない。
  - 内部のネットワークを踏み台にされない。
- 引き受けるコスト：
  - 受け手は、イベントのたびに API を呼ぶ。その呼び出しもレート制限の対象になる。
  - まとめの窓の分、通知が遅れる。
  - egress の Lambda の同時実行と、連携ごとの上限を運用する。

## Confirmation

- 結合テスト：共有を外した後の再試行が送られない。コメントの読み取りの能力のない連携に、コメントのイベントが送られない。
- 結合テスト：署名が本文と `verification_token` から検証できる。
- SSRF：Slack の ADR-0016 と同じ宛先の一覧（プライベート・リンクローカル・メタデータ・リダイレクト）に送らない。
- 指標：配送の遅れの p95・p99、失敗率、egress での拒否の数。
