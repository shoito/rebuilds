# ADR-0024: 公開 API は本家の形と日付のバージョンに寄せ、連携は明示的に共有されたページだけを読む

## Context

intent.md は、公開 API と Webhook を MVP に含める。連携と AI エージェントが、ページとデータベースを読み書きする。

決めることは 2 つある。

- API の形とバージョン：本家は、ページ・ブロック・データベース・データソース・利用者・コメント・検索のリソースを持ち、`Notion-Version: YYYY-MM-DD` のヘッダーを必須にしている。バージョンは互換性を壊す変更のときだけ出す（[Versioning](https://developers.notion.com/reference/versioning)。最新は 2026-03-11）。
- 連携の権限：本家の連携（コネクション）は、ワークスペースのメンバーの権限を持たず、ページの共有の設定で明示的に加えられたページと子孫だけを読める。公開の連携は、OAuth の認可の画面でページを選ぶ（[Authorization](https://developers.notion.com/docs/authorization)）。その上に能力（読み取り・更新・挿入、コメント、利用者の情報）を重ねる（[Capabilities](https://developers.notion.com/reference/capabilities)）。

Slack の先例は、`/v1` のパスのバージョンと、スコープによる権限にしている（Slack の ADR-0030）。

## Options

API の形とバージョン：

1. **本家のリソースの形に寄せ、日付のバージョンのヘッダー（`<Brand>-Version`）を必須にする**
2. **Slack と同じく、パスのバージョン（`/v1` → `/v2`）だけにする**

連携の権限：

- A. **連携を ACL の主体（`bot`）にし、明示的に共有されたページと子孫だけを読ませる。能力を上限として重ねる**
- B. **連携を導入した人の権限で動かす**
- C. **スコープだけで決め、ワークスペース全体を読ませる**

## Decision

1 と A を採用する。詳細は [api-and-integrations.md](../architecture/api-and-integrations.md) にある。

- **バージョン**：パスは本家と同じ `/v1` のまま、`<Brand>-Version: YYYY-MM-DD` を必須にする（リポジトリ共通の ADR-0006 のとおり、ヘッダー名は本家のものを使わない）。追加は全バージョンに入れ、壊す変更だけ新しいバージョンにする。バージョンの違いは、ハンドラーの外の変換層で吸収する。2 は、ブロックの種類やプロパティの形の小さな変更のたびに、全体のバージョンを上げることになる。
- **リソース**：本家と同じく、データベース（入れ物）とデータソース（表）を分ける。検索は本家と同じくタイトルだけにし、全文検索は MCP で出す。
- **連携の権限**：
  - 連携は、判定関数（ADR-0004）の主体の 1 つ `bot:{integration_id}` になる。共有の設定・継承・取り消しは、人と同じ規則で効く。
  - 連携の水準は、共有の水準と能力の小さい方。
  - 内部の連携はワークスペースの所有者だけが作れる。公開の連携は OAuth 2.1 で、認可する人が全権限を持つページだけを選べる。
  - B は、導入した人が読めるものすべて（非公開のページを含む）が連携に届き、導入した人が抜けると連携が止まる。人の権限の委任は、MCP（ADR-0026）で扱う。
  - C は、1 つの連携の漏洩が、ワークスペース全体の漏洩になる。
- 個人のアクセストークン（本家は 2026-05 に追加）は、MVP では持たない。

## Consequences

- 良くなること：
  - 連携が読める範囲が、ページの共有の画面で見え、人と同じ方法で取り消せる。
  - 本家の API に慣れた開発者が、同じ考え方で使える。
  - 判定関数・検索の権限キー・Webhook の配送の判定が、連携にもそのまま使える。
- 引き受けるコスト：
  - バージョンの変換層を保守する。古いバージョンを長く保つ負担がある。
  - 連携を使うたびに、ページを共有する手間が利用者にかかる（本家と同じ）。
  - 本家の SDK はそのまま使えない。公式の SDK を用意する（リポジトリ共通の ADR-0006）。

## Confirmation

- 性質ベーステスト：任意の木・共有の設定・移動の列で、連携が API で読めるページの集合が、`can(bot, read, page)` が真の集合と一致する。
- 漏洩テスト：共有されていないページを、取得・子の一覧・問い合わせ・検索・リレーション・ロールアップ・Webhook で返さない。
- バージョンごとの入出力のスナップショットを CI で比べ、既存のバージョンの応答が変わらない。
- レビュー：ヘッダー名・トークンの接頭辞に、本家の名前が残っていない。
