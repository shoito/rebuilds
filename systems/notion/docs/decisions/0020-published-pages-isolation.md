# ADR-0020: 公開ページは別の登録可能ドメインで、専用の描画サービスから配り、既定で検索エンジンに載せない

## Context

Web への公開は、ワークスペースの外の、ログインしていない人にページを見せる。本家は `notion.site` のドメインで配り、子のページも既定で公開し、「Discoverable on the web」を有効にしたときに検索エンジンに載る。Enterprise は公開を禁止でき、禁止すると公開中のサイトも取り下げる（[Publish a website with Notion Sites](https://www.notion.com/help/public-pages-and-web-publishing)、2026-09-26 に確認）。

公開ページは、だれでも作れる内容を匿名に配る。次の危険がある。

- アプリと同じオリジンで配ると、アプリの Cookie・API・ローカルの保存に近い場所で、第三者が書いた内容が動く。
- アプリのドメインの信用を借りたフィッシングに使われ、アプリのドメインがブロックリストに載ると、全利用者が影響を受ける。
- 公開していない子孫やメンション先が、公開の描画に混ざる。

## Options

1. **アプリと同じオリジン** で、アプリのクライアントを匿名で動かして見せる
2. **アプリと同じ登録可能ドメインのサブドメイン**（`sites.<domain>`）で配る
3. **別の登録可能ドメイン**（`<brand>.site`）で、サーバーで描画した HTML を配る。Public Suffix List に登録し、ワークスペースごとのサブドメインを別のサイトにする

## Decision

3 を採用する。詳細は [permissions-and-sharing.md](../architecture/permissions-and-sharing.md) の 7〜8 節と [security.md](../architecture/security.md) の 3.4・8 節。

- 公開サイトの描画は専用のサービスが行い、`public` の主体で 1 ブロックずつ判定関数を通す。アプリのスクリプトを読み込まない。
- 検索エンジンへの掲載は既定で無効（`X-Robots-Tag: noindex`）。所有者が有効にしたときだけ外す。
- 共有のリンク（「リンクを知っているウェブ上の全員」）も、ログインしていない閲覧者には公開サイトのオリジンで見せる。アプリのオリジンは、ログインした人だけに内容を見せる。
- 取り下げは CDN を無効化し、1 分以内に反映する。
- 名前は repo の [ADR-0006](../../../../docs/decisions/0006-brand-neutral-identifiers.md) に従い、実際のドメインは開発リポジトリの作成時に決める。
- 1 は、XSS が 1 つあれば、公開ページを開いたログイン中の利用者のセッションで API を呼べる。
- 2 は、同じサイト（same-site）になり、`SameSite` の Cookie の保護が効かない。ドメインの評判もアプリと共有する。

## Consequences

- 良くなること：
  - 公開の内容とアプリのセッション・評判を分けられる。フィッシングで公開サイトのドメインが止められても、アプリは動く。
  - 公開の範囲の判定が描画サービスの 1 か所に集まり、試験しやすい。
- 悪くなること、引き受けるコスト：
  - ドメインを 2 つ運用し、Public Suffix List への登録を待つ必要がある。
  - アプリと別の描画の実装（サーバーでの HTML の生成）を持つ。ブロックの種類を増やすたびに両方を直す。
  - ログインしていない閲覧者の体験が、本家（アプリの中で見られる場合がある）と違いうる（未検証）。

## Confirmation

- 性質ベーステスト：任意の木と公開・制限の設定で、公開サイトの HTML に、`public` で読めないブロックの中身が現れない。
- 結合テスト：公開サイトの応答の `noindex` の既定、CSP、アプリの API の CORS が公開サイトのドメインを許可しないこと。
- 結合テスト：取り下げから 1 分以内に、CDN を含めて 404 になる。
