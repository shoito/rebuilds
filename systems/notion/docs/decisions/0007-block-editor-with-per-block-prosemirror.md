# ADR-0007: ブロックの層は自前で作り、ブロックの中のテキストの編集に ProseMirror を使う

## Context

エディタは、ブロックの木（ADR-0002）を直接編集する。次を満たす必要がある。

- ブロック単位の操作（並べ替え、インデント、種類の変更、同期ブロック、子ページ）を、ADR-0005 の操作のトランザクションにそのまま写せる。
- 1,000 ブロックのページを p75 1.5 秒で表示し（NFR-002）、10 万ブロックのページも開ける。画面の外のブロックを DOM に置かない仮想化が要る。
- 同期ブロックの中身は別のページの部分木で、権限もそこで決まる。1 つのページの中に、別のページのブロックが混ざる。
- 日本語の入力（IME）、貼り付け、選択、取り消しが壊れない。

本家のエディタは、ブロックごとに `contenteditable` を持つ自前の実装だと言われるが、公式の文書では確かめられなかった（未検証）。

2026-09-26 に npm で確認した各ライブラリの状態：

| ライブラリ | 版 | 形 |
| --- | --- | --- |
| ProseMirror（`prosemirror-view`） | 1.42 | 1 つの文書と 1 つの `contenteditable`。スキーマ・トランザクション・IME の扱いが成熟。Slack の入力欄で採用済み |
| TipTap（`@tiptap/core`） | 3.x | ProseMirror の上の拡張の仕組み。一部の拡張は有償 |
| Lexical | 0.51 | 1.0 前。1 つのエディタに 1 つの `contenteditable` |
| Slate | 0.12x | 1.0 前。IME・Android での不具合の報告が多い |
| BlockSuite（`@blocksuite/affine`） | 0.22 | ブロック単位の編集。Yjs の文書を正本とし、Web Components（Lit）で描く |

## Options

1. **ProseMirror（か TipTap）の 1 つの文書で、ページ全体を編集する**。ブロックの木を ProseMirror のノードの木に写す
2. **Lexical・Slate の 1 つのエディタで、ページ全体を編集する**
3. **BlockSuite を使う**
4. **ブロックの層を自前で作り、テキストを持つブロックごとに ProseMirror の `EditorView` を置く**
5. **ブロックの層も、ブロックの中のテキストの編集も、すべて自前で作る**（本家に最も近い）

## Decision

4 を採用する。詳細は [editor.md](../architecture/editor.md) の 3・4 節にある。

- 1 は、ページ全体が 1 つの `contenteditable` になり、画面の外のブロックを DOM から外せない。ブロックの操作を ProseMirror の位置の操作に写し、確定した操作を ProseMirror の `Step` に戻す変換が、ページの木の全体に及ぶ。同期ブロックのように、別のページの部分木が混ざる形も扱いにくい。複数のブロックにまたがる選択が標準で使えるのは利点である。
- 2 は、1 と同じ問題に加え、どちらも 1.0 前で、Slate は IME の不具合が多い。
- 3 は、ブロックの正本が Yjs の文書になり、ADR-0002（ブロックの表）と ADR-0005（サーバーが確定する操作）と二重になる。描画が Lit で、React のクライアントと混ざる。
- 5 は、IME・スペルチェック・選択・貼り付けの扱いを一から作ることになり、小さなチームでは不具合の量が読めない。
- 4 は、ブロックの木をそのまま React で描くので、ブロックの操作・仮想化・同期ブロック・権限の表示を自由に作れる。テキストの編集の難しいところ（IME、選択、入力の規則、取り消しの粒度）は ProseMirror に任せられる。ProseMirror の文書はブロック 1 つ分のテキストだけなので、スパン（ADR-0006）との変換が小さい。
- テキストの編集の部分は `src/editor/inline/` の 1 つの境界（スパンを受け取り、テキストの操作を出す）に閉じる。5 へ移す必要が出たら、この境界の中身だけを差し替える。

> 2026-09-27 の注記：Context の「本家はブロックごとに `contenteditable` を持つ」は、2026-09-27 にも公式の文書で確かめられなかった。本家の公式の記録には、テキストのエディタを作り直したという更新の記録（[Release 2022-01-19](https://www.notion.com/releases/2022-01-19)）しかない。未検証のまま残す。決定は本家の実装に依存しないので、変えない。

## Consequences

- 良くなること：
  - エディタの操作と ADR-0005 の操作が 1 対 1 に近くなり、同時編集・履歴・取り消しを操作の単位で扱える。
  - 画面に見えるブロックだけを描けるので、巨大なページを開ける。
- 引き受けるコスト：
  - ブロックの間のカーソルの移動、ブロックの選択、コピー・貼り付けを自前で作る。
  - 複数のブロックにまたがる部分的なテキストの選択は、MVP では作らず、ブロックの選択に切り替える。
  - `EditorView` を多数作ると重い。画面の近くのブロックだけに遅れて作り、それまでは静的に描く（[editor.md](../architecture/editor.md) の 4.3 節）。静的な描画と ProseMirror の描画の見た目を一致させる試験が要る。
  - テキストの同時編集の統合を ProseMirror の外（[collaboration.md](../architecture/collaboration.md)）で行い、確定した変更を ProseMirror の文書に当てる処理を持つ。`y-prosemirror` のような既製の結合は使えない。

## Confirmation

- E3 の着手前に PoC で計測する：1,000 ブロックのページの表示が NFR-002 に収まること、`EditorView` の生成の費用、Safari・Firefox での IME。
- 部品のテスト（Chromium / Firefox / WebKit）：IME の確定の `Enter` でブロックが分割されない。静的な描画から ProseMirror への差し替えの前後で、見た目とカーソルの位置が変わらない。
- lint：`src/editor/inline/` の外から ProseMirror を import しない。
