# ADR-0013: オフラインで使うページを理由ごとに記録して決め、Web とデスクトップで SQLite に保存する

## Context

MVP は「開いたことのあるページの閲覧と編集、再接続時の統合」を含む（[intent.md](../intent.md)）。モバイルのネイティブアプリは作らず、Web（PWA）とデスクトップ（Web を包む）で提供する。

本家は、オフラインをデスクトップとモバイルのアプリだけで提供する。対象は、利用者が明示したページと、有料プランでは最近開いたページとお気に入り。データベースは最初のビューの先頭 50 行を含め、子ページは含めない（[ヘルプ](https://www.notion.com/help/use-pages-offline)）。端末では SQLite を持続的な保存にし、`offline_page` と、残す理由を持つ `offline_action` の表で管理し、最後の理由が消えたときだけページを外す（[How we made Notion available offline](https://www.notion.com/blog/how-we-made-notion-available-offline)）。Web では、WASM の SQLite を OPFS に置いている（[How we sped up Notion in the browser with WASM SQLite](https://www.notion.com/blog/how-we-sped-up-notion-in-the-browser-with-wasm-sqlite)）。

決めること：

- どのページをオフラインで使えるようにするか。
- どこに、どれだけ保存するか。

## Options

### 対象

1. 開いたことのあるページをすべて持つ
2. **理由（明示、最近開いた、お気に入り、データベースからの継承）ごとに記録し、上限の中で持つ**
3. ワークスペース全体を持つ

### 保存

A. IndexedDB（Slack の [ADR-0024](../../../slack/docs/decisions/0024-client-data-layer-and-offline.md)）
B. **SQLite。Web は WASM＋OPFS、デスクトップはネイティブ**

## Decision

対象は 2、保存は B を採用する。詳細は [collaboration.md](../architecture/collaboration.md) の 11 節。

- 理由は、明示、最近開いた（直近 30 日の 50 ページ）、お気に入り、データベースからの継承（最初のビューの先頭 50 行）の 4 つ。子ページは含めない。本家と同じ範囲にする。
- プランによって変えない（プランの区別は MVP で決めていない）。
- Web でもオフラインを提供する。本家と違うが、この再構築では Web が主のクライアントだからである。
- 上限は、ワークスペース・端末ごとに 2,000 ページ、合計 1GB。超えたら「最近開いた」を古い順に外す。明示とお気に入りは自動で外さない。
- 1 を採らない理由：端末の容量と、鮮度を保つための照合の量が際限なく増える。3 は、大きなワークスペースで端末に収まらず、読める範囲の判定を端末に持ち込むことになる。
- SQLite にする理由：データベースのビューの絞り込み・並べ替えを、オフラインでも SQL で行える。本家が Web とアプリの両方で同じ形を使っている。書き込みは Web Locks で選んだ 1 つのタブの専用ワーカーだけが行う（OPFS の同期アクセスは専用ワーカーでしか使えないため）。OPFS が使えないブラウザでは、オフラインを無効にする。
- 鮮度は、オフライン用のページを購読せず、10 分ごとと再接続時に `(page_id, seq)` をまとめて照合して保つ。

## Consequences

- 良くなること：
  - 利用者が、どのページがオフラインで使えるかを予測できる。理由ごとに持つので、ある理由を外しても、他の理由で残すページを誤って消さない。
  - ビューの問い合わせをオフラインでも動かせる。
- 引き受けるコスト：
  - WASM の SQLite の読み込み（初回の表示の遅れ）と、タブ間の書き込みの調整を持つ。
  - Safari は、ホーム画面に追加していないサイトのデータを 7 日で消しうる。未送信の変更を失う危険を、警告で知らせる。
  - OPFS の対応状況（特に Safari の版）と、WASM の SQLite の容量の上限は **未検証**。E4 の着手前に、各ブラウザで PoC をする。
  - 子ページを含めないので、利用者は必要なページを 1 つずつオンにする必要がある。

## Confirmation

- 性質ベーステスト：任意の理由の追加・削除の列で、ページが端末に残ることと「理由が 1 つ以上ある」ことが一致する。
- Playwright（Chromium / Firefox / WebKit）：オフラインにして、明示したページとデータベースの先頭 50 行を開いて編集でき、再接続で送られる。複数のタブを開いても SQLite が壊れない。
- 上限を超えたとき、「最近開いた」から外れ、明示とお気に入りが残る。
