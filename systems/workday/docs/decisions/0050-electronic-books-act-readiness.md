# ADR-0050: 電子帳簿保存法の対象になりうる給与の記録に、最低限の要件と優良な電子帳簿に相当する機能を持たせ、当てはめはテナントと税理士に委ねる

詳細は [audit-and-retention.md](../architecture/audit-and-retention.md) の 7 節。

## Context

- intent の L5 は、源泉徴収簿や給与計算のデータが電子帳簿保存法の対象になるかを確認待ちにしている。
- [国税庁 電子帳簿保存法一問一答【電子計算機を使用して作成する帳簿書類関係】](https://www.nta.go.jp/law/joho-zeikaishaku/sonota/jirei/pdf/03-2.pdf)（令和 7 年 6 月）によると（2026-09-28 に確認）：
  - 電子計算機で一貫して作る国税関係帳簿書類は、要件の下で電磁的記録で保存できる。
  - すべての帳簿・書類に、システムの概要書などの備付けと見読可能装置の備付けが要る。優良以外の帳簿は、ダウンロードの求めに応じることが要る。
  - 優良な電子帳簿は、訂正・削除・追加の事実と内容を確認できるシステム、帳簿間の相互関連性、検索の機能を要る。
  - 電子取引の保存の義務は、源泉徴収に係る所得税を除く所得税と、法人税の保存義務者が対象とされる。
- 本システムの給与の結果は、確定の後に書き換えず、取消・遡及の差額・逆仕訳で直す（[ADR-0004](0004-payroll-engine.md)）。仕訳は実行の段と結ぶ（[ADR-0037](0037-payroll-journal-export.md)）。多くの要件は、すでに設計に入っている。
- 国税庁の源泉徴収簿は、源泉徴収の事務の便宜のために国税庁が作った様式で、法令で定められたものではない。毎月の源泉徴収の記録が分かり、年末調整に使える給与台帳などで代えてよい（[国税庁 A2-2 源泉徴収簿の作成](https://www.nta.go.jp/taxes/tetsuzuki/shinsei/annai/gensen/annai/1648_03.htm)、2026-09-28 に確認）。本システムの給与の結果が国税関係帳簿に当たるかの当てはめは、テナントと税理士が行う（L5）。

## Options

1. **対象になりうる記録に、最低限の要件と優良に相当する機能を持たせ、要件の対応表と事務処理の規程の雛形を出す。当てはめはテナントと税理士が行う**
2. 対象でないと判断して、何も持たない
3. 優良な電子帳簿としての適合を、本システムが表明する

## Decision

1 を採用する。

- 概要書・操作説明書：リリースごとに公開し、バージョンを残す（[delivery.md](../architecture/delivery.md) の 7 節）。
- 見読：画面と PDF。
- ダウンロードの求め：期間・従業員・項目の条件で、給与の記録と仕訳を CSV で出す一括の出力。
- 訂正・削除の履歴：確定した結果を書き換えない設計と、監査の画面。
- 相互関連性：仕訳の行 → 実行と段 → 結果の行 → 入力の文書のハッシュ。
- 検索：支給日・金額・従業員で、範囲と組み合わせの条件。
- 2 を採らない理由：対象になると判断されたときに、後から要件を満たすのは難しい（特に訂正・削除の履歴）。設計の中にほとんどあるので、追加の費用は小さい。
- 3 を採らない理由：当てはめは税理士の判断で、システムは結論を出さない（[AGENTS.md](../../AGENTS.md)）。JIIMA などの認証を取るかは、需要を見て MVP の後に決める。

## Consequences

- 良くなること：
  - テナントが給与の記録を電子で保存すると決めたとき、そのまま使える。
  - 税務の調査の出力の手順が決まる。
- 引き受けるコスト：
  - 概要書と操作説明書をリリースごとに保守する。
  - 源泉徴収簿の扱い（L52）と、優良の要件の当てはめ（L55）は確認待ち。確認まで E12 の `ebooks-act-readiness` の spec を承認しない。

## Confirmation

- 結合テスト：同じ条件のダウンロードの出力が、画面の検索と同じ行を返す。確定した結果を変える API がない（書き換えの試みが拒まれる）。
- レビュー：リリースのチェックリストに、概要書・操作説明書の更新の有無を入れる。
