# ADR-0045: マイナンバーの入力と本人確認は保管庫が配る画面で受け、方法と確認した人を記録する

詳細は [my-number-vault.md](../architecture/my-number-vault.md) の 4 節。

## Context

- 本人から番号の提供を受けるときは、本人確認（番号法 16 条）が要る。方法は、個人番号カード、または番号確認書類と身元確認書類の組み合わせなどで、法令と利用事務実施者が認める方法による（[特定個人情報の適正な取扱いに関するガイドライン（事業者編）](https://www.ppc.go.jp/legal/policy/my_number_guideline_jigyosha/) の第 4-3-(4)、令和 7 年 6 月一部改正のバージョンを 2026-09-28 に確認）。
- 番号の平文は保管庫の外に出さない（[ADR-0005](0005-security-and-my-number.md)、[AGENTS.md](../../AGENTS.md)）。人事の SPA と API が番号を受けると、その経路（ブラウザのメモリー、API のログ、トレース、WAF のログ）が特定個人情報の安全管理の範囲に入る。
- 本人確認の書類の画像も特定個人情報を含む。保存するか、いつ消すかは確認待ち。
- 扶養の親族の番号は、従業員が扶養控除等申告書に書いて出す。この番号は従業員が個人番号関係事務実施者として本人確認を行い、事業者には本人確認の義務がない（[個人情報保護委員会の Q&A](https://www.ppc.go.jp/legal/policy/faq/) の Q6-2-2）。国民年金の第 3 号被保険者の届出は、第 3 号被保険者本人が事業者に出すもので、従業員は代理人として出す（同 Q1-12）。どちらも 2026-09-28 に確認。

## Options

入力の経路：

1. **保管庫が配る画面（別のオリジン、保管庫のアカウントの ALB）で受ける。人事の SPA と API を通さない**
2. 人事の SPA で入力し、人事の API が保管庫へ中継する
3. 紙で受け、事務取扱担当者が保管庫の画面で入力する

確認の画像：

- a. **保管庫の S3 に置き、事務取扱担当者の確認の後 30 日で消す（既定）。確認の記録（方法、書類の種類、確認した人、時刻）は残す**
- b. 画像を保存しない（確認の記録だけ）
- c. 画像を保存の期間の間残す

## Decision

1 と a を採用する。3 は、画面を使えない人の例外の経路として持つ（事務取扱担当者が代わりに入力し、代わりに入力したことを記録する）。

- 画面は `mn.<tenant>.<brand>.<domain>`。人事のセッションから、保管庫のセッション（10 分）に引き換えて開く。引き換えは、人事の側が署名した主張（[ADR-0046](0046-purpose-bound-vault-api-and-access-log.md)）で行う。
- 入力の前に、テナントが登録した利用目的の通知の文面を出し、表示したバージョンを記録する。
- 番号はチェックデジットを画面とサーバーの両方で確かめる。重複はテナントの HMAC で検知する。
- 本人確認の方法は `mn_card`、`number_doc_and_id_doc`、`id_known_by_employment` から選ぶ。システムは方法の正しさを判定せず、事務取扱担当者の確認の操作を記録する。
- 扶養の親族の番号は、従業員が同じ画面で入れる。親族の本人確認の要否は、事務ごとの確認の結論を待つ。
- 2 を採らない理由：人事の側の経路全体（ブラウザ、API、ログ、WAF）が特定個人情報の範囲に入り、[ADR-0005](0005-security-and-my-number.md) でアカウントを分けた意味が薄れる。
- b を既定にしない理由：確認の操作の後に、書類の不備が分かったときに確かめ直せない。30 日で消せば、長く持つ危険は小さい。確認の結論で b に変えられる形にする。
- c を採らない理由：本人確認の書類の写しを保管する法令上の義務はなく、保管するなら安全管理措置が要り、不要になった段階で速やかに廃棄するよう案内されている（[個人情報保護委員会の Q&A](https://www.ppc.go.jp/legal/policy/faq/) の Q6-2・Q6-2-2、2026-09-28 に確認）。持つほど漏えいの影響が大きい。

## Consequences

- 良くなること：
  - 番号が、入力の時点から保管庫のアカウントの中だけを通る。
  - 本人確認の経緯を、方法と確認した人で後から示せる。
- 引き受けるコスト：
  - 保管庫のアカウントに画面の配信（CloudFront、WAF、ALB）が要る。
  - 利用者が別のオリジンに移る。画面の案内が要る。
  - 画像の保存と削除の期間、親族の本人確認、身元確認の省略は確認待ち（L44〜L46）。確認まで E11 の `mn-collection-and-verification` の spec を承認しない。

## Confirmation

- CI：人事の側のパッケージ（SPA、API、Worker）のコード・フィクスチャーに、番号の入力の欄や個人番号の形が現れない。
- 結合テスト：番号の登録が人事の API を通らない（人事の API のアクセスの記録に該当の要求がない）。チェックデジットの誤りと重複を拒む。
- 本番：`registered` のまま 30 日を超えた件数を、テナントの事務取扱責任者に知らせる。
