# ADR-0009: 有効日付の実装を、純粋な参照のモデルとのモデルベーステストで確かめる

詳細は [object-model-and-effective-dating.md](../architecture/object-model-and-effective-dating.md) の 12 節。

## Context

[ADR-0002](0002-effective-dated-data-model.md) は、有効日付に性質ベーステスト（期間が重ならない、時点の問い合わせが再現できる、訂正と取消の後も過去の知識が変わらない）を求めた。[AGENTS.md](../../AGENTS.md) も fast-check を使うと決めている。

性質を個別の検査（例：重なりがない）だけで書くと、「結果が正しい」ことまでは確かめられない。畳み込み・訂正・取消・時点の問い合わせの組み合わせは広く、例のテストでは覆えない。

## Options

1. **純粋な参照のモデル（全差分をメモリーに持ち、問い合わせのたびに畳み込む）を正解にし、DB の実装と同じ操作の列の結果を比べる（fast-check のモデルベーステスト）**
2. 性質を個別の不変条件だけで書く
3. 例のテストと決定表だけにする

## Decision

1 を採用し、2 の不変条件と決定表も併せて持つ。

- `fold` を純粋な関数にし、DB の書き込みの経路と参照のモデルの両方で使う。参照のモデルは、版・現在のテーブル・ロックを持たず、時刻 T の問い合わせに「T までに記録された差分」を畳み込んで答える。
- fast-check の `commands`（[Model based testing](https://fast-check.dev/docs/advanced/model-based-testing/)、2026-09-28 に確認）で、変更・過去日付の変更・訂正・取消・終わり・再開・時点の問い合わせの操作を生成し、Testcontainers の PostgreSQL 18 と参照のモデルに同じ列を入れて比べる。
- `fold` 自体の正しさは、参照のモデルとは別の書き方の小さな実装（日ごとの状態の表を作る素朴な方法）と比べる。同じ誤りを両方に入れないため。
- 性質は PROP-TEMP-001〜009。CI は 1 性質 500 回、夜間は 20,000 回。失敗の種と縮めた列を回帰のテストに残す。
- 本番では、夜間に 1% の主体を抜き取り、差分から参照のモデルで畳み込み直して版と比べる（NFR-002）。
- 2 だけを採らない理由：重ならない・空でないは満たすが、値が誤っている実装を見逃す。
- 3 を採らない理由：組み合わせが広すぎる。

## Consequences

- 良くなること：
  - DB の実装の最適化（影響の始まりの日から後だけを作り直す、coalesce）が、素朴な正解と一致することを機械的に確かめられる。
  - 本番の検査に同じ参照のモデルを使える。
- 引き受けるコスト：
  - Testcontainers の DB を使う性質ベーステストは遅い。CI の時間を 1 性質あたり数十秒に収めるため、生成器の大きさを抑える（主体 3、日付の窓 60 日）。
  - 参照のモデルと `fold` を共有する部分に誤りがあると、両方が同じく誤る。素朴な実装との比較で補う。

## Confirmation

- CI：PROP-TEMP-001〜009 のテストが、要件 ID を名前に含んで存在し、毎回走る。
- レビュー：新しい facet や操作を足す変更は、生成器にその操作を足していることを確かめる。
- 本番：夜間の抜き取りの検査の食い違い 0 件。
