# ADR-0019: 職務分掌を範囲つきの規則表で持ち、有効化・所属の変更・案件の操作・夜間の走査の 4 か所で検査する

詳細は [security-model.md](../architecture/security-model.md) の 5 節。

## Context

[ADR-0005](0005-security-and-my-number.md) は、既定の職務分掌の規則表（両立しない権限の組）を持ち、テナントが足せ、反する割り当ては権限の有効化のときに拒むと決めた。[ADR-0003](0003-business-process-engine.md) は、同じ案件で起票と承認をしないことを、委任の後の実際の操作者で判定すると決めた。

残っている論点は次のとおり。

- 権限は、方針の有効化だけでなく、所属・ロールの割り当ての変更と、職務・所属の変更（職務や組織で決まるグループ）でも変わる。有効化のときだけの検査では、異動で生まれた違反を見逃す。
- 「両立しない」の範囲。会社 A の給与の確定と、会社 B の給与の変更を持つ人は、統制の上で問題か。
- 違反を止めるか、警告にとどめるか。
- 本家は職務分掌の潜在的な衝突の報告を持つ（検索の要約による。中身は未検証。[Security Policy Configuration and Activation](https://doc.workday.com/workday-education/en-us/course-manuals/security-for-administrators/security-policy-configuration-and-activation.html)、2026-09-28 に確認）。

## Options

検査の場所：

1. **方針の有効化、所属・ロール・職務・所属の組織の変更の完了、案件の操作、夜間の走査の 4 か所**
2. 方針の有効化と案件の操作だけ
3. 夜間の報告だけ

範囲：

- a. **A と B の範囲（根の組織の下位）が重なるときだけ違反とする**
- b. 範囲を問わず、両方を持てば違反とする

## Decision

1 と a を採用する。

- 規則は（権限 A、権限 B、範囲の条件、強さ）の行。システムの規則（給与の変更と給与の確定、他人の振込先の承認と振込の承認、方針の編集と有効化、給与の個別の調整と確定、定義の編集と有効化、所属・ロールの変更の起票と承認）は止める強さで、例外を作れない。テナントの規則は止めるか警告かを選べる。
- 範囲の条件は「重なるとき」か「常に」。重なるとは、A と B の根の組織の下位に、今日共通の組織があること。`all` はすべてと重なる。
- 検査点（DT-SEC-002）：
  1. 方針の有効化：新しいバージョンで全員を検査し、止める違反があれば有効化を拒む。
  2. 所属・ロール・職務・異動の案件の完了：所属が変わる人を検査し、止める違反があれば完了を拒む。
  3. 案件の操作：起票者と承認者の一致と、案件の対象の範囲で両立しない権限を、実際の操作者と委任した人で検査する。
  4. 夜間の走査：抜けた違反を報告する。権限は自動では外さない。
- 規則表は方針のバージョンの一部として有効化する。
- 2 を採らない理由：職務や組織で決まるグループは、異動・昇格の完了で暗に変わり、方針の有効化を経ない。
- 3 を採らない理由：違反の権限で操作が行われた後に気づく。
- b を採らない理由：グループ会社の多いテナントで、別の会社の担当を兼ねる人の正当な割り当てが、すべて違反になる。統制の目的（同じお金の流れを 1 人で完結させない）は、範囲の重なりで表せる。

## Consequences

- 良くなること：
  - 違反の権限を持つ状態が、方針・所属・職務のどの経路でも作られにくい。
  - 案件ごとの検査で、残った違反があっても、その案件での不正な承認は止まる。
- 引き受けるコスト：
  - 異動の完了が、職務分掌の違反で止まることがある。起票者に理由と直し方を示す必要がある。
  - 範囲の重なりの判定が、組織の再編で変わる。夜間の走査で拾う。

## Confirmation

- 決定表のテスト：DT-SEC-002、規則表の各行（両立しない割り当ての有効化・所属の変更が拒まれる）。
- 性質ベーステスト：PROP-SEC-004（任意の列の後、止める規則の違反を持つ利用者がいない）、PROP-BP-003（起票者と承認者の一致がない）。
- 本番：夜間の走査の違反の件数と、解消までの日数。
