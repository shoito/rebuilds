# ADR-0043: 移行は履歴を「移行」の差分として取り込み、本番の開始日より前に遡及を出さず、並行稼働は現行の入力も取り込めるようにする

詳細は [integrations-and-bulk.md](../architecture/integrations-and-bulk.md) の 4・5 節。

## Context

- [architecture/README.md](../architecture/README.md) の 6 節は、移行で履歴（過去の所属・給与・年休の残り・社会保険の等級）が欠けると、有効日付と遡及の前提が崩れるとした。
- 移行で入れる過去の差分は、有効日が過去で、記録の時刻は取り込みの時刻になる。遡及の検知（[ADR-0028](0028-retro-deltas-and-bonus-runs.md)）は、確定した期間にかかる過去日付の変更を候補にする。本番の前の期間には本システムの確定した結果がない。
- 年の途中で切り替えると、源泉所得税・社会保険料・支給の年の累計、標準賞与額の年度の累計（健康保険の上限）、36 協定の対象期間の累計が要る。
- 並行稼働（[ADR-0029](0029-parallel-run-and-compute-partitioning.md)）の差は、計算の差と、入力（勤怠）の差が混ざる。入力の差で説明の作業が増えると、3 か月の判定（NFR-001、K2）に間に合わない。
- 現行のシステムの本番のデータを、開発・テストの環境に持ち込まない（[AGENTS.md](../../AGENTS.md)）。

## Options

履歴：

1. **現行の履歴を、`migration` の業務プロセスの種類の差分として、有効日の順に取り込む。記録の時刻は取り込みの時刻。給与のグループごとの `go_live_on` より前の期間に遡及の候補を作らない**
2. 現時点の値だけを入れ、履歴は持たない
3. 履歴を、記録の時刻も過去に書き換えて取り込む

期首の値：

- a. **種類ごとの台帳に `migrate` の行として入れる（累計、等級、年休、36 協定の累計）**
- b. 移行の月の給与の入力に手で入れる

並行稼働の入力：

- i. **本システムの勤怠の締めか、現行の勤怠の集計の取り込みかを、実行ごとに選べる**
- ii. 本システムの勤怠の締めだけ

## Decision

1、a、i を採用する。

- `migration` の種類は、テナントが `implementing` の間か、本番を始める前の雇用にだけ使える。承認は親の案件の 1 回。実行の権限はテナントの導入の担当に限る。
- `go_live_on` より前の有効日の変更が本番の後に入ったら、「現行の期間の遡及」として給与の担当に示し、差額は個別の調整で扱う（DT-INT-003）。
- 期首の値は `payroll_ytd_opening`、`overtime_ytd_opening`、`leave_ledger_entries`（`migrate`）、`worker_social_insurance` の履歴に入れる。現行の出力と 1 円・1 分・1 日まで一致を確かめる。
- 移行は、同じ本番のアカウントの sandbox のテナントで試し、検証の報告の差が 0 件になってから本番のテナントに入れる。移行のファイルは取り込みの完了から 30 日で消す。
- 並行稼働は、入力の元を実行ごとに選ぶ。2 つの元で 2 回回して差を比べ、`input_diff` と計算の差を分ける。
- 2 を採らない理由：遡及、社会保険の随時改定の候補（3 か月の平均）、年休の付与（勤続の年数）、労働者名簿の履歴が、本番の開始の直後から作れない。
- 3 を採らない理由：「そのときシステムが何を知っていたか」が偽になる（[ADR-0002](0002-effective-dated-data-model.md) の意味を壊す）。
- b を採らない理由：累計が入力の文書の個別の調整に散らばり、年末調整（E13）と上限の計算で毎月参照し直すことになる。
- ii だけにしない理由：並行稼働の差の多くが入力の差になり、計算の正しさの判定が遅れる。

## Consequences

- 良くなること：
  - 本番の開始の直後から、履歴を前提にした計算（遡及、随時改定、付与）が動く。
  - 並行稼働で、計算の誤りを入力の誤りから切り分けられる。
- 引き受けるコスト：
  - 現行のシステムごとに、履歴と期首の値の書き出しの形に合わせた対応表（取り込みの雛形の列の対応）を作る。
  - `go_live_on` より前の遡及は手の調整になる。件数を見て、多ければ別の ADR で扱う。
  - 並行稼働で現行の勤怠を取り込むことの契約上の扱いは法務の確認待ち（[intent.md](../intent.md) の L11）。

## Confirmation

- 決定表のテスト：DT-INT-003。
- 結合テスト：合成の 3 万人の「現行の出力」からの移行で、検証の報告の差が 0 件。移行の差分より前の `known_at` の問い合わせで何も出ない。
- 本番：テナントごとの移行の検証の報告を、本番の開始の判定の記録に残す。
