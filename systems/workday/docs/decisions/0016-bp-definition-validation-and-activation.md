# ADR-0016: 業務プロセスの定義を静的な検査と模擬の実行で確かめ、編集と有効化を別の人に分ける

詳細は [business-process-engine.md](../architecture/business-process-engine.md) の 11 節。

## Context

[architecture/README.md](../architecture/README.md) の 6 節は、テナントの定義の誤り（承認者がいない、無限に差し戻す、職務分掌が崩れる）をリスクに挙げた。[ADR-0003](0003-business-process-engine.md) は、保存の前の検査（到達できないステップ、承認者が決まらないステップ、終わらない差し戻し）と、定義の変更の承認（編集と有効化を別の人にできる）と、模擬の実行を求めた。

本家は、権限の方針の変更を「保留」にし、別の権限で「有効化」する（[Security Policy Configuration and Activation](https://doc.workday.com/workday-education/en-us/course-manuals/security-for-administrators/security-policy-configuration-and-activation.html)、2026-09-28 に確認）。業務プロセスの定義も同じ考え方を当てる。

## Options

検査：

1. **保存のたびの静的な検査（スキーマ、形、上限、式の型、ロールの存在、必須の承認、自分だけの承認、差し戻し先、自動の承認の禁止、補償の有無）と、有効化の前の模擬の実行（代表の組織での担当の決まり方）**
2. 静的な検査だけ
3. 有効化の後の監視だけ（担当が決まらない件数などで気づく）

有効化：

- a. **下書きと有効化を分け、有効化を業務プロセス（`bp_definition_activation`）にし、編集者と承認者を別にする**
- b. 保存で即時に有効にする

## Decision

1 と a を採用する。

- 静的な検査は DT-BP-004 の 12 項目。給与・口座・退職・権限などの種類では、条件なしで必ず通る承認のステップを 1 つ以上求める。承認の自動の処理を禁じる。給与・口座・雇用の日付の訂正を承認なしにする定義は、有効化の画面で明示の確認を求める。
- 直列・並列・条件だけの形と、差し戻しの回数の上限（5 回）で、到達できないステップと終わらない差し戻しは構造上起きない。常に偽の条件は式の定数の畳み込みで警告する。
- 模擬の実行は、下書きの定義をテナントの対象（または合成の対象）に当て、今日の組織で担当と条件の評価を示す。データは書かない。有効化の前に、監督組織の各階層の代表での模擬の実行を必須にし、担当が決まらない組織を一覧にする。
- 有効化は `bp_definition_activation` の業務プロセスで行い、編集者と承認者を別にする（職務分掌の規則表の既定の行）。有効化した版は書き換えず、戻すときは古い版の中身で新しい版を作る。
- 2 を採らない理由：担当が決まるかは、テナントの組織とロールの割り当ての実データに依存し、定義だけからは分からない。
- 3 を採らない理由：誤った定義で進んだ案件（承認なしの給与の変更など）は、後から取り消すしかない。
- b を採らない理由：1 人で承認の流れを外せてしまい、職務分掌の抜け道になる。

## Consequences

- 良くなること：
  - 承認者がいない・自分だけで承認できる定義を、有効化の前に止められる。
  - 定義の変更が監査に残り、戻せる。
- 引き受けるコスト：
  - 小さなテナントでも、定義の変更に 2 人が要る。1 人の管理者のテナントは、本システムの支援の窓口での確認を代わりにする運用を持つ（持ち越し。[security-model.md](../architecture/security-model.md) の 16 節と合わせる）。
  - 模擬の実行の画面を作る。

## Confirmation

- 決定表のテスト：DT-BP-004 の全行。
- 性質ベーステスト：PROP-BP-008（検査を通った任意の定義が有限のステップで終わる）。
- 結合テスト：編集者が自分の下書きを有効化しようとすると拒まれる。
