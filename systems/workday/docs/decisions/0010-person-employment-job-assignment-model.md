# ADR-0010: 人・雇用・職務の割り当ての 3 層で持ち、人員の枠をポジションに一本化する

詳細は [core-hr.md](../architecture/core-hr.md) の 3・4.3・7 節。

## Context

[ADR-0002](0002-effective-dated-data-model.md) は、facet の分け方を core-hr の領域で決め、変えるときは ADR にするとした。決めることは次のとおり。

- 退職して再雇用された人、グループの別の会社で働く人、兼務の人を、どの単位で持つか。給与の計算、社会保険の資格、年休の勤続の年数は「雇用」の単位で決まり、氏名や住所は「人」の単位で決まる。
- 人員の枠の管理。本家は、監督組織ごとに、ポジション管理（空いた承認済みのポジションが要る）とジョブ管理（組織ごとの制限。数の上限なし）を選び、混ぜられる（[Staffing Models](https://doc.workday.com/workday-education/en-us/course-manuals/hcm-core-for-administrators/staffing-models.html)、2026-09-28 に確認）。2 つのモデルを持つと、異動・入社・ロールの割り当て・権限のすべての経路が 2 通りになる。
- 業務委託・派遣の人（外部の人）をどう持つか。

## Options

人の持ち方：

1. **人・雇用・職務の割り当ての 3 層**
2. 人と雇用を 1 つにする（従業員 = 1 回の雇用）
3. 人だけを持ち、雇用の期間は状態の facet で表す

人員の枠：

- a. **ポジションに一本化する。ジョブ管理の組織は、入社・異動のときにポジションを自動で作る**
- b. 本家と同じく 2 つのモデルを持つ
- c. ポジションを持たない（職務と組織だけ）

外部の人：

- i. **雇用の種類 `contingent` として同じ 3 層で持つ**
- ii. 別の表（外部の人の名簿）で持つ

## Decision

1、a、i を採用する。

- 人（`workers`）は同じ個人。雇用（`employments`）は 1 つの会社との 1 回の雇用の期間で、種類（`employee`・`contingent`）と社員番号を持つ。職務の割り当て（`job_assignments`）は雇用の中の仕事で、主たる職務と兼務（最大 4）がある。主たる職務は `employment_primary_job` の facet で毎日ちょうど 1 つ。
- 同じ人・同じ会社の雇用は重ならない。別の会社との同時の雇用は受ける。
- facet は、人の単位（氏名、住所、連絡先、扶養、緊急連絡先）、雇用の単位（在籍の状態、契約、主たる職務、給与、振込先）、職務の割り当ての単位（ポジション・組織・職務・等級・事業所）に分ける。
- すべての職務の割り当てはポジションを持つ。監督組織の `staffing_model` が `job` なら、入社・異動の完了のときに `position_create` の子の案件を承認なしで作る。`position` なら、`open` のポジションがないと拒む。
- ロールは組織×ポジションに割り当てる（[core-hr.md](../architecture/core-hr.md) の 4.5 節）。
- 外部の人は `contingent` の雇用で持ち、給与の入力に入れず、住所・口座・扶養・マイナンバーの facet を持たない。契約の終了日を必須にする。
- 2 を採らない理由：再雇用のたびに人が別になり、氏名・住所・扶養の履歴と、マイナンバーの参照を 2 重に持つ。
- 3 を採らない理由：再雇用の前後の給与・勤続・年休が同じ主体に混ざり、「1 回の雇用」を単位にする給与と社会保険の計算の切れ目を毎回推定することになる。
- b を採らない理由：入社・異動・ロールの割り当て・権限の範囲・レポートの全経路が 2 通りになる。ジョブ管理の利点（速さ）は、自動のポジションで保てる。
- c を採らない理由：ロールをポジションに割り当てられない（人に割り当てると、異動のたびにロールの付け替えが要る）。人員の予算の管理もできない。
- ii を採らない理由：組織図、承認の起点、入館や SSO の連携で、社員と外部の人を同じ経路で扱えない。

## Consequences

- 良くなること：
  - 再雇用、兼務、グループの別の会社の雇用を、同じ形で持てる。
  - ロールが人の異動に影響されない。
- 引き受けるコスト：
  - ジョブ管理の組織でも、ポジションの行が人の数だけできる。自動で作ったものは印を付け、画面で隠す。
  - 兼務の上長のルーティングで、案件の対象の職務の割り当てを常に持つ必要がある。
  - 在籍出向・転籍の持ち方は未決（[core-hr.md](../architecture/core-hr.md) の 14 節の持ち越し）。

## Confirmation

- 性質ベーステスト：PROP-HR-001（同じ会社の雇用が重ならない）、PROP-HR-002（主たる職務がちょうど 1 つ、子の facet が雇用の中）、PROP-HR-004（ポジションに高々 1 人）。
- 決定表のテスト：DT-HR-003（人員の管理のモデル）。
- 給与の入力のスナップショットの生成のテスト：`contingent` の雇用が入らない。
