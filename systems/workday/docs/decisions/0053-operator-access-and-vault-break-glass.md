# ADR-0053: 運用者は本番のデータに常設の権限を持たず、テナントのデータの参照はテナントの許可で行い、保管庫の番号を復号できる人のロールは作らない

詳細は [security.md](../architecture/security.md) の 7 節。

## Context

- 本システムは、多くのテナントの給与・口座・扶養とマイナンバーを持つ。運用者のアカウントの乗っ取りや内部の不正は、大量の漏えいになる。
- [ADR-0005](0005-security-and-my-number.md) は、運用者は通常の運用で保管庫のデータを見られないとし、障害の対応での例外の手順をこの領域で決めるとした。[architecture/README.md](../architecture/README.md) の 6 節も同じ。
- 他の題材（Auth0 の ADR-0056）は、常設の権限をメトリクスとログに限り、DB とシェルを期限つきにし、テナントのデータの参照をテナントの許可にした。
- 番号法のガイドラインは、特定個人情報を扱う者を事務取扱担当者に限るアクセス制御を求める（[ガイドライン](https://www.ppc.go.jp/legal/policy/my_number_guideline_jigyosha/) の別添 1 の F、2026-09-28 に確認）。本システムの運用者は、テナントの事務取扱担当者ではない。
- 本システムが委託先に当たるか（[intent.md](../intent.md) の L1）で、運用者が番号に触れることの扱いが変わりうる。どちらでも成り立つよう、運用者が番号に触れない形にする。

## Options

1. **常設はメトリクスとログだけ。DB・シェル・KMS は期限つき。テナントのデータの参照はテナントの許可（ドメインを限る、P3・P4 は除く）かセキュリティの事象のときだけ。保管庫の番号を復号できる人のロールを作らない。保管庫の緊急の操作は 2 人の承認とテナントへの通知で、基盤の操作に限る**
2. Ops に本番の読み取りの常設の権限を与え、監査で追う
3. 保管庫に break-glass の復号のロールを置く（2 人の承認）

## Decision

1 を採用する。

- 期限つきの権限は最長 4 時間。DB の読み取りは Ops の責任者の承認、書き込みと ECS Exec は 2 人。保管庫と Payroll Compute のタスクには ECS Exec を提供しない。
- テナントのデータの参照は、テナントの管理者が期限つきで許可する（`support_access_grants`）。P3・P4 と `my_number` は選べない。許可のない参照は、セキュリティの事象の対応に限り、`platform_audit_events` に残し、事後にテナントへ知らせる。
- 運用者は代理のログインを使わない（[ADR-0020](0020-sensitive-read-audit-and-access-explanations.md)）。
- 保管庫の番号の `Decrypt` を持つ人のロールはない（[ADR-0052](0052-kms-key-hierarchy.md)）。保管庫の緊急の操作（タスクの入れ替え、DB の構造の修復、PITR の復元の開始）は、セキュリティの担当と Ops の責任者の承認と、テナントの事務取扱責任者への通知で行う。番号の平文に触れる手順は作らない。
- AI エージェントは本番に経路を持たない。
- 四半期ごとにアクセスレビューを行う。
- 2 を採らない理由：1 人のアカウントの乗っ取りで、全テナントの給与と個人情報が読める。
- 3 を採らない理由：復号の経路が 1 つでもあれば、その経路の乗っ取りで番号が読める。番号の復号が要る障害の復旧（例：誤った番号の修正）は、テナントの事務取扱担当者が保管庫の画面で行えばよい。

## Consequences

- 良くなること：
  - 運用者のアカウントが乗っ取られても、読めるのは個人情報を含まないメトリクスとログだけ。
  - 保管庫の番号は、テナントの事務取扱担当者の操作でしか平文にならない。委託の関係の結論（L1）によらず成り立つ。
- 引き受けるコスト：
  - 障害の調査で、権限を得る手間（数分）とテナントの許可の待ちがかかる。SEV1 では、承認をオンコールの二次が行ってよい。
  - 保管庫の番号のデータの誤りは、本システムの側で直せない。テナントの担当者に依頼する。
  - 運用者による参照の例外を、契約でどう約束するかは確認待ち（L56）。

## Confirmation

- IAM の静的検査：本番のアカウントに、期限つきの権限の仕組み以外から DB・ECS Exec・KMS の管理の権限を持つ人のロールがない。保管庫のアカウントに、`vault-mn` の `Decrypt` を持つ人のロールがない。
- 週次：期限を過ぎて残る割り当てがない。
- 四半期：アクセスレビューの記録。テナントの許可のない参照の件数と理由。
