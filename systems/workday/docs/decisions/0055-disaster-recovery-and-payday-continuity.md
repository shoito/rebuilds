# ADR-0055: 大阪にウォームスタンバイを持ち、切り替えは支払の経路を先に戻し、支給日の前は大阪で振込ファイルを作り直してハッシュの一致を毎日確かめる

詳細は [infrastructure.md](../architecture/infrastructure.md) の 6 節と [runbooks/disaster-recovery.md](../runbooks/disaster-recovery.md)。

## Context

- NFR-006：AZ の障害は RPO 0・RTO 15 分以内。リージョンの障害は RPO 5 分以内・RTO 4 時間以内。支給日の前の 5 営業日にリージョンが落ちても、振込ファイルを当日中に出せる。
- 給与の支払いの遅れは、労働基準法の賃金の支払い（毎月 1 回以上、一定の期日）に関わり、従業員の生活に直結する。振込の締め切りは銀行ごとに違う（未検証）。
- 振込ファイルは支払の指示から決定的に作り、承認はファイルの SHA-256 に結ぶ（[ADR-0035](0035-bank-transfer-files.md)）。指示は Aurora に、ファイルは S3 にある。
- 保管庫は、振込ファイルにも給与の計算にも要らない（[ADR-0026](0026-payroll-run-stages-and-input-snapshot.md)）。
- 他の題材（Auth0 の ADR-0060）は、大阪にウォームスタンバイを置き、失った範囲をやり直す手順を持つ。
- DR の仕組みは、使わない間に壊れても気づかない。支給日に初めて使って動かないのが最悪である。

## Options

1. **ウォームスタンバイ。切り替えの順序を決め（支払の経路 → セルフサービスと打刻 → タイマーとレポート → 保管庫）、支給日の前の 5 営業日は大阪で振込ファイルを複製から作り直してハッシュの一致を毎日確かめ、大阪の台数を増やす**
2. パイロットライト（大阪は DB の複製だけ）
3. 東京と大阪のアクティブ・アクティブ

## Decision

1 を採用する。

- 大阪に常に置く：Aurora Global Database の二次（人事・保管庫）、各サービスの最小のタスク、ALB、VPC エンドポイント、KMS のレプリカ、ECR・Secrets Manager の複製、S3 の複製（Replication Time Control）。
- `AuroraGlobalDBRPOLag` が 60 秒を超えたら呼び出す。
- 切り替えの順序：人事の Aurora と、給与・人事の担当の画面、振込ファイルの worker を先に戻す。次にセルフサービスと打刻、次にタイマーとレポート、最後に保管庫。
- 支給日の前の 5 営業日：大阪の api と worker の最小を 2 倍にする。大阪で、二次の reader から承認済み・承認待ちの振込ファイルを作り直し（書き込みはしない）、SHA-256 が東京と一致することを毎日確かめる。一致しなければ SEV2。
- 切り替えの後、失った範囲（複製の遅延ぶん）の承認・確定・取り出しを、log-archive の監査の記録（大阪へ複製）から特定し、業務プロセスでやり直す。すでに東京で取り出した振込ファイルの二重の提出を防ぐ手順を runbook に持つ。
- 2 を採らない理由：大阪でサービスを起こし、台数を広げるまでに時間がかかり、支給日の当日の締め切りに間に合わない恐れがある。
- 3 を採らない理由：人事のデータの書き込み（有効日付の畳み込み、業務プロセスの状態機械）が 1 つの writer を前提にしている。2 つのリージョンの書き込みの衝突の解消は、給与の正しさの危険が大きい。

## Consequences

- 良くなること：
  - 支給日の前に、大阪で振込ファイルを出せることが毎日確かめられる。
  - 切り替えのとき、最も時間に厳しい支払の経路が先に戻る。
- 引き受けるコスト：
  - 大阪の常時の台数と、支給日の前の増強の費用。
  - 失った範囲の承認・確定のやり直しは人の作業になる。
  - 保管庫の復旧は後回しになる。番号の提出と書類の生成は、その間止まる。

## Confirmation

- 本番：支給日の前の 5 営業日の毎日の作り直しで、ハッシュの一致 100%。
- 訓練：四半期に staging で計画外のフェイルオーバー（支給日の 1 営業日前を模して、振込ファイルを大阪で出すまで）。年 1 回、本番の switchover。RTO を記録する。
- 日次：KMS のレプリカ、ECR・Secrets Manager の複製、大阪の Terraform の plan の差分なし。
