# ADR-0049: 保存の期間を確認の状態つきの規則表で持ち、確認待ちの間は長いほうで動かし、保全を優先して専用のロールで消す

詳細は [audit-and-retention.md](../architecture/audit-and-retention.md) の 5 節。

## Context

- 記録の保存の期間は、法令ごとに違い、起算の事象も違う。例：労働基準法 109 条の記録は 5 年（当分の間 3 年）で、賃金台帳は最後の記入の日（支払期日が遅ければ支払期日）から数える（[厚生労働省の Q&A](https://www.mhlw.go.jp/content/000617980.pdf)、施行規則 56 条）。健康保険・厚生年金の書類は完結の日から 2 年、雇用保険の被保険者の書類は 4 年（各施行規則。e-Gov で確認）。扶養控除等申告書は翌年 1 月 10 日の翌日から 7 年（[国税庁 No.2503](https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2503.htm)）。いずれも 2026-09-28 に確認。
- 期間の当てはめ（どの記録がどの種類か、経過措置で 3 年でよいか、源泉徴収簿が法定の帳簿か）は確認待ち（[intent.md](../intent.md) の L2・L5）。
- 確認の結論は、設計の後に出る。結論で期間が変わっても、コードを変えずに済む形が要る。
- 人事のデータの差分と版の表は追記のみで、アプリのロールは消せない（[ADR-0006](0006-temporal-table-triplet-and-fold.md)）。期限の来た退職者のデータを消すには、別の経路が要る。
- 保存の期間より長く持つことは、個人情報を必要以上に持つことになる。短く持つことは、法令の違反になりうる。

## Options

1. **規則表（データの種類、根拠、起算の事象、期間、確認の状態、候補）をデータで持つ。確認待ちの行は候補のうち長いほうで動く。テナントは延ばすだけ。削除は種類ごとのジョブと専用のロールで行い、保全が優先する**
2. 期間をコードの定数で持つ
3. すべてを最長の期間（10 年）で一律に持つ

## Decision

1 を採用する。

- `retention_rules` はテナントの外の共通のデータで、版を持つ。変更は規則表の取り込みと同じく、2 人の確認と公開を経る（[ADR-0030](0030-rule-table-ingestion-and-verification.md) の考え方）。出典の URL と確認の日を持つ。
- `pending_review` の行は `candidates` の最長で動く。確認で `confirmed` にするとき、期間が短くなるなら、次の削除のジョブから効く。
- テナントの延長は `tenant_retention_overrides`。短くできない。
- 保全（`legal_holds`）はすべての削除に優先する。S3 は Object Lock のリーガルホールドを付ける。
- 削除：時間で並ぶ表はパーティションの `DROP`。主体で並ぶ表は `retention_purger` のロールが消す（追記のみのトリガーは、このロールと実行の記録のあるトランザクションだけを通す）。実行は予覧と 2 人の承認を経て、`platform_audit_events` に残す。
- 期間が短くなりうるデータには、コンプライアンスモードの Object Lock を使わない。
- 2 を採らない理由：確認の結論のたびにコードのリリースが要る。どの期間がどの根拠かが、コードの中に散らばる。
- 3 を採らない理由：扶養・健康などの情報を必要以上に長く持つ。個人情報保護法の消去の努力義務（L10）と合わない。

## Consequences

- 良くなること：
  - 確認の結論を、規則表の版の公開だけで反映できる。
  - どの記録をなぜ何年持つかを、根拠つきでテナントと監査人に示せる。
- 引き受けるコスト：
  - 確認待ちの間は長く持つ。確認を急ぐ（L51〜L55）。
  - 追記のみの表に、削除の例外の経路（`retention_purger`）ができる。例外の経路の権限と使用を見張る。
  - Object Lock の期間は、置いた後に短くできない。コンプライアンスモードは監査ログと連鎖に限る。

## Confirmation

- 決定表のテスト：DT-AUD-001、DT-AUD-002。
- 性質ベーステスト：PROP-AUD-005（保全の範囲は消えない）。
- DB の権限の検査：`retention_purger` 以外のロールで、追記のみの表の `DELETE` が失敗する。`retention_purger` でも、実行の記録のないトランザクションでは失敗する。
- 本番：期限を過ぎて残っている行の件数（規則ごと）を月次に見る。
