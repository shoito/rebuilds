# ADR-0021: 打刻を端末が採番した追記のみの事象にし、訂正は記録の追加で行い、客観的な記録との乖離は検知だけする

詳細は [time-and-attendance.md](../architecture/time-and-attendance.md) の 3 節。

## Context

- 打刻は労働時間の計算、36 協定、割増賃金の元になる。賃金その他の労働関係の書類は 5 年（当分の間 3 年）の保存が要る（[労働基準法](https://laws.e-gov.go.jp/law/322AC0000000049) 109 条・143 条、e-Gov で 2026-09-28 に確認）。
- 打刻は始業の 15 分に集中し（S1 で 400 件/秒）、通信が落ちても失ってはならない（NFR-004）。端末からの再送で二重になりうる。
- 労働時間は、タイムカードや PC の使用時間などの客観的な記録を基礎にして把握する。自己申告と入退場・PC の記録に著しい乖離があれば、実態を調べて補正する（[労働時間の適正な把握のためのガイドライン](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/koyou_roudou/roudoukijun/roudouzikan/070614-2.html)、検索の要約で 2026-09-28 に確認）。
- 打刻の誤り（押し忘れ、押し間違い）の訂正は日常的にある。一方で、上長が部下の労働時間を減らす訂正は、未払いの残業の温床になる。

## Options

打刻の持ち方：

1. **端末が採番した ID（UUIDv7）つきの追記のみの事象。端末は一時に貯めて送る**
2. サーバーが受けた順に 1 日 1 行の「勤務の記録」（出勤・退勤の列）を更新する
3. 端末からの送信を同期の API に限る（貯めない）

訂正：

- a. **元の打刻を残し、「追加」「無効」の訂正の記録を業務プロセスで足す**
- b. 打刻の行を書き換える（前後の値は監査ログに残す）

乖離：

- i. **検知して理由を求める。自動では直さない**
- ii. 客観的な記録で打刻を自動で置き換える
- iii. 見ない

## Decision

1、a、i を採用する。

- `time_clock_events` は追記のみ。`(tenant_id, employment_id, client_event_id)` を一意にし、再送は最初の記録を返す。
- 端末は IndexedDB に貯めて古い順に送る。72 時間より古い打刻は受けるが印を付け、上長の確認を要する。時計のずれは印を付けるだけで直さない。
- 訂正は `time_correction` の業務プロセスで `time_clock_corrections` に `add`・`void` を記録する。上長が起票する訂正は本人に通知する。労働時間を減らす訂正は理由を必須にし、件数を報告に出す。
- PC のログと入退室は、日ごとの最初と最後の時刻だけを取り込む。乖離がしきい値（既定 30 分）以上なら `time_divergences` に記録し、本人に理由か訂正を求める（DT-TIME-001）。
- 自己申告の運用は、客観的な記録の連携を必須にしたうえで許す。
- 2 を採らない理由：行の更新は、再送・並行の打刻で最後の書き込みが勝ち、打刻が消える。何を受けたかの記録も残らない。
- 3 を採らない理由：通信の断で打刻を失う。NFR-004 に反する。
- b を採らない理由：訂正の前の値が監査ログにしか残らず、計算の再現（どの打刻で計算したか）ができない。
- ii を採らない理由：客観的な記録は「在社」を示すだけで、労働かは分からない。自動の置き換えは、労務の判断をシステムが代わることになる（[intent.md](../intent.md) の Non-goals）。
- iii を採らない理由：ガイドラインが求める把握を支えられない。

## Consequences

- 良くなること：
  - 打刻を失わず、二重にもならない。
  - 訂正の履歴がすべて残り、誰がどの向きに直したかを監査できる。
- 引き受けるコスト：
  - 計算のたびに打刻と訂正を合わせる手間がある。日の単位で行うので小さい。
  - 乖離の理由の入力が本人の手間になる。しきい値は社労士の確認で決める（L20）。
  - 端末の時計に依存する。ずれの印の運用が要る。

## Confirmation

- 性質ベーステスト：PROP-TIME-002（再送で数が変わらない）、PROP-TIME-005（訂正で行が減らない）。
- 決定表のテスト：DT-TIME-001。
- DB の権限の検査：アプリのロールで `time_clock_events` への `UPDATE`・`DELETE` が失敗する。
- 本番：労働時間を減らす訂正の件数と、上長の起票の割合を月次で出す。
