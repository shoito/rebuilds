# ADR-0003: 日付の範囲の検索は 2 段にする。OpenSearch に空きの区間を `date_range` の欄で入れて「滞在の範囲を含む区間がある」で候補を 300 件に絞り、Valkey の空室の写し（2 年分の泊のビット列と規則の要約）で滞在の規則を確かめる。価格は粗く絞り、料金の要約で正しく絞る。正しさは予約の時の DB で守る

## Context

ゲストは「この地図の範囲（か地名）で、この日付に、この人数で、この予算で泊まれる所」を探す（NFR-001、NFR-002）。

- 地理：地図の範囲（矩形）、地名（市区町村、駅、観光地）の範囲か点と半径。日本語と外国語の地名。
- 日付：チェックインとチェックアウト。日付を決めない検索（週末、1 週間、この月の中で）もある。
- 人数、物件の種類、設備、即時予約だけ、などの条件。
- 価格：総額か 1 泊あたりの範囲。総額は日付・泊数・人数・割引・料金・税・通貨で変わる。

中心の難しさは、**日付の範囲の空室** である。

- S3 で 1,000 万件のリスティング、2 年先までの泊。リスティングごとに空いている日の形が違う。
- 「泊まれる」は、その泊がすべて空いているだけでなく、最短・最長の泊数、チェックインの曜日、締め切り、予約できる期間、準備の日を満たすこと（[ADR-0002](0002-availability-representation-and-double-booking.md)）。
- 予約が入るたびに空室が変わる。S3 で 1 日 45 万件の予約と、ホストのブロック・iCal の取り込みの変化がある。
- 地図を動かすたびに検索が走る。S3 の最大で 1 秒 2 万件。

本家の検索の内部は公開されていない（**未検証**）。

## Options

日付の範囲の絞り方：

1. **2 段。OpenSearch に空きの区間（`date_range`）を入れて「含む」の問い合わせで候補を絞り、Valkey の空室の写しで規則を確かめる**
2. OpenSearch に泊ごとの空き（2 年分の日付の配列）を入れ、全部の泊の日付を AND で問う
3. 地理と条件だけを OpenSearch で問い、候補（数千件）の空室を DB で確かめる
4. 自前の検索のエンジン（メモリの上に地理の索引と空室のビット列）

地理：

- a. **OpenSearch の `geo_point`（ずらした位置）と、地名の範囲の `geo_shape`。地図の点の集まりは `geotile_grid` の集計**
- b. Uber の題材の自前の六角形の格子（`geogrid`）のセルの ID を欄に入れる

## Decision

1 と a を採用する。

### 索引の欄（リスティングの文書）

| 欄 | 型 | 中身 |
| --- | --- | --- |
| `approx_point` | `geo_point` | ずらした位置。正確な位置は入れない（location-and-geo の領域） |
| `stay_ranges` | `date_range`（複数の値） | 「この範囲に収まる滞在なら、泊と準備の日がすべて空いている」区間。下で定義 |
| `max_guests`、`property_type`、`room_type`、`bedrooms`、`amenities`、`instant_book` | keyword・数 | 条件 |
| `min_nights_floor` | 数 | リスティングの最短の泊数の既定と上書きの最小 |
| `price_bands` | 月ごとの `{month, nightly_min, nightly_max}`（円に直した参考の値） | 価格の粗い絞り |
| `title_*`、`description_*` | 言語ごとの `text` | 日本語（Sudachi）、英語、中国語、韓国語ほか |
| `rank_features` | 数の集まり | 順位の式の材料（レビューの点、転換、ホストの信頼など） |
| `listing_version`、`calendar_version` | 数 | 外部のバージョン |

**`stay_ranges` の作り方**：リスティングの有効な `stay_claims` の `block_span` の和の、[今日, 今日 + 予約できる期間) の中の補集合を空きの区間 `[a, b)` とする。リスティングの準備の日を `p` として、各区間を `[a, b − p)` に縮めたものを `stay_ranges` に入れる。滞在 `[check_in, check_out)` が収まる、つまり `a ≤ check_in` かつ `check_out ≤ b − p` なら、その滞在の `block_span = [check_in, check_out + p)` は `[a, b)` に収まり、どの行とも重ならない。最短の泊数の最小より短い区間は入れない。

### ステージ 1（OpenSearch）

- 地理：`approx_point` の `geo_bounding_box`（地図の範囲）か、地名の `geo_shape` の範囲。
- 日付：`stay_ranges` に `{ "gte": check_in, "lte": check_out }` を `relation: contains` で問う（範囲の型の「含む」の問い合わせ）。
- 条件：人数、種類、設備、即時予約。泊数 ≥ `min_nights_floor`。
- 価格：チェックインの月の `price_bands` が、求める 1 泊あたりの範囲と ±30% の余裕で重なること。
- 粗い順位（順位の式の材料の線形の和）で上位 300 件を取る。地図の点のために `geotile_grid` で 300 件の点をまとめる。

### ステージ 2（`search-api` の中、Valkey の写し）

- 300 件の空室の写し（`avail:{listing_id}`。下で定義）を 1 回のパイプラインで取る。
- 各件で `checkStayRules`（[ADR-0002](0002-availability-representation-and-double-booking.md) と同じ関数）を、写しの規則の要約と泊のビット列で回す。締め切り・曜日・最短と最長・予約できる期間をここで正しく判定する。
- 残った件で、料金の要約（`quoteSummary`：泊の料金の和、清掃料、サービス料、税の目安、表示の通貨）を求め、価格の範囲で正しく絞る。料金の要約は（リスティング、日付、人数、料金のバージョン）で Valkey に 10 分持つ。
- 順位の式 v1 で並べ、1 ページ（18 件）と地図の点を返す。件数は粗く出す（「300 件以上」）。

### 空室の写し（Valkey）

- 鍵 `avail:{listing_id}`。中身は、基準の日（物件の現地の今日の月の初め）からの 2 年分（最大 31 + 730 泊）のビット列（`block_span` で埋まった日）、準備の日、最短・最長の泊数（既定とチェックインの日ごとの上書きの差分）、曜日、締め切り、予約できる期間、物件のタイムゾーン、`calendar_version`。
- `availability-cache-writer` が `stay_claims` とカレンダーの設定の変化の outbox から作り直し、Lua で `calendar_version` が大きいときだけ書く。
- 写しがない・Valkey が使えないときは、その件を DB で確かめる（読み出しの写しに 1 回の問い合わせで 300 件）。DB への迂回の率を見張る。
- 写しは正本ではない。失えば作り直す。

### 日付を決めない検索

- 「週末」「1 週間」「この月の中で N 泊」は、ステージ 1 で日付の欄を使わず、`stay_ranges` が求める月と交わり（`relation: intersects`）、長さが N 泊以上ある件に絞る。
- ステージ 2 で、各件の写しから、条件に合う最初の日程（週末なら金曜のチェックインで 2 泊、など）を探し、その日程の料金の要約で並べる。日程の候補は 1 件あたり最大 8 つ。

### 鮮度と正しさ

- 予約・ブロックの変化は、outbox → `search-indexer`・`availability-cache-writer` で p95 10 秒で効く（NFR-002）。索引の更新はリスティングの `calendar_version` を外部のバージョンにし、古い更新を捨てる。
- 毎日、物件の現地の 0 時の後に、`stay_ranges` の下の端を今日に進める処理を回す。古い下の端は、ステージ 2 の締め切りの判定で落ちるので、遅れても正しさに影響しない。
- **検索の結果は約束ではない。** 予約の時に DB の排他の制約と `checkStayRules` で必ず確かめる。検索で泊まれると見せて予約で断った率を SLI にする。
- 抜き取りの再判定：検索の結果の 0.1% を、DB の `stay_claims` で再判定し、混入の率（泊まれないのに出た）を計る（NFR-002 の 0.5% 未満）。泊まれるのに出なかった率は、日次に全リスティングの写しと索引の `stay_ranges` を DB と比べて計る。

### 地理

- 地図の範囲は `geo_bounding_box`、地名は地名の索引（PostGIS の行政の区域の多角形を正本にし、OpenSearch に写した `geo_shape`）で範囲に直す。駅・観光地は点と半径（既定 2 km）。
- Uber の題材の自前の六角形の格子（[ADR-0002](../../../uber/docs/decisions/0002-hex-grid-geospatial-model.md)）は、日本を 1 つの平面に写す方式で、中心から 2,500 km の外を扱えない。世界のリスティングを扱うこの題材には使わない。区画の集計（需要の地図など）は、OpenSearch の `geotile_grid` と、MVP の後に必要なら別の ADR で決める。
- **範囲の問い合わせで正確な位置を割り出せないようにする。** 索引には `approx_point` だけを入れるので、細かい範囲を何度問うても、得られるのはずらした位置である。

### 順位の式 v1

`search-and-ranking` の領域で確定する。v1 は決めた重みの線形の和で、バージョンを付け、結果の記録に式のバージョンを書く。

- 材料：レビューの点（ベイズの平均）、過去 90 日の閲覧から予約への転換（新しいリスティングは同じ区域の事前の値）、価格の競争力（同じ範囲の同じ泊数の中央値との比）、ホストの信頼（ホストの都合のキャンセルの率、応答の率）、写真と内容の充実、苦情の罰。
- 使わない材料：ゲストの国籍・言語の推定から人を分けること、保護される属性とその代わりの値（[ADR-0009](0009-trust-and-safety-and-ml-boundary.md)）。表示の言語の内容がある件を少し上げるのはよい。
- ML の順位は MVP の後に、影の評価を通してから出す。

### 他の案を選ばなかった理由

- **2（泊ごとの日付の配列）**：「泊がすべて空いている」は 7 泊なら 7 つの語の AND で問えるが、準備の日・最短の泊数・曜日は表せない。2 年分の日付の配列は、1 件の予約で 1 文書の全体の作り直しになり、`stay_ranges` と同じ更新の量で、問い合わせが重い。
- **3（DB で確かめる）**：地図の範囲が広いと候補が数万件になり、地理と条件だけで 300 件に絞ると、空いていない件ばかりが残って結果が空になる。日付の絞りをステージ 1 に入れないと、繁忙期に検索の結果が成り立たない。
- **4（自前の検索のエンジン）**：地理・文字・多言語・集計を自前で作るのは、この題材の核の外の大きな仕事になる。日付の範囲の判定（`stay_ranges` の作り方とステージ 2）が核で、そこは自前で書く。
- **b（自前の格子）**：上の理由で、世界を扱えない。

## Consequences

- 良くなること：
  - 日付の範囲の空室を、ステージ 1 で大きく絞れる。繁忙期にも空いている件が残る。
  - 滞在の規則の判定が、予約と検索で同じ関数になる。
  - 索引と写しが遅れても、予約の正しさは DB が守る。
- 引き受けるコスト：
  - `stay_ranges` は準備の日・最短の泊数で近似した値で、ステージ 2 で落ちる件がある。落ちる率が高いと 1 ページを埋められない。ステージ 1 の件数（300）を `availability-search-poc` で確かめ、足りなければ次の 300 件を取る。
  - 予約・ブロックのたびに、リスティングの文書の部分の更新が走る。S3 で 1 秒数十件の更新で、OpenSearch の更新の負荷になる（capacity の領域）。
  - 料金の範囲の絞りは粗く、ステージ 2 で正しく絞る。価格の範囲が狭いと、ステージ 1 の 300 件の多くが落ちる。
  - 結果の件数を正確に出さない。

## Confirmation

- 性質ベーステスト：任意の `stay_claims` の集まりと規則と検索の条件で、「ステージ 1 → ステージ 2」で残る件の集合が、参照の実装（全リスティングに `checkStayRules` を素直に当てる）の結果を含み（ステージ 1 の候補の上限の外は除く）、ステージ 2 を通った件はすべて参照の実装でも泊まれる（[quality.md](../quality.md) の 2.2.1 節 E）。
- 鮮度の試験：予約・ブロック・取り込みの事象を、重複と順序の入れ替えで流し、仮想の時計で 60 秒の後に、索引と写しが DB と一致する（同 E）。
- 本番：混入の率（抜き取り）、予約での断りの率、DB への迂回の率、索引の遅れ（[runbooks/](../runbooks/README.md)）。
