# ADR-0072: 送金の口座・連絡先・パスキー・共同ホスト・PMS・届出住宅の変更を大事な操作とし、直近 10 分の強い確認を求める。送金の口座・連絡先の変更、回復、最後のパスキーの削除から 72 時間は送金の実行を待たせる（仕訳は動かさない）。退会は予約・お金・案件が残れば受け付けず、30 日の `deleting` の後に仮名にする

## Context

- ホストへの支払いはチェックインの予定の時刻 + 24 時間に `host_payable` へ振り替わり、毎営業日に送る（[ADR-0005](0005-payments-hold-capture-and-ledger.md)）。繁忙期の後に大きく溜まる。乗っ取った人は、送金の口座を書き換えて次の束を待つ。
- [ADR-0007](0007-tenancy-host-accounts-and-rls.md) は、送金の口座の変更・共同ホストの追加・届出住宅の登録を `owner` だけにし、口座の変更から 72 時間は送金を保留すると決めた。どの変更で待ちを始めるか、待ちを台帳でどう表すかは決めていない。
- [ADR-0005](0005-payments-hold-capture-and-ledger.md) の `host_payable_hold` は、不正の疑い・本人確認の未了などの措置の保留で、[ADR-0009](0009-trust-and-safety-and-ml-boundary.md) の人の審査を要る。本人の操作に結び付く待ちと混ぜると、措置の記録と異議の経路が要ることになる。
- 退会の時に、未来の予約・送金の残り・宿泊者名簿（ホストが 3 年保存する義務）が残る。ゲストが泊まる所を失ってはならない。保持の期間は法務の確認待ち（L3・L8）。
- Mercari の題材は、大事な操作と 72 時間の振込の待ちと、取引が残る退会の受け付けの条件を決めた（[Mercari の ADR-0067](../../../mercari/docs/decisions/0067-account-takeover-step-up-and-payout-holds.md)、[ADR-0068](../../../mercari/docs/decisions/0068-account-deletion-and-minors.md)）。

## Options

送金の待ちの表し方：

1. **待ちの行（理由、終わりの時刻）を `payouts` が束を作る前に読み、待ちのホストを外す。仕訳は動かさない**
2. `host_payable_hold` へ振り替える仕訳で表す
3. 待ちを持たず、変更を知らせるだけにする

退会：

- a. **予約・お金・案件が残れば受け付けない。30 日の取り消せる期間の後に仮名にし、法令と会計の記録を残す**
- b. 退会で未来の予約を自動でキャンセルする

## Decision

1 と a を採用する。詳細は [accounts.md](../architecture/accounts.md) の 7・10 節。

- **大事な操作**（DT-ACC-001）：送金の口座の登録・変更、メールアドレス・電話番号の変更、パスキーの追加・削除、外部の ID の提供者の結び付け、共同ホストの招待と役割、PMS の許可、届出住宅の登録、住所の変更。直近 10 分の強い確認（パスキー、パスキーがなければメールと SMS の 2 つのコード）。パスキーのない `owner` は送金の口座の登録でパスキーの登録を求める。
- **送金の待ち**：送金の口座の変更は、口座を持つ `payouts` が ledger の `payout_holds`（理由 `payout_account_changed`、72 時間）で持つ（[ledger-and-payouts.md](../architecture/ledger-and-payouts.md) の 7 節）。それ以外（`email_changed`・`phone_changed`・`recovery`・`last_passkey_removed`）は、`identity` が core の `payout_waits` に終わり = 72 時間の後を、変更と同じトランザクションで書く。`payouts` は束の前に両方を読み（`identity.payoutWaitUntil(host_account)`）、待ちのホストを外す。release は時刻どおりに行う（NFR-008）。重なりは最も遅い終わり。待ちの始まりで `security` の通知を全経路（古いメールアドレス、全端末）に送る。
- **「これは私ではない」**：`locked`、全セッションの取り消し、送金の停止、待ちの間なら送金の口座を前の口座に戻す。進行中と未来の予約は続ける。
- **錠**：本人の操作か T&S の人の判定でだけかける。危険の点だけでかけない。
- **退会の条件**：ゲストの進行中・未来の予約、チェックアウトから 14 日の中の予約、ホストの未来・進行中の予約、0 円でない `host_payable`・送金の途中、開いた損害の請求・チャージバック・T&S の案件、他の成員のいるホストのアカウントの `owner`。どれかがあれば受け付けない。
- **退会の流れ**：`deleting`（30 日、ログインで取り消せる）→ `deleted`（`account-eraser` が段ごとに記録して進める）。連絡先の平文を消し、金庫の鍵（位置、口座）を破棄する。台帳、予約の記録、措置、監査、宿泊者名簿は残す。期間と HMAC を残す期間は法務の確認待ち（L3・L8）。

### 他の案を選ばなかった理由

- **2（仕訳で表す）**：本人の操作の待ちが措置の保留と同じ口座に入り、措置の記録・異議の経路の対象と区別できない。72 時間ごとに振り替えの往復の仕訳が増える。
- **3（知らせるだけ）**：乗っ取った人がメールアドレスを先に変えると、知らせが本人に届かない。待ちがあれば、本人が気づく時間が残る。
- **b（自動のキャンセル）**：ホストの退会でゲストが泊まる所を失う。ゲストの退会でキャンセルの返金の計算が退会の画面の中で起き、理解しにくい。キャンセルは本人が既存の流れで行う。

## Consequences

- 良くなること：
  - 一時コードの詐取だけでは送金の行き先を変えられず、変えても 72 時間の間に本人が気づける。
  - 措置の保留（`host_payable_hold`）と本人の操作の待ちが分かれ、異議と監査の対象が明らか。
  - 退会でゲストもホストも予約を失わない。
- 引き受けるコスト：
  - 正しい口座の変更でも、送金が最大 72 時間遅れる。画面で先に知らせる。
  - 退会できない理由が多く、CS への問い合わせが増える。
  - 退会の後も、法令と会計の記録が残る（期間は法務の結論まで既定の値）。
