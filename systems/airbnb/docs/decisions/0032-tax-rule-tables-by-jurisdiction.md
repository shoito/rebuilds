# ADR-0032: 税は `tax_rules` の行（管轄、税の種類、適用の開始と終わり（泊の日）、施設の種類、計算の型、段階・率、課税の標準の定義、免除、端数、同時に集める他の管轄）で持ち、表全体にバージョンを付ける。計算の型は `bracket_per_person_night`・`percent_per_person_night`・`flat_per_person_night` の 3 つ。値は公式の資料から運用と法務が入れ、資料の URL と確認日を行に持つ

詳細は [taxes.md](../architecture/taxes.md) の 4 節。

## Context

- 宿泊税は自治体ごとに、段階の定額（京都市、大阪府）、定率（東京都の 2027-04-01 から）、都道府県と市の重ね（福岡市と福岡県）と形が違い、改正が続く（[taxes.md](../architecture/taxes.md) の 2 節、2026-10-10 に確認）。
- 施設の種類で当てはまりが違う（東京都の改正前は民泊を含まない）。課税の標準に清掃料を含むか（大阪府は含む）も違う。
- 税の表はバージョンの付いた設定にし、コードに自治体の名前を書かない（[AGENTS.md](../../AGENTS.md)）。見積もりは表のバージョンを固定する（[ADR-0004](0004-booking-state-machine-and-holds.md)）。

## Options

1. **管轄ごとの行と、3 つの計算の型の宣言の表。表全体のバージョン**
2. 自治体ごとの計算の関数をコードに書く
3. 外部の税の計算のサービスに任せる

## Decision

1 を採用する。

- 行の欄：`jurisdiction`、`tax_kind`、`valid_from`・`valid_to`（泊の日）、`facility_types`、`calc_type`、`brackets`・`percent_bp`・`exempt_below`・`flat_amount`、`base_includes`、`person_rule`、`requires_amenity`、`rounding`、`collected_with`、`source_url`、`source_checked_at`。
- 管轄は都道府県・市区町村のコードか税の区域の ID。リスティングの管轄の集まりは、ピンの確定の時に求めた値から決める。
- 表全体に `tax_table_versions` のバージョンを付けて出す。行の変更は新しいバージョン。古いバージョンは消さない。
- 資料で確かめられない欄を持つ行は `unverified` の印を持ち、本番の表に入れない。
- 表の中身は運用と法務が入れる。期待する値の試験のベクトルは QA が持つ。

### 他の案を選ばなかった理由

- **2**：改正のたびにコードを出すことになり、自治体の名前がコードに入る。表の変更と見積もりの固定の関係も追いにくい。
- **3**：日本の自治体の宿泊税の細かい規則（施設の種類、課税の標準、重ね）を持つサービスがあるか確かめていない。持っていても、見積もりの固定と再現（同じバージョンで同じ額）を本システムで守れない。

## Consequences

- 良くなること：
  - 新しい自治体・改正を、コードを変えずに表のバージョンで出せる。
  - 行ごとに出典があり、監査と確かめができる。
- 引き受けるコスト：
  - 3 つの型に収まらない税（宿泊料金の帯で率が変わる定率など）は、型を足すコードの変更が要る。
  - 表を最新に保つ運用（改正の見張り）が要る。
