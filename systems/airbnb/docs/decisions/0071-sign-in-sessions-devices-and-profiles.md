# ADR-0071: 登録はメール・電話番号・外部の ID の提供者で始め、予約の前に確認済みのメールと電話番号を求める。ログインはパスキーを第一にし、一時コードと外部の ID の提供者も受け、パスワードは持たない。セッションは端末の鍵で署名する入れ替えの更新のトークンと 15 分のアクセスのトークンで持つ。予約の前のホストにゲストの名前と顔の写真を見せない

## Context

- ゲストの多くは海外から来る。日本の携帯の番号を持たない。ホストは日本に住み、送金の口座を持つ（[intent.md](../intent.md)）。
- 乗っ取りの価値は、ホストの送金と、ゲストの保存したカードと予約の住所にある（[security.md](../architecture/security.md) の T1）。一時コードの詐取が主な入口になる。
- 最初の設計で「パスキーを勧め、メールの一時コードと外部の ID の提供者。パスワードは持たない」と決めた（[architecture/README.md](../architecture/README.md) の 6 節）。
- 本家はパスキーを持ち、操作の確かめにも使う（[ヘルプの記事 4094](https://www.airbnb.com/help/article/4094)、2026-10-10 に確認）。パスワードと Apple でのサインインも持つ（記事の存在だけを確かめた。細部は**未検証**）。
- Mercari の題材は、電話番号を必須の識別にし、パスキーと SMS で入れる形を決めた（[Mercari の ADR-0066](../../../mercari/docs/decisions/0066-sign-in-sessions-and-devices.md)）。海外のゲストには電話番号を必須の入口にできない。
- 予約の前にホストへゲストの属性が見えると、断りの差別の恐れがある（[ADR-0009](0009-trust-and-safety-and-ml-boundary.md)、法務の L11）。

## Options

ログイン：

1. **パスキーを第一。メールと SMS の一時コード、Apple・Google の外部の ID の提供者。パスワードなし**
2. パスワードと任意の 2 段階の認証
3. 電話番号の SMS を必須の識別にする（Mercari の題材の形）

予約の前のゲストの名前と写真：

- a. **既定で見せず、法務の結論で変えられる値にする**
- b. 名を見せ、写真は見せない
- c. 名と写真を見せる

## Decision

1 と a を採用する。詳細は [accounts.md](../architecture/accounts.md) の 4〜6・8 節。

- **登録**：メールアドレスか電話番号の 6 桁のコード、または Apple・Google の OpenID Connect。予約の前に確認済みのメールアドレスと電話番号の両方を求める。1 つのメール・電話番号に有効なアカウントは 1 つ（HMAC の部分一意の索引）。差別の禁止の方針への同意を登録の必須の段にする。
- **SMS**：国ごとの許可の一覧（`ops.sms_allowed_countries`）と国ごとの 1 時間の上限。一覧の外の番号は SMS を送らず、メールで確かめる。
- **強さ**：`strong`（パスキー）、`federated`、`otp`、`otp2`（メールと SMS の 2 つのコード）、`recovery`。パスキーのあるアカウントの `otp`・`federated` のセッションは、大事な操作にパスキーか回復を求める（[ADR-0072](0072-sensitive-operations-payout-holds-and-account-deletion.md)）。
- **パスキー**：RP ID `<brand>.<domain>`、`userVerification = required`、見つけられる資格情報、10 まで。
- **アプリのセッション**：端末の取り出せない P-256 の鍵で署名する更新のトークン（使うたびに入れ替え、2 秒の外の再使用で系列を取り消す）と、15 分の不透明なアクセスのトークン（Valkey の写し）。使わない 90 日（ホストのアカウントの `owner` は 30 日）、最長 1 年。取り消しは 5 秒で効く。
- **Web のセッション**：`__Host-session` の Cookie、使わない 14 日、最長 30 日、CSRF のトークン。
- **端末**：サーバーが出す `device_id`、1 人 20 台、端末の証明は信号だけ。
- **プロフィール**：予約の前のホストには、本人確認の印・登録の年・レビュー・話す言語だけを見せ、名前と顔の写真は `legal.prebooking_guest_identity_display`（既定 `none`。法務の確認待ち：L11）に従う。
- **アプリ**：iOS・Android は React Native（TypeScript）、Web は React（[architecture/README.md](../architecture/README.md) の 4 節の「accounts の領域で ADR にする」）。全要求に `X-<Brand>-Client` を付ける。

### 他の案を選ばなかった理由

- **2（パスワード）**：使い回しと詐取の入口が増え、漏れの対応（ハッシュの守り、総当たりの絞り）が要る。パスキーと一時コードで足りる。
- **3（電話番号の必須の識別）**：海外のゲストが日本向けの番号の扱いと SMS の届きにくさで登録できない。国際の SMS の料金の詐取の面も広がる。
- **b・c（名・写真を見せる）**：差別の禁止の範囲（法務の L11）の結論の前に、断りの偏りの材料を出すことになる。結論で値を変えれば広げられる。

## Consequences

- 良くなること：
  - 海外のゲストがメールか外部の ID の提供者で入れる。
  - 一時コードを詐取されても、パスキーのあるアカウントの送金・連絡先は変えられない。
  - 盗んだ更新のトークンは端末の鍵なしで使えない。
- 引き受けるコスト：
  - 外部の ID の提供者の障害と、提供者のアカウントの乗っ取りの面を持つ。
  - SMS の国の一覧と上限の運用。
  - 予約の前に名前が見えないことを嫌うホストがいる（リクエストの承認の率を見る）。

## Confirmation

- 性質ベーステスト：1 つのメール・電話番号の有効なアカウントは 0 か 1（PROP-ACC-001）、取り消しの 5 秒の後の 401（PROP-ACC-002）、更新のトークンの再使用（PROP-ACC-003）、`otp` のセッションの制限（PROP-ACC-006）。
- 漏れの経路：予約の前のホストに名前・写真・連絡先が出ない（[quality.md](../quality.md) の 2.2.1 節 H）。
- E20 の外部のペンテストでログインとセッションを確かめる。
