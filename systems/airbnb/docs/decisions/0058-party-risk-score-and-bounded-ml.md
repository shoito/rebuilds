# ADR-0058: パーティーの危険の点 v1 は、許した特徴の一覧だけを使う加点の式（0〜1）で、0.50 以上は `step_up`（ハウスルールの明示の同意と本人確認）、催しの窓の中は 0.75 以上、外は 0.85 以上で `hold`。ML の点は影の評価の後に、式の点から ±0.20 の範囲でだけ動かせる。ゲストの住まいとの距離は `identity` が 3 つの区分に丸めて渡す

詳細は [trust-and-safety.md](../architecture/trust-and-safety.md) の 7 節。

## Context

- パーティーは近隣の迷惑と物件の損害になり、本システムの登録と自治体との関係にも響く。ハウスルールの `events` の既定は禁止にする。
- [ADR-0009](0009-trust-and-safety-and-ml-boundary.md) は、パーティーの危険の点を予約の時に出し、高ければ `step_up` か `review` にし、地域と時期で規則を強めるとした。ML は点と理由のコードだけを返す。保護される属性とその代わりの値を使わない。
- MVP の時点では学習のデータがない。本家の方式は公開されていない（**未検証**）。
- 予約の時の判定は 150ms に収めたい（NFR-004）。

## Options

1. **許した特徴の加点の式から始め、ML は影の評価の後に式の点から ±0.20 の範囲で足す**
2. 最初から ML の点を使う
3. 点を持たず、決めた条件（大晦日の 1 泊の家全体）だけで止める

## Decision

1 を採用する。

- 特徴と加点：家全体 +0.15、1 泊 +0.20（2 泊 +0.08）、金・土・祝日の前の夜 +0.10、催しの窓 +0.20、住まいとの距離 `local` +0.15、アカウント 30 日未満 +0.10、完了した滞在 0 件 +0.10、良い滞在 3 件以上 −0.20、パーティーの違反の確かめた記録 +0.40、定員 6 以上で定員と同じ人数 +0.05、チェックインまで 2 日未満 +0.10。0〜1 に切る。
- 0.50 以上で `step_up`、催しの窓の中は 0.75 以上、外は 0.85 以上で `hold`（[ADR-0057](0057-ts-decision-points-and-outcomes.md)）。
- 特徴の一覧はバージョンで持ち、追加は QA と法務の確認を通す。保護される属性、氏名、顔の写真、言語の設定、国の推定を使わない。
- 住まいとの距離は `identity` が `local`・`regional`・`far`・`unknown` に丸めて渡す。
- ML は段 0（使わない）→ 段 1（影の記録だけ）→ 段 2（最終の点 = clamp(式 + clip(ML − 式, −0.20, +0.20), 0, 1)）。段 2 は評価の集まりの基準と公平さの比 1.25 以下と、T&S の責任者・法務の承認の後。50ms で返らなければ式の点だけ。

### 他の案を選ばなかった理由

- **2**：学習のデータがなく、誤りの形を確かめられない。ML の点だけで予約を止めると、説明も異議も難しい。
- **3**：条件の組み合わせが固く、少しずれた形（2 泊、週末の前の夜）を逃す。点にすれば閾値で調整できる。

## Consequences

- 良くなること：
  - 点の理由を加点の行で説明でき、例で確かめられる。
  - ML を入れても、式から大きく外れた判定にならない。
- 引き受けるコスト：
  - 加点の値は推定で、評価の集まりと運用で直す。
  - 住まいとの距離は、国内と海外のゲストで結果を偏らせうる。公平さの段「物件と同じ国か」で見張る。
