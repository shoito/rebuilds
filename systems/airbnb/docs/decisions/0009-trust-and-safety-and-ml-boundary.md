# ADR-0009: T&S は、同期の検査・規則のエンジン・人の審査・措置の記録の段に分ける。不正・パーティーの危険・偽のリスティングの ML は点と理由のコードだけを出す。料金の提案はホストが決めた範囲でだけ効き、順位付けの ML は影の評価の後に出す。保護される属性を特徴に使わない

## Context

宿泊のマーケットプレイスの T&S は、お金だけでなく、人の身の安全に関わる。

- **偽のリスティング**：存在しない部屋、他の物件の写真の使い回し、前払いを外部へ誘う詐欺。
- **決済の不正**：盗んだカードでの予約、チャージバック。
- **乗っ取り**：ホストのアカウントを取って送金の口座を変える。
- **パーティー**：近所に迷惑をかける大人数の集まり。本家はパーティーを禁じている（2020 年の一時の禁止を 2022 年に恒久にしたと報道された。公式の文は確かめられなかった。**未検証**）。
- **安全の事故**：ゲストやホストのけが、隠しカメラ、不法な侵入。24 時間の対応が要る。
- **差別**：ホストがゲストの属性で断る。順位付けや不正の点が属性で偏る。

ML は、不正の点、パーティーの危険の点、偽のリスティングの点、料金の提案、順位付けに使える。誤りの影響は、予約の拒否（ゲストが泊まる所を失う）、送金の保留（ホストの生活）、差別に及ぶ（NFR-013）。

Mercari の題材は、同期の検査・非同期の分類器・規則のエンジン・人の審査・措置の記録に分けた（[ADR-0009](../../../mercari/docs/decisions/0009-trust-and-safety-pipeline-boundary.md)）。

## Options

1. **段に分け、ML は点と理由のコードだけ。措置は規則と人が記録してから効かせる**
2. ML の点の閾値で自動に措置する
3. 外部の不正の検知のサービスに判定を任せる

## Decision

1 を採用する。

### 段

| 段 | どこで | 何をする |
| --- | --- | --- |
| 同期の検査 | 予約の作成、リスティングの公開、送金の口座の変更、メッセージの送信 | 決定的な検査（禁止の語、写真の知覚ハッシュの一致、届出番号の重複、速さの上限、連絡先の形）。p95 100ms |
| 点 | `ml-inference` | 不正の点（予約）、パーティーの危険の点（予約）、偽のリスティングの点、乗っ取りの点（ログイン・口座の変更）。点と理由のコードだけを返す |
| 規則のエンジン | `trust-safety` | 点、検査の結果、利用者の履歴、本人確認の水準から、`allow`・`step_up`（本人確認・3-D セキュアを求める）・`review`（進めて審査）・`hold`（予約の確定を止めて審査、送金の保留）・`block` を決める。規則は宣言の表でバージョンを付ける |
| 人の審査 | 審査の待ち行列 | `review`・`hold`・通報・安全の事故を人が判定する |
| 措置の記録 | `moderation_actions` | 措置の根拠（規則のバージョン、点、審査の判定）を書いてから、予約・リスティング・アカウントの状態を変える（outbox） |

- **自動の措置は `step_up` と `hold` まで。** アカウントの停止、予約の取り消し、リスティングの削除は、人の審査を通す。例外は、決定的な一致（既知の盗難のカード、確かめた偽のリスティングの写真のハッシュ）で、規則の表に理由を書いたものだけ。
- **パーティーの危険**：予約の時の点（泊数、曜日、人数、ゲストの住所と物件の近さ、過去の苦情）が高いと、規則で `step_up`（ハウスルールへの明示の同意、本人確認）か `review` にする。地域と時期（年末年始、ハロウィン）で規則を強める。
- **安全の事故**：アプリの緊急のボタンと電話の窓口から、`safety_incidents` の案件を作る。緊急の案件は、24 時間の安全の担当に p90 2 分で人がつく（NFR-013）。予約の停止、代わりの宿の手配の記録、ホストの送金の保留を、案件から操作できる。警察・消防への連絡は利用者に促す。本システムが代わりに通報する条件は法務と決める。

### 料金の提案（ML の境界）

- 料金の提案は、ホストが有効にし、最低と最高の値を決めたときだけ、`calendar_days` の料金を書き換える。書き換えは主体 `pricing_suggestion` の通常のカレンダーの書き込みで、範囲の外の値は `pricing` が拒む。
- 有効にしていないホストには、提案の値を画面に出すだけ。
- MVP の提案は、同じ区域・同じ定員の、過去の予約の泊の料金の分布と、日付の需要（検索の量）から出す統計の値。ML のモデルは MVP の後に、影の評価（本番の予約で提案だけを記録し、実際の予約の率と比べる）を通してから出す。
- 料金の提案は、サービス料・税・キャンセルの精算の計算に使わない。

### 順位付けの ML

- MVP は規則の式（[ADR-0003](0003-search-for-date-range-availability.md)）。ML の順位は MVP の後に、影の評価（同じ検索で式とモデルの順位を記録し、予約の率を比べる）と、公平さの評価を通してから出す。

### 公平さと差別の禁止

- 不正の点、パーティーの危険の点、順位付けの特徴に、国籍、人種、民族、宗教、性別、性的指向、障害、年齢と、その代わりになる値（氏名、顔の写真、言語の設定から推した出身）を使わない。特徴の一覧はバージョンで持ち、追加は QA と法務の確認を通す。
- 予約の確定の前に、ホストにゲストの顔の写真を見せない。ホストの断りの率を、属性の代わりの値なしで見張る（法務の L11）。
- 公平さの評価：利用者の段（新しいアカウント、本人確認の有無、表示の言語）ごとの `hold`・`block` の率と誤りの率を、モデル・規則の変更ごとに比べる。

### 他の案を選ばなかった理由

- **2（自動の措置）**：誤った予約の拒否・送金の保留は、利用者の旅行と生活を壊す。説明と異議の経路が要る。
- **3（外部に任せる）**：パーティーの危険や偽のリスティングは、宿泊に固有で、本システムの審査のデータで学び続けたい。決済の提供者の不正の点は、点の 1 つとして受け取る。

## Consequences

- 良くなること：
  - 措置に必ず根拠の記録があり、異議と監査ができる。
  - 料金の提案と順位付けの ML を、ホストの決めた範囲と影の評価の中に閉じられる。
  - 差別の禁止を、特徴の一覧と公平さの評価で確かめられる。
- 引き受けるコスト：
  - 人の審査の量が増える。繁忙期と事故の時に、審査の人手と 24 時間の安全の担当が要る。
  - 自動の措置を絞る分、不正の一部が審査までの間に通る。送金の保留で損失を抑える。

## Confirmation

- 評価の集まり：偽のリスティング・パーティーの危険・不正の点の評価の集まり（[quality.md](../quality.md) の 2.2.1 節 I）と、公平さの評価。
- 本番：措置の取り消しの率、`hold` の率、安全の窓口の応答の時間（[runbooks/](../runbooks/README.md)）。
