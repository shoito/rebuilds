# ADR-0039: ポリシーの表の v1（柔軟・中程度・厳格と確定から 24 時間の全額の返金）を DT-CXL-001 の 12 行で確定する。境はチェックインの時刻からの時間で測る。返金は泊・清掃料・税の行ごとに、請求の通貨とリスティングの通貨の両方で計算し、端数はゲストに有利にする。税は泊まらなかった泊の分を返す。サービス料はホストが受け取る額の 15%

## Context

- MVP は柔軟（24 時間前まで全額）、中程度（5 日前まで全額、以後は 50%）、厳格（30 日前まで全額、7〜30 日前は 50%、7 日未満は返金なし）と、7 日以上前に確定した予約の確定から 24 時間の全額の返金（[architecture/README.md](../architecture/README.md) の 6 節）。
- 本家の柔軟・中程度は、期限の後に「泊まった泊と追加の 1 泊」をホストに払う（[ヘルプの記事 475](https://www.airbnb.com/help/article/475)、2026-10-10 に確認）。README の「以後は 50%」はこの細部を書いていない。
- 返金は払った通貨と額をもとに計算する（[ADR-0008](0008-multi-currency-and-fx.md)）。返金 + ホストの取り分 + 収益 = 払った額（NFR-007）。
- サービス料はホストだけの型で、宿泊の対価の小計に掛け、税に掛けない（[ADR-0031](0031-host-only-service-fee.md)）。チェックインの前のキャンセルは税を全額返す（[ADR-0034](0034-tax-collection-model.md)）。
- 違約金の妥当さは法務の L7。

## Options

1. **行ごと・通貨ごとに残す割合を当てる決定表。柔軟・中程度は本家の「追加の 1 泊」に寄せ、厳格は README の値。境は絶対の時間**
2. 総額に割合を当てる（行を見ない）
3. 境を暦の日（物件の現地の 0 時）で測る

## Decision

1 を採用する。表・式・例は [cancellations-and-changes.md](../architecture/cancellations-and-changes.md) の 5 節。

- DT-CXL-001：全額（主体がホスト・運用の全額）→ 確定から 24 時間 → 柔軟（24h）→ 中程度（120h）→ 厳格（720h、168h、チェックインの後）→ 運用の「使わなかった泊を返す」→ 表の誤り。
- 柔軟の期限の後：使った泊と使わなかった最初の 1 泊を残す。中程度：同じく残し、残りの使わなかった泊の 50% を残す。滞在の行（清掃料）はチェックインの前なら返す。
- 税の行は泊まらなかった泊の分を返す。
- `retained = floor(paid × keep_bps / 10000)`、`refund = paid − retained`。請求の通貨は見積もりの按分の額、リスティングの通貨は見積もりの行で、別に計算する。
- サービス料 = 残した泊と滞在の行の和 × 見積もりの率。ホストの取り分 = その和 − サービス料 + 残した税（`host` のとき）。
- 計算は `packages/cancellation` の `computeSettlement` だけ。表はバージョンで、予約の時のバージョンを使う。

### 他の案を選ばなかった理由

- **2**：清掃料と税を泊と同じ割合で扱い、泊まっていない税を残す。チェックインの後の「使った泊」を表せない。
- **3**：夏時間とチェックインの時刻で、「5 日前」がゲストの見た説明と数時間ずれる。

## Consequences

- 良くなること：
  - 和が最小単位で一致し、返金は払った通貨の額で為替に依らない。
  - 境の判定が 1 つの瞬間の比べで済む。
- 引き受けるコスト：
  - 厳格は本家の今の厳格（7 日以上前は 50%）と違う。税の返し方も柔軟で違う（[README.md](../architecture/README.md) の 1.4 節に足す提案）。
  - 行の数だけ計算する（27 泊で 60 行ほど）。

## Confirmation

- 性質ベーステスト PROP-CXL-001〜006（和、上限、単調、24 時間、`refund-ref` との一致、ポリシーの固定）。夜間 100 万の場面（[quality.md](../quality.md) の 2.2.1 節 C）。
- 表駆動テスト：DT-CXL-001 の全 12 行と 5.5・5.6 節の例。
