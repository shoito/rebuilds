# ADR-0080: 計装は属性の許可の一覧と型での禁止で個人のデータを出さず、検索の語・地図の範囲・外の URL を出さない。高い基数の ID をラベルにせず、熱いリスティングは枠で見る。不正・お金・PMS のダッシュボードは低い基数の集計だけにし、個別は案件の画面で見る。アプリの計測は本システムの受け口にだけ送る

## Context

- ログ・トレースに、住所、正確な位置、氏名、電話番号、メールアドレス、旅券の番号、本人確認の書類、メッセージの本文、検索の語、口座の番号を書かない（[AGENTS.md](../../AGENTS.md)）。検索の語と地図の範囲は、利用者の旅の行き先を表す。iCal の URL と Webhook の受け口の URL は秘密のトークンを含みうる。
- 熱いリスティング、PMS のアプリ、乗っ取り、名簿の持ち出しの兆しを見たいが、リスティングや利用者の ID をラベルにすると、メトリクスの基数が爆発し、ダッシュボードが個人を指す。
- アプリの計測に第三者の部品を入れると、外部送信規律（電気通信事業法）の公表と同意の論点になる（法務の L9）。
- Mercari の題材は、属性の許可の一覧、低い基数のダッシュボード、本システムの受け口だけのアプリの計測を決めた（[Mercari の ADR-0075](../../../mercari/docs/decisions/0075-sli-measurement-and-correctness-monitors.md)、[ADR-0076](../../../mercari/docs/decisions/0076-fraud-and-money-dashboards.md)）。

## Options

1. **属性の許可の一覧と型での禁止、低い基数のラベル、案件の画面での個別の調べ、本システムの受け口だけのアプリの計測**
2. ログに出してから、収集の側で個人のデータを伏せる
3. 第三者の計測の SaaS をアプリに入れる

## Decision

1 を採用する。詳細は [observability.md](../architecture/observability.md) の 2・6・8 節。

- **属性**：`packages/telemetry/attributes.ts` の許可の一覧の外を落として数える。金庫・連絡先・2 者の型（`ExactAddress`、`ExactGeoPoint`、`PersonName`、`PhoneNumber`、`EmailAddress`、`PassportNumber`、`BankAccountNumber`、`MessageBody`、`RegistryEntry`）はロガーに渡せない。検索の語・地名の入力・地図の範囲・iCal と Webhook の URL を出さない（解決した場所の ID、アドレスの ID、購読の ID は出してよい）。
- **ラベル**：サービス、経路、結果と理由のコード、検索の種類、支払いの方法、通知の種類、AZ、都道府県、審査を通した PMS のアプリの ID、iCal の相手のドメインの上位 20。利用者・リスティング・予約・届出住宅の ID、IP、端末、検索の語は使わない。熱いリスティングは枠（`slot=0..19`）で見て、対応は運用の画面だけ。
- **ダッシュボード**：乗っ取り、送金、予約の不正、偽のリスティングとパーティー、位置のスクレイピング、名簿、お金、PMS、SSRF の面を、AMP の低い基数の集計と Athena の日次の集計で作る。フォルダーは T&S・セキュリティ・財務・Ops の組だけ。個別の調べは `ops-api` の JIT の案件の画面で行う。
- **アプリの計測**：本システムの受け口（`api.<brand>.<domain>/telemetry`）だけ。第三者の計測・広告の部品を既定で入れない。送る項目の一覧を持ち、第三者の部品を足すときの公表と同意は法務の確認待ち（L9）。

### 他の案を選ばなかった理由

- **2（後で伏せる）**：伏せる前の経路（収集器、バッファー、誤りの報告）に平文が残る。型で入口を閉じるほうが漏れの経路が少ない。
- **3（第三者の SaaS）**：外部送信規律の公表と同意が要り、旅の行き先と端末の情報が第三者に渡る。越境の整理（法務の L8）も要る。

## Consequences

- 良くなること：
  - ログとダッシュボードからの個人のデータの漏れの経路が、型と許可の一覧で閉じる。
  - メトリクスの基数が抑えられ、費用が読める。
- 引き受けるコスト：
  - 個別のリスティングの調べに、運用の画面への移動が要る。
  - 自前の受け口とクラッシュの記号化の運用。

## Confirmation

- 型の検査と性質ベーステスト：ログに金庫・連絡先・2 者の型の値が現れない（PROP-OBS-001）。
- 夜間のログの走査：住所・正確な位置・氏名・電話番号・メール・旅券の番号・口座・カード番号の形の検出 0（[quality.md](../quality.md) の 2.2.1 節 H）。
- CI：メトリクスのラベルの許可の一覧の外のラベルを拒む。
