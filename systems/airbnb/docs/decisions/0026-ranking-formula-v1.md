# ADR-0026: 順位の式 `rank_v1` = (0.35·Q + 0.25·C + 0.15·H + 0.10·D + 0.15·P) × 苦情の罰 × 表示の言語の原文の 1.05 倍。Q はレビューのベイズの平均（事前 10 件）、C は平滑した転換、H はホストの信頼、D は内容の充実、P は同じ検索の総額の中央値との比。ステージ 1 は P を除いた `rank_static` で並べる。1 ページに同じホストのアカウントは 3 件まで

詳細は [search-and-ranking.md](../architecture/search-and-ranking.md) の 7 節。

## Context

- [ADR-0003](0003-search-for-date-range-availability.md) は順位の式 v1 を決めた重みの線形の和とし、材料（レビューの点、転換、価格の競争力、ホストの信頼、内容の充実、苦情の罰）を挙げた。重みはこの領域で決める。
- 順位付けの ML は MVP の後（[ADR-0009](0009-trust-and-safety-and-ml-boundary.md)）。保護される属性とその代わりの値を使わない。
- 新しいリスティングはレビューも転換の記録もない。点が 0 になると、二度と上に出ない。
- 価格の競争力は、検索ごとの日付・泊数・人数で決まり、索引の時に計算できない。

## Options

1. **0〜1 に揃えた材料の重みつきの和。レビューと転換は事前の値で平滑する。価格はステージ 2 で足す**
2. Mercari の題材のような積の式（[ADR-0019](../../../mercari/docs/decisions/0019-ranking-formula-v1.md)）
3. 価格の安い順を既定にする

## Decision

1 を採用する。

```
rank_v1 = (0.35·Q + 0.25·C + 0.15·H + 0.10·D + 0.15·P) × M × (1 + 0.05·L)
Q = clamp((bayes − 3.5)/1.5, 0, 1)、bayes = (n·avg + 10·μ_area)/(n + 10)
C = min(1, conv/(2·area_conv))、conv = (bookings_90d + 200·area_conv)/(views_90d + 200)
H = clamp(1 − 5·host_cancel_rate_365d − 0.5·(1 − response_rate_30d), 0, 1)
D = 0.4·min(1, photos/15) + 0.2·[説明 ≥ 300 文字] + 0.2·min(1, amenities/15) + 0.2·写真の質の中央値
P = clamp(1.25 − 0.5·r, 0, 1)、r = 総額 ÷ 同じ検索の中央値
M = 1 − min(0.5, 0.15·確かめた苦情_90d)、L = 表示の言語の原文の有無
同じ点は listing_id の昇順
```

- ステージ 1 は `rank_static = (0.35·Q + 0.25·C + 0.15·H + 0.10·D) × M` で並べる。
- 1 ページ（18 件）に同じホストのアカウントの件は 3 件まで。
- 式はコードのバージョン。重みを変えるときは `rank_v2` を作り、両方の順位を記録して 14 日比べてから切り替える。フラグで経路ごとに切り替えない。

### 他の案を選ばなかった理由

- **2**：積の式は 1 つの材料が 0 に近いと全体が 0 に近づく。新しいリスティングの転換や、レビューのない件が沈みすぎる。宿泊は文字の一致（BM25）が主の入口でないので、掛ける土台がない。
- **3**：安さだけで並べると、写真と違う安い件や、キャンセルの多いホストが上に来る。価格の安い順は並べ替えの選択肢として持つ。

## Consequences

- 良くなること：
  - 新しい件は区域の事前の値の近くから始まり、記録が増えるにつれて実際の値に寄る。
  - 材料ごとの寄与を説明でき、例の点を試験のベクトルで確かめられる。
- 引き受けるコスト：
  - 重みは推定で、S1 の運用で直す。
  - 価格の材料は同じ検索の中の相対の値で、検索の範囲の広さで変わる。
