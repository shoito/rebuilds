# ADR-0022: 取り込みの区間が本システムの行と重なったら、重ならない部分だけを `ical_block` で入れ、重なりを `calendar_conflicts` に記録する。重なった相手の種類で深刻さを分け（DT-ICS-001）、確定した予約との重なりは 5 分以内にホストへ知らせ運用の待ち行列に入れる。相手の行が外れたら、取り込みの区間の欠けを自動で埋め直す。本システムの予約は自動で取り消さない

## Context

- 外部と本システムで同じ夜が売れていても、どちらが先かを本システムは知れない。本システムの予約を自動で取り消さない（[architecture/README.md](../architecture/README.md) の 1.3 節 E）。
- 取り込みと本システムの重なりを、取り込みから 5 分以内にホストへ知らせる（NFR-003、K2）。
- 重なる取り込みを丸ごと捨てると、重ならない夜（外部で売れた夜）が本システムで空いて見え、新しい二重の予約を作る。
- 重なりの相手が仮押さえ（10 分）なら、支払いの結果でどちらにも転ぶ。

## Options

1. **重ならない部分を入れ、重なりを記録する。相手の種類で深刻さを分け、相手が外れたら埋め直す**
2. 重なる取り込みの区間を丸ごと捨てて記録する
3. 取り込みを優先し、本システムの仮押さえ・リクエストを外す

## Decision

1 を採用する。詳細は [calendar-sync.md](../architecture/calendar-sync.md) の 6.3〜6.6 節。

- 挿入が排他の制約に当たったら、区間から重なる行の `block_span` を引いた片を `ical_block` で入れ、重なりごとに `calendar_conflicts` に 1 行を書く。
- DT-ICS-001：`reservation` → `double_booking`（ホストへプッシュとメール、運用の待ち行列）。ただし予約の泊とちょうど同じで書き出していた予約なら `possible_echo`。`hold` → `pending`（知らせない）。`request` → `request_overlap`（ホストに断れることを知らせる）。ブロック → `covered`。他の取り込み → 両方が外部の予約なら `external_double_booking`、他は `covered`。
- 相手の行が外れた事象と、同じ取り込みの次の書き込みで、区間の欠けを埋め直し、埋まった重なりを閉じる。相手が `hold` から `reservation` になったら深刻さを上げる。
- 取り込みは本システムの行を外さない。

### 他の案を選ばなかった理由

- **2**：重ならない外部の夜が空いて見え、二重の予約を増やす。
- **3**：外部の予定が古い・誤りのとき、本システムのゲストの支払いの途中の仮押さえを失わせる。仮押さえの結果は 10 分で決まるので、待てば足りる。

## Consequences

- 良くなること：
  - 外部で売れた夜は、重ならない限り必ず塞がる。
  - 仮押さえとの一時の重なりで、ホストに誤った知らせを送らない。
- 引き受けるコスト：
  - 二重の予約の解消はホストと CS の手に残る。
  - 相手の掲載先が書き出しの `UID` を付け替えて戻すと、偽の重なりが出る（`possible_echo` で深刻さを下げる）。

## Confirmation

- 性質ベーステスト PROP-ICS-002（重なりは入らず記録される）、PROP-ICS-003（相手が外れたら埋め直す）。
- 表駆動テスト：DT-ICS-001 の全 7 行。
- 仮想の時計：取り込みから知らせの依頼まで 5 分以内。
