# ADR-0059: 偽のリスティングは、写真の使い回し、禁止のハッシュ、位置の食い違い、届出番号の重複、相場から外れた価格、外部への誘導、到着の時の「存在しない」の報告を信号にする。新しいホストのアカウントの最初の 3 件の予約は、ホストの送金をチェックアウトの後 24 時間まで待たせ（送金の待ち `new_host_first_stays`）、内容の食い違いの報告があれば措置の保留にする

> 2026-10-10 の注記：統合の工程で、新しいホストの扱いを「release を延ばして `host_payable_hold` に置く措置の保留」から「release は時刻どおり、送金の束から外す決まった待ち（`payout_holds.kind = 'wait'`）」に変えた。ledger-and-payouts の領域の「最初の予約の release から 72 時間」の待ちと 2 つの規則があったため、こちらの範囲（最初の 3 件、チェックアウトの後 24 時間）で 1 つにした。持ち主は `payouts` で、決まった待ちは措置でないので異議の対象にしない。

詳細は [trust-and-safety.md](../architecture/trust-and-safety.md) の 8 節。

## Context

- 偽のリスティング（存在しない部屋、他の物件の写真、前払いを外部へ誘う詐欺）は、ゲストが泊まる所を失い、お金を失う（[ADR-0009](0009-trust-and-safety-and-ml-boundary.md)）。
- ふつうの送金の release はチェックインの予定の時刻 + 24 時間（[ADR-0005](0005-payments-hold-capture-and-ledger.md)）。偽のリスティングでも、ゲストが到着して気づく前に release されうる（チェックインの時刻にゲストが来ないと、報告が遅れる）。
- [ADR-0005](0005-payments-hold-capture-and-ledger.md) は、新しいホストの初回を送金の保留の理由に挙げた。範囲は決めていない。

## Options

1. **信号を規則のエンジンに入れ、新しいホストの最初の 3 件の送金をチェックアウトの後 24 時間まで待たせる**
2. 新しいホストの最初の予約の前に、運用の現地の確かめを求める
3. 新しいホストの保留をしない（信号と審査だけ）

## Decision

1 を採用する。

- 信号：`photo_reuse`（他のホストのアカウントと距離 1〜6）、`photo_blocklist_exact`、`location_review`、`registration_duplicate`、価格が区域の中央値の 40% 未満（新しいホストのアカウント）、説明・メッセージの外部への誘導の件数、チェックインの日の「存在しない・入れない」の報告。
- 結果は `review` が主で、`block` は禁止のハッシュの完全な一致だけ。到着の時の報告はリスティングの `hold` と安全の S2 の案件。
- 新しいホストのアカウントの最初の 3 件の予約は、release を時刻どおりに行い、`payouts` が ledger の `payout_holds` に送金の待ち（`kind = 'wait'`、理由 `new_host_first_stays`、終わり = その予約の `check_out_at` + 24 時間）を書く。待ちの間はそのホストの送金を束から外す。待ちの間に内容の食い違いの報告があれば、T&S が措置の保留（`kind = 'hold'`、`fraud_suspected`）に替える。規則の正本は [ledger-and-payouts.md](../architecture/ledger-and-payouts.md) の 7.3 節（[ADR-0048](0048-release-payout-batching-and-holds.md)）。
- 偽と判定したら、リスティングを停止し、将来の予約を運用のキャンセルで全額返金し、写真のハッシュを禁止の一覧に足す（T&S の責任者の承認）。

### 他の案を選ばなかった理由

- **2**：S1 の 10 万件の多くが新しいホストで、現地の確かめの人手が足りない。
- **3**：前払いの詐欺のお金は、最初の滞在で気づく前に出ていく。

## Consequences

- 良くなること：
  - 偽のリスティングで失うお金を、最初の滞在の確かめまで止められる。
- 引き受けるコスト：
  - 正しい新しいホストの最初の 3 件の受け取りが、チェックインの後 24 時間からチェックアウトの後 24 時間に遅れる。画面で事前に知らせる。
  - 待ちの間は、そのホストのアカウントの他の予約の送金も待つ（送金は口座ごとの 1 つの残高のため）。

## Confirmation

- 評価の集まり：偽のリスティングの `hold` の再現率 90% 以上・適合率 70% 以上（[quality.md](../quality.md) の 2.2.1 節 I）。
- 仮想の時計の試験：新しいホストの最初の 3 件の予約のどれかの `check_out_at` + 24 時間より前に、そのホストの送金が実行されない。release は時刻どおり。4 件目からは待ちを書かない（PROP-PO-001）。
