# ADR-0075: データを 10 の区分に分け、区分ごとに置き場所・暗号化・ログに出してよいか・保持の既定を 1 つの表で持つ。保持の値は本システムの既定で、法務の L3・L8 の結論で置き換える。名簿と旅券は作成から 3 年を下限にし、自動の削除は法務の結論の後に始める。データレイクには金庫・連絡先・2 者の本文を入れない

## Context

- この題材は、身の安全に関わる正確な住所、法令で保存が決まる名簿、旅券の画像、送金の口座、メッセージを持つ（[intent.md](../intent.md)）。どれをどこに置き、いつ消すかを、領域ごとに別々に決めると食い違う。
- 名簿は作成日から 3 年保存する（観光庁の [住宅宿泊事業者の義務](https://www.mlit.go.jp/kankocho/minpaku/business/host/index.html)、2026-10-10 に確認）。本システムが名簿を持つことの整理、旅券の画像の保存の上限、退会の後の保持、越境の移転は法務の確認待ち（L3・L8）。
- ログ・トレースに利用者のデータを出さない（[AGENTS.md](../../AGENTS.md)）。データレイクは学習と分析に使い、ML は保護される属性とその代わりの値を使わない（[ADR-0009](0009-trust-and-safety-and-ml-boundary.md)）。
- Mercari の題材は、区分と保持の既定を 1 つの表で持った（[Mercari の ADR-0071](../../../mercari/docs/decisions/0071-data-classes-and-lifecycle.md)）。

## Options

1. **区分の表と保持の既定を 1 か所で持ち、法令が下限を決めるものは下限で持ち、自動の削除を法務の結論の後に始める**
2. 領域ごとに保持を決める
3. 法務の結論まで、何も消さない

## Decision

1 を採用する。詳細は [security.md](../architecture/security.md) の 4・7 節。

- **区分**：S 秘密、V 金庫、C 連絡先、P 2 者、O 本人、U 公開、F お金、A 監査、M 運用、L 分析。区分ごとに置き場所、暗号化、ログに出してよいか（V・C は ID だけ、P は ID と状態と理由のコードだけ）を決める。
- **保持の既定**：正確な位置はリスティングの削除から 1 年、名簿と旅券は作成から 3 年を下限、口座は削除まで（前の口座は 1 年）、本人確認は法務の結論まで消さない、連絡先は退会まで、予約のメッセージはチェックアウトから 3 年、予約とお金の記録は 10 年、監査は 7 年、本人の履歴と通知は 90 日、ログは 30 日と S3 で 1 年、データレイクは 2 年。
- **名簿と旅券**：保持の期限の後の自動の削除（年度の鍵の破棄。[ADR-0073](0073-key-layout-and-vault-envelope-encryption.md)）は `legal.registry_auto_delete_enabled`（既定 `false`）の後に始める。それまでは期限を過ぎた年度を報告し、法務が判断する。
- **消す処理**：`retention-sweeper` が区分ごとの規則を日次で当てる。大きな表は月の区切りで落とす。保全の印（`legal_holds`：照会、紛争、損害の請求、安全の事故、措置）の行は消さない。期限から 7 日を過ぎた残りはチケット。
- **データレイク**：V・C の欄と P の本文を落とし、ID をレイクの鍵（年ごとに替える）の HMAC にし、位置を市区町村に丸めてから入れる。元の ID へ戻す表は持たない。
- **越境**：日本の外の PMS と提供者への送信は法務の確認待ち（L8）。結論まで日本の外の PMS にゲストの個人のデータを出さない。

### 他の案を選ばなかった理由

- **2（領域ごと）**：同じデータ（例：住所）が領域ごとに違う期間で残り、消し忘れの経路ができる。法務の結論が出たときの変更の場所が散らばる。
- **3（何も消さない）**：旅券の画像とメッセージが際限なく溜まり、漏れたときの範囲が広がる。法令の下限のあるものは下限で持ち、下限のないものは本システムの既定で消すほうが小さい。

## Consequences

- 良くなること：
  - 区分の表が、ログの検査・データレイクの落とし・消す処理の 1 つの正本になる。
  - 法務の結論が出たら、`legal.*` と表の値の変更で切り替えられる。
- 引き受けるコスト：
  - 名簿と旅券は、法務の結論までは期限を過ぎても残る（報告で見える形にする）。
  - 区切りの表と `retention-sweeper` の運用。

## Confirmation

- 仮想の時計の試験：期限を過ぎた行が `retention-sweeper` の 1 回の後に残らない（保全の印と、自動の削除を有効にしていない名簿を除く）。
- 夜間のログの走査：V・C の形の検出 0（[quality.md](../quality.md) の 2.2.1 節 H）。
- データレイクの取り込みの検査：V・C の欄と P の本文が入らない。
