# ADR-0014: ずらした位置は、正確な位置から、密度の区分で決めた輪（都市 300〜500 m、郊外 400〜650 m、地方 500〜800 m）の中の、秘密の鍵と位置の組の ID から HMAC で決める点にする。40 m 以内の物件は同じ位置の組として同じ点を共有し、40 m 未満のピンの直しでは点を変えない。地図には点を中心に輪の外径の円を出す

詳細は [location-and-geo.md](../architecture/location-and-geo.md) の 5 節。

## Context

- 正確な住所と位置は、確定した予約のゲストにだけ出す（NFR-016、[ADR-0007](0007-tenancy-host-accounts-and-rls.md)）。検索・地図・リスティングの画面には、ずらした位置（`approx_point`）だけを使う。
- [architecture/README.md](../architecture/README.md) の 1.3 節は、ずらした位置を半径 300〜800 m の中の、リスティングの ID と秘密の値から決まる点にし、作り直さないとした。
- 割り出しの方法は、同じ建物の複数のリスティングの点の平均、ピンを少しずつ動かして点の変化を見ること、地図の範囲の細かい問い合わせである。
- 本家のずらし方は公開されていない（**未検証**）。

## Options

1. **輪の中の HMAC の決まった点。位置の組で共有し、小さな直しで変えない**
2. リスティングごとの決まった点（リスティングの ID から）
3. 格子の中心に丸める（例：500 m の格子）
4. 表示のたびに違う点を出す

## Decision

1 を採用する。

- `h = HMAC-SHA256(K, "approx:v1:" || group_id || ":" || try)`。方位 `360° × u1`、距離 `sqrt(u2 × (r_max² − r_min²) + r_min²)`。輪は密度の区分で都市 300〜500 m、郊外 400〜650 m、地方 500〜800 m。
- 正確な位置が 40 m 以内の物件は、ホストのアカウントをまたいで同じ位置の組に入る。組の中心から 40 m 未満のピンの直しでは組を変えない。新しい組への移動は 1 リスティング 365 日に 3 回まで。
- 点が陸の多角形に入らなければ `try` を上げてやり直す（16 回まで）。
- 地図は点を中心に、`r_max` を 100 m 単位に切り上げた半径の円を出す。
- 鍵 `K` は KMS で守り、漏えいの時にだけ替える。替える時は全部の点と索引を作り直す。
- 索引・地図・画面・距離の計算・「駅から徒歩 N 分」は `approx_point` だけを使う。

### 他の案を選ばなかった理由

- **2**：同じ建物の 10 室のリスティングは 10 の独立した点を持ち、平均で正確な位置に近づく（誤差は 1/√10 ≒ 0.32 倍）。
- **3**：格子の線の近くの物件は、格子の中心から見た位置が偏る。格子の大きさを知れば、物件がどの升にあるかが正確にわかり、升の端の物件ほど不利になる。
- **4**：表示のたびの点を集めて平均すれば、正確な位置が出る。

## Consequences

- 良くなること：
  - 点と正確な位置の距離が常に `r_min` 以上で、問い合わせを重ねても正確な位置に近づかない。
  - 同じ建物のリスティングから位置を絞れない。
- 引き受けるコスト：
  - 新しい組への移動の 3 回で、3 つの点が集められる（誤差は約 0.58 倍）。上限の回数を超える移動は運用の審査にする。
  - 地図の円が広く、都市の中ではゲストが場所を選びにくい。駅・地名の情報で補う。
  - 輪の中心に物件がないことを知る攻撃者は、輪の面積（都市で 0.50 km²）まで絞れる。
