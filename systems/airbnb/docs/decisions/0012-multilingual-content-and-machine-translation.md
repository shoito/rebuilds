# ADR-0012: 説明の文はホストが書いた言語ごとの原文を正にし、機械翻訳は原文のハッシュを鍵にした別の行に置いて、画面と API で「機械翻訳」の印と原文への切り替えを必ず付ける。翻訳の提供者に送るのは公開の項目だけで、チェックインの案内・住所・メッセージは送らない

詳細は [listings-and-content.md](../architecture/listings-and-content.md) の 5 節。

## Context

- 海外のゲストは英語・中国語・韓国語で読みたい。多くのホストは日本語だけで書く（[intent.md](../intent.md)）。
- 機械翻訳は誤る。ハウスルールや設備の誤訳は、ゲストとホストの争いになる。ゲストは訳文と原文を区別できなければならない。
- 自前の翻訳のモデルは作らない（[intent.md](../intent.md) の Non-goals）。翻訳の提供者に送る文は、国外の事業者に渡る可能性がある（法務の L8）。
- 原文が編集されると、古い訳文が残りやすい。

## Options

1. **原文の行と、原文のハッシュを鍵にした訳文の行を分ける。訳文には必ず印を付ける**
2. 訳文を原文と同じ行の言語ごとの列に書き、ホストが直せるようにする
3. 表示の時に毎回訳し、持たない

## Decision

1 を採用する。

- 原文は `listing_texts`（言語ごと）。書ける言語は `ja`・`en`・`zh-Hans`・`zh-Hant`・`ko`。
- 訳文は `listing_translations`（`source_hash`、`provider`、`provider_model` つき）。読み出しは今の原文の `body_hash` と一致する行だけ。古い行は 30 日で消す。
- 公開の改訂の入れ替えで、原文のない 5 つの言語へ題名と説明を先に訳す。他の言語と他の項目は最初に読まれた時に訳す。
- 訳文の API の型は `machine_translated` と `source_lang` を必須にする。画面は印と「原文を表示」を必ず出す。
- 提供者に送るのは、公開している改訂の公開の項目だけ。チェックインの案内、住所、届出番号、メッセージ、ホストの氏名は送らない。
- 訳文にも連絡先の絞り込みを当て、当たれば原文を出す。
- 検索の索引は訳文も言語ごとの欄に入れ、重みを原文の 0.8 にする。

### 他の案を選ばなかった理由

- **2**：ホストが直した訳と機械の訳の区別がつかなくなる。ホストが直したいなら、その言語の原文として書けばよい。
- **3**：同じ文を何度も訳して費用がかかり、提供者の停止で画面が遅れる。検索の索引に訳文を入れられない。

## Consequences

- 良くなること：
  - 原文の変更で古い訳文が出ない。
  - ゲストは常に訳文と原文を区別できる。
- 引き受けるコスト：
  - 5 つの言語の先の翻訳の費用（S1 で約 5 億文字の見込み。capacity の領域）。
  - 訳文の絞り込みで、正しい訳文が出ない場合がある（原文を出す）。
