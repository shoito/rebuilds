# ADR-0045: チャージバックは予約の状態を変えず、提供者が引き落とした額を `psp_chargeback_held` に移す。負担は理由と時期で決める：不正の理由は本システム、提供されなかった・説明と違うは運用の判断でホストに戻せる。release の前なら預かりで受け、ホストに送らない

## Context

- 盗んだカードの予約、滞在の後の「提供されなかった」の申し出でチャージバックが来る。release の前と後で、お金の場所が違う（預かりか、ホストへの支払いか）。
- ホストは不正の被害者であることが多い。ホストに負担を移すのは、ホストに責任があるときだけにしたい。
- 本家の負担の規則は**未検証**。Mercari の題材は売り手からの回収（`chargeback_receivable`）を持つ。

## Options

1. **状態を変えない。理由と時期の表で負担を決め、ホストへの移しは運用の判断**
2. 常にホストに戻す
3. 常に本システムが負う

## Decision

1 を採用する。詳細は [payments-and-fx.md](../architecture/payments-and-fx.md) の 7 節。

- 通知で型 19（`psp_receivable` → `psp_chargeback_held`）、運用の案件を開く。予約の状態は変えない（DT-BKG-001 の行 30）。
- release の前：運用が予約を取り消すなら、精算の返金の先を提供者の引き落としに当てる（ゲストに二重に返さない）。
- release の後：不正で 3-D セキュアの責任の移転がなければ本システム（型 21）。提供されなかった・説明と違うは運用の判断で、ホストの責任なら型 22（`host_receivable`）で後の送金と相殺。
- 勝てば型 20。

### 他の案を選ばなかった理由

- **2**：不正の被害者のホストに負担を移す。ホストの信頼を失う。
- **3**：滞在を提供しなかったホストに不当な利益が残る。

## Consequences

- 良くなること：
  - 予約の状態とお金の争いが分かれ、状態の機械が単純なまま。
- 引き受けるコスト：
  - 不正の負担が本システムに残る。3-D セキュアと T&S の規則で抑える。
  - ホストへの移しの判断が運用の仕事になる。

## Confirmation

- 性質ベーステスト：チャージバックの開始・勝ち・負けの列で、台帳の不変条件（PROP-LED-001）が保たれ、ゲストへの返金と提供者の引き落としが重ならない。
- 表駆動テスト：負担の表。
